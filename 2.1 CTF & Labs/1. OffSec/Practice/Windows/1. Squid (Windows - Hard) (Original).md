
## About this lab

In this lab, we will enumerate ports behind a Squid proxy to gain an initial foothold through phpMyAdmin. Privileges will then be elevated by creating scheduled tasks to enable restricted privileges. This lab focuses on exploiting proxy configurations and privilege escalation methods.

## Learning Objectives

**After completion of this lab, learners will be able to:**

- Enumerate open ports behind the Squid proxy to identify accessible services.
- Exploit phpMyAdmin to upload a web shell and establish a reverse shell as LOCAL SERVICE.
- Recover default LOCAL SERVICE privileges using a scheduled task.
- Enable the SeImpersonatePrivilege via a scheduled task with a crafted Principal.
- Use PrintSpoofer to exploit SeImpersonatePrivilege and achieve SYSTEM-level access.

## Lab Description

This lab demonstrates using a Squid proxy to enumerate open ports on a target and gain initial access via phpMyAdmin with default credentials. Learners will escalate privileges by recovering restricted LOCAL SERVICE privileges through scheduled tasks. Finally, they will exploit the SeImpersonatePrivilege using PrintSpoofer to achieve a SYSTEM shell. This lab emphasizes proxy exploitation, privilege recovery, and abuse of impersonation rights.

Absolutely. **Squid is a proxy server**, and in this lab its importance is that the target's Squid service can potentially make HTTP connections to services that **you cannot directly reach from Kali**.

Think of it as a **middleman**.

### Without Squid

Normally:

```
Kali ────────────────> Target:8080
```

Kali directly connects to port 8080.

If a firewall blocks 8080:

```
Kali ───────X───────> Target:8080
```

You can't access it.

### With Squid

Your connection becomes:

```
Kali
  │
  │ HTTP request
  ▼
Target:3128
  │
  │ Squid makes the request
  ▼
Target:8080
```

So **Kali isn't directly connecting to 8080**.

Instead, you're saying to Squid:

> "Hey Squid, please fetch `http://192.168.208.189:8080` for me."

Squid then makes that connection itself.


Your Nmap scan from Kali sees only the ports that are reachable **from Kali's network position**.

But Squid is running **on the target**.

Therefore:

```
             TARGET
       ┌─────────────────┐
       │                 │
Kali ──┤ Squid :3128     │
       │       │         │
       │       ├──> :8080│
       │       ├──> :8081│
       │       └──> :9000│
       │                 │
       └─────────────────┘
```

That's why the lab tells you to **enumerate ports behind the Squid proxy**.

how did we directly look out for port 8080 here

Exactly — that's the important question. **We didn't actually discover port 8080 from your Nmap scan.** I used `8080` as an **example** of a possible hidden web port.

Your original scan showed:

```
135/tcp
139/tcp
445/tcp
3128/tcp   ← Squid
49666/tcp
49667/tcp
```

There is **no 8080** in that output.

### So how do we discover it?

We need to ask the **Squid proxy to connect to different ports** and see which ones respond.

For example:

```
curl -x http://192.168.208.189:3128 http://192.168.208.189:8080/
```

means:

> Kali → Squid:3128 → Target:8080

But why 8080?

Because **8080 is a common alternative HTTP/web port**. We could similarly test:

```
80
81
443
8000
8080
8081
8888
8443
```

For example:

```
curl -x http://192.168.208.189:3128 http://192.168.208.189:8000/
curl -x http://192.168.208.189:3128 http://192.168.208.189:8080/
curl -x http://192.168.208.189:3128 http://192.168.208.189:8081/
```

### But we don't want to manually guess hundreds of ports

That's the actual **enumeration** step.

You can automate the requests:

```
for port in 80 81 443 8000 8008 8080 8081 8888 8443; do
    echo "===== $port ====="
    curl -x http://192.168.208.189:3128 \
         --connect-timeout 2 \
         -s -o /dev/null \
         -w "%{http_code}\n" \
         http://192.168.208.189:$port/
done
```

Then investigate the ports that produce interesting responses.

So remember the distinction:

```
Normal Nmap:
Kali ──────────> Target:PORT
       direct

Through Squid:
Kali ──> Squid:3128 ──> Target:PORT
                         ↑
                   test hidden ports
```

**8080 wasn't discovered beforehand; it was just a common port we chose to test.** The lab's objective is for you to discover which port behind Squid hosts phpMyAdmin.
