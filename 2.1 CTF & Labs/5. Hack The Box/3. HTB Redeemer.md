# LAB — Information Disclosure with Redis (HTB Redeemer)

> **Platform:** Hack The Box — Starting Point
> **Box:** Redeemer
> **Difficulty:** Very Easy
> **OS:** Linux
> **Technique:** Unauthenticated Redis enumeration → key-value data extraction

Redeemer showcases enumeration and exploitation of a Redis database server using `redis-cli` to extract sensitive data from an unauthenticated instance.

---

---

## 2. Connect with `redis-cli`

```
└─# redis-cli -h 10.129.52.194
10.129.52.194:6379> 
```

🚨 **Connected without any authentication** — the Redis instance has no password configured. This is the core misconfiguration.

## Redis CLI Quick Reference

| Command | Purpose |
|---------|---------|
| `redis-cli -h <IP>` | Connect to remote Redis server |
| `info` | Server information and statistics |
| `select <N>` | Switch to database index N |
| `keys *` | List all keys in the current database |
| `get "<key>"` | Retrieve the value of a specific key |
| `config get dir` | Get the Redis working directory |
| `config set dir <path>` | Change the Redis working directory |
| `config set dbfilename <file>` | Set the persistent storage filename |
| `save` | Write in-memory data to disk |

---

## Lessons Learned

- **Unauthenticated Redis = full data access.** If Redis has no password, anyone can read every key-value pair.
- Always check the **Keyspace** section at the bottom of `info` output — it tells you how many databases and keys exist.
- The `select` command lets you switch between databases (e.g., `select 0`, `select 1`) if multiple exist.
- Redis is an **in-memory** store — data lives in RAM and is optionally persisted to disk via RDB snapshots.
