| Field      | Value              |
| ---------- | ------------------ |
| Category   | General Skills     |

### Description

> Using a Secure Shell (SSH) is going to be pretty important.
>
> Can you `ssh` as `ctf-player` to `titan.picoctf.net` at port `51654` to get the flag?
>
> You'll also need the password `84b12bae`. If asked, accept the fingerprint with `yes`.

**Useful links from the challenge:**
- Webshell: [https://webshell.picoctf.org](https://webshell.picoctf.org/)
- Shell primer: [https://primer.picoctf.com/#_the_shell](https://primer.picoctf.com/#_the_shell)

### Hints

- [SSH man page](https://linux.die.net/man/1/ssh)
- You can try logging in "as" someone with `<user>@titan.picoctf.net`
- How could you specify the port?
- Remember, passwords are hidden when typed into the shell

### Walkthrough

**Step 1 — Connect via SSH**

The challenge gives us a username, host, port, and password. We assemble the SSH command:

```bash
ssh ctf-player@titan.picoctf.net -p 51654
```

### Flag

```

```

### Takeaways

- `ssh user@host -p port` is the standard syntax. The `-p` flag specifies a non-default port (default is 22).
- On first connection to a new host, SSH prompts you to verify the server's fingerprint — type `yes` to trust it.
- Passwords are **not echoed** in the terminal; this is normal security behaviour, not a bug.

## Challenge 3 — What's a Net Cat?

| Field      | Value              |
| ---------- | ------------------ |
| Category   | General Skills     |
| Difficulty | Easy               |
| Technique  | Netcat (`nc`)      |

### Description

> Using netcat (`nc`) is going to be pretty important. Can you connect to `fickle-tempest.picoctf.net` at port `58850` to get the flag?

### Hints

- [Netcat tutorial](https://linux.die.net/man/1/nc)

### Netcat Quick Reference

Before solving, here's a quick primer on `nc` (netcat) — the "Swiss Army knife" of networking:

**Basic syntax:**

```bash
nc [options] host port
```

**Connect to a host:**

```bash
nc 192.168.1.10 80
```

**Check if a port is open:**

```bash
nc -zv 192.168.1.10 22
```

| Flag | Purpose                        |
| ---- | ------------------------------ |
| `-z` | Scan mode (don't send data)    |
| `-v` | Verbose output                 |

```
Connection to 192.168.1.10 22 port [tcp/ssh] succeeded!
```

**Scan a range of ports:**

```bash
nc -zv 192.168.1.10 20-100
```

Useful for quick enumeration when `nmap` isn't available.

### Walkthrough

**Step 1 — Connect with netcat**

```bash
Akshit023-academy@webshell:~$ nc fickle-tempest.picoctf.net 58850
You're on your way to becoming the net cat master
picoCTF{nEtCat_Mast3ry_0d33dA2C}
```

That's it — `nc` opens a raw TCP connection to the target host and port. The server responds with the flag.

### Flag

```
picoCTF{nEtCat_Mast3ry_0d33dA2C}
```

### Takeaways

- `nc host port` creates a raw TCP connection — no protocol overhead like HTTP or SSH.
- Netcat is invaluable for interacting with custom services, grabbing banners, and piping data in CTFs.
- Unlike `ssh`, there's no authentication — you're talking directly to whatever service is listening.

### Lessons Learned

1. **`wget`** — Downloads files from URLs. Watch for auto-renamed files (`.1`, `.2` suffixes).
2. **`ssh`** — Secure remote login. Always specify `-p` for non-standard ports. Fingerprint prompts are expected on first connection.
3. **`nc` (netcat)** — Raw TCP connections. The fastest way to interact with a bare service. Also doubles as a port scanner with `-zv`.
4. **General mindset** — Sanity challenges exist to confirm your tooling works. Don't overthink them, but *do* make sure you understand the tools — they're the building blocks for everything harder.
