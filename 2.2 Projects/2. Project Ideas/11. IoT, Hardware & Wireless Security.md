## IoT security

### IoT Device Vulnerability Assessment
A Red Team project focused on assessing the security of Internet of Things (IoT) devices in a simulated smart home environment. Goal: identify vulnerabilities in IoT devices and provide recommendations for enhancing their security.
**Key Activities:**
- Performed a thorough vulnerability assessment using tools such as OpenVAS and IoT-specific scanners. Identified common vulnerabilities such as outdated firmware, weak default passwords, and insecure communication protocols.
- Evaluated the physical security of IoT devices by assessing their placement and potential for tampering. Identified vulnerabilities that could allow an attacker to gain physical access and manipulate the devices.
- Compiled a comprehensive report detailing findings (identified vulnerabilities and exploitation techniques) and actionable recommendations — updating firmware regularly, using strong unique passwords, and implementing network segmentation to isolate IoT devices from critical networks.

### AI-Driven IDS for IoT (from Bitten Tech "Cyber Projects for Future")
Uses **Deep Learning** to monitor IoT network traffic and detect anomalous behavior that traditional firewalls might miss.

### IoT Honeypot (from Bitten Tech)
Creates realistic dummy IoT devices to capture attacker behavior, payloads, and command patterns, which are then analyzed using machine learning.

### Network Honeypot for Threat Intelligence
How it works: Deploy tools like Cowrie (SSH/Telnet honeypot) or HoneyDB agent to capture malicious login attempts.
Example: A company placed a Pi 5 in their DMZ to log brute-force attacks, revealing attacker IPs, tools, and methods.
Why Pi 5? Cheap, low-power, and can run 24/7 without increasing electricity bills.

### Portable Network Traffic Analyzer
How it works: Run tcpdump or Wireshark on the Pi to capture and analyze suspicious network activity.
Example: A security team plugged the Pi 5 into a SPAN port and caught a malware-infected PC sending data to an external C2 server.
Why Pi 5? Can store captures locally or stream them to a secure remote server for analysis.

## Hardware & wireless (Hackathon)

### HSM Tampering Detection System (Hardware Security)
Design and implement a real-time monitoring system that detects, logs, and responds to tampering attempts on Hardware Security Modules (HSMs). Focus on practical, demonstrable tamper scenarios — voltage glitches, enclosure opening, fault injections, sensor triggers. The system must securely log tamper events, generate real-time alerts, and produce compliance reports aligned with international benchmarks (e.g., FIPS 140-3 Level 3+). Full FIPS compliance may be beyond the timeframe; address a meaningful subset (side-channel aggregation, fault attack countermeasures, secure log storage) and validate against simulated tamper events.
**Exact Deliverables:**
- Prototype tamper detection system with continuous telemetry and alerting.
- Side channel and sensor aggregation (voltage, enclosure switches, etc.) with secure logging.
- Test rig that validates against FIPS-140 tamper event requirements.
- Monitoring module with compliance-ready reporting.
**Milestones, Evolution Parameters:**
- Phase 1: Submission of proposed approaches and a baseline prototype on a simulated HSM, with a detailed report.
- Phase 2: Shortlisted teams develop enhanced prototypes on low-cost hardware (e.g., ARM Juno Board, Raspberry Pi, or other OP-TEE supported boards).
- Phase 3: Final demos evaluated against key FIPS 140-3 Level 3+ principles (tamper detection, evidence, response, secure logging).
**Additional Information:** Prioritize modular design so the system works across multiple HSM vendors; secure append-only, cryptographically signed tamper log storage; support integration into enterprise SIEM dashboards.

### Wireless Protocol Fuzzing (Security in distributed wireless networks — IoT/CPS, 5G, etc.)
Develop an automated fuzzing tool to discover protocol-level vulnerabilities in distributed wireless systems such as IoT, CPS, Wi-Fi, Zigbee, Bluetooth, and 5G. Identify flaws in protocol handshakes, reconnection flows, and state transitions. Goal: a scalable, reproducible, coverage-guided fuzzer that strengthens the resilience of emerging IoT and wireless infrastructure.
**Exact Deliverables:**
- A working fuzzer for at least one protocol stack (WPA2/3, BLE, Zigbee, or Wi-Fi), with extendable architecture for IoT protocols.
- Automated crash detection and unique bug identification module.
- Reporting framework to measure unique crashes and CVEs found against baselines.
- Proof-of-concept demonstrating fuzzing against simulated or open-source protocol implementations.
**Milestones, Evolution Parameters:**
- Phase 1: Implement baseline protocol fuzzing for WPA2/3 or BLE.
- Phase 2: Add instrumentation and state coverage tracking.
- Phase 3: Extend framework to IoT protocols (Zigbee, LoRaWAN, Matter).
- Phase 4: Support multi-protocol fuzzing and real-time reporting.
**Additional Information:** Focus on lightweight fuzzers that run on commodity hardware or cloud instances; follow ethical guidelines (lab environments, not live production networks); modular design extendable to future protocols (Matter, LoRaWAN).
