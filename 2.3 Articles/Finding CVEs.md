
### How beginners actually get there

Earning a CVE can sound impossibly advanced, but people do it every day by starting small and being methodical. A realistic progression looks like this:

1. Pick a small, open-source project or an inexpensive Internet-of-Things device (something with a real but manageable attack surface).
2. Learn that target deeply: read its code, understand how it works, and map out where it handles input and trust.
3. Look for common, well-understood vulnerability classes rather than exotic ones.
4. When you find something, write a clear, reproducible proof of concept.
5. Report it responsibly to the vendor and give them reasonable time to fix it before any public disclosure.

A CVE is the headline achievement, but it's not the only way to stand out, and you shouldn't wait for one to start building a presence.

Running a blog where you write up techniques you've learned, publishing tools or scripts on GitHub, creating walkthrough videos on YouTube, participating in bug bounty programs, contributing to open-source security projects, and sharing your capture-the-flag write-ups all create a visible body of work.

Taken together, that portfolio tells employers exactly who you are and how you think.

Always disclose responsibly

When you find a real vulnerability, report it privately to the vendor and give them reasonable time to fix it before going public. Responsible disclosure is what separates a security researcher from an attacker — and it's what earns you respect in the industry.
