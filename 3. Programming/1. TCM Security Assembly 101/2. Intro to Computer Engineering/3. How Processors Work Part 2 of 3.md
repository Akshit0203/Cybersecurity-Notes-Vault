## Three Main Units of the CPU

```
    ┌───────────┐
    │ Control   │ → controls operations
    │ Unit      │
    ├───────────┤
    │ Registers │ → A, B, C, D, IP
    ├───────────┤
    │ ALU       │ → calculations
    └───────────┘
```

### 1. Control Unit

- The **controller** of everything inside the processor
- Takes the majority of inputs and routes them
- Handles moving data between memory locations
- Decides which unit should perform what operation

### 2. Arithmetic Logic Unit (ALU)

- Performs **arithmetic**: addition, subtraction, multiplication, division
- Contains dedicated circuits for each operation (e.g., an adding circuit)

### 3. Internal Registers

- **Tiny, fast storage locations inside the CPU** (not RAM, not the hard drive)
- Think of them as small variables inside the CPU

Our simplified 8-bit CPU has **5 registers**:

| Register | Purpose |
|----------|---------|
| **A** | General-purpose data |
| **B** | General-purpose data |
| **C** | General-purpose data |
| **D** | General-purpose data |
| **IP** | **Instruction Pointer** — tracks which instruction to fetch next |

> IP is like the CPU's **bookmark** — it points to the next instruction in memory.

---

## Register Width = Processor Bit Size

Each register stores **one byte (8 bits)** — this is called the **register width**, and it's what makes this an **8-bit processor**.

```
A = 10110011     ← 8 bits = 1 byte
```

---

## Instruction Set (Opcodes)

Every processor has an **instruction set** — the list of operations it can perform, and the binary codes to trigger each one.

| Assembly | Machine Code (Binary) | Description |
|----------|----------------------|-------------|
| `MOVA` | `1111 0011` | Move next data into register **A** |
| `MOVB` | `1111 0111` | Move next data into register **B** |
| `ADD` | `1100 0011` | Add A + B → store result in **A** |
| `NOP` | `1111 1111` | **No Operation** — do nothing |

The CPU doesn't understand the word `ADD`. It receives binary:

```
Assembly        Machine Code

MOVA       →    11110011
MOVB       →    11110111
ADD        →    11000011
NOP        →    11111111
```

### How MOVA works

`MOVA` sets up the processor so the **next piece of data** it receives goes into register A:

```
MOVA
   ↓
00000010      ← decimal 2
   ↓
A = 2
```

### How ADD works

`ADD` adds the values in A and B, storing the result back in A:

```
A = 5,  B = 3

ADD  →  A = A + B  →  A = 8
```

> To use `ADD`, you must first load values into A and B using `MOVA` / `MOVB`.

## ROM (Read-Only Memory)

- Stores instructions and data at **specific address locations** that the processor can fetch
- Think of ROM as a **book of instructions** for the CPU

```
ROM

Address 0 → MOVA
Address 1 → 2
Address 2 → MOVB
Address 3 → 3
Address 4 → ADD
Address 5 → NOP
```

---

## Wiring: AD Lines (Address/Data Bus)

The processor communicates with ROM via **AD0–AD7** lines:
- **8 lines** that can carry 8 bits
- **Bidirectional** — used for both:
    - **Writing out** an address (CPU → ROM: "give me data at this address")
    - **Reading in** data (ROM → CPU: "here's what's at that address")

```
CPU → ROM    (address)
ROM → CPU    (data)
```

---

## Clock Signal (CLK)

- Controls the **timing** of the CPU — its "heartbeat"
- On each clock cycle, the processor performs one step of the program
- CPU speed in MHz/GHz = clock cycles per second

```
_|‾|_|‾|_|‾|_

Clock pulse → CPU reads instruction → CPU performs operation → Next pulse
```

---

## Read/Write Signal (R/W)

Tells ROM which direction data is flowing:
- **Write mode** — CPU is sending out an **address** to ROM
- **Read mode** — CPU is reading in **data** from ROM

This prevents the bidirectional AD lines from conflicting.

---

## CPU Execution Cycle (Fetch-Decode-Execute)

The CPU repeatedly performs:

```
FETCH → DECODE → EXECUTE → FETCH → DECODE → EXECUTE ...
```

1. **Fetch** — get the instruction from memory (using IP)
2. **Decode** — understand what instruction it is
3. **Execute** — perform the operation
4. **Advance IP** — move to the next instruction

---

## Complete Example: `2 + 3`

```
MOVA → 2     →  A = 2
MOVB → 3     →  B = 3
ADD           →  ALU: 2 + 3 = 5  →  A = 5
NOP           →  (do nothing)
```

Visualized:

```
        ROM
         │
         │ instruction
         ↓
       CPU
         │
    ┌────┴─────┐
    │ Control  │
    │   Unit   │
    └────┬─────┘
         │
         ↓
      Registers
      A       B
      2       3
       \     /
        \   /
         ALU
          │
          ↓
          5
          │
          ↓
          A
```

## Quick Reference

| Component | Simple Meaning |
|-----------|---------------|
| **Control Unit** | Controls what happens |
| **ALU** | Performs calculations |
| **Register** | Tiny temporary storage inside CPU |
| **A/B/C/D** | General-purpose registers |
| **IP** | Keeps track of the instruction position |
| **ROM** | Stores instructions/data |
| **Instruction Set** | Defines what instructions the CPU understands |
| **Clock** | Provides timing |
| **AD lines** | Carry address/data (bidirectional) |
| **R/W** | Indicates read/write direction |
| **NOP** | Do nothing |

> **The CPU gets an instruction from memory, the Control Unit tells the CPU what to do, the ALU performs calculations when needed, registers temporarily hold the data, and the clock keeps everything moving step by step.**
