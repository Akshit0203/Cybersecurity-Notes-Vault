## Instruction Set (Recap)

| Instruction | Binary Code | Meaning |
|-------------|-------------|---------|
| `MOVA` | `1111 0011` | Put next data into A |
| `MOVB` | `1111 0111` | Put next data into B |
| `ADD` | `1100 0011` | A + B → A |
| `NOP` | `1111 1111` | Do nothing |

---

## The Program: Add 2 + 2

### Memory Layout

Addresses start at `1111 0000` (`F0` hex) — the **entry point**. Most real processors don't start at address 0; the entry point is typically somewhere in the middle of the address space.

| Address | Contents (Binary) | Meaning |
|---------|-------------------|---------|
| `1111 0000` | `1111 0011` | `MOVA` |
| `1111 0001` | `0000 0010` | Data: **2** |
| `1111 0010` | `1111 0111` | `MOVB` |
| `1111 0011` | `0000 0010` | Data: **2** |
| `1111 0100` | `1100 0011` | `ADD` |
| `1111 0101` | `1111 1111` | `NOP` |

In human-readable form:

```
MOVA    ← Put next value into A
2       ← A = 2
MOVB    ← Put next value into B
2       ← B = 2
ADD     ← A = A + B = 4
NOP     ← Do nothing
```

## Key Concept: Address vs Contents

> **Address = WHERE** something is stored
> **Contents = WHAT** is stored there

```
Address        Contents
1111 0000  →   1111 0011  (MOVA)
1111 0001  →   0000 0010  (data: 2)
```

**Analogy — memory is like a hotel:**

```
Room number       Person inside
101               Alice
102               Bob
```

The room number is the **address**. The person inside is the **contents**.

## Step-by-Step Execution

### Initialization

On startup, the processor sets the **Instruction Pointer (IP)** to the entry point address (`F0` = `1111 0000`).

### Step 1 — Fetch MOVA

1. IP = `F0` → CPU writes address `1111 0000` onto the AD lines (R/W = **Write**)
2. ROM receives the address and retrieves contents: `1111 0011`
3. R/W flips to **Read** → ROM sends `1111 0011` back on data lines
4. CPU decodes `1111 0011` = **MOVA** → prepares to load next data into register A

> At this point, registers don't change yet — the CPU is just set up to know the next data goes into A.

### Step 2 — Load 2 into A

1. IP increments to `F1` → CPU writes `1111 0001` to address lines
2. ROM returns `0000 0010` (decimal **2**)
3. CPU loads it into register **A**

```
A = 2
```

![](attachments/Pasted%20image%2020260929215400.png)

![](attachments/Pasted%20image%2020260929215525.png)

### Step 3 — Fetch MOVB

1. IP increments to `F2` → CPU fetches `1111 0111` = **MOVB**
2. CPU prepares to load next data into register **B**

> Nothing changes in the registers yet.

### Step 4 — Load 2 into B

1. IP increments to `F3` → CPU fetches `0000 0010` (decimal **2**)
2. CPU loads it into register **B**

```
A = 2,  B = 2
```

![](attachments/Pasted%20image%2020260929220017.png)

![](attachments/Pasted%20image%2020260929220100.png)

### Step 5 — Execute ADD

1. IP increments to `F4` → CPU fetches `1100 0011` = **ADD**
2. ALU computes: A + B = 2 + 2 = **4**
3. Result stored back in **A**

```
A = 4,  B = 2
```

![](attachments/Pasted%20image%2020260929220152.png)

### Step 6 — NOP

1. IP increments to `F5` → CPU fetches `1111 1111` = **NOP**
2. Nothing happens — registers unchanged

## Important: Clock Cycles Per Instruction

Each instruction takes **multiple clock cycles** to complete (fetch address → wait → read data). The exact number varies per processor and per instruction. This is why it takes several steps before moving to the next address.
