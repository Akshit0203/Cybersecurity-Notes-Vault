
# Keys

Keys are **special columns** in a table that serve specific roles for identifying rows and linking tables.

---

## Primary Key

A column (or set of columns) that **uniquely identifies each row** in a table.

- There is only **one** primary key per table
- Must be **unique** — no two rows can share the same value
- Must be **NOT NULL** — can never be empty

**Examples of good primary keys:** Roll number (unique per student), Employee ID (unique per employee).

**Bad primary key choices:** Name (two people can share a name), Salary (two employees can earn the same).

---

## Foreign Key

A column (or set of columns) that **refers to the primary key of another table**.

- There can be **multiple** foreign keys in a table
- Can have **duplicate** values
- Can have **NULL** values

> The word "foreign" here means "of another table" — it's a column that exists in *this* table but is actually the primary key of *some other* table.

---

## Example: Student & City Tables

![](../Apna%20College%20Youtube/attachments/Pasted%20image%2020260724144359.png)

- In the **City** table → `id` is the **primary key** (unique, not null)
- In the **Student** table → `student_id` is the **primary key**
- In the **Student** table → `city_id` is a **foreign key** (references `id` from the City table)

`city_id` can repeat in the Student table (e.g., multiple students from Pune) because it only needs to be unique in its *own* table (City), not in the table referencing it (Student).

---

## Primary Key vs Foreign Key

| Property | Primary Key | Foreign Key |
| --- | --- | --- |
| Count per table | Only **one** | Can be **multiple** |
| Uniqueness | Must be **unique** | Can have **duplicates** |
| NULL allowed | **No** | **Yes** |
| Purpose | Identify rows in *this* table | Reference rows in *another* table |
