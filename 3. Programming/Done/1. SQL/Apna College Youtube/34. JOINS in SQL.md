
# JOINS in SQL

A **JOIN** combines rows from two or more tables based on a related column between them.

![481](attachments/Pasted%20image%2020260823233443.png)

![](attachments/Pasted%20image%2020260823234015.png)

> A foreign key is **not required** to perform a join — any two tables with a related/common column can be joined.

---

## Types of Joins

| Type | What It Returns |
| --- | --- |
| **Inner Join** | Only rows with matching values in **both** tables |
| **Left Join** | **All** rows from the left table + matched rows from the right |
| **Right Join** | **All** rows from the right table + matched rows from the left |
| **Full Join** | **All** rows from both tables (matched + unmatched) |
| **Left Exclusive** | Rows **only** in the left table (no match in right) |
| **Right Exclusive** | Rows **only** in the right table (no match in left) |
| **Cross Join** | Every row of one table paired with every row of the other (Cartesian product) |
| **Self Join** | A table joined **with itself** |

## Inner Join

![](attachments/Pasted%20image%2020260823233959.png)

Returns **only** the rows that have matching values in **both** tables.

> In an Inner Join the **order of tables does not matter** — `A INNER JOIN B` and `B INNER JOIN A` give the same result. This is **not true** for Left/Right Joins.

### Syntax

```sql
SELECT column(s)
FROM tableA
INNER JOIN tableB
ON tableA.col_name = tableB.col_name;
```

- `ON` specifies the **join condition** — the column from each table whose values must be equal for rows to match.
- Use the **dot operator** (`table.column`) to distinguish columns when names could be ambiguous.

### Example — student ⟕ course

```sql
SELECT *
FROM student
INNER JOIN course
ON student.id = course.id;
```

![](attachments/Pasted%20image%2020260825211841.png)

Only IDs `102` and `103` exist in **both** tables, so only those rows appear in the result — combined into one row with columns from both tables.

> The joined columns **don't need the same name**. If the course table had `course_id` instead of `id`, you'd simply write `ON student.id = course.course_id`.

### Using Aliases

**Aliases** (`AS`) give tables short nicknames, making queries easier to read:

```sql
SELECT *
FROM student AS s
INNER JOIN course AS c
ON s.id = c.id;
```

The result is identical — `s` refers to `student`, `c` refers to `course`.

### Additional Example — Customers & Orders

| CustomerID | CustomerName |
| --- | --- |
| 1 | Alice |
| 2 | Bob |
| 3 | Carol |

| OrderID | CustomerID | Product |
| --- | --- | --- |
| 101 | 1 | Laptop |
| 102 | 3 | Smartphone |
| 103 | 2 | Headphones |

```sql
SELECT Customers.CustomerName, Orders.Product
FROM Customers
INNER JOIN Orders ON Customers.CustomerID = Orders.CustomerID;
```

| CustomerName | Product |
| --- | --- |
| Alice | Laptop |
| Bob | Headphones |
| Carol | Smartphone |

## Left Join (Left Outer Join)

![](attachments/Pasted%20image%2020260823234105.png)

![](attachments/Pasted%20image%2020260825212906.png)

Returns **all** rows from the **left** table, plus matched rows from the right table. Where there is no match, the right-side columns are filled with `NULL`.

> **Order matters!** The table after `FROM` is the **left** table; the table after `LEFT JOIN` is the **right** table.

### Syntax

```sql
SELECT column(s)
FROM tableA
LEFT JOIN tableB
ON tableA.col_name = tableB.col_name;
```

### Example — student ⟕ course

![](attachments/Pasted%20image%2020260825212954.png)

```sql
SELECT *
FROM student AS s
LEFT JOIN course AS c
ON s.id = c.id;
```

![](attachments/Pasted%20image%2020260825213104.png)

All three students (`101`, `102`, `103`) appear. Adam (`101`) has no matching course, so the course columns show `NULL`.

### Additional Example — Customers & Orders

```sql
SELECT Customers.CustomerName, Orders.Product
FROM Customers
LEFT JOIN Orders ON Customers.CustomerID = Orders.CustomerID;
```

| CustomerName | Product |
| --- | --- |
| Alice | Laptop |
| Bob | Headphones |
| Carol | Smartphone |
| NULL | Monitor |

Rows from the left table with no match get `NULL` in the right-side columns.

## Right Join (Right Outer Join)

![](attachments/Pasted%20image%2020260825213952.png)

Returns **all** rows from the **right** table, plus matched rows from the left table. Where there is no match, the left-side columns are filled with `NULL`.

### Syntax

```sql
SELECT column(s)
FROM tableA
RIGHT JOIN tableB
ON tableA.col_name = tableB.col_name;
```

### Example — student ⟕ course

![](attachments/Pasted%20image%2020260825214027.png)

```sql
SELECT *
FROM student AS a
RIGHT JOIN course AS b
ON a.id = b.id;
```

![](attachments/Pasted%20image%2020260825215152.png)

All four courses appear. IDs `105` and `107` have no matching student, so the student columns show `NULL`.

### Additional Example — Customers & Orders

```sql
SELECT Customers.CustomerName, Orders.Product
FROM Customers
RIGHT JOIN Orders ON Customers.CustomerID = Orders.CustomerID;
```

| CustomerName | Product |
| --- | --- |
| Alice | Laptop |
| Carol | Smartphone |
| Bob | Headphones |
| NULL | Keyboard |

> **Left vs Right — when to use which?**
> - Need **all** data from the left table → `LEFT JOIN`
> - Need **all** data from the right table → `RIGHT JOIN`

## Full Join (Full Outer Join)

![](attachments/Pasted%20image%2020260823234201.png)

Returns **all** rows from **both** tables — matched rows are combined; unmatched rows get `NULL` in the missing columns.

> **MySQL does not have a `FULL JOIN` keyword.** Other databases (PostgreSQL, Oracle) support `FULL OUTER JOIN` directly. In MySQL we emulate it with `LEFT JOIN UNION RIGHT JOIN`.

### Syntax (MySQL workaround)

```sql
SELECT ... FROM A LEFT JOIN B ON ...
UNION
SELECT ... FROM A RIGHT JOIN B ON ...;
```

`UNION` combines the results and **removes duplicates** automatically.

### Example — student ⟕ course

![](attachments/Pasted%20image%2020260825215607.png)

```sql
SELECT *
FROM student AS a
LEFT JOIN course AS b
ON a.id = b.id
UNION
SELECT *
FROM student AS a
RIGHT JOIN course AS b
ON a.id = b.id;
```

![](attachments/Pasted%20image%2020260825215856.png)

All five IDs (`101`–`103`, `105`, `107`) appear. Names and courses are filled where available; `NULL` elsewhere.

### Additional Example — Customers & Orders

```sql
SELECT Customers.CustomerName, Orders.Product
FROM Customers
FULL OUTER JOIN Orders ON Customers.CustomerID = Orders.CustomerID;
```

| CustomerName | Product |
| --- | --- |
| Alice | Laptop |
| Bob | Headphones |
| Carol | Smartphone |
| NULL | Monitor |
| NULL | Keyboard |

## Exclusive Joins

![](attachments/Pasted%20image%2020260825220548.png)

Exclusive joins return rows that exist in **only one** table and have **no match** in the other. There is no dedicated keyword — they are built by adding a `WHERE … IS NULL` filter to a Left or Right Join.

### Left Exclusive Join

Returns rows from the **left** table that have **no match** in the right table.

**How it works:** In a Left Join, unmatched right-table columns are `NULL`. Filtering on `WHERE right_table.id IS NULL` keeps only those exclusive rows.

> Use `IS NULL`, not `= NULL` — the `=` operator does not work with `NULL` values.

```sql
SELECT *
FROM student AS a
LEFT JOIN course AS b
ON a.id = b.id
WHERE b.id IS NULL;
```

![](attachments/Pasted%20image%2020260825220642.png)

Only Adam (`101`) appears — he is the only student with no matching course.

### Right Exclusive Join

Returns rows from the **right** table that have **no match** in the left table.

```sql
SELECT *
FROM student AS a
RIGHT JOIN course AS b
ON a.id = b.id
WHERE a.id IS NULL;
```

![](attachments/Pasted%20image%2020260825220849.png)

Only IDs `105` and `107` appear — they are courses with no matching student.

## Cross Join

A **Cross Join** (Cartesian Product) pairs **every** row from one table with **every** row from the other — no join condition needed.

> ⚠️ Cross joins can produce very large result sets: `m × n` rows for tables of size `m` and `n`.

### Syntax

```sql
SELECT columns
FROM table1
CROSS JOIN table2;
```

### Example — Students & Courses

| StudentID | StudentName |
| --- | --- |
| 1 | Alice |
| 2 | Bob |

| CourseID | CourseName |
| --- | --- |
| 101 | Maths |
| 102 | Science |

```sql
SELECT Students.StudentName, Courses.CourseName
FROM Students
CROSS JOIN Courses;
```

| StudentName | CourseName |
| --- | --- |
| Alice | Maths |
| Alice | Science |
| Bob | Maths |
| Bob | Science |

Each student is paired with each course → 2 × 2 = 4 rows.

## Self Join

A **Self Join** joins a table **with itself**. It is not a separate keyword — you use a regular `JOIN` but reference the same table twice with different aliases.

> **Aliases are mandatory** in a Self Join because you need two references to the same table.

### Syntax

```sql
SELECT column(s)
FROM table_name AS a
JOIN table_name AS b
ON a.col_name = b.col_name;
```

### Use Case — Employee-Manager Hierarchy

![](attachments/Pasted%20image%2020260825221826.png)

**Setup:**

```sql
CREATE TABLE employee(
	id INT PRIMARY KEY,
	name VARCHAR(50),
	manager_id INT
);

INSERT INTO employee (id, name, manager_id)
VALUES
(101, "adam", 103),
(102, "bob", 104),
(103, "casey", NULL),
(104, "donald", 103);
```

```sql
SELECT * FROM employee;
```

![](attachments/Pasted%20image%2020260825222108.png)

**Hierarchy:**
- Adam (`101`) → manager Casey (`103`)
- Bob (`102`) → manager Donald (`104`)
- Casey (`103`) → no manager (`NULL`)
- Donald (`104`) → manager Casey (`103`)

**Step 1 — Raw Self Join (all columns):**

```sql
SELECT *
FROM employee AS a
JOIN employee AS b
ON a.id = b.manager_id;
```

![](attachments/Pasted%20image%2020260825222217.png)

**Step 2 — Clean output (manager name + employee name):**

```sql
SELECT a.name AS manager_name, b.name
FROM employee AS a
JOIN employee AS b
ON a.id = b.manager_id;
```

![](attachments/Pasted%20image%2020260825222441.png)

| manager_name | name |
| --- | --- |
| Casey | Adam |
| Donald | Bob |
| Casey | Donald |

> Use a Self Join whenever **both sides of a relationship live in the same table** (e.g., employee ↔ manager, category ↔ parent category).

### Additional Example — Employees Table

| EmployeeID | EmployeeName | ManagerID |
| --- | --- | --- |
| 1 | Alice | 3 |
| 2 | Bob | 3 |
| 3 | Carol | NULL |
| 4 | David | 1 |

```sql
SELECT e1.EmployeeName AS Employee, e2.EmployeeName AS Manager
FROM Employees AS e1
JOIN Employees AS e2 ON e1.ManagerID = e2.EmployeeID;
```

| Employee | Manager |
| --- | --- |
| Alice | Carol |
| Bob | Carol |
| David | Alice |
