
# UNION in SQL

`UNION` combines the result sets of two or more `SELECT` statements into a **single result set**, returning only **unique** rows.

---

## Rules for Using UNION

1. Every `SELECT` must have the **same number of columns**
2. Columns must have **similar data types**
3. Columns must be in the **same order** across all `SELECT` statements

---

## Syntax

```sql
SELECT column(s) FROM tableA
UNION
SELECT column(s) FROM tableB;
```

---

## UNION vs UNION ALL

| Operator | Duplicates? | Description |
| --- | --- | --- |
| `UNION` | ❌ Removed | Returns only **unique** rows |
| `UNION ALL` | ✅ Kept | Returns **all** rows including duplicates |

### Example — UNION (unique rows)

```sql
SELECT name FROM employee
UNION
SELECT name FROM employee;
```

![](attachments/Pasted%20image%2020260825223110.png)

Since both sides are the same table, `UNION` removes duplicates — each name appears only once.

### Example — UNION ALL (with duplicates)

```sql
SELECT name FROM employee
UNION ALL
SELECT name FROM employee;
```

![](attachments/Pasted%20image%2020260825223254.png)

`UNION ALL` keeps duplicates — each name appears twice (once from each SELECT).

> `UNION` is commonly used to perform a **Full Join in MySQL**, by combining a `LEFT JOIN` and a `RIGHT JOIN`.

---

## All Set Operations in SQL

| Operation | What It Returns |
| --- | --- |
| `UNION` | All unique rows from both result sets |
| `UNION ALL` | All rows (including duplicates) from both result sets |
| `INTERSECT` | Only rows **common** to both result sets |
| `EXCEPT` / `MINUS` | Rows in the **first** result set that are **not** in the second |

### INTERSECT Example

```sql
SELECT CustomerName FROM Customers
INTERSECT
SELECT SupplierName FROM Suppliers;
```

Returns only names that appear in **both** tables. If none match → empty result.

### EXCEPT Example

```sql
SELECT CustomerName FROM Customers
EXCEPT
SELECT SupplierName FROM Suppliers;
```

Returns names from `Customers` that are **not** in `Suppliers`.

## Set Operations vs Joins

| Aspect | Set Operations | Joins |
| --- | --- | --- |
| **Purpose** | Combine result sets based on set theory | Combine data from related tables on a condition |
| **Data Source** | Result sets of `SELECT` queries | Tables related by common columns |
| **Duplicates** | `UNION` removes duplicates by default | Joins don't inherently handle duplicates |
| **Column Rules** | Same number of columns, compatible data types | Can combine different column counts and types |
| **Conditions** | No join condition required | Requires a join condition (`ON …`) |
| **Performance** | Generally faster and simpler | Can be more resource-intensive on large datasets |
