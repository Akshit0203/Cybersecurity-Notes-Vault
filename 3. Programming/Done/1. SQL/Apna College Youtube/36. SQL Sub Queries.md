
# SQL Sub Queries

A **subquery** (also called an inner query or nested query) is a query written **inside another SQL query**. It involves two `SELECT` statements — the inner one provides data to the outer one.

![](attachments/Pasted%20image%2020260825224220.png)

---

## Where Can Subqueries Be Written?

| Location | Usage |
| --- | --- |
| Inside `WHERE` | ✅ **Most common** — filter rows based on a dynamic value |
| Inside `FROM` | Treat the subquery result as a temporary table |
| Inside `SELECT` | Add a computed column (must return exactly **one** value) |

---

## Syntax (Subquery in WHERE)

```sql
SELECT column(s)
FROM table_name
WHERE col_name operator
( subquery );
```

The **inner subquery runs first** and returns a value (or set of values), which the **outer query** then uses for comparison.

## Example 1 — Subquery in WHERE (Class Average)

**Goal:** Get names of all students who scored more than the class average.

![](attachments/Pasted%20image%2020260825225739.png)

### Step-by-step approach

**Step 1 — Find the class average:**

```sql
SELECT AVG(marks)
FROM student;
```

![](attachments/Pasted%20image%2020260825225838.png)

Average = `87.6667`

**Step 2 — Find students above that average (hardcoded):**

```sql
SELECT name , marks
FROM student
WHERE marks > 87.6667;
```

![](attachments/Pasted%20image%2020260826083656.png)

### Problem with hardcoding

If a new student joins or marks are updated, the average changes — you'd have to recalculate and rewrite the query manually.

### Dynamic solution with a subquery

```sql
SELECT name , marks
FROM student
WHERE marks > (SELECT AVG(marks) FROM student);
```

![](attachments/Pasted%20image%2020260826083924.png)

The inner query dynamically calculates the current average every time, so the outer query always returns the correct students — no manual updates needed.

## Example 2 — Subquery with IN (Even Roll Numbers)

**Goal:** Find the names of all students with even roll numbers.

### Step-by-step approach

**Step 1 — Find even roll numbers** (using modulo `%`):

```sql
SELECT rollno
FROM student
WHERE rollno % 2 = 0;
```

Returns: `102, 104, 106`

**Step 2 — Get names for those roll numbers:**

### Dynamic solution with a subquery

Use the `IN` operator with the subquery replacing the hardcoded list:

```sql
SELECT name , rollno
FROM student
WHERE rollno IN (
SELECT rollno
FROM student
WHERE rollno % 2 = 0);
```

## Example 3 — Subquery in FROM

**Goal:** Find the max marks from students of Delhi.

![](attachments/Pasted%20image%2020260826084832.png)

**Step 1 — Get Delhi students:**

```sql
SELECT *
FROM student
WHERE city = "Delhi";
```

![](attachments/Pasted%20image%2020260826085012.png)

**Step 2 — Find max marks from that subset:**

```sql
SELECT MAX(marks)
FROM (SELECT * FROM student WHERE city = "Delhi") AS temp;
```

![](attachments/Pasted%20image%2020260826090044.png)

> When using a subquery in `FROM`, you **must** give it an alias (e.g., `AS temp`). The outer query needs a name to reference the virtual temporary table.

### Simpler alternative (using WHERE directly)

```sql
SELECT MAX(marks)
FROM student
WHERE city = "Mumbai";
```

![](attachments/Pasted%20image%2020260826090254.png)

## Example 4 — Subquery in SELECT

A subquery in `SELECT` adds a computed column to every row:

```sql
SELECT (SELECT MAX(marks) FROM student), name
FROM student;
```

![](attachments/Pasted%20image%2020260826090412.png)

This prints the class maximum alongside every student's name.

> ⚠️ A subquery in `SELECT` **must return exactly one value** (a scalar). If it returns multiple rows, MySQL throws: `Error Code: 1242. Subquery returns more than 1 row`.

## Additional Example — Products & Orders

| ProductID | ProductName | Price |
| --- | --- | --- |
| 1 | Laptop | 1000 |
| 2 | Smartphone | 500 |
| 3 | Headphones | 50 |

| OrderID | ProductID | Quantity |
| --- | --- | --- |
| 101 | 1 | 2 |
| 102 | 3 | 1 |

**Goal:** Retrieve product names where `Price × Quantity > average price`:

```sql
SELECT ProductName, Quantity
FROM Products
WHERE Price * Quantity > (SELECT AVG(Price) FROM Products);
```

| ProductName | Quantity |

## Subqueries vs Joins

| Aspect | Subqueries | Joins |
| --- | --- | --- |
| **Purpose** | Filter, compare, or calculate within a larger query | Combine data from related tables |
| **Result set** | Scalar values, single-column, or small sets | Multi-column result sets |
| **Performance** | Can be slower on large datasets | More efficient for combining multiple tables |
| **Complexity** | Easier for simple, step-by-step tasks | Better suited for large-scale data retrieval |
| **Versatility** | Usable in `WHERE`, `FROM`, `SELECT`, `HAVING` | Primarily used in `FROM` clause |
