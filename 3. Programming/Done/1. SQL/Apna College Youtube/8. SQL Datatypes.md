
# SQL Datatypes

Data types define the kind of data that can be stored in a column.

> Full reference: [MySQL Data Types Documentation](https://dev.mysql.com/doc/refman/8.0/en/data-types.html)

![](attachments/Pasted%20image%2020260723190859.png)

## Character / String Types

### `CHAR` vs `VARCHAR`

Both store strings of size 0–255 characters.

| Type | Storage | Use Case |
| --- | --- | --- |
| `CHAR(50)` | **Fixed length** — always reserves 50 bytes, even for short strings | When all values have the same length (e.g., country codes) |
| `VARCHAR(50)` | **Variable length** — uses only as much space as needed | **Preferred** — more memory-efficient |

![](attachments/Pasted%20image%2020260723191305.png)

**Example:** Storing "Pune" (4 characters) in `CHAR(50)` reserves 50 bytes. In `VARCHAR(50)`, it only uses 4 bytes.

![](attachments/Pasted%20image%2020260723191408.png)

> **Always prefer `VARCHAR`** for storing strings — it's more efficient.

### `BLOB`

Stores **large binary objects** (e.g., file data). Size: 0–65,535 bytes.

```sql
BLOB(size)
```

## Numeric Types

| Type        | Range                           | Use Case          |
| ----------- | ------------------------------- | ----------------- |
| `INT`       | -2,147,483,648 to 2,147,483,647 | Standard integers |
| `TINYINT`   | -128 to 127                     | Small integers    |
| `MEDIUMINT` | ~-8.3M to ~8.3M                 | Medium integers   |
| `BIGINT`    | Very large range                | Large integers    |
| `BIT(x)`    | x-bit value (x = 1 to 64)       | Store bit flags   |

![](attachments/Pasted%20image%2020260723191635.png)

### `BIT` Examples

- `BIT(1)` → stores `0` or `1`
- `BIT(2)` → stores `00`, `01`, `10`, or `11`

![](attachments/Pasted%20image%2020260723191655.png)

## Decimal Types

| Type     | Precision        | Use Case                               |
| -------- | ---------------- | -------------------------------------- |
| `FLOAT`  | Up to 23 digits  | Standard decimal values (e.g., `12.5`) |
| `DOUBLE` | Larger precision | Large decimal values                   |

## Boolean

```sql
BOOLEAN
```

Stores `TRUE` (1) or `FALSE` (0).

> In MySQL, `BOOLEAN` is internally implemented as `TINYINT` — 0 = false, 1 = true.

## Date / Time Types

| Type | Format | Example |
| --- | --- | --- |
| `DATE` | `YYYY-MM-DD` | `2026-07-23` |
| `DATETIME` | `YYYY-MM-DD HH:MM:SS` | `2026-07-23 19:30:00` |
| `YEAR` | `YYYY` | `2026` |
| `TIME` | `HH:MM:SS` | `19:30:00` |

## Signed vs Unsigned

By default, numeric types are **signed** (allow both negative and positive values).

If you know a column will only have **positive values** (e.g., age, salary), use `UNSIGNED` to **double the positive range**:

| Type | Signed Range | Unsigned Range |
| --- | --- | --- |
| `TINYINT` | -128 to 127 | 0 to 255 |
| `INT` | -2.1B to 2.1B | 0 to 4.2B |

![](attachments/Pasted%20image%2020260723193039.png)

```sql
age TINYINT UNSIGNED    -- Can store 0 to 255
salary INT UNSIGNED     -- Can store 0 to 4,294,967,295
```

## Quick Reference

| Type | For | Example |
| --- | --- | --- |
| `VARCHAR(n)` | Variable-length strings | `name VARCHAR(50)` |
| `CHAR(n)` | Fixed-length strings | `code CHAR(3)` |
| `INT` | Whole numbers | `age INT` |
| `FLOAT` | Decimal numbers | `gpa FLOAT` |
| `BOOLEAN` | True/False | `is_active BOOLEAN` |
| `DATE` | Dates | `dob DATE` |
| `BLOB` | Large binary data | `file_data BLOB(1000)` |

> **Note:** `CHAR` = fixed length, `VARCHAR` = variable length. Use `UNSIGNED` with numeric types when only positive values are needed.
