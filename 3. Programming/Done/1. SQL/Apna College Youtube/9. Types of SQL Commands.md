
# Types of SQL Commands

All SQL commands are classified into **five categories**:

| Category | Full Form | Purpose | Key Commands |
| --- | --- | --- | --- |
| **DDL** | Data Definition Language | Define/modify database structure | `CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE` |
| **DQL** | Data Query Language | Retrieve/read data | `SELECT` |
| **DML** | Data Manipulation Language | Insert, update, delete data | `INSERT`, `UPDATE`, `DELETE` |
| **DCL** | Data Control Language | Manage user permissions | `GRANT`, `REVOKE` |
| **TCL** | Transaction Control Language | Manage transactions | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

> For exams (CEH, CPTS, OSCP): `SELECT` belongs to **DQL**, not DML. Some older textbooks group `SELECT` under DML, but the modern classification separates them.

---

# 1. DDL (Data Definition Language)

DDL commands define and manage the **structure** of databases and their objects (tables, indexes, constraints).

### `CREATE TABLE`

Creates a new table.

```sql
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    salary DECIMAL(10, 2)
);
```

### `ALTER TABLE`

Modifies the structure of an existing table (add/modify/drop columns, constraints).

```sql
ALTER TABLE employees ADD COLUMN email VARCHAR(100);
```

### `DROP TABLE`

Deletes an entire table along with its data.

```sql
DROP TABLE employees;
```

### `TRUNCATE TABLE`

Deletes **all data** inside a table but keeps the table structure.

```sql
TRUNCATE TABLE employees;
```

> **DROP** = delete table + data. **TRUNCATE** = delete data only, keep table.

### `CREATE INDEX` / `DROP INDEX`

Create or remove an index for faster queries.

```sql
CREATE INDEX idx_employee_name ON employees (name);
DROP INDEX idx_employee_name;
```

### `CREATE CONSTRAINT` / `DROP CONSTRAINT`

Define or remove constraints (PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK).

```sql
ALTER TABLE orders ADD CONSTRAINT fk_customer
    FOREIGN KEY (customer_id) REFERENCES customers(id);

ALTER TABLE orders DROP CONSTRAINT fk_customer;
```

# 2. DQL (Data Query Language)

DQL retrieves data from the database. The core command is `SELECT`.

### `SELECT`

```sql
SELECT column1, column2 FROM table_name;
SELECT * FROM table_name;  -- All columns
```

Example:

```sql
SELECT CustomerName, City FROM Customers;
```

### `WHERE` — Filter Records

```sql
SELECT * FROM Customers WHERE Country = 'Mexico';
```

| Operator | Meaning |
| --- | --- |
| `=` | Equal |
| `>` / `<` | Greater / Less than |
| `>=` / `<=` | Greater/Less than or equal |
| `<>` or `!=` | Not equal |

### `AND`, `OR`, `NOT`

Combine multiple conditions in `WHERE`:

```sql
SELECT * FROM Customers WHERE Country = 'India' AND City = 'Delhi';
SELECT * FROM Customers WHERE Country = 'America' AND (City = 'India' OR City = 'Korea');
SELECT * FROM Customers WHERE NOT Country = 'Germany';
```

- `AND` — All conditions must be TRUE
- `OR` — Any condition can be TRUE
- `NOT` — Inverts the condition

### `DISTINCT` — Remove Duplicates

```sql
SELECT DISTINCT column1, column2 FROM table_name;
```

### `LIKE` — Pattern Matching

Uses wildcards: `%` (zero or more characters) and `_` (exactly one character).

```sql
SELECT * FROM employees WHERE first_name LIKE 'J%';
```

| Pattern | Matches |
| --- | --- |
| `'a%'` | Starts with "a" |
| `'%a'` | Ends with "a" |
| `'%or%'` | Contains "or" anywhere |
| `'_r%'` | Has "r" in the second position |
| `'a_%'` | Starts with "a", at least 2 chars |
| `'a__%'` | Starts with "a", at least 3 chars |
| `'a%o'` | Starts with "a", ends with "o" |

### `IN` — Match from a List

```sql
SELECT * FROM products WHERE category_id IN (1, 2, 3);
```

### `BETWEEN` — Range Filter

```sql
SELECT * FROM orders WHERE order_date BETWEEN '2023-01-01' AND '2023-06-30';
```

### `IS NULL` — Check for NULL

```sql
SELECT * FROM customers WHERE email IS NULL;
```

### `AS` — Alias (Rename Columns)

```sql
SELECT first_name AS "First Name", last_name AS "Last Name" FROM employees;
```

### `ORDER BY` — Sort Results

```sql
SELECT product_name, price FROM products ORDER BY price DESC;
```

- Default: ascending (`ASC`)
- Use `DESC` for descending

Sort by multiple columns:

```sql
SELECT first_name, last_name FROM employees ORDER BY last_name, first_name;
```

Sort by position:

```sql
SELECT product_name, price FROM products ORDER BY 2 DESC, 1 ASC;
```

### `GROUP BY` — Group Rows

Groups rows and applies aggregate functions to each group.

```sql
SELECT department, AVG(salary) FROM employees GROUP BY department;
```

Group by multiple columns:

```sql
SELECT department, gender, AVG(salary) FROM employees GROUP BY department, gender;
```

### `HAVING` — Filter Groups

Like `WHERE`, but for **grouped** data (works with aggregate functions):

```sql
SELECT department, AVG(salary) FROM employees
GROUP BY department HAVING AVG(salary) > 50000;
```

Combine with `ORDER BY`:

```sql
SELECT department, COUNT(*) FROM employees
GROUP BY department ORDER BY COUNT(*) DESC;
```

### Aggregate Functions

| Function | Purpose |
| --- | --- |
| `COUNT()` | Count rows |
| `SUM()` | Sum of numeric values |
| `AVG()` | Average of numeric values |
| `MAX()` | Maximum value |
| `MIN()` | Minimum value |

# 3. DML (Data Manipulation Language)

DML commands manipulate the **data** within tables.

### `INSERT`

```sql
INSERT INTO employees (first_name, last_name, salary) VALUES ('John', 'Doe', 50000);
```

### `UPDATE`

```sql
UPDATE employees SET salary = 55000 WHERE first_name = 'John';
```

### `DELETE`

```sql
DELETE FROM employees WHERE last_name = 'Doe';
```

---

# 4. DCL (Data Control Language)

DCL manages **access rights and permissions** — controls who can access what.

### `GRANT`

```sql
GRANT SELECT ON Employees TO Analyst;
```

Gives the `Analyst` user permission to `SELECT` from the `Employees` table.

### `REVOKE`

```sql
REVOKE SELECT ON Employees FROM Analyst;
```

Removes the `SELECT` permission from the `Analyst` user.

# 5. TCL (Transaction Control Language)

TCL manages **transactions** — groups of SQL statements executed as a single unit.

### `COMMIT`

Permanently saves all changes made during a transaction.

```sql
UPDATE Employees SET Salary = Salary * 1.10 WHERE Department = 'Sales';
COMMIT;
```

### `ROLLBACK`

Undoes all changes since the transaction began (used when errors occur).

```sql
BEGIN;
UPDATE Inventory SET Quantity = Quantity - 10 WHERE ProductID = 101;
-- An error occurs here
ROLLBACK;
```

### `SAVEPOINT`

Creates a named checkpoint within a transaction. You can `ROLLBACK TO` a savepoint without undoing everything.

```sql
BEGIN;
UPDATE Accounts SET Balance = Balance - 100 WHERE AccountID = 123;
SAVEPOINT before_withdrawal;
UPDATE Accounts SET Balance = Balance + 100 WHERE AccountID = 456;
-- An error occurs here
ROLLBACK TO before_withdrawal;
-- The first update is still applied
COMMIT;
```

## `SELECT` Classification Note

| Command | Reads Data | Changes Data |
| --- | --- | --- |
| `SELECT` | ✅ Yes | ❌ No |
| `INSERT` | ❌ No | ✅ Yes |
| `UPDATE` | ❌ No | ✅ Yes |
| `DELETE` | ❌ No | ✅ Yes |

`SELECT` does not modify data — that's why the modern classification puts it in **DQL** (separate from DML).
