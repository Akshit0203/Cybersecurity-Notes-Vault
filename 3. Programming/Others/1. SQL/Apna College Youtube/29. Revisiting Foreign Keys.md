
# Revisiting Foreign Keys

A **foreign key** in one table references the **primary key** of another table, creating a link between them.

---

## Setting Up Linked Tables

### Department Table (Parent)

```sql
CREATE TABLE dept (
	id INT PRIMARY KEY,
	name VARCHAR(50)
);
```

### Teacher Table (Child)

```sql
CREATE TABLE teacher (
	id INT PRIMARY KEY,
	name VARCHAR(50),
	dept_id INT,
	FOREIGN KEY (dept_id) REFERENCES dept(id)
);
```

## How the Link Works

Consider two tables — `dept` and `teacher`:

| dept.id | dept.name |
| --- | --- |
| 101 | Science |
| 102 | English |
| 103 | Hindi |

| teacher.id | teacher.name | dept_id (FK) |
| --- | --- | --- |
| 101 | Adam | 101 |
| 102 | Bob | 103 |
| 103 | Casey | 102 |
| 104 | Donald | 102 |

- `dept_id` in the teacher table is a **foreign key** referencing `dept(id)`.
- Each teacher's `dept_id` must match an existing `id` in the `dept` table.

---

## Parent Table vs Child Table

| Term | Definition |
| --- | --- |
| **Parent Table** | The table whose **primary key** is being referenced (`dept`) |
| **Child Table** | The table that contains the **foreign key** (`teacher`) |

> The primary key from the Parent Table goes into the Child Table and becomes a foreign key — similar to how traits transfer down a hierarchy.

## EER Diagrams (Entity Relationship Diagrams)

You can visualize foreign key relationships in **MySQL Workbench**:

1. Go to **Database → Reverse Engineer**
2. Select your database and click through the wizard
3. An **EER Diagram** appears showing all tables and their connections

![](attachments/Pasted%20image%2020260823203440.png)

> The arrow between tables in the EER Diagram represents the **foreign key** connection linking them together.
