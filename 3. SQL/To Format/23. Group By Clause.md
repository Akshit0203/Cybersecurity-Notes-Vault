# Group By Clause

Groups rows that have the same values into summary rows.
It collects data from multiple records and groups the result by one or more column.

*Generally we use group by with some aggregation function.



```
SELECT city
FROM student
GROUP BY city;
```

```
SELECT city , count(rollno)
FROM student
GROUP BY city;
```

```
SELECT city , name, count(rollno)
```

**Chapter: Group By Clause** [01:32:33]

"Now next, we are going to talk about another clause, which is our **Group By Clause**.

So until now, we have seen Where, we have seen Order By, we have seen the Limit Clause. There is another very famous clause of ours, the **Group By Clause**. The job of the Group By Clause is **to retrieve things by grouping them**. If we want things collected together in a group, in a cluster, then we use this clause for that. What does it do? **It groups our rows**. Such rows upon which some same value exists.

For example, let's suppose we can have an example where **we want the count of how many students are there inside all of our cities**. So for that, we will use the Group By Clause, and **on what basis will we group? We will group on the basis of our cities**. Basically, the Group By Clause says that whenever you have to make groups—like in this case, we have to make groups such that we want students' marks from each city—so what will we do? We will make a group of the first city, say Pune, so that all the kids inside Pune, their marks can come. Then we can make our group according to Delhi city, then we can make our group according to Mumbai city. So in this way, we will make groups, and then on these groups, we will individually perform some operations.

So what does it do? **'It collects data from multiple records and groups the result by one or more columns.'** Meaning, according to whichever column we have to make the group—here, on the basis of which column will the group be formed? Here, it will be formed on the basis of our city column, and three groups will be made. Now, sometimes it might happen that we have to make a group based on city and country, or city and marks, but generally, we make groups according to a single column. So when we have made a group according to one column, we get multiple summary groups—meaning, in this one, all Pune kids; in this one, all Delhi kids; in this one, all Mumbai kids.

But **whenever we use the Group By Clause, generally along with it, we also use aggregate functions**, those aggregate functions which we have already studied. For example, if we have to calculate the count of how many students of ours are studying inside all of the cities, then for that, we will also use our `count` aggregate function and we will also use our Group By Clause. So, to retrieve this information, we can write:

```
SELECT city, COUNT(name) FROM student GROUP BY city;
```

So let's understand this statement once slowly—how Group By works. We can write... let's remove this... first of all, we will write:

```
SELECT city FROM student GROUP BY city;
```

So we wrote this much statement. On selecting and executing this statement, we will get three cities—indicating that one group of ours was formed for Pune, one group was formed for Mumbai, and one group was formed for Delhi. Since there are three cities, we selected all of the cities and we grouped them based on their city value.

Now along with this, if we want the count of how many students are studying inside each city, then we can either take the count of roll numbers or take the count of names—both are valid. So what will we do? We want the count of how many students are studying inside each city, so that will come to us... let's execute this.

So this has formed one column of ours for `city`, inside which all the cities are coming, and the second column is formed for `COUNT(roll_no)`. That is telling us that **our Delhi city has three students inside it, our Mumbai city has two students inside it, and our Pune city has one student inside it**.

So what exactly happened here? Here, **Group By made groups on the basis of cities**. So, from the cities column we selected, we can form groups, and there we took the count of all of our roll numbers that were available inside that city.

Now, **there is one more special thing in Group By**: whichever columns we write here as normal columns (upon which we have not applied any aggregate function), **we must write at least those many columns inside the Group By clause**. For example, if we had written `city` and `name` here, then we would have got an error. The error would come because this `name`, we did not use it inside the Group By. So we got this error here; the error code is `1055`. If you want, whenever an error comes in SQL, you can directly search "MySQL error code 1055", and the complete description of that error will come to us on Google.

So its basic meaning is that **whenever we are forming groups with an aggregate function, then apart from the aggregate function, whichever columns we have selected, we have to form groups on the basis of all of those columns**. So if we are making groups on the basis of city, we can only select city for our group, and then we will have to make a group on the basis of that.

But if, let's suppose, we wrote `name` here, then we could write both `city` and `name` here [in GROUP BY]. Let's select and execute this. So what happened this time? The group was formed on the basis of both city and name. So we got one group inside which there are Pune and Anil both, so there is only one student in it. Then Mumbai and Bhumika, there is also only one student in it. Then Mumbai and Chetan is there, in which there is also only one student.

But here, if it were the case that there were two Chetans inside Mumbai city—if we had two students whose name was Chetan—then what would happen in that case? In that case, the count of roll numbers would come as two for us, because that wouldn't remain a unique thing then, it would become duplicate. So here, **on the basis of whichever city and name are unique, our group will be formed**.

So, Group By might seem a bit difficult to learn, but it is not that difficult. Basically, **whenever we have to group on the basis of anything, we write its name and then group by it**. And if we have to extract some information inside these groups—like, let's suppose, we want to find our maximum, or we want to find our average inside all cities...

...let's suppose we want to calculate the average of all students' marks—how many average marks did students get inside Pune, how many average marks did students get inside Delhi, or how many average marks did students get inside Mumbai—then those will come to us. On executing: **so inside Pune, the average marks of students were 78; inside Mumbai, it was 89; inside Delhi, it remained 63.3**. So, the average marks of all of our cities have come to us. So this is how our Group By works."
