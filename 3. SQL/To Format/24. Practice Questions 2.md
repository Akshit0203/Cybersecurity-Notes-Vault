**First Practice Problem: City Average Marks**

"Now we are going to solve a **practice question**.

The question is: **'Write the query to find the average marks in each city in ascending order'**.

Among these, one part of this we have already completed, which is finding the average marks in each city. For that, what did we write? We wrote `SELECT` and then we can write our `city` from our `student` table, and here we can write `GROUP BY` and then our `city`. Based on this, our city's entire data will come arranged—meaning we will get Pune, we will get Mumbai city's data, and we will get Delhi's data. Now we want that we should also get the average marks, so we can directly write `AVG(marks)`. So we will get all the average marks on the basis of cities.

But we want these marks to be **arranged in ascending order**. So at the end, we can also apply an `ORDER BY` clause—that if we want it in ascending order based on city, we can do that.

So we can write:

```
SELECT city, AVG(marks) FROM student GROUP BY city ORDER BY city;
```

So, city-wise, the marks will come arranged in ascending order. So this is our first city, Delhi, which has these average marks; then Mumbai came, which has these average marks; then Pune came, which has these average marks.

Now, if we want, we can also arrange them on the basis of marks. So now what happened? Now, on the basis of our marks, these averages have come arranged—meaning, first we got Delhi and its average marks, then Pune came and its marks, then Mumbai came and its marks. So we can arrange on the basis of average marks as well, and we can arrange on the basis of city in ascending order as well.

Now, we noticed about `ORDER BY` that by default, if we do not write ascending or descending, it arranges and gives it in ascending order. But if we write `DESC` here, then we will get the marks in decreasing order too. If written like this, first the highest marks will come, then less than that, then less than that. So specifying ascending is not always necessary, but in the case of descending, we always have to write `DESC`. So in this way, we can calculate our marks by combining different clauses."

**Second Practice Problem: Customer Payments**

"Now, we are going to do **another practice question**. Inside this, we are given a lot of data, and this is our total payments data. So we have our customer ID, we have many customers' names, we have modes—modes, meaning how the payment has been done, whether net banking has been done, credit card payment has been done, or we have debit card payment—and we have many cities too inside this table. Let's suppose this table of ours, the name of this table is `payment`—meaning we have payment data with us, or we can also call it customer table, but we will call it payment table.

Now, what do we have to do? **'Find the total payments according to each payment method.'** Meaning, how many payments were made through net banking, we have to tell that; how many payments were made through debit card, we have to tell that; how many payments were made through credit card, we have to tell that—and we do not have to count them one by one, we have to use SQL and tell.

So here, you should pause the video and think a bit about how we can solve this question using `GROUP BY`, and then we can look at the solution.

Now, whenever we use `GROUP BY`, the very first thought that should come to mind is: on what basis do we have to create the group? In the first case, we knew that we had to make the group on the basis of city. On what basis do we have to make the group here? Because we have to count the total payments of each payment method, we know that, first, we will have to tell all those payments that were made for net banking, then all those that were made for credit card, and then all those that were made for debit card. So, this will become the basis of our group: that the mode of payment which was used—meaning whichever mode of payment we used—we will make the group on the basis of that.

So we can write:

```
SELECT mode FROM payment GROUP BY mode;
```

So from this, what will happen? All three of our modes will come: net banking will come, credit card will come, and debit [card] will also come.

Now we want to know how many total payments were made within each mode—within each different mode. So how will the total payments be known? However many customers we have, or however many customer IDs we have, those will be our total payments. Let's suppose we take our customers. So however many customers are there, those many payments are there. Now what do we need to calculate the total of customers—meaning how many payments? We need the count of how many customers are there, count them. So for that, we can put a comma and write `COUNT(customer)`.

Let's drag this a little, a bit to this side. So what is this? We can select all the modes from payment and we will group by mode. Now, within each mode, however many customers are there, we will also print their count along with it, so we will get the total number of payments. So this will be the way to calculate all the payments according to each payment method. If you want, you can also create this table inside SQL and check, and write this statement to verify whether the final answer we are getting is correct or not. Otherwise, my guarantee is the final answer will be correct if we have entered the correct data inside our table."

**Additional Concept: Grade Grouping**

"Now, in the same way, we can also write another sample thing using `GROUP BY`. Let's suppose I want to calculate: how many students in the class got an A grade, how many students got a B grade, how many students got an F grade? Basically, on the basis of grade, I want to find out how many students are there who got that particular grade.

So first of all, the group will be formed on the basis of grade. So we select grade from our student table, group by grade:

```
SELECT grade FROM student GROUP BY grade;
```

So from this, all the grades that have come in the class will come for us. On executing: `C, A, B, F`—so all the grades have come. If we want, we can also order them: let's do ascending, `ORDER BY grade`. So they will come in ascending order on the basis of grade: `A, B, C, and F`.

Now, along with this, I want to know how many students got which grade. So we can count the number of—either we will count the students, we can do `COUNT(name)`, or we can do `COUNT(roll_no)` because two people can have the same name. Let's do this, so we got: **there are two students who got an A grade, two students got B, one got C, and one student got F grade**. So in this way, on the basis of grade, we can use grouping inside our class too.**First Practice Problem: City Average Marks**
