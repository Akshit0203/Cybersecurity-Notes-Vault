# Task 3 IP Address (Easy)

According to [Akamai](https://www.akamai.com/blog/security/digging-deeper-an-in-depth-analysis-of-a-fast-flux-network), Fast Flux is a DNS technique used by botnets to hide phishing, web proxying, malware delivery, and malware communication activities behind compromised hosts acting as proxies. The purpose of using the Fast Flux network is to make the communication between malware and its command and control server (C&C) challenging to be discovered by security professionals. 

So, the primary concept of a Fast Flux network is having multiple IP addresses associated with a domain name, which is constantly changing. Palo Alto created a great fictional scenario to explain Fast Flux: ["](https://unit42.paloaltonetworks.com/fast-flux-101/)[Fast Flux 101: How Cybercriminals Improve the Resilience of Their Infrastructure to Evade Detection and Law Enforcement Takedowns"](https://unit42.paloaltonetworks.com/fast-flux-101/)

This is one of the examples of a Punycode attack used by the attackers to redirect users to a malicious domain that seems legitimate at first glance.

What is Punycode? As per [Jamf](https://www.jamf.com/blog/punycode-attacks/) , "Punycode is a way of converting words that cannot be written in ASCII, into a Unicode ASCII encoding."

What you saw in the URL above is  `adıdas.de`  which has the Punycode of  `http://xn--addas-o4a.de/`

Internet Explorer, Google Chrome, Microsoft Edge, and Apple Safari are now pretty good at translating the obfuscated characters into the full Punycode domain name.

To detect malicious domains, proxy logs or web server logs can be used.

Attackers usually hide the malicious domains under URL shorteners.   A URL Shortener is a tool that creates a short and unique URL that will redirect to the specific website specified during the initial step of setting up the URL Shortener link. The attackers normally use the following URL-shortening services to generate malicious links: 

- bit.ly
- goo.gl
- ow.ly
- s.id
- smarturl.it
- tiny.pl
- tinyurl.com
- x.co

You can see the actual website the shortened link is redirecting you to by appending "+" to it (see the examples below). Type the shortened URL in the address bar of the web browser and add the above characters to see the redirect URL.

# Task 6 Network Artifacts (Annoying)

Think of **network artifacts** as _digital clues_ left behind when something communicates over a network.
## 🌐 What are network artifacts?

A **network artifact** is any noticeable pattern in network traffic that can help you spot normal vs suspicious activity. Common examples are:

- **User-Agent string** – tells the server _what program/device_ is making the request (browser, script, malware, etc.)
    
- **C2 (Command & Control) info** – where malware talks back to its attacker
    
- **URI patterns** – strange or repetitive URLs
    
- **HTTP POST requests** – often used to _send data out_ (like stolen info)

### 🧭 User-Agent (important one)

The **User-Agent** is a small text field in every HTTP request that identifies the client (for example: Chrome on Windows).

It’s formally defined in RFC 2616.

![|560x286](attachments/image.png)

👉 Attackers often use:

- Very **unusual** User-Agents
    
- Or **custom-made** ones
    
- Or ones **never seen before** in your environment
    

That makes User-Agents a great detection point.

If you suddenly see something like:

> `Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1…)`

inside a modern network — that’s a 🚩 red flag.

### 🚩 1. Those versions are _ancient_

That string claims the computer is using:

- Internet Explorer 6
    
- Windows NT 5.1 (that’s Windows XP)
    

Both are **20+ years old** and no longer used in real environments today.

So realistically:

👉 Your company PCs / laptops are _not_ running this.  
👉 Modern browsers _don’t_ send this anymore.

---

### 🚩 2. Malware often _pretends_ to be old software

Attackers commonly hard-code fake User-Agents like this because:

- It’s easy to copy from old examples
    
- They don’t care about realism
    
- They just need _something_ that works
    

So many malware tools reuse these outdated strings.

In other words:

> **Legitimate users upgrade. Malware doesn’t.**

---

### 🚩 3. It doesn’t match your environment baseline

In a normal network you’ll mostly see things like:

- Chrome / Edge / Firefox
    
- Windows 10/11, macOS, Linux
    

If _one_ host suddenly says:

> “Hi, I’m Internet Explorer 6 on Windows XP”

that machine immediately stands out.

Security teams call this an **anomaly**.

---

### 🚩 4. It’s commonly used by bots & trojans

A lot of automated malware (downloaders, backdoors, C2 beacons) reuse exactly these kinds of User-Agents. Seeing them often means:

- scripted traffic
    
- malware callback
    
- or compromised host
    

not a real human browsing.


## 🔍 How do we find these artifacts?

You usually look inside **PCAP files** (packet captures) using tools like:

- Wireshark – graphical interface
    
- TShark – command-line version
    
- IDS logs from systems like Snort
    

These tools let you inspect traffic and extract things like hosts, URLs, and User-Agents.

---

## 🧪 Example: extracting User-Agents with TShark

This command:

`tshark --Y http.request -T fields -e http.host -e http.user_agent -r analysis_file.pcap`

Simply means:

- Read the PCAP file
    
- Show only **HTTP requests**
    
- Print:
    
    - the destination host
        
    - the User-Agent string
        

So you get a clean list of _who talked to whom, and using what client_.

---

## 🚨 Why this matters (real malware example)

Malware families like Emotet Downloader Trojan are known to use **specific or strange User-Agent strings** during infection.

If you learn these patterns, you can:

✅ Detect infected machines  
✅ Write firewall/IDS rules to block them  
✅ Add friction for attackers  
✅ Stop data exfiltration early

In practice:

> **Spot custom User-Agent → block it → attacker’s malware breaks.**
