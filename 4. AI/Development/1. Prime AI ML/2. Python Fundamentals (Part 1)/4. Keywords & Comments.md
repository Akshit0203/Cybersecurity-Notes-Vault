**Along with this, we also have something called keywords in Python****. Keywords are basically reserved words****. Saying "reserved words" means these are words whose meaning in Python is fixed****. We can never use these words as a variable name or any function name—meaning as an identifier****. For example, we have** **False****. Now** **False** **has a fixed meaning in Python: that** **False** **is a boolean value, and the meaning of False will remain False****. It is not like we can make a variable named** **False** **and assign it a value of 1, 2, 3—this is not possible****. Similarly, we have** **None****, we have** **True****, we have** **lambda****, we have** **else****.**

**So we don't have to memorize them, nor do we need to make notes of them****. We just need to have a general understanding that there are some reserved words in Python that cannot be used as variables****.**

**Along with this, there is something called comments in Python****. So let's clear this****. Basically, whenever we want to write something in our code that we want to tell another programmer, another developer, or another AI engineer, such things are not part of our code****. We generally write such things in English****. So we write these things in the form of comments****. Just like in real life people pass comments, similarly, in a program, if we need to write something in English—not in Python, write something in English—then we write it in the form of comments****. To write comments, we simply have to start the comment with a hash (#)****. And generally, all our code editors highlight comments with green colors****. So whatever we write after putting a hash is something that our Python interpreter will now ignore****. This is something which is only meant for humans, not for machines****.**



```
print(type(isPrime)) #comment
```


For example, here I can write any false value as well. Like I wrote `False = 1 2 3`. This is something we know. In Python's syntax, if we write `False = 1 2 3`, we will get an error. For example, if I run this code, I am going to get this error: `False = 1 2 3`—this is a syntax error. Syntax error means this is going against Python's rules, it is breaking Python's rules. "Cannot assign to False". Meaning this 1 2 3 value cannot be assigned to this thing named `False` because `False` cannot become a variable. So this we got as an error. But if we write the exact same thing inside comments—like here we print the type of age, and we have removed `is_prime`—then Python has completely ignored this comment. So we can write anything inside comments. Generally, inside comments, we explain what work our code, our program, or our function performs.


```
False = 123

print(type(isPrime)) #False = 123
```

```
    False = 123
    ^^^^^
SyntaxError: cannot assign to False
```


**And the interpreter will ignore this comment****. Now, just like we have single-line comments with the help of hash, similarly, we have multiple-line comments as well****. Meaning, if we want, we can write anything across multiple lines****. To write a multi-line comment, we have to use triple quotes****. And if we write anything inside triple quotes, "This is a multi line comment," then this is also something which our code will ignore**


```
print(type(isPrime)) #False = 123

'''
This is a 
multi-line
comment
'''

```
