# Classless IP Addressing (CIDR)

> [!tip] Core Rule
> **IPv4 = 32 bits → `/Prefix` = Network bits → `32 - Prefix` = Host bits → `2^(Host bits)` = Total addresses**

---

## Classful vs Classless

### The Old Way — Classful Addressing

Under classful addressing, the **first octet** determined the network size:

| Class | Range    | Default Mask | Total Addresses |
| ----- | -------- | ------------ | --------------- |
| A     | 1–126    | `/8`         | 16,777,216      |
| B     | 128–191  | `/16`        | 65,536          |
| C     | 192–223  | `/24`        | 256             |
| D     | 224–239  | Multicast    | —               |
| E     | 240–255  | Experimental | —               |

**Example:** `192.168.1.10` → `192` = Class C → automatically `/24` → 254 usable hosts.

**Problem:** Extremely inflexible. An org needing only 50 IPs would get a `/24` (256 addresses) — massive waste. An org needing 500 IPs would need a Class B `/16` (65,536 addresses) — even more waste.

### The Modern Way — CIDR (Classless Inter-Domain Routing)

> **The `/prefix` determines the network size, NOT the first octet.**

The same IP can belong to completely different-sized networks depending on the prefix:

```
192.168.1.0/24  → 256 addresses
192.168.1.0/25  → 128 addresses
192.168.1.0/26  → 64 addresses
192.168.1.0/27  → 32 addresses
```

And `10.x.x.x` (traditionally Class A) can use `/16`, `/20`, `/24`, etc.

> [!important] Mental Model
> ❌ **Don't think:** "192 = Class C"
> ✅ **Think:** "/24 tells me the first 24 bits are the network"

## How CIDR Subnetting Works

### The `/prefix` Boundary

An IPv4 address has 32 bits. The prefix tells you how many bits are network vs host.

**Example: `192.168.1.10/24`**

```
192       168       1         10
11000000  10101000  00000001  00001010

/24 mask:
11111111  11111111  11111111  00000000
<-------- Network -------->  <-Host->

Network = 192.168.1.0
Host    = .10
```

**Example: Same IP with `/16`**

```
192.168.1.10/16

11111111  11111111  00000000  00000000
<------- Network -------->  <--- Host --->

Network = 192.168.0.0
Host    = 1.10
```

> The IP address didn't change — only the prefix length changed. **You cannot properly understand an IP address without its subnet mask/prefix.**

### Calculating Network Size

```
32 - Prefix = Host bits
2^(Host bits) = Total addresses
Total - 2 = Traditional usable hosts (subtract network + broadcast)
```

**Example: `192.168.1.0/26`**

```
32 - 26 = 6 host bits
2⁶ = 64 total addresses

Network address = 192.168.1.0
Usable hosts    = 192.168.1.1 – 192.168.1.62
Broadcast       = 192.168.1.63
Usable          = 62 hosts
```

## Worked Example: `/20` Subnetting

**IP:** `172.16.35.20/20`

```
20 network bits, 12 host bits
2¹² = 4096 total addresses
Subnet mask: 255.255.240.0
```

Network boundaries occur in blocks of 16 in the third octet:

```
172.16.0.0
172.16.16.0
172.16.32.0   ← our network (35 falls between 32 and 47)
172.16.48.0
172.16.64.0
...
```

```
Network:    172.16.32.0
First host: 172.16.32.1
Last host:  172.16.47.254
Broadcast:  172.16.47.255
```

## Why CIDR Was Created

**Problem:** Company needs ~500 IPs.

| Option  | Prefix | Addresses | Fit?          |
| ------- | ------ | --------- | ------------- |
| Class C | `/24`  | 256       | Not enough    |
| Class B | `/16`  | 65,536    | Massive waste |
| CIDR    | `/23`  | 512       | ✅ Close fit   |

## CIDR and Routing (Route Aggregation)

CIDR isn't just about host counts — it's fundamental to **routing**.

A router with `10.0.0.0/8` can have sub-routes:

```
10.0.0.0/16
10.1.0.0/16
10.2.0.0/16
```

CIDR prefixes determine where traffic goes → **route aggregation**.

## Private IP Ranges

These are still described using their historical ranges, but actual addressing is CIDR/classless:

| Range             | CIDR           |
| ----------------- | -------------- |
| `10.0.0.0`        | `10.0.0.0/8`   |
| `172.16.0.0`      | `172.16.0.0/12` |
| `192.168.0.0`     | `192.168.0.0/16`|
