
Windows Command Line ▰ Windows has two command shells: The Command shell and PowerShell ▰ Officially called Windows Command Processor, but also sometimes referred to as the command shell or cmd prompt, or cmd.exe. ▰ Sometimes called ‘DOS prompt’, incorrectly. ▰ PowerShell was designed to extend the capabilities of the Command shell to run PowerShell commands called cmdlets ▰ You can run Windows Commands and PowerShell cmdlets in Powershell, but the Command shell can only run Windows Commands and not PowerShell cmdlets.

**Part 1: The Windows Command Line and the DOS Misconception**

Now let's talk about the **Windows command line**. Earlier we talked about Linux. Now, in Windows, we have a slightly different concept here. **Windows also has command shells**. They do the same work. But it has two of them. The normal command shell is named **CMD**, and there is another one called **PowerShell**.

Now, officially, what we use in Windows is called a **command processor**. But people call it a prompt shell, cmd.exe—whatever you want to call it is up to you. Another point that comes up here is that we also call it **DOS**. DOS is a completely different OS from Windows that was used earlier. Here we are calling this shell DOS again. But brother, **it is not exactly DOS; it is not that OS**. It has been made like that to **emulate DOS commands**. It is just an interpreter similar to DOS commands that runs our Windows commands. That is not the DOS OS, brother—this is incorrect and a **misconception**. It is only emulating DOS commands, which is why it feels that way to us. And PowerShell, as its name suggests, is much more powerful...

**Part 2: Why PowerShell is More Powerful (Objects vs. Text)**

...PowerShell. So why is this PowerShell powerful? The main concept of PowerShell is **different from our normal shell**. Why? Because in a normal command shell, everything is **text-based**. So, the output you get will also be in text form. If you want to fetch something specific from that output—like if I get a whole output and I want to fetch a specific string that I need—then in a normal shell, **you have to parse and search through the entire text**.

But in PowerShell, **it treats every output as an object**. So, by applying a method of that object, you can **directly go to the exact string you need**. This is the capability of PowerShell, and it is very good. It uses **cmdlets (command-lets)**, which join large commands together. We will use PowerShell later when we need to, but here we are mainly talking about the Linux shell and the normal Windows shell. Windows...

**Part 3: Key Differences and Interface Features**

...commands can be run in PowerShell. Normally, **all CMD commands can be run in PowerShell**. However, **PowerShell's cmdlets cannot be run in the normal Windows shell (cmd.exe)**. This is the key difference between the two.

The normal cmd.exe is what you refer to as the DOS prompt. This is where you type commands for the **kernel**. There are many commands, and we will slowly see them and learn their usage one by one. What is on the right side of the screen is PowerShell, where you can see **the commands are of a different type and start with capital letters**. On the left side is the standard cmd.exe. By default, the CMD screen is **black**, while the PowerShell screen is **blue**.
