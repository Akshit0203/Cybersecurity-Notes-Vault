# Windows Command Line

> Windows has two command shells: **Command Prompt (cmd.exe)** and **PowerShell**. PowerShell extends CMD's capabilities with powerful cmdlets and object-based output.

![](attachments/Pasted%20image%2020260814225158.png)

---

## Two Command Shells

| Feature | Command Prompt (cmd.exe) | PowerShell |
| ------- | ----------------------- | ---------- |
| **Also called** | CMD, command processor, "DOS prompt" | PowerShell |
| **Output type** | Text-based | **Object-based** |
| **Can run CMD commands?** | ✅ Yes | ✅ Yes |
| **Can run PowerShell cmdlets?** | ❌ No | ✅ Yes |
| **Default screen color** | Black | Blue |
| **Command style** | Lowercase commands | PascalCase cmdlets (e.g., `Get-Process`) |

---

## The DOS Misconception

> [!WARNING]
> CMD is **not** DOS. DOS (Disk Operating System) was a completely separate OS used earlier. The Windows command shell only **emulates DOS-style commands** — it is a command interpreter, not the DOS OS itself.

---

## Why PowerShell is More Powerful

### Text-Based (CMD) vs. Object-Based (PowerShell)

- **CMD:** Output is plain text → to extract specific data, you must **parse through the entire text** manually
- **PowerShell:** Every output is treated as an **object** → you can call methods/properties on it to **directly access the exact data** you need

### Cmdlets
- PowerShell uses **cmdlets** (command-lets) — small, focused commands that can be chained together
- Cmdlets follow a `Verb-Noun` naming convention (e.g., `Get-Process`, `Set-Location`)

---

## Key Takeaway

- Use **CMD** for basic Windows commands and quick tasks
- Use **PowerShell** for advanced scripting, automation, and when you need to work with structured data
- All CMD commands work in PowerShell, but **not** the other way around
