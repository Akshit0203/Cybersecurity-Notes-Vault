# Linux Command Line

> Kali Linux uses the **Bourne Again Shell (Bash)**, created for the GNU project as a successor to the Bourne Shell. Bash can read and execute commands from a file (shell script) and includes features from the Korn shell (ksh) and C shell (csh) such as command-line editing and command history.

## Shell History & Evolution

```
Bourne Shell ──→ Bash (Bourne Again Shell)
                    ↑
Korn Shell (ksh) ───┤  (borrowed features: history, editing)
C Shell (csh) ──────┘
```

- **Bourne Shell** — the original Unix shell
- **Korn Shell (ksh)** and **C Shell (csh)** — added command history and editing
- **Bash** — combined the best of all predecessors; now the default shell in most Linux distributions

## Shell Scripts vs. Batch Files

| Platform | Term | Description |
| -------- | ---- | ----------- |
| **Linux** | Shell script (`.sh`) | Multiple commands in a single file for **automation** |
| **Windows** | Batch file (`.bat`) | Multiple commands in a single file |

- On the command line, you enter commands **one by one**
- In a script, many commands run **together sequentially**
- Shell scripting is a key tool for **automation**

## Shell Architecture

```
┌──────────────────────────────┐
│    Applications              │  (mail, browser, spreadsheet)
├──────────────────────────────┤
│   Shell Commands             │  (cp, grep, tar, sed, sort, etc.)
│   ┌────────────────────────┐ │
│   │     Shell (Bash)       │ │
│   └────────────────────────┘ │
├──────────────────────────────┤
│         Kernel               │
├──────────────────────────────┤
│        Hardware              │
└──────────────────────────────┘
```

- Core shell commands (`cp`, `grep`, `tar`, `sed`, `sort`) interact **directly with the kernel**
- Users can interact with the shell directly — no application layer needed
- Users **cannot** interact with the kernel directly; it must go through the shell
