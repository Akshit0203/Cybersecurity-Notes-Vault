
Linux Command Line ▰ Kali Linux uses the Bourne Again or Bash shell, created for use in the GNU project, as a successor to the Bourne shell ▰ Bash can also read and execute commands from a file, called a shell script. ▰ Bash command syntax includes ideas drawn from the Korn shell (ksh) and the C shell (csh) such as command line editing, command history

**Part 1: Kali Linux, the Bash Shell, and the GNU Project**

We are going to talk about the **Linux command line**, which is going to be of more use to us. When we use Linux—the Kali one—the default shell type of Kali Linux is the **Bourne Again Shell (Bash shell)**, which is currently running in almost all Linux distributions nowadays. Earlier, a simple shell was used—the **Bourne Shell** was used; they used to call it that. Here we call it **Bash**.

All the distributions of Linux are based on the **GNU Project**. There was a man in this project named **Richard Stallman** [phonetically transcribed in the transcript as "Richards for in"]. What did he say? He said that this software should be freely available for everyone to use, modify, and help others to improve, so that the entire community can grow. This project was made to use and distribute software freely, and he did this work through a license, which we call the **GNU GPL license**. Linux is also based on that, and Linux has that same license. It is free for everyone for non-commercial use. Here, in Bash, you can take input from a file. Meaning...

...you make a file and write many commands together in it. In the case of Windows, we call that a **batch file**. When we write commands together, it is a batch file, and all the commands run together if we give input. But here, in the case of Linux, it is called a **shell script**. There are many commands in it together. When you use the command line, you have to give commands one by one, but in a shell script, there are many together. So your work will become highly automated; shell script is used for **automation**.

Earlier there were two other shells: the **Korn shell** and the **C shell**. From those, the advanced form has come here, which is the **Bash shell**. It has added many more things—you can view the **command history** and even do editing directly through the command line in text files, so this is a very good thing. This is somewhat what the Bash shell looks like; in the case of Ubuntu, it looks like this, but in different OSs, the color and interface might change a little bit. This is the structure of the shell. Here, the hardware and kernel are, let's say, the same—it is the same up to that point. But above that, here, there is only a small part of the shell; not a large part of the shell, just a small part here. And in the other parts, some things are written—here, `cp`, `grep` [phonetically transcribed in the transcript as "gap"], `tar`, `sed` [phonetically transcribed in the transcript as "sd"], `sort`—what are all these? These are all commands that you type in the shell, so these interact directly with your kernel. These very commands are what make up your shell, and these will mostly be useful to you—these commands will be of the greatest use to you.

On top of that, you run applications—whether it is mail, browser, or spreadsheet. So all users can interact directly with the shell; there is no need for applications here. However, you cannot interact with the kernel directly; you can only do it through the shell. So, that is all for the Linux command line.
