
diff bw /etc/passwd and /shadow files in kali linux

In Kali/Linux, `/etc/passwd` and `/etc/shadow` both contain **user account information**, but they serve very different purposes.

## 1. `/etc/passwd`

This is the **general user account database**.

View it with:

cat /etc/passwd

A typical entry looks like:

akshit:x:1000:1000:Akshit:/home/akshit:/bin/bash

The fields are separated by `:`:

akshit : x : 1000 : 1000 : Akshit : /home/akshit : /bin/bash

   │      │     │      │       │          │            │

 username │     │      │       │          │            └─ Login shell

          │     │      │       │          └──────────── Home directory

          │     │      │       └────────────────────── User description

          │     │      └────────────────────────────── Primary GID

          │     └───────────────────────────────────── UID

          └─────────────────────────────────────────── Password placeholder

### Important fields

|Field|Meaning|
|---|---|
|Username|Account name|
|`x`|Password is stored in `/etc/shadow`|
|UID|User ID|
|GID|Primary group ID|
|GECOS|User information|
|Home|User's home directory|
|Shell|Default login shell|

---

# 2. `/etc/shadow`

`/etc/shadow` contains **password-related authentication information** and is much more sensitive.

You normally need root privileges to read it:

sudo cat /etc/shadow

An entry might look conceptually like:

akshit:$y$j9T$...:20500:0:99999:7:::

Its fields include things such as:

username

password hash

last password change

minimum password age

maximum password age

warning period

inactive period

expiration information

The most important part is:

$y$j9T$...

That's the **password hash**, not the plaintext password.

---

# 3. Why are they separate?

This is the key security idea.

`/etc/passwd` needs to be readable by many programs and users because applications frequently need basic information such as:

> "What UID belongs to `akshit`?"

So historically `/etc/passwd` is generally world-readable.

But password hashes are sensitive.

Therefore:

/etc/passwd

      ↓

General account information

      ↓

Generally readable

  

  

/etc/shadow

      ↓

Password hashes + authentication aging information

      ↓

Restricted access

This separation prevents ordinary users from simply reading everyone's password hashes.

---

# 4. Why does `/etc/passwd` contain `x`?

You might wonder:

akshit:x:1000:1000:...

Why isn't the password hash there?

Historically, password hashes **were stored in `/etc/passwd`**.

Modern Linux systems moved them to:

/etc/shadow

So:

/etc/passwd

       │

       └── x → "Look in /etc/shadow"

---

# 5. How authentication works

Suppose you type:

username: akshit

password: MyPassword

Linux doesn't normally do:

Password == value in /etc/shadow

Instead, conceptually:

Your password

      ↓

Password hashing algorithm

      ↓

Generated hash

      ↓

Compare with stored hash

      ↓

Match?

   /     \

 Yes      No

 ↓         ↓

Login     Reject

The actual authentication stack can involve PAM and other system components, but that's the basic idea.

---

# 6. Very important for cybersecurity

If you obtain:

/etc/passwd

that's useful for **user enumeration**, but normally doesn't give you password hashes.

If you obtain:

/etc/shadow

that's much more sensitive because you may obtain password hashes that could potentially be subjected to **offline password-cracking attempts**.

For example, you'll encounter commands/tools such as:

unshadow

john

hashcat

in legitimate penetration-testing labs.

---

# 7. `/etc/passwd` isn't actually "the password file"

This is a common beginner misconception.

Despite its name:

/etc/passwd

is primarily an **account information file** today.

Think:

/etc/passwd

=

Who are the users?

  

  

/etc/shadow

=

Authentication/password information

---

# 8. One more important thing: not every account is a human

If you run:

cat /etc/passwd

you'll see accounts such as:

root

daemon

bin

sys

sync

games

man

www-data

backup

...

Many are **system/service accounts**, not people.

For example:

www-data

is commonly associated with web services.

This is why `/etc/passwd` is also very useful during Linux enumeration.

---

## The interview answer

If someone asks:

> **What's the difference between `/etc/passwd` and `/etc/shadow`?**

Say:

> **"`/etc/passwd` contains general information about Linux user accounts, such as usernames, UIDs, GIDs, home directories, and login shells. `/etc/shadow` contains sensitive password authentication information, primarily password hashes and password-aging data, and is normally restricted to privileged users. The `x` in `/etc/passwd` indicates that the password hash is stored in `/etc/shadow`."**

That's the answer you want to have memorized.
