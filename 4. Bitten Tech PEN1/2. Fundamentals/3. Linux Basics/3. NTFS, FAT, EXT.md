# NTFS, FAT, EXT — File Systems


---

## FAT32 (File Allocation Table)

Most commonly used in **USB drives** (pen drives). Data is stored in **clusters** (groups of sectors).

- A hard disk contains many **sectors** (typically **512 bytes** each)
- Sectors are grouped into **clusters** (e.g., a 4 KB cluster contains multiple sectors)
- Grouping sectors into clusters makes data management easier as a single unit
- If a file doesn't fit in one cluster, it spans across **multiple clusters**

### Cluster Addressing Trade-off

FAT32 increases the number of bits used for addressing clusters. Since overall storage remains constant:

- More addressing bits → more clusters can be tracked
- More clusters → each cluster becomes **smaller**
- Smaller clusters → **more efficient storage** (less wasted space when files don't completely fill a cluster)

### FAT32 Limits

| Property          | Limit       |
| ----------------- | ----------- |
| Max disk size     | **2 TB**    |
| Max file size     | **4 GB**    |

> You can test this — try creating a file larger than 4 GB on a FAT32 pen drive; it will not work.

---

## NTFS (New Technology File System)

Microsoft's default file system for Windows. Not Windows-exclusive — can be used on Linux and macOS too.

- Linux and BSD have a **free and open-source NTFS driver**
- macOS comes with **read-only** support for NTFS

| Property            | Value       |
| ------------------- | ----------- |
| Max file size       | **16 TB**   |
| Default cluster size| **4 KB**    |

Because NTFS supports massive storage spaces, it is the default choice for Windows.

---

## EXT4 (Extended File System 4)

Currently the **default file system for the Linux kernel**.

- Supports **file-based encryption** — file contents, filenames, and symbolic link targets are all encrypted
- Supports **journaling** — if a file block gets corrupted, the journal maintains an access path for error recovery (adds some file overhead)
- Also works with **symbolic links**

---

## Cross-Platform Access

| Direction           | Support                                                    |
| ------------------- | ---------------------------------------------------------- |
| Linux → NTFS        | ✅ **Native support** — can easily access Windows drives    |
| Windows → EXT4      | ❌ Requires **additional software** to be installed         |
| macOS → NTFS        | Read-only by default                                       |

> Linux has native support for accessing all files on a Windows local hard disk, but you cannot do the reverse in Windows without installing extra software.
