# netdiscover

> [!info] What is it?
> `netdiscover` is a **host-discovery tool** that finds **live devices on a local network** using ARP.
> It answers: **"What machines are alive on this LAN, and what are their IP/MAC addresses?"**

---

## How It Works (ARP)

`netdiscover` primarily uses **ARP (Address Resolution Protocol)**.

1. Your machine is on a network, e.g. `192.168.1.0/24`.
2. `netdiscover` sends ARP requests asking:
   > **"Who has 192.168.1.X?"**
3. Any alive host responds with its MAC address.
4. Now `netdiscover` knows that host exists.

---

## Important Commands

### 1. Basic scan

```bash
sudo netdiscover
```

Automatically selects an interface and scans the local network.

---

### 2. Scan a specific range

```bash
sudo netdiscover -r 192.168.1.0/24
```

`-r` = specify the range. **Most useful form to remember.**

---

### 3. Specify your interface

```bash
sudo netdiscover -i wlan0
```

Use when connected through a specific adapter (e.g. Wi-Fi).

Check available interfaces with:

```bash
ip a
```

---

### 4. Passive mode

```bash
sudo netdiscover -p
```

Instead of actively sending ARP probes, it **listens for ARP traffic** already on the network.

- **Active** → you shout "who's there?" (generates traffic)
- **Passive** → you sit quietly and listen (stealthier)

---

## `netdiscover` vs `nmap`

| | `netdiscover` | `nmap` |
|---|---|---|
| Main purpose | Discover hosts | Discover + enumerate |
| Protocol | Primarily ARP | ICMP, TCP, UDP, ARP, etc. |
| MAC addresses | ✅ | ✅ on local network |
| Ports | ❌ | ✅ |
| Services | ❌ | ✅ |
| Service versions | ❌ | ✅ |
| Local LAN | ⭐ Excellent | ⭐ Excellent |
| Remote target / VPN | Limited | ⭐ Excellent |

> [!tip] Easy memory trick
> **`netdiscover` → "Who is alive on my local network?"**
> **`nmap` → "What's running on that machine?"**

---

## ⚠️ Important for OSCP

`netdiscover` is **mainly useful when you're on the same Layer-2 network** as the targets.

If you're attacking an HTB / OffSec target **over a VPN**, you generally **won't use netdiscover** because the target is not on your local Ethernet broadcast domain.

For those situations, use:

```bash
nmap -sn <target-range>
```

or scan the specific target IP you've been given.

> [!summary] Bottom line
> Learn `netdiscover` enough to understand **ARP-based host discovery**, but spend considerably more time mastering **Nmap**.
