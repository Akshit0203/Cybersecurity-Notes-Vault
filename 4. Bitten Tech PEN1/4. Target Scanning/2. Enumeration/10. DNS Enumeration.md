



DNS Enumeration (Zone Transfer)
32
▰ It is a process of locating the DNS server and the records of a target
network.
▰ An attacker can gather valuable network information such as DNS
server names, hostnames, machine names, user names, IP addresses,
etc. of the potential targets.
▰ The DNS implements a distributed, hierarchical, and redundant
database for information associated with Internet domain names and
addresses.
▰ In a DNS zone transfer enumeration, an attacker tries to retrieve a copy
of the entire zone file for a domain from the DNS server.

**[Section 3: The Attacker's Perspective & Distributed Redundant Databases]**

So basically, what does an attacker do here? They find out the **DNS server name, host name, machine names, and then user names, and IP addresses of the potential targets**. They find out all this data.

After that, you must already know how the DNS system is. What is DNS, basically? **DNS is a distributed system**. There are many DNS servers around the world that keep the information of the same domain name. This is because it's not like if I am sitting in India, I have to repeatedly query in America, querying a DNS server located in America. My overhead would increase a lot. So for that reason, the redundant data will be right here with me in India so that it takes less time and I get a fast response.

So it is a distributed and redundant database. This is because a lot of information gets duplicated across different DNS servers so that time is saved. You can think of this like a Content Delivery Network (CDN) that you use for websites. For example, if there is America—suppose you made a website in America, and you used a CDN, then a lot of content got copied across India, in Australia, and wherever throughout the entire world. So the regional users there don't have to spend a lot of time opening the website, which is why you store all your data there too so they can query directly from there.
