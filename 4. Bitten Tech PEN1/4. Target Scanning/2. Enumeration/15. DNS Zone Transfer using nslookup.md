# DNS Zone Transfer using `nslookup`

## Why Use `nslookup` on Windows?

In Linux, `nslookup`'s `ls` command **does not work** for zone transfers. On Windows, it works correctly — making Windows `nslookup` the better choice for this method.

> [!tip] Comparison
> `nslookup` zone transfer gives **more detail** than the `host` command — you get the full zone file with all record types.

---

## Step-by-Step Zone Transfer

### Step 1: Open `nslookup` Interactive Prompt

```cmd
C:\Users\Akshit>nslookup
Default Server:  UnKnown
Address:  192.168.1.1
```

### Step 2: Set the Target DNS Server

```
> server nsztm1.digi.ninja.
Default Server:  nsztm1.digi.ninja
Address:  81.4.108.41
```

### Step 3: Set Query Type to ALL Records

```
> set type=any
```

Since we want **everything** (not a specific record type), use `any`.

### Step 4: Perform the Zone Transfer

```
> ls -d zonetransfer.me
```

**Syntax:** `ls -d <domain>` — list all hosts of that domain (zone transfer)

## Key Findings from the Zone File

| Record                  | Type   | Value / Significance                         |
| ----------------------- | ------ | -------------------------------------------- |
| First record            | **SOA** | Start of Authority — always first in a zone  |
| `HINFO`                 | HINFO  | **OS: Windows XP** — system information leak |
| `internal`              | NS     | **Private internal hosts** ⚠️ — confidential |
| `owa`                   | A      | Outlook Web Access endpoint                  |
| `vpn`                   | A      | VPN endpoint                                 |
| `staging`               | CNAME  | Points to sydneyoperahouse.com               |
| `contact`               | TXT    | Leaks name, phone, email of admin            |
| `sqli`                  | TXT    | SQL injection payload (intentional demo)     |
| `xss`                   | TXT    | XSS payload (intentional demo)               |
| `sshock`                | TXT    | Shellshock payload (intentional demo)         |

> [!warning] Internal hosts like `internal.zonetransfer.me` are **confidential** — finding these during a pentest is a significant bug. You also get the IPs, which can be audited further.
