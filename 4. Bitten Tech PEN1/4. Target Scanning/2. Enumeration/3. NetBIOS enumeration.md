11
▰ Software applications on a NetBIOS network locate and identify
each other via their NetBIOS names. (16 characters)
▰ Applications on other computers access NetBIOS names over
UDP (NBNS)
▰ Two applications start a NetBIOS session when the client sends
a command to "call" another client (the server) over TCP port
139. (session mode)
▰ The "hang-up" command terminates a NetBIOS session.
▰ NOTE: NetBIOS name resolution is not supported by Microsoft
for Internet Protocol Version 6 (IPv6)

What is NetBIOS? Microsoft made its own protocol and told users to utilize it if they were running Windows. So basically, it is nothing but an **API**. Originally, you will still use the same thing—meaning you will use TCP/IP—but Microsoft created an API on top of it. **[Part 3: Packet Integration and Name Identifiers]**

"Then, from that API, whatever your TCP/IP packet is, you will embed all your NetBIOS data into that packet itself. Then, through TCP/IP, it will circulate throughout the entire network, wherever you need to send it. So, **NetBIOS works through TCP/IP itself**. Earlier, it worked on something else, which was **NetBEUI** (NetBIOS Extended User Interface), but nowadays it works on TCP/IP (or it used to work until some time ago). If we want to use this on Windows, we need an identifier. **Every user has a NetBIOS name**, and it is recognized by that name across the entire network and the entire Windows system. **[Part 4: Communication Ports (UDP 137, TCP 139)]**

"The basic meaning of NetBIOS is that it is a communication protocol. As I explained, the NetBIOS name makes it clear what your identifier is and who you are. Meaning, for the applications running NetBIOS on your system, how will the API work? After that, **applications on other computers access NetBIOS names over UDP**. This is what we have to enumerate: we need to enumerate NetBIOS names. This is our objective of enumeration here, which we will do over UDP using **NBNS** (**NetBIOS Name Service**).

Just like in FTP where you have two separate connections for data and control using ports 20 and 21, NetBIOS is similar. Here, **three ports are used**. To establish a NetBIOS session, the client has to send a command named 'CALL' to another client or server. A TCP port is used to start the session mode, and **TCP port 139 is used to start the TCP session**. To terminate the session, a hang-up command has to be used."

explain netbios simply

**NetBIOS (Network Basic Input/Output System)** is basically a set of network services that lets **Windows computers discover and communicate with each other on a local network**, especially for file/printer sharing.

Think of it like:

> **NetBIOS = a way for Windows machines to identify themselves and find/talk to other Windows machines.**

### Simple example

Suppose a network has:

```
PC-A
Name: SALES-PC

PC-B
Name: HR-PC
```

NetBIOS can help PC-A discover:

```
"Who is HR-PC?"
→ "That's 192.168.1.20"
```

and then communicate with it.

### Important ports for OSCP

You should remember:

|Port|Protocol|Purpose|
|---|---|---|
|**137**|UDP|NetBIOS Name Service (NBNS)|
|**138**|UDP|NetBIOS Datagram Service|
|**139**|TCP|NetBIOS Session Service|

Especially:

```
UDP 137
UDP 138
TCP 139
```

You'll commonly see **139 alongside 445** during SMB enumeration.

### NetBIOS vs SMB

Don't confuse them:

```
NetBIOS
   ↓
Provides naming/session services

SMB
   ↓
File/printer sharing protocol
```

Historically, **SMB could run over NetBIOS**, using TCP 139.

Modern Windows commonly uses:

```
SMB directly over TCP 445
```

### Why do you care for OSCP?

If Nmap shows:

```
139/tcp open  netbios-ssn
445/tcp open  microsoft-ds
```

that's a big indication to investigate **Windows/SMB**.

You might enumerate things such as:

- Host/computer names
- Workgroup/domain information
- SMB shares
- Users
- Sessions
- OS information

For example:

```
nmap -sV -p 139,445 <IP>
```

and:

```
nbtscan <IP>
```

**Easy memory trick:**

> **137 = names**  
> **138 = datagrams**  
> **139 = sessions**  
> **445 = modern SMB**

so is netbios rlevant nowadays

Yes — **NetBIOS is still relevant, but mostly as a legacy/Windows-networking technology rather than something modern networks rely on heavily.**

### Where you still encounter it

- **Windows/Active Directory environments** — especially older or poorly hardened networks.
- **SMB enumeration** — NetBIOS can reveal Windows hostnames, workgroup/domain information, and sometimes user/share-related information.
- **CTFs / OSCP labs** — very relevant because lab machines often intentionally expose legacy services.
- **Internal penetration tests** — you may encounter NetBIOS over UDP **137**, NetBIOS datagrams over **138**, and NetBIOS session service over TCP **139**.

### Important distinction

Modern Windows file sharing generally uses **SMB directly over TCP 445**, so you shouldn't think:

> NetBIOS = how Windows networking works today.

A better mental model is:

> **NetBIOS = older Windows naming/session technology that you may still find around, especially in internal networks.**

For OSCP, remember **UDP 137** and **TCP 139**. If you see those open, it's worth enumerating.
