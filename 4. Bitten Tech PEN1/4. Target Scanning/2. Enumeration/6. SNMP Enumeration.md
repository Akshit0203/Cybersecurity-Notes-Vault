### SNMP — simply

**SNMP = Simple Network Management Protocol.**

It is used to **monitor and manage network devices** such as:

- Routers
- Switches
- Servers
- Printers
- Firewalls
- UPS devices

Think of SNMP as a way for an administrator to **ask a network device questions**.

For example:

> "What is your hostname?"  
> "How much traffic is going through this interface?"  
> "How much CPU/memory are you using?"  
> "What interfaces do you have?"

### How it works

Usually:

**SNMP Manager → SNMP Agent**

- **Manager** = monitoring system
- **Agent** = SNMP service running on the device
- **MIB** = database/structure containing information the agent can provide

SNMP commonly uses **UDP 161** for queries and **UDP 162** for traps/notifications.

### Why it matters for OSCP

**Very relevant during enumeration.**

If you find:

```
UDP 161 open
```

you should immediately think:

> **SNMP enumeration**

Misconfigured SNMP can leak useful information such as:

- Hostname
- Operating system information
- Network interfaces
- IP addresses
- Routing information
- Running processes
- Installed software
- System information
- Sometimes usernames or other sensitive details

A common thing you'll encounter is a **community string**, essentially a shared value used for SNMP access. The old/default one is:

```
public
```

So for OSCP, remember:

> **UDP 161 → SNMP → try enumeration → potentially lots of system/network information.**

And unlike **NetBIOS**, SNMP is still very much used in real-world networks today, although modern SNMP deployments often use **SNMPv3** because older versions have weaker security.

"...and it maintains descriptions of all managed objects. Now, what are objects? Suppose there is a device of mine.
