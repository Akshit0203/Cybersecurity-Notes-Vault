
### LDAP — simply

**LDAP (Lightweight Directory Access Protocol)** is a protocol used to **store, organize, and retrieve information about users, computers, groups, and other resources on a network.**

Think of it as a **directory/database for an organization**.

For example, a company might have:

```
Company
│
├── Users
│   ├── Alice
│   ├── Bob
│   └── Akshit
│
├── Groups
│   ├── IT
│   ├── HR
│   └── Administrators
│
└── Computers
    ├── PC01
    ├── PC02
    └── SERVER01
```

LDAP provides a standardized way for applications and systems to **query this directory**.

### Where does LDAP fit with Active Directory?

This is the important part for OSCP:

**Active Directory (AD) commonly uses LDAP.**

For example:

```
Windows Client
      │
      │ LDAP
      ▼
Domain Controller
      │
      ▼
Active Directory
```

A domain controller can use LDAP to answer questions such as:

- What users exist?
- What groups exist?
- Who is a member of the Domain Admins group?
- What computers exist?
- What attributes does a particular user have?

### LDAP ports

|Port|Use|
|---|---|
|**389**|LDAP|
|**636**|LDAPS (LDAP over TLS)|

You'll commonly see:

```
nmap -p 389,636 <IP>
```

If you find **389 open**, that's a strong indication that you're dealing with a directory service, often **Active Directory** in Windows environments.

### Why LDAP matters in OSCP

LDAP can become useful during **enumeration**.

For example, after discovering a domain controller, you may want to enumerate:

```
Domain
 ↓
Users
 ↓
Groups
 ↓
Computers
 ↓
Group memberships
 ↓
Potential attack paths
```

Tools such as **ldapsearch**, **NetExec**, and **BloodHound** can interact with directory information in different ways.

### Easy way to remember

Think of the protocols you've asked about like this:

```
SMB  → File/printer sharing
SNMP → Network/device information
LDAP → Directory information
```

And in an AD environment:

```
Active Directory
       │
       ├── LDAP → directory queries
       ├── Kerberos → authentication
       ├── SMB → file/admin sharing
       └── DNS → name resolution
```

So **LDAP is absolutely relevant today**, especially when you're doing **Active Directory enumeration**, which is very important for OSCP.
