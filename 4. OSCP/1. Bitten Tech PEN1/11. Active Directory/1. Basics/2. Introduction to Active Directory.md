# Introduction to Active Directory

---

## What is Active Directory?

**Active Directory (AD)** is a Microsoft product that consists of several services running on Windows Server to manage permissions and access to networked resources.

- AD stores data as **objects** — a single element such as a user, group, application, or device (e.g., a printer)
- AD DS (Active Directory Domain Services) verifies access when a user signs into a device or attempts to connect to a server over a network
- A Domain Controller is a server — a physical/virtual machine. Inside it, AD is the software that manages directory services

> [!important] Key Concept
> "Directory" = information stored in a **hierarchical structure** — domains, OUs, departments, user accounts, and sub-domains forming a complete tree.

---

## Active Directory Domain Services (AD DS)

Microsoft named the product **Active Directory (AD)**, and its real-world implementation is **Active Directory Domain Services (AD DS)**.

AD DS:
- Runs on Windows Server (the Domain Controller)
- Manages network resources
- Provides services for accessing resources within a domain
- **Treats every piece of data as an object**

---

## AD Objects

Everything in AD is an object:

| Object Type | Examples |
|-------------|----------|
| User | Employee accounts, service accounts |
| Computer | Workstations, servers |
| Group | Security groups, distribution groups |
| Device | Printers, scanners |
| Application | Line-of-business apps |

> Objects have defined methods and functions — like OOP, an object is an entity we can perform operations with.

---

## How Authentication Works

When a user signs in:
1. AD stores their **user account information**, **access levels**, and **access controls**
2. Local systems can use a local account database
3. Connecting to a **remote server** in a Microsoft environment relies on Active Directory

```
User wants to access File Server
        ↓
Authentication request → Active Directory
        ↓
AD verifies identity → grants/denies access
```

## Trees and Forests

### Domain Tree

A domain can contain multiple sub-domains, forming an inverted tree structure where the root domain sits at the top:

```
        example.com          ← root domain
            │
    ┌───────┴───────┐
    ▼               ▼
sales.example.com  hr.example.com   ← sub-domains
```

This implements **LDAP (Lightweight Directory Access Protocol)** — AD natively implements LDAP.

### Forest

When multiple domain trees exist — each with its own structure — combining all these trees creates a **forest**:

```
            FOREST
              │
     ┌────────┴────────┐
     ▼                 ▼
  blue.com           red.com
     │                 │
  (tree 1)          (tree 2)
```

> A forest is formed by a set of multiple trusted domain trees and is the **uppermost layer** of Active Directory.

---

## Trust Relationships

A **trust relationship** means domains can authenticate users on behalf of each other.

| Trust Type | Description |
|-----------|-------------|
| **One-way** | Domain A trusts Domain B (B's users can access A's resources, not vice versa) |
| **Two-way** | Both domains mutually trust each other |
| **Transitive** | If A trusts B, and B trusts C, then A automatically trusts C |

**Example:** If `sales.blue.com` trusts `blue.com`, and `blue.com` trusts `p.blue.com`, then `sales.blue.com` automatically trusts `p.blue.com` transitively.

---

## Organizational Units (OUs)

An OU exists **within a domain** to streamline administration by managing:
- Department scopes
- Permissions
- Administrative duties

**Example departments as OUs:** Marketing, Accounts, Sales, HR

```
        blue.com
            │
   ┌────────┼────────┐
   ▼        ▼        ▼
  Sales   Marketing   HR
  (OU)     (OU)      (OU)
```
