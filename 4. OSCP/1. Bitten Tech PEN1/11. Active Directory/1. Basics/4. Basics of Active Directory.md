# Basics of Active Directory

---

## AD vs. DC — The Key Distinction

> **AD = the directory/service and the information it manages.**
> **DC = a Windows Server running the AD Domain Services role that provides that directory service.**

```
Active Directory (AD)
│
├── Users
├── Groups
├── Computers
├── OUs
├── Policies
├── Domain information
└── Directory database
        │
        ▼
   Domain Controller (DC)
   ├── Stores AD database (NTDS.dit)
   ├── Authenticates users
   ├── Handles Kerberos/LDAP
   └── Replicates AD data with other DCs
```

**Example:**

```
Domain: corp.local

        Active Directory
             │
     ┌───────┴───────┐
     ▼               ▼
   DC01             DC02
     │               │
  AD database     AD database
   replica         replica
```

> Compromising a Domain Controller is critical — it has access to the domain's directory data and authentication infrastructure.

## 1. What is Active Directory?

AD is a **central management system for an organization's Windows network**.

Without AD → manage each computer and user individually.
With AD → centrally manage Users, Computers, Groups, Servers, Printers, Permissions, Policies, Authentication.

**Example:**

```
Company: ACME
Domain: acme.local

acme.local
│
├── Users
│   ├── Alice
│   ├── Bob
│   └── Akshit
│
├── Computers
│   ├── PC01, PC02, PC03
│
├── Servers
│   ├── DC01, FILE01
│
└── Groups
    ├── Domain Admins
    ├── IT
    └── HR
```

> AD provides a **centralized directory of objects and their relationships**.

---

## 2. What is AD DS?

**AD DS = Active Directory Domain Services** — the core directory service for a traditional Windows domain.

```
Active Directory
      │
      └── AD DS
```

### Two Core Functions

| Function | Question It Answers | Example |
|----------|-------------------|---------|
| **Authentication** | "Who are you?" | Username + password → verified by domain |
| **Authorization** | "What are you allowed to do?" | Akshit → can access FILE01, can read Documents, cannot access HR folder |

```
Authentication → Who are you?
Authorization  → What can you access/do?
```

---

## 3. Where Does AD DS Run?

A **Domain Controller (DC)** is a Windows Server running AD DS.

```
Windows Server
      │
      └── AD DS installed
              │
              ▼
       Domain Controller
              │
              ├── Authentication
              ├── Authorization
              ├── AD database
              └── AD replication
```

---

## 4. What Does AD Store?

AD stores **objects** — entities represented inside the directory.

| Object Type | Example Properties |
|-------------|-------------------|
| User | Username, Display Name, Email, SID, Groups |
| Computer | Hostname, OS, SID |
| Group | Members (users/computers), permissions |
| Printer | Location, driver, shared name |
| OU | Contained objects, linked GPOs |

> **AD is a directory/database containing information about objects in the domain.**

## 5. Benefits of Active Directory

### A. Hierarchical Organizational Structure

```
acme.local
│
├── IT
│   ├── Users
│   └── Computers
│
├── HR
│   ├── Users
│   └── Computers
│
└── Finance
    ├── Users
    └── Computers
```

Organize users logically instead of configuring each individually.

### B. Multimaster Authentication & Replication

Multiple DCs can participate in managing the directory:

```
       AD Domain
           │
    ┌──────┴──────┐
    ▼             ▼
  DC01           DC02

Admin creates user on DC01 → replicates to DC02
```

If one DC goes down, another continues providing domain services.

### C. Single Point of Access to Network Resources

Instead of separate accounts on every machine:

```
         AD
          │
   ┌──────┼──────┐
   ▼      ▼      ▼
 PC01   FILE01  SERVER01
```

One domain identity → access resources according to permissions.

### D. Trust Relationships

```
Domain A
   │
   │ Trust
   ▼
Domain B
```

Identities from one environment can access resources in another, subject to permissions.

## 7. What is a Domain?

A **domain** is a logical boundary containing AD objects.

```
Domain: org.com

org.com
│
├── Users
├── Groups
├── Computers
├── Servers
└── OUs
```

A domain also provides a **namespace**: `DC01.org.com`, `PC01.org.com`

---

## 8. AD Objects

An **object** is an entity represented inside AD:

```
User, Computer, Group, Printer, OU
```

> **If AD needs to keep information about something, it represents that thing as an object.**

---

## 9. Security Principals

A **security principal** is an identity that can be assigned permissions.

| Security Principal | Example |
|-------------------|---------|
| User | `akshit` |
| Computer | `PC01$` |
| Group | `Domain Admins` |

Each has a **SID (Security Identifier)**:

```
User → SID → S-1-5-21-...
```

Windows uses SIDs (not visible usernames) when determining security permissions.

### SID + RID

- **SID**: Identifies the domain the object belongs to (shared prefix for all objects in the same domain)
- **RID (Relative Identifier)**: Unique numerical ID for an individual object within that domain
- **SID + RID** = globally unique identifier

## 10. Forest

> A forest is a collection of trees that share a common global catalog, schema, structure, and configuration.

**Hierarchy:**

```
Object → Domain → Tree → Forest
```

### Domain

```
corp.local
```

### Tree

Related domains with a contiguous namespace:

```
            example.com
                │
        ┌───────┴───────┐
        ▼               ▼
 sales.example.com   hr.example.com
```

### Forest

Multiple domain trees:

```
              FOREST
                 │
        ┌────────┴────────┐
        ▼                 ▼
      TREE 1            TREE 2
        │                 │
    example.com       example.net
        │
   ┌────┴────┐
   ▼         ▼
 sales       hr
```

> The forest is the **largest logical AD structure**.

---

## 11. Global Catalog

A searchable directory containing information about objects across the **entire forest**.

```
Forest
│
├── Domain A → Users, Computers
└── Domain B → Users, Computers
```

The Global Catalog helps locate objects across domains.

> [!tip] For OSCP
> The **Global Catalog operates at the forest level** and helps search/locate objects across domains.

---

## 12. Organizational Units (OUs)

An OU is an **organizational container inside a domain**.

```
acme.local
│
├── OU=IT
│   ├── Alice, Bob
│   └── PC01
│
├── OU=HR
├── OU=Finance
└── OU=Sales
```

### Why Use OUs?

Apply management policies to groups of objects:

```
OU=Finance
      │
      ▼
   GPO applied
      │
      ├── Password requirements
      ├── Desktop settings
      └── Security configuration
```

### OU Naming (LDAP Format)

```
DC=org,DC=com
   │
   ├── OU=Sales
   ├── OU=Tech
   └── OU=HR
```

> `OU=Sales,DC=org,DC=com` — the OU is **not** a separate domain, it's a container within `org.com`.

## 13. Group Policy

### What is Group Policy?

> **Group Policy lets administrators centrally control how domain computers and users behave.**

Instead of manually configuring 500 computers: Disable USB, set password policy, configure firewall, Windows Defender, desktop restrictions, software control → use Group Policy.

### Local Group Policy vs. AD Group Policy

| Type | Scope | Requires AD? |
|------|-------|-------------|
| **Local GPO** | Applies to one computer only | No |
| **AD Group Policy** | Centralized, all domain-joined machines | Yes |

```
Local:                    AD Group Policy:
PC01                           AD
 │                              │
 └── Local GPO                 GPO
                                │
                      ┌─────────┼─────────┐
                      ▼         ▼         ▼
                    PC01      PC02      PC03
```

### What is a GPO?

A **Group Policy Object** is a **configuration package**:

```
GPO: Workstation Security
│
├── Password policy
├── Firewall configuration
├── Windows Defender settings
├── User restrictions
└── System configuration
```

Every GPO has two areas:

| Node | Controls | Think... |
|------|----------|----------|
| **User Configuration** | Desktop settings, start menu, user restrictions | "What happens when this user logs in?" |
| **Computer Configuration** | Security settings, services, firewall, system config | "How should this computer behave?" |

### Security Advantages of GPOs

| Advantage | Example |
|-----------|---------|
| Strong password policy | Min length, complexity, expiration, lockout |
| Principle of Least Privilege | No unnecessary admin privileges |
| Regular health checks | Centralized logging, antivirus deployment |
| System management | Configure thousands of machines centrally |

### GPO Processing Order — LSDOU

When a domain-joined computer boots or a user logs in, GPOs process in this order:

| Order | Level | Scope |
|-------|-------|-------|
| 1 | **L** — Local | Smallest scope, evaluated first |
| 2 | **S** — Site | Physical/geographical location |
| 3 | **D** — Domain | Domain-level policies |
| 4 | **OU** — Organizational Unit | Processed last, **highest precedence** |

> OU policies evaluated last → **higher-precedence OU policies override conflicting lower-level policies**.

## 14. AD vs. MDM (macOS Comparison)

| Windows Enterprise | Apple/macOS Enterprise |
|-------------------|----------------------|
| Active Directory / AD DS | Apple Platform + directory/identity services |
| Domain Controller | Directory/identity infrastructure |
| Group Policy (GPO) | MDM configuration profiles / policies |
| AD user account | Managed Apple/enterprise identity |
| Domain-joined PC | Mac enrolled in MDM |

**Key points:**
- Macs **can join** a Windows Active Directory domain
- Modern Mac management primarily uses **MDM** (Jamf, Intune, Kandji, Mosyle)
- **AD = directory/identity/domain infrastructure**
- **MDM = centralized device management**
- Microsoft Intune can manage **both Windows and macOS**

## Mental Model — Put It All Together

```
                    FOREST
                       │
             ┌─────────┴─────────┐
             │                   │
           TREE 1              TREE 2
             │
          DOMAIN
        corp.local
             │
     ┌───────┼────────┐
     │       │        │
    OUs    Users   Computers
     │
 ┌───┴────┐
 IT       HR
 │         │
Users     Users
```

**Hierarchy to memorize:**

```
FOREST → TREE → DOMAIN → OU → OBJECT
```

**And separately:**

```
DOMAIN → Domain Controller → Runs AD DS → Provides authentication, authorization, directory services, and replication
```

> [!important] The Big Picture
> AD stores and organizes identities/resources → DCs provide AD DS → domains organize those objects → OUs organize them further → GPOs control their configuration.
