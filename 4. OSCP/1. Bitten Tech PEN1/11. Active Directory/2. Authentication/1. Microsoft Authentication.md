# Microsoft Authentication — Overview

> [!NOTE]
> This is a high-level overview of the three pillars of Windows authentication. Each topic (SAM, NTLM, Kerberos) is covered in depth in subsequent notes.

---

## Why This Matters

- ~90 % of corporate internal networks run Microsoft Windows.
- Windows uses **proprietary, closed-source** authentication protocols — understanding them is essential for penetration testing.
- Attacks specifically target these protocols, making this knowledge critical for OSCP and real-world engagements.

---

## The Three Pillars

### 1. Security Accounts Manager (SAM)

- **What**: A local database file that stores user authentication data.
- **Where**: On the local machine (SAM file) or in the **Active Directory database** (domain accounts).
- **Key rule**: Passwords are **never stored in cleartext** — they are always hashed before storage.

### 2. NTLM (New Technology LAN Manager)

- **What**: Both a **hashing algorithm** and an **authentication protocol**.
- **Full form**: New Technology LAN Manager.
- **How it works**: The NTLM algorithm hashes a password → the resulting hash is stored inside the SAM file → during authentication the hash is compared.
- **Two sub-protocols**:
  - **LM** (LAN Manager) — older, weaker, deprecated.
  - **NTLM** — newer, stronger replacement.
- Comparable to other hashing families (SHA, MD5) but specific to Windows credential storage.

### 3. Kerberos

- **What**: Microsoft's **modern default authentication protocol**.
- **Improvement over NTLM**: Stronger, more efficient, with a significantly evolved ticketing mechanism.
- **Important distinction**: Kerberos handles the *authentication flow* (tickets, KDC, etc.), but the *password hashing* still uses the NTLM algorithm under the hood.

## Relationship Summary

```
User Password
    │
    ▼
NTLM Hash Algorithm  ──►  Hash stored in SAM / AD database
    │
    ▼
Authentication Protocol
    ├── NTLM Protocol  (legacy challenge-response)
    └── Kerberos       (modern ticket-based, default)
```
