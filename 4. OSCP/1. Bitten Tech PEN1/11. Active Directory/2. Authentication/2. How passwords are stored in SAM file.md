# Security Accounts Manager (SAM) Database

---

## What Is SAM?

- A **database file** present on every Windows system (XP, Vista, 7, 8, 8.1, 10, 11).
- Stores **user passwords** (hashed) and account metadata.
- Used to authenticate both **local** and **remote** users.
- Beginning with **Windows 2000 SP4**, remote/domain users are authenticated via **Active Directory** instead of the local SAM.

---

## Cryptography & Hash Storage

- SAM uses cryptographic hashing to prevent unauthenticated access.
- User passwords are stored in a **registry hive** as either:
  - **LM hash** — legacy, deprecated, blank on modern systems.
  - **NTLM hash** — current standard.

---

## SAM File Location

| Item | Value |
|---|---|
| **File path** | `C:\Windows\System32\config\SAM` |
| **Registry mount** | `HKLM\SAM` |
| **Typical size** | ~128 KB |
| **File type** | System file (no extension) |

> [!IMPORTANT]
> The `System32\config` directory contains critical OS files. The SAM file is **locked by the OS** while Windows is running — you cannot simply open it in Notepad.

## SAM File Permissions & Dumping

- Opening the SAM file directly will **fail** or show random/unintelligible data because the OS locks active registry hives.
- To extract contents, use specialised tools such as:
  - `samdump2`
  - `mimikatz` → `lsadump::sam`
  - `secretsdump.py` (Impacket)

---

## SAM Record Structure

A dumped SAM entry follows a format similar to Linux's `/etc/passwd`:

```
Username : RID : LM Hash : NTLM Hash
```

| Field | Description |
|---|---|
| **Username** | Account name (e.g., `Sheila`) |
| **RID** | Relative Identifier assigned to the user |
| **LM Hash** | Legacy LAN Manager hash — typically `NO PASSWORD` or blank on modern systems (LM disabled) |
| **NTLM Hash** | The actual password hash (stronger, current standard) |

> [!WARNING]
> Password hashes in SAM are a **prime target** during privilege escalation and credential harvesting. Extracting and cracking these hashes is a core post-exploitation technique.
