### **[Section 1: Security Accounts Manager (SAM) Overview & Role in Networks]**

In this lesson, the focus is on Microsoft's **SAM**—the **Security Accounts Manager** database. The topic centers on user authentication within a Microsoft environment and across a system. This involves not just a single system, but the entire network infrastructure and environment, which includes multiple PCs, servers, file shares, groups, and overall network configurations.

The SAM file is a database file that stores user passwords as well as additional account information. It is present across every major Windows operating system, including Windows XP, Vista, 7, 8, 8.1, and 10, and remains in use today for both local and remote authentication. Remote authentication across a network is facilitated using Active Directory, a service introduced with Windows 2000 Server Service Pack 4 to authenticate remote users.

---

### **[Section 2: Cryptography, SAM File Path, and Inspection]**

SAM employs cryptography—specifically NTLM hashing—to prevent unauthorized access to credentials. User passwords are stored within registry hives as either LM (LAN Manager) or NTLM hashes. While NTLM is the modern standard, references to NTLM implicitly include LM structures because NTLM evolved from LM.

To locate the SAM file on a Windows host, navigate from the root file system where Windows is installed:

- **Directory Path**: `C:\Windows\System32\config\SAM`.

The `System32` directory contains critical files that define the Windows operating system and should generally be accessed in read-only mode. Inside the `config` subfolder, the `SAM` file exists as a system file type with no extension, typically around 128 KB in size.

---

### **[Section 3: File Permissions, SAM Dumping, & Account Structure]**

Attempting to open the SAM file directly in Notepad or through "Open With" will fail or display unintelligible, random data because the operating system locks active registry hives from direct user reading. To inspect or dump the contents of the SAM database, specialized administrative utilities such as `samdump2` must be used.

The internal structure of the SAM database resembles the user information layout found in Linux credential files (such as `/etc/passwd`). A dumped SAM record contains:

1. **Username**: The account name (e.g., `Sheila`).
2. **User ID (RID)**: The Relative Identifier assigned to the user.
3. **LM Hash**: Legacy LAN Manager password hash. Because LM hashing is deprecated and disabled in modern Windows, this field typically displays `NO PASSWORD` or blank placeholders.
4. **NTLM Hash**: Following a colon separator, the stronger NTLM password hash is stored.

Because password hashes stored in the SAM file can be targeted for offline cracking, the SAM database represents a critical security target during privilege escalation and credential harvesting engagements. Extracting these hashes requires dedicated tools, which complete the overview of the SAM database.
