# NTLM Authentication

---

## What Is NTLM?

- **Full form**: New Technology LAN Manager.
- Both an **authentication protocol** and a **hashing algorithm**.
- Encompasses two sub-versions:
  - **LM v1/v2** — legacy, deprecated.
  - **NTLM v1/v2** — current; NTLMv2 is the modern standard.
- Works on a **Challenge-Response** mechanism to prove the user knows the password without sending it in plaintext.

## Domain vs. Local Account Authentication

| Account Type | Authentication Target | Verification Source |
|---|---|---|
| **Domain account** | Domain Controller | Active Directory database |
| **Local account** | Local machine | Local SAM file |

- **Domain account**: Registered in the Domain Controller; the PC/server is joined to the domain. Credentials are verified against the DC.
- **Local account**: Exists only on that specific machine. Credentials are verified against the local SAM file.
- In enterprise environments, **domain accounts** are used almost exclusively.

## Three Core Operations of NTLM

### 1. Authentication (Challenge-Response)

- The server sends a **challenge** (random nonce) to the client.
- The client encrypts the challenge using the NTLM hash of the user's password and returns the **response**.
- The server compares the response against its own computation using the stored hash.

### 2. Signing (Message Integrity)

- Uses a **symmetric signature scheme** (Message Authentication Code — MAC).
- Ensures the message is digitally signed and originates from the legitimate sender.
- A **shared secret key** exists between sender and receiver; messages from unauthorised parties fail validation.

### 3. Sealing (Encryption / Confidentiality)

- The **NTLM Security Support Provider (NTLMSSP)** applies symmetric encryption to network traffic.
- Protects against eavesdropping and man-in-the-middle attacks.
- Symmetric encryption is chosen for **speed**.

## Challenge-Response Flow

```
User (Sheila)                        Domain Controller
     │                                      │
     ├── 1. Enter password ────────────────►│
     │      (password is hashed)            │
     │                                      │
     │◄── 2. Challenge (random nonce) ──────┤
     │                                      │
     ├── 3. Response (hash of challenge) ──►│
     │                                      │
     │      DC compares response with       │
     │      stored hash computation         │
     │                                      │
     │◄── 4. Access Granted / Denied ───────┤
```

## NTLM vs. Kerberos

> [!NOTE]
> Microsoft has upgraded its default authentication protocol to **Kerberos**, which provides stronger authentication than NTLM. However, NTLM is still widely encountered alongside Kerberos in modern environments.
