# Kerberos Authentication

---

## What Is Kerberos?

- Microsoft's **modern default authentication protocol** (Version 5).
- Provides **mutual authentication** between client ↔ server or server ↔ server.
- The **Key Distribution Center (KDC)** uses the Active Directory database as its security account database.
- Supports authentication over the internet (not limited to LAN).

> [!IMPORTANT]
> Kerberos is the *authentication protocol* (defines how data flows across servers). The *password hashing* still uses the **NTLM algorithm** under the hood.

## Main Entities

| Entity | Role |
|---|---|
| **Client** | Software acting on behalf of the user; initiates access requests |
| **Server** | Target host where the desired service runs (SAP, FTP, SSH, etc.) |
| **Authentication Server (AS)** | Validates user credentials; issues the **TGT** |
| **Ticket Granting Server (TGS)** | Issues **Service Tickets** for specific resources |
| **Key Distribution Center (KDC)** | Logical combination of AS + TGS + AD Database; resides on the Domain Controller |

## The 6-Step Kerberos Authentication Flow

### Step 1 — User Authentication Request

User enters username + password → client sends initial request to the **AS** inside the KDC.

### Step 2 — AS Verification & TGT Issuance

- AS verifies password against the AD database.
- On success, AS encrypts a **Ticket Granting Ticket (TGT)** using a secret session key shared between AS and TGS.
- Sends encrypted TGT back to the client.

### Step 3 — Client Holds TGT

- Client receives the encrypted TGT.
- Client **cannot decrypt or alter** the TGT (lacks the AS-TGS shared key).

### Step 4 — Request to TGS

- Client sends the encrypted TGT + the **Service Principal Name (SPN)** of the desired service → to the TGS.

### Step 5 — TGS Decryption & Service Ticket Issuance

- TGS decrypts the TGT using its shared key with the AS.
- Validates the TGT, then issues a **Service Ticket** encrypted with a key shared between TGS and the target application server.

### Step 6 — Service Access

- Client presents the Service Ticket to the target application server.
- Server decrypts it and **grants access** to the requested service.

## Key Point: Hashing vs. Protocol

- **Kerberos** = authentication *protocol* (defines flow, tickets, encryption of tickets).
- **NTLM hash** = *password hashing algorithm* (how the password itself is hashed and stored in SAM/AD).
- Tickets (TGT and Service Tickets) are encrypted with shared keys known only to KDC servers and application servers — clients **cannot** decrypt, tamper with, or forge tickets.
