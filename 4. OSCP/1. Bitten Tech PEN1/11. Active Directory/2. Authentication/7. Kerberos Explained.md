# Kerberos Protocol — Deep Dive

> [!NOTE]
> This note expands on the Kerberos fundamentals from [[5. Kerberos Authentication]] with detailed message structures, protocol characteristics, and known attack vectors.

---

## History & Background

- Named after **Cerberus** — the three-headed guard dog from Greek mythology.
- Originally developed by **MIT** in the 1980s for network authentication.
- Microsoft adopted and standardised it; **Version 5** is the current standard.
- Incorporates NTLM hashing algorithms for password storage.

---

## Protocol Characteristics

| Characteristic | Description |
|---|---|
| **Stateless** | No session state maintained between steps; each request must carry all necessary metadata |
| **Symmetric Key Encryption** | Uses shared secret keys and temporary session keys |
| **Ticket-Based Access** | Users receive time-limited tickets (default **10 hours**, configurable via GPO) that grant access without re-authentication |

---

## Key Distribution Center (KDC) Components

| Component | Role |
|---|---|
| **Authentication Service (AS)** | Authenticates users during initial logon; verifies they hold valid domain credentials |
| **Ticket Granting Service (TGS)** | Issues Service Tickets for specific network resources |
| **Account Database** | Stores user IDs, passwords, and secret keys — AD uses LDAP, SAM (local), or **`ntds.dit`** (domain) |

---

## The 3 Request-Response Pairs (Detailed)

### Pair 1: `AS-REQ` / `AS-REP` (Authentication Service Exchange)

#### `AS-REQ` (Client → AS)

| Field | Content |
|---|---|
| Security Identifier (SID) | User's SID |
| Requested Service | Target service name |
| User's IP Address | Client IP |
| Desired TGT Lifetime | Default 10 hours (GPO configurable) |
| Encrypted Timestamp | Encrypted with user's NT hash (pre-authentication) |

#### `AS-REP` (AS → Client) — Two Messages

**Message A** (encrypted with user's secret key — client can decrypt):

| Field | Content |
|---|---|
| TGS ID | ID of the Ticket Granting Server |
| Timestamp | Current timestamp |
| Lifetime | Session validity |
| TGS Session Key | Shared session key for TGS communication |

**Message B — Ticket Granting Ticket (TGT)** (encrypted with `krbtgt` account hash — **client cannot decrypt**):

| Field | Content |
|---|---|
| Security Identifier (SID) | User's SID |
| TGS ID | Ticket Granting Server ID |
| Timestamp | Issuance time |
| User's IP Address | Client IP |
| TGT Lifetime | Validity period |
| TGS Session Key | Same session key (embedded in TGT) |

### Pair 2: `TGS-REQ` / `TGS-REP` (Ticket Granting Service Exchange)

#### `TGS-REQ` (Client → TGS) — Two Messages

**Message 1** (contains unmodified TGT):

| Field | Content |
|---|---|
| TGT | The encrypted TGT from AS-REP |
| Service SPN | Kerberos ID of the target service |
| Lifetime | Requested lifetime |

**Message 2 — Authenticator** (encrypted with TGS Session Key):

| Field | Content |
|---|---|
| User ID | Client identity |
| Timestamp | Current time |

#### `TGS-REP` (TGS → Client) — Two Messages

**Message E — Service Ticket** (encrypted with target service account's secret key `K_service`):

| Field | Content |
|---|---|
| User's ID | Client identity |
| User's IP Address | Client IP |
| Lifetime | Ticket validity |
| Service Session Key | New session key for service communication |

**Message F** (encrypted with TGS Session Key — client can decrypt):

| Field | Content |
|---|---|
| User ID | Client identity |
| Timestamp | Current time |
| Lifetime | Session validity |
| Service Session Key | Same key (for client's use) |

### Pair 3: `AP-REQ` / `AP-REP` (Application Server Exchange)

#### `AP-REQ` (Client → App Server) — Two Messages

**Message 1** (Service Ticket — encrypted with `K_service`):

| Field | Content |
|---|---|
| Service Ticket | The encrypted ticket from TGS-REP |
| User ID, IP, Timestamp | Client metadata |

**Message 2 — Authenticator** (encrypted with Service Session Key):

| Field | Content |
|---|---|
| User ID | Client identity |
| Timestamp | Current time |

#### `AP-REP` (App Server → Client)

| Field | Content |
|---|---|
| Timestamp | Confirmation timestamp |
| Service Session Key | Encrypted confirmation |

All subsequent session traffic is encrypted using the **Service Session Key**.

## Features of Kerberos

- **Effective Access Control** — ticket expiration limits unauthorized access windows
- **Single Sign-On (SSO)** — authenticate once with AS, then request multiple Service Tickets without re-entering passwords
- **Limited Lifetime Tickets** — default 10 hours, must be renewed
- **Mutual Authentication** — both client and server verify each other
- **Reusable Authentication** — valid TGT can be reused across multiple services
- **Strong Encryption** — modern implementations use AES (not deprecated RC4)

## Known Attack Vectors

| Attack | Description |
|---|---|
| **Golden Ticket** | Attacker compromises `krbtgt` NTLM hash → forges arbitrary TGTs with Domain Admin privileges and custom expiration |
| **Silver Ticket** | Attacker compromises a service account hash → forges Service Tickets for that specific service |
| **Pass the Hash** | Uses NTLM hashes directly to authenticate without knowing the plaintext password |
| **Pass the Ticket (PtT)** | Extracted valid TGTs or Service Tickets are re-injected into memory sessions to hijack access |
| **Overpass the Hash** | Uses NTLM hash to request a Kerberos TGT (hybrid NTLM→Kerberos attack) |
| **Kerberoasting** | Any authenticated user requests Service Tickets → extracts encrypted tickets → cracks service account passwords offline |
