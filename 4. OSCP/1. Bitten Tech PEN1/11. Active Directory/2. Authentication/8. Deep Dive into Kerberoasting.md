
What is Kerberoasting?
▸ Service principal names (SPNs) are used to uniquely identify each
instance of a Windows service.
▸ By logging into an Active Directory domain as any authenticated user,
we are able to request service tickets (TGS) for service accounts by
specifying their SPN value.
▸ Active Directory will return an encrypted ticket, which is encrypted
using the NTLM hash of the account that is associated with that SPN.
▸ Used to harvest TGS tickets for services that run on behalf of user
accounts in the AD, not computer accounts.

### **[Section 2: Service Principal Names (SPNs) & Service Accounts]**

To understand Kerberoasting, we first need to define **Service Principal Names (SPNs)**. An SPN is a unique identifier assigned to a network service instance. Services can include file shares, web servers (IIS), file servers (CIFS), database servers (SQL Server), or printers.

In Windows and Active Directory, when a service executes, it runs under the security context of a specific account. In Linux, services run under dedicated service accounts like `mysql`, `ftpd`, or `smtp`. Similarly, in modern Active Directory environments, services are associated with service accounts.

Administrators often configure **domain user accounts** to act as service accounts—for example, creating a domain user account specifically to execute IIS or Microsoft SQL Server.

---

### **[Section 3: Kerberos Ticket Exchange & The Authorization Void]**

To request a service ticket in a Kerberos environment, an attacker must first be an authenticated domain user holding a valid Ticket Granting Ticket (TGT).

When an authenticated user requests a service ticket from the Ticket Granting Server (TGS) by presenting a valid TGT and an SPN, a critical design choice occurs:

- The TGS **does not verify authorization**—it does not check whether the requesting user ought to have access to that service account.
- The TGS simply issues the requested service ticket (`TGS-REP`) without validating user authorization for that specific resource.
- Actual authorization checking is deferred until the client presents the ticket to the target application server.

---

### **[Section 4: Service Ticket Encryption & Offline Hash Cracking]**

When the TGS generates a service ticket (`TGS-REP`), it encrypts the ticket using the **NTLM/NT password hash of the service account** associated with that SPN.

Because many service accounts are configured as domain user accounts, the resulting service ticket is encrypted with that domain user's password hash.

- Anyone holding a valid domain account can request a service ticket for any SPN.
- The returned service ticket contains data encrypted with the target service account's NT hash.
- The attacker extracts this encrypted ticket from memory and performs **offline password cracking** (using tools like Hashcat or John the Ripper) on their local machine.
- Because the cracking occurs offline, no network traffic is generated to the Domain Controller or service server, avoiding detection and lockouts.

This attack exploits the fundamental workflow design of Kerberos rather than a software bug. Tim Medin first demonstrated Kerberoasting at DerbyCon in 2014.

---

### **[Section 5: Targeting User Accounts vs. Computer Accounts]**

Kerberoasting specifically targets **user accounts** configured with SPNs, rather than computer accounts.

- **Computer Accounts**: Passwords for machine accounts are generated automatically by Active Directory, are 120+ characters long, and rotate frequently, making them virtually impossible to crack offline.
- **User Accounts**: Passwords for user accounts acting as service accounts are set manually by administrators, rarely change, and are often vulnerable to dictionary or wordlist attacks.

---

### **[Section 6: Required Prerequisites & Exploitation Tools]**

For Kerberoasting to succeed, two main conditions must be met:

1. **Valid Domain Credentials**: The attacker must already hold initial access as a valid domain user to obtain a TGT.
2. **Non-Null SPN Attribute**: The target domain user account must have a populated `ServicePrincipalName` (SPN) attribute.

#### **Common Exploitation Tools**:

- **Impacket**: `GetUserSPNs.py` requests SPNs and dumps Kerberoastable tickets directly.
- **PowerShell / PowerSploit**: `PowerView.ps1` (`Get-DomainUser -SPN`) or Active Directory PowerShell modules.
- **Cracking Frameworks**: `hashcat`, `john`, or Impacket's `tgsrepcrack`.
