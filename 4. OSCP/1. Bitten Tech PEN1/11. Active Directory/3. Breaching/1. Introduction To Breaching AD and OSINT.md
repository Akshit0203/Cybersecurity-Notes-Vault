OSINT and Phishing



Two popular methods for gaining access to that first set of AD credentials is Open Source Intelligence (OSINT) and Phishing. We will only briefly mention the two methods here, as they are already covered more in-depth in other rooms.  

**OSINT**

OSINT is used to discover information that has been publicly disclosed. In terms of AD credentials, this can happen for several reasons, such as:

- Users who ask questions on public forums such as [Stack Overflow(opens in new tab)](https://stackoverflow.com/) but disclose sensitive information such as their credentials in the question.
- Developers that upload scripts to services such as [Github(opens in new tab)](https://github.com/) with credentials hardcoded.
- Credentials being disclosed in past breaches since employees used their work accounts to sign up for other external websites. Websites such as [HaveIBeenPwned(opens in new tab)](https://haveibeenpwned.com/) and [DeHashed(opens in new tab)](https://www.dehashed.com/) provide excellent platforms to determine if someone's information, such as work email, was ever involved in a publicly known data breach.  
    

By using OSINT techniques, it may be possible to recover publicly disclosed credentials. If we are lucky enough to find credentials, we will still need to find a way to test whether they are valid or not since OSINT information can be outdated. In Task 3, we will talk about NTLM Authenticated Services, which may provide an excellent avenue to test credentials to see if they are still valid.


**Phishing**

Phishing is another excellent method to breach AD. Phishing usually entices users to either provide their credentials on a malicious web page or ask them to run a specific application that would install a Remote Access Trojan (RAT) in the background. This is a prevalent method since the RAT would execute in the user's context, immediately allowing you to impersonate that user's AD account. This is why phishing is such a big topic for both Red and Blue teams.

### **[Section 4: Configuring Local DNS Settings]**

Connecting to the VPN alone is insufficient; you must also configure local DNS settings on your attacking machine so that domain names resolve correctly across the lab network.

**DNS Configuration Steps**:

1. Open **Advanced Network Configuration** on Kali Linux (or edit your network profile).
2. Navigate to **IPv4 Settings** and locate the **Additional DNS Servers** field.
3. Enter the primary Domain Controller's IP address (`THMDC`) first.
4. Append a public DNS server IP (e.g., Google Public DNS `8.8.8.8`) separated by a comma so that you maintain public internet connectivity alongside local domain resolution:
    
    ```
    <DC_IP_ADDRESS>, 8.8.8.8
    ```
    
5. Save the configuration and restart the Network Manager service:
    
    ```
    sudo systemctl restart NetworkManager
    ```
    
6. Complete the initial setup confirmation tasks on the TryHackMe interface.

### **[Section 5: Initial Access Vectors — OSINT & Phishing]**

#### **1. Open Source Intelligence (OSINT)**

OSINT involves gathering actionable intelligence from publicly available sources:

- **Stack Overflow & Code Snippets**: Developers troubleshooting code often paste snippets containing hardcoded configuration details, usernames, passwords, API keys, or database credentials.
- **Public GitHub Repositories**: Freelancers or contract developers sometimes inadvertently commit proprietary scripts or configuration files containing Active Directory credentials to public GitHub repositories. Tools like GitHub Recon and GitLeaks help identify these exposed secrets.
- **Breach Aggregation Platforms**: Public breach lookup services (such as _Have I Been Pwned_ or _DeHashed_) allow attackers to identify exposed corporate email addresses and leaked credentials from historical third-party data breaches.

#### **2. Phishing Campaigns**

Phishing remains a primary initial access vector in red team engagements and corporate penetration tests:

- **Targeted Spear-Phishing**: Sending customized emails containing malicious URLs, weaponized Office macros, or zero-day exploits to corporate employees.
- **Payload Execution**: Executing Remote Access Trojans (RATs) or malicious attachments to establish reverse shell connections back to the attacker's infrastructure.
