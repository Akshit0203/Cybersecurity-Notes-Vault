# Introduction to AD Enumeration

Enumeration is the **first step** once you are inside Active Directory. It is a post-exploitation / privilege-escalation activity — it begins only *after* you gain access to a domain-joined workstation as a domain user.

> In OSCP, the hard part is usually not **how** to attack, but **what** to attack. Enumeration is what reveals *what* to exploit.

Initial access to an AD environment is usually obtained through **non-AD vectors** (web services, network services, standard testing procedures). AD techniques only apply once you have at least one user or service account and an interactive shell inside the domain.

## Prerequisites

- Low-privileged access / foothold on a domain workstation (as a domain user belonging to that domain).
- An interactive shell as a domain user.

> Administrator or `SYSTEM` access is **not** required — any ordinary low-privileged domain account is enough to start enumerating.

## Two Enumeration Avenues: Users and Services

### Service Enumeration

- Each service runs in the context of an OS user. Services launched by the system run under **Service Accounts**.
- Complex enterprise applications run under a dedicated **domain user account** (e.g. a SQL user for SQL Server, an IIS/HTTP user for IIS). The same pattern exists on Linux (dedicated MySQL, FTP, SMTP accounts).
- A **Service Principal Name (SPN)** is a unique service *instance* identifier that associates a service to its service account in AD. A service can have multiple running instances across the network, and each instance gets its own SPN.
- Example services: **SQL, Exchange, IIS**.

**Why it matters (Kerberoasting target discovery):** In Kerberos authentication, accessing a service requires a **Service Ticket**. These tickets are encrypted; if you crack the encryption you obtain access to the underlying service account.

So the goal is to **query all domain accounts and find which ones have a valid (non-null) SPN** — every account with a populated SPN is a potential target for a service-based attack. This is the initial service enumeration step, and it can be done with PowerShell, BloodHound, SharpHound, and others.

### User Enumeration

- Target is to generate an **enumeration map** of the domain.
- Find domain users first, then currently logged-in users on the compromised machine.
- These users can be enumerated further to obtain high-value info: high-value domain groups, SPNs, ACLs, attributes, etc.
- Compromising these users allows **lateral movement** to compromise more domain machines.

Once you have initial access as a user, you escalate privileges → administrator → post-exploitation → lateral movement. To plan this, you build an enumeration map, for which the primary tool is **BloodHound**.

BloodHound recursively maps all privileges, user accounts, access controls, attributes, and object properties across the domain, and establishes the relationships between them. It reveals account names, `sAMAccountName` values, associated SPNs, creation dates, group memberships, whether an account is a high-value target, and whether it is Kerberoastable. Because it is built for security auditing / pentesting, when it finds an interesting target it also illustrates **attack paths** to exploit it.

## Tools Used

- **PowerShell** (PowerView, PowerSploit / PowerUp) — heavily used when you have interactive Windows access.
- **BloodHound** (Linux GUI) with **SharpHound** (Windows data collector, from GitHub) — the most powerful enumeration tool; best for visual mapping and attack paths.
- **Command Prompt** — basic enumeration (e.g. `net user /domain` to list domain users). Works but is far less powerful, lacks deep data, and needs many cumbersome commands.

## Example Attack Chain (Lateral Movement → Domain Admin)

This is the exact methodology expected in **OSCP**. A typical AD exam environment has **one Domain Controller and two clients**.

1. **Initial access as Bob on Client 1.** Enumerate the domain to find other workstations and the Domain Admins.
2. Discover that **Bob is a local administrator on Client 2** (or is logged into it). Use Bob's logged-in credentials from Client 1 to log into Client 2 → **first lateral movement**.
3. On **Client 2**, enumerate users and permissions. Discover that **Alice is a local administrator on Server 1** (the Domain Controller).
4. Acquire **Alice's password hash** through post-enumeration exploitation, then perform a **Pass-the-Hash** attack to gain access to **Server 1**.
5. Once on Server 1 (the DC), enumerate further to reach the **Domain Admin** account (e.g. Jeff) → **Domain Admin privileges achieved.**

The complete chain — from low-privileged user all the way to Domain Admin — must be executed to earn full points.

Typical OSCP AD flow:
- Initial access on Client 1 → escalate to Administrator / `SYSTEM`.
- Initial access on Client 2 → escalate to `SYSTEM`.
- Compromise the third machine (the Domain Controller) → **Domain Admin**.
