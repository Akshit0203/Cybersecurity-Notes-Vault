# LAB - Enumeration Lab Setup

**Room:** TryHackMe — Enumerating Active Directory
https://tryhackme.com/room/adenumeration

This room follows on from **Breaching AD**. Once you have initial (low-level, guest-level) access on an AD machine — obtained through AD or non-AD methods — you enumerate it. Enumeration continues even after privilege escalation, because post-exploitation requires continuous enumeration to support **lateral movement** across machines until you reach Domain Admin / the highest privilege in the environment.

## Lab Topology

- **THMDC** — Domain Controller.
- **THM-IIS** — server hosting a service at `distributor.<domain>`.
- **THM-MDT** — workstation.
- **THM-JMP1** — workstation (the jump box you log into).

Tools exercised in this room: **MMC (Microsoft Management Console)**, **Command Prompt**, **PowerShell**, and finally **BloodHound** (the most critical AD enumeration tool).

## 1. Connect to the Special VPN

This room uses a **dedicated VPN segment** — standard TryHackMe OpenVPN configs will not work.

1. Navigate to the TryHackMe Access page → select the **Breaching AD** network pack.
2. Download the custom OpenVPN config file.
3. Connect:

```bash
sudo openvpn breaching_ad.ovpn
```

4. Verify your connection shows **Connected** with an assigned internal IP.

![415](attachments/Pasted%20image%2020261005085933.png)

## 2. Configure DNS

Connecting to the VPN alone is insufficient — local DNS must resolve lab domain names. Your safest bet for a DNS server is the Domain Controller's IP, so your system can resolve all domain services and servers across the network. (Internal DNS is sometimes configured automatically via DHCP/VPN, but **not** on this network.)

1. Open **Advanced Network Configuration** in Kali.

![277](attachments/Pasted%20image%2020261005104322.png)

2. Double-click your connection name.

![432](attachments/Pasted%20image%2020261005104450.png)

3. Go to **IPv4 Settings**.

![459](attachments/Pasted%20image%2020261005104545.png)

4. In **Additional DNS Servers**, enter the DC IP first, then Google DNS for internet access:

```
10.200.70.101, 8.8.8.8
```

![505](attachments/Pasted%20image%2020261005104653.png)

![509](attachments/Pasted%20image%2020261005104836.png)

5. Save, then restart NetworkManager:

```bash
sudo systemctl restart NetworkManager
```

## 4. RDP into the System

In the username field, use the format `Domain name\username`:

```
"Domain name\username"
```

```
xfreerdp /v:THMJMP1.za.tryhackme.com /u:marcus.riley /p:Svlr0694 /cert:ignore /dynamic-resolution
```

### RDP vs SSH

Prefer **RDP** — SSH only gives command-line access, which limits GUI-based management tasks (e.g. MMC). If RDP (port 3389) is blocked, fall back to SSH.

## Lab Stability Note

This specific room runs on a **shared network segment** (no dedicated instance), so it is known to be unstable. Common symptom: `DNS name not found` on RDP even though the network shows "Running." Resetting the network requires a **group vote (5 votes)**, and other users' conflicting actions can disable the network. If a credential pair fails, generate a new set from the portal. For stable hands-on AD practice, dedicated labs like **Hack The Box Pro Labs** (Dante, RastaLabs) are more reliable.
