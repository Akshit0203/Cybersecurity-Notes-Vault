## What is MMC?

**Microsoft Management Console (MMC)** is a Windows framework that provides a **graphical interface for managing and configuring Windows systems**. Think of it as a **container** that hosts different Windows administration tools.

```
             Microsoft Management Console (MMC)
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     Event Viewer    Services       Device Manager
          │              │              │
      View logs      Manage        Manage hardware
                     services
```

MMC itself doesn't perform the management task — it loads specialized **snap-ins**.

### Snap-ins

A **snap-in** is an administrative component you add to MMC. Launch MMC with `mmc.exe`, then use **File → Add/Remove Snap-in** to add tools.

| Snap-in | Purpose |
|---|---|
| `eventvwr.msc` | Event Viewer |
| `services.msc` | Windows Services |
| `devmgmt.msc` | Device Manager |
| `compmgmt.msc` | Computer Management |
| `gpedit.msc` | Local Group Policy Editor |
| `dsa.msc` | Active Directory Users and Computers |
| `certmgr.msc` | Certificates |

### Why `.msc` files?

`.msc` means **Microsoft Management Console snap-in file**:

```
services.msc → MMC loads the Services snap-in → you get the Services management GUI
```

### In cybersecurity

Many Windows admin tools are built around MMC. In an AD environment:

```
MMC
 ├── Active Directory Users and Computers
 ├── Group Policy Management
 ├── Event Viewer
 ├── Certificates
 └── Computer Management
```

Security testers encounter MMC when enumerating **users, groups, services, policies, certificates, and domain configuration**.

> 🧠 **Memory trick:** MMC = the Windows management toolbox/container. Snap-ins = the individual tools you put inside the toolbox.

## Installing the RSAT AD Snap-Ins

The provided VM (THMJMP1) already has RSAT installed. On your own Windows machine:

1. Press **Start**
2. Search **"Apps & Features"** and press enter
3. Click **Manage Optional Features**
4. Click **Add a feature**
5. Search for **"RSAT"**
6. Select **"RSAT: Active Directory Domain Services and Lightweight Directory Tools"** and click **Install**

## Adding & Configuring the AD RSAT Snap-Ins

1. Click **File → Add/Remove Snap-in**
2. Select and **Add** all three Active Directory snap-ins:
   - **Active Directory Domains and Trusts**
   - **Active Directory Sites and Services**
   - **Active Directory Users and Computers**
3. Click through any errors and warnings
4. Right-click **Active Directory Domains and Trusts** → **Change Forest** → enter `za.tryhackme.com` as **Root domain** → **OK**
5. Right-click **Active Directory Sites and Services** → **Change Forest** → enter `za.tryhackme.com` → **OK**
6. Right-click **Active Directory Users and Computers** → **Change Domain** → enter `za.tryhackme.com` → **OK**
7. Right-click **Active Directory Users and Computers** in the left-hand pane
8. Click **View → Advanced Features** (reveals additional containers/attributes hidden by default)

> The snap-ins take a little time to load as they authenticate against the domain in the background. Without configuring the forest/domain, expanding them shows no objects.

### Inspecting Object Attributes

Double-clicking a **user** shows publicly accessible info: First/Last/Display Name, Address, Account settings (incl. Logon Name), Profile path, Organization, Telephone. Key tabs:
- **Security** — assigned permissions and group memberships (e.g. checkboxes like *Read Personal Information*, *Read General Information*). Can't modify without admin rights.
- **Member Of** — security groups the user belongs to (e.g. Domain Users, Internet Access).
- **Sessions** — inspect/terminate disconnected sessions; Remote Control settings.
- **Object** — object class and creation timestamps.

Inspecting a **server** object shows DNS name, Domain Controller type, OS (**Windows Server 2019 Standard**), domain membership, delegation settings, security access controls, and creation metadata.

### Targeting High-Value Accounts

The real goal is choosing your **next target user**. From Task Manager we saw **`T1_Henry_Miller`** logged in — a **Tier 1 admin**. Checking his group memberships confirms **Domain Users** + **Tier 1 Admins**. Compromising him → elevate to **Tier 1 admin**, then push toward **Tier 0 admin** (highest domain authority).

## Benefits

- The GUI provides an excellent holistic view of the AD environment.
- Rapid searching of different AD objects.
- Direct method to view specific updates of AD objects.
- With sufficient privileges, you can directly update existing AD objects or add new ones.

## Drawbacks

- Requires RDP (GUI) access to the machine where it is executed.
- Although searching for a single object is fast, gathering AD-wide properties/attributes cannot be performed.
