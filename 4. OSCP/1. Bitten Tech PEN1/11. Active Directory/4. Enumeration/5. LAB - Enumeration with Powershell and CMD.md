# Task 4 — Enumeration through Command Prompt (`net`)

Sometimes you just need a quick and dirty AD lookup. Good ol' reliable **CMD** is handy when you don't have RDP access, defenders are monitoring for PowerShell use, or you're enumerating through a **Remote Access Trojan (RAT)**. You can even embed a couple of simple AD enumeration commands in a **phishing payload** to gather the info needed to stage the final attack.

CMD's built-in **`net`** command enumerates information about the local system and AD. `net <sub-option>` targets the local machine; adding `/domain` queries the Domain Controller.

> **Note:** For this task you must use **THMJMP1** (not your own Windows VM) — see drawbacks.

### Password policy (`net accounts /domain`)

`net accounts /domain` reveals the domain password policy — useful for planning **password spraying** without locking out accounts:

- **Length of password history** kept (how many unique passwords before reuse).
- **Lockout threshold** for incorrect attempts and **lockout duration**.
- **Minimum password length**.
- **Maximum password age** (whether passwords must rotate).

This helps you guess which single passwords to try and how many attempts you can make before risking lockouts. (Note: blind spraying may still lock accounts, since you didn't check each account's remaining attempts.)

Full `net` command reference: https://docs.microsoft.com/en-us/troubleshoot/windows-server/networking/net-commands-on-operating-systems

## Benefits

- No additional/external tooling; these simple commands are often **not** monitored by the Blue team.
- No GUI required.
- VBScript and other macro languages used for phishing payloads support these commands natively — usable to enumerate initial AD info before crafting more specific payloads.

## Drawbacks

- `net` commands must run from a **domain-joined machine** — otherwise it defaults to the WORKGROUP domain.
- May not show all information (e.g. a user in more than ten groups won't have all groups shown).

# Task 5 — Enumeration through PowerShell

PowerShell is the upgrade of Command Prompt (first released 2006). It has all standard CMD functionality plus **cmdlets** (pronounced *command-lets*) — .NET classes that perform specific functions. You can write your own (as PowerView's creators did), but the built-in ones get you very far.

Installing the **AD-RSAT** tooling (Task 3) automatically installed the associated cmdlets — **50+** of them. Full cmdlet list: https://docs.microsoft.com/en-us/powershell/module/activedirectory/?view=windowsserver2022-ps

From an SSH terminal, upgrade to a PowerShell terminal with: `powershell`

## What are cmdlets?

> A **cmdlet** is a small PowerShell command designed to perform one specific operation.

Examples:

```
Get-Process
Get-Service
Get-ADUser
Get-ChildItem
Set-Location
```

### Naming pattern: `Verb-Noun`

```
Get-Process
│   │
│   └── Noun: what you're working with
└────── Verb: what you're doing
```

### Cmdlets vs traditional Windows executables

PowerShell runs both. These are equivalent-ish for inspecting IP config:

```
ipconfig              ← traditional Windows executable (ipconfig.exe)
Get-NetIPConfiguration ← PowerShell cmdlet
```

PowerShell treats data as **objects** rather than plain text, so you can query objects, build custom ones, apply pipeline filters, and script automation. Because it provides deep access into AD, it's always preferred over CMD during assessments. It also supports tab completion and syntax suggestions.

## Users — `Get-ADUser`

```markup
PS C:\> Get-ADUser -Identity gordon.stevens -Server za.tryhackme.com -Properties *

AccountExpirationDate                :
accountExpires                       : 9223372036854775807
AccountLockoutTime                   :
[...]
Deleted                              :
Department                           : Consulting
Description                          :
DisplayName                          : Gordon Stevens
DistinguishedName                    : CN=gordon.stevens,OU=Consulting,OU=People,DC=za,DC=tryhackme,DC=com
[...]
```

Parameters:
- **`-Identity`** — the account name being enumerated.
- **`-Properties`** — which properties to show; `*` shows all.
- **`-Server`** — since we're not domain-joined, point it at the domain controller.

> Running `Get-ADUser` with no parameters prompts for a mandatory filter rather than returning all users at once.

Use **`-Filter`** for more control and pipe into **`Format-Table`** (`ft`) to display neatly:

```markup
PS C:\> Get-ADUser -Filter 'Name -like "*stevens"' -Server za.tryhackme.com | Format-Table Name,SamAccountName -A

Name             SamAccountName
----             --------------
chloe.stevens    chloe.stevens
samantha.stevens samantha.stevens
[...]
janice.stevens   janice.stevens
gordon.stevens   gordon.stevens
```

## AD Objects — `Get-ADObject`

A more generic search for any AD objects. For example, all objects changed after a specific date:

```markup
PS C:\> $ChangeDate = New-Object DateTime(2022, 02, 28, 12, 00, 00)
PS C:\> Get-ADObject -Filter 'whenChanged -gt $ChangeDate' -includeDeletedObjects -Server za.tryhackme.com

Deleted           :
DistinguishedName : DC=za,DC=tryhackme,DC=com
Name              : za
ObjectClass       : domainDNS
ObjectGUID        : 518ee1e7-f427-4e91-a081-bb75e655ce7a

Deleted           :
DistinguishedName : CN=Administrator,CN=Users,DC=za,DC=tryhackme,DC=com
Name              : Administrator
ObjectClass       : user
ObjectGUID        : b10fe384-bcce-450b-85c8-218e3c79b30f
```

To stage a **password spraying attack without locking out accounts**, enumerate accounts with a `badPwdCount` greater than 0 and avoid them:

```markup
PS C:\> Get-ADObject -Filter 'badPwdCount -gt 0' -Server za.tryhackme.com
PS C:\>
```

This only shows results if a user mistyped their password a couple of times. (If an account has a lockout threshold — e.g. 3/5/10 attempts — entering wrong credentials locks it, so exclude such accounts or throttle attempts.)

## Domains — `Get-ADDomain`

Retrieve high-level domain metadata (essential for advanced Kerberos attacks like Golden/Silver Tickets):

```markup
PS C:\> Get-ADDomain -Server za.tryhackme.com

AllowedDNSSuffixes                 : {}
ChildDomains                       : {}
ComputersContainer                 : CN=Computers,DC=za,DC=tryhackme,DC=com
DeletedObjectsContainer            : CN=Deleted Objects,DC=za,DC=tryhackme,DC=com
DistinguishedName                  : DC=za,DC=tryhackme,DC=com
DNSRoot                            : za.tryhackme.com
DomainControllersContainer         : OU=Domain Controllers,DC=za,DC=tryhackme,DC=com
[...]
UsersContainer                     : CN=Users,DC=za,DC=tryhackme,DC=com
```

All AD cmdlets follow a consistent structure: `Get-ADUser`, `Get-ADGroup`, `Get-ADObject`, `Get-ADDomain`.

## Altering AD Objects — `Set-ADAccountPassword`

Some AD-RSAT cmdlets can create or alter AD objects. Our focus here is **enumeration** — creating/altering objects is AD **exploitation** (covered later). Example of force-changing a user's password:

```markup
PS C:\> Set-ADAccountPassword -Identity gordon.stevens -Server za.tryhackme.com -OldPassword (ConvertTo-SecureString -AsPlaintext "old" -force) -NewPassword (ConvertTo-SecureString -AsPlainText "new" -Force)
```

> Change the identity/password to the account you were provided on the distributor webpage in Task 1. As a standard user you can only change your **own** password, not others'.

## Benefits

- Enumerates significantly **more** information than `net` commands.
- Can specify the server and domain, so it works via `runas` from a non-domain-joined machine.
- You can write your own cmdlets to enumerate specific info.
- AD-RSAT cmdlets can directly change AD objects (reset passwords, add users to groups).

## Drawbacks

- PowerShell is **monitored more** by blue teams than Command Prompt (process creation + script block logging; many EDR rules flag AD cmdlets).
- Requires installing AD-RSAT tooling or using other, potentially detectable, scripts.

> Effective in internal audits, CTFs, and lab exams (OSCP), but red teams in monitored environments must minimize noise.
