# Introduction to Lateral Movement

## What is Lateral Movement?

Lateral movement is the set of techniques used to move around a network. Once we gain access to the first machine, we use the resources and credentials available on it to exploit and access other machines.

- **Importance:** obtain more privileges on the network and discover new internal assets.
- **Common protocols exploited:** WinRM, SSH, VNC, RDP.

Simply obtaining initial access or escalating privileges on a single machine does not guarantee Domain Admin. Domain accounts and domain objects can be present on and accessed from multiple machines across the domain, so you must traverse complete attack chains to compromise an environment and reach **Domain Admin**. In modern enterprise deployments, machines and domains rarely sit on a single isolated network segment, which also makes **pivoting** necessary.

## Why Move Laterally — Domain Accounts & Cached Credentials

In an Active Directory domain, a user is not limited to logging into their assigned workstation. A domain user can log into any workstation across the domain, provided Group Policy allows it.

If a Domain Admin has logged into another workstation, their credentials can be extracted from memory (the **LSASS cache**). Extracting them requires **local administrator rights** on that target first — so you must move laterally to that machine before you can access the Domain Admin credentials.

This movement is also essential for **pivoting**, which becomes possible once you compromise a machine serving as a **pivot point** with network interfaces connected to both networks.

Enumeration may reveal that a high-value user account is active on another machine, creating **transitive relationships** an attacker can exploit. Being restricted to a single host also severely limits visibility; moving to another system exposes a broader attack surface for further enumeration.

## Legitimate Protocols for Lateral Movement

Lateral movement frequently relies on legitimate administrative implementations built into Windows:

- **WinRM (Windows Remote Management):** a legitimate remote management protocol used by admins, which can be leveraged by an attacker.
- **RDP, SSH, and VNC:** standard remote access protocols used to log into additional systems.

These techniques do not necessarily exploit software vulnerabilities or misconfigurations. Instead they abuse legitimate Microsoft services for unauthorized access using credentials, hashes, or passwords obtained earlier. The services themselves remain authentic and legitimate.

## The Lateral Movement Attack Cycle

Lateral movement is a **cycle**, not a single linear step:

1. **Reconnaissance & Initial Access** — external recon, initial compromise, establish a foothold.
2. **Privilege Escalation** — elevate privileges locally using OS or AD privilege escalation techniques.
3. **Internal Reconnaissance** — enumerate the compromised host with tools like **BloodHound** or **PowerShell** to map privileges, user objects, and target machines.
4. **Credential Harvesting & Lateral Movement** — once local admin is obtained, harvest passwords, hashes, and Kerberos tickets to move to the next target.
5. **Persistence** — maintain presence on the newly accessed system.

This cycle repeats until you compromise a Domain Controller (DC) and obtain Domain Admin privileges.

## Reaching Domain Admin

In a typical environment with two client workstations and one Domain Controller, the cycle runs across both workstations before compromising the DC. Enumeration will have already identified which accounts belong to the **Domain Admins** group.

Once you obtain the password or hash of a Domain Admin account, you gain full control over the Domain Controller. The next technique covered is **Pass-the-Hash**, the primary technique for lateral movement.
