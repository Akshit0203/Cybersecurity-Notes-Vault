### **[Section 1: Introduction to Lateral Movement and Pivoting]**

In this video, we begin discussing **Active Directory lateral movement and pivoting**, both of which are covered in this module. Understanding these concepts is essential because modern Active Directory architectures require traversing complete attack chains to compromise an environment and reach **Domain Admin**. Furthermore, in modern enterprise deployments, machines and domains rarely exist on a single isolated network segment, making **pivoting** necessary.

Lateral movement is critical because simply obtaining initial access or escalating privileges on a single machine does not guarantee Domain Admin privileges. This is because domain accounts and domain objects can be present on and access multiple machines across the domain.

---

### **[Section 2: Domain Accounts, Cached Credentials, and the Need to Move Laterally]**

In an Active Directory domain, a user is not limited to logging into their assigned workstation. A domain user can log into any workstation across the domain, provided Group Policy allows it.

If a Domain Admin has logged into another workstation, their credentials can be extracted from memory (**LSASS cache**). However, extracting those credentials requires having access—specifically **local administrator rights**—on that target system first. Therefore, you must move laterally across the network to that machine before you can access the Domain Admin credentials.

This movement is also essential for pivoting, which becomes possible once you compromise a machine serving as a **pivot point** that has network interfaces connected to both networks. By leveraging existing privileges and compromised resources, you utilize compromised systems to access other machines.

Enumeration may reveal that a high-value user account is active on another machine, creating **transitive relationships** that an attacker can exploit. Additionally, being restricted to a single host severely limits visibility into the rest of the network. Moving to another system exposes a broader attack surface for further enumeration and next steps.

---

### **[Section 3: Legitimate Protocols for Lateral Movement]**

Lateral movement frequently relies on legitimate administrative implementations built into the Windows environment. For example:

- **WinRM (Windows Remote Management)**: A legitimate remote management protocol used by system administrators to manage Windows systems remotely, which can be leveraged by an attacker.
- **RDP, SSH, and VNC**: Standard remote access protocols used to move laterally and log into additional systems.

These techniques do not necessarily exploit software vulnerabilities or misconfigurations. Instead, they exploit legitimate services provided by Microsoft for unauthorized access using credentials, hashes, or passwords obtained during earlier phases. The services themselves remain authentic and legitimate.

---

### **[Section 4: The Lateral Movement Attack Cycle]**

The lateral movement cycle follows a structured attack methodology:

1. **Reconnaissance & Initial Access**: Conduct external reconnaissance, achieve initial compromise, and establish a foothold on a machine.
2. **Privilege Escalation**: Elevate privileges on the local system using operating system or Active Directory privilege escalation techniques.
3. **Internal Reconnaissance**: Perform enumeration on the compromised host using tools like **BloodHound** or **PowerShell** scripts to map available privileges, user objects, and target machines.
4. **Credential Harvesting & Lateral Movement**: Once local administrator rights are obtained, harvest passwords, hashes, and Kerberos tickets to move laterally to the next identified target system.
5. **Persistence**: Maintain presence on the newly accessed system.

This cycle repeats continuously until you compromise a Domain Controller (DC) and obtain Domain Admin privileges.

---

### **[Section 5: Reaching Domain Admin & Module Conclusion]**

In an environment with two client workstations and one Domain Controller, this cycle is typically executed across both workstations before compromising the DC. Enumeration will have already identified which user accounts belong to the **Domain Admins** group.

Once you obtain the password or hash of a Domain Admin account, you gain full control over the Domain Controller. Keeping this attack cycle in mind is fundamental for traversing Active Directory environments. In the next video, we will cover **Pass-the-Hash**, which serves as the primary technique for lateral movement.
