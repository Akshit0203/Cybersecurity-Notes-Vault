# LAB — Pass the Ticket

## Concept

Pass-the-Ticket moves laterally by passing a **Kerberos ticket** instead of a hash. Two ticket types:
- **TGT (Ticket Granting Ticket)** — valid for every service the user is permitted to access (broad).
- **TGS (Ticket Granting Service ticket)** — valid for one specific service only.

We prioritize extracting the **TGT** because it grants broader access. We cannot *forge* a TGT here (that needs the `krbtgt` NT hash — a Golden Ticket), so instead we **extract tickets already in memory** and inject them.

Pass-the-Ticket is essential where tools strictly demand Kerberos and reject NTLM — whenever Pass-the-Hash fails, Pass-the-Ticket is the alternative. At a practical level both achieve the same lateral movement; the only difference is the authentication protocol (NTLM vs Kerberos).

**Extracting vs. injecting from "memory":** we extract a ticket from one user's session (LSASS process memory) and inject it into *our* session context (ticket cache). Extracting **TGTs** requires administrator credentials; extracting **TGSs** can be done with a low-privileged account (only the ones assigned to that account).

## Step 2 — Export tickets from LSASS

Requires SYSTEM/admin privileges on the attacked machine:
```
mimikatz # privilege::debug
mimikatz # sekurlsa::tickets /export
```
`/export` writes every ticket belonging to authenticated users on the system to `.kirbi` files in the current directory. Exit Mimikatz and list them:
```
exit
dir
```

![](attachments/Pasted%20image%2020261010184718.png)

The directory contains both **TGS** and **TGT** files for multiple users/services. Because our account had admin privileges, we could dump TGTs too. Locate the **TGT** of the target user and copy its exact `.kirbi` filename (a TGT filename contains `@krbtgt`).

> If you only had a ticket but not its corresponding **session key**, you couldn't use it — both are necessary.

## Step 3 — Inject the ticket with `kerberos::ptt`

Injecting tickets into your own session does **not** require admin privileges. Relaunch Mimikatz, verify `privilege::debug`, then inject the TGT (the filename must be the `@krbtgt` TGT):
```
mimikatz # kerberos::ptt [0;443d9c]-2-0-40e10000-t2_eileen.hall@krbtgt-ZA.TRYHACKME.COM.kirbi
```
Mimikatz returns `OK`, confirming the ticket was processed and injected into your active session memory. From now on, network authentication uses this injected ticket — no password prompts.

> `ptt` = Pass the Ticket. `OK` means the `.kirbi` was processed for injection; it does not by itself prove the ticket will grant access to a particular remote service.

## Step 5 — Lateral movement via `winrs`

Run a remote command against `THMIIS` — no password required, since the injected ticket is used automatically. The `-r` option specifies the **remote computer name**, not a username:
```
winrs.exe -r:THMIIS.za.tryhackme.com cmd
```
The command prompt opens on `THMIIS` immediately. Inside the session, `whoami` confirms the identity is the ticket's user on hostname `THMIIS`.

This is the same outcome as the Pass-the-Hash demo — previously we injected an NTLM hash; here we injected a Kerberos ticket.

## Notes

- **TGT scope:** because the injected ticket is a **TGT** (not a service-specific TGS), the user can authenticate to **any and all** domain services their account is authorized to access.
- This is **not** a TGT for the built-in Administrator account. A forged TGT for the default Domain Administrator is a **Golden Ticket** (persistent domain-wide access). A Tier-1 admin like Toby Beck is not the default domain administrator.
- **Overpass-the-Hash (Pass-the-Key)** follows the same core principles and can be practiced from the lab's task instructions.
