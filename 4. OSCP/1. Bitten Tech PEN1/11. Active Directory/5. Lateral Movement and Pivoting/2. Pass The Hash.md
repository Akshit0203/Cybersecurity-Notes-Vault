What is Pass the Hash?LSASS (Local Security Authority Subsystem Service) is a critical Windows process responsible for enforcing local security policies and handling important authentication-related operations.

Its executable is:

```
C:\Windows\System32\lsass.exe
```

For cybersecurity and AD labs, LSASS is especially important because it can handle sensitive authentication material.

## 1. What does LSASS do?

LSASS is responsible for several security functions:

- Authentication: Helps validate user logons.
    
- Security policy enforcement: Enforces local security policies.
    
- Access tokens: Works with Windows security components involved in creating security contexts for logged-in users.
    
- Password changes: Handles password-change operations.
    
- Authentication secrets: May hold sensitive credentials or authentication material in memory, depending on the Windows version and configuration.
    

## 2. How does LSASS fit into Windows login?

1. User enters credentials

Username and password

2. Windows authentication components

LSASS and configured authentication packages

3. Authentication result

Successful authentication can lead to a Windows logon session and security token

In a domain environment, authentication may involve a Domain Controller through Kerberos or NTLM. LSASS participates in the local authentication process; it does not independently replace the Domain Controller.

### **[Section 1: Introduction to Pass-the-Hash & NTLM Challenge-Response Design]**

Hello friends, in this video we will discuss the **Pass-the-Hash** technique. This is a very important and popular lateral movement technique used to gain access to other network systems. While we have touched upon this before, reviewing it is helpful because the underlying concept is straightforward. In Windows environments, whenever authentication takes place—such as accessing a service or connecting to a network share—you must first authenticate. Microsoft implemented this using a challenge-response mechanism. As seen in NTLM, a challenge-response protocol is used where the client never transmits its cleartext password across the wire to the server; credentials are always sent in a hashed format. The flaw in this design is that if you obtain the password hash of another user without authorization, you can pass that hash directly to authenticate without needing their cleartext password.

---

### **[Section 2: The Core Concept of Pass-the-Hash vs. Password Cracking]**

When you capture or extract a password hash normally, discovering the plaintext password requires cracking it offline. If the password is long and complex—such as 20 to 30 characters with mixed case and symbols—cracking it may prove impossible. Pass-the-Hash eliminates that barrier entirely. If you have the hash, you have a guaranteed way to authenticate and take full advantage of that account. Instead of supplying the plaintext password, you pass the hash for the target user and authenticate directly under their security context.

As discussed earlier, **LSASS** (Local Security Authority Subsystem Service) is a memory space that enforces group policies and security policies. LSASS memory holds the active credentials of currently logged-in users. When an attacker obtains a valid hash, they load that hash into LSASS memory, allowing the operating system to authenticate them directly.

---

### **[Section 3: Gathering Hashes, Access Targets, and Operational Advantages]**

The most common targets for this technique are Windows systems. Targets can include network file shares (such as `C$` or `D$` administrative shares) and network printers. However, our primary offensive objective is obtaining an interactive command prompt, reverse shell, or bind shell.

To execute Pass-the-Hash, you must first obtain a hash. There are multiple ways to extract hashes:

- Dumping the local **SAM** database if you hold local administrator rights.
- Dumping the **`ntds.dit`** database if you hold Domain Admin privileges.
- Capturing hashes across the network via sniffing or poisoning techniques.

Once elevated privileges are achieved, dumping hashes is very straightforward.

**Key Operational Advantages**:

- **Fast and Efficient**: It is not time-consuming because there is no need to crack hashes offline.
- **No Account Lockouts**: Because you are not guessing passwords through repeated login attempts, account lockout thresholds are never triggered.
- **Guaranteed Access**: The valid hash is submitted once and accepted directly by the server.

---

### **[Section 4: Technical Prerequisites: SMB, NTLM, and Administrative Rights]**

Today, executing Pass-the-Hash generally requires an administrative account. Following security updates introduced around 2014, Windows restricts Pass-the-Hash execution from standard, non-administrative user accounts.

The primary technical requirements include:

1. **NTLM Authentication**: The technique does not operate over Kerberos because it does not use Kerberos hashing; NTLM authentication must be enabled on the target.
2. **SMB Protocol Enabled**: The attack relies on requesting an SMB share. The client initiates a request to the SMB share, prompting the server to issue a challenge, to which the client returns the computed response.
3. **Local Administrator Privileges**: The attacker must hold local administrative access, as non-admin hashes are largely ineffective on modern patched systems.

Once authenticated through the SMB share, code or hashes can be injected into memory, allowing an interactive shell to be established.

---

### **[Section 5: LSASS Architecture & Simulating Single Sign-On]**

The **Local Security Authority Subsystem Service (LSASS)** maintains user sessions, validates authentications, and facilitates **Single Sign-On (SSO)** so users do not have to re-enter credentials repeatedly. LSASS stores valuable authentication data, including plaintext passwords, encrypted credentials, LM hashes, NT hashes, and Kerberos tickets. It runs under the high-privilege **`NT AUTHORITY\SYSTEM`** account, meaning an attacker with `SYSTEM` access can extract credentials from LSASS memory without restriction.

Conceptually, the attacker's system simulates LSASS memory containing the compromised hash. Whether operating from a Windows system or using dedicated Linux toolsets, the attacker simulates Single Sign-On locally. Once the hash is injected into memory, native Windows APIs can be used to authenticate to the remote target, replicating the standard authentication process that occurs between two Windows workstations.

---

### **[Section 6: Mitigations, Credential Guard, and Architectural Limitations]**

True mitigations for Pass-the-Hash are difficult to implement because the underlying challenge-response behavior exists by design in the operating system. Redesigning the entire authentication architecture would require years of engineering and disrupt complex enterprise workflows.

Defensive controls include:

- **Credential Guard**: On modern Windows enterprise systems, Credential Guard uses virtualization-based security to isolate LSASS memory into a protected container that standard processes cannot access.
- **Patching Non-Admin Vectors**: Microsoft has patched non-administrative Pass-the-Hash vectors, limiting exploitation to administrative accounts.

However, if an attacker achieves full `SYSTEM` access on a machine, distinguishing between legitimate administrative processes and attacker manipulation remains a fundamental challenge. Because challenge-response authentication is a foundational component of Windows networks, the technique cannot be patched entirely.
