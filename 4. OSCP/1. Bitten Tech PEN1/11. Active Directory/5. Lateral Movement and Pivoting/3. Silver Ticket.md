### **[Section 1: Introduction to Pass-the-Ticket & Silver Tickets]**

Hello friends, in this video we will discuss another lateral movement technique named **Pass-the-Ticket**. This is similar to Pass-the-Hash, but as the name suggests, here we need to pass a ticket. Now, the specific name that comes up here is the **Silver Ticket**. You might have heard this popular term many times. In Pass-the-Ticket, two concepts can arise: Golden Tickets and Silver Tickets. However, in lateral movement, we will talk specifically about Silver Tickets, as Golden Tickets are useful for persistence. As shown earlier, when performing Kerberos authentication, you receive a TGT. After that, you must specify a Service Principal Name (SPN) to authenticate alongside the TGT. Following that, you receive a service ticket. This is referred to as a TGS or `TGS-REP`. If you could create a valid TGS yourself where you could modify anything, consider how it works: normally, you cannot decrypt a TGS reply and must crack it offline because it is encrypted with the service account's hash.

---

### **[Section 2: Forging Service Tickets (TGS) & Arbitrary User Context]**

Is it possible to forge a TGS yourself? It is possible because by meeting a few simple requirements and gathering certain details, you can construct it yourself. The difference between forging it yourself versus receiving it legitimately is that in a legitimate ticket, your specific User ID and IP address are explicitly stated. When the target service authenticates you, it knows exactly which user is requesting access. However, when creating it yourself, you can forge it on behalf of any user—meaning you can alter the User ID. Consequently, you can gain access to any service on behalf of any arbitrary user with any privilege level. There is a clear distinction: if I access that service as an administrator, I receive elevated privileges, whereas a standard user receives limited permissions. This attack operates by forging a valid TGS service ticket on behalf of whichever user you choose, giving you full control over selecting the user identity and specifying the desired permissions.

---

### **[Section 3: Target Gathering & Silver Ticket Prerequisites]**

You can define the exact permissions, and our obvious target is the Administrator. This technique also works across multiple servers if that SPN is registered across multiple servers. The SPN is critical here, as you must supply the SPN when generating a Silver Ticket. The requirements are straightforward: to identify the target domain where this ticket operates, you first need the Domain Security Identifier (SID). This is easily obtained during the enumeration phase. Next, you need the target username, which is also discovered during enumeration. If you have initial access, all of this can be gathered. The domain name is simple to obtain, and the service name (SPN) is also uncovered via enumeration. The only remaining requirement is the password hash of the service account. This hash is acquired post-exploitation once you achieve local administrator rights, whether by dumping the SAM database or cracking it.

---

### **[Section 4: Privilege Escalation via RID 500 & High-Value Groups]**

Once you have these components, you can easily forge a Silver Ticket yourself. What is the primary advantage of doing this? If you obtain the password hash of a service account, that service account is not necessarily a local administrator or a member of an administrative group. If you only have access to a non-administrative service account, you cannot perform lateral movement via standard Pass-the-Hash, because Pass-the-Hash strictly requires administrative accounts. Therefore, you cannot move laterally using a standard service account hash normally. Instead, you can forge a Silver Ticket. When forging the ticket, you specify the user as Administrator. The Relative ID (RID) for the built-in Administrator account is 500. In whichever tool you use, you specify that the user is Administrator with RID 500. This assigns your forged ticket group memberships in high-value administrative groups.

---

### **[Section 5: Exploiting Service Trust & Gaining Remote Administrative Access]**

Your membership is applied to these high-value groups. When you pass this ticket to the target service, it trusts the ticket blindly because the service itself does not independently verify group permissions. It relies entirely on ticket validation, leaving verification to the KDC or Domain Controller. We exploit this architectural design to forge a ticket on behalf of an administrator identity that we do not actually hold, granting us elevated permissions on that service that we normally could not obtain. If that service is running on another remote system with an active SPN, we obtain administrative privileges on that target service. That service could be a network share, a file server, or a web server. With administrative privileges granted, we can perform administrative interactions or spawn a shell on the target system. To enable lateral movement, we forge and escalate our group permissions inside a forged service ticket.

# Silver Ticket Attack — Explained Simply

A Silver Ticket Attack is an Active Directory (AD) attack in which an attacker forges a Kerberos service ticket to access a specific service on a machine without contacting the Domain Controller (DC) to obtain that ticket.

Think of it as creating a fake entry ticket for one particular room inside a building.

## 1. Understand it with an example


![](attachments/Pasted%20image%2020261009125422.png)

Imagine a company has:

- Domain Controller (DC): The security office that manages authentication.
    
- File Server: A room containing confidential files.
    
- Attacker: Someone who has stolen a service account's password hash.
    

Here's how the attack works:

Step 1 — Steal a service account hash

The attacker obtains the NTLM hash of an account associated with a service, such as a file server's CIFS service.

Step 2 — Forge a service ticket

The attacker uses that hash to create a fake Kerberos service ticket, often called a Silver Ticket.

Step 3 — Present the ticket to the service

The attacker presents the forged ticket directly to the target service, such as the file server, without requesting that ticket from the DC.

Step 4 — Potential unauthorized access

If the service accepts the ticket and the forged identity has suitable permissions, the attacker may access protected resources.

## 2. Why is it called a Silver Ticket?

Kerberos uses different types of tickets.

|Ticket|Purpose|
|---|---|
|TGT (Ticket-Granting Ticket)|Used to request tickets for services|
|TGS (Service Ticket)|Used to access a particular service|

A Silver Ticket is a forged TGS service ticket.

The key idea is that the attacker forges the ticket for a particular service using the secret key associated with that service account or computer account.

## 3. Silver Ticket vs. Golden Ticket

This is especially important for CEH and Active Directory labs.

|Feature|Silver Ticket|Golden Ticket|
|---|---|---|
|Forged ticket|TGS|TGT|
|Secret typically needed|Target service account's key/hash|`krbtgt` account's key/hash|
|Scope|Typically a specific service|Can be used to request tickets for many domain services|
|Must contact DC to obtain the forged ticket?|No|No|
|Main concern|Unauthorized access to a target service|Potentially broad domain-wide access|

Easy memory trick:

- Silver = Service ticket.
    
- Golden = TGT ticket.
    

## 4. Why can it be difficult to detect?

A forged Silver Ticket can be presented directly to a service, so the Domain Controller may not see the normal ticket-request exchange for that ticket.

However, it is not invisible. The target server can generate security events, and defenders can look for suspicious logons, unusual group memberships, inconsistent ticket details, and abnormal service-account activity.

## 5. How to defend against it

- Use long, random passwords for service accounts and managed service accounts where possible.
    
- Rotate compromised service-account credentials and computer-account secrets.
    
- Apply least privilege to service accounts.
    
- Monitor Windows security logs on the target servers, especially suspicious logons and service access.
    
- Investigate unusual privileged group memberships or ticket behavior.
    

The one-line takeaway: A Silver Ticket attack is when an attacker uses a compromised service-account secret to forge a Kerberos ticket and attempt to access a specific service without obtaining that ticket from the Domain Controller.
