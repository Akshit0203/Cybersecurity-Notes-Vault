
OVERPASS THE HASH
What is Overpass the Hash?
▸ Combination of Pass the Hash and Pass the Ticket
▸ Allows the creation of Kerberos tickets from NTLM hash or AES keys
▸ Allows access to the resource service that requires Kerberos
authentication.
▸ Useful when NTLM auth is disabled, only Kerberos is allowed.



Overpass-the-Hash (Pass-the-Key) — Explained Simply
Overpass-the-Hash is an Active Directory attack where an attacker uses a stolen password hash to obtain a Kerberos Ticket-Granting Ticket (TGT), instead of knowing the user's plaintext password.
Think of it as using a stolen key to get a legitimate entry pass.
1. Understand it with an example
Imagine a company uses Active Directory (AD) for authentication.









Step 1 — Steal a password hash
An attacker obtains a user's NTLM hash from a compromised Windows machine.












Step 2 — Use the hash to request a Kerberos TGT
The attacker uses the hash as cryptographic key material to authenticate through Kerberos, without needing the plaintext password.












Step 3 — Obtain a TGT
If the authentication succeeds, the Domain Controller issues a Ticket-Granting Ticket (TGT).












Step 4 — Request service tickets
The attacker can use the TGT to request Kerberos service tickets for resources the compromised account is authorized to access.



2. Why is it called Overpass-the-Hash?
The attacker takes a hash-based credential and uses it to move into Kerberos authentication, obtaining a TGT.
The flow is:
Stolen NTLM hash

Kerberos authentication

TGT obtained

Request service tickets


3. Overpass-the-Hash vs. Pass-the-Hash
This distinction is important for CEH and AD labs.
Feature	Pass-the-Hash (PtH)	Overpass-the-Hash
Credential used	NTLM hash	NTLM hash / compatible key material
Authentication	Typically NTLM	Kerberos
Main goal	Authenticate using the hash	Obtain a Kerberos TGT using the hash
TGT obtained?	Not inherently	Yes, if successful
Memory trick:
- Pass-the-Hash: Use the hash to authenticate.
- Overpass-the-Hash: Use the hash to get a Kerberos ticket.
4. How is it different from a Silver Ticket?
Attack	What the attacker creates or obtains
Overpass-the-Hash	Obtains a TGT through Kerberos authentication
Silver Ticket	Forges a service ticket (TGS) using a service account's secret
Golden Ticket	Forges a TGT using the krbtgt account's secret
The critical difference is that Overpass-the-Hash normally involves authenticating to the Domain Controller to obtain a TGT, whereas a forged Silver Ticket can be presented directly to its target service without requesting that ticket from the DC.


### **[Section 1: Introduction to Overpass-the-Hash & NTLM Restrictions]**

Hello friends, in this video we will discuss **Overpass-the-Hash**. This is a modification of the previous attack techniques, acting as a **combination of Pass-the-Hash and Pass-the-Ticket**.

Consider a scenario where **NTLM authentication is disabled**, only Kerberos is enabled across the network systems, or certain programs simply refuse to accept NTLM hashes for authentication. For instance, looking at **Sysinternals PsExec** from Microsoft: if you want to execute a command remotely using PsExec, it will not accept raw hashes. Instead, it requires a ticket that must be present in your memory. The system from which you run PsExec must hold a **Ticket Granting Ticket (TGT)** or Kerberos ticket in memory for authentication before you can execute commands on another target system. There are many other programs that strictly demand Kerberos tickets for authentication rather than accepting password hashes. What do you do in that scenario?

### **[Section 2: Converting NTLM Hashes into Kerberos Tickets]**

You may hold an NTLM hash, but you cannot authenticate or move laterally with it directly. In that situation, the solution is to **convert your NTLM hash into a Kerberos ticket**.

This conversion is entirely possible. Tools are available in **Impacket** and **Mimikatz**, and if you want to perform an interactive login, you can also use `net use`. There are multiple methods available: if you need to authenticate to a network share, query a share, request access, or connect to it, you can use `net use`. In that case, an interactive login takes place and Kerberos tickets can be generated, or you can construct them manually using the Impacket toolkit.

The core challenge was that we could not pass NTLM hashes laterally and were forced to use tickets instead. Therefore, **we generate the Kerberos ticket directly from the hash itself**. For our target user—whichever user that hash belongs to—we generate a **TGT (Ticket Granting Ticket)**.

We then pass that ticket—which is why this technique is called **Overpass-the-Hash**—and move laterally through it.
