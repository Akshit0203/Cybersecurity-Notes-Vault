`mimikatz # privilege::debug` tells Mimikatz to enable the Windows debug privilege (`SeDebugPrivilege`) for its current process, if the process token has that privilege available.

### 1. What does each part mean?

- `mimikatz #` — the Mimikatz interactive prompt.
    
- `privilege::` — the module for managing privileges.
    
- `debug` — requests the debug privilege.
    

### 2. What is `SeDebugPrivilege`?

Windows normally restricts which processes can inspect or interact with other processes. The debug privilege can allow a process to access processes it would otherwise be restricted from accessing, subject to Windows protections and other security controls.

For example, it can be relevant when inspecting LSASS (Local Security Authority Subsystem Service), which handles important Windows authentication functions.

### 3. Why is it used in Mimikatz?

Some Mimikatz operations need elevated access to inspect protected processes or access sensitive authentication information. Enabling debug privilege may be a prerequisite for those operations.

The command does not automatically:

- Make you an administrator.
    
- Give you SYSTEM privileges.
    
- Dump credentials.
    
- Guarantee access to LSASS.
    

The process must already have the necessary rights for the privilege to be enabled.

### 4. What does success look like?

Mimikatz commonly reports:

```
Privilege '20' OK
```

This indicates that enabling the requested privilege succeeded. If it reports an error, the process may lack the required rights, or the privilege may be unavailable in its token.

Memory trick: `privilege::debug` = request permission to debug other processes; it doesn't automatically grant higher privileges.
