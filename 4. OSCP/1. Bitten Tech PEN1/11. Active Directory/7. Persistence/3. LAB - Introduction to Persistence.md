# LAB — Introduction to Persisting Active Directory

> [!abstract] Overview
> This room (**Persisting Active Directory**) follows the exploitation phase. It assumes you already achieved **Domain Admin** / **`NT AUTHORITY\SYSTEM`** on the DC. The goal now is to plant reliable footholds so you can quickly regain that same high privilege later — this is the **post-exploitation (post-compromise)** phase, mapped to **"maintaining presence"** in the attack lifecycle.

## The Post-Exploitation Dilemma

Reaching Domain Admin / DC SYSTEM is the end of the attack *chain*, but not the engagement. Consider needing access again tomorrow:

- If you only held a single interactive reverse shell and the machine **reboots**, the connection dies with no easy reconnect.
- Many previous techniques rely on **volatile actions** — e.g. resetting a user's password to run PsExec, Pass-the-Hash, or Pass-the-Ticket.

## Why Exploitation Vectors Are Volatile

- If a compromised user's password is **changed/reset**, that access is severed.
- If the **`krbtgt`** password is reset **twice**, forged Golden/Silver Tickets stop working.
- Blue teams eventually detect intrusions. Even without detection, routine events happen: users change passwords, systems restart, Group Policies update.

Under any of these, regaining access without persistence means re-running the **entire** attack lifecycle from initial enumeration and breaching.

## Defining Persistence (the Red Team Objective)

**Persistence** = establishing footholds so that whenever you need to regain high privilege, you can do so quickly and easily with just a few commands — granting **maximum access for maximum duration**.

From a red team perspective: maintain deep access for as long as possible while making it hard for the blue team to evict you. Deploy persistence **after each round** of lateral movement / privilege escalation — don't wait for full domain compromise.

## Stealth & Evasion — Blending In

Many persistence mechanisms are hard to detect because they **leverage legitimate functions** domain admins routinely perform for business operations. By using techniques that look entirely genuine and blend into normal administrative activity, you avoid abnormal indicators and minimize detection noise.
