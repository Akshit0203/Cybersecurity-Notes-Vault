# Hash Injection / Pass the Hash

> **Category:** Active Online Attack (Windows)
> **Authentication Protocol:** NTLM

---

## How It Works

1. **Password Storage** — When you log into Windows, your password is **hashed (NTLM)** and stored locally. It is **never kept in cleartext**.
2. **Domain Controller Authentication** — In an Active Directory environment, Windows converts your password to a hash and sends a login request. The DC uses a **challenge-response protocol** to verify the hash against its stored copy.
3. **The Core Flaw** — You **never need the cleartext password** to authenticate. If an attacker possesses the NTLM hash, they are automatically authenticated.

## Attack Flow

```
Compromise Target System → Dump NTLM Hashes (e.g., Mimikatz) → Inject Hash → Authenticate to Domain Controller
```

1. The attacker first **gains access** to a system on the domain.
2. Once access is achieved, tools like **Mimikatz** are used to **dump stored NTLM hashes** from memory.
3. The attacker **injects/passes the hash** to the Domain Controller.
4. If the compromised account is a **Domain Admin**, the attacker achieves **privilege escalation** with the highest privileges on the domain.

---

## Key Points

- This is **not a software bug** — it is the **fundamental design and behavior** of NTLM authentication (similar to how ARP works by design).
- As long as NTLM is active, this mechanism exists.
- **Primary mitigation**: Prevent the attacker from compromising the initial system in the first place.
