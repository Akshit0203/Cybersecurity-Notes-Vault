# Introduction to Windows Services

> [!NOTE]
> Foundation knowledge required before exploiting any of the four service abuse vectors.

---

## What Are Windows Services?

- **Long-running executable applications** that run in their own Windows sessions
- Run in the background (similar to Unix daemons)
- Managed by the **Service Control Manager (SCM)**
- Can be configured to start automatically at boot and run as long as Windows is running
- **LocalSystem** is frequently used to operate services — this is what we exploit

---

## Common Use Cases

- Web servers, SSH, FTP — services that must start automatically without interactive login
- Windows Update — applies patches silently in the background
- Network management, log file generation/cleanup, disk maintenance
- Any task that needs to run continuously without a logged-in user session

---

## Service Configuration Parameters

Every service has specific configuration parameters:

| Parameter       | Description                                                       |
| --------------- | ----------------------------------------------------------------- |
| **Service Name**   | Internal identifier used by SCM                                  |
| **Display Name**   | Human-readable name shown in services.msc                        |
| **Binary Path**    | Full path to the executable (.exe)                               |
| **Service Type**   | Own process (`WIN32_OWN_PROCESS`) or shared (`WIN32_SHARE_PROCESS`) |
| **Start Type**     | `AUTO_START`, `DEMAND_START` (manual), or event-triggered        |
| **Service Account**| The user context the service runs under                          |

---

## Service Control Manager (SCM)

The **SCM** is the core Windows system utility that governs the entire service lifecycle:

- **Registering** services with required parameters and startup rules
- **Starting**, pausing, resuming, and **stopping** service processes
- **Monitoring** status, capturing errors, and logging events

A service must first be **registered** with SCM and **installed** onto the OS before it can run.

---

## Why LocalSystem Matters for PrivEsc

- Most system services require elevated permissions for low-level tasks:
  - Binding to privileged ports (80, 443, 22)
  - Transmitting custom network packets
  - Updating system files / managing user accounts
- Many services therefore run under the **LocalSystem** account
- **LocalSystem** is a built-in Windows security principal (system SID, not a standard user account) with **full, unrestricted system permissions**
- Targeting services running as LocalSystem → escalate to **`NT AUTHORITY\SYSTEM`**

---

## Four Core Service Abuse Vectors

| # | Vector                        | What You Exploit                                    |
|---|-------------------------------|-----------------------------------------------------|
| 1 | **Insecure Service Executables** | Weak file permissions on the service binary (.exe)  |
| 2 | **Insecure Service Permissions** | `SERVICE_CHANGE_CONFIG` on the service object (DACL) |
| 3 | **Unquoted Service Paths**       | Path resolution search order when spaces + no quotes |
| 4 | **DLL Hijacking**                | DLL search order — placing a malicious DLL in a writable path |
