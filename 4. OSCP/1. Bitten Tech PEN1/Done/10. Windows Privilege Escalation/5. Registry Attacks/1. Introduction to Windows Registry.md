# Introduction to Windows Registry

> [!summary] Quick Recall
> The Windows Registry is a **hierarchical database** that stores low-level settings and configuration data for the OS, hardware, software, and users. It is the Windows equivalent of Linux's `/etc` directory. Registry misconfigurations are a major source of **privilege escalation** vectors.

---

## What is the Windows Registry?

- A **centralized configuration database** built into Windows
- Stores settings for: software programs, hardware devices, user preferences, OS configuration, services
- Data is stored in **key-value pairs**
- Whenever the OS kernel or background applications execute, they fetch configuration parameters directly from the Registry

![](attachments/Pasted%20image%2020260925160351.png)

### Registry vs Linux `/etc`

| Linux            | Windows          |
| ---------------- | ---------------- |
| `/etc` directory | Windows Registry |
| Text-based config files | Structured binary hive files |
| Per-application config | Centralized + per-application |

### Why a Registry Instead of Normal Files?

| Reason               | Explanation                                                                 |
| -------------------- | --------------------------------------------------------------------------- |
| Centralized management | System-wide and app settings managed through a common system               |
| Structured data      | Supports named keys/values with typed data (not just plain text)            |
| Permissions (ACLs)   | Registry keys have security permissions controlling who can read/modify     |
| Efficient access     | Binary format allows fast lookup without parsing entire text files          |

> [!important]
> The Registry does **not** replace all configuration files. Applications still use `.ini`, `.xml`, `.json`, SQLite, etc. The developer chooses the storage mechanism.

## Registry Structure

### Hierarchy

```
Registry
└── Hive (e.g., HKEY_CURRENT_USER)
    └── Key (e.g., Software)
        └── Subkey (e.g., ExampleApp)
            ├── Value Name: Theme  →  Value Data: Dark
            └── Value Name: FontSize  →  Value Data: 14
```

| Registry Term | Simple Meaning               |
| ------------- | ---------------------------- |
| **Hive**      | Major logical section (top-level branch) |
| **Key**       | Container / folder organizing related settings |
| **Subkey**    | Nested key within a key      |
| **Value Name**| Name of a specific setting   |
| **Value Data**| The actual stored information |

### Example

```
Key: HKEY_CURRENT_USER\Software\ExampleApp

Theme       REG_SZ       Dark
Enabled     REG_DWORD    1
InstallPath REG_SZ       C:\ExampleApp
```

## Registry Hives

A **hive** is a logical group of keys and subkeys, prefixed with `HKEY_` (Handle for a Registry Key).

| Hive | Abbreviation | Purpose |
| ---- | ------------ | ------- |
| `HKEY_LOCAL_MACHINE` | `HKLM` | **System-wide** settings for all users — contains **SAM**, SECURITY, SOFTWARE, SYSTEM |
| `HKEY_CURRENT_USER` | `HKCU` | Settings specific to the **currently logged-in user** |
| `HKEY_CLASSES_ROOT` | `HKCR` | File associations and COM class registrations |
| `HKEY_CURRENT_CONFIG` | `HKCC` | Hardware profile for the active session |
| `HKEY_USERS` | `HKU` | All user profiles loaded on the system |

> [!note]
> Upon login, a new `HKEY_CURRENT_USER` hive is dynamically created for that user session.

### Critical Hives in `HKLM`

- **SAM** — Stores local password hashes (can be cracked offline if extracted)
- **SECURITY** — Security policies
- **SOFTWARE** — Installed software configuration
- **SYSTEM** — System hardware and service configuration

## Registry Data Types

| Registry Type    | Meaning                          | Example               |
| ---------------- | -------------------------------- | --------------------- |
| `REG_SZ`         | Text string                      | `Dark`                |
| `REG_DWORD`      | 32-bit integer                   | `1`                   |
| `REG_QWORD`      | 64-bit integer                   | `100000`              |
| `REG_BINARY`     | Binary data                      | Raw bytes             |
| `REG_MULTI_SZ`   | Multiple strings                 | Several text entries  |
| `REG_EXPAND_SZ`  | Text with environment variables  | `%SystemRoot%\System32` |

> The type tells Windows how to interpret the data. `REG_DWORD = 1` is stored as an integer, not the text character `"1"`.

---

## How Registry Data is Physically Stored

```
Registry Editor (GUI)  →  Windows Registry Manager  →  Registry Hive Files (on disk)
```

- Hive files use a **structured binary format** (not human-readable in Notepad)
- They contain: keys, relationships, value names, value types, value data, metadata
- Windows interprets these structures and presents them through `regedit` or CLI commands

---

## What the Registry Stores (Security-Relevant)

| Category | Examples |
| -------- | -------- |
| Service execution | Binary paths (`ImagePath`), startup type, account context |
| Saved passwords | PuTTY session keys, third-party app credentials |
| Installation permissions | Which users can install software (`AlwaysInstallElevated`) |
| Security controls | Windows Defender, Firewall, Credential Guard status (binary `0`/`1` flags) |
| Autorun programs | Programs that start at boot/login |

### What the Registry Does NOT Directly Contain

- Granular user-specific permission rights (stored separately in ACLs)
- Plaintext credentials (rare — though SAM hashes and PuTTY keys can be found)
- System log file contents (only their path references)

## Viewing the Registry

Press `Win + R` → type `regedit` → Enter

```
HKEY_CURRENT_USER
    └── Software
        └── MyApp
            └── Theme = Dark
```

> For the current Windows user, the application `MyApp` has a setting called `Theme` with value `Dark`.

## Real-Life Registry Examples

| Daily Activity          | Registry Connection                          |
| ----------------------- | -------------------------------------------- |
| Open a `.txt` file      | File association → `HKCR\.txt`               |
| Click a website link    | Default browser → default app configuration  |
| Connect a USB device    | Device/driver config under `HKLM\SYSTEM`     |
| Install software        | Uninstall info under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` |
| Sign in to Windows      | User profiles under `HKLM\...\ProfileList`   |
| Run a service           | Service config under `HKLM\SYSTEM\CurrentControlSet\Services` |
| Change Dark Mode        | User preferences in `HKCU` keys              |

### Example: File Associations

```
HKEY_CLASSES_ROOT
    └── .txt
          └── (Default) = txtfile
```

Windows checks this to determine which application opens `.txt` files.

### Example: Service Configuration

```
HKEY_LOCAL_MACHINE
    └── SYSTEM
        └── CurrentControlSet
            └── Services
                └── ExampleService
                    ├── ImagePath = C:\Program Files\Example\service.exe
                    └── Start = 2
```

### Example: Application Settings (Chrome)

| Setting Type | Storage | Why |
| ------------ | ------- | --- |
| Bookmarks, history, extensions | Chrome's own files (`AppData`) | Only Chrome needs them |
| Default browser, file associations | Registry | Windows-wide setting — other apps need to know |
| Uninstall information | Registry (`Uninstall` key) | Windows needs this for Add/Remove Programs |

## Privilege Escalation Strategy via Registry

> [!tip] Attack Methodology
> Use the Registry as a **map** to locate target binary paths, then perform **file-system permission checks** on those target locations.

1. **Inspect Registry keys** for service paths, autorun entries, installer settings
2. **Check permissions** on those Registry keys (`accesschk`, `Get-Acl`)
3. **Check permissions** on the referenced executable files (`icacls`)
4. If Registry key permissions are **misconfigured** → modify key values (e.g., change `ImagePath`)
5. If executable permissions are misconfigured → replace the binary with a payload

### Key Registry Locations for PrivEsc

| Attack Vector | Registry Path |
| ------------- | ------------- |
| Autorun programs | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` |
| Autorun (once) | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce` |
| Service executables | `HKLM\SYSTEM\CurrentControlSet\Services\<ServiceName>` |
| AlwaysInstallElevated | `HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer` |
| AlwaysInstallElevated | `HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer` |

## Key Takeaways

> **Windows Registry** = A shared configuration database for Windows
> **Application files** = Settings managed by individual applications
> They complement each other — the Registry doesn't replace app config files.

> [!quote] Interview Answer
> "The Windows Registry is a centralized configuration database used by Windows and applications to store and manage settings. Applications use their own files for app-specific data, while the Registry is used for settings that need integration with Windows, system components, or other applications."
