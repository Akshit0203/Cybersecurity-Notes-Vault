# Introduction to Command Line

> A **command shell** is a text-based application for viewing, handling, and manipulating files on your computer. It acts as the **user-to-kernel interface**, allowing you to use operating system services without programming the hardware directly.

**Other names:** CMD, CLI, prompt, console, terminal.

## Architecture: Hardware → Kernel → Shell → Applications

```
┌──────────────────────────┐
│   User Applications      │  (email, browser, MS Word, etc.)
├──────────────────────────┤
│        Shell             │  (command interpreter)
├──────────────────────────┤
│       Kernel             │  (core of the OS — manages hardware)
├──────────────────────────┤
│      Hardware            │  (CPU, RAM, disk, NIC, USB, etc.)
└──────────────────────────┘
```

### Hardware
- Everything physical: CPU, RAM, disk drive, printer, NIC, USB ports, monitor, etc.

### Kernel
- The **central part of the OS** that directly manages hardware
- Understands machine-level instructions and system calls
- Operates in **privileged mode** — decides which hardware runs what

### Shell
- A **software layer** (system software) that sits between the user and the kernel
- Translates human-readable commands into **system calls** the kernel can understand
- Handles the transition from **user mode → privileged mode**
- The "black screen" you see is just a **GUI/interface for the shell** — the shell itself is a command interpreter with no visual component

### Applications
- Programs that run on top of the shell (email, text editors, games, etc.)
- Can send commands to the shell, or you can send commands directly

---

## What Can You Do with the Shell?

- Copy, move, rename files
- Check network IP configuration
- Change system configuration and passwords
- Run any installed application
- Execute programming languages directly (Python, PHP, Perl, Bash)
- Run scripts and security tools

---

## Key Concepts

| Concept | Explanation |
| ------- | ----------- |
| **Command interpreter** | The shell interprets typed commands into system calls |
| **Privileged mode** | System calls run in privileged mode; the shell manages this transition |
| **Standard input** | Shell reads from input devices (keyboard) or from files |
| **Shell scripting** | Writing multiple commands in a file for automation |
| **Terminal vs. Shell** | Each user gets a separate terminal, but the shell is shared/common |
| **Shell starts** | When the user logs in or starts the terminal |

## Shell Prompt Identifiers

| Symbol | Meaning |
| ------ | ------- |
| `#`    | Root (admin) user |
| `$`    | Normal user |

> The prompt shows the current user, hostname, and directory — this differs between Linux and Windows.
