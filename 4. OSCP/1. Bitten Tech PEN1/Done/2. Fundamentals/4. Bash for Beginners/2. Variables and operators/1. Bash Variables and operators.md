# Bash Variables and Operators

---

## Variable Types

| Type | Description | Example |
|------|-------------|---------|
| **User-defined** | Created by you in a script | `name="Akshit"` |
| **Environment (system)** | Predefined by the OS/shell | `$PATH`, `$HOME`, `$USER` |

> Bash is **untyped** — no need to declare data types. Values are inferred automatically (like Python).

---

## Naming Conventions

- ✅ Must start with a **letter** or **underscore** (`_`)
- ❌ Cannot start with a **number**
- Variable names are **case-sensitive** (`name` ≠ `NAME`)
- No spaces around `=` in assignments

```bash
# ✅ Valid
name="Akshit"
_count=5
MY_VAR="hello"

# ❌ Invalid
1name="bad"       # starts with number
name = "bad"      # spaces around =
```

## Command Substitution and Newlines

Command substitution removes **trailing newlines** from output. Quoting behaviour affects how embedded newlines are displayed:

### With Double Quotes — Newlines Preserved

```bash
#!/bin/bash

name=$(seq 1 5)
echo $?

echo "Hello $name"
```

```
0
Hello 1
2
3
4
5
```

### Without Quotes — Newlines Collapsed to Spaces

```bash
#!/bin/bash

name=$(seq 1 5)
echo $?

echo Hello $name
```

```
0
Hello 1 2 3 4 5
```

> **Key insight:** Double quotes preserve internal newlines; unquoted variables undergo **word splitting**, collapsing newlines into spaces.

### Practical Use — Creating Directories from Command Output

```bash
#!/bin/bash

name=$(seq 1 5)
mkdir $name

ls
```

```
└─$ ./new.sh
1  2  3  4  5  new.sh
```

Without quotes, `$name` expands to `1 2 3 4 5` (space-separated) → `mkdir` creates five separate directories.

## Environment Variables

### View All Environment Variables

```bash
└─$ printenv
COLORTERM=truecolor
DISPLAY=:0.0
LANG=en_US.UTF-8
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/local/games:/usr/games
USER=kali
HOME=/home/kali
SHELL=/usr/bin/zsh
...
```

> Other commands: `env`, `set` (each shows slightly different scopes).

### Using Environment Variables in Scripts

```bash
#!/bin/bash

echo $PATH
```

```
└─$ ./new.sh
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/local/games:/usr/games
```

### Common Environment Variables

| Variable | Description |
|----------|-------------|
| `$USER` | Current username |
| `$HOME` | Home directory path |
| `$SHELL` | Default shell path |
| `$HOSTNAME` | System hostname |
| `$PATH` | Executable search directories |
| `$BASH_VERSION` | Bash version |
| `$PWD` | Current working directory |

### Example — Combining User & Environment Variables

```bash
#!/bin/bash

NAME="Hello"
SURNAME="World"

echo "My name is $NAME $SURNAME and my username is $USER and my hostname is $HOSTNAME, my home directory is $HOME and my shell is $SHELL and it's version is $BASH_VERSION"
```

```
└─$ ./new.sh
My name is Hello World and my username is kali and my hostname is kali, my home directory is /home/kali and my shell is /usr/bin/zsh and it's version is 5.3.9(1)-release
```

## Arithmetic Operations

### ❌ `echo` Doesn't Evaluate Math

```bash
#!/bin/bash

number=12345

echo $number + 10
```

```
12345 + 10
```

It prints the literal string — no calculation performed.

### ✅ Method 1 — Double Parentheses `$(( ))`

```bash
#!/bin/bash

number=12345

result=$(( number+10 ))

echo $result
```

```
12355
```

**Adding two variables:**

```bash
#!/bin/bash

number1=12345
number2=67890

result=$((number1+number2))

echo $result
```

```
80235
```

> **Note:** Inside `$(( ))`, you do **not** need the `$` prefix for variables — the `$` is already on the outer `$((`.

> Spaces inside `$(( ))` are optional — `$((number1 + number2))` and `$((number1+number2))` both work.

### ✅ Method 2 — `expr` Command (with Backticks)

```bash
#!/bin/bash

number1=12345
number2=67890

result=`expr $number1 + $number2`

echo $result
```

```
80235
```

> ⚠️ With `expr`, spaces around the operator are **required**: `` `expr $a + $b` `` ✅ vs `` `expr $a+$b` `` ❌

## Command-Line Arguments

### Positional Parameters

| Variable | Meaning |
|----------|---------|
| `$0` | Script name |
| `$1` | First argument |
| `$2` | Second argument |
| `$N` | Nth argument |
| `$#` | Total number of arguments |
| `$*` | All arguments as a single string |

### Example — Accessing `$1` and `$2`

```bash
#!/bin/bash

echo $1
```

```
└─$ ./new.sh 12345 567
12345
```

```bash
#!/bin/bash

echo $2
```

```
└─$ ./new.sh 12345 567
567
```

### Example — Script Name with `$0`

```bash
#!/bin/bash

echo $0
```

```
└─$ ./new.sh 12345 567
./new.sh
```

### Example — Argument Count with `$#`

```bash
#!/bin/bash

echo $#
```

```
└─$ ./new.sh 12345 567
2
```

### Example — All Arguments with `$*`

```bash
#!/bin/bash

echo $*
```

```
└─$ ./new.sh 12345 567 123456
12345 567 123456
```

### Arithmetic with Command-Line Arguments

```bash
#!/bin/bash

result=`expr $1 + $2`

echo $result
```

```
└─$ ./new.sh 10 20
30
```

## String Concatenation

In Bash, there is **no `+` or `.` operator** for concatenation — just place variables/strings next to each other:

```bash
#!/bin/bash

NAME="Hello"
SURNAME="World"

echo $NAME $SURNAME
```

```
└─$ ./new.sh
Hello World
```

### Distinguishing Variables with Curly Braces `${}`

When a variable name runs into adjacent text, use `${}` to clarify the boundary:

```bash
#!/bin/bash

NAME="Hello"

echo ${NAME}ISTRUE
```

```
HelloISTRUE
```

Without braces, `$NAMEISTRUE` would be treated as a single (undefined) variable.
