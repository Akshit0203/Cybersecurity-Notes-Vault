# Nmap — Types of Scans

Different scan types use different TCP flags, giving you varying levels of stealth and information. The primary reason to use alternative scan types is to **avoid logging** on the target and to **remain anonymous** — not primarily for firewall bypass (that is covered separately).

---

## Nmap Scan Techniques Reference

```
SCAN TECHNIQUES:
  -sS/sT/sA/sW/sM: TCP SYN/Connect()/ACK/Window/Maimon scans
  -sU: UDP Scan
  -sN/sF/sX: TCP Null, FIN, and Xmas scans
  --scanflags <flags>: Customize TCP scan flags
  -sI <zombie host[:probeport]>: Idle scan
  -sY/sZ: SCTP INIT/COOKIE-ECHO scans
  -sO: IP protocol scan
  -b <FTP relay host>: FTP bounce scan
```

---

## 1. TCP Full Connect Scan (`-sT`)

Completes the full **3-way handshake** (SYN → SYN/ACK → ACK) on every port.

```bash
nmap 192.168.60.138 -sT
```

- Most **reliable** scan — if the handshake completes, the port is definitely open.
- Most **detectable** — the full connection is logged by the target.

---

## 2. TCP SYN / Half-Open Scan (`-sS`)

Sends a SYN, waits for SYN/ACK, but **never completes** the handshake (sends RST instead of ACK).

```bash
nmap 192.168.60.138 -sS
```

- **Default** Nmap scan (requires root).
- Faster and **less logged** than `-sT` because the connection is never fully established.
- Output is the same as `-sT` for open ports.

---

## 3. TCP ACK Scan (`-sA`)

Sends only an ACK flag. Used to **map firewall rules**, not to find open ports.

```bash
nmap 192.168.60.138 -sA
```

- Ports respond with RST → **unfiltered** (no firewall blocking).
- No response → **filtered** (firewall is dropping packets).
- **Cannot determine** if a port is open or closed — only whether it is filtered.

---

## 4. UDP Scan (`-sU`)

Scans UDP ports instead of TCP.

```bash
nmap 192.168.60.138 -sU
```

| Response | Meaning |
|---|---|
| No response | Port is **open** (or filtered) |
| ICMP "Port Unreachable" | Port is **closed** |

> [!IMPORTANT]
> UDP scans are **slow**. Always remember to scan UDP — many exam candidates forget and miss critical services like DNS (53), SNMP (161), TFTP (69).

---

nmap 192.168.60.138 -sN

---

## 6. TCP FIN Scan (`-sF`)

Sends a packet with only the **FIN flag** set.

```bash
nmap 192.168.60.138 -sF
```

- Same principle as Null scan — open ports give no response → `open|filtered`.

---

## 7. TCP Xmas Scan (`-sX`)

Sets **FIN + PSH + URG** flags simultaneously (the packet "lights up like a Christmas tree").

```bash
nmap 192.168.60.138 -sX
```

- Same output behavior as Null and FIN scans → `open|filtered` on no response.
- Named "Xmas" because multiple flags are lit up.

---

## Why Use Null / FIN / Xmas Scans?

These scans exist primarily to **avoid detection in target logs**:

| Scan Type | Logged by Target? | State Reported |
|---|---|---|
| Full Connect (`-sT`) | ✅ Heavily logged | `open` / `closed` |
| SYN Half-Open (`-sS`) | ⚠️ Less logged | `open` / `closed` |
| Null / FIN / Xmas | ❌ Minimal logging | `open|filtered` / `closed` |

> [!NOTE]
> **Trade-off:** Less logging = less certainty. You lose the ability to distinguish between `open` and `filtered` because the handshake is never completed.

---

## Quick Reference

| Flag | Scan Name | What It Does | Best For |
|---|---|---|---|
| `-sT` | TCP Connect | Full 3-way handshake | Reliable port discovery |
| `-sS` | SYN (Half-Open) | SYN only, no full connection | Default, fast, semi-stealthy |
| `-sA` | ACK | ACK probe only | Mapping firewall rules |
| `-sU` | UDP | UDP port scanning | Finding DNS, SNMP, TFTP |
| `-sN` | Null | No flags set | Stealth / log evasion |
| `-sF` | FIN | FIN flag only | Stealth / log evasion |
| `-sX` | Xmas | FIN + PSH + URG | Stealth / log evasion |
