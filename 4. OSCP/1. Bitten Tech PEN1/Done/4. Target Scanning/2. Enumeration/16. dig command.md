# `dig` Command

## What is `dig`?

**dig** (Domain Information Groper) is a powerful DNS query tool that outputs results in a **standard, systematic DNS format**. It is the **most widely used tool** for DNS enumeration and reconnaissance.

---

## Help / Syntax

```bash
dig -h
```

```
Usage:  dig [@global-server] [domain] [q-type] [q-class] {q-opt}
            {global-d-opt} host [@local-server] {local-d-opt}
            [ host [@local-server] {local-d-opt} [...]]
Where:  domain    is in the Domain Name System
        q-class  is one of (in,hs,ch,...) [default: in]
        q-type   is one of (a,any,mx,ns,soa,hinfo,axfr,txt,...) [default:a]
                 (Use ixfr=version for type ixfr)
        q-opt    is one of:
                 -4                  (use IPv4 query transport only)
                 -6                  (use IPv6 query transport only)
                 -b address[#port]   (bind to source address/port)
                 -c class            (specify query class)
                 -f filename         (batch mode)
                 -k keyfile          (specify tsig key file)
                 -p port             (specify port number)
                 -q name             (specify query name)
                 -t type             (specify query type)
                 -u                  (display times in usec instead of msec)
                 -x dot-notation     (shortcut for reverse lookups)
                 -y [hmac:]name:key  (specify named base64 tsig key)
```

## Specific Record Types

### NS Records (Name Servers)

```bash
dig google.com -t ns
```

```
;; ANSWER SECTION:
google.com.             5       IN      NS      ns3.google.com.
google.com.             5       IN      NS      ns2.google.com.
google.com.             5       IN      NS      ns4.google.com.
google.com.             5       IN      NS      ns1.google.com.

;; ADDITIONAL SECTION:
ns3.google.com.         5       IN      A       216.239.36.10
ns2.google.com.         5       IN      A       216.239.34.10
ns4.google.com.         5       IN      A       216.239.38.10
ns1.google.com.         5       IN      A       216.239.32.10
```

### MX Records (Mail Exchangers)

```bash
dig google.com -t mx
```

```
;; ANSWER SECTION:
google.com.             5       IN      MX      10 smtp.google.com.

;; ADDITIONAL SECTION:
smtp.google.com.        5       IN      A       192.178.158.26
smtp.google.com.        5       IN      A       192.178.158.27
```

The number (10) is the **priority** — lower = higher priority.

### AAAA Records (IPv6)

```bash
dig google.com -t aaaa
```

```
;; ANSWER SECTION:
google.com.             5       IN      AAAA    2404:6800:4013:813::65
google.com.             5       IN      AAAA    2404:6800:4013:813::8a
google.com.             5       IN      AAAA    2404:6800:4013:813::8b
google.com.             5       IN      AAAA    2404:6800:4013:813::71
```

## The `+short` Flag

By default, `dig` outputs verbose information (headers, flags, additional sections). Use **`+short`** to get **only the answer**:

```bash
dig google.com -t ns +short
```

```
ns3.google.com.
ns2.google.com.
ns4.google.com.
ns1.google.com.
```

```bash
dig google.com -t mx +short
```

```
10 smtp.google.com.
```

---

## Shorthand Syntax

You can omit `-t` and just specify the record type directly:

```bash
dig google.com ns       # Same as: dig google.com -t ns
dig google.com mx       # Same as: dig google.com -t mx
dig google.com a        # Same as: dig google.com -t a
```

## Quick Reference

| Command                             | Purpose                         |
| ----------------------------------- | ------------------------------- |
| `dig <domain>`                      | Default A record query          |
| `dig <domain> -t ns`               | Name server records             |
| `dig <domain> -t mx`               | Mail exchanger records          |
| `dig <domain> -t aaaa`             | IPv6 address records            |
| `dig <domain> -t soa`              | Start of Authority record       |
| `dig <domain> -t txt`              | TXT records                     |
| `dig <domain> -t any`              | All record types                |
| `dig <domain> axfr @<nameserver>`  | **Zone transfer (AXFR)**        |
| `dig <domain> <type> +short`       | Short/clean output only         |
| `dig @<server> <domain>`           | Query a specific DNS server     |

> [!tip] Dig is King
> `dig` is the **primary tool** for DNS enumeration and zone transfers. If you learn one DNS tool well, make it `dig`.
