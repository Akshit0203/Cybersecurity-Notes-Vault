# LAB — SSH Local Port Forwarding

> **Lab Environment:** TryHackMe Wreath
> **Goal:** Access an internal web server (`10.200.180.150:80`) from Kali through a compromised gateway (`10.200.180.200`).

---

## Step 1 — SSH into the Compromised Gateway

```bash
ssh -i id_rsa root@10.200.180.200
```

Check the network interface and subnet:

```
[root@prod-serv ~]# ifconfig
eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 9001
        inet 10.200.180.200  netmask 255.255.255.0  broadcast 10.200.180.255
```

- Subnet mask `255.255.255.0` → `/24` → only the last octet changes.

---

## Step 2 — Upload a Static Nmap Binary

A **static Nmap binary** bundles all dependencies into one executable — it runs on any Linux box without needing installed libraries.

```
Normal Nmap                       Static Nmap
─────────────                     ─────────────
nmap                              nmap (static)
 ├── needs libc                    ├── Nmap code
 ├── needs libssl                  ├── required libraries
 ├── needs other libraries         ├── dependencies
 └── needs those installed         └── everything in one executable
```

Download from: `https://github.com/andrew-d/static-binaries/blob/master/binaries/linux/x86_64/nmap`

Transfer to the compromised host (e.g., via `curl` or `python3 -m http.server`), then:

```bash
chmod +x nmap
```

## Step 3 — Host Discovery (Ping Sweep)

```bash
./nmap -sn 10.200.180.200/24
```

- `-sn` — Ping sweep only (host discovery, no port scan).
- `/24` — Scan the full subnet (only last octet varies).

## Step 4 — Port Scanning the Internal Hosts

### Scanning `10.200.180.100`

```bash
./nmap -p0-100 -vv 10.200.180.100
```

```
All 101 scanned ports on ip-10-200-180-100.eu-central-1.compute.internal (10.200.180.100) are filtered because of 101 no-responses
```

> All ports **filtered** — cannot access directly. Must reach `.100` through `.150` first.

### Scanning `10.200.180.150`

```bash
./nmap -p0-100 -vv 10.200.180.150
```

```
PORT   STATE SERVICE REASON
80/tcp open  http    syn-ack ttl 128
```

> Port 80 is **open** — a web service is running.

```bash

Returns Django debug page with URL patterns: `/registration/login/`, `/gitstack/`, `/rest/`.

└─# curl http://10.200.180.150


```

> No response — Kali cannot directly reach the internal server. **This is exactly why we need local port forwarding.**

## Step 6 — Create the Local Port Forward

### Syntax Recap

```
ssh -L [LOCAL_PORT]:[REMOTE_TARGET_HOST]:[REMOTE_TARGET_PORT] -i [KEY] [USER]@[JUMP_HOST]
```

### Execute

```bash
ssh -L 8000:10.200.180.150:80 root@10.200.180.200 -i id_rsa -fN
```

| Flag | Meaning |
|---|---|
| `-L 8000:10.200.180.150:80` | Bind local port `8000` → forward to `10.200.180.150:80` through the jump host |
| `-f` | Send SSH to background before command execution |
| `-N` | Don't execute a remote command or open an interactive shell |

> **Tip:** It's often better to skip `-fN` and just open a separate terminal with the SSH session. This way closing the terminal automatically kills the tunnel — no stale background processes.

### Verify the Process is Running

```bash
┌──(root㉿kali)-[/home/kali/Downloads/wreath]
└─# ps aux | grep "ssh"
root       86135  0.0  0.0  19728  5992 ?        Ss   12:49   0:00 ssh -L 8000:10.200.180.150:80 root@10.200.180.200 -i id_rsa -fN
```

## Step 8 — Kill the Port Forward

Find the process ID:

```bash
ps aux | grep "ssh"
```

Kill it:

```bash
kill -9 86135
```

Verify it's gone:

```bash
┌──(root㉿kali)-[/home/kali/Downloads/wreath]
└─# ps aux | grep "ssh"
kali        1426  0.0  0.0  10676  1912 ?        Ss   10:02   0:00 /usr/bin/ssh-agent -s
root       59589  0.0  0.1  19728 11316 pts/7    S+   11:56   0:00 ssh -i id_rsa root@10.200.180.200
root       93457  0.0  0.0   6552  2384 pts/1    S+   13:02   0:00 grep --color=auto ssh
```

> The `-L` port forwarding process is no longer listed — tunnel is closed.

## Summary

| What | How |
|---|---|
| Discover internal hosts | Static nmap binary + `-sn` ping sweep on the `/24` subnet |
| Identify open ports | `./nmap -p0-100 -vv <target>` from the jump host |
| Forward internal service to Kali | `ssh -L <local_port>:<internal_ip>:<internal_port> user@jump_host` |
| Access forwarded service | `curl http://127.0.0.1:<local_port>` or browser to `localhost:<local_port>` |
| Kill background tunnel | `ps aux \| grep ssh` → `kill -9 <PID>` |
