## Lab Setup

```bash
ssh user@<TARGET_IP> -oHostKeyAlgorithms=+ssh-rsa
# Password: password321
```

> [!note] The `-oHostKeyAlgorithms=+ssh-rsa` flag is needed because OpenSSH may reject deprecated RSA host key algorithms.

> [!tip] Privilege escalation may not always be a single hop. In real-world scenarios it can involve **multiple pivots**: service account → normal user → another user → root. The enumeration methodology remains the same at every stage.

## 1. Current User & Privilege Level

### `whoami` — Current Username

```
user@debian:~$ whoami
user
```

### `id` — UID, GID, and Group Memberships

```
user@debian:~$ id
uid=1000(user) gid=1000(user) groups=1000(user),24(cdrom),25(floppy),29(audio),30(dip),44(video),46(plugdev)
```

- Custom user accounts typically start at **UID 1000**
- Check group memberships — special groups can provide immediate escalation paths

```
Debian-exim:x:101:103::/var/spool/exim4:/bin/false

mysql:x:104:106:MySQL Server,,,:/var/lib/mysql:/bin/false
```

**What to look for:**
- Users with **UID ≥ 1000** → interactive custom users
- **UID 0** → root account
- Accounts with `/bin/bash` or `/bin/sh` → have login shells
- Accounts with `/bin/false` or `/usr/sbin/nologin` → no interactive login

> [!tip] Mapping users helps determine if you can escalate **directly to root** or need to **pivot horizontally** first (`user` → `user2` → `user3` → `root`).

### Dangerous Group Memberships to Watch For

| Group | Privilege Escalation Risk |
|---|---|
| **docker** | Run containers → trivial root escalation |
| **shadow** | Read `/etc/shadow` → extract password hashes for offline cracking |
| **sudo / wheel** | Execute commands as root |
| **disk** | Raw disk access → read any file |
| **adm** | Read SSH auth logs, inspect past login attempts |
| **backup** | Access system file backups |
| **mysql** | Read/manipulate database files directly |

## 5. OS & Kernel Version

```
user@debian:~$ cat /etc/issue
Debian GNU/Linux 6.0 \n \l
```

```
user@debian:~$ cat /etc/os-release
cat: /etc/os-release: No such file or directory
```

- `uname -a` gives the exact **kernel version** and **CPU architecture**
- Search Exploit-DB for kernel exploits matching the version

> [!warning] Kernel exploits are **rarely the intended vector** in modern pentests or OSCP (99% of systems are patched, and kernel exploits can crash the system). However, kernel enumeration is still essential for determining compilation tools and software distribution requirements.

**Key technique:**
- `ps aux | grep root` → filter for **root-owned processes**
- If a root process runs a script/binary you can **modify**, you get root code execution
- In `top`, press `u` then type `root` to filter by user interactively
