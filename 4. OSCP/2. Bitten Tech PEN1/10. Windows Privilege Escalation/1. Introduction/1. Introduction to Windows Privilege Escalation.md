### **[Section 2: Penetration Testing Methodology & Initial Compromise]**

I have created a separate course for Linux, which you can take. This course is specifically tailored for Windows. Let's take a look at our penetration testing methodology. This overview diagram provides a complete view of penetration testing stages and how the overall process works.

The first stage is reconnaissance, information gathering, scanning, and identifying details about how the target is built and what it contains. Next is initial compromise, where you identify system vulnerabilities to achieve Remote Code Execution (RCE). Finding initial access flaws can involve web-related vulnerabilities, public exploits, passwords, credentials, or misconfigurations.

---

### **[Section 3: Gaining Initial Foothold & Low-Privilege Accounts]**

After identifying vulnerabilities, we establish a foothold on the target machine based on the exploitability of those flaws and obtain an RCE shell session. Once access is established, we begin the stage taught in this course: **Privilege Escalation**.

Generally, when conducting penetration testing, initial web-based access lands on low-privileged service accounts created specifically for those services with minimal system privileges. To compromise the system completely, obtain kernel or superuser access, or reach administrator-level permissions, you must escalate privileges.

---

### **[Section 4: Active Directory & Enterprise Infrastructure]**

The stages above this involve maintaining presence internally, which is used in multi-user environments like domain environments managed by Active Directory (AD). In real-world corporate setups, there are many Windows machines across different departments. In those environments, domain controllers and connected systems require managing complex multi-level privileges. I have created a separate course covering Active Directory, internal reconnaissance, lateral movement, and persistence.

---

### **[Section 5: The Ultimate Goal — Superuser Access]**

In an engagement, your ultimate mission is not just obtaining superuser access on a single machine, but gaining administrative control across the entire domain or enterprise infrastructure. You aim to reach the highest level of privilege above which no further escalation is possible. Initial access rarely grants direct admin permissions. Because administrator accounts are highly regulated and rarely exposed with external misconfigurations, initial access usually lands on a standard or low-privileged service account.

---

### **[Section 6: Low-Privilege Service Accounts to Admin]**

For example, web applications on Windows run under low-privileged service accounts like `www-data` or the IIS Application Pool (`IIS_IUSRS`), which have fewer privileges than even standard users. Therefore, privilege escalation is required to reach the Local Administrator account, which holds the necessary permissions to modify systems or install software on Windows.

---

### **[Section 7: Importance of Enumeration]**

Information gathering and enumeration are critical throughout this stage and course. In penetration testing exams like OSCP or real engagements, it's not just about _how_ you attack, but _what_ you attack. Finding _what_ is vulnerable across a large system with numerous services, programs, users, credentials, and features is the most important and challenging part. Enumeration is key.

---

### **[Section 8: Lateral Movement & Targeting Strategy]**

Lateral movement—moving from one system to another across network segments—is only possible once you hold maximum privileges on a compromised system. Creating network routes to pivot across internal network segments requires elevated privileges that low-level users cannot execute. Privilege escalation is not always a one-step process; it may involve stepping from a service account to a standard user, then to another user, before reaching administrator permissions.

---

### **[Section 9: Defining Your Target Account: Local Admin vs. NT AUTHORITY\SYSTEM]**

You must establish a clear target path. In Linux, the ultimate superuser account is `root`. In Windows, if you are focusing on technical administration, the target is the **Local Administrator** account.

However, if you have advanced knowledge of Windows architecture, the ultimate goal is the **`NT AUTHORITY\SYSTEM`** account, which is a reserved system protection account with privileges higher than a standard local administrator. Setting `SYSTEM` as your target ensures you reach the absolute highest privilege level in Windows.

---

### **[Section 10: Overview of Windows User Accounts: Local vs. Domain]**

In Windows, accounts are broadly divided into two categories: **Local Accounts** and **Domain Accounts**. A local account's permissions and scope of access are restricted exclusively to that specific isolated local machine. Local account types include Administrator, Standard User, Guest, and Shared accounts.

---

### **[Section 11: Domain Accounts & Default Accounts]**

In contrast, Domain Accounts are joined to an Active Directory domain controller. A single domain account can log into any of the domain-joined computers based on granted permissions. Among local accounts, you will also find the Default Account, which is a built-in reserved account used to run multi-user or shared application processes that remain active even when individual user sessions log off.

---

### **[Section 12: Guest Accounts]**

The Guest account provides extremely limited temporary access. It is disabled by default, allows no password requirement when enabled, and prevents users from installing applications, modifying system files, or altering other users' data.

---

### **[Section 13: Standard User Accounts]**

Standard User accounts are what normal employees or lab students receive. They can execute assigned applications and store files within their designated profile directories, but cannot install programs, uninstall software, modify system configurations, or perform administrative tasks without entering administrator credentials.

---

### **[Section 14: Administrator Accounts]**

The Administrator account is the most powerful login account in Windows. It can install or uninstall programs, modify system settings, create or delete user accounts, and reset passwords. Reaching this account is the primary objective during privilege escalation.

---

### **[Section 15: Common Misconfiguration Attack Vectors]**

Where do common misconfigurations occur in Windows systems?

1. **Windows Services**: How service binaries run, which user permissions they inherit, binary execution paths, and whether service binaries/directories are writable.
2. **Access Control Lists (ACLs)**: Misconfigured permissions on files, folders, and registry keys.
3. **Privilege Tokens**: Abusing specific user privileges/tokens such as `SeImpersonatePrivilege`, `SeAssignPrimaryTokenPrivilege`, or `SeBackupPrivilege`.
4. **Sensitive Information & Stored Credentials**: Hardcoded credentials in unattended install files, log files, backup files, registry keys, or API tokens.
5. **Software Vulnerabilities**: Unpatched third-party applications and public CVE exploits.
