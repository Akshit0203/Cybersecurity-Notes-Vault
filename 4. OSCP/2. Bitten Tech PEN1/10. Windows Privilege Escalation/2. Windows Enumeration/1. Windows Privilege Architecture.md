# Windows: Administrator vs SYSTEM

The main difference is the level of privileges and what the account is allowed to control.

## 1. Administrator

An Administrator is a user account with extensive privileges on a Windows computer.

Example:

```
WIN-PC\Akshit
```

with membership in the local Administrators group.

An Administrator can generally:

- Install software and drivers (subject to security controls).
    
- Create and manage user accounts.
    
- Change system settings.
    
- Access many protected files.
    
- Configure services and scheduled tasks.
    
- Perform administrative actions with elevated privileges.
    

However, Windows User Account Control (UAC) can restrict when administrative privileges are used. An administrator may operate with a filtered token until elevation occurs.

## 2. SYSTEM (NT AUTHORITY\SYSTEM)

SYSTEM is a built-in Windows service account, also called the Local System account.

Its identity is:

```
NT AUTHORITY\SYSTEM
```

It is used by Windows services and system processes.

SYSTEM generally has very extensive local privileges, including the ability to:

- Manage operating system services.
    
- Access protected system resources.
    
- Run processes on behalf of Windows components.
    
- Access many local files and registry locations.
    
- Operate with powerful local security privileges.
    

SYSTEM is not the same as a normal Administrator account. It is intended for the operating system itself.

## 3. Simple comparison

|Feature|Administrator|SYSTEM|
|---|---|---|
|Account type|Administrative user|Built-in service identity|
|Identity example|`PC\admin`|`NT AUTHORITY\SYSTEM`|
|Intended use|Human administration|Windows system operations|
|UAC|Can be subject to UAC|Not a normal interactive UAC user|
|Local privileges|Extensive|Generally more powerful for system operations|
|Network identity|Uses its user or machine context|Usually uses the computer's machine account for network access|
|Interactive login|Can log in normally|Not intended for normal interactive login|

## 4. OSCP privilege escalation example

Imagine you obtain a shell as:

```

```

Output:

```

```

You then discover a misconfigured service that allows you to execute code as SYSTEM.

Your privilege level changes:

You can verify your current identity with:

```

```

To inspect your privileges:


To check group membership:

```

```

### Important

Administrator does not always mean you automatically have SYSTEM. In penetration-testing labs, you may need to identify a separate privilege escalation path.

# Windows Mandatory Integrity Levels (MIC)

Mandatory Integrity Control (MIC) is a Windows security mechanism that controls what processes can do to objects based on their integrity level.

Simple idea:

> A process with a lower integrity level generally cannot modify objects belonging to a higher integrity level.

## 1. Main integrity levels

Windows commonly uses these four integrity levels:

|Integrity level|Meaning|Example|
|---|---|---|
|Low|Highly restricted|Sandboxed browser process|
|Medium|Normal user execution|Standard application|
|High|Elevated administrator process|Administrator Command Prompt|
|System|System-level execution|Windows services running as SYSTEM|

There is also an Untrusted level below Low.

### Visual hierarchy

```
System       🔴 Highest
    ↑
High
    ↑
Medium
    ↑
Low
    ↑
Untrusted    🔵 Lowest
```

This is a simplified hierarchy. Actual access also depends on security tokens, ACLs, privileges, and other Windows security controls.

## 2. Example: Medium vs High

Suppose you open a normal Command Prompt:

```
whoami
```

Your process may have:

```
Medium Integrity
```

You then open an elevated Administrator Command Prompt:

```
High Integrity
```

The administrator process has a higher integrity level.

A medium-integrity process generally cannot directly modify protected objects that require a higher integrity level, even if the user is an administrator.

## 3. How to check integrity level

Run:

```
whoami /groups
```

Look for a line similar to:

```
Mandatory Label\Medium Mandatory Level
```

Or:

```
Mandatory Label\High Mandatory Level
```

Example:

```
Mandatory Label\High Mandatory Level
```

This indicates that the security token has High integrity.

### PowerShell alternative

```
whoami /groups | Select-String "Mandatory Label"
```

## 4. Why MIC matters in OSCP

During Windows privilege escalation, you should distinguish between:

- User identity: Who are you?
    
- Group membership: Which groups do you belong to?
    
- Integrity level: At what trust level is your process running?
    
- Privileges: What special rights does your token possess?
    

For example:

```
User:       Administrator
Integrity:  Medium
```

does not mean the same thing as:

```
User:       Administrator
Integrity:  High
```

> Integrity level = How trusted your process is.

> Privileges = What special actions your token can perform.

### **[Section 1: Introduction to Windows Enumeration & Security Basics]**

So coming to enumeration, why do we do it and how do we do it in Windows? We will learn this. But before enumeration, I would like to tell you some basics of Windows. Understanding some basics is necessary—how access control, user levels, and security controls work in Windows—because these will be very useful to us in the exploitation phase in understanding how and why we apply exploits.

Before understanding them, we have to understand that there are **Integrity Levels** in Windows. I have told you before as well that the levels of users in Windows start at the bottom with the **Guest User**, which is very temporary. Once you log in and log out, it is gone because it has no permanent foothold on the system. On the system, a temporary Guest user is just created, and you don't need to make major changes to the system—just limited access without any permanent changes. So you can create a Guest user.

---

### **[Section 2: User Access Levels (Standard User vs. Administrator)]**

And then above that comes the **Standard User**, which is a normal user that has its own directory in Windows—a home folder, Desktop, Documents. You can log in through that, and it is permanent until explicitly deleted. So you will be able to log in with limited access—meaning access to its own files and folders, but not to others' files and folders by default. It can work in its own login, access its own files, and perform common tasks like opening files/folders, audio/video files, documents, or surfing the internet. But it cannot make system-wide changes like admin-level changes that affect the entire system.

Above that comes the **Administrator**. This is the highest level of user access that can do almost everything in Windows. But there is a difference: people think Administrator is the highest level in Windows, but that is not so. There is another level above it, but understanding the difference is essential. The Administrator also lacks access to certain things on the system, but mostly has access to install programs, make system-level changes, install configurations/services, perform system updates and upgrades, and has access to all users—changing passwords, executing system-level tasks. So the Administrator can do all of this; it holds the most power. You can log in through it, it has its own built-in user, and it is assigned to the `Administrators` group. So creating user accounts, creating groups—it can do all these things. Normally for a regular user, this is the highest level of access, right? So we understand user levels now.

---

### **[Section 3: Access Tokens & Windows Security Identifiers (SIDs)]**

Now let's talk about **Integrity Levels**. What is integrity? In Windows, there is a concept that whenever you log in, you log in through a defined user. For that login session, an **Access Token** is assigned to you. That Access Token will be used across all processes and threads that you spawn as a user.

So let's assume you have a user—in Windows terms, every user has an **SID (Security Identifier)**. An SID is a long string. An Access Token is mapped to that SID, and whatever action this SID performs will run using this Access Token. So an Access Token means an access control mechanism that defines what access my user has and what tasks I can perform. Throughout that logon session, I will be assigned an Access Token if I am a normal/standard user.

Now, if I am an Administrator on the system and I log in as an Admin, I will be assigned **not one, but TWO Access Tokens**! Two access tokens will be assigned to my user ID: one access token like a normal user, and the second a high-privilege access token. So these two access tokens you get—one low-privilege and one high-privilege—we can refer to this privilege as **Integrity**. The privilege assigned to an Access Token is called its Integrity level, a concept introduced starting with Windows Vista.

---

### **[Section 4: Mandatory Integrity Control (MIC) & Default Medium Integrity]**

All protectable/securable objects—like processes, threads, files, folders, shares—are assigned an Integrity Level. Whatever process is spawned gets an Integrity Level defined by its Access Token, which indicates its integrity level.

By default, as a normal user, I get a **Medium Integrity** level. Interestingly, even if you are an Administrator, by default you are ALSO assigned a Medium Integrity level! This is an interesting point: when you log in as Admin, you get two access tokens, but the first one (low/medium privilege) is assigned to you by default. Whatever task you do, whether you are Admin or not, you get Medium Integrity by default. You cannot use the High-level access token by default. You can only use it when you give explicit consent to use it, or through an auto-elevate process/technology which we will discuss later.

All processes initiated by you run with Medium Integrity level. The exception is **Windows Services**, which run with **System Integrity**. System Integrity is the highest level of integrity. I am not saying High—High is a separate integrity level, and System is another higher integrity level. We will talk about Integrity Levels, but there is also **Low Integrity**, which is very restricted and not given to standard users (given to Guest or isolated accounts). But we get Medium.

Why was this Integrity concept created? Because if an arbitrary process/thread/service runs and accidentally or maliciously turns bad, if it is at Low or Medium integrity, it cannot write to, access, or modify higher-integrity objects. So this is a security boundary: even if you are an Admin, you are not an Admin in the real sense until you give explicit consent every time—following a privilege-change or access-control prompt—otherwise you remain at Medium. Understanding Integrity is necessary because we will use it heavily when exploiting later, as certain things won't work at Medium Integrity and require High. Exploiting Admin-level tasks won't work on Medium; they require High. To perform Administrator privilege tasks, we need to own at least a High Integrity object. So a standard user has only one Access Token (Medium Integrity), while an Administrator user has two Access Tokens (one Medium Integrity and one High Integrity).

---

### **[Section 5: Hierarchy of Integrity Levels in Windows]**

Now let me explain how Integrity Levels work in Windows:

1. **Low Integrity Level**: This is very restrictive. In virtual environments or sandbox environments, if you test applications, you explicitly assign Low level to an object. By default, when you log in as a standard user, you don't get Low. But some processes are assigned Low by the system—for example, any file downloaded from the internet initially runs at Low Integrity for security. Browsers, internet-downloaded files, or unknown source processes run at Low Integrity first before escalating. Sandboxes and App Containers also use Low Integrity by default for testing untrusted code/malware.
2. **Medium Integrity Level**: Generally, you start at Medium. If you spawn a CMD or reverse shell as a standard user (and not a service account), you will get Medium Integrity. Sometimes service accounts also yield Medium, which you must note. At Medium, elevated admin commands in Windows are not permitted—you cannot run `sudo`-equivalent tasks. You can only manage and access your own files and folders, not others'. In our privilege escalation course, the primary escalation step is moving from Medium to High Integrity!
3. **High Integrity Level**: High belongs to Admin, where the admin can do anything system-wide, like a superuser with `sudo`/admin access. Why say `sudo`? Pay close attention: **I did NOT call Admin 'root'. Admin is NOT root!** People get confused thinking Admin in Windows equals root in Linux, but that is not completely true. If you log in as Admin and open a CMD, it STILL opens with Medium Integrity! To do Admin tasks, you must bypass **UAC (User Access Control)**. User Access Control is the mechanism separating these Integrity Levels.
4. **System Integrity Level**: Once you reach High Integrity, there is another step above it: System Level Integrity. This is what actually compares to 'root'. It doesn't match root 100%, but it is very close to root. When playing CTFs or doing privesc, the maximum shell you aim for is **`NT AUTHORITY\SYSTEM`**. That's when you say privesc is complete. Just like reaching root in Linux, in Windows our target is `NT AUTHORITY\SYSTEM` access.

---

### **[Section 6: Local Administrator vs. `NT AUTHORITY\SYSTEM`]**

Now, the biggest confusion people have is when they do Windows privesc and get Admin access. Once they get Admin, they don't know whether to proceed further or stop, thinking Admin equals root. But what is System / `NT AUTHORITY`? Why do we need to reach it, and what is the difference between Admin and System? Let me explain the difference:

- **Administrator**: First, Administrator is a **User Account**. You can log in through that account; it has an assigned UID/SID, belongs to the default `Administrators` group, and you can assign privileges or groups to it.
- **`NT AUTHORITY\SYSTEM`**: SYSTEM is **NOT a user account**; it is a **Security Principal / built-in Security Model**. You cannot create or delete it. It is a security identifier assigned to services executing high-level kernel tasks. You CANNOT log in as SYSTEM with a username and password—that never happens. It is not assigned to any group, nor is it a group itself, so you cannot assign privileges to it. It possesses its own maximum-level privileges to perform everything at the kernel level.

There are things an Admin CANNOT do! For example, Windows File Protection or files currently in use—like the SAM file (`C:\Windows\System32\config\SAM`), which is in use by the system from startup to shutdown. As an Admin, you cannot directly modify or access the SAM file while in use. But with SYSTEM privileges, you can forcefully access or modify files while they are in use! As a penetration tester, reaching SYSTEM allows you to perform deep kernel-level changes, access locked files, or modify restricted registry keys that even Admin cannot touch. SYSTEM has literally unrestricted system service access, whereas Admin has restricted access.

Local Admin has an SID, and SYSTEM also has an SID (`S-1-5-18`). `Local System` is another name for `NT AUTHORITY\SYSTEM`. Whether you say `System` or `Local System`, it is the same thing. Local System holds the highest level of access using the SYSTEM SID and receives System-level Integrity. Whenever you find an avenue to execute commands on behalf of Local System, you get a System-level shell, which is your ultimate objective in privilege escalation.

Why `NT AUTHORITY`? As mentioned earlier, modern Windows still uses the NT kernel (introduced in Windows NT). That's why it is named `NT AUTHORITY\SYSTEM`. It is a security model, not a standard user/group, giving kernel-level access. Most system services run on its behalf.

### **[Section 7: Summary of Integrity Levels (HackTricks Reference)]**

Looking at the HackTricks snapshot of integrity levels:

- **Untrusted Integrity**: Assigned automatically to processes logged on anonymously (e.g., browser sandboxes).
- **Low Integrity**: Used for protected mode apps like browsers or temporary downloaded files so they cannot write to the registry or restricted directories.
- **Medium Integrity**: Where most objects and normal user sessions run by default (neither low nor high, in the middle).
- **High Integrity**: When you want to become High Integrity, Admin works here via UAC. Bypassing UAC elevates you to High Integrity. Right-clicking CMD and choosing "Run as Administrator" prompts a UAC prompt; clicking Yes launches CMD with High Integrity.
- **System Integrity**: Used by system services, providing kernel-level access.
- **Installer Integrity**: Used by application installers to uninstall/modify all objects (we focus primarily on System Integrity as the highest level).

---

### **[Section 8: Practical Inspection Commands (`whoami` & `icacls`)]**

Now let me show you commands to find file integrity levels and permissions. We have the **`icacls`** command (`icacls <file/directory>`). We will use this command extensively to analyze access rights on objects, because you can only modify files or misconfigurations if you have appropriate write/modify permissions. To check your current user permissions and group memberships, you can run **`whoami /groups`**.

Demonstrating on my main Windows system: I am logged in as an admin user (`add`). Checking `net user add` shows group membership in `Administrators`. Running `whoami /groups` lists my groups and shows **`Mandatory Label\Medium Mandatory Level`**. Even though I am an Admin, opening standard `cmd.exe` without "Run as Administrator" assigns Medium Integrity by default!

This Medium integrity level reflects **Mandatory Integrity Control (MIC)**, which assigns a trust level to every process/resource. If I search CMD, right-click, and select "Run as Administrator", a UAC consent prompt appears asking _"Do you want to allow this app to make changes to your device?"_. Clicking Yes launches CMD, and running `whoami /groups` now displays **`Mandatory Label\High Mandatory Level`**!

To check or set file integrity levels using `icacls`:

```
icacls <filename> /setintegritylevel H
```

Running this attempts to set the file integrity level to High. However, if you attempt this from a Medium Integrity shell, it fails because a Medium process cannot assign a higher integrity level than its own. Setting it to Medium (`/setintegritylevel M`) succeeds. Once set, running `icacls` displays the assigned integrity level (`Mandatory Label\Medium Mandatory Level`).

You can also use GUI monitoring tools like Process Monitor (ProcMon) or Process Hacker to view running process integrity levels in real time. Remember: you cannot perform High-integrity tasks or set High-integrity levels unless you are operating within a High-integrity context yourself.
