### **[Section 1: Introduction to User Access Control (UAC) & Integrity Levels]**

Now we will talk about **User Access Control (UAC)**. This concept is very similar to and directly related to what we previously covered regarding Integrity—specifically how system execution behavior changes when Access Control is enabled.

You may have heard about User Access Control, which is a core security feature in Windows. When UAC is enabled, by default it forces all applications and processes to run at a **Medium Integrity** level in a non-administrative context. Even if you are logged in using an Administrator account, the access token used across all your active processes remains at Medium Integrity—the High Integrity token is not used by default. If UAC is disabled, the situation changes and it grants High Integrity directly. However, whenever you attempt a task that requires administrator access, a consent or approval prompt appears so you can explicitly approve actions that require elevated privileges. For elevated activities, UAC presents an approval form.

---

### **[Section 2: UAC Prompts, Non-Admin vs. Admin, & Pen Testing Context]**

If you are logged in as an Administrator, a simple **Yes/No** consent prompt appears. If you are logged in as a non-admin standard user, you must enter the credentials (username and password) of an Administrator account to authorize the action. Thus, explicit consent must be granted to execute tasks as an Administrator.

In penetration testing engagements, when you obtain an initial reverse shell session on a target system, you generally do not have GUI desktop access—you only have an interactive command prompt shell (`cmd.exe`). If UAC is enabled on the target system, your shell session executes at Medium Integrity level even if the account belongs to the `Administrators` group.

For visual examples: if you are logged in as a non-admin and attempt administrative tasks—such as upgrading the system, modifying firewall or system settings, installing software, or creating a system service—a prompt appears asking for an Administrator username and password. When logged in as an Administrator, a consent prompt appears requiring only a Yes or No click to proceed.

---

### **[Section 3: UAC Default Slider Settings & System Demonstration]**

Once you click Yes, the task executes, but Windows will continue prompting for subsequent administrative tasks.

Reviewing the screenshots from my own system: when running `whoami` for the user account (e.g., `dell`), `dell` is a local Administrator because it is added to the `Administrators` group. However, when checking `dell`'s active execution level using `whoami /groups`, it displays **Medium Mandatory Level**. This is precisely why UAC exists.

By default, when UAC is enabled, it is set to the default notification slider position (referred to as level 5 or the second setting from the top). Under this default setting, Windows notifies you only when applications attempt to make changes to your computer or Windows settings on your behalf. When an app attempts a system change, a consent prompt appears and the desktop screen dims (entering Secure Desktop mode). All other screen interactions are suspended until you click Yes or No on the prompt.

---

### **[Section 4: Always Notify (Recommended Security Level) & UAC Bypass Preview]**

While the default setting notifies only when apps attempt changes, the recommended security setting is **"Always Notify"** (the highest top position on the UAC slider). Under "Always Notify", UAC prompts for approval whenever applications attempt to install software or make changes, as well as whenever you personally attempt to modify Windows system settings. This forces you to pause and verify why a setting change or installation is occurring. While prompting frequently can slightly impact user experience, it is highly recommended from a security standpoint.

This provides our core definition of User Access Control (UAC). In upcoming modules, when we cover **UAC Bypass** exploitation techniques, understanding these underlying UAC slider levels and integrity token mechanics will be essential.
