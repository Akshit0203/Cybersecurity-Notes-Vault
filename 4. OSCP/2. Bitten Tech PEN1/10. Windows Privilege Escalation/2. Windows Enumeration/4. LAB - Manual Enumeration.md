This command shows the Windows hotfixes and security updates installed on the machine. In OSCP, we use it to identify potential missing patches and Windows privilege escalation vulnerabilities.

## 1. Understand the command

```
wmic qfe get *
```

|Part|Meaning|
|---|---|
|`wmic`|Windows Management Instrumentation Command-line|
|`qfe`|Queries Quick Fix Engineering (hotfixes/updates)|
|`get *`|Displays all available fields|

In simple words:

> "Show me the updates and hotfixes installed on this Windows machine."

## 2. Understand your output

You found:

```
HotFixID     Description
KB4514366    Update
KB4512577    Security Update
KB4512578    Security Update
```

These are KB (Knowledge Base) numbers that identify specific Microsoft updates.

|Field|Meaning|
|---|---|
|`HotFixID`|Update identifier, e.g. `KB4514366`|
|`Description`|Type of update|
|`InstalledOn`|Installation date|
|`CSName`|Computer name|
|`Caption`|Microsoft support URL for the update|

Your output shows updates installed on September 7, 2019.

## 3. Why is this useful in OSCP?

You want to determine whether the Windows machine is missing security updates.

The general workflow is:

```
Enumerate installed patches
          |
          v
Identify Windows version/build
          |
          v
Research relevant vulnerabilities
          |
          v
Check whether the target is affected
          |
          v
Test an appropriate exploit in the authorized lab
```

### Example

If you find an old Windows build and notice that a particular security update is missing, you can investigate whether a documented vulnerability applies.

Important: An old installation date does not automatically prove that the machine is vulnerable. You need to compare the installed patches against the OS version, build, and vulnerability requirements.

## 4. Useful commands for your notes

```
wmic qfe get HotFixID,Description,InstalledOn
```

### Modern PowerShell alternative

```
Get-HotFix
```


# `tasklist /svc` in Windows

The command:

```
tasklist /svc
```

shows all running processes and the Windows services associated with each process.

## 1. Understand the command

|Part|Meaning|
|---|---|
|`tasklist`|Lists currently running processes|
|`/svc`|Displays the services hosted by each process|

In simple words:

> "Show me which processes are running and which Windows services are running inside them."

## 2. Example output

```
Image Name      PID    Services
svchost.exe     1200   Dhcp, Dnscache
svchost.exe     1500   Schedule, EventLog
lsass.exe       700    N/A
```

### Understand the columns

|Column|Meaning|
|---|---|
|`Image Name`|Process executable name|
|`PID`|Process ID|
|`Services`|Services running inside that process|

### Example

```
svchost.exe    1500    Schedule, EventLog
```

This means:

- `svchost.exe` is running with PID `1500`.
    
- The `Schedule` and `EventLog` services are hosted in that process.
    

## 3. Why is it useful in OSCP?

You use it during Windows enumeration to understand running services and processes.

```
Running processes
       |
       v
Identify services
       |
       v
Investigate service configuration
       |
       v
Look for misconfigurations
```

You might investigate:

- Services running with elevated privileges.
    
- Unusual processes.
    
- Service names and associated PIDs.
    
- Services that may be relevant to privilege escalation.
    

Important: `tasklist /svc` only shows process and service associations. It does not automatically tell you whether a service is vulnerable.

## 4. Useful related commands

### List running processes

```
tasklist
```

### Display services

```
sc query
```

### Show detailed process information

```
tasklist /v
```

### Check a specific process

```
tasklist /fi "PID eq 1500"
```

### Why is this important?

Windows Installer packages (`.msi`) may run with elevated privileges, potentially allowing a low-privileged user to execute installer-provided actions with SYSTEM-level privileges.

#### **[Section 2: User and Group Enumeration]**

Now, let's begin manual enumeration. The very first step is verifying your current user identity and existing privilege context:

```
whoami
```

Running `whoami` displays the `HOSTNAME\username` format (e.g., `SERVER2019\user`).

To enumerate all local user accounts created on the target machine, use the **`net user`** command (the Windows equivalent of inspecting `/etc/passwd` on Linux):

```
net user
```

This lists default built-in accounts (such as `Administrator` and `Guest`), custom local accounts, and your active user account. Focus your attention on custom user accounts and administrative users rather than low-privileged default accounts.

To extract detailed account properties for a specific user, pass the username to `net user`:

```
net user user
```

This reveals:

- Full name, account comments, country/region code.
- Account active status (`Yes`/`No`), password expiration dates, and password requirements.
- Last logon timestamp and password last set timestamp.
- **Local Group Memberships** (e.g., `*Users`) and Global Group Memberships.

Checking administrative users (e.g., `net user admin`) confirms whether they belong to the **`Administrators`** group, identifying them as primary privilege escalation targets.

To list all local security groups created on the machine, run:

```
net localgroup
```

This displays default and custom groups (such as `Administrators`, `Users`, `Remote Desktop Users`, or `IIS_IUSRS`).

To view all user accounts assigned to a specific local group, pass the group name to `net localgroup`:

```
net localgroup Users
net localgroup Administrators
```

Inspecting `net localgroup Administrators` reveals all users holding full, unrestricted administrative access over the operating system.

#### **[Section 3: Operating System & Kernel Enumeration]**

Next, we perform operating system enumeration to identify kernel versions, OS builds, and installed patch hotfixes. Kernel vulnerabilities (CVEs) can provide direct system-level access if matching public exploits exist.

The most comprehensive manual OS enumeration command in Windows is **`systeminfo`**:

```
systeminfo
```

`systeminfo` collects and displays:

- **Host Name** and **OS Name** (e.g., `Microsoft Windows Server 2019 Standard`).
- **OS Version & Build Number** (e.g., `10.0.17763 N/A Build 17763`).
- **System Type / Architecture** (e.g., `x64-based PC`) and total system memory.
- **Installed Hotfixes (KBs)**: Lists all installed security updates.

Identifying exact build numbers and installed hotfixes (KB articles) is critical. If a specific hotfix addressing a known kernel flaw is already installed on the build, associated public exploits will fail.

Alternatively, Windows Management Instrumentation (**WMI**) can query hotfix updates directly:

```
wmic qfe get Caption,Description,HotFixID,InstalledOn
```

To query OS version details via WMI:

```
wmic os get Caption,Name,BuildNumber
```

#### **[Section 4: Process and Service Mapping]**

To enumerate all active running processes, use the **`tasklist`** utility:

```
tasklist
```

`tasklist` displays process image names, Process IDs (PIDs), session names, and memory consumption.

To identify which specific user account is running each process, use the verbose flag:

```
tasklist /v
```

This reveals system processes running under `NT AUTHORITY\SYSTEM`, user processes running under logged-in user contexts, and background service instances.

```
tasklist /svc
```

Mapping processes to services is vital because misconfigured or vulnerable services running under elevated privileges represent key privilege escalation vectors.

#### **[Section 5: Network Configuration & Firewall Enumeration]**

To inspect local IP address assignments, network adapters, subnet masks, default gateways, and DNS/DHCP configurations, run:

```
ipconfig /all
```

To view the system IP routing table, active interfaces, and network gateways, use:

```
route print
```

To enumerate active network connections and internal listening ports, run **`netstat`**:

```
netstat -ano
```

- **`-a`**: Displays all active connections and listening ports.
- **`-n`**: Displays addresses and port numbers in numerical format.
- **`-o`**: Displays the associated Process ID (PID) for each connection.

Analyzing `netstat -ano` reveals internally bound services (e.g., ports listening strictly on `127.0.0.1` or internal subnets) that were invisible during external Nmap scans.

To check the current status of Windows Firewall, execute:

```
netsh advfirewall show currentprofile
```

This displays whether the firewall state is **ON** or **OFF**, along with default inbound/outbound connection policies.

To list all configured firewall rules, run:

```
netsh advfirewall firewall show rule name=all
```

#### **[Section 7: File Permissions via Sysinternals AccessChk]**

To recursively audit file and directory permissions across system drives (such as `C:\Program Files`), we use the Sysinternals **`accesschk.exe`** utility:

```
accesschk.exe -uwcqv Users "C:\Program Files" -accepteula
```

- **`-u`**: Suppresses errors.
- **`-w`**: Searches strictly for writable elements.
- **`-c`**: Searches service permissions.
- **`-q`**: Quiet mode.
- **`-v`**: Verbose output.
- **`-accepteula`**: Silently accepts the Sysinternals license agreement to prevent GUI pop-up prompts in non-interactive shells.

Running `accesschk.exe` identifies writable executables, misconfigured service binaries, and unquoted service paths modifiable by the `Users` group.

#### **[Section 8: Windows Services & Registry Auto-Elevate Checks]**

To query installed Windows services and inspect service configurations, use the **`sc`** (Service Control) command:

```
sc query
sc qc <SERVICE_NAME>
```

Running `sc qc` reveals the binary execution path (`BINARY_PATH_NAME`), service start type, and run context.

To check if the system is configured to execute Windows Installer packages with elevated system privileges (**AlwaysInstallElevated**), query the registry:

```
reg query HKCU\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

If both registry keys return a DWORD value of `0x1`, any standard user can construct a malicious `.msi` installer payload to gain instant **`NT AUTHORITY\SYSTEM`** privileges.
