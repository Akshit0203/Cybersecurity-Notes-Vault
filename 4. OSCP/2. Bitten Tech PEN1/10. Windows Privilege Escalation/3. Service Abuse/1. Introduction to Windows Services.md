### **[Part 1: Introduction to Service Abuse & Windows Services]**

Hello friends, in this video we will start another section in our Windows Privilege Escalation course. This section is very important because services run on every single Windows machine. The foundation of this section—Service Abuse—is built on Windows services, which operate across all environments: production servers, personal computers, workstations, and enterprise systems. Because services run continuously on every host, service misconfigurations are extremely common.

In this course, we will cover four distinct methods of service abuse, which represent the vast majority of real-world service misconfigurations. Before exploring those attacks, we must first understand what a service is and how it functions, as its execution mechanics reveal how misconfigurations arise and how to exploit them. In Windows, services function similarly to daemons in Unix systems.

---

### **[Part 2: Use Cases, Service Accounts, and Background Processes]**

Let's first look at common use cases: for example, running a web service on Windows. It is not feasible to log into the machine manually every time the OS boots just to click a button to start a web server.

To automate tasks and simplify management, service accounts are created to manage and launch services automatically. These background services open network ports, resolve hostnames, and handle protocols like HTTP, FTP, or SSH without requiring interactive user sessions. Eliminating manual user interaction makes the system significantly more efficient, reliable, and scalable. In essence, services are long-running executable applications...

---

### **[Part 3: Service Parameters & Service Control Manager (SCM)]**

...that run within their own designated Windows execution sessions. Every service has specific configuration parameters, including the service name, description, executable binary path, service type, and startup type (such as auto-start, manual start, or event-triggered start).

All service configurations and their entire execution lifecycles—starting, pausing, resuming, and stopping processes—are governed by a core Windows system utility known as the **Service Control Manager (SCM)**. Beyond web servers, services handle critical background operations such as the Windows Update service, which applies system patches silently without presenting frequent interactive GUI pop-ups to the user.

---

### **[Part 4: Background Tasks, Port Binding, and Elevated Contexts]**

Services also handle recurring system tasks, such as network management, generating or removing log files, and automated disk cleanup (e.g., clearing temporary files when storage thresholds are reached). Running as background daemons, services can be configured to launch automatically at boot time.

When configuring a startup service, you specify the user account context under which it executes. Most system services require elevated administrative permissions because they perform low-level tasks—such as binding to privileged network ports (e.g., ports 80, 443, 22), transmitting custom network packets, updating system files, or managing user accounts. Consequently, many Windows services are configured to run under the **LocalSystem** account.

---

### **[Part 5: LocalSystem Account Mechanics & Service Registration Lifecycle]**

The **LocalSystem** account is a built-in Windows security principal (represented by a system SID rather than a standard user account) that possesses full, unrestricted system permissions. Because LocalSystem holds maximum kernel privileges, targeting services running under LocalSystem allows us to escalate our shell to full **`NT AUTHORITY\SYSTEM`** access.

For a service to run, it must first be registered with the Service Control Manager (SCM), installed onto the operating system with its required parameters, and assigned startup rules. SCM then controls its entire lifecycle: starting the process, monitoring status, capturing errors, and logging events to log files. Understanding this service lifecycle provides the foundation for identifying and abusing service misconfigurations.
