
Active Directory
Active Directory (AD) is a Microsoft product that consists of several services that run on Windows Server to manage permissions and access to
networked resources.
Active Directory stores data as objects. An object is a single element, such as a user, group, application or device, such as a printer.
AD DS verifies access when a user signs into a device or attempts to
connect to a server over a network.
A forest is formed by a set of multiple and trusted domain trees and forms the uppermost layer of the Active Directory.

### **[Section 1: Introduction to Active Directory & Domain Controllers]**

**Hello friends. In this video, we are going to talk about Active Directory.** What actually is Active Directory, and what is its purpose? As I told you earlier, in a Microsoft Windows environment, we have to set up a server to control the domain, which we call a **Domain Controller**—it manages permissions, authentication, and user accounts.

So, what enables it to do all this? It requires software or a utility. A Domain Controller is a server—a physical object. Inside it, there must be software or a utility that can manage all these components and properly enable directory services. What does "directory" mean here? Here, we are storing information in a **hierarchical structure**. For example, inside a domain, there is a department. ### **[Section 2: Active Directory Structure, AD DS, & Objects]**

A domain does not merely contain user accounts. Inside a domain, there can be sub-domains, and inside those, further sub-domains. This forms an **inverted hierarchical tree structure**. That is what we refer to as a directory.

Microsoft named this product **Active Directory (AD)**, and its real-world implementation is called **Active Directory Domain Services (AD DS)**. It is used to access services and resources within a domain. It is a software product that runs many services on a Windows Server (the Domain Controller) to manage network resources. A key feature of Active Directory is that **it treats every piece of data as an object**.

---

### **[Section 3: Objects, Authentication, and Remote Servers]**

This means a user is an object, a computer is an object, a printer, application, group, or device—any device is treated as an object. These objects have defined methods and functions. As we know from Object-Oriented Programming, an object is an entity or composite element that we can perform operations with.

When a user attempts to sign in, Active Directory stores their user account information, access levels, and access controls. This becomes essential when connecting to a remote computer or server. While local systems can use a local account database, connecting to a remote server in a Microsoft environment relies on Active Directory.

---

### **[Section 4: Remote Authentication, Trees, and LDAP]**

If there is a remote server on the network—such as a file server—and I want to authenticate against it, I sign in. However, my account information is stored centrally in Active Directory rather than locally. The authentication request goes to Active Directory to verify identity and grant access to the requested server.

Several key terms apply here, such as **trees** and **forests**. A domain can contain multiple sub-domains, forming an inverted tree structure where the root contains a single domain with sub-domains beneath it. This implements the **LDAP (Lightweight Directory Access Protocol)** structure, as Active Directory natively implements LDAP. Arranging domains and sub-domains hierarchically forms a **domain tree**.

---

### **[Section 5: Forests, Trust Relationships, and Domain Trees]**

When multiple domains exist—each with its own tree structure—combining all these domain trees creates a **forest**, just as a physical forest contains many trees. For example, consider two domains: `blue.com` and `red.com`.

A relationship exists between domains called a **trust**. A trust relationship means that if you attempt to log into a domain—say `blue.com`—and it is unavailable at that moment, you can authenticate via `red.com` if a trust relationship exists between them. If trusted, `red.com` allows authentication on behalf of `blue.com`. Trust relationships can exist between two distinct domains or between sibling sub-domains.

---

### **[Section 6: Transitive Trusts & Organizational Units (OUs)]**

Trust relationships can be hierarchical and **transitive**. Transitive means that if `sales.blu.com` trusts `blue.com`, and `blue.com` trusts `p.blu.com`, then `sales.blu.com` automatically trusts `p.blu.com` transitively. This can also be a two-way transitive trust.

Regarding **Organizational Units (OUs)**, an OU exists within a domain to streamline administration by managing department scopes, permissions, and administrative duties across departments such as Marketing, Accounts, Sales, and HR.

Grouping multiple domains and sub-domains creates multiple trees, and combining all these trees forms a forest. The triangles in architecture diagrams represent individual domain trees, which together make up a forest.
