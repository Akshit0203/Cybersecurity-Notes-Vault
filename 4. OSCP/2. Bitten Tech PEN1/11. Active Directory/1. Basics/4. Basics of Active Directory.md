### **[Section 2: Standalone Windows Computers vs. Corporate Network Challenges]**

When you use a personal computer running Microsoft Windows at home—a standalone loan PC connected to the internet—you act as the owner and **Administrator** of that system. In technical terms, holding administrative privileges means you have full control over the local operating system. You can set rules, apply policies, install software, connect to any server, modify account names, update settings, or delete files because you hold the highest local privilege: **Administrator**.

Now consider a corporate environment or enterprise organization with many employees connected over an internal network across industries like medical, finance, or automobile. Multiple departments exist with numerous workstations and users. If everyone operates separate standalone systems, managing them becomes extremely difficult.

Without central management, administrative and security drawbacks arise:

- **Security & Unauthorized Access**: If users log into separate standalone machines without centralized access controls, every user holds local admin rights on their own machine. If another user logs in, they could gain unauthorized access, alter settings, or change passwords. There is no central audit trail or security tracking.
- **Physical Distance & Management Bottlenecks**: In large corporate campuses spanning several kilometers, troubleshooting errors or performing updates requires IT personnel to physically walk to each machine.
- **Unmanaged File Sharing**: Without a central authority, sharing files requires direct peer-to-peer transfers or hosting on unmanaged servers. Anyone with the server's IP address can pull data regardless of authorization policies, as no central judging authority exists to enforce granular access controls.

To resolve these management issues, we group systems together and enforce a unified set of administrative policies across the group. That centralized management framework is **Active Directory**, Microsoft's default identity and management technology.

### **[Section 3: What is Active Directory (AD) & Domain Controllers (DC)?]**

**Active Directory is a structured, hierarchical database** used primarily for centralized **authentication** and **authorization**.

Instead of storing data informally, Active Directory stores information about every entity in the network as an **object**:

- **User Accounts**: Staff and employee accounts, including credentials and contact details.
- **Resources & Devices**: Workstations, member servers, printers, shared drives, and file servers.

Because Active Directory is a database, it requires a dedicated host platform. Microsoft developed specialized server operating systems—such as **Windows Server 2016** and **Windows Server 2019**—equipped with administrative features to manage remote systems. When you install Active Directory Domain Services (AD DS) on a Windows Server, that server becomes a **Domain Controller (DC)**.

Key functions of a Domain Controller:

- **Central Management**: Controls domain policies, user access levels, and security boundaries.
- **Managed Laptops/Workstations**: Enforces organizational rules on domain-joined laptops (e.g., blocking external USB drives, restricting file copying, or blocking unauthorized installer execution).
- **Redundancy & Synchronization**: Organizations can deploy multiple Domain Controllers for replication, synchronization, and high availability, ensuring there is no single point of failure.
- **Cross-Platform Compatibility**: AD supports cross-version interoperability and cross-platform integrations with Unix/Linux environments.

---

### **[Section 4: Active Directory Objects, SIDs, and RIDs]**

Inside Active Directory, every managed entity is treated as an **object** with specific attributes and schemas:

- **User Objects**: Attributes include username, first name, last name, password history, password expiration timestamps, phone numbers, and physical addresses.
- **Resource Objects**: Printers, file shares, and servers hold distinct attributes and unique identifiers.

To locate and reference objects uniquely across the network, Active Directory assigns unique security identifiers:

1. **SID (Security Identifier)**: Identifies the specific domain to which the object belongs. All objects within the same domain share the same domain SID prefix.
2. **RID (Relative Identifier)**: A unique numerical ID assigned to an individual object within that domain.

Combining the **SID + RID** creates a globally unique identifier that distinguishes a specific user or computer object across single or multi-domain environments.

---

### **[Section 5: Logical Structures: Domains, Trees, Forests, and OUs]**

Active Directory organizes components into logical hierarchical structures:

- **Domain**: A logical grouping of objects (users, computers, devices) sharing a common database and security policy under a single namespace (e.g., `org.com`).
- **Domain Tree**: A collection of one or more domains that share a contiguous namespace and transitive trust relationships (e.g., `sales.org.com` beneath `org.com`).
- **Forest**: The highest organizational boundary in Active Directory. A forest is a collection of one or more domain trees that share a common **Global Catalog**, logical structure, directory schema, and enterprise configuration.
- **Organizational Unit (OU)**: A logical container within a domain used to organize objects by department (e.g., HR, Finance, IT, Sales, Marketing).
    - Creating OUs simplifies administration by allowing IT staff to delegate management rights per department.
    - **OUs are the recommended and most efficient level for applying Group Policies**.

---

### **[Section 6: Group Policy Objects (GPOs) & Security Benefits]**

A **Group Policy Object (GPO)** is a collection of centralized configuration rules and settings applied to domain-joined computers and users.

#### **Local GPO vs. Domain GPO:**

- **Local Group Policy**: Applies strictly to an individual, standalone Windows machine that is not joined to a domain.
- **Active Directory (Domain) Group Policy**: Centrally managed on the Domain Controller and automatically enforced across all domain-joined objects.

#### **GPO Nodes:**

Every GPO consists of two main nodes:

1. **User Configuration**: Applies settings based on user object attributes.
2. **Computer Configuration**: Applies settings based on computer object attributes.

#### **Key Security Advantages of GPOs:**

- **Password Security Policies**: Enforces minimum password length (e.g., 10 or 12 characters), character complexity requirements, password history retention, and expiration intervals.
- **Principle of Least Privilege**: Restricts unnecessary user rights, limits administrative access, and controls which applications or scripts users can run.
- **System Management & Health Audits**: Enforces centralized logging, log retention schedules, workstation lockouts, and antivirus deployment policies.

---

### **[Section 7: GPO Processing Order (LSDOU) & Management]**

When a domain-joined computer boots or a user logs in, Group Policies are processed in a strict sequential order known as **LSDOU**:

1. **L - Local**: Local group policies are evaluated first (smallest scope).
2. **S - Site**: Policies assigned to the physical or geographical location/site are applied next.
3. **D - Domain**: Domain-level policies are evaluated third.
4. **OU - Organizational Unit**: OU-level policies are processed last.

Because OU policies are evaluated last in the hierarchy, **higher-precedence OU policies override conflicting lower-level local or site policies**. Administrators configure and link GPOs using the **Group Policy Management Console (GPMC)** on the Domain Controller.
