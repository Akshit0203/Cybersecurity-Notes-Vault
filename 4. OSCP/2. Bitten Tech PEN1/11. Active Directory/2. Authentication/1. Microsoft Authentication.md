### **[Part 2: Security Accounts Manager (SAM) Database]**

The very first term is the **Security Accounts Manager**, or **SAM** for short, which is a database. Inside this database, user authentication data is stored. In authentication, sensitive data refers to user passwords, which in Windows are stored in the SAM file either locally on that machine or within the Active Directory database. Passwords are never stored in cleartext; even in the SAM file, passwords are stored hashed. This is the fundamental meaning of SAM, which we will cover in detail later.

---

### **[Part 3: NTLM (New Technology LAN Manager) Hashing Algorithm & Protocol]**

Next is **NTLM** authentication. The full form of NTLM is **New Technology LAN Manager**. While SAM is a database, NTLM is an authentication mechanism and a type of hashing algorithm. You apply the NTLM hashing algorithm to a password, generate a hash, and store that hash inside the SAM file.

The NTLM authentication protocol consists of two parts: NTLM and LM (LAN Manager). LM was used earlier, whereas NTLM is newer and stronger. Similar to hashing algorithms like SHA or MD5, NTLM is applied to a password to generate a hash, which is stored in the SAM file for password comparison.

---

### **[Part 4: Kerberos Authentication Protocol & Summary]**

After that comes **Kerberos** authentication. While NTLM was used in older implementations, Microsoft nowadays utilizes Kerberos as its primary authentication protocol suite. Kerberos is much stronger and highly efficient, with a significantly evolved mechanism. It serves as a modern authentication protocol, although passwords themselves are still stored in the SAM file to this day.

These three core concepts—SAM, NTLM, and Kerberos—form the foundation of Windows authentication that we will study. That wraps up this summary video, and we will dive into each topic in detail in the upcoming videos. Keep watching, keep learning, and goodbye!
