### **[Section 1: Introduction to LAN Manager (LM) Hash]**

Hello friends. In this video, we are going to talk about the **LAN Manager (LM) Hash**. This is not as important today, but it was used previously for authentication in Windows. You could call it encryption, but it is technically a cryptographic hash algorithm—a true hash function.

Before NTLM was introduced, the LM algorithm was used. It is a one-way hash function used when creating account passwords in Windows. When a password is submitted, the LM algorithm hashes it before storing it.

However, the major drawback is that it is not truly one-way and can be reversed to some extent. To understand why, look at how LM processes passwords:

- First, the input password is padded to **14 bytes**. If the password is shorter than 14 bytes, it is padded with null bytes (`00`) or random data to reach exactly 14 bytes.

---

### **[Section 2: DES Encryption & Security Weaknesses]**

- The 14-byte padded string is split into two separate **7-byte halves**.
- Each 7-byte half is encrypted independently using the **DES (Data Encryption Standard)** algorithm with separate keys.

DES is extremely weak and was famously cracked back in 1999. Because the algorithm encrypts two 7-byte blocks separately rather than treating the 14 bytes as a single unit, the effective keyspace is small. This design flaw makes LM hashes highly susceptible to trivial brute-force attacks.

For these reasons, LM hashing is obsolete and disabled by default in modern Windows operating systems, starting from **Windows Vista** and onwards.

---

### **[Section 3: SAM Database Structure & Transition to NTLM]**

When inspecting the SAM (Security Accounts Manager) file, password entries contain two distinct hash fields:

1. **LM Hash Field**
2. **NTLM Hash Field**

In modern systems, the LM hash field remains completely blank because LM hashing is disabled. It was superseded by the stronger **NTLM** hashing protocol, which is what modern Windows systems use.
