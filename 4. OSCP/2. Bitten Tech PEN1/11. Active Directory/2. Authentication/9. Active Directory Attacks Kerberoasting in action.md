### **[Section 2: Executing Impacket `GetUserSPNs.py` & Dumping Tickets]**

Now, let's construct the full execution command with the required arguments:

1. **Domain Name & User Credentials**: Provide the full domain name (`bittu_tech.local`), followed by a slash `/`, the username (`ansh_b`), and a colon `:` with the password (`Password123`). Syntax: `bittu_tech.local/ansh_b:Password123`.
2. **Domain Controller IP (`-dc-ip`)**: Specify `-dc-ip 192.168.75.16`.
3. **Request Flag (`-request`)**: Append `-request` to instruct the tool to request and dump the Service Tickets (`TGS-REP`) for all identified SPNs.

Upon running the command, it detects an **MSSQL Service** (`SQL Service`).

_Troubleshooting Tip_: If Kerberos clock skew or time synchronization errors occur, ensure your Kali attacking machine's system time matches the Domain Controller's time accurately.

After synchronizing the system time, re-running the command successfully dumps the encrypted Kerberos 5 TGS ticket hash for the SQL service account.

Because the ticket string is lengthy, copy the entire raw ticket hash output from the terminal and save it to a local text file to prepare for offline cracking.

### **[Section 3: Offline Ticket Cracking using Hashcat]**

After saving the dumped ticket hash into a file:

1. **Identifying Hashcat Mode**: Filter Hashcat's help menu for Kerberos / TGS hash modes. The correct mode for Kerberos 5 TGS-REP (`$krb5tgs$`) is **Mode 13100**.
    
2. **Running Hashcat**: Execute Hashcat targeting the ticket file using a wordlist:
    
    ```
    hashcat -m 13100 hash.txt rockyou.txt --force
    ```
    
3. **Handling Formatting Errors**: If Hashcat reports `No hashes loaded` or a separator error, ensure the raw hash was pasted without truncated lines or missing header prefixes (`$krb5tgs$23$*...`).
    
4. **Cracking Speed & Wordlist Exhaustion**: Once GPU/kernel memory initializes, Hashcat evaluates millions of candidate passwords per second. If the target service account password is simple, Hashcat cracks it almost instantaneously. If the wordlist finishes without finding a match (exhausts), it indicates that the service account password is sufficiently complex and absent from the wordlist.

### **[Section 4: Mitigations & Defense Strategies]**

To mitigate and prevent Kerberoasting attacks in Active Directory environments:

1. **Enforce AES Encryption (AES-128 / AES-256)**: By default, legacy Active Directory accounts use RC4 encryption (`RC4_HMAC_MD5`), which uses short keys and is fast to crack offline. Switching service accounts to require AES encryption significantly increases key length and computational complexity, rendering offline brute-force attacks infeasible.
    
2. **Enforce Strong, Long Passphrases (25+ Characters)**: Service account passwords must be long and complex. Passwords with 11–16 characters can be cracked rapidly using GPU acceleration. Enforcing passphrases of **25+ characters** ensures resistance against wordlist attacks. Consider using Group Managed Service Accounts (gMSA), which feature automatically rotated 128-character passwords managed directly by Active Directory.
    
3. **Apply the Principle of Least Privilege**: Avoid configuring service accounts as Domain Admins or Local Administrators. If a service account's password is cracked offline, administrative privileges would allow full domain compromise. Assign service accounts the minimal necessary rights (e.g., standard user context) so that a cracked ticket yields minimal access.
