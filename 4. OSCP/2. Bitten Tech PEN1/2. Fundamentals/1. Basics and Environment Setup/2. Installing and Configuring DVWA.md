## What is DVWA?

**Damn Vulnerable Web Application (DVWA)** is a PHP-based web application that is **intentionally vulnerable**. It has built-in bugs deliberately placed so you can test whether you can identify and exploit them.

- Contains most of the famous web application attacks (Brute Force, SQL Injection, XSS, etc.)
- You can configure and test these attacks inside your own system environment
- Not just an environment — it is a full application package for practicing **web application hacking skills**

## Using DVWA

After logging in, the DVWA interface opens. Various attacks are listed on the left sidebar (Brute Force, SQL Injection, etc.).

![](attachments/Pasted%20image%2020260710195516.png)

Clicking any attack (e.g., "Brute Force") opens a configuration screen where you can test the attack.

![](attachments/Pasted%20image%2020260710195634.png)

### View Source — Learning Feature

At the bottom-right of each attack page there is a **"View Source"** option. This shows you **exactly how the PHP backend has been coded**. If you get stuck or can't execute an attack, checking the source code helps you understand how to construct your attack. Having access to backend source code makes designing attacks much easier — an excellent learning feature.

### Security Levels

Under **"DVWA Security"**, there are **four levels**:

| Level          | Description                                                    |
| -------------- | -------------------------------------------------------------- |
| **Low**        | Easiest — start here                                           |
| **Medium**     | Intermediate challenge                                         |
| **High**       | Maximum realistic difficulty                                   |
| **Impossible** | Cannot be hacked — demonstrates secure coding                  |

> [!TIP]
> **Start with "Low"**, then progress to Medium, then High. Don't jump to High out of excitement — you won't be able to do it and it will only demotivate you. Each attack has its own configurations and coding per level.

## Important Safety Notes

> [!WARNING]
> - All testing runs on **localhost** — you own the environment, so there is no issue
> - Performing these attacks in the real world is wrong — **never do so unless you have explicit permission**
> - Always use **sandbox environments** like DVWA unless you have professional authorization

### Network Mode for VMs

Because DVWA is intentionally vulnerable, if you run it inside a VM (VMware / VirtualBox):

- ✅ **Use NAT mode** — external internet cannot access your open ports
- ✅ Host-only or local network setup are also safe
- ❌ **Never use Bridged mode** — exposes your vulnerable app to the network
- ❌ Avoid setting up port forwarding
