# `/etc/passwd` vs `/etc/shadow`

> Both files contain user account information in Linux, but they serve very different security purposes.

---

## 1. `/etc/passwd` — User Account Database

The **general user account information** file. Readable by many programs and users.

```bash
cat /etc/passwd
```

### Entry Format

```
akshit:x:1000:1000:Akshit:/home/akshit:/bin/bash
  │     │  │    │     │        │           │
  │     │  │    │     │        │           └─ Login shell
  │     │  │    │     │        └───────────── Home directory
  │     │  │    │     └────────────────────── GECOS (user description)
  │     │  │    └──────────────────────────── Primary GID
  │     │  └───────────────────────────────── UID
  │     └──────────────────────────────────── Password placeholder ("x" = look in /etc/shadow)
  └────────────────────────────────────────── Username
```

| Field | Meaning |
| ----- | ------- |
| Username | Account name |
| `x` | Password is stored in `/etc/shadow` |
| UID | User ID |
| GID | Primary group ID |
| GECOS | User information / description |
| Home | User's home directory |
| Shell | Default login shell |

---

## 2. `/etc/shadow` — Password Authentication Data

Contains **sensitive password hashes and aging information**. Restricted to root.

```bash
sudo cat /etc/shadow
```

### Entry Format

```
akshit:$y$j9T$...:20500:0:99999:7:::
```

| Field | Meaning |
| ----- | ------- |
| Username | Account name |
| Password hash | Hashed password (e.g., `$y$j9T$...`) — **not** plaintext |
| Last changed | Days since epoch when password was last changed |
| Min age | Minimum days before password can be changed |
| Max age | Maximum days before password must be changed |
| Warning period | Days before expiry to warn the user |
| Inactive period | Days after expiry before account is disabled |
| Expiration | Account expiration date |

---

## 3. Why Are They Separate?

```
/etc/passwd                         /etc/shadow
     │                                   │
     ▼                                   ▼
General account info               Password hashes + aging data
     │                                   │
     ▼                                   ▼
Generally world-readable           Restricted to root only
```

- `/etc/passwd` **must** be readable by many programs (e.g., resolving `"What UID belongs to akshit?"`)
- Historically, password hashes **were stored in `/etc/passwd`** — this was a security risk
- Modern Linux moved hashes to `/etc/shadow` to prevent ordinary users from reading them

---

## 4. Why Does `/etc/passwd` Contain `x`?

```
akshit:x:1000:1000:...
       │
       └── "x" means: "The real password hash is in /etc/shadow"
```

This is a legacy placeholder from when hashes used to live directly in `/etc/passwd`.

---

## 5. How Authentication Works

```
Your password
      │
      ▼
Password hashing algorithm
      │
      ▼
Generated hash
      │
      ▼
Compare with stored hash in /etc/shadow
      │
    Match?
   /     \
 Yes      No
  ▼        ▼
Login    Reject
```

Linux does **not** compare plaintext passwords — it hashes your input and compares hashes. The actual authentication stack involves PAM and other components.

---

## 6. Cybersecurity Significance

| File Obtained | Value |
| ------------- | ----- |
| `/etc/passwd` | **User enumeration** — usernames, UIDs, shells, home dirs |
| `/etc/shadow` | **Critical** — password hashes for offline cracking |

### Relevant Tools for Penetration Testing

| Tool | Purpose |
| ---- | ------- |
| `unshadow` | Combine passwd + shadow for cracking |
| `john` (John the Ripper) | Offline password hash cracker |
| `hashcat` | GPU-accelerated hash cracker |

---

## 7. Not Every Account is a Human

```bash
cat /etc/passwd
```

You'll see accounts like: `root`, `daemon`, `bin`, `sys`, `www-data`, `backup`, `games`, etc.

- Many are **system/service accounts**, not real users
- `www-data` is commonly associated with web services
- This makes `/etc/passwd` very useful during **Linux enumeration**

---

## 8. The Interview Answer

> **Q: What's the difference between `/etc/passwd` and `/etc/shadow`?**
>
> **A:** "`/etc/passwd` contains general information about Linux user accounts, such as usernames, UIDs, GIDs, home directories, and login shells. `/etc/shadow` contains sensitive password authentication information, primarily password hashes and password-aging data, and is normally restricted to privileged users. The `x` in `/etc/passwd` indicates that the password hash is stored in `/etc/shadow`."
