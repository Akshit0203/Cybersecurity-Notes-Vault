# Hello World in Bash

---

## The Script

```bash
#!/bin/bash

echo "Hello world"
```

---

## The Shebang (`#!`)

- The **first line** of every script should be the **shebang** — a combination of `#` (hash) and `!` (bang).
- It tells the shell **which interpreter** to use for the script.
- Format: `#!/path/to/interpreter`

| Script Type | Shebang |
|-------------|---------|
| Bash | `#!/bin/bash` |
| Python | `#!/usr/bin/python3` |

> When you run a script with `./`, the shell reads the shebang on line 1 to determine the interpreter. Without it, the shell may guess (and guess wrong).

### Proof — Wrong Shebang Breaks the Script

If you set `#!/usr/bin/python` on a Bash script:

```
./hello_world
# /usr/bin/python: bad interpreter: No such file or directory
```

The shell tried Python (because the shebang said so), and `echo` is not valid Python — so it failed.

---

## Running the Script

### Method 1 — Using the `bash` Command

No execute permission needed; you explicitly tell the shell to use `bash`:

```bash
└─$ bash new.sh
Hello world
```

### Method 2 — Using `./` (Dot-Slash)

Requires execute permission on the file:

```bash
└─$ ./new.sh
zsh: permission denied: ./new.sh
```

> `./` means "run this file from the current directory." It relies on the shebang to find the interpreter.

---

## File Permissions & `chmod`

### Check Current Permissions

```bash
└─$ ls -la
total 12
drwxrwxr-x  2 kali kali 4096 Aug 16 04:54 .
drwx------ 23 kali kali 4096 Aug 16 04:40 ..
-rw-rw-r--  1 kali kali   31 Aug 16 04:54 new.sh
```

No `x` (execute) bit is set — the file cannot be run with `./`.

### Add Execute Permission for Everyone (`+x`)

```bash
└─$ chmod +x new.sh

└─$ ls -la
-rwxrwxr-x  1 kali kali   31 Aug 16 04:54 new.sh
```

> ⚠️ This gives execute permission to **user, group, and others**. Usually too broad.

### Remove Execute Permission (`-x`)

```bash
└─$ chmod -x new.sh

└─$ ls -la
-rw-rw-r--  1 kali kali   31 Aug 16 04:54 new.sh
```

### Add Execute Permission for Owner Only (`u+x`) — Recommended

```bash
└─$ chmod u+x new.sh

└─$ ls -la
-rwxrw-r--  1 kali kali   31 Aug 16 04:54 new.sh
```

| Symbol | Meaning |
|--------|---------|
| `u` | Owner (user) |
| `g` | Group |
| `o` | Others |
| `+x` | Add execute |
| `-x` | Remove execute |

### Now It Runs

```bash
└─$ ./new.sh
Hello world
```

## Extension Is Optional

- The `.sh` extension is **not required** — it's just a convention for readability.
- A file named `hello_world` (no extension) works identically, because the **shebang** determines the interpreter, not the file extension.

> **Best practice:** Always include the shebang line. It makes the script self-documenting and portable.
