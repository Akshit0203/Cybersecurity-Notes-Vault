```
#!/bin/bash

read -p "Enter first number:" a
read -p "Enter second number:" b

read -p "Enter operation (+,-,x,/):" op 

case $op in 

	+)
		echo $((a+b))
		;;

	-)
		echo $((a-b))
		;;

	x)
		echo $((a*b))
		;;

	/)
		echo $((a/b))
		;;

	*)
		echo "Operation not permitted"
		;;

esac
```

**[Part 1: Introduction to Case Statements in Bash]**

"Hello friends. In this video, we will learn about **case statements**. As you might have studied, there is a switch-case concept in programming. A switch-case means if you need to check a value or evaluate an expression, what value does it yield? Depending upon that value, you execute that specific set of commands, which you can also do using `if` statements.

But sometimes, what is the problem? In `if-else` blocks, you must have noticed that you apply many `elif` statements, set up numerous conditions, perform string comparisons, and then in integer comparisons, you have to apply `equal to` and logical operators, requiring a lot of setup. That sometimes is not very good for code readability and maintainability—meaning when you have a vast number of comparisons and options where you need to build menu-driven programs for the user.

You need to take parameters from the user and then ask them what operation to perform with all of them. There are many operations—for instance, if you want to build a calculator, whether to perform addition or multiplication is something the user specifies themselves."

---

**[Part 2: Why Case Statements over** **elif** **Ladders]**

"So if you repeatedly write `elif`, `elif` with `==` to compare strings and then `echo` inside them, that is not easy to read and doesn't look clean either. Your code should be systematic, concise, and simple—only then does it make sense.

For these types of applications, when you need to create an options-based or menu-driven script, you can use **case statements**, which are much more readable and give you a very simple structure if you need to debug your code. Your code becomes very clean and simple."

---

**[Part 3: Syntax of Case Statements (****case ... in** **and** **esac****)]**

"So I will show you its syntax here. How do you write it? There is a `case` statement here—there is no keyword named 'switch' in Bash. So write `case` first, followed by your expression. You replace `EXPRESSION` with whatever you want to evaluate—you can also pass a simple variable here. After that comes the keyword `in`. Keywords get highlighted in purple here.

Then below, indent and write `pattern1)` followed by a closing parenthesis. Then indent again and write your commands. Whatever statements you write here will execute. And when ending a pattern block, you must end it with **two semicolons** `;;`. That completes matching one pattern.

Now you can have many patterns like this, depending on which pattern your evaluated expression matches—whether it's value 1, 2, 3, or 4. So there are a number of patterns or values you can input, specifying that if it matches this value, run these statements; if it matches another value, run those statements.

And if it doesn't match any pattern, there is a **default case**—which you might have studied—represented by the asterisk symbol `*)`, followed by commands, ending with `;;` as well.

So this is the syntax of `case`. What do you replace here? Replace `EXPRESSION` with your variable, `commands` with your execution code, and `patterns` with your expected values.

Some key things to note: `case` starts with the `case` keyword, and when ending the entire block—just like you ended `if` with `fi`—you reverse the word `case` to **esac**. So every case block stays enclosed between `case` and `esac`.

---

**[Part 4: Multi-Pattern Matching with Pipes (****|****)]**

"Inside these patterns, you can also use a pipe symbol `|` to club multiple patterns together at once. Sometimes, users get confused between uppercase and lowercase, and Bash scripting is case-sensitive.

So if they enter something starting with an uppercase letter or in all lowercase, you sometimes need to club different variations of the same word under a single condition block. You can club them like `pattern1 | pattern2)`. And remember that every set of statements inside a pattern block must end with double semicolons `;;`."

---

**[Part 5: Building a Shell Calculator Script Example]**

"What use case have I taken here? I have taken two numbers as input from the user. You can use `read -p` to give a prompt string directly for the user indicating what to enter, and whatever they type gets stored in that variable—no need to use a separate `echo` statement.

After that, ask the user with `read -p` which operation to perform: _'Enter operation'_. Tell the user which symbols to enter—like `+` for addition, `-` for subtraction, `x` for multiplication, and `/` for division. Store whatever they enter in a variable named `op`.

Now `op` can contain any of those four operation symbols. You pass `$op` into `case $op in`. Now it checks the value of `$op`:

- If `$op` is `+`, it runs the addition commands. I want to print/echo addition. For addition, evaluate it directly inside arithmetic expansion `$((a + b))`.
- If `-` comes, evaluate `$((a - b))`.
- For multiplication, notice one important thing: you shouldn't use `*` as the multiplication symbol here because `*` is also the symbol for the default case! So it's better to use `x` for multiplication to distinguish it properly.
- For division `/`, evaluate `$((a / b))`."

---

**[Part 6: Default Case (*********) & Execution Test]**

"For the default case `*)`—similar to `else` in `if` statements—specify what to do if nothing matches. Print something like `'Operation not permitted'`.

Now let's run it: `./case.sh 10 20`.

- If I enter `+` for the operation, it gives `30`—matching the first pattern.
- If I want to multiply, I enter `x`, and it gives `200`.
- If I enter division `/` on `10` and `20`, it outputs `0` because of integer division. To get precise decimal points, you can pipe the expression to the `bc` (Basic Calculator) command. If I enter `300` and `6` with `/`, it correctly outputs `50`.
- If an invalid operation symbol is entered, it triggers the default case `*)` and prints `'Operation not permitted'`."

---

**[Part 7: Multi-Case Normalization (Handling Uppercase/Lowercase)]**

"As I mentioned, you can use pipes `|` for multi-pattern matching. For example, if you ask the user to enter a word like `Windows`, they might type `windows`, `Windows`, or `WINDOWS`.

Piping them together like `windows | Windows | WINDOWS)` ensures all casing variations trigger the same block without throwing syntax errors."
