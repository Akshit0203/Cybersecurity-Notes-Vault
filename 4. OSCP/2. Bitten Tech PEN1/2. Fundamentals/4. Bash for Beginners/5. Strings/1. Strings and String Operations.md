### What does `(-11)` mean?

In Bash substring expansion, a **negative offset** means:

> Start counting from the **end of the string**.

Your string is:

```
welcome to programming
```

The last 11 characters are:

```
programming
```

So:

```
${str1:(-11)}
```

means:

> Start **11 characters from the end** and take everything from there.

Therefore:

```
programming
```

### Why are the parentheses used?

You could write:

```
${str1:(-11)}
```

The parentheses make it unambiguous that `-11` is a **negative offset**.

This is especially useful because Bash has other meanings for `:-`.

**[Part 1: Introduction to Strings in Bash]**

Hello friends. In this video, we will talk about strings1. We have seen strings before, but let me explain them in a little more detail in this video1. There are various string operations—you can extract substrings, search within strings, and perform many other tasks just as you would in other programming languages1.

I have already explained how to declare a string1. Anything written inside double quotes or single quotes is called a sequence of characters, which we refer to as a string1. Here, a string does not necessarily have to be letters like `abc` or uppercase `ABC`1. Even numbers like `1234` can be treated as a string1. If I assign `1234` to a variable without quotes, it is treated as an integer1. But if I enclose it inside single quotes, it becomes a string1. So anything written inside quotes is treated as a string—a set or group of characters1.

---

**[Part 2: String Comparison & POSIX Double-Quoting]**

There are many string comparison operators to check whether two strings are equal or not, or if one is less than or greater than another2.

Let's declare `str1="Welcome to Programming"` and `str2="Programming"`2. To check if both strings are equal, we write an `if` statement using the single equal sign `=` comparison operator: `if [ $str1 = $str2 ]; then echo "Strings are equal"; fi`2.

If you run this without quotes around string variables containing spaces, Bash throws a syntax error: `too many arguments`23. When using POSIX single square brackets `[ ]` or the `test` command, spaces inside a string cause Bash to split the string into multiple arguments3. To prevent splitting and preserve whitespace, always wrap string variable references in double quotes: `"$str1"`3. Wrapping variables in double quotes is the recommended standard practice for string operations3. Once double quotes are added (`if [ "$str1" = "$str2" ]`), the syntax error disappears3.

---

**[Part 3: Lexicographical Comparisons & Workarounds]**

To perform less-than (`<`) or greater-than (`>`) comparisons inside single square brackets `[ ]`, you must escape the operator with a backslash (`\<` or `\>`); otherwise, Bash treats `<` as file redirection and throws a `No such file or directory` error4.

When comparing strings with `\<` or `\>`, Bash compares them in **lexicographical order** (ASCII/alphabetical order), NOT by character length5. For example, if `str1="P"` and `str2="Q"`, comparing `"$str1" \< "$str2"` evaluates to true because `P` precedes `Q` in ASCII order5.

For Not Equal To, use the `!=` operator6. Because operators like `<=`, `>=`, `-le`, or `-ge` do not work directly with string characters, you can construct a logical workaround using `!` (NOT) combined with `\>` to test for Less Than or Equal To6. Additionally, while double equals `==` works in Bash, single equals `=` is the official POSIX standard6.

---

**[Part 4: Checking Empty and Non-Empty Strings (****-z** **and** **-n****)]**

To test whether a string is empty or has zero length, Bash provides specific flag switches7:

- **-z** **(Zero Length / Empty Check)**: Checks if a string is empty7. `if [ -z "$str2" ]; then echo "String is empty"; fi`7. If `str2=""`, this returns true7.
- **-n** **(Non-Zero Length / Non-Empty Check)**: Checks if a string is non-empty8. `if [ -n "$str1" ]; then echo "String is non-empty"; fi`8. If `str1` contains characters, this returns true8.

---

**[Part 5: Methods to Find String Length]**

There are multiple methods to calculate the length of a string in Bash8:

1. **Parameter Expansion (****${#STR}****)**: The cleanest and recommended native method is `${#str1}`8more_horiz. For `str1="Programming"`, `${#str1}` returns `11`9.
2. **expr length** **Command**: Using command substitution with `expr length "$str1"` also returns `11`9.
3. **Piping** **echo** **to** **wc -c**: Using `echo "$str1" | wc -c` counts characters11. However, because `echo` automatically appends a trailing newline (`\n`), `wc -c` returns `12` instead of `11`11. To suppress the trailing newline and get the exact count, pass the `-n` flag: `echo -n "$str1" | wc -c`1011.

---

**[Part 6: Substring Extraction (Slicing)]**

To extract a substring from a string variable (such as `str1="Welcome to Programming"`), Bash uses parameter expansion slicing syntax1012:

$$\text{\$\{VARIABLE:OFFSET:LENGTH\}}$$12

- **VARIABLE**: The string variable name12.
- **OFFSET**: The zero-indexed starting position1213.
- **LENGTH**: (Optional) The number of characters to extract1213. If omitted, it extracts from the offset to the end of the string13.

**Examples:**

- `${str1:11}` extracts from index 11 to the end, returning `Programming`13.
- `${str1:11:1}` extracts 1 character starting at index 11, returning `P`13.
- **Negative Offset (From End)**: Wrapping a negative offset in parentheses, such as `${str1:(-11)}`, counts 11 characters backward from the end, returning `Programming`14.

---

**[Part 7: Concatenation and Loop Appending]**

String **concatenation** in Bash requires no special operators or plus signs—simply place variables side by side1415: `echo "$str1 $str2"`1415.

You can also construct or accumulate strings inside a loop using the append operator (`+=`)16:

```
str4=""
for i in 1 2 3 4 5; do
    str4+="$i"
done
echo "$str4"
```

This loop initializes `str4` as an empty string, iterates through `1 2 3 4 5`, and appends each element to produce `12345`1617.

That covers the essential fundamentals of string handling and manipulation in Bash scripting17!
