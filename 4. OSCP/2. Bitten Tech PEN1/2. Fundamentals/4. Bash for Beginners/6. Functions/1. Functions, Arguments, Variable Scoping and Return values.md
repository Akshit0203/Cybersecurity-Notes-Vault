# Functions, Arguments, Variable Scoping, and Return Values

> Bash functions let you group reusable commands under a single name. This note covers declaration syntax, argument passing, local vs global variables, exit status return values, and overriding built-in commands.

---

## Declaring Functions

### Syntax Option 1 — Parentheses Style

```bash
function_name() {
	commands
}
```

### Syntax Option 2 — `function` Keyword

```bash
function function_name {
	commands
}
```

> Both are functionally identical. When using the `function` keyword, parentheses are optional. Semicolons are only needed if writing the entire function on a single line.

### Example — Simple Function

```bash
#!/bin/bash

hello() {
	echo "Hello"
}

hello
```

```
Hello
```

> **Calling a function:** Just write the function name — **no parentheses** when calling (unlike most other languages).

---

## Passing Arguments to Functions

Arguments are passed by **separating them with spaces** after the function name (just like command-line arguments):

```bash
hello "akshit" "test"
```

### Accessing Arguments Inside the Function

| Parameter | Description                                       |
| --------- | ------------------------------------------------- |
| `$1`      | First argument                                    |
| `$2`      | Second argument                                   |
| `$n`      | *n*-th argument                                   |
| `$#`      | Total number of arguments                         |
| `$@`      | All arguments as separate words (array-like)      |
| `$*`      | All arguments as a single string                  |
| `$0`      | Script/function name                              |

### Example — Single Argument

```bash
#!/bin/bash

hello() {
	echo "Hello $1"
}

hello "akshit"
```

```
Hello akshit
```

### Example — Multiple Arguments with `$#` and `$@`

```bash
#!/bin/bash

hello() {
	echo "Hello $1 $2"
	echo $#
	echo $@
}

hello "akshit" "test"
```

```
Hello akshit test
2
akshit test
```

## Variable Scoping — Local vs Global

### Default Behavior: Global

Variables assigned inside a function **without** the `local` keyword are **global** — they persist and are accessible after the function exits.

```bash
#!/bin/bash

v1=10

add() {
	v2=15
	echo "adding v1 and v2 = $((v1+v2))"
}

add
```

```
adding v1 and v2 = 25
```

> `v2=15` is global. After `add` runs, `v2` is accessible everywhere.

### The `local` Keyword

Declaring a variable with `local` restricts its scope **strictly to the function**. It shadows any global variable of the same name.

```bash
#!/bin/bash

v1=10

add() {
	local v1=5
	v2=15
	echo "adding v1 and v2 = $((v1+v2))"
}

add
```

```
adding v1 and v2 = 20
```

> Inside `add()`, `v1` is locally `5`, so `5 + 15 = 20`. The global `v1` remains `10`.

### Example — Demonstrating Scope Persistence

```bash
#!/bin/bash

v1=10

add() {
	local v1=5
	v2=15
	echo "adding v1 and v2 = $((v1+v2))"
}

add

echo "v1=$v1 and v2=$v2"
```

```
adding v1 and v2 = 20
v1=10 and v2=15
```

> After `add()` returns: `v1` is still `10` (local didn't modify global), but `v2` is `15` (no `local` keyword → global).

### Example — Before and After Function Call

```bash
#!/bin/bash

v1=10
v2=30

add() {
	local v1=5
	v2=15
	echo "adding v1 and v2 = $((v1+v2))"
}

echo "v1=$v1 and v2=$v2"

add

echo "v1=$v1 and v2=$v2"
```

```
v1=10 and v2=30
adding v1 and v2 = 20
v1=10 and v2=15
```

> Before: `v2=30`. After `add()`: `v2` changed to `15` globally (no `local`). `v1` stayed `10` (protected by `local`).

## Return Values and Exit Status (`$?`)

Bash functions do **not** return raw data values like other languages. Instead, they return an **exit status** — the exit code of the **last command** executed in the function.

| Exit Status | Meaning              |
| ----------- | -------------------- |
| `0`         | Success              |
| `1–255`     | Error/failure code   |

### Example — Checking Exit Status

```bash
#!/bin/bash

v1=10
v2=30

add() {
	local v1=5
	v2=15
	echo "adding v1 and v2 = $((v1+v2))"
}

echo "v1=$v1 and v2=$v2"

add
echo "Exit status of add is $?"

echo "v1=$v1 and v2=$v2"
```

```
v1=10 and v2=30
adding v1 and v2 = 20
Exit status of add is 0
v1=10 and v2=15
```

> `$?` must be checked **immediately** after the function call — any subsequent command overwrites it.

## Overriding Built-in Commands (`builtin` Keyword)

Bash lets you create a function with the **same name** as a built-in command (like `echo`), effectively overriding it.

### The Problem: Infinite Recursion

If you define an `echo()` function and call `echo` inside it, Bash calls **your function** again (not the built-in), causing infinite recursion:

```
echo() → echo() → echo() → echo() → ... (recursion error)
```

### The Solution: `builtin` Keyword

The `builtin` keyword tells Bash to use the **original built-in command** instead of your custom function:

```bash
builtin echo "text"    # Calls Bash's native echo, not your function
```

### Example — Custom Logging `echo` with Timestamps

```bash
#!/bin/bash

echo() {
	builtin echo -n `date +"[%Y-%m-%d %H:%M:%S]"` ": "
	builtin echo $1
}

echo "modified echo completed"
```

```
[2026-09-15 13:26:53] : modified echo completed
```

**How it works:**

1. `builtin echo -n` — prints the timestamp **without** a trailing newline (`-n` flag).
2. `` `date +"[%Y-%m-%d %H:%M:%S]"` `` — command substitution runs `date` and inserts the formatted timestamp.
3. `builtin echo $1` — prints the first argument on the same line, then adds a newline.

**Result:** Every `echo` call automatically prepends a timestamp — useful for **logging, automation, and debugging**.

### Modern Improvement

Prefer `$(...)` over backticks for command substitution, and use `"$@"` to handle all arguments (not just `$1`):

```bash
echo() {
	builtin echo -n "$(date +"[%Y-%m-%d %H:%M:%S]") : "
	builtin echo "$@"
}
```

## Quick Reference

| Concept                | Syntax / Command                          |
| ---------------------- | ----------------------------------------- |
| Declare function       | `name() { ... }` or `function name { ... }` |
| Call function           | `name arg1 arg2`                          |
| Access argument         | `$1`, `$2`, `$@`, `$#`                   |
| Local variable          | `local var=value`                         |
| Check exit status       | `$?`                                      |
| Override built-in       | Define `cmd() { builtin cmd ...; }`       |
| Prevent recursion       | Use `builtin` keyword inside overrides    |
