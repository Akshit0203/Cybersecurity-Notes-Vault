# File Operations and Aliases

---

## 1. Reading a File into a Variable

Sample file used throughout — [colors.txt](https://github.com/imsky/wordlists/blob/master/adjectives/colors.txt) (one colour per line: amber, ash, … yellow).

### Backtick Method

```bash
#!/bin/bash
file_contents=`cat colors.txt`
echo $file_contents
```

**Output** — all words on a single line (newlines stripped because the variable is **unquoted**):

```
amber ash asphalt auburn avocado aquamarine azure …
```

### Command Substitution (Quoted)

```bash
#!/bin/bash
file_contents=$(cat colors.txt)
echo "$file_contents"
```

**Output** — newlines preserved because `"$file_contents"` is **double-quoted**:

```
amber
ash
asphalt
…
yellow
```

> **Key Rule:** Always wrap multi-line variables in double quotes (`echo "$var"`) to preserve whitespace and newlines.

### Input Redirection Shorthand

```bash
file_contents=$(< colors.txt)
echo "$file_contents"
```

Equivalent to `$(cat colors.txt)` but avoids spawning a sub-process for `cat`.

## 2. Reading a File Line by Line

### Basic `while read` Loop

```bash
#!/bin/bash

while read line
do
	echo $line
done < colors.txt
```

**How it works:**

```
colors.txt
    │  < input redirection
    ↓
while read line
    │
    ├── line = "amber"   → echo
    ├── line = "ash"     → echo
    ├── …
    └── line = "yellow"  → echo
    │
    ↓
EOF → read fails → loop ends
```

| Component | Role |
|---|---|
| `read` | Bash built-in command — reads one line from stdin |
| `line` | Variable name (arbitrary — could be `x`, `color`, etc.) |
| `< colors.txt` | Input redirection — feeds the file as stdin to the loop |

When `read` reaches **end-of-file**, it returns non-zero and the `while` loop exits.

### The `-r` Flag (Raw Input)

```bash
#!/bin/bash

while read -r line
do
	echo $line
done < colors.txt
```

`-r` tells `read` **not to treat backslashes as escape characters**, preserving the literal text. Always use `-r` for safety.

### Safer Best Practice

```bash
while IFS= read -r line
do
    echo "$line"
done < colors.txt
```

`IFS=` additionally preserves leading/trailing whitespace in each line.

## 3. Accepting a Filename as an Argument (`$1`)

```bash
#!/bin/bash

file=$1

while read -r line
do
	echo $line
done < $file
```

```
$ ./code.sh colors.txt
amber
ash
…
yellow
```

`$1` is the **first positional argument** passed to the script.

## 4. File and Directory Test Operators

Before reading, verify the path exists:

```bash
#!/bin/bash

file=$1

if [ -f $file ]
then
	echo "File exists"
else
	echo "file does not exist"
	exit 0
fi

while read -r line
do
	echo $line
done < $file
```

```
$ ./code.sh color.txt
file does not exist

$ ./code.sh colors.txt
File exists
amber
ash
…
```

### Test Operator Reference

| Operator | True When… |
|---|---|
| `-e PATH` | Path exists (file, directory, device — anything) |
| `-f PATH` | Path is a **regular file** |
| `-d PATH` | Path is a **directory** |

### Checking Both File and Directory

```bash
#!/bin/bash

file=$1
dir=$2

if [ -f $file ]
then
	echo "File exists"
else
	echo "file does not exist"
	exit 0
fi

if [ -d $dir ]
then
	echo "Directory exists"
else
	echo "Directory does not exist"
	exit 0
fi
```

```
$ ./code.sh colors.txt test
File exists
Directory does not exist
```

## 5. Writing and Appending to Files

### Overwrite with `>`

```bash
echo "papaya" > vegetables.txt
cat vegetables.txt
```

```
papaya
```

Creates a new file or **completely replaces** existing content.

### Interactive Input with `read -p`

```bash
read -p "input some vegetables to write: " veg
echo "$veg" > vegetables.txt
cat vegetables.txt
```

```
input some vegetables to write: onion
onion
```

**`read -p "prompt" variable`** breakdown:

| Part | Role |
|---|---|
| `read` | Bash built-in — reads user input |
| `-p "…"` | Displays a prompt message before waiting |
| `veg` | Variable where the typed input is stored |

### Append with `>>`

```bash
read -p "input some vegetables to write: " veg
echo "$veg" >> vegetables.txt
cat vegetables.txt
```

```
input some vegetables to write: papaya
onion
onoin
papaya
```

`>>` appends to the end of the file **without deleting** existing content.

### Display AND Append with `tee -a`

Standard redirection (`>>`/`>`) suppresses terminal output. To **both** print to the screen and write to a file:

```bash
read -p "input some vegetables to write: " veg
echo "$veg" | tee -a vegetables.txt
```

| Flag | Meaning |
|---|---|
| `tee` | Reads stdin, writes to both stdout and a file |
| `-a` | Append mode (without it, `tee` overwrites) |

## 7. Checking Variable States (`-v` vs `-z`)

### Common Mistake — Spaces in Assignment

```bash
a = 100   # ❌ WRONG — Bash interprets this as a command
a=100     # ✅ CORRECT
```

### `-v` — Is the Variable Set?

Pass the variable **name** (without `$`):

```bash
a=100

if [ -v a ]; then echo "true"; fi    # ✅ true — variable 'a' is set
if [ -v b ]; then echo "true"; fi    # (nothing) — 'b' is not defined
```

> **Gotcha:** `[ -v $a ]` expands `$a` first → becomes `[ -v 100 ]` → not what you want.

### `-z` — Is the Value Empty?

Pass the **value** (with `$`, in quotes):

```bash
if [ -z "$b" ]; then echo "true"; fi   # ✅ true — b is unset/empty
```

> `-z` tests whether a string is **zero length**.

### The Important Distinction

```
Variable NAME       Variable VALUE
     a                  100
     ↑                   ↑
    a                   $a
```

| Command | What It Actually Checks |
|---|---|
| `[ -v a ]` | Does variable `a` exist/is set? ✅ |
| `[ -v $a ]` | Expands `$a` first → checks variable named `100` ❌ |
| `[ -v b ]` | Does variable `b` exist/is set? |
| `[ -z b ]` | Is literal string `b` empty? (no — 1 char) ❌ |
| `[ -z {b} ]` | Is literal string `{b}` empty? (no — 3 chars) ❌ |
| `[ -z "$b" ]` | Is the **value** of `b` empty? ✅ |

> **Unset** = never declared. **Null** = declared but holds `""`.

## 8. Aliases

Aliases map long commands to short custom shortcuts.

### Create an Alias

```bash
alias datet="date +%H:%M:%S"
```

```
$ datet
05:29:07
```

### List All Active Aliases

```bash
$ alias
datet='date +%H:%M:%S'
diff='diff --color=auto'
grep='grep --color=auto'
ll='ls -l'
ls='ls --color=auto'
…
```

### Remove an Alias

```bash
unalias datet
```

### Make Aliases Persistent

Add `alias` commands to `~/.bashrc` or `~/.bash_profile` so they survive shell restarts.

> **Remember:** No spaces around `=` in alias definitions — same rule as variable assignment.
