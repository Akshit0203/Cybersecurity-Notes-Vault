# Introduction to Office Macros

---

## Overview

Client-side attacks bypass the need for **direct routable access** to a target machine. Instead of exploiting a service (SSH, SMB, HTTP), you deliver a payload to a **human user (the client)** who executes it on their machine, granting you access.

> [!IMPORTANT]
> 90% of all cyberattacks start with some form of **social engineering**. Client-side attacks are a core OSCP topic with a dedicated exam section.

---

## Client-Side Attacks — Core Concepts

### Why Client-Side?

- Modern security solutions make purely technical initial access (direct exploitation) extremely difficult.
- The **"Assume Breach"** model is common, but when you must obtain initial access yourself, client-side attacks are the primary vector.
- You target the **person using the machine**, not the machine's exposed services.

### Delivery Does Not Require Routable Access

- Unlike exploiting SQL Injection, SSRF, or SMB CVEs — which require a **network route** to the target — client-side payloads are delivered **out-of-band**.
- Delivery methods: email attachments, WhatsApp messages, hosted file links, etc.
- The target machine can be on an **internal non-routable network** and the attack still works.
- A routable path from their network to yours is only needed if you want a **reverse shell callback**.

### CVSS Context

- In CVSS metrics, client-side attacks are scored with **"User Interaction: Required"** — the victim must download *and* execute the payload (minimum two-step interaction).

## Prerequisites — Know Your Target

Before crafting a client-side attack, you must profile the target:

| Information Needed       | Why It Matters                                                        |
| ------------------------ | --------------------------------------------------------------------- |
| **Operating System**     | Determines payload type (Windows vs Linux vs macOS)                   |
| **Browser**              | Browser-based exploits differ per browser (Chrome vs Firefox)         |
| **Office Suite Version** | Macro support and behavior varies across versions                     |
| **Role / Department**    | Informs the pretext (HR, Sales, Engineering, etc.)                    |

### Reconnaissance Methods

- **Shodan** — find IPs, banners, browser fingerprints
- **Social media & job postings** — reveal internal tech stack (OS, platforms, tools)
- **Active social engineering** — call HR, marketing, or sales reps to extract info
- **Browser fingerprinting** — identify client browser and OS details

## Social Engineering & Pretexts

A **pretext** is a fabricated scenario that feels genuine and compels the victim to perform the desired action (click, download, enable, execute).

### Pretext Examples

| Target          | Pretext                                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------- |
| **HR Manager**  | Send a resume; claim it's base64-encoded for GDPR/privacy — "Enable macros to decode and read." |
| **App Owner**   | Send a fake pentest report: "Bugs found in your app — please review."                           |
| **Any Staff**   | "Document compressed for transfer — click Enable Content to restore formatting."                |

### Countering Security Warnings

- When AV flags the file, tell the victim it's a **false positive** and instruct them to ignore the warning.
- Design pretexts that give the victim a **logical reason** to click "Enable Content."

## Office Macros — What Are They?

A **macro** is a series of automated commands written in **Visual Basic for Applications (VBA)**, built into Microsoft Office products (Word, Excel, PowerPoint).

### Legitimate Use Cases

| Product        | Macro Use Cases                                                               |
| -------------- | ----------------------------------------------------------------------------- |
| **PowerPoint** | Enforce consistent fonts, colors, bullet styles across all slides             |
| **Excel**      | Calculate means, generate charts, apply formulas dynamically across datasets  |
| **Word**       | Find/replace across document, fix grammar, add dynamic headers/footers, apply branding/watermarks |

### Why Macros Are Attractive for Attacks

- **Built-in & legitimate** — macros are a genuine Office feature, making detection harder.
- **VBA can interact with the system shell** — enabling arbitrary command execution / RCE.
- **Low AV detection at rest** — a macro-enabled document sitting on disk performs no malicious actions, spawns no processes, and makes no network requests until executed.
- **VBA supports extensive obfuscation** — signature-based AV struggles to detect obfuscated VBA code.

### Limitations

- Macros are **disabled by default** in modern Office — users must manually enable them.
- **Protected View** blocks macros on files downloaded from untrusted sources until the user clicks "Enable Editing."

## Practical Walkthrough — Creating an Office Macro

### Step 1: Open the Macro Editor

Navigate to **View → Macros** in any Office product.

![](attachments/Pasted%20image%2020260908225508.png)

![](attachments/Pasted%20image%2020260908225611.png)

### Step 2: Create a New Macro

- Give the macro a name (e.g., `MyMacro`).
- **Select "Current Document"** (not "All Presentations" or "All Documents").
- Click **Create** to open the VBA Editor.

![](attachments/Pasted%20image%2020260908230333.png)

![](attachments/Pasted%20image%2020260908230630.png)

![](attachments/Pasted%20image%2020260908230646.png)

### Step 3: Write the VBA Code

The VBA editor is a built-in mini-IDE. Use `MsgBox` for a simple test:

![](attachments/Pasted%20image%2020260908230659.png)

![](attachments/Pasted%20image%2020260908230923.png)

![](attachments/Pasted%20image%2020260908231014.png)

```vb
Sub test()
    MsgBox "Hello World!"
End Sub

Private Sub Document_Open()
    test
End Sub

Sub AutoOpen()
    test
End Sub
```

> [!NOTE]
> - `test()` — contains the payload (here just a message box; in real attacks, a reverse shell).
> - `Document_Open()` — auto-fires when the document is opened (Word).
> - `AutoOpen()` — alternative auto-execution hook for compatibility across Office versions.
> - **Include both** `Document_Open` and `AutoOpen` for maximum reliability.

### Step 4: Test with the Run Button

The VBA editor has a **Run** button to test your macro locally and verify there are no syntax errors.

![](attachments/Pasted%20image%2020260908231525.png)

![](attachments/Pasted%20image%2020260908231558.png)

### Step 5: Save in Macro-Enabled Format

> [!WARNING]
> Saving as standard `.pptx` / `.docx` **discards the macro**. You must use a macro-enabled format.

| Format                                   | Extension  |
| ---------------------------------------- | ---------- |
| Word Macro-Enabled Document              | `.docm`    |
| PowerPoint Macro-Enabled Presentation    | `.pptm`    |
| Excel Macro-Enabled Workbook             | `.xlsm`    |
| Office 97-2003 format (also works)       | `.doc` / `.ppt` / `.xls` |

The macro-enabled file will be slightly larger than the original.

![](attachments/Pasted%20image%2020260908231658.png)

### Step 6: Test the Macro Execution Flow

1. Close and reopen the saved document.
2. The **"Security Warning: Macros have been disabled"** banner appears.
3. Click **"Enable Content"**.
4. The macro auto-executes — `Hello World!` message box pops up.

![](attachments/Pasted%20image%2020260908231918.png)

![](attachments/Pasted%20image%2020260908232004.png)

![](attachments/Pasted%20image%2020260908232044.png)

> [!TIP]
> If nothing happens after enabling content, verify that you included **auto-execution functions** (`Document_Open` / `AutoOpen`). Defining the function alone without an auto-run trigger means it won't fire on open.

## Trust Center & Macro Security Settings

Access via: **File → Options → Trust Center → Trust Center Settings → Macro Settings**

![](attachments/Pasted%20image%2020260908232124.png)

![](attachments/Pasted%20image%2020260908232156.png)

| Setting                                        | Behavior                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------ |
| **Disable all macros without notification**     | Blocks silently — no banner, no option to enable. Maximum security.      |
| **Disable all macros with notification** *(default)* | Shows the "Enable Content" banner — user can choose to run macros.  |
| **Enable all macros**                           | Runs everything immediately — unrealistic to expect on a victim's machine. |

### Protected View

- Files downloaded from the internet open in **Protected View** (read-only).
- User must click **"Enable Editing"** first, then **"Enable Content"** to run macros.
- This is a **two-step barrier** for internet-sourced documents.

> [!TIP]
> For your **local testing environment**, you can disable Protected View in Trust Center settings. But always design payloads assuming the victim has default settings enabled.

---

## Key Takeaways

1. Client-side attacks target the **user**, not the machine — no routable network access needed.
2. **Social engineering pretexts** are critical — the payload is useless if the victim doesn't execute it.
3. Office macros use **VBA** and are a legitimate automation feature — this gives them inherent stealth.
4. Always include **both** `Document_Open()` and `AutoOpen()` for cross-version compatibility.
5. Save documents in **macro-enabled formats** (`.docm`, `.pptm`, `.xlsm`).
6. Macros are **disabled by default** — your pretext must convince the victim to click "Enable Content."
7. VBA code at rest has **low AV detection** due to no active behavior until execution + obfuscation support.
