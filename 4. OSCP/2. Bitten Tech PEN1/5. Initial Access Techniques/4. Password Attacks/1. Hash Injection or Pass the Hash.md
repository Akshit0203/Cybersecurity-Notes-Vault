About **injection attacks**: Hello friends, in this video we will talk about **Hash Injection attacks**. This is an **active online attack** used in a Windows environment. Basically, its other name is **Pass the Hash**. For this, you should know about the **Active Directory Domain Controller**, which will be covered further. If you do not have prior knowledge about it, please watch that video first so you can follow along here.

If you understand **hashes and hashing**, both concepts are applied here. If you don't know about hashes, review that topic as well since it was explained in the cryptography module. Now, how is a hash created? When you log into a system and enter your username, your Windows machine **hashes and stores your password**. Your password is stored in hash form and is **never kept in clear text or plain text**.

In a **Domain Controller environment**, when you attempt to log in, you provide a username and password. Your Windows machine automatically converts that password into a hash and sends a login request to the Domain Controller. The Domain Controller uses a **challenge-response protocol**: the DC sends a challenge, and if you provide the correct response, it verifies and matches the response to authenticate you. It then stores a copy of your password hash in its database.

The authentication mechanism and hash algorithm being used here is **NTLM**. The inherent issue with how this operates is that **you never actually need the clear text password** to log into the Domain Controller. If you possess the hash, you will automatically be authenticated. If an attacker obtains the stored hash of your password from your machine, they can log directly into the Domain Controller by **injecting or passing the hash**.

To extract the hash, the attacker must first gain access to your system. Once system access is achieved, there are multiple tools available to **dump stored NTLM hashes** from Windows, with the most common tool being **Mimikatz**. First, the attacker compromises your system, dumps the hash, and then injects your hash into the Domain Controller to gain access and act on your behalf.

In a local session, a **compromised hash is injected** and validated with network resources. If the attacker compromises a system with a logged-on **Domain Admin**, they extract the admin account hash to log into the Domain Controller. Logging in as an admin provides the **highest privileges**, resulting in **privilege escalation**.

This is how **Pass the Hash or Hash Injection** takes place. In NTLM, this isn't strictly a software flaw or vulnerability, but rather **its fundamental design and operational behavior**. Similar to **ARP**, as long as NTLM is active, this mechanism remains. The primary mitigation is ensuring an attacker cannot compromise the initial system in the first place.
