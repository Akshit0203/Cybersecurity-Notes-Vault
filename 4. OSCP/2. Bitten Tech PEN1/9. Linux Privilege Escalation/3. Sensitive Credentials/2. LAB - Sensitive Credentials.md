## Task 16 — History Files

> If a user accidentally types their password on the command line instead of into a password prompt, it may get recorded in a history file.

### Steps

1. View all hidden history files in the user's home directory:
    ```bash
    cat ~/.*history | less
    ```
2. Note that the user has tried to connect to a MySQL server using the `root` username with a password submitted via the command line (no space between `-p` and the password).
3. Switch to root using the discovered password:
    ```bash
    su root
    ```
4. Exit the root shell before continuing.

### Answer

**Q: What is the full mysql command the user executed?**

```
mysql -h somehost.local -uroot -ppassword123
```

### Walkthrough Notes

- Navigating to `/var/www/html` — no config files found (no web app installed, only a default `index.html`).
- Inspecting `.bash_history` in the user's home directory reveals the MySQL command with the `root` password typed inline.
- Having obtained this password → attempt MySQL login or test **password reuse** across system accounts.
- Check `echo $HISTFILE` to confirm which history file is active.
- Also check `.mysql_history`, `.nano_history` for additional leaked data.

## Task 17 — Config Files

> Config files often contain passwords in plaintext or other reversible formats.

### Steps

1. List the user's home directory:
    ```bash
    ls /home/user
    ```
2. Note the `myvpn.ovpn` config file. View its contents:
    ```bash
    cat /home/user/myvpn.ovpn
    ```
3. The `.ovpn` file references an external authentication file (`pass.txt`) via a path directive. Open that file to find cleartext credentials:
    ```
    username: root
    password: <cleartext_password>
    ```
4. Switch to root using the credentials:
    ```bash
    su root
    ```
5. Exit the root shell before continuing.

### Answer

**Q: What file did you find the root user's credentials in?**

```
/etc/openvpn/auth.txt
```

### Walkthrough Notes

- OpenVPN config files (`.ovpn`) store network connection settings and can reference external auth files containing cleartext credentials.
- Storing passwords in plaintext for OpenVPN is insecure — certificate-based or private-key-based authentication is far more secure.
- Other history files (`.nano_history`, `.mysql_history`) should also be inspected, as text editors and database clients log commands and file paths.

## Task 18 — SSH Keys

> Sometimes users make backups of important files but fail to secure them with the correct permissions.

### Steps

1. Look for hidden files and directories in the system root:
    ```bash
    ls -la /
    ```
2. Note a hidden `.ssh` directory. View its contents:
    ```bash
    ls -l /.ssh
    ```
3. There is a **world-readable** file called `root_key` — a private SSH key for the root user.
4. Copy the key to your Kali box and set correct permissions:
    ```bash
    chmod 600 root_key
    ```
5. Use the key to log in as root:
    ```bash
    ssh -i root_key -oPubkeyAcceptedKeyTypes=+ssh-rsa -oHostKeyAlgorithms=+ssh-rsa root@10.114.149.78
    ```
6. Exit the root shell before continuing.

### Walkthrough Notes

- Attempting to read `/root/.ssh/id_rsa` directly may yield `"Permission denied"`.
- However, if root's RSA private key is found in a **backup folder, web directory, or world-readable location**, you can copy it and authenticate.
- Private keys **must** have `600` permissions or OpenSSH will refuse to use them.
- If OpenSSH returns `"No mutual signature algorithm supported"` (legacy RSA deprecation), append:
  ```bash
  ssh -i id_rsa root@<target_ip> -o PubkeyAcceptedKeyTypes=+ssh-rsa
  ```
- If the private key is unencrypted (no passphrase), key-based auth grants an **immediate passwordless root shell**.

## Automated Enumeration — LinPEAS

Running `./linpeas.sh` automates the search for leaked credentials and sensitive config files.

LinPEAS highlights high-confidence findings in **red and yellow**:

- `PermitRootLogin` SSH settings
- OpenVPN configuration files and extracted cleartext password files (`pass.txt`)
- Active cron jobs, Tmux sessions, Redis passwords, Neo4j databases
- Unprotected SSH directories
- Keywords like `pw` and `pass` across user home directories
