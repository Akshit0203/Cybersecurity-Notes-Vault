# Introduction to Cron Jobs — Linux Privilege Escalation

> [!tip] Core Idea
> Cron jobs are scheduled tasks that run programs/scripts at specific intervals. If a cron job runs as `root` and the script or its environment is misconfigurable, it becomes a direct privilege escalation vector.

---

## What Are Cron Jobs?

- **Cron** (Greek for "time") — an automated task scheduler on Unix/Linux systems
- Schedules programs or scripts to run at specific time intervals
- Commonly used for sysadmin work: backups, cleanup, automated maintenance
- Alternative: `at` command (one-time task scheduler)

---

## Crontab — Cron Table Files

Crontab files store the cron configuration (what to run, when, as whom).

| Type | Location | Notes |
| --- | --- | --- |
| **System-wide** | `/etc/crontab` | All users' scheduled jobs; includes username field |
| **User-specific** | `crontab -l` | Only current user's jobs; no username field |

> [!important]
> For privilege escalation, focus on the **system-wide** crontab (`/etc/crontab`), since it contains jobs that run as `root`. User crontabs only execute under the current user's privileges.

## Crontab Syntax

```
┌───────── minute (0–59)
│ ┌─────── hour (0–23)
│ │ ┌───── day of month (1–31)
│ │ │ ┌─── month (1–12)
│ │ │ │ ┌─ day of week (0–6, Sun=0)
│ │ │ │ │
* * * * *  user  command
```

### Operators

| Operator | Meaning | Example |
| --- | --- | --- |
| `*` | Every possible value | `* * * * *` = every minute |
| `,` | Multiple discrete values | `1,5,10` = at minutes 1, 5, and 10 |
| `-` | Inclusive range | `0-5` = minutes 0 through 5 |
| `/` | Step value (every Nth) | `*/5` = every 5 minutes |

### Common Schedule Examples

| Expression | Meaning |
| --- | --- |
| `* * * * *` | Every minute |
| `*/5 * * * *` | Every 5 minutes |
| `*/2 * * * *` | Every 2 minutes (common in CTFs/OSCP) |
| `0 17 * * *` | Daily at 5:00 PM |
| `0 17 31 * *` | At 5:00 PM on the 31st of every month |
| `0 17 31 7 *` | At 5:00 PM on July 31st |

> [!note] Online Tool
> Use [crontab.guru](https://crontab.guru/) to visualize and validate cron expressions.

## Crontab Environment Directives

Pay attention to these at the top of `/etc/crontab`:

- **`SHELL`** — Which shell executes the scripts (e.g., `SHELL=/bin/sh`)
- **`PATH`** — Binary search path; if a user-writable directory (like `/home/user`) appears first, it's a PATH hijacking opportunity

---

## Three Cron Job PrivEsc Vectors

| Vector | Condition | Method |
| --- | --- | --- |
| **Weak File Permissions** | Script is world-writable | Modify the script directly (inject reverse shell) |
| **PATH Manipulation** | Script called without absolute path + writable dir in `$PATH` | Create malicious script in higher-priority PATH directory |
| **Wildcard Injection** | Script uses wildcards (`*`) in commands like `tar` | Create filenames that look like command-line options |
