## Why Privilege Escalation Matters

![](attachments/Pasted%20image%2020260923095820.png)

- Initial access is **not** direct-to-admin — it lands on a standard or low-privilege user
- Escalation is required to move from that low-privilege foothold upward
- Extensive **information gathering and enumeration** about the target precedes every escalation attempt
- Escalation feeds directly into lateral movement and post-exploitation

**Elevated access targets:**

| OS      | Target Account                  |
| ------- | ------------------------------- |
| Linux   | `root`                          |
| Windows | Local Administrator / `NT AUTHORITY\SYSTEM` |

## Penetration Testing Methodology — Where PrivEsc Fits

The overall pentest workflow:

1. **Reconnaissance** — information gathering, scanning, identifying the target's architecture and contents
2. **Initial Compromise** — exploiting web vulnerabilities, public exploits, leaked credentials, or misconfigurations to achieve **Remote Code Execution (RCE)**
3. **Foothold** — establishing a shell session on the target (usually lands on a low-privileged service account, e.g. `IIS_IUSRS`, `www-data`)
4. **Privilege Escalation** ← *this course* — moving from a service/standard account to **Local Administrator** or **`NT AUTHORITY\SYSTEM`**
5. **Lateral Movement** — pivoting across internal network segments (requires elevated privileges to create routes and tunnels)
6. **Post-Exploitation / Persistence** — domain-level attacks via Active Directory, maintaining access

> [!IMPORTANT]
> Privilege escalation is **not always one step**. It may chain: service account → standard user → another user → administrator → SYSTEM.

## Defining Your Target Account

### Linux

- Ultimate superuser: **`root`**

### Windows

- **Local Administrator** — can install/uninstall programs, modify system settings, create/delete accounts, reset passwords
- **`NT AUTHORITY\SYSTEM`** — reserved system protection account with privileges **higher** than a standard local administrator; this is the absolute ceiling

> [!TIP]
> Always set `SYSTEM` as your target to ensure you reach the highest possible privilege level on the box.

## Windows User Account Architecture

### Local Accounts

Permissions are restricted to the specific local machine only.

| Account Type       | Description |
| ------------------ | ----------- |
| **Administrator**  | Full control — install/uninstall software, modify settings, manage users, reset passwords. Primary PrivEsc target. |
| **Standard User**  | Can run assigned apps and store files in their profile; **cannot** install programs, change system config, or perform admin tasks without admin credentials. |
| **Guest**          | Extremely limited temporary access. Disabled by default, no password required when enabled, cannot install apps or modify system/user data. |
| **Default Account**| Built-in reserved account for multi-user / shared application processes that persist across logon sessions. |

### Domain Accounts

- Joined to an **Active Directory** domain controller
- A single domain account can log into **any** domain-joined machine based on granted permissions
- Domain environments introduce multi-level privilege hierarchies managed centrally

## Common Misconfiguration Attack Vectors

| # | Vector | What to Look For |
|---|--------|------------------|
| 1 | **Windows Services** | Which user a service runs as, binary execution paths, writable service binaries/directories |
| 2 | **Access Control Lists (ACLs)** | Misconfigured permissions on files, folders, and registry keys |
| 3 | **Privilege Tokens** | Abusable tokens such as `SeImpersonatePrivilege`, `SeAssignPrimaryTokenPrivilege`, `SeBackupPrivilege` |
| 4 | **Sensitive Info & Stored Credentials** | Hardcoded creds in unattended install files, log files, backups, registry keys, API tokens |
| 5 | **Software Vulnerabilities** | Unpatched third-party applications and public CVE exploits |

## Study Strategy

1. **Hands-On Practice** — practice each module line-by-line before moving on
2. **Take Your Own Notes** — document key commands, concepts, and observations
3. **Problem-Solving Mindset** — constantly ask *why* a vulnerability exists and *how* a mechanism operates
4. **Enumeration is the Key** — finding *what* is vulnerable is harder and more important than knowing *how* to exploit it
