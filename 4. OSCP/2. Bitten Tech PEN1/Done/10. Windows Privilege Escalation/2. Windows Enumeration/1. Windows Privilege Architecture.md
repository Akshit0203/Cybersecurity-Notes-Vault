# Windows Privilege Architecture

---

## Windows Integrity Levels (Mandatory Integrity Control)

Since Windows Vista, all protected/securable objects are labelled with an **integrity level**. Mandatory Integrity Control (MIC) defines what processes can do to objects based on their trust level.

> [!IMPORTANT]
> A process with a lower integrity level **cannot write to** an object with a higher integrity level. For administrator privilege, we need to own at least a **High integrity** object.

![](attachments/Pasted%20image%2020260923103124.png)

### Integrity Level Hierarchy

| Level | Meaning | Example |
|-------|---------|---------|
| **Untrusted** | Anonymous / sandbox | Browser sandbox processes |
| **Low** | Highly restricted | Internet-downloaded files, Protected Mode apps |
| **Medium** | Normal user execution (default) | Standard applications, normal CMD |
| **High** | Elevated administrator | "Run as Administrator" CMD |
| **System** | System-level execution | Windows services running as `NT AUTHORITY\SYSTEM` |
| **Installer** | Application installers | Can uninstall/modify all objects |

```
System       🔴 Highest
    ↑
High
    ↑
Medium
    ↑
Low
    ↑
Untrusted    🔵 Lowest
```

### Key Rules

- Most user/system files default to **Medium** integrity
- Process/thread security context is defined in **Access Tokens**
- Most user processes run with **Medium** integrity; most services run with **System** integrity
- Even as an Administrator, you get **Medium integrity by default** — the High integrity token is not used until you give explicit consent (UAC)
- A standard user gets **one** Access Token (Medium); an Administrator gets **two** (Medium + High)

> [!TIP]
> **OSCP tip**: Run `whoami /all` to inspect your identity, groups, privileges, and integrity label in one command.

## Administrator vs NT AUTHORITY\SYSTEM

![](attachments/Pasted%20image%2020260923103630.png)

### Administrator

A **user account** with extensive local privileges.

```
WIN-PC\Akshit
```
(with membership in local `Administrators` group)

**Can do:**
- Install software and drivers (subject to UAC)
- Create and manage user accounts
- Change system settings
- Access many protected files
- Configure services and scheduled tasks

**Cannot do:**
- Directly modify files currently in use by the system (e.g., SAM file)
- Bypass Windows File Protection
- Perform certain kernel-level changes

> Windows UAC restricts when administrative privileges are used — admin operates with a filtered (Medium) token until elevation occurs.

### NT AUTHORITY\SYSTEM

A **built-in security principal / service identity** — NOT a user account.

```
NT AUTHORITY\SYSTEM
```

- SID: `S-1-5-18`
- Also called `Local System`
- Used by Windows services and system processes
- You **cannot** log in as SYSTEM interactively
- Not a member of any group; you cannot assign it to groups
- Possesses maximum kernel-level privileges

**Can do (that Admin cannot):**
- Forcefully access/modify files while in use (e.g., SAM file at `C:\Windows\System32\config\SAM`)
- Perform deep kernel-level changes
- Access locked files and restricted registry keys

> The `NT` in `NT AUTHORITY` comes from the Windows NT kernel that modern Windows still uses.

### Comparison Table

| Feature | Administrator | SYSTEM |
|---------|--------------|--------|
| Account type | Administrative user | Built-in service identity |
| Identity example | `PC\admin` | `NT AUTHORITY\SYSTEM` |
| Intended use | Human administration | Windows system operations |
| UAC | Subject to UAC | Not an interactive UAC user |
| Local privileges | Extensive | Most powerful — unrestricted system service access |
| Network identity | Uses user or machine context | Uses computer's machine account |
| Interactive login | Can log in normally | Not intended for interactive login |
| SID | User-specific | `S-1-5-18` |

### OSCP PrivEsc Example

```
whoami
# Output: nt authority\local service

# → Discover misconfigured service → exploit →

whoami
# Output: nt authority\system   ← PrivEsc complete!
```

> [!IMPORTANT]
> Administrator ≠ SYSTEM. In pentesting labs, you may need a separate escalation path from Admin to SYSTEM.

### Memory Trick

> **Administrator** = A powerful user who manages Windows.
> **SYSTEM** = Windows' own powerful service identity (closest to Linux `root`).

## Checking Integrity Levels — Practical Commands

### Check Your Current User

```cmd
whoami
# desktop-2er5cui\akshit
```

### List All Users on System

```cmd
net user
```

```
User accounts for \\DESKTOP-2ER5CUI
-------------------------------------------------------------------------------
Administrator            Akshit                   CodexSandboxOffline
CodexSandboxOnline       DefaultAccount           Guest
WDAGUtilityAccount
```

### Check User Group Membership

```cmd
net user <username>
```

```cmd
net user Akshit
```

```
Local Group Memberships      *Administrators
```

### Check Integrity Level via Groups

```cmd
whoami /groups
```

Look for the last line:

```
Mandatory Label\Medium Mandatory Level        Label    S-1-16-8192
```

> Even though we are Admin, a standard CMD shows **Medium Mandatory Level**!

### Elevated CMD (Run as Administrator)

```cmd
whoami /groups
```

```
Mandatory Label\High Mandatory Level          Label    S-1-16-12288
```

> After "Run as Administrator" → UAC consent → now shows **High Mandatory Level**.

### PowerShell Alternative

```powershell
whoami /groups | Select-String "Mandatory Label"
```

### Why This Matters in OSCP

```
User:       Administrator     |    User:       Administrator
Integrity:  Medium            |    Integrity:  High
→ Cannot run admin commands   |    → Full admin access
```

> **User** = Who you are. **Integrity level** = How trusted your process is. **Privileges** = What special actions your token can perform.

## Checking File Integrity Levels with `icacls`

![570](attachments/Pasted%20image%2020260923104518.png)

### View file permissions

```cmd
icacls Enumeration-pdf.pdf
```

```
Enumeration-pdf.pdf NT AUTHORITY\SYSTEM:(I)(F)
                    BUILTIN\Administrators:(I)(F)
                    DESKTOP-2ER5CUI\Akshit:(I)(F)
```

### Set file integrity level

```cmd
icacls <filename> /setintegritylevel m
# m = medium
# h = high
# You cannot set integrity level higher than that of your current user/process
```

```cmd
icacls Enumeration-pdf.pdf /setintegritylevel m
```

### Verify the set level

```cmd
icacls Enumeration-pdf.pdf
```

```
Enumeration-pdf.pdf NT AUTHORITY\SYSTEM:(I)(F)
                    BUILTIN\Administrators:(I)(F)
                    DESKTOP-2ER5CUI\Akshit:(I)(F)
                    Mandatory Label\Medium Mandatory Level:(NW)
```

> [!NOTE]
> Setting a High integrity level from a Medium integrity shell will **fail** — a Medium process cannot assign a higher integrity level than its own.

> You can also use GUI tools like **Process Monitor (ProcMon)** or **Process Hacker** to view running process integrity levels in real time.
