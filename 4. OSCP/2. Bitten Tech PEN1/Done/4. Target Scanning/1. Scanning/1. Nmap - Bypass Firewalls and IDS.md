# Nmap — Bypass Firewalls & IDS

When a firewall sits between you and the target, ports often show as **filtered**. These Nmap options help you evade or detect firewalls and IDS/IPS.

> [!NOTE]
> None of these techniques **guarantee** a bypass. They are common methods to **try**; results depend on the firewall configuration, network topology, and IDS/IPS rules.

---

## 1. IP Fragmentation (`-f`)

Splits packets into **8-byte fragments** (default). Many firewalls pass small fragments without deep inspection.

```bash
nmap 192.168.60.138 -f
```

## 2. Custom MTU (`--mtu`)

**MTU** = Maximum Transmission Unit. Lets you choose the exact fragment size (must be a multiple of 8).

```bash
nmap 192.168.60.138 --mtu 16
```

- Fragments packets into **16-byte** chunks instead of the default 8.
- Firewalls that ignore small packets may let these through.

---

## 3. Decoy Scan (`-D`)

Makes the scan appear to originate from **multiple IP addresses**, flooding the target's logs with decoy sources.

```bash
nmap 192.168.60.138 -D RND:16
```

- `-D` = Decoy scan
- `RND:16` = Nmap generates **16 random decoy IP addresses**

**How it works:** Nmap crafts packets with spoofed source IPs. The target sees traffic from many addresses, making it harder to identify the real scanner.

> [!WARNING]
> Decoys **do not make you anonymous**. They obscure your identity in the target's logs, but:
> - Network infrastructure can still observe which machine actually generated traffic
> - The target may distinguish the real scanner via TCP/IP characteristics, routing behavior, packet timing, and response patterns
> - Decoy IPs that don't actually exist on the network can be easily filtered out

> **Memory aid:** `-D` → **Decoy** → scan appears to come from multiple addresses.

---

## 4. Source IP Spoofing (`-S` + `-e`)

Manually set a **specific** source IP (unlike decoys, which are random).

```bash
nmap 192.168.60.138 -e eth0 -S 192.168.60.100
```

- `-S 192.168.60.100` = Spoof source IP to `192.168.60.100`
- `-e eth0` = **Required** — specify the network interface

> [!NOTE]
> You will likely see errors like `dnet: failed to bind: Cannot assign requested address` if the spoofed IP cannot be bound on your system. The scan may still send packets from your real IP. Experiment with different addresses.

---

## 5. Zombie / Idle Scan (`-sI`)

Use a **zombie host** (an idle machine under your control) to scan the target on your behalf. The target only sees traffic from the zombie.

```bash
nmap 192.168.60.138 -e eth0 -sI 192.168.60.100
```

**Requirements for the zombie host:**
- Must be alive and reachable
- Must be under your control
- Must have predictable IP ID sequence (idle host)

---

## 6. Source Port Spoofing (`--source-port` / `-g`)

Change the **source port** in your packets. Useful if the firewall only allows traffic from certain ports.

```bash
nmap 192.168.60.138 --source-port 65
```

- Try common allowed ports (e.g., 53 for DNS, 80 for HTTP) to bypass port-based firewall rules.
- Use **Wireshark / tcpdump / tshark** to verify the source port is actually being changed in the packets.

---

## 7. MAC Address Spoofing (`--spoof-mac`)

Spoof your **MAC address** in the packets.

```bash
nmap 192.168.60.138 --spoof-mac 0
```

- `0` = Nmap picks a **random** MAC address
- You can also specify a full MAC address manually

```
└─# nmap 192.168.60.138 --spoof-mac 0    
Starting Nmap 7.99 ( https://nmap.org ) at 2026-09-04 04:11 -0400
Spoofing MAC address 9B:55:2D:E7:D9:7F (No registered vendor)
Note: Host seems down. If it is really up, but blocking our ping probes, try -Pn
Nmap done: 1 IP address (0 hosts up) scanned in 1.56 seconds
```

> [!IMPORTANT]
> When you spoof the MAC, responses go to the **owner of that MAC**, not you. To still receive output, combine with `-sT` (full TCP connect) and `-Pn` (skip ping):

```bash
nmap 192.168.60.138 --spoof-mac 0 -sT -Pn
```

---

## 8. Data Length Padding (`--data-length`)

Nmap sends minimal packets by default (headers only). Adding **padding** (dummy data) can confuse firewalls that filter based on packet size.

```bash
nmap 192.168.60.138 --data-length 40
```

- Adds 40 bytes of zero-padding to each packet.
- Only the headers are meaningful; the extra data is filler.

---

## 9. Randomize Host Order (`--randomize-hosts`)

When scanning a **range** of hosts, randomize the order instead of scanning sequentially.

```bash
nmap 192.168.60.138 --randomize-hosts
```

- Useful to avoid triggering sequential-scan detection in IDS/IPS.

---

## 10. Bad Checksum — Firewall Detection (`--badsum`)

Sends packets with an **intentionally invalid checksum**. Legitimate hosts drop these packets, but **firewalls may respond** because they don't verify checksums.

```bash
nmap 192.168.60.138 --badsum
```

```
└─# nmap 192.168.60.138 --badsum        
Starting Nmap 7.99 ( https://nmap.org ) at 2026-09-04 04:15 -0400
Nmap scan report for 192.168.60.138
Host is up (0.00086s latency).
All 1000 scanned ports on 192.168.60.138 are in ignored states.
Not shown: 1000 filtered tcp ports (no-response)
MAC Address: 00:0C:29:06:33:26 (VMware)

Nmap done: 1 IP address (1 host up) scanned in 21.77 seconds
```

**Purpose:** Detect whether a firewall is active.
- **If a response comes back** → it's from the firewall (real hosts drop bad-checksum packets).
- **If no response** → packets were dropped (either no firewall, or the host itself dropped them).
- In the example above, all ports show `filtered` because every bad-checksum packet was silently dropped (no firewall present to respond).

## Quick Reference

| Technique | Flag | Purpose |
|---|---|---|
| Fragment packets | `-f` | Bypass packet-size inspection |
| Custom MTU | `--mtu <size>` | Control fragment size (multiple of 8) |
| Decoy scan | `-D RND:<count>` | Obscure scanner IP in logs |
| Spoof source IP | `-S <IP> -e <iface>` | Change source IP |
| Zombie/Idle scan | `-sI <zombie_IP>` | Scan via an intermediary host |
| Spoof source port | `--source-port <port>` | Bypass port-based firewall rules |
| Spoof MAC | `--spoof-mac <mac\|0>` | Change source MAC address |
| Data padding | `--data-length <bytes>` | Add dummy data to packets |
| Randomize hosts | `--randomize-hosts` | Avoid sequential scan detection |
| Bad checksum | `--badsum` | Detect active firewalls |
