# Banner Grabbing with Netcat

**Netcat (`nc`)** — the "TCP/IP Swiss Army Knife" — is a simple Unix utility that reads and writes data across network connections using TCP or UDP. It is one of the most versatile tools for banner grabbing, establishing connections, and basic network debugging.

---

## Why Netcat Over Telnet?

| Issue | Telnet | Netcat |
|---|---|---|
| Stays running until network closes | ❌ Exits on EOF | ✅ Stays open |
| Handles binary data | ❌ Strips telnet chars | ✅ Passes all data |
| Diagnostic output | Mixed with data | Kept separate |
| Listen mode (act as server) | ❌ | ✅ |
| UDP support | ❌ | ✅ |

### Key Options for Banner Grabbing

| Option | Purpose |
|---|---|
| `-n` | Numeric IP address (skip DNS resolution) |
| `-v` | Verbose — show connection status |
| `-vv` | Extra verbose |
| `-l` | Listen mode (turn your machine into a server) |
| `-u` | Use UDP instead of TCP |
| `-z` | Zero-I/O mode (for port scanning) |

## Banner Grabbing Examples

### HTTP Banner (Port 80)

Connect to port 80, then send a malformed HTTP request to trigger an error response containing the server banner:

```bash
nc -nv 192.168.60.138 80
```

Once connected (you'll see `80 (http) open`), type any garbage HTTP request and press Enter:

```
HTTP/1.1 200
```

The server responds with an error revealing its banner:

```
└─# nc -nv 192.168.60.138 80
(UNKNOWN) [192.168.60.138] 80 (http) open
HTTP/1.1 200
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">
<html><head>
<title>400 Bad Request</title>
</head><body>
<h1>Bad Request</h1>
<p>Your browser sent a request that this server could not understand.<br />
</p>
<hr>
<address>Apache/2.2.8 (Ubuntu) DAV/2 Server at metasploitable.localdomain Port 80</address>
</body></html>
```

**Extracted info:**
- **Web Server:** Apache/2.2.8
- **OS:** Ubuntu
- **Module:** DAV/2
- **Hostname:** metasploitable.localdomain

### SSH Banner (Port 22)

SSH services automatically send their banner upon connection — no additional input needed:

```
└─# nc -nv 192.168.60.138 22
(UNKNOWN) [192.168.60.138] 22 (ssh) open
SSH-2.0-OpenSSH_4.7p1 Debian-8ubuntu1
```

**Extracted info:** OpenSSH 4.7p1 on Debian/Ubuntu.

---

### FTP Banner (Port 21)

FTP services also send their banner automatically:

```
└─# nc -nv 192.168.60.138 21
(UNKNOWN) [192.168.60.138] 21 (ftp) open
220 (vsFTPd 2.3.4)
```

**Extracted info:** vsFTPd 2.3.4.

---

## The Technique

1. **Connect** with `nc -nv <target> <port>` to establish a TCP connection.
2. **For HTTP:** Send a malformed request to trigger a `400 Bad Request` error — the error page reveals the server banner in the `<address>` tag.
3. **For SSH / FTP / SMTP:** The service **automatically** sends its banner upon connection — just connect and read.
4. **Research** the extracted version numbers to find known vulnerabilities and available exploits.

> [!TIP]
> Netcat gives you banners for **any port**, not just HTTP. A browser can only show you the HTTP banner, but Netcat can grab SSH, FTP, SMTP, and any other service that responds with identifying information.
