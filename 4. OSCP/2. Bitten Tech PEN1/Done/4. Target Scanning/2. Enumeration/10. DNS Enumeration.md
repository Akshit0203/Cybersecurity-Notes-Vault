# DNS Enumeration

## What is DNS Enumeration?

DNS enumeration is the process of **locating DNS servers and extracting their records** for a target network. It is the **biggest and most-used method** in the enumeration phase.

### What Attackers Gather

- DNS server names and locations
- Hostnames and machine names
- Usernames
- IP addresses of potential targets
- Full zone file contents (via zone transfer)

---

## DNS Fundamentals (Quick Recap)

- **DNS** is a **distributed, hierarchical, and redundant** database for domain names and addresses
- Multiple DNS servers around the world hold copies of the same domain information (redundancy)
- This is similar to a **CDN** concept — regional copies reduce query time
- In scanning/recon, we found IPs, name servers, and mail servers. In DNS **enumeration**, we go deeper into **zone details, all records, and the full DNS hierarchy**

---

## DNS Enumeration vs. Earlier Recon

| Phase                | What You Get                                  |
| -------------------- | --------------------------------------------- |
| **Scanning/Recon**   | IP, main NS records, MX records               |
| **DNS Enumeration**  | Full zone files, all record types, internal hostnames, DNS hierarchy |

---

## Zone Transfer — The Core Technique

In DNS zone transfer enumeration, an attacker tries to **retrieve a copy of the entire zone file** from the DNS server.

> [!important] What is a Zone Transfer?
> An attacker impersonates a secondary DNS server and requests the full zone file from the primary. If no authentication is in place, the entire DNS database is handed over.

A successful zone transfer reveals:
- All subdomains (including internal/hidden ones)
- All DNS record types (A, AAAA, MX, NS, CNAME, TXT, SOA, PTR, SRV, etc.)
- Internal infrastructure and IP addresses

### Example

```bash
dig AXFR example.com @ns1.example.com
```

Could reveal:

```
dev.example.com
vpn.example.com
mail.example.com
admin.example.com
internal.example.com
staging.example.com
```

> [!note]
> A successful unrestricted AXFR is relatively **uncommon on properly configured modern systems**, but it still occurs and is always worth testing.
