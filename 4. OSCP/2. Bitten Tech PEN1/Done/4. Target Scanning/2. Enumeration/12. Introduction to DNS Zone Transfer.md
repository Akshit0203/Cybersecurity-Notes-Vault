# Introduction to DNS Zone Transfer

## What is a DNS Zone Transfer?

A **zone transfer** is the process of copying/synchronizing DNS zone data from a **primary DNS server to a secondary DNS server**.

```
Primary DNS Server (master copy of the zone)
       │
       │  Zone Transfer (TCP)
       │  "Here is the updated zone data"
       ↓
Secondary DNS Server (backup copy)
```

## Why Zone Transfers Exist

- Every DNS server has at least **one primary and one secondary** server
- The **primary** holds the **master copy** of the zone file (newest, most updated)
- The **secondary** holds a **redundant backup** for reliability
- If the primary fails → users still get DNS responses from the secondary
- The secondary **must stay in sync** with the primary → this sync is the **zone transfer**

### Synchronization Flow

1. Administrator updates a record on the **primary** DNS server
2. The zone file on the primary is modified
3. The **zone serial number increments** (triggers automatic transfer)
4. The updated zone file is **transferred to the secondary** over TCP
5. The secondary now has the same data as the primary

> [!note] Key Rule
> Updates only flow **Primary → Secondary** (unidirectional). You never update the secondary directly.

---

## Types of Zone Transfers

| Type     | Name                                    | What Transfers         |
| -------- | --------------------------------------- | ---------------------- |
| **AXFR** | Asynchronous Full Transfer              | **Entire zone file**   |
| **IXFR** | Incremental Transfer                    | **Only changed records** |

> For enumeration, we use **AXFR** because we want **all** the data, not just incremental updates.

---

## The Security Problem: No Authentication in AXFR

> [!warning] Critical Vulnerability
> **AXFR offers no authentication** — any client can ask a DNS server for a copy of the entire zone.

### How an Attacker Exploits This

1. Attacker discovers the target's **name servers** (NS records)
2. Attacker sends a request to the primary DNS: *"I am your secondary DNS server, send me the zone file"*
3. If **no authentication/protection** is configured, the primary **cannot verify** the requester's identity
4. The entire zone file is handed over — including **all domains, subdomains, IPs, internal hosts, and all record types**

```
Attacker  →  "I'm the secondary, send me the zone"  →  Primary DNS
                                                            │
                           ← Entire zone file ←─────────────┘
```

## Where are DNS Zones Stored?

DNS zones are stored on **authoritative DNS servers** which could be:

| Location                    | Example                    |
| --------------------------- | -------------------------- |
| Company's own **data center** | Server room on-premises   |
| **Cloud provider**          | AWS, Azure, GCP            |
| **Dedicated DNS provider**  | Cloudflare, AWS Route 53   |
| **Distributed** across locations | Multiple geographic sites |

### Example Multi-Server Setup

```
             example.com
                  │
        ┌─────────┴─────────┐
        ↓                   ↓
 Primary DNS          Secondary DNS
 US                    Europe
        │                   │
        └──── Zone Transfer┘
```

> [!important] Zone Transfer ≠ CDN
> Zone transfer is about **redundancy and keeping authoritative DNS servers synchronized**, not about geographic content distribution.

## OSCP Relevance

If a DNS server accidentally allows **anyone** to perform an AXFR:

```bash
dig axfr example.com @ns1.example.com
```

You might receive:

```
dev.example.com
internal.example.com
vpn.example.com
mail.example.com
test.example.com
admin.example.com
```

→ This reveals **subdomains and internal infrastructure** useful for further enumeration and exploitation.

> **Zone = collection of DNS records for a domain.**  
> **Zone transfer = synchronization/copying of that zone between authorized DNS servers.**  
> **Misconfigured zone transfer = attackers can download the entire DNS database.**
