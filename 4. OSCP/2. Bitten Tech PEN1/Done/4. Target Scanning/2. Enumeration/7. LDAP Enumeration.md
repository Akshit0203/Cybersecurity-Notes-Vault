# LDAP Enumeration

## What is LDAP?

**LDAP (Lightweight Directory Access Protocol)** is a protocol used to **store, organize, and retrieve information** about users, computers, groups, and other resources on a network.

> Think of it as a **directory/database for an organization** — like a phone book for network resources.

```
Company
│
├── Users
│   ├── Alice
│   ├── Bob
│   └── Akshit
│
├── Groups
│   ├── IT
│   ├── HR
│   └── Administrators
│
└── Computers
    ├── PC01
    ├── PC02
    └── SERVER01
```

- An Internet protocol for accessing **distributed directory services**
- A **hierarchical** compilation used to access directory listings
- Data is **distributed** — accessible from anywhere on the network (with authentication)
- Tree-type structure displayed in tabular format

---

## LDAP and Active Directory

> [!important] Key Relationship
> **Active Directory (AD) commonly uses LDAP** as its query protocol.

```
Windows Client
      │
      │ LDAP
      ▼
Domain Controller
      │
      ▼
Active Directory
```

A domain controller can use LDAP to answer:
- What **users** exist?
- What **groups** exist?
- Who is a member of the **Domain Admins** group?
- What **computers** exist?
- What **attributes** does a particular user have?

### AD Protocol Stack

```
Active Directory
       │
       ├── LDAP     → directory queries
       ├── Kerberos  → authentication
       ├── SMB       → file/admin sharing
       └── DNS       → name resolution
```

## LDAP Ports

| Port    | Use                    |
| ------- | ---------------------- |
| **389** | LDAP                   |
| **636** | LDAPS (LDAP over TLS)  |

```bash
nmap -p 389,636 <IP>
```

If **389 is open** → strong indication of a directory service, often **Active Directory** in Windows environments.

> [!warning] Plain LDAP is Plaintext
> Standard LDAP (port 389) transmits data in **plain text** — it is **encoded** (using BER — Basic Encoding Rules), **not encrypted**. Use LDAPS (port 636) for security.

---

## LDAP Technical Details

- Client starts a session by connecting to a **Directory System Agent (DSA)** on TCP port 389
- Sends an **operation request** to the DSA
- Information is transmitted using **Basic Encoding Rules (BER)**

## LDAP Attribute Identifiers

| Attribute | Full Name              | Purpose                                    |
| --------- | ---------------------- | ------------------------------------------ |
| **CN**    | Common Name            | Identifies a person or object              |
| **OU**    | Organizational Unit    | Department or unit a person belongs to     |
| **O**     | Organization           | Name of the organization                   |
| **L**     | Locality               | City or area                               |
| **ST**    | State                  | State or province                          |
| **C**     | Country                | Country code                               |
| **DC**    | Domain Component       | Part of a domain name (e.g., `google` + `com`) |

### Reading the Hierarchy

```
DC=com
  └── DC=example
        └── OU=people
              └── UID=babs  (person in example.com, under "people" OU)
        └── OU=servers
```

The user `babs` belongs to: `OU=people, DC=example, DC=com`

## What Attackers Extract via LDAP

- Valid **usernames**
- **Addresses** and departmental details
- **Domain** information
- **Group memberships**
- Computer objects

### Enumeration Workflow

```
Domain
 ↓
Users
 ↓
Groups
 ↓
Computers
 ↓
Group memberships
 ↓
Potential attack paths
```

## Quick Protocol Comparison

```
SMB  → File/printer sharing
SNMP → Network/device information
LDAP → Directory information (users, groups, computers)
```

> **LDAP is absolutely relevant today**, especially for **Active Directory enumeration** — very important for OSCP.
