# Introduction to Metasploit

> **The Metasploit Framework is a penetration testing toolkit, exploit development platform, and research tool that includes hundreds of working remote exploits for a variety of platforms.**
> It supports fully automated exploitation of web servers, by abusing known vulnerabilities and leveraging weak passwords via Telnet, SSH, HTTP, and SNMP.

---

## What is Metasploit?

Metasploit is a **framework** that gives you a structured way to find and exploit vulnerabilities:

```
Find vulnerability
      ↓
Choose exploit
      ↓
Configure exploit
      ↓
Choose payload
      ↓
Run exploit
      ↓
Get result/session
```

Instead of manually writing or adapting an exploit every time, Metasploit provides **modules** that already implement many techniques.

**Example:** You discover a vulnerable SMB version on a target:

```
Target
└── SMB
    └── vulnerable version
```

You search Metasploit for a corresponding exploit:

```
msfconsole
```

```
search <vulnerability>
```

## Core Concept — Exploit vs Payload

```
EXPLOIT                    PAYLOAD
   │                          │
   │ "How do I get code       │ "What code/action do I
   │  executed?"              │  execute after exploitation?"
   │                          │
   └──────────┬───────────────┘
              ↓
           TARGET
```

### Exploit

An **exploit abuses a vulnerability** to achieve code execution or access.

```
Vulnerable SMB service
        ↓
     EXPLOIT
        ↓
Code execution
```

### Payload

The **payload is what you want executed** after the exploit succeeds.

```
Exploit
   ↓
Execute payload
   ↓
Reverse shell
```

> [!IMPORTANT]
> This distinction is **extremely important for OSCP**.

## Metasploit Architecture

```
                    METASPLOIT
                        │
        ┌───────────────┼────────────────┐
        ↓               ↓                ↓
     Exploit         Payload          Auxiliary
        │               │                │
        ↓               ↓                ↓
   Abuse vuln      Code/action       Supporting
                                   functionality
```

### Module Types

| Module     | Purpose                                          |
| ---------- | ------------------------------------------------ |
| **Exploit**    | Abuse a specific vulnerability                   |
| **Payload**    | Code/action executed after exploitation          |
| **Auxiliary**  | Scanning, enumeration, fuzzing, credential tests |
| **Post**       | Post-exploitation actions                        |
| **Encoder**    | Encode payloads to evade detection               |
| **NOP**        | Generate no-operation instructions for sleds     |
| **Evasion**    | Evasion-specific modules                         |

> For OSCP, **Exploit + Payload + Auxiliary + Post** are the most important.

## Exploit Module

An **exploit module** is a packaged implementation of a particular vulnerability/attack technique.

```
exploit/windows/...
exploit/linux/...
exploit/multi/...
```

Each module contains:

```
Target software
Vulnerability
Required options
Target versions
Compatible payloads
```

## The Exploitation Workflow (5 Steps)

```
1. Configuring Active Exploit
2. Verifying Exploit Options
3. Selecting a Target
4. Selecting Payload
5. Launching Exploit
```

---

### Step 1 — Configure the Exploit

Select an exploit:

```
use exploit/...
```

Inspect its options:

```
show options
```

Common options:

```
RHOSTS = WHERE?        → Target IP        (e.g. 10.10.10.5)
RPORT  = WHICH SERVICE? → Target port     (e.g. 445)
```

---

### Step 2 — Verify Options

Run `show options` and confirm all required fields are populated:

```
RHOSTS = target IP       ✅
RPORT  = target port     ✅
LHOST  = your VPN IP     ✅
LPORT  = listening port  ✅
```

Depending on the exploit/payload, different options will be required.

---

### Step 3 — Select a Target

A Metasploit exploit may support multiple **target configurations** (OS versions, architectures):

```
Target 0 → Windows version A
Target 1 → Windows version B
Target 2 → Windows version C
```

Inspect and set:

```
show targets
set TARGET <number>
```

> Choose the target matching the victim's environment — don't choose blindly.

---

### Step 4 — Select a Payload

See compatible payloads:

```
show payloads
```

Payload types include:

```
shell
meterpreter
reverse connection
bind connection
```

```
EXPLOIT
    ↓
Vulnerability successfully exploited
    ↓
PAYLOAD
    ↓
Your desired code/action
```

---

### Step 5 — Launch

Once everything is configured:

```
run
```

or:

```
exploit
```

Metasploit then attempts the exploitation process.

## Payload Module (Deep Dive)

> **A payload is the code/action that Metasploit executes on the target after exploitation succeeds.**

A payload could:

```
Open a shell
Create a Meterpreter session
Execute a command
Establish a reverse connection
```

### Reverse Shell Example

```
Target (10.10.10.20)
  │
  │ exploited
  ↓
Payload executes
  │
  │ connects BACK
  ↓
Kali (10.10.14.5)
```

**LHOST = local host = your attacking machine.**

## Singles, Stagers, and Stages

### Single (Stageless)

A **single/stageless payload** contains everything in one payload.

```
Exploit
   ↓
Complete payload
   ↓
Execution
```

### Stager

A **stager** is a small piece that establishes communication and prepares for the larger payload.

```
Exploit
   ↓
Small stager
   ↓
Connection established
   ↓
Larger stage
```

### Stage

The **stage** is the larger payload delivered after the stager connects.

```
Stager
   ↓
loads
   ↓
Stage
```

**Summary:**

```
STAGER = establishes/prepares
STAGE  = larger payload delivered afterward
```

---

## Staged vs Stageless

### Staged (Two pieces)

```
Exploit
   ↓
Stager
   ↓
Stage
   ↓
Shell/session
```

### Stageless (One piece)

```
Exploit
   ↓
Entire payload
   ↓
Shell/session
```

> **Payload naming:** `windows/meterpreter/reverse_tcp` (staged — slash separates stager/stage) vs `windows/meterpreter_reverse_tcp` (stageless — underscore).

> [!TIP]
> Don't memorize filenames blindly — understand the architecture.

## Auxiliary Modules

> **Auxiliary = useful functionality that isn't primarily an exploit.**

Examples:

```
Scanning
Enumeration
Service interaction
Fuzzing
Credential testing
Information gathering
```

Usage:

```
use auxiliary/...
```

### Exploit vs Auxiliary — Key Distinction

```
Exploit module
    ↓
TRY TO EXPLOIT A VULNERABILITY

Auxiliary module
    ↓
DO SOMETHING USEFUL WITHOUT BEING THE EXPLOIT ITSELF
```

**Example use case:** Nmap finds `445/tcp open SMB`. Use an auxiliary module to gather more SMB information:

```
Nmap
 ↓
Discovery
 ↓
Metasploit auxiliary module
 ↓
More enumeration
```

### The Locked Door Analogy

```
                 LOCKED DOOR
                     │
        ┌────────────┴────────────┐
        │                         │
     Exploit                   Auxiliary
        │                         │
"Here's a flaw in             "Let me inspect
the lock; I'll abuse it        the lock / test
to get through."               how it behaves."
```

> [!WARNING]
> **Auxiliary ≠ harmless.** Auxiliary modules can perform attacks (DoS, fuzzing). The distinction is about the module's *function*, not whether the activity is "good" or "bad."

**OSCP Mental Model:**

```
EXPLOIT   → Abuse a specific vulnerability
AUXILIARY → Scan / enumerate / fuzz / interact / perform supporting action
PAYLOAD   → What executes after successful exploitation
```

If you see `auxiliary/scanner/...`, think:

> *"This is probably helping me investigate or interact with the target, not directly exploiting a vulnerability."*

### Example — Auxiliary for Redis

```
6379/tcp open redis
```

```
Target Redis
     ↓
Auxiliary module
     ↓
Gather information
```

You're **using the service**, not necessarily exploiting a vulnerability.

## NOP Module

**NOP = No Operation.** The classic x86 NOP instruction is `0x90`.

> "Do nothing and continue to the next instruction."

### What is a NOP Sled?

```
[ NOP ][ NOP ][ NOP ][ NOP ][ NOP ][ PAYLOAD ]
```

Instead of needing execution to land at one exact byte, landing anywhere in the NOP region lets execution **"slide"** toward the payload.

```
              ↓
[ NOP ][ NOP ][ NOP ][ NOP ][ PAYLOAD ]
```

This was especially important in older stack-based buffer overflow exploitation. Modern mitigations (ASLR, DEP/NX, stack canaries) have made the classic NOP-sled less central.

### NOP Module Options

| Option | Description                              |
| ------ | ---------------------------------------- |
| `-b`   | Characters to avoid (e.g. `\x00\xff`)    |
| `-s`   | Registers to save/preserve               |
| `-t`   | Output type: `ruby`, `perl`, `c`, `raw`  |
| `-h`   | Help banner                              |

> [!TIP]
> For OSCP, understand the **concept** of NOPs. Don't spend excessive time on NOP-generator syntax unless your course specifically requires exploit development.

## OSCP Quick Reference

| Concept      | Definition                                                              |
| ------------ | ----------------------------------------------------------------------- |
| **Metasploit**   | Framework for exploitation, payload delivery, enumeration, post-exploitation |
| **Exploit**      | Abuses a vulnerability to achieve execution/access                      |
| **Payload**      | What you want executed after exploitation                               |
| **Auxiliary**    | Supporting functionality (scanning, enumeration, fuzzing, etc.)         |
| **Stager**       | Small component that establishes/prepares the connection for a stage    |
| **Stage**        | The larger payload delivered after the stager                           |
| **Stageless**    | Complete payload delivered as one unit                                  |
| **NOP**          | No-operation instruction; used to build NOP sleds for exploit reliability |

    ↓

    ↓

    ↓

    ↓

> **OSCP Warning:** Don't make Metasploit your default for every box. You should be able to exploit many vulnerabilities **manually** — the OSCP tests your ability to understand and reproduce the exploitation process, not just find a Metasploit module.
