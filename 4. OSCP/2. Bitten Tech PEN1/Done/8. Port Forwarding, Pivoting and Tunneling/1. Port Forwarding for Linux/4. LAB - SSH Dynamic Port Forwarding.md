# LAB — SSH Dynamic Port Forwarding

> **Lab Environment:** TryHackMe Wreath
> **Goal:** Use a SOCKS proxy to dynamically access **any service on any host** in the internal network — without creating individual port forwards.

---

## Concept

Local and Remote forwarding are **one-to-one** (one local port → one remote port on one host). Dynamic forwarding creates a **SOCKS proxy** — **one-to-many mapping**.

- You open a single SOCKS proxy port on Kali.
- Any connection sent through it is dynamically forwarded to **any IP and port** reachable by the pivot host.
- You do **not** specify a fixed remote IP or port when setting up the tunnel.

> ⚠️ **Important:** Proxychains works at Layer 7 (TCP). It does **NOT** support ICMP (`ping`) or ARP.

---

## Step 1 — Configure Proxychains

Edit the config file:

```bash
sudo gedit /etc/proxychains4.conf
```

Add this line at the bottom:

```
socks5 127.0.0.1 9050
```

> The port must match the `-D` port used in the SSH command.

## Step 2 — Establish the Dynamic SSH Tunnel

Run on Kali:

```bash
ssh -D 9050 -i id_rsa root@10.200.180.200
```

| Flag | Meaning |
|---|---|
| `-D 9050` | Opens a local SOCKS proxy listening on port `9050` |
| `-i id_rsa` | SSH private key for authentication |

```
┌──(root㉿kali)-[/home/kali/Downloads/wreath]
└─# ssh -D 9050 -i id_rsa root@10.200.180.200

[root@prod-serv ~]# 
```

> Dynamic port forwarding is now active on `127.0.0.1:9050`.

## Step 4 — Full Port Scan Through the Proxy

```bash
┌──(root㉿kali)-[/home/kali/Downloads]
└─# proxychains -q nmap -sT -Pn -p 22,80,443,445,3389,8000,8080,8443,10000 --max-retries 1 10.200.180.150
Starting Nmap 7.99 ( https://nmap.org ) at 2026-09-15 15:10 -0400
Nmap scan report for 10.200.180.150
Host is up (0.00s latency).

PORT      STATE  SERVICE
22/tcp    closed ssh
80/tcp    open   http
443/tcp   closed https
445/tcp   closed microsoft-ds
3389/tcp  open   ms-wbt-server
8000/tcp  closed http-alt
8080/tcp  closed http-proxy
8443/tcp  closed https-alt
10000/tcp closed snet-sensor-mgmt

Nmap done: 1 IP address (1 host up) scanned in 106.60 seconds
```

**Key findings:**
- Port **80** (HTTP) — open
- Port **3389** (RDP) — open → confirms this is a **Windows host**

> **Tips for scanning through SOCKS:**
> - Use `-q` flag with proxychains to suppress verbose proxy connection logs.
> - Use `-sT` (TCP connect scan) — SYN scans (`-sS`) don't work through SOCKS.
> - Use `-Pn` — skip host discovery (ICMP doesn't work through SOCKS).
> - Scan standard ports first, then run `-sV`/`-sC` **only against discovered open ports** to save time.

## Step 5 — RDP Through the Proxy

Since port 3389 is open:

```bash
┌──(root㉿kali)-[/home/kali/Downloads]
└─# proxychains rdesktop -u administrator -p password -v 10.200.180.150
```

Or with xfreerdp:

```bash
proxychains xfreerdp /v:10.200.180.150 /u:dummy /p:dummy
```

## Step 7 — Running Exploits Through the Proxy

Prefix exploit scripts with `proxychains`:

```bash
proxychains -q python2 2432.py
```

Example — RCE against GitStack on the internal host:

```bash
proxychains python2 43700.py http://10.200.180.150 "whoami"
```

Returns: `nt authority\system`

> From here you can execute administrative commands (add local admin user, etc.) and log in via RDP.

## Summary

| What | Command |
|---|---|
| Set up SOCKS proxy | `ssh -D 9050 -i id_rsa root@<pivot_ip>` |
| Configure Proxychains | Add `socks5 127.0.0.1 9050` to `/etc/proxychains4.conf` |
| Nmap through proxy | `proxychains -q nmap -sT -Pn -p <ports> <target>` |
| curl through proxy | `proxychains curl http://<target>` |
| RDP through proxy | `proxychains rdesktop -u <user> -p <pass> <target>` |
| Browser through proxy | FoxyProxy → SOCKS5 → `127.0.0.1:9050` |
| Run exploits | `proxychains -q python2 exploit.py` |

### Key Constraints of Proxychains

| Works ✅ | Doesn't Work ❌ |
|---|---|
| TCP connections (curl, nmap `-sT`, RDP, SSH, HTTP) | ICMP (`ping`) |
| Layer 7 application traffic | ARP |
| `-sT` connect scans | `-sS` SYN stealth scans |
