# Introduction to Linux Privilege Escalation

---

## Penetration Testing Methodology

![](attachments/Pasted%20image%2020260917094430.png)

The standard penetration testing workflow consists of five stages:

| # | Stage                    | Description                                                                                              |
|---|--------------------------|----------------------------------------------------------------------------------------------------------|
| 1 | **Initial Recon**        | Discover what the system is running — open services, active ports (Web, FTP, Mail, etc.)                 |
| 2 | **Initial Compromise**   | Identify a vulnerability and exploit it (SQLi, default SSH creds, weak passwords, etc.)                  |
| 3 | **Establish Foothold**   | Gain remote access to the target; RCE may take multiple steps before you get shell access                |
| 4 | **Escalate Privileges**  | Elevate from low-privilege access to root/administrator — **this is the focus of this course**           |
| 5 | **Complete Mission**     | Post-exploitation: maintain persistence, move laterally, exfiltrate data                                 |

> [!important] This course focuses on **Stage 4 — Escalate Privileges** on Linux systems.

---

## Why Privilege Escalation?

- **Initial access is never direct-to-root** — exploiting a service typically lands you as a low-privilege user (e.g., `www-data` from a web application exploit)
- Escalation is required to move beyond the standard/low-privilege user
- Requires extensive information gathering and enumeration about the target
- Followed by privilege escalation and lateral movement

### Limitations of a Low-Privilege Shell

When you land as a service account like `www-data`, your capabilities are severely limited:

- You can read some files, but **cannot move laterally** to other systems
- You **cannot change user passwords** or store persistent credentials
- You **cannot stop system services/programs** or disable firewalls
- No assigned home directory or interactive login shell

> To overcome these restrictions, you must **escalate privileges** — elevate your permissions, rights, and role to a user with higher system access.

## Privilege Escalation Goals

| OS      | Ultimate Goal                            |
|---------|------------------------------------------|
| Linux   | **root** access                          |
| Windows | **NT AUTHORITY\SYSTEM** or local administrator |

## Linux Account Types

![](attachments/Pasted%20image%2020260917094456.png)

| Account Type    | Access Level                                                                 | Usage                                                                                   |
|-----------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------|
| Root User       | Full access — can run any command, modify settings, edit files, install software | System administration tasks                                                             |
| Standard User   | Limited — cannot affect core system settings or other accounts               | Basic access for utilizing system resources                                             |
| Sudo User       | Standard user granted permissions to execute certain commands as root         | Every root-requiring command must be preceded with `sudo`                                |
| System Account  | Accounts for applications/services that perform specific tasks               | Restricted permissions to enhance security and control over system operations            |
| Guest User      | Temporary accounts with restricted and controlled privileges                 | Short-term access; no personal files or settings                                        |
| User Groups     | Permissions assigned to a logical collection of users                        | Admins manage permissions for an entire group instead of individual accounts             |

## Common Privilege Escalation Avenues

- Misconfigured services
- Improper file permissions
- Kernel vulnerabilities
- Super user exploits
- Sensitive information exposure

## Why Linux Dominates Servers

- **Highly customizable** — install services, make kernel-level changes, build your own kernel
- **Open source** — brings both customizability and robustness
- **Virus-resistant** — Linux viruses are extremely rare compared to Windows
- **Superior resource management** — excellent bandwidth, memory management, and flexibility
- ~99% of server OS market share is split between Linux and Windows

---

## Enumeration — The Key to Privilege Escalation

> [!tip] **Enumeration is the absolute key to privilege escalation.**

- After gaining a foothold, you must conduct **extensive internal enumeration** to discover:
	- **How** to escalate privileges
	- **Which** technique to apply
- Privilege escalation is rarely direct — it involves complex, multi-step techniques
- The same enumeration mindset used for initial access (ports, services) applies internally on the target host

### What This Course Covers

- Enumerating Linux systems for escalation paths
- Exploiting misconfigurations to escalate to root
- Understanding network operations during post-exploitation
- Managing connections and roles during lateral movement
