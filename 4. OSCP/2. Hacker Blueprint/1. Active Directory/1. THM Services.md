# THM Services

> **Platform:** TryHackMe — https://tryhackme.com/room/services
> **OS:** Windows (Active Directory)
> **Domain:** `services.local` — host `WIN-SERVICES`

> **Note on the target IP:** TryHackMe VPN, so the address rotated between sessions (`10.49.153.50` during recon, `10.48.147.252` later). Commands keep whichever was live — substitute your own.

## Attack Path Overview

1. **Recon** – DC with an IIS "Above Services" website.
2. **Username harvesting** – names from the website → AD permutations → Kerbrute validation → four valid users.
3. **AS-REP Roasting** – `j.rock` has pre-auth disabled; crack the AS-REP → `Serviceworks1`.
4. **Foothold** – WinRM as `j.rock` → user flag.
5. **Privilege escalation** – `j.rock` is in **`BUILTIN\Server Operators`**, which can reconfigure service binaries. Point a `LocalSystem` service at a reverse shell → SYSTEM.

## 5. Privilege Escalation — Server Operators → SYSTEM

Check group memberships — `j.rock` is in **`BUILTIN\Server Operators`**:

```powershell
whoami /all
```

> Members of `Server Operators` can **reconfigure Windows services**. If a service runs as `LocalSystem`, we can repoint its binary to our own payload and get SYSTEM when it starts.

List services whose config we can modify (Evil-WinRM's `services` command), then inspect one that runs as `LocalSystem`:

```powershell
services
```

```

----                                                                           ---------- -------          
C:\Windows\ADWS\Microsoft.ActiveDirectory.WebServices.exe                            True ADWS             
"C:\Program Files\Amazon\SSM\amazon-ssm-agent.exe"                                   True AmazonSSMAgent   
"C:\Program Files\Amazon\XenTools\LiteAgent.exe"                                     True AWSLiteAgent     
...
```

```powershell
sc.exe qc AWSLiteAgent
```

```
SERVICE_NAME: ADWS
        BINARY_PATH_NAME   : C:\Windows\ADWS\Microsoft.ActiveDirectory.WebServices.exe
        SERVICE_START_NAME : LocalSystem
```

> Confirm the chosen service's `SERVICE_START_NAME` is `LocalSystem` (`sc.exe qc <service>`) — that's what makes the swap land you at SYSTEM.

## Lessons Learned

- **Website → usernames → Kerbrute → AS-REP** is the canonical unauthenticated AD foothold chain.
- **Only accounts with `DONT_REQ_PREAUTH` are AS-REP roastable** — `GetNPUsers` tells you which of your candidates qualify.
- **`BUILTIN\Server Operators` is effectively SYSTEM.** Members can reconfigure any service's `binPath`; point a `LocalSystem` service at a payload and restart it.
- Always confirm the target service is `SERVICE_START_NAME : LocalSystem` before swapping its binary.
