# THM VulnNet: Roasted

> **Platform:** TryHackMe — https://tryhackme.com/room/vulnnetroasted
> **OS:** Windows (Active Directory)
> **Domain:** `vulnnet-rst.local` — host `WIN-2BO8M1OE1M1`
> **Theme:** the full Kerberos roasting workflow — AS-REP → NETLOGON loot → Kerberoast → DCSync.

> **Note on the target IP:** TryHackMe VPN, so the address rotated across the session (`10.49.130.76`, `10.48.142.135`, `10.48.132.120`, `10.48.133.219`, `10.49.144.185`, `10.48.131.119`, …). Commands keep whichever was live — substitute your own.

## Attack Path Overview

1. **Recon** – DC with anonymous SMB shares.
2. **Anonymous SMB** – business/enterprise text files leak four employee names.
3. **AS-REP Roasting** – `t-skid` has pre-auth disabled; crack → `tj072889*`.
4. **NETLOGON loot** – as `t-skid`, a `ResetPassword.vbs` logon script hardcodes `a-whitehat : bNdKVkjv3RR9ht`.
5. **Kerberoasting** – `t-skid` requests the SPN ticket for `enterprise-core-vn`; crack → `ry=ibfkfv,s6h,`.
6. **Domain Admin** – `a-whitehat` is a DA → WinRM for the user flag, then **DCSync** for the Administrator hash → Pass-the-Hash → root.


```vbscript
' Determine DNS domain name from RootDSE object.

' ... (the rest binds to the user over LDAP and calls objUser.SetPassword strPassword) ...
```

## Lessons Learned

- **Anonymous SMB shares leak names**, which seed the whole username → AS-REP/Kerberoast chain.
- **AS-REP roasting ≠ WinRM access.** `t-skid` cracked but couldn't WinRM — the creds were valuable only for *authenticated SMB/Kerberos*.
- **NETLOGON / SYSVOL scripts** (`.vbs`, `.bat`, `.ps1`) regularly hardcode credentials — always read logon scripts once you can authenticate.
- **Kerberoasting** against SPN accounts is the counterpart to AS-REP roasting; `MemberOf` in the `GetUserSPNs` output tells you whether the cracked account is immediately useful (e.g. `Remote Management Users`).
- **DCSync closes it out** whenever you land a Domain Admin — `secretsdump` dumps every hash; `secretsdump`'s trailing tracebacks are cosmetic.
