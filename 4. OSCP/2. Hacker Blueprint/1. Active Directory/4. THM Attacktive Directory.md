# THM Attacktive Directory

> **Platform:** TryHackMe — https://tryhackme.com/room/attacktivedirectory
> **OS:** Windows (Active Directory)
> **Domain:** `spookysec.local` — host `ATTACKTIVEDIREC` (`AttacktiveDirectory.spookysec.local`)

> **Note on the target IP:** TryHackMe VPN — mostly `10.48.155.187`, later `10.48.183.196`. Substitute your own.

## Attack Path Overview

1. **Recon** – standard DC; SMB allows null auth and leaks the domain name.
2. **User enumeration** – Kerbrute against the room's wordlist → valid users including `svc-admin` and `backup`.
3. **AS-REP Roasting** – `svc-admin` has pre-auth disabled; crack → `management2005`.
4. **SMB loot** – as `svc-admin`, a `backup` share holds `backup_credentials.txt` (base64) → `backup : backup2517860`.
5. **DCSync** – the `backup` account has replication rights → `secretsdump` dumps the Administrator hash → Pass-the-Hash.

```bash

```

Grab the user flag (`svc-admin` desktop) and the root flag (`Administrator` desktop) from the shell.

## Lessons Learned

- **AS-REP roasting still needs a username list** — Kerbrute against the provided wordlist seeds `GetNPUsers`.
- **A cracked AS-REP account may not WinRM** (`svc-admin` couldn't) — pivot to what its creds *can* do: authenticated SMB.
- **Loot every readable share.** `backup_credentials.txt` was plain base64 — decode, don't assume it's encrypted.
- **Dedicated "backup" accounts frequently have DCSync rights** — always check BloodHound's *Principals with DCSync privileges*.
- **DCSync → Pass-the-Hash** is the recurring AD endgame.
