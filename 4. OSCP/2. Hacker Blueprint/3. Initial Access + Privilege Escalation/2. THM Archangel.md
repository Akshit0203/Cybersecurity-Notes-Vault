This is an excellent question. Understanding this is important in web penetration testing because virtual hosting is a common reason a website looks different when you access it by IP versus by domain name.

Let's understand exactly what's happening.

## 1. One IP address can host multiple websites

Imagine one server is a building with multiple offices.

One web server

## 10.48.161.10

Apache listening on port 80

Website A

Default site — shown when you visit the IP

Website B

Mafialive — shown when the hostname matches

Apache can host both websites on the same IP address and port. It distinguishes them using the HTTP `Host` header.

## 2. What happens when you visit each address?

Case A — You enter the IP address

You visit:

```
http://10.48.161.10/
```

Your browser sends an HTTP request similar to:

```
GET / HTTP/1.1
Host: 10.48.161.10
```

Apache looks for a website configuration matching that host. If no specific virtual host matches, it usually serves the default website for that IP and port.

Case B — You enter the domain name

You visit:

```
http://mafialive.thm/
```

Your browser sends:

```
GET / HTTP/1.1
Host: mafialive.thm
```

The request reaches the same IP address, but Apache sees a different `Host` header and can serve a different website.

## 3. Why does ping show the original IP?

Because `/etc/hosts` tells your computer how to resolve the hostname:

```
10.48.161.10 mafialive.thm
```

So when you run:

```
ping mafialive.thm
```

your computer resolves `mafialive.thm` to `10.48.161.10`.

That resolution determines where the packets go, not which website Apache serves.

Think of it as two separate decisions:

- DNS or `/etc/hosts`: Which server should I contact?
    
- HTTP `Host` header: Which website do I want on that server?
    

## 4. Let's prove it in your lab

Run this command in Kali:

```
curl -s -H "Host: mafialive.thm" http://10.48.161.10/ | head -n 15
```

This connects directly to the IP but manually supplies the hostname in the HTTP request.

Condition A: Block a particular traversal string
```
!containsStr($_GET['view'], '../..')
```
The `!` means NOT. This condition passes only if the parameter does not contain the literal substring `../..`

The `&&` operator means both conditions must be true.

Condition B: Require a specific directory string
```
containsStr(
    $_GET['view'],
    '/var/www/html/development_testing'
)
```
The parameter must contain the specified directory path somewhere in the string.

Work-around :
The filter only blocks paths containing "**../..**" but allows other traversal sequences like "**..//..//**", and it only checks if the path contains the string "**/var/www/html/development_testing**", which can be bypassed by cleverly crafting the path to include that substring along with traversal sequences.
