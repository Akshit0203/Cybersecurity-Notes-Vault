# PayDay — Proving Grounds

> [!abstract] Summary
> PayDay is an intermediate Linux machine. The web service runs **CS-Cart 1.3.3**, whose admin panel accepts the default credentials `admin:admin`. CS-Cart's template/file manager allows writing a `.phtml` file to bypass the `.php` extension filter, giving a reverse shell as `www-data`. From there, the local user `patrick` reuses `patrick` as a password, and `sudo -l` shows `patrick` can run a root shell, giving root.

## Methodology

1. Scan all TCP ports and identify the web application.
2. Brute-force/guess the admin panel, then abuse the authenticated template manager for RCE.
3. Pivot to a local user via credential reuse.
4. Escalate to root via sudo privileges.

## Reconnaissance & enumeration

**Nmap scan** — a full TCP port scan reveals several open services:

- **Port 22:** SSH (`OpenSSH 4.6p1`)
- **Port 80:** HTTP (`Apache 2.2.4`, running **CS-Cart 1.3.3**)
- **Ports 110, 995, 143, 993:** POP3/IMAP
- **Ports 139, 445:** SMB (`MSHOME` domain, `PAYDAY` PDC)

**Web enumeration:**

- Directory scanning (Gobuster or Dirb) identifies an admin login panel at `/admin` (or `/admin/login.php`).
- Default administrative credentials work: `admin : admin`.

## Exploitation (authenticated RCE)

**Vulnerability:** CS-Cart 1.3.3 allows authenticated users with access to the template/admin manager to upload or edit template files.

**Gaining a shell:**

- Navigate to the template editor or file-upload section in the admin dashboard.
- Bypass the `.php` extension filter by naming the reverse-shell payload with a `.phtml` extension (e.g. `reverse.phtml`).
- Trigger/access the uploaded `.phtml` file via the web server to obtain a reverse shell as `www-data` (or `apache`).

## Lateral movement / user pivot

- Check system users via `/etc/passwd`, which reveals a user named `patrick`.
- Test weak/default credentials for `patrick` — the password matches the username: `patrick : patrick`.
- Log in or switch to `patrick` (via SSH or the shell) to grab the local user flag (`local.txt`).

## Privilege escalation (root)

Run `sudo -l` as `patrick` to inspect sudo permissions:

```bash
sudo -l
```

The configuration shows that `patrick` can run all commands or a root shell (`sudo /bin/bash` or `sudo su`) with no password / full privileges. Spawn a root shell:

```bash
sudo /bin/bash
```

Retrieve the final proof flag (`proof.txt` / root flag) from `/root`.

## Lessons learned

- Default credentials (`admin:admin`) and username-as-password (`patrick:patrick`) remain common on legacy CMS boxes — always test them before heavier brute-forcing.
- Extension-filter bypasses (`.phtml`, `.php5`, `.phar`) are a standard way past naive `.php` upload filters when the web server still executes them as PHP.
- Always run `sudo -l` immediately after landing any shell; a permissive sudoers entry is the fastest path to root.
