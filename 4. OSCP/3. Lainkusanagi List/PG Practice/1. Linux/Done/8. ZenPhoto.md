# ZenPhoto — Proving Grounds

> [!abstract] Summary
> ZenPhoto hosts the **ZenPhoto 1.4.1.4** gallery under `/test/` on port 80. That version (and all of 1.2.4 → 1.4.1.4) is vulnerable to an unauthenticated **remote code execution** in `ajax_create_folder.php` (EDB-18083), giving a shell as `www-data`. The box runs an old Ubuntu kernel, so privilege escalation is the **RDS protocol local root** kernel exploit (CVE-2010-3904, EDB-15285): compile it on the target and run it to become root.

**Target:** `192.168.143.41`

## Methodology

1. Scan all TCP ports; identify the web server and MySQL.
2. Directory-brute the web root and find the ZenPhoto install under `/test/`.
3. Fingerprint the ZenPhoto version from the page source and exploit the `ajax_create_folder.php` RCE.
4. Transfer and compile the RDS kernel exploit on the target; run it for root.

## Exploitation — ZenPhoto RCE (EDB-18083)

> [!info] Vulnerability
> All ZenPhoto versions from **1.2.4 through 1.4.1.4** are affected by a remote code execution flaw in `zp-core/full-image.php` / `ajax_create_folder.php` (fixed in 1.4.1.5). The parameters are not sanitised and reach a command sink, so an unauthenticated attacker gets code execution as the web user.

Reference exploit repo (CVE-2011-4825): https://github.com/XavLimSG/Zenphoto-1.4.1.4-CVE-2011-4825-RCE

Using the public RCE (EDB-18083) against the `/test/` path:

```
# EDB-18083 — ZenPhoto <= 1.4.1.4 Remote Code Execution
searchsploit -m 18083
# set RHOST/target and the /test/ path inside the script, start a listener, run it
nc -nvlp <port>
python 18083.py 192.168.143.41 /test/
```

This yields a reverse shell as `www-data`.

## Privilege escalation — RDS kernel exploit (CVE-2010-3904)

With a `www-data` shell on an old 2.6.x kernel, a kernel-suggester (e.g. `linux-exploit-suggester`) flags the **RDS protocol** local privilege escalation as highly probable.

###### ==🔴CVE: CVE-2010-3904 | Name: rds ==

http://www.exploit-db.com/exploits/15285

> [!info] What CVE-2010-3904 is
> A flaw in the Linux kernel's **RDS (Reliable Datagram Sockets)** protocol implementation lets an unprivileged local user write to arbitrary kernel memory and escalate to root. Affected kernels are roughly 2.6.30 → 2.6.36-rc8 — which matches this box's Ubuntu 10.04 kernel.

download and transfer to victim linux first 

then on victim linux : 
```
gcc 15285.c -o exploit
chmod +x exploit
/exploit
```

Running the compiled exploit drops a root shell. Read `/root/proof.txt`.

> [!tip] Alternative privesc
> Given the kernel age, **Dirty COW (CVE-2016-5195, EDB-40839)** is another reliable local-root on this box if the RDS exploit is unstable. Kernel exploits can hang or panic the target — snapshot/expect a revert.

## Lessons learned

- Fingerprint web-app **versions** precisely (from `/test/` page source here). ZenPhoto 1.4.1.4 maps directly to a public RCE.
- The service banners tell you the OS era — OpenSSH 5.3 / Apache 2.2.14 / CUPS 1.4 scream "old Ubuntu, old kernel," which is the signal to go for a kernel privesc.
- Always run a kernel-exploit suggester on legacy boxes; CVE-2010-3904 (rds) and Dirty COW are the usual suspects for 2.6.x kernels.
- Compile kernel exploits **on the target** when possible to avoid libc/architecture mismatches.
