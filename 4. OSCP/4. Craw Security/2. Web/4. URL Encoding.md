
# URL Encoding (Percent-Encoding) — Complete Guide

## What is URL Encoding?

**URL Encoding** (also called **Percent-Encoding**) is the process of converting characters into a format that can be safely transmitted in a URL.

- Some characters have **special meanings** in URLs.
- Some characters are **not allowed** at all.
- URL encoding replaces these characters with a **% followed by two hexadecimal digits** representing their ASCII value.

Example:

```
Space
↓
ASCII = 32
Hex = 20

Encoded:
%20
```

Example:

```
Hello World

↓

Hello%20World
```

---

# Why is URL Encoding Needed?

Without encoding, browsers and web servers cannot correctly interpret certain characters.

Example:

```
https://example.com/search?q=red shoes
```

The browser may interpret this as:

```
q = red
```

and

```
shoes
```

becomes something unexpected.

Instead:

```
https://example.com/search?q=red%20shoes
```

Now the server knows the search term is:

```
red shoes
```

# Reserved Characters

These characters control the structure of URLs.

|Character|Meaning|
|---|---|
|:|Protocol separator|
|/|Directory separator|
|?|Starts query string|
|&|Separates parameters|
|=|Assigns parameter value|
|#|Fragment|
|%|Escape character|
|+|Space (sometimes in forms)|

Example

```

```

Here

```
?
```

starts parameters.

```
&
```

separates parameters.

```
=
```

assigns values.

# Space Encoding

This is one of the most confusing topics.

## Method 1

```
Space

↓

%20
```

Most URLs use this.

Example

```
Hello World

↓

Hello%20World
```

---

## Method 2

HTML Forms use:

```
+
```

Example

```
name=John+Doe
```

The server converts

```
+
```

into

```
Space
```

So

```
John+Doe
```

becomes

```
John Doe
```

# Security Perspective (Important for Pentesting)

URL encoding is frequently encountered in web application testing.

### 1. Bypassing Input Filters

Applications may block a literal string like:

```
../
```

An attacker may try:

```
..%2F
```

or double-encoded:

```
..%252F
```

to see if the application decodes the input multiple times.

---

### 2. Directory Traversal

Normal request:

```
GET /../../etc/passwd
```

Encoded request:

```
GET /..%2F..%2Fetc%2Fpasswd
```

Some vulnerable applications decode the path and process it as:

```
../../etc/passwd
```

---

### 3. XSS Testing

Instead of sending:

```
<script>
```

an attacker may send:

```
%3Cscript%3E
```

If the application decodes and reflects it without proper output encoding, it may contribute to an XSS vulnerability.

---

### 4. SQL Injection

Instead of:

```
'
```

an attacker may send:

```
%27
```

Example:

```
?id=1%27%20OR%201=1--
```

The server decodes it to:

```
?id=1' OR 1=1--
```

---

### 5. WAF Evasion

Some web application firewalls inspect requests before decoding them or only decode once. Attackers sometimes experiment with different encodings (including double encoding) to test whether malicious payloads slip past inspection. Well-designed WAFs normalize and decode inputs before applying detection rules.

# Best Practices

- Encode user input before placing it in a URL.
- Decode input only once on the server unless there's a specific reason otherwise.
- Don't confuse URL encoding with HTML encoding, Base64 encoding, or encryption—they serve different purposes.
- Validate and sanitize decoded input on the server side.

---

# URL Encoding vs HTML Encoding vs Base64

|Feature|URL Encoding|HTML Encoding|Base64|
|---|---|---|---|
|Purpose|Safe transmission in URLs|Safe display in HTML|Binary/text representation|
|Example|`%3C`|`&lt;`|`PHNjcmlwdD4=`|
|Reversible|Yes|Yes|Yes|
|Encryption|❌ No|❌ No|❌ No|
|Main Use|URLs, query strings|Web pages|Data transport/storage|

---

# Key Takeaways

- URL encoding (percent-encoding) converts unsafe or reserved characters into `%HH`, where `HH` is the hexadecimal value of the byte.
- Reserved characters such as `?`, `&`, `=`, `/`, and `#` have special meanings in URLs and should be encoded when they are intended to be data rather than URL syntax.
- Spaces are typically encoded as `%20`; HTML form submissions often use `+` in query parameters.
- Browsers automatically URL-encode many characters before sending requests.
- In web security testing, understanding URL encoding is essential for analyzing requests, identifying normalization issues, and testing how applications handle encoded input.
