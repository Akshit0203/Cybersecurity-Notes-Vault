## 1. Note-Making

### Why notes matter
- Builds discipline and **documentation habits**.
- In professional security you must **report findings** in a standardized, easy-to-understand format — including for **non-technical stakeholders**.

### How to take them
- Prefer **digital e-notes** over handwritten (any app; instructor uses **Microsoft OneNote**).
- Reference: instructor's OSCP notes structure → GitHub link in pinned tweet on Twitter **`TechHacker98`**; also a YouTube video on organizing notes in OneNote.
- Keep a clear **hierarchy**, e.g.:

```
Active Directory
├── AD Basics
│   ├── What is Active Directory
│   ├── Domain Controllers (DCs)
│   ├── Organizational Units (OUs)
│   └── Groups & other directory components
├── AD Enumeration
│   ├── User enumeration
│   └── Computer enumeration
├── AD Exploitation
│   └── Sequential exploitation steps / attack workflows
├── Post-Exploitation & Domain Persistence
│   ├── Harvesting Kerberos tickets
│   ├── Extracting cached credentials
│   └── Abusing specific network protocols
├── Lateral Movement
├── Persistence Mechanisms
├── Credential Harvesting
└── Lab Walkthroughs (one per lab solved)
```

### Rules for good notes
- **Concise and precise** — no copied book chapters, pasted articles, or bloated paragraphs.
- Written in **your own words** that trigger instant recall.
- During a live pentest you won't have time to read paragraphs → use **cheat sheets, mind maps, bullet points** with tools, commands, and hard-to-memorize syntax.
- Write **complete step-by-step walkthroughs** for every lab challenge.
- Document **continuously** while learning — don't wait until the end.

## 4. Be Tool-Agnostic

> [!tip] The **concept** stays the same — only the **syntax/tooling** changes.

| Task | Shown in course | Alternatives |
|---|---|---|
| Credential dumping / ticket creation | **Mimikatz**, **Impacket** | **Rubeus** (ticket manipulation) |
| Pivoting | **Chisel** | **Socat**, **Netcat**, **pwncat**, native **SSH port forwarding** |

- No spoon-feeding: the course shows the path — you walk it.
- Be innovative, do your own research, try to find better workflows than those taught.
- Active Directory is a whole universe — this course is only the tip of the iceberg.
