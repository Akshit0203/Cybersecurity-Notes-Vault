# LAN Manager (LM) Hash

---

## What Is the LM Hash?

- A **one-way hash function** (technically a cryptographic hash algorithm) used by Microsoft **before** NTLM was introduced.
- Applied to user passwords during account creation to generate a hash for storage.
- **Major flaw**: Not truly one-way — it can be reversed / cracked trivially.

---

## How LM Hashing Works

1. The input password is **padded to 14 bytes** (null-padded if shorter).
2. The 14-byte string is **split into two 7-byte halves**.
3. Each 7-byte half is encrypted **independently** using the **DES** algorithm with separate keys.

```
Password (up to 14 chars)
    │
    ▼
Pad to 14 bytes (null-fill if needed)
    │
    ├── First 7 bytes  ──► DES encrypt (Key A) ──► Hash Part 1
    └── Last  7 bytes  ──► DES encrypt (Key B) ──► Hash Part 2

LM Hash = Hash Part 1 + Hash Part 2
```

---

## Why LM Is Weak

| Weakness | Impact |
|---|---|
| Password split into two independent 7-byte halves | Attacker cracks each half separately — drastically reduces keyspace |
| Uses **DES** encryption | DES was publicly cracked in **1999**; extremely weak by modern standards |
| Max 14 characters | Limits password complexity |
| Case-insensitive | Converts all characters to uppercase before hashing, further reducing keyspace |

> [!CAUTION]
> LM hashes are trivially brute-forced. A 14-character LM hash can be cracked in seconds on modern hardware.

---

## Current Status

- **Disabled by default** starting from **Windows Vista** and all later Windows versions.
- In the SAM file, the LM hash field is **blank / empty** on modern systems.
- Superseded by the much stronger **NTLM** hashing algorithm.

### SAM Entry with LM Disabled

```
Username : RID : <blank LM hash> : NTLM Hash
```
