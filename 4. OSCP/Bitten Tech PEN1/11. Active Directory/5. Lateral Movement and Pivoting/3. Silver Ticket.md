# Pass the Ticket — Silver Ticket

## Overview

- A Silver Ticket is a **valid, forged TGS** (service ticket) for a service, created once the **NTLM hash of the service account is owned**.
- It grants access to that service as **any user with any permission**.
- Works across multiple servers if the same SPN is registered on them.

**Requirements to forge a Silver Ticket**
- Domain SID
- Username
- Domain name
- Service name (SPN)
- Password hash of the service account

## Concept — Forging a Service Ticket (TGS)

In Pass-the-Ticket, two concepts arise: **Golden Tickets** and **Silver Tickets**. For lateral movement we focus on **Silver Tickets** (Golden Tickets are used for persistence).

Normally in Kerberos you receive a TGT, then specify an SPN to request a **service ticket** (TGS / `TGS-REP`), which is encrypted with the service account's hash — you cannot decrypt it and must crack it offline.

It **is** possible to forge a TGS yourself if you gather a few details. The difference between a forged ticket and a legitimate one: a legitimate ticket explicitly states your real User ID and IP, so the service knows exactly which user is requesting access. When you forge it yourself, **you can set any User ID** — meaning you can gain access to any service on behalf of any arbitrary user with any privilege level. Access as an administrator yields elevated privileges; a standard user yields limited permissions.

## Silver Ticket Prerequisites (Enumeration)

The obvious target user is **Administrator**. The SPN is critical — you must supply it when generating the ticket, and the attack works across multiple servers if that SPN is registered on them.

- **Domain SID** — obtained during enumeration.
- **Username** — discovered during enumeration.
- **Domain name** — simple to obtain.
- **Service name (SPN)** — uncovered via enumeration.
- **Password hash of the service account** — acquired post-exploitation once you have local admin rights (dump SAM database or crack it).

## Why Forge Instead of Pass-the-Hash? (RID 500)

If you obtain a service account's hash, that account is **not necessarily** a local administrator or member of an admin group. A non-administrative service account cannot be used for standard Pass-the-Hash (which strictly requires administrative accounts).

Instead, forge a Silver Ticket and specify the user as **Administrator**, whose built-in **Relative ID (RID) is 500**. In whichever tool you use, you specify the user is Administrator with RID 500. This assigns your forged ticket membership in high-value administrative groups.

## Exploiting Service Trust

When you pass this ticket to the target service, it **trusts the ticket blindly** — the service does not independently verify group permissions. It relies entirely on ticket validation, leaving verification to the KDC / Domain Controller. We exploit this architectural design to forge a ticket on behalf of an administrator identity we don't actually hold, granting elevated permissions on that service.

If that service runs on a remote system with an active SPN, we obtain administrative privileges on it — a network share, file server, or web server. With admin privileges we can perform administrative interactions or spawn a shell on the target.

## Silver Ticket Attack — Explained Simply

A Silver Ticket attack forges a Kerberos **service ticket** to access a specific service on a machine **without contacting the Domain Controller** to obtain that ticket. Think of it as creating a fake entry ticket for one particular room inside a building.

![](Pasted%20image%2020261009125422.png)

Example environment:
- **Domain Controller (DC):** the security office that manages authentication.
- **File Server:** a room containing confidential files.
- **Attacker:** someone who has stolen a service account's password hash.

How the attack works:
1. **Steal a service account hash** — obtain the NTLM hash of an account associated with a service (e.g. a file server's CIFS service).
2. **Forge a service ticket** — use that hash to create a fake Kerberos service ticket (the Silver Ticket).
3. **Present the ticket to the service** — present it directly to the target service, without requesting it from the DC.
4. **Potential unauthorized access** — if the service accepts the ticket and the forged identity has suitable permissions, the attacker may access protected resources.

### Why "Silver" Ticket?

| Ticket | Purpose |
|---|---|
| TGT (Ticket-Granting Ticket) | Used to request tickets for services |
| TGS (Service Ticket) | Used to access a particular service |

A Silver Ticket is a **forged TGS service ticket**, forged for a particular service using the secret key of that service account or computer account.

### Silver Ticket vs. Golden Ticket

| Feature | Silver Ticket | Golden Ticket |
|---|---|---|
| Forged ticket | TGS | TGT |
| Secret typically needed | Target service account's key/hash | `krbtgt` account's key/hash |
| Scope | Typically a specific service | Can request tickets for many domain services |
| Must contact DC to obtain the forged ticket? | No | No |
| Main concern | Unauthorized access to a target service | Potentially broad domain-wide access |

Memory trick:
- **Silver = Service ticket.**
- **Golden = TGT ticket.**

### Why is it hard to detect?

A forged Silver Ticket is presented directly to a service, so the DC may not see the normal ticket-request exchange. It is **not invisible**, though — the target server can generate security events, and defenders can look for suspicious logons, unusual group memberships, inconsistent ticket details, and abnormal service-account activity.

### Defense

- Use long, random passwords for service accounts and managed service accounts where possible.
- Rotate compromised service-account credentials and computer-account secrets.
- Apply least privilege to service accounts.
- Monitor Windows security logs on target servers, especially suspicious logons and service access.
- Investigate unusual privileged group memberships or ticket behavior.

**One-line takeaway:** a Silver Ticket attack uses a compromised service-account secret to forge a Kerberos ticket and access a specific service without obtaining that ticket from the Domain Controller.
