# Introduction to Domain Controller

---

## What is a Domain?

A **domain** refers to a set of entities that are interrelated, work together, and are considered a **single administrative unit**.

**Example:** Google owns `google.com`, `google.com.au`, `google.co.uk`, `google.co.in` — within a single domain like `google.com`, all components are interrelated and managed as one unit.

Within a domain:
- Multiple servers and sub-networks can exist
- Web servers, file servers, and various shared resources between PCs
- Complex operations: file sharing, user authentication, group permissions, offline management

> [!important] Key Idea
> To maintain all these functions, there must be an **administrative authority** to execute admin actions and hold admin rights across the domain. That authority is the **Domain Controller**.

---

## What is a Domain Controller (DC)?

A **Domain Controller** is a server that responds to security authentication requests within a Windows Server domain.

```
Domain Controller (DC)
├── Stores AD database (NTDS.dit)
├── Authenticates users
├── Stores user account information
│   ├── Username, full name, department
│   ├── Phone number, contact details
│   └── Password credentials
├── Enforces security policies
│   ├── Access boundaries & rules
│   ├── Roles & privilege levels
│   └── Regulations within the domain
├── Handles Kerberos / LDAP
└── Replicates AD data with other DCs
```

> The DC is the **centerpiece** of the Windows Active Directory service — it acts like the "brain" for a Windows Server domain.

## DC in a Network Environment

A network environment involves many components:

| Component | Examples |
|-----------|----------|
| Workstations | Client PCs where users work |
| Servers | Web server, file server, DNS server, Samba server |
| Protocols | SMB, NetBIOS, NTLM, Kerberos |
| Platform | Microsoft Windows (used in ~90% of industrial cases) |

```
               Domain Controller
                      │
         ┌────────────┼────────────┐
         ▼            ▼            ▼
      PC-01         PC-02       FILE-SRV
   (workstation)  (workstation)  (server)
```

---

## What Does a DC Store?

The DC authenticates users and stores **user account information**:

- Username, full name, department
- Phone number, contact details
- Password credentials (hashed)

It enforces **security policies** within the enterprise:
- Access boundaries
- Rules and regulations
- Roles and privilege levels

## Primary vs. Secondary Domain Controllers

DC capabilities originated with **Windows 2000**.

| Type | Role |
|------|------|
| **Primary Domain Controller** | Main DC handling writes and authentication |
| **Secondary / Backup DCs** | Provide redundancy and load balancing |

As technology evolved, Microsoft introduced **Active Directory** as a superior architecture for distributed administration — a core service executed **inside** the Domain Controller.

```
Windows Server
    │
    └── AD DS role installed
            │
            ▼
      Domain Controller
            │
            ├── Active Directory
            ├── Administrative roles & features
            └── Domain control & administration
```

> [!note] Key Distinction
> - **DC** = a physical/virtual server where we add administrative roles, features, and Active Directory
> - **AD** = the directory service/software running on the DC
> - A Domain Controller **hosts** Active Directory; AD is not "inside" a DC as a physical container
