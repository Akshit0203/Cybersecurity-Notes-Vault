# LAB — Extracting Credentials From Common Windows Locations

> [!abstract] TL;DR
> Credential harvesting = gathering any sensitive authentication material (passwords, NTLM hashes, Kerberos TGT/TGS, SSH/private keys) to enable lateral movement. The primary goal is to acquire credentials of other accounts to pivot from one host to another. **Local admin on a host is the prerequisite** for most harvesting methods. This task covers the common locations where credentials are stored — focusing on the **Windows Registry** and **AD user descriptions**.

## Credential Access — Concept (MITRE ATT&CK TA0006)

Adversaries find credentials on compromised systems to reuse them or impersonate a user. This is essential for lateral movement and accessing other resources. **Obtaining legitimate user credentials is preferred over exploiting systems with CVEs.**

Credentials are not just passwords — they include Kerberos tickets, cleartext passwords, cryptographic hashes, SSH keys, and any other authentication material needed to move laterally.

### Where credentials are stored (sources)

- **Clear-text files** — MITRE *Unsecured Credentials: Credentials In Files* ([T1552.001](https://attack.mitre.org/techniques/T1552/001/))
- **Database files**
- **Memory** (e.g. LSASS)
- **Password managers**
- **Enterprise Vaults**
- **Active Directory**
- **Network Sniffing**

### Clear-text file types worth hunting

- Command history
- Configuration files (Web App, FTP, etc.)
- Windows application files (browsers, email clients)
- Backup files (web backups, SSH backups, cron job backups)
- Shared files and folders
- Registry
- Source code (passwords left in code or comments)

## Command History

PowerShell saves executed commands to a per-user history file by default (unless explicitly disabled). Inspecting it can reveal cleartext credentials passed on the command line — analogous to checking `.bash_history` on Linux.

```
C:\Users\USER\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
```

## Searching the Windows Registry for Passwords

Various programs store configuration and credentials directly in the Registry (instead of the cleartext file system) so they can be queried on demand — making it a high-value, "juicy" source.

The native **`reg`** utility supports `query` (search/retrieve) and `add` (create/update). Registry root keys (hives):

| Hive | Full name | Contains |
|---|---|---|
| `HKLM` | `HKEY_LOCAL_MACHINE` | Local machine configuration and settings |
| `HKCU` | `HKEY_CURRENT_USER` | User-specific config/app data for the current account |

### `reg query` switches

- **`/f`** — exact search string (e.g. `password`)
- **`/t`** — restrict search by data type (e.g. `REG_SZ`)
- **`/s`** — search recursively through all subkeys

### Search the local machine hive

Returns all strings containing "password" recursively:

```
reg query HKLM /f password /t REG_SZ /s
```

A broad search at the root of `HKLM` scans the whole hive and returns a large volume of default system keys (294 matches in the lab) — most are noise, but filtering reveals a custom key:

```
HKEY_LOCAL_MACHINE\SYSTEM\DriverDatabase\DriverPackages\ehstorpwddrv.inf_amd64_fb92106dd2773d21\Strings
    devicename    REG_SZ    Microsoft supported IEEE 1667 password silo

HKEY_LOCAL_MACHINE\SYSTEM\THM
    flag    REG_SZ    password: 7tyh4ckm3

End of search: 294 match(es) found.
```

### Search the current-user hive

Same syntax against `HKCU`:

```
reg query HKCU /f password /t REG_SZ /s
```

## Database Files

Applications store settings, configurations, and credentials in local database files — an excellent target to hunt for credentials. (Example referenced: extracting credentials from a local McAfee Endpoint database file in the *Breaching AD* room.)

## Password Managers

Store and manage login info. Examples:

- Built-in password managers (Windows)
- Third-party: KeePass, 1Password, LastPass

Misconfigurations and security flaws can let adversaries access stored data. Various tools can dump sensitive data from browser and desktop password managers. (Windows Credential Manager is covered in a later task.)

## Memory Dump

The OS memory is a rich source of sensitive data belonging to the OS, users, and applications. Access is limited to administrator users. Examples of in-memory data:

- Clear-text credentials
- Cached passwords
- AD tickets

## Active Directory Misconfigurations That Leak Credentials

- **Users' description** — admins set a new-employee password in the description and forget to remove it.
- **Group Policy SYSVOL** — leaked encryption keys let attackers access admin accounts (vulnerable GPP; see LAPS task).
- **NTDS** — contains all AD users' credentials; prime target.
- **AD Attacks** — misconfigurations enable Kerberoasting, AS-REP Roasting, etc.

## Network Sniffing

Man-in-the-Middle attacks against network protocols let an attacker spoof trusted resources to steal authentication info such as NTLM hashes (e.g. LLMNR/NBT-NS poisoning, NTLM relaying).

```
powershell
```
