# Bash Comments, Quotes, and Command Substitution

---

## Variables — Quick Intro

### Declare and Print a Variable

```bash
#!/bin/bash

name="Akshit"

echo $name
echo "Hello $name"
```

```
└─$ ./new.sh
Akshit
Hello Akshit
```

### Read User Input with `read`

```bash
#!/bin/bash

echo "enter your name: "
read name

echo "Hello $name"
```

```
└─$ ./new.sh
enter your name: 
Akshit
Hello Akshit
```

**How `read` works:**

- `read` is a **Bash built-in** that takes input from **stdin** (keyboard) and stores it in the variable you specify.
- `read name` → "Read whatever the user types, store it in `name`."
- Pressing **Enter** signals the end of input.

```
Keyboard → stdin → read → name = "Akshit"
```

> `read` performs the assignment itself — no `name="..."` syntax needed.

### ⚠️ No Spaces Around `=` in Assignments

```bash
# ✅ Correct
name="Akshit"

# ❌ Wrong — Bash sees three words: command "name", arg "=", arg "Akshit"
name = "Akshit"
# Error: name: command not found
```

**Why?** Bash uses **whitespace to separate tokens**. Without spaces, `name="Akshit"` is a single assignment token. With spaces, Bash interprets `name` as a command to execute.

| Syntax | Bash Interprets As |
|--------|--------------------|
| `name="Akshit"` | variable `name` ← value `"Akshit"` |
| `name = "Akshit"` | command `name`, args `=` and `"Akshit"` |

> Spaces **inside** the value are fine: `name="Akshit Sharma"` works because quotes protect internal spaces.

## Comments

### Single-Line Comments (`#`)

```bash
#!/bin/bash

#this is a comment
echo "enter your name: "
read name

echo "Hello $name"
```

Comments are ignored by the interpreter — used only for programmer documentation.

### Multi-Line Comments

#### Option 1 — Here-Document (`<<`)

```bash
#!/bin/bash

<<Comments

comment line 1
comment line 2
comment line 3

Comments

#this is a comment
echo "enter your name: "
read name

echo "Hello $name"
```

> Start with `<<WORD`, end with the same `WORD` on its own line. Everything in between is a comment.

#### Option 2 — Colon + Single Quotes (`: '...'`)

```bash
#!/bin/bash

: '

comment line 1
comment line 2
comment line 3

'

#this is a comment
echo "enter your name: "
read name

echo "Hello $name"
```

> `: '` opens the block, a lone `'` closes it. **Space after `:` is required.**

---

## Single Quotes vs. Double Quotes

| Feature | Single Quotes `' '` | Double Quotes `" "` |
|---------|---------------------|---------------------|
| Variable expansion (`$var`) | ❌ Literal `$var` printed | ✅ Value substituted |
| Command substitution (`$(...)`) | ❌ Literal text printed | ✅ Command executed |
| Backslash escaping | ❌ | ✅ |
| Use case | Hardcoded literal strings | Strings with variables/commands |

**Example — Double quotes expand, single quotes don't:**

```bash
name="Akshit"

echo "Hello $name"   # → Hello Akshit
echo 'Hello $name'   # → Hello $name  (literal)
```

> **Rule of thumb:** Use double quotes when you need expansion; use single quotes when you want everything printed literally.

## Command Substitution (Inline Execution)

Run a command and capture its output — either inline in a string or stored in a variable.

### Syntax 1 — `$(command)` (Recommended)

```bash
#!/bin/bash

echo "Hello $(hostname)"
```

```
└─$ ./new.sh
Hello kali
```

### Syntax 2 — Backticks `` `command` ``

```bash
#!/bin/bash

echo "Hello `hostname` "
```

```
└─$ ./new.sh
Hello kali
```

### Storing Command Output in a Variable

```bash
#!/bin/bash

name=$(hostname)
echo "Hello $name "
```

```
└─$ ./new.sh
Hello kali
```

Equivalent with backticks:

```bash
name=`hostname`
echo "Hello $name "
```

```
└─$ ./new.sh
Hello kali
```

### Another Example — `who` Command

```bash
#!/bin/bash

name=$(who)
echo "Hello $name "
```

```
└─$ ./new.sh
Hello kali     seat0        2026-08-17 09:50 (:0)
```

### Why `$()` Is Preferred Over Backticks

**Nestability** — `$()` can be nested cleanly; backticks require escaping and become unreadable:

```bash
#!/bin/bash

# Nested command substitution — clean with $()
name=$(hostname -i $(command2))

# Same thing with backticks — messy escaping required
name=`hostname -i \`command2\``
```

> **Best practice:** Always use `$()` — it's more readable, nestable, and modern.
