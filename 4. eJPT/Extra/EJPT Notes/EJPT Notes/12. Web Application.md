- Web applications are softwares run on the web servers and can be accessed in the internet through browser.
- It is interactive and data is dynamic.
- Eg: Social media platform, LMS, email platform etc.

**How do web applications work**:
- It uses client server model.
- Data and logic hosted in web server.
- UI will have HTML, CSS and JS with some frameworks.
- Users will send requests to web apps and the response will be sent from the web server to user's browser.
- Has cross-platform compatibility.
- HTTP protocol is stateless, so the web apps should maintain the session.

**Web Application Security**:
- It is a critical aspect of cybersecurity that focuses on identifying vulnerabilities, threats and attacks.
- Primary objective is to ensure CIA of data and mitigating the risks.

**Web app security is crucial**:
- Protection of Sensitive Data
- Safeguarding User Trust
- Prevention of Financial Losses
- Compliance and Regulatory Standards
- Mitigation of Cyber Threats
- Protection against DDOS
- Maintaining Business Continuity
- Prevent Defacement and Data Manipulation

### Passive Crawling using Burp Suite:

**Crawling**:
- It is the process of navigating around the web application, following links, submitting forms and logging in.
- It is a passive process and is done via publicly accessible contents.
- It is to map out the application to better understand.

**Spidering**:
- It is the process of automatically discovering new resources(URLs) on a web app.
- It begins with a list of target URLs called seeds.
- Then the hyperlinks of those pages were collected and same is done recursively.
- It is loud and it is a active information gathering.
- We can use owasp ZAP to spider the applications.

Now to passive crawl using burp, we have to turn on burp proxy but should keep intercept off.
Then we just have to test all functionalities in the web app, all requests will be recorded in burp.
We can check it in Target -> Sitemap


### Active Spidering using OWASP ZAP:

- Goto Tools --> Spider.
- There select the site.
- Enable recurse and show advanced options
- Now run it. It will spider all the links.
- We can also export it.
- Also we can visit sitemap to see all spidered info.

### Important Tips:
- In web application, always do directory bruteforcing with dirb.
- If found a endpoint called **/uploads**, then try to upload webshell to it using curl. Also webdav enabled , then you can upload file using PUT method.
- Now get a reverse shell.
- Try LFI on every parameter, `../../../../flag.txt`. Mainly on parameter that fetch file.
- For bruteforcing web login use this cmd. `hydra -L /usr/share/seclists/Usernames/top-usernames-shortlist.txt -P /root/Desktop/wordlists/100-common-passwords.txt target.ine.local http-post-form "/login:username=^USER^&password=^PASS^:F=Invalid username or password"`
- Here /login is the endpoint where login panel is there. `username` and `password` are the parameters and `F` is to specify the keyword not to match. If the response doesn't have the keyword **"Invalid username or password"**, then it will give us the result.
- Even if you find the login creds of a login panel, always try **SQLi** , no matter what.
