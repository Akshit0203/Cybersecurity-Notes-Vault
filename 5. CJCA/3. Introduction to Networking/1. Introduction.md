## Networking Overview

A network enables two computers to communicate with each other. There is a wide array of `topologies` (mesh/tree/star), `mediums` (ethernet/fiber/coax/wireless), and `protocols` (TCP/UDP/IPX) that can be used to facilitate the network.

> [!IMPORTANT] Why This Matters for Security
> When the network fails, the error may be silent, causing us to miss something. Understanding networking is fundamental for security professionals.

Setting up a large, flat network is not extremely difficult, but a flat network is like building a house on a land plot and considering it secure because it has a lock on the door. By creating lots of smaller networks and having them communicate, we can add defense layers. Pivoting around a network is not difficult, but doing it quickly and silently is tough and will slow attackers down.

---

### Network Segmentation — Why It Matters

#### Example 1 — Access Control Lists

Building smaller networks and putting ACLs around them is like putting a fence around the property's border that creates specific entry and exit points. An attacker could jump over the fence, but this looks suspicious and is not common, allowing it to be quickly detected. *Why is the printer network talking to the servers over HTTP?*

#### Example 2 — Documentation & Visibility

Mapping out and documenting each network's purpose is like placing lights around the property. *Why is the printer network talking to the internet at all?*

#### Example 3 — Intrusion Detection

Having bushes around windows is a deterrent — just like IDS tools like Suricata or Snort deter network scans. *Why did a port scan originate from the printer network?*

These examples may sound simple, but if the printer is on a "flat /24 network" and gets a DHCP address, it can be challenging to place these restrictions.

## Story Time — A Pentester's Oversight

Most networks use a `/24` subnet, so much so that many Penetration Testers will set this subnet mask (`255.255.255.0`) without checking. The `/24` network allows computers to talk to each other as long as the first three octets are the same. Setting the subnet mask to `/25` divides this range in half.

A pentest report claimed a Domain Controller was offline when it was just on a different network:

- Server Gateway: `10.20.0.1/25`
- Domain Controller: `10.20.0.10/25`
- Client Gateway: `10.20.0.129/25`
- Client Workstation: `10.20.0.200/25`
- Pentester IP: `10.20.0.252/24` (Set Gateway to `10.20.0.1`)

The Pentester communicated with the Client Workstations and managed to steal a workstation password via Impacket. However, due to a failure to understand the network, they never managed to get off the Client Network and reach more "high value" targets such as database servers.

The entire internet is based on many subdivided networks, as shown above marked as "`Home Network`" and "`Company Network`."

### URL vs. FQDN

- An `FQDN` (`www.hackthebox.eu`) only specifies the address of the "building"
- A `URL` (`https://www.hackthebox.eu/example?floor=2&office=dev&employee=17`) also specifies the "floor," "office," "mailbox" and the corresponding "employee"

### How Data Flows — Post Office Analogy

Our `router` is the post office we utilize to connect to the "Internet." The packet is forwarded to the `main post office` (`ISP`), which looks in the `address register` (`DNS`) where this address is located and returns the corresponding `IP address`. Now the packet is sent directly there. The web server sends us back the packet via the `router` of the "Company Network" to the specified return address (`our IP address`).

## Network Segmentation Best Practices

In the diagram above, the company network should ideally consist of **five separate networks**:

1. **Web Server → DMZ** — Clients on the internet can initiate communications with the website, making it more likely to become compromised. Placing it in a separate network allows putting networking protections between the web server and other devices.
2. **Workstations → Own Network** — Ideally each workstation should have a Host-Based Firewall rule preventing it from talking to other workstations. If a Workstation is on the same network as a Server, attacks like `spoofing` or `MITM` become much more of an issue.
3. **Switch and Router → Administration Network** — Prevents workstations from snooping on communication between these devices. `OSPF` advertisements on an untrusted network could allow `MITM` attacks against any network.
4. **IP Phones → Own Network** — Prevents computers from eavesdropping on communication. Placing them on their own network allows prioritizing traffic to prevent high latency.
5. **Printers → Own Network** — Printers are next to impossible to secure. If a printer tells a computer authentication is required during a print job, that computer will attempt `NTLMv2` authentication, which can lead to passwords being stolen. These devices also have tons of sensitive information sent to them.

### Bad Setup — Flat Network

```
Office Wi-Fi / LAN (192.168.1.0/24)
 ├── Employee Laptop 1
 ├── Employee Laptop 2
 ├── HR Computer
 ├── Printer
 ├── CCTV Camera
 ├── NAS Server
 └── CEO's Laptop
```

Everything can directly communicate with everything else. If an attacker hacks the printer, they can scan the network, discover laptops, attack shared folders, capture authentication attempts, and move laterally.

### Good Setup — Segmented Network

```
Employee VLAN (192.168.10.0/24)
 ├── Laptop 1
 ├── Laptop 2
 └── HR PC

Printer VLAN (192.168.20.0/24)
 ├── Printer 1
 └── Printer 2

Server VLAN (192.168.30.0/24)
 ├── File Server
 └── Database

Guest Wi-Fi (192.168.40.0/24)
 ├── Visitor Phones
 └── Visitor Laptops
```

A router or firewall controls which VLANs can talk to each other:

- ✅ Employees → Printers (allowed)
- ❌ Printers → Employee laptops (blocked)
- ❌ Guest Wi-Fi → Internal servers (blocked)

### Why Printers Are Dangerous

Printers are notoriously difficult to secure because they often:
- Run outdated firmware
- Rarely receive updates
- Have default passwords
- Store copies of printed documents
- Support many network protocols that aren't needed

### NTLM Authentication Attack via Printer

A malicious printer (or device pretending to be one) can respond: *"I need you to authenticate before I print."* Windows may automatically attempt **NTLMv2 authentication**. The attacker can capture the NTLM challenge-response and potentially crack it offline or relay it.

### VLAN Segmentation for Printers

Printers don't need another physical Wi-Fi — they should be on a **separate VLAN**:

```
SSID: Office-Employees → VLAN 10 → Employee laptops
SSID: Office-Printers  → VLAN 20 → Network printers
SSID: Guest            → VLAN 30 → Visitors
```

Or via Ethernet:

```
Laptop (Wi-Fi)
     │
  Network Switch
   ├── VLAN 10 → Employee PCs
   ├── VLAN 20 → Printers
   └── VLAN 30 → Servers
```

> [!TIP] Key Idea
> Put printers on a dedicated VLAN/subnet. Allow employees to send print jobs. **Block printers from initiating connections** to employee devices or sensitive servers.

## Fun Story — Physical Penetration Test

During COVID, a tester purchased an expensive printer and put a reverse shell in it, then shipped it to the company with a phishing email. The printer was hooked up almost instantly, and their domain administrator's computer was kind enough to send the printer his credentials.

If the client had designed a secure network:
- Printer should not have been able to talk to the internet
- Workstation should not have been able to communicate to the printer over port 445
- Printer should not be able to initiate connections to workstations
