
# FunboxEasy — OffSec Proving Grounds Writeup

---

## About This Lab

Utilize enumeration and web enumeration techniques to identify vulnerabilities. Engage in exploiting SQL injection and file upload vulnerabilities, along with implementing privilege escalation strategies. Additionally, harness the abuse of sudo permissions to enhance your access. This lab is designed to capitalize on your skills in vulnerability exploitation.

## Learning Objectives

**After completion of this lab, learners will be able to:**

- Perform Nmap and Gobuster scans to identify open ports, web directories, and hidden resources.
- Exploit SQL Injection to dump credentials from the database using tools like SQLMap.
- Log into the web application, exploit the file upload vulnerability, and obtain a reverse shell.
- Discover user credentials from configuration files or plaintext files on the target system.
- Identify sudo misconfigurations and escalate to root using tools like pkexec, time, or read sensitive files using mtr.

## Lab Description

This lab involves exploiting an SQL Injection vulnerability to leak credentials for a web application, leading to a file upload vulnerability that provides initial access. Privilege escalation is achieved via user password disclosure and multiple sudo misconfigurations, ultimately granting root access through tools like pkexec or time.

## 1. Reconnaissance — Nmap Scanning

We start with network scanning using **Nmap** to identify all running ports and services on the target.

```bash
nmap -p- 192.168.195.111 --min-rate 10000 -sCV
```

- `-p-` — Scan all 65,535 TCP ports.
- `--min-rate 10000` — Send packets at a minimum rate of 10,000 per second for speed.
- `-sCV` — Combine service version detection (`-sV`) and default NSE script scanning (`-sC`).

### 3.6 Setting Up the Netcat Listener and Triggering the Shell

Before clicking the shell, we need to start a **Netcat listener** on our attacker machine to catch the incoming connection.

```bash
nc -lnvp 1234
```

| Option | Meaning | Easy Way to Remember |
|--------|---------|----------------------|
| `-l` | **Listen** for incoming connections | **L = Listen** |
| `-n` | **No DNS lookup** (use IP addresses directly) | **N = No DNS** |
| `-v` | **Verbose** (show connection information) | **V = Verbose** |
| `-p` | **Port** to listen on | **P = Port** |

> **Listen (`-l`) on port (`-p`) 1234, don't do DNS lookups (`-n`), and show verbose output (`-v`).**

With the listener ready, we simply click the reverse shell file from `/store/bootstrap/img/` in the browser.


## 7. Lessons Learned

1. **Always try default credentials.** The bookstore admin panel fell to `admin:admin` — a trivial but effective first check before reaching for SQLMap or brute-force tools.

2. **Manual exploitation deepens understanding.** An automated RCE exploit existed for CSE Bookstore, but walking through the file upload chain manually (login → upload → locate → trigger) teaches the underlying mechanics far better.

3. **Plaintext credential files are common in CTFs.** After landing a shell, always enumerate home directories and configuration files for hardcoded passwords. The `password.txt` in `/home/tony` handed us SSH access on a silver platter.

4. **`sudo -l` is the first privesc check.** Tony's account had an absurd number of NOPASSWD sudo entries. Always cross-reference `sudo -l` output with [GTFOBins](https://gtfobins.org/) — `pkexec`, `time`, and several others on this list are trivial escalation vectors.

5. **Use `find` to locate flags.** When `proof.txt` and `local.txt` aren't in expected locations, `find / -name "filename"` will track them down quickly.
