## What does `bash -p` actually do?

The `-p` option means **privileged mode**.

Normally, when Bash detects it's running as a SUID program or with different real/effective user IDs, it **drops privileges** for safety.

With `-p`, Bash **preserves the effective UID instead of dropping it**.

It **does not magically grant root privileges**.

By running:

```
sudo chmod +s /usr/bin/bash
```

you set the **SUID bit** on the Bash executable.

You can verify it with:

```
ls -l /usr/bin/bash
```

You'll likely see something like:

```
-rwsr-xr-x 1 root root ... /usr/bin/bash
```

Notice the **`s`** in place of the owner's execute bit (`rws`). That means:

- The file is owned by `root`.
- When **any user** executes `/usr/bin/bash`, the kernel starts it with an **effective UID of root**.

Normally, Bash detects that it's running with elevated privileges and **drops them** for safety. However, when you run:

```
bash -p
```

the `-p` ("privileged mode") option tells Bash **not to drop the effective UID**, so it stays running as root.

That's why your `oscp` user was able to do:

```
$ bash -p
# whoami
root
```

This works **because you made Bash SUID-root**. On a normal Linux installation, `/usr/bin/bash` should **not** have the SUID bit set.

### Security note

Setting the SUID bit on `bash` is **highly insecure** on a real system because it allows any local user to obtain a root shell with `bash -p`.
