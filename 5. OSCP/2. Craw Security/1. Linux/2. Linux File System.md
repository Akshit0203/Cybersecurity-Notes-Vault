**`ls` is a command in Kali/Linux** — not usually called a “function.”

It stands for:

**`ls` = list**

It shows files and folders in a directory.

Nice question. Understanding this makes Linux feel much less “magic.”

When you type:

```
ls
```

here’s what actually happens step by step.

---

## 1. Your shell waits for input

In Kali you’re usually using **Bash** or zsh.

Prompt:

```
kali@kali:~$
```

Shell is basically asking:

> “What command do you want me to run?”

You type:

```
ls
```

and press Enter.

---

## 2. Shell reads “ls”

It splits what you typed.

Example:

```
ls -la /etc
```

becomes:

- command = `ls`
- option = `-la`
- argument = `/etc`

For plain:

```
ls
```

just command = `ls`

---

## 3. Shell asks: “Where is `ls`?”

Linux searches directories listed in **PATH**.

Check PATH:

```
echo $PATH
```

Example:

```
/usr/local/bin:/usr/bin:/bin
```

Shell checks in order:

```
/usr/local/bin/ls
```

```
/usr/bin/ls
```

```
/bin/ls
```

Finds:

```
/usr/bin/ls
```

You can verify:

```
which ls
```

---

## 4. Linux loads that program into memory

Now the shell tells Linux kernel:

> “Run `/usr/bin/ls`.”

Kernel:

- loads executable
- gives CPU time
- gives access to terminal

Then `ls` starts running.

---

## 5. `ls` reads current directory

It asks kernel:

> “What files are in this folder?”

Kernel returns entries like:

```
notes.txtDownloadsPictures
```

---

## 6. `ls` formats output

Plain:

```
ls
```

prints:

```
Desktop Downloads notes.txt
```

Detailed:

```
ls -l
```

asks for more info:

- permissions
- owner
- size
- timestamps

Then prints.

---

## 7. Program exits

`ls` finishes.

Control returns to shell.

Prompt appears again:

```
kali@kali:~$
```

Waiting for next command.

---

Ah—you mean **how does `ls` actually get the file names from the kernel?** Good question.

Let’s zoom in on just that part.

You run:

```
ls
```

Now `ls` needs to know:

> “What files are in this folder?”

It cannot read the disk directly itself.

So it asks the **Linux kernel** using a **system call**.

Think:

```
ls → kernel → disk → kernel → ls → screen
```

Step by step:

---

## 1. `ls` needs current folder

Shell started `ls` inside:

```
/home/kali
```

`ls` knows:

> “I should list `/home/kali`.”

---

## 2. `ls` asks kernel

Internally `ls` makes a system call like:

```
opendir("/home/kali")
```

Meaning:

> “Kernel, open this directory for me.”

Kernel checks:

- does it exist?
- do you have permission?

If yes:

returns a handle.

Like:

```
OK, here’s access to that folder
```

---

## 3. `ls` asks for entries

Then repeatedly:

```
readdir()
```

Meaning:

> “Give me next item.”

Kernel reads filesystem metadata from disk.

Example disk data:

```
notes.txtDownloadsPictures.bashrc
```

Kernel gives one entry at a time.

Like:

```
Entry 1: notes.txtEntry 2: DownloadsEntry 3: Pictures
```

---

## 4. Kernel gets that from filesystem

Filesystem could be:

- ext4
- xfs
- ntfs

Kernel knows layout.

Example:

Directory contains metadata:

```
inode 245 → notes.txtinode 246 → Downloadsinode 247 → Pictures
```

Kernel reads these and sends names back.

---

## 5. `ls` prints them

Then:

```
notes.txt  Downloads  Pictures
```

to your terminal.

---

ls: "Can I open cabinet?"kernel: "Yes."ls: "Next file?"kernel: "notes.txt"ls: "Next?"kernel: "Downloads"ls prints them.

Perfect—that output is exactly what we needed. Thanks for pasting it.

Now let’s connect it to your question: **“how does `ls` actually happen?”**

When you ran:

```
strace ls
```

`strace` showed every time `ls` talked to the Linux kernel.

Here are the important parts only:

---

## 1. Linux starts `ls`

You see:

```
execve("/usr/bin/ls", ["ls"], ...)
```

Meaning:

> Bash found `/usr/bin/ls` and asked kernel:  
> **“Run this program.”**

Kernel loads it into memory and starts it.

---

## 2. `ls` opens current directory

You see:

```
openat(AT_FDCWD, ".", O_RDONLY|O_DIRECTORY) = 3
```

Breakdown:

- `.` = current folder
- `O_DIRECTORY` = open as folder
- `= 3` = kernel gives back handle number **3**

Meaning:

> `ls`: “Open the folder I’m in.”

Kernel:

> “Okay—use handle #3.”

---

## 3. `ls` asks “what files are here?”

You see:

```
getdents64(3, ... /* 35 entries */, 32768) = 1136
```

This is the big one.

Meaning:

- use folder handle `3`
- read directory entries

Kernel replies with:

```
DesktopDocumentsDownloadshashMusicPictures
```

Think:

> `ls`: “Give me the list.”

Kernel:

> “Here are 35 items.”

Then:

```
getdents64(... /* 0 entries */)
```

means:

> “No more files.”

---

## 4. `ls` prints to terminal

You see:

```
write(1, "Desktop Documents Downloads ...", 88)
```

Meaning:

- `1` = terminal screen (stdout)
- write text there

Kernel sends text to your terminal.

That’s why you saw:

```
Desktop  Documents  Downloads
```

---

## 5. Program exits

You see:

```
exit_group(0)
```

Meaning:

> `ls` finished successfully

Then shell prompt comes back.

---

# Super simple flow

You type:

```
ls
```

Then:

```
Bash → "run ls"Kernel → starts /usr/bin/lsls → "open current folder"Kernel → "okay"ls → "give file names"Kernel → "Desktop, Downloads..."ls → "print them"Kernel → terminal displays themls exitsBash waits again
```

That `getdents64(...)` line is the exact moment `ls` receives the filenames.
