# Network Security and Data Flow Analysis

---

## Network Security

Network security = measures to protect data, applications, devices, and systems from unauthorized access or damage. The goal is to uphold the `CIA Triad`:

| **Principle**      | **Description**                               |
| ------------------ | --------------------------------------------- |
| `Confidentiality`  | Only authorized users can view the data        |
| `Integrity`        | Data remains accurate and unaltered            |
| `Availability`     | Network resources are accessible when needed   |

---

### Firewalls

A `Firewall` is a network security device (hardware, software, or both) that monitors incoming/outgoing traffic and enforces rules (`firewall policies` / `access control lists`) to **allow or block** specific traffic.

> [!TIP] Analogy
> A security guard at a building entrance checking who's allowed in or out based on a list of rules.

_**The open source router/firewall [pfSense](https://www.pfsense.org/):**_
![GIF showcasing firewall rule creation in pfSense.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Security/pfsense.gif)

Firewalls analyze packets based on: **IP addresses, port numbers, and protocols**. They also log traffic events and generate alerts about suspicious activity.

#### Types of Firewalls

##### 1. Packet Filtering Firewall

| **Description**                                                                     |
| ----------------------------------------------------------------------------------- |
| Operates at Layer 3 (Network) and Layer 4 (Transport)                               |
| Examines source/destination IP, source/destination port, and protocol type          |
| `Example`: Router ACL allowing only HTTP (port 80) and HTTPS (port 443)             |

##### 2. Stateful Inspection Firewall

| **Description**                                                                     |
| ----------------------------------------------------------------------------------- |
| Tracks the **state of network connections**                                         |
| More intelligent — understands the entire conversation                              |
| `Example`: Only allows inbound data matching an already established outbound request |

##### 3. Application Layer Firewall (Proxy Firewall)

| **Description**                                                                     |
| ----------------------------------------------------------------------------------- |
| Operates up to Layer 7 (Application)                                                |
| Inspects **actual content** of traffic (e.g., HTTP requests)                        |
| `Example`: Web proxy filtering out malicious HTTP requests with suspicious patterns |

##### 4. Next-Generation Firewall (NGFW)

| **Description**                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------- |
| Combines stateful inspection with **deep packet inspection**, intrusion detection/prevention, and application control                  |
| `Example`: Blocks known malicious IPs, inspects encrypted traffic, enforces application-specific policies                             |

#### Firewall Placement

- **Home:** Router/modem often has a built-in software firewall
- **Business:** Firewall is typically a separate device placed after the modem/router and before the internal network

### Intrusion Detection and Prevention Systems (IDS/IPS)

Security solutions that monitor and respond to suspicious network/system activity.

| System  | Action                                                             |
| ------- | ------------------------------------------------------------------ |
| `IDS`   | **Detects and alerts** — observes traffic, generates alerts, does not block |
| `IPS`   | **Detects and prevents** — blocks/rejects malicious traffic in real time    |

_**[Suricata](https://suricata.io/) — widely used IDS/IPS software:**_
![GIF showcasing rule enablement in Suricata.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Security/suricata-2.gif)

#### Detection Techniques

| **Technique**              | **Description**                                            |
| -------------------------- | ---------------------------------------------------------- |
| `Signature-based detection`| Matches traffic against a database of known exploits       |
| `Anomaly-based detection`  | Detects anything unusual compared to normal activity       |

_**Suricata in IDS mode:**_
![GIF showcasing Suricata in IDS mode.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Security/suricata-3.gif)

#### Types of IDS/IPS

##### Network-Based IDS/IPS (NIDS/NIPS)

| **Description**                                                                                |
| ---------------------------------------------------------------------------------------------- |
| Hardware or software placed at strategic network points to inspect all passing traffic          |
| `Example`: Sensor connected to the core switch monitoring data center traffic                  |

##### Host-Based IDS/IPS (HIDS/HIPS)

| **Description**                                                                                              |
| ------------------------------------------------------------------------------------------------------------ |
| Runs on individual hosts, monitoring inbound/outbound traffic and system logs on that specific machine        |
| `Example`: Antivirus or endpoint security agent on a server                                                  |

#### IDS/IPS Placement Options

1. **Behind the firewall** — firewall filters obvious threats, IDS/IPS inspects remaining traffic
2. **In the DMZ** — monitors traffic to/from publicly accessible servers
3. **On endpoint devices** — detects suspicious activity at the host level

![IDS/IPS positioned after firewall: Internet → Firewall → IPS/IDS → Router → Devices](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Security/IPS_IDS-1.png)

### Security Best Practices

| **Practice**                  | **Description**                                                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `Define Clear Policies`       | Consistent firewall rules based on **least privilege** (only allow what's necessary)           |
| `Regular Updates`             | Keep firewall, IDS/IPS signatures, and OS up to date                                          |
| `Monitor and Log Events`      | Review firewall logs, IDS/IPS alerts, and system logs to identify suspicious patterns early    |
| `Layered Security`            | **Defense in depth** — firewalls + IDS/IPS + antivirus + endpoint protection                  |
| `Periodic Penetration Testing`| Simulate real attacks to test effectiveness of security                                        |

## Data Flow Example — Accessing a Website

A complete walkthrough of what happens when a user accesses a website from their laptop.

### 1. Connecting to the Network (WLAN)

| **Step**                                                                                      |
| --------------------------------------------------------------------------------------------- |
| Laptop identifies the correct wireless network/SSID                                           |
| If WPA2/WPA3, user provides password/credentials to authenticate                             |
| Connection established → DHCP takes over IP configuration                                     |

### 2. DHCP — Getting an IP Address

| **Step**                | **Description**                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------- |
| `IP Address Assignment` | Laptop requests an IP from the router's DHCP server (valid only within the local network)         |
| `DHCP Acknowledgement`  | DHCP assigns a private IP (e.g., `192.168.1.10`) + subnet mask, default gateway, DNS server      |

### 3. DNS Resolution

| **Step**       | **Description**                                                                          |
| -------------- | ---------------------------------------------------------------------------------------- |
| `DNS Query`    | Laptop sends a DNS query to the DNS server (typically ISP or third-party like Google DNS) |
| `DNS Response` | DNS server returns IP (e.g., `93.184.216.34` for `www.example.com`)                      |

### 4. Data Encapsulation and Transmission

| **Layer**            | **Description**                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| `Application Layer`  | Browser creates an HTTP/HTTPS request                                                                        |
| `Transport Layer`    | Request wrapped in TCP segment with source/destination ports (HTTP: 80, HTTPS: 443)                          |
| `Internet Layer`     | TCP segment placed in IP packet. Source: `192.168.1.10`, Destination: `93.184.216.34`                        |
| `Link Layer`         | IP packet placed in Ethernet/Wi-Fi frame with MAC addresses (source: laptop NIC, destination: router)        |

The laptop checks its **ARP table** (or sends an ARP request) to find the router's MAC address, then sends the frame.

### 5. NAT — Translating Addresses

The router replaces the **private IP** (`192.168.1.10`) with its **public IP** (`203.0.113.45`) via NAT, then forwards the packet to the ISP. Intermediate routers determine the best path to `93.184.216.34`.

### 6. Server Processing and Response

1. Server's firewall checks if traffic on port 80/443 is allowed
2. Web server software (Apache, Nginx, IIS) processes the request
3. Server prepares and sends the response (HTML, CSS, images)
4. Response follows the reverse path — server IP (`93.184.216.34`) → home router's public IP (`203.0.113.45`)
5. Router's NAT maps the response back to the laptop's private IP (`192.168.1.10`)

### 7. Decapsulation and Display

The laptop strips away: Ethernet/Wi-Fi frame → IP header → TCP header → extracts application layer data. The browser reads HTML/CSS/JavaScript and **renders the webpage**.
