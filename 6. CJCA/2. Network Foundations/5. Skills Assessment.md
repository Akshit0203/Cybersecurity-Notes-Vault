### The Loopback Interface (`lo`)

The [loopback](https://www.geeksforgeeks.org/what-is-a-loopback-address/) address is always `127.0.0.1`. It's used when a device needs to send network traffic **to itself**.

**Key characteristics of `lo`:**
- Greater MTU (65536) compared to other interfaces
- IPv6 address is `::1` with scopeid `host` (not `link`)
- Layer-2 info shows `loop` and `Local Loopback`

**Use cases:**
- **Testing** — verify an application works before going live on the network
- **Internal services** — e.g., an e-commerce website's database only accessible by the server itself; when a user logs in, the server queries its own database via loopback on behalf of the user

### Port Forwarding

Port forwarding redirects traffic from one TCP/UDP port to another — even across machines.

> [!EXAMPLE]
> A Windows host forwards local port 8888 to a Linux VM's SSH port (22). The Linux VM runs with NAT, so it has no directly accessible IP. The Windows host acts as intermediary.

### Testing Connectivity with `ping`

`ping` tests the reachability of a host. It's a **Layer 3** protocol (doesn't use TCP/UDP ports).

```bash
ping -c 4 <target ip>
```

> [!TIP] Key Fields
> - **`ttl` (Time-to-Live)** — how many "hops" packets can take to reach the target
> - **`time`** — latency in milliseconds (here ~71 ms)

### Interacting with FTP via Netcat

[Netcat](https://en.wikipedia.org/wiki/Netcat) makes raw TCP/UDP connections — lets us see how FTP works under the hood.

#### Connecting to the Control Channel

```bash
nc <target ip> 21
```

```
220 Microsoft FTP Service
```

#### Logging In (Anonymous)

```
USER anonymous^M
331 Anonymous access allowed, send identity (e-mail name) as password.
PASS anything^M
230 User logged in.
PASV^M
227 Entering Passive Mode (10,129,233,197,194,40).
```

> [!NOTE] FTP requires `\r\n` (return + newline) for commands.
> In netcat, press `Ctrl+V`, then `Enter`, then `Enter` again to send the proper line ending.

#### FTP Channels

| **Channel**     | **Purpose**                                   | **Port**                          |
| --------------- | --------------------------------------------- | --------------------------------- |
| Control Channel | Sends FTP commands (USER, PASS, LIST, RETR)   | Port 21                          |
| Data Channel    | Transfers files and directory listings         | Dynamic port (varies by mode)    |

#### Calculating the Passive Mode Port

The last two numbers in the PASV response encode the port: `p1 * 256 + p2`

**Example:** `194` and `40` → `194 * 256 + 40 = 49704`

See [RFC 959](http://www.faqs.org/rfcs/rfc959.html) for details.

#### Connecting to the Data Channel

```bash
nc -v <target ip> 49704
```

#### Listing Files (Control Channel)

```
LIST^M
125 Data connection already open; Transfer starting.
226 Transfer complete.
```

**Data channel output:**

```
02-08-25  08:37PM                  438 Note-From-IT.txt
```

#### Retrieving a File

1. In the control channel, enter passive mode again:
   ```
   PASV^M
   227 Entering Passive Mode (10,129,233,197,194,50).
   ```
2. Calculate new port: `194 * 256 + 50 = 49714`
3. Connect to the new data channel:
   ```bash
   nc -v <target ip> 49714
   ```
4. In the control channel:
   ```
   RETR Note-From-IT.txt^M
   125 Data connection already open; Transfer starting.
   226 Transfer complete.
   ```

**Data channel output — contents of `Note-From-IT.txt`:**

```
Bertolis,

The website is still under construction. To stop users from poking
their nose where it doesn't belong, I've configured IIS to only
allow requests containing a specific user-agent header. If you'd
like to test it out, please provide the following header to your
HTTP request.

User-Agent: Server Administrator

The site should be finished within the next couple of weeks.
I'll keep you posted.

Cheers,
jarednexgent
```

### Interacting with HTTP via Netcat

The web server requires a specific `User-Agent` header to allow access.

#### Sending the HTTP Request

```bash
nc -v <target ip> 80
```

```
GET / HTTP/1.1
Host: <target ip>
User-Agent: Server Administrator

```

> [!IMPORTANT] Press Enter twice after the last header to send the request.

#### Server Response

```http
HTTP/1.1 200 OK
Content-Type: text/html
Server: Microsoft-IIS/10.0
Content-Length: 746

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN"
  "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">
<html xmlns="http://www.w3.org/1999/xhtml">
<head>
<title>IIS Windows Server</title>
</head>
<body>
<div id="container">
<a href="http://go.microsoft.com/fwlink/?linkid=66138&amp;clcid=0x409">
<img src="iisstart.png" alt="IIS" width="960" height="600" /></a>
</div>
</body>
</html>
<!-- HTB{S00n_2_B_N3tw0rk1ng_GURU!} -->
```

#### Understanding the HTTP Exchange

**Request headers:**
- `GET /` — request the homepage (root directory). For a login page: `GET /login.php`
- `Host` — tells the server which site we're requesting (servers can host multiple sites)
- `User-Agent` — identifies the agent making the request (browser name/version, or custom)

**Response headers:**
- `Content-Type` — type of data in the response
- `Accept-Ranges` — what data types the server can receive
- `Server` — web server software (Microsoft IIS)

The HTML (including a flag hidden in comments) is below the headers.

---

### Key Takeaways

- **FTP** uses separate control (port 21) and data channels, requires `\r\n` line endings
- **HTTP** is more syntactically forgiving but enforces administrator-defined policies (e.g., user-agent filtering)
- **Netcat** lets you see raw protocol exchanges that browsers/FTP clients abstract away
- The hidden flag `HTB{S00n_2_B_N3tw0rk1ng_GURU!}` is only visible in raw HTTP — browsers render the HTML and hide comments
