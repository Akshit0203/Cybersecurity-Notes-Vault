## Vulnerability Research

- **White box approach** to software testing
- > "Security engineers see the world differently than other engineers."

### Process

| Step                              | Description                                        |
| --------------------------------- | -------------------------------------------------- |
| **Fuzzing & Reverse Engineering** | Testing inputs to find unexpected behaviour         |
| **Network & Protocol Analysis**   | Examining communication flows for weaknesses       |
| **Cryptography**                  | Reviewing cipher implementations and key management|
| **Web Apps, APIs & Mobile**       | Testing application-layer attack surfaces          |
| **Hardware Analysis**             | Examining firmware and physical components         |

### Goals

- Understand **how a system works** (X) vs **how a system fails** (Y)
- Can be conducted by good or bad actors
- Derives concepts from known attacks and applies them statistically to current systems
- Periodic operations help **mitigate security attacks**
- Helps **reduce zero-day exploits**

## Operating Systems: Linux

- **Open Source**, cross-platform operating system
- Derived from UNIX OS, modified by **Linus Torvalds**
- Developed and launched in **1991** — one of the most widely used kernels
- Runs on everything: smartphones, laptops, servers, home appliances, submarines, space rockets
- UNIX shell-based environment — Linux itself is **just a kernel**

> [!NOTE]
> - In Linux we say **distributions**, not versions
> - Every user can't command or program at the hardware level
> - The **kernel** is a small part of the OS — the OS includes user environment, user base, and shell
> - Everything between the user and kernel to facilitate interaction is the **desktop environment** — it converts the kernel into a usable OS

### Evolution of Linux

| Year  | Event                                                                    |
| ----- | ------------------------------------------------------------------------ |
| 1969  | UNIX project started at Bell Laboratories, written in C                  |
| —     | Used by large organizations who developed their own dialects of UNIX     |
| —     | Wasn't open source or collaborative → failed to gain mass popularity     |
| 1991  | Torvalds wrote his own UNIX and made it freely available                 |
| 1992  | Linux placed under GNU GPL License — not available for commercial use    |
| —     | Programmers have since modified and released many flavours (distributions)|

### GNOME Desktop Environment

**GNOME** is a popular desktop environment for Linux/Unix-like systems. It provides the graphical interface you interact with instead of using only the command line — the **complete visual workspace**.

**What it includes:**
- Desktop layout and windows
- Top bar / system menu
- App launcher
- File manager (**Nautilus**)
- Settings panel, notifications
- Workspaces / multitasking tools
- Themes and accessibility features

**Used by default in:** Ubuntu (modern), Fedora Workstation, Debian, RHEL/CentOS derivatives

**Why people like GNOME:**
- ✅ Clean and modern design — minimal clutter
- ✅ Productivity-focused — workspaces and overview mode
- ✅ Stable ecosystem — widely supported
- ✅ Accessibility — strong keyboard navigation, screen reader support, scaling

## Penetration Testing

- An **authorized simulated cyberattack** on a computer system
- To **evaluate the security** of the system
- Automated with software applications or performed manually
- Checks compliance requirements, employee security awareness, and organizational immunity to incidents
- Domain knowledge is at an **expert level**
- > *Ethical hacking is learning; penetration testing is implementing*

### Phases of Penetration Testing

| Phase | Description |
| ----- | ----------- |
| **1. Pre-Engagement** | Meeting with client for crystal-clear understanding of their needs and vision |
| **2. Planning & Recon** | Test plan generation and public information gathering through scanning |
| **3. Threat Modelling & Vulnerability ID** | Model of all security concerns and ranking vulnerability severity |
| **4. Exploitation** | Gaining access by breaching security or finding a bug to exploit |
| **5. Post-Exploitation** | Determining value of compromised assets and further attack propagation |
| **6. Reporting** | Detailing vulnerabilities found, stating impact and remedies |
| **7. Resolution & Re-Testing** | Resolving issues and verifying fixes |

## Ethical Hacking Laws and Policies

### Why Do We Need Laws?

- **Is Ethical Hacking really ethical?** In 2013, an MP in the Netherlands faced legal action for pointing out a security flaw in a medical center website — the center **prosecuted him** instead of thanking him.
- What if the ethical hacker performs unethical actions during the job?
- A solicited hacker may exceed scope and access systems not covered by the agreement

### What Legal Laws Must Include

- Definition of ethical hacking
- Whether ethical hacking should only be done when **formally solicited**; how will unsolicited hacking be viewed?
- Only formal, detailed agreements between hacker and organization qualify as solicited hacking
- Whether every organization will facilitate swift acceptance of issue descriptions
- Whether unsolicited hackers will be punished for bypassing bureaucratic procedures
- Clear statement of ethical hacker's **job scope** in the legal agreement
- Definition of **compensation and rewards** for solicited and unsolicited hackers
- How to address misuse of discovered security flaws by unsolicited hackers

## IT Act 2000 (India)

India's primary cyber law dealing with electronic records, digital signatures, cybercrime, e-commerce, hacking, and unauthorized access.

- **Notified:** October 17, 2000
- Contains **13 chapters and 90 sections**
- Based on The Indian Penal Code, 1860
- Provides legal recognition to transactions done via electronic exchange of data
- Significantly amended in **2008**

### Why It Was Created

Before this law:
- Paper documents had legal recognition; digital documents/emails/contracts were legally unclear
- Cybercrimes had limited dedicated legal framework

The Act gave legal backing to digital transactions and created cybercrime provisions.

### Main Objectives

1. **Legal recognition of electronic records** — emails, digital documents, electronic contracts
2. **Legal recognition of digital signatures** — using asymmetric cryptosystem and hash functions
3. **Facilitate e-commerce and e-governance** — online filing, records, digital transactions
4. **Punish cybercrimes** — unauthorized access, hacking, data theft, identity misuse, obscene content

### Key Features

- All electronic contracts made through secure electronic channels are legally valid
- Digital Signatures use an **asymmetric cryptosystem** and a **hash function**
- The Act applies to offences committed **outside India**
- Senior police officers can enter any public place, search, and arrest **without warrant** (Section 80)
- Based on The Indian Penal Code, 1860

### Important Sections

| Section     | Offence / Provision                                                          |
| ----------- | ---------------------------------------------------------------------------- |
| **43**      | Penalty for unauthorized access, downloading data, introducing malware, damaging systems, disrupting networks |
| **66**      | Computer-related offenses (dishonest/fraudulent acts under Section 43)       |
| **66C**     | Identity theft — misuse of password, digital signature, credentials          |
| **66D**     | Cheating by personation using computer resources (e.g., online fraud, pretending to be bank support) |
| **66E**     | Violation of privacy (capturing/transmitting private images)                 |
| **67**      | Publishing/transmitting obscene material electronically                      |
| **69**      | Government power for interception/monitoring/decryption under legal conditions |
| **70**      | Protected systems / critical infrastructure                                  |
| **72**      | Breach of confidentiality/privacy by authorized persons                      |
| **80**      | Warrantless search & arrest powers for police in public places               |

### Section 66A (Struck Down)

Section 66A punished sending offensive messages through communication services:
- (a) information that is grossly offensive or has menacing character
- (b) false information for causing annoyance, inconvenience, danger, obstruction, insult, injury, criminal intimidation, enmity, hatred, or ill will
- (c) electronic mail for causing annoyance/inconvenience or to deceive/mislead about origin

> **Section 66A was struck down on 24 March 2015** by the Supreme Court of India in *Shreya Singhal vs. Union of India* (AIR 2015 SC 1523) for violating free speech. **It is no longer valid law.**

> [!IMPORTANT]
> **66A being struck down does NOT mean harmful fake content is legal.** Other laws still apply — cheating/fraud, forgery/impersonation, defamation, public mischief, promoting enmity, and platform-level takedowns under intermediary frameworks.

**Practical example — Fake AI reels (e.g., plane landing on a railway station):**

| Scenario                               | Risk Level                           |
| -------------------------------------- | ------------------------------------ |
| Clearly labeled parody/satire          | Low — mostly a platform moderation issue |
| Presented as real breaking news        | High — possible police complaint if it causes panic |
| Monetized misinformation repeatedly    | Risk increases substantially         |

Police evaluate: **Intent** (joke or deception?), **Impact** (panic, damage, fraud?), **Reach** (private vs viral), **Context** (during disaster/election = more serious).

### Section 80 — Warrantless Search Powers

Authorized police officers (**Inspector rank or above**) may enter a public place, search, seize devices, and arrest **without warrant** if they reasonably suspect an IT Act offence.

**Rationale:** Cyber evidence is fragile and can disappear quickly (deleting logs, wiping devices, remote-deleting cloud data).

**"Public place" includes:** cyber cafés, offices open to public, shared workspaces, shops, publicly accessible premises.

**Important limits — this does NOT mean unlimited power:**
- Officers must have legal authority and reasonable suspicion
- Must follow criminal procedure and proper seizure process
- Must respect constitutional rights
- Must produce arrested persons before a magistrate
- Illegal/abusive searches can be challenged in court
- Private residences require additional legal procedures

> [!WARNING]
> Warrantless powers are controversial due to concerns about privacy, misuse, harassment, and overreach. Courts and procedural safeguards remain critical.

### 2008 Amendments

Major updates added:
- Stronger cybercrime provisions
- Identity theft provisions
- Privacy violations
- Intermediary liability concepts
- Corporate data protection obligations (Section 43A)

### Quick Reference Table

| Topic                              | Covered? |
| ---------------------------------- | -------- |
| Electronic records                 | Yes      |
| Digital signatures                 | Yes      |
| Cybercrime                         | Yes      |
| Hacking                           | Yes      |

## Risk Management

Identifying risks and vulnerabilities, then applying administrative actions and comprehensive solutions to ensure adequate organizational protection.

> Considering potential risks or events before they occur saves money and protects the organization's future.

### Risk Management Methodology

| Step                           | Description                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| **1. Establish Context**       | Understand circumstances; define criteria for evaluating risk; define analysis structure                       |
| **2. Risk Identification**     | Identify and define potential risks that may negatively influence a company process or project                 |
| **3. Risk Analysis**           | Determine odds of occurrence and consequences; understand how each risk influences projects and objectives     |
| **4. Risk Assessment**         | Assess overall consequence; decide whether risk is acceptable based on risk appetite                          |
| **5. Risk Mitigation**         | Develop plans to alleviate highest-ranked risks using specific risk controls                                  |
| **6. Risk Monitoring**         | Continuously monitor and track new and existing risks; follow up on the overall plan                          |
| **7. Communicate & Consult**   | Include internal and external stakeholders in communication at each appropriate step                          |

## Dual Boot vs Virtual Machine

### Dual Boot

Splitting your computer's resources between two operating systems. Each OS has its own dedicated partition on the same hard drive or an external drive. **You can't run both simultaneously.**

| Advantages                                              | Disadvantages                                                            |
| ------------------------------------------------------- | ------------------------------------------------------------------------ |
| Full access to dedicated hardware (CPU, RAM, etc.)      | Installation is complex; errors can affect the whole system              |
| Perfect for resource-intensive tasks (gaming, 3D, video)| Must restart to switch between operating systems                         |

### Virtual Machine

A dedicated virtual environment within your OS, allowing you to run two or more operating systems **simultaneously**. Requires virtualization software (VMware, VirtualBox, Parallels) and an ISO file of the target OS.

| Advantages                                                  | Disadvantages                                            |
| ----------------------------------------------------------- | -------------------------------------------------------- |
| Easy to set up and switch; sandboxed (safer)                | No dedicated resource access between OSes                |
| Extra layer of security against malware                      | Inconvenient for resource-intensive tasks                |
| Create snapshots of the OS                                   |                                                          |
| Portable — can move VMs between computers                    |                                                          |

## NAT vs Bridged vs Host-Only

### NAT (Network Address Translation)

- Just like your home network with a wireless router — the VM is assigned in a **separate subnet**
- Your VM can access the outside network like your host, but **no outside access to your VM directly** — it's protected
- **DHCP is internal**

![](attachments/Pasted%20image%2020260710185910.png)

### Bridged

- Your VM will be in the **same network** as your host
- It can be accessed by all computers in your host network
- **DHCP is external**

![](attachments/Pasted%20image%2020260710185942.png)

### Host-Only

- Creates a network that is **completely contained within the host computer**
- All VMs connected to a host-only network will be visible to the host and to each other

### LAN Segments

- An internal network which logically divides a private network into network segments, completely contained within the host computer
- All VMs connected to an internal network will be visible to **each other but not to the host**
