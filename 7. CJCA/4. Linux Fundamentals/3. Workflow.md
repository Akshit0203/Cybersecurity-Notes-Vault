# Navigation

Navigation is essential. We use different commands and tools to print out information about a directory or a file and can use advanced options to optimize the output to our needs.

## `pwd` — Print Working Directory

```shellsession
cry0l1t3@htb[~]$ pwd
/home/cry0l1t3
```

## `ls` — List Directory Contents

```shellsession
cry0l1t3@htb[~]$ ls
Desktop  Documents  Downloads  Music  Pictures  Public  Templates  Videos
```

With the `-l` flag for detailed information:

```shellsession
cry0l1t3@htb[~]$ ls -l
total 32
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:37 Desktop
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:34 Documents
drwxr-xr-x 3 cry0l1t3 htbacademy 4096 Nov 15 03:26 Downloads
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:34 Music
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:34 Pictures
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:34 Public
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:34 Templates
drwxr-xr-x 2 cry0l1t3 htbacademy 4096 Nov 13 17:34 Videos
```

`total 32` means 32 × 1024-byte blocks = 32 KB of disk space used.

| Column | Description |
| --- | --- |
| `drwxr-xr-x` | Type and permissions |
| `2` | Number of hard links |
| `cry0l1t3` | Owner |
| `htbacademy` | Group owner |
| `4096` | Size in bytes |
| `Nov 13 17:37` | Date and time |
| `Desktop` | Name |

### VIM

VIM has six fundamental modes, but the three most important are:

| Mode | Description |
| --- | --- |
| `Normal` | Default mode — navigate and manipulate text. All keystrokes are editor commands. |
| `Insert` | Press `i` to enter. Type text normally. Press `Esc` to return to Normal mode. |
| `Command` | Press `:` from Normal mode. Type commands like `:w` (save), `:q` (quit), `:wq` (save & quit), `:q!` (quit without saving). |

VIM cheat sheet:

```
i       → Enter insert mode

:w      → Save
:q      → Quit
:wq     → Save and quit
:q!     → Quit without saving
dd      → Delete a line
yy      → Copy a line
p       → Paste
u       → Undo
/text   → Search for "text"
n       → Next search result
```

# Find Files and Directories

## `which` — Locate an Executable

Returns the path of a command by searching through the directories defined in the `PATH` environment variable.

```shellsession
cry0l1t3@htb[~]$ which python
/usr/bin/python
```

## `find` — Search the Filesystem

The `find` command is one of the most powerful tools for searching files and directories.

```shellsession
cry0l1t3@htb[~]$ find / -type f -name "*.conf" -size +25k -newermt 2020-03-03 2>/dev/null
```

| Option | Description |
| --- | --- |
| `-type f` | Files only |
| `-type d` | Directories only |
| `-name "*.conf"` | Filter by name/pattern |
| `-size +25k` | Larger than 25 KB |
| `-size -30k` | Smaller than 30 KB |
| `-user root` | Owned by root |
| `-newermt 2020-03-03` | Modified after a date |
| `2>/dev/null` | Suppress permission errors |
| `-exec cmd {} \;` | Execute a command on each result |

### Example: Count Configuration Files

```shellsession
cry0l1t3@htb[~]$ find / -type f -name "*.conf" 2>/dev/null | wc -l
2510
```

## `locate` — Fast Filename Search

Uses a pre-built database for faster searches. Must update the database first:

```shellsession
cry0l1t3@htb[~]$ sudo updatedb
cry0l1t3@htb[~]$ locate *.conf
```

### `find` vs `locate`

| Feature | `find` | `locate` |
| --- | --- | --- |
| Speed | Slower (scans filesystem) | Faster (uses database) |
| Accuracy | Always current | May be outdated |
| Filters | Many (size, user, date, etc.) | Name only |

# File Descriptors and Redirections

## File Descriptors (FD)

A file descriptor is a number the OS assigns to track open files and streams.

| FD | Name | Description |
| --- | --- | --- |
| `0` | STDIN | Standard Input (keyboard) |
| `1` | STDOUT | Standard Output (terminal) |
| `2` | STDERR | Standard Error (terminal) |

## Redirection Operators

### STDOUT Redirection

```shellsession
cry0l1t3@htb[~]$ find / -name "*.conf" > results.txt 2>/dev/null
```

- `>` — Redirect STDOUT to a file (overwrite)
- `>>` — Redirect STDOUT to a file (append)

### STDERR Redirection

```shellsession
cry0l1t3@htb[~]$ find / -name "*.conf" 2>/dev/null
```

- `2>/dev/null` — Discard all error messages
- `2>errors.txt` — Save errors to a file

### Redirect Both STDOUT and STDERR

```shellsession
cry0l1t3@htb[~]$ find / -name "*.conf" > results.txt 2>&1
```

- `2>&1` — Send STDERR to the same place as STDOUT

### STDIN Redirection

```shellsession
cry0l1t3@htb[~]$ cat < results.txt
```

- `<` — Feed a file as input to a command

## Pipes

The pipe `|` takes the STDOUT of one command and feeds it as STDIN to another:

```shellsession
cry0l1t3@htb[~]$ find / -name "*.conf" 2>/dev/null | grep "systemd"
```

You can chain multiple pipes:

```shellsession
cry0l1t3@htb[~]$ find / -name "*.conf" 2>/dev/null | grep systemd | wc -l
```

```shellsession
cry0l1t3@htb[~]$ head /etc/passwd       # First 10 lines

```

## `sort`

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | sort
```

## `grep` — Search for Patterns

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep "/bin/bash"
```

Useful flags:

| Flag | Meaning |
| --- | --- |
| `-v` | Invert match (exclude) |
| `-c` | Count matches |
| `-i` | Case insensitive |
| `-E` | Extended regex |

Example — exclude lines containing `false` or `nologin`:

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin"
```

## `cut` — Extract Fields

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin" | cut -d":" -f1
root
sync
mrb3n
cry0l1t3
htb-student
```

- `-d":"` — Delimiter is `:`
- `-f1` — First field only

## `tr` — Translate Characters

`tr` replaces **individual characters**, not words.

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin" | tr ":" " "
```

This replaces every `:` with a space.

### `tr` vs `sed`

- **`tr`** → Replace or delete **single characters** (character-by-character mapping)
- **`sed`** → Replace **words, substrings, or regex patterns**

Example showing the difference:

```
echo "bin" | tr "bin" "HTB"    → HTB  (maps b→H, i→T, n→B)
echo "binary" | tr "bin" "HTB" → HTBary (maps each char individually)

echo "/bin/bash" | sed 's/bin/HTB/g' → /HTB/bash (replaces the substring "bin")
```

## `column` — Format as Table

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | column -t
root         x  0     0      root        /root        /bin/bash
sync         x  4     65534  sync        /bin         /bin/sync
mrb3n        x  1000  1000   mrb3n       /home/mrb3n  /bin/bash
```

## `awk` — Pattern Scanning and Processing

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | awk '{print $1, $NF}'
root /bin/bash
sync /bin/sync
mrb3n /bin/bash
```

### Key `awk` Variables

| Expression | Meaning |
| --- | --- |
| `$1` | First field |
| `$2` | Second field |
| `$NF` | Last field (Number of Fields) |
| `NF` | Total number of fields |

### Why `$NF` Instead of a Fixed Field Number?

Not every line has the same number of fields. `$NF` automatically adapts to however many fields are on that line.

Example — `root` has 7 fields (`$7` = `/bin/bash`), but `postgres` has 8 fields due to extra spaces in the comment field. Using `$NF` always gets the last field correctly.

### Using `-F` to Set the Delimiter

Instead of piping through `tr`, tell `awk` the delimiter directly:

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep "cry0l1t3" | awk -F: '{print $1, $3}'
cry0l1t3 1002
```

## `sed` — Stream Editor

The `s` flag stands for substitute. The `g` flag replaces all matches.

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | awk '{print $1, $NF}' | sed 's/bin/HTB/g'
root /HTB/bash
sync /HTB/sync
```

### Rule of Thumb

- **`tr`** → Replace or delete **single characters**
- **`sed`** → Replace **words, substrings, or regex patterns**

## `wc` — Word Count

```shellsession
cry0l1t3@htb[~]$ cat /etc/passwd | grep -v "false\|nologin" | tr ":" " " | awk '{print $1, $NF}' | wc -l
6
```

`wc` can count:

```
wc fruits.txt
4 4 26 fruits.txt
Lines  Words  Characters
```

| Flag | Counts |
| --- | --- |
| `-l` | Lines |
| `-w` | Words |
| `-c` | Characters/bytes |

# Regular Expressions

Regular expressions (`RegEx`) are sequences of characters and symbols that form search patterns. They allow you to find, replace, and manipulate data with precision.

## Grouping Operators

| Operator | Description |
| --- | --- |
| `(a)` | Group parts of a regex to be processed together |
| `[a-z]` | Character class — match one character from the set |
| `{1,10}` | Quantifier — how often a previous pattern should repeat |
| `\|` | OR operator — match one of the two expressions |
| `.*` | AND-like — match anything between two patterns (in order) |

### OR Operator

```shellsession
cry0l1t3@htb:~$ grep -E "(my|false)" /etc/passwd
lxd:x:105:65534::/var/lib/lxd/:/bin/false
pollinate:x:109:1::/var/cache/pollinate:/bin/false
mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

### AND Operator (using `.*`)

```shellsession
cry0l1t3@htb:~$ grep -E "(my.*false)" /etc/passwd
mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

This finds lines where `my` appears **before** `false` (with anything in between).

Equivalent alternative using two pipes:

```shellsession
cry0l1t3@htb:~$ grep -E "my" /etc/passwd | grep -E "false"
mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

---

## Regex Symbols Explained

### `()` — Grouping

Group patterns together. Example: `(my|false)` = match `my` OR `false`.

### `[]` — Character Class

Match **one character** from the list.

- `[a-z]` → any lowercase letter
- `[0-9]` → any digit

### `{}` — Quantifier

Specify **how many times** a pattern repeats.

- `a{3}` → exactly three `a`'s (`aaa`)
- `a{2,4}` → between 2 and 4 `a`'s

### `|` — OR

Either this **or** that. Example: `grep -E "(cat|dog)"` matches `cat` or `dog`.

### `.*` — Any Text

`.` = any single character. `*` = zero or more. Together, `.*` = any amount of any text.

Example: `my.*false` matches `my123false`, `my hello false`, etc.

# Permission Management

In Linux, permissions control access to files and directories. They are assigned to both users and groups.

Every file and directory has an owner (a user) and is associated with a group. Permissions define what actions — reading, writing, or executing — are allowed.

The `execute` permission on a directory is required to traverse (enter) it. Without it, even if the contents are visible, you cannot access them:

```shellsession
cry0l1t3@htb[/htb]$ ls -al mydirectory/
ls: cannot access 'mydirectory/script.sh': Permission denied
ls: cannot access 'mydirectory/subdirectory': Permission denied
```

---

## Permission Types

- (`r`) — Read
- (`w`) — Write
- (`x`) — Execute

Permissions are set for three categories: **owner**, **group**, and **others**.

```shellsession
cry0l1t3@htb[/htb]$ ls -l /etc/passwd
- rwx rw- r--   1 root root 1641 May  4 23:42 /etc/passwd
- --- --- ---   |  |    |    |   |__________| 
|  |   |   |    |  |    |    |        |_ Date
|  |   |   |    |  |    |    |__________ File Size
|  |   |   |    |  |    |_______________ Group
|  |   |   |    |  |____________________ User
|  |   |   |    |_______________________ Number of hard links
|  |   |   |_ Permission of others (read)
|  |   |_____ Permissions of the group (read, write)
|  |_________ Permissions of the owner (read, write, execute)
|____________ File type (- = File, d = Directory, l = Link, ... )
```

---

## `chmod` — Change Permissions

### Symbolic Notation

```shellsession
cry0l1t3@htb[/htb]$ chmod a+r shell && ls -l shell
-rwxr-xr-x   1 cry0l1t3 htbteam 0 May  4 22:12 shell
```

- `u` = owner, `g` = group, `o` = others, `a` = all users
- `+` = add permission, `-` = remove permission

### Octal Notation

```shellsession
cry0l1t3@htb[/htb]$ chmod 754 shell && ls -l shell
-rwxr-xr--   1 cry0l1t3 htbteam 0 May  4 22:12 shell
```

```
Binary Notation:                4 2 1  |  4 2 1  |  4 2 1
Binary Representation:          1 1 1  |  1 0 1  |  1 0 0
Octal Value:                      7    |    5    |    4
Permission Representation:      r w x  |  r - x  |  r - -
```

## SUID & SGID

The Set User ID (`SUID`) and Set Group ID (`SGID`) bits enable users to run certain programs with the privileges of the file's owner or group.

Indicated by an `s` in place of the usual `x` in the permission set.

> [!warning] Security Risk
> If `SUID` is applied to a program like `journalctl` (which can launch a shell), any user running it could execute a shell as root. See [GTFObins](https://gtfobins.github.io/gtfobins/journalctl/) for more examples.

---

## Sticky Bit

When set on a directory, only the file's owner, the directory's owner, or root can delete or rename files — even if others have write access.

```shellsession
cry0l1t3@htb[/htb]$ ls -l
drw-rw-r-t 3 cry0l1t3 cry0l1t3   4096 Jan 12 12:30 scripts
drw-rw-r-T 3 cry0l1t3 cry0l1t3   4096 Jan 12 12:32 reports
```

| Symbol | Meaning |
| --- | --- |
| `t` | Execute permission **+ Sticky Bit** |
| `T` | Sticky Bit **without** execute permission |

### Example: `/tmp`

```
drwxrwxrwt  /tmp
```

Without the sticky bit, any user could delete any other user's temporary files. With `t`, User B **cannot** delete User A's file.

### Setting the Sticky Bit

```shellsession
chmod +t shared_directory
```

> [!note]
> The sticky bit is an **additional permission** on top of `rwx`. It only affects **deletion and renaming** behavior in shared directories.
