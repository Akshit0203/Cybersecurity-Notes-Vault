# Enumerating AI Systems

---

## Overview

In Task 3, we identified the framework behind each service. Now we need to **extract everything those services are willing to hand over**.

- **Fingerprinting** tells you "that is an MLflow server."
- **Enumeration** tells you "that MLflow server contains 4 experiments, 3 production models, artifact URIs pointing to `s3://cyphira-ml-models/`, and the models were created by J.Chen (AI Engineer) at Cyphira."

One is identification. The other is intelligence.

> [!NOTE] Analogy
> Imagine someone leaves an office filing cabinet unlocked. **Fingerprinting** = reading the label ("This is a finance cabinet"). **Enumeration** = opening the drawers and reading the files (employee names, salaries, contracts, bank details).

## 1. MLflow Enumeration

Think of **MLflow as Google Drive + GitHub + Excel for AI models**. When a company builds AI models, MLflow keeps records of everything: which models exist, who created them, when they were trained, their accuracy, and where the actual model files are stored.

If an MLflow server is accidentally exposed, you can query its REST API to extract all of this.

### Step 1: List All Experiments

```
POST /api/2.0/mlflow/experiments/search
```

The response returns every experiment on the server with its name and internal ID. Experiment names often reveal project codenames and business objectives.

Example response:

```json
{
  "experiments":[
    {"experiment_id":"1", "name":"Fraud Detection V3"},
    {"experiment_id":"2", "name":"Customer Churn"}
  ]
}
```

Now you know what AI projects exist, their names, and their IDs. That's valuable intelligence.

### Step 2: List Registered Models

```
GET /api/2.0/mlflow/registered-models/list
```

This returns the full model inventory — every model the organisation has built and registered. Names, descriptions, and creation timestamps.

Example response:

```json
{
 "registered_models":[
   {"name":"FraudDetector"},
   {"name":"RecommendationEngine"}
 ]
}
```

### Step 3: Get Model Version Details

```
GET /api/2.0/mlflow/model-versions/search
```

This is where it gets serious. The response includes:

```json
{
  "version":"3",
  "stage":"Production",
  "user_id":"J.Chen",
  "source":"s3://company-models/fraud/v3"
}
```

| Field     | Value                            | Intelligence Value                                            |
| --------- | -------------------------------- | ------------------------------------------------------------- |
| `version` | `3`                              | Third iteration of the model                                  |
| `stage`   | `Production`                     | This is the model actually serving customers (vs Staging/Archived) |
| `user_id` | `J.Chen`                         | The AI engineer's identity                                    |
| `source`  | `s3://company-models/fraud/v3`   | Cloud provider, bucket name, directory structure              |

Even if you can't access the S3 bucket, you've learned about the company's internal infrastructure.

### Step 4: Search Training Runs

```
POST /api/2.0/mlflow/runs/search
```

A "run" means one training attempt. The response includes hyperparameters and metrics:

```json
{
 "accuracy":"95%",
 "epochs":"20",
 "learning_rate":"0.001"
}
```

Now you know exactly how they trained the AI. It also stores tags:

```json
{
 "git_commit":"4fd98ab",
 "environment":"production",
 "project":"Phoenix"
}
```

Tags reveal internal project names, Git commit IDs, deployment environments, and team workflows.

### Step 5: List Downloadable Artifacts

```
GET /api/2.0/mlflow/artifacts/list
```

Artifacts are the files produced during training (e.g., `model.pkl`, `weights.pt`, `config.yaml`, `metrics.csv`). If downloads are allowed, an attacker might retrieve these files.

At this point, you have mapped the organisation's entire ML portfolio through five API calls.

> [!WARNING] Why Is This Dangerous?
> Without breaking in, you learn: they are building a fraud detection system, the production model is version 8, the lead AI engineer is J. Chen, models are stored in S3 bucket `company-models`, and artifact names reveal model formats and configuration files. This can reveal confidential business projects, expose internal infrastructure, help plan further attacks, and leak intellectual property.

## 2. Inference Server Metadata

**Triton** and **TensorFlow Serving** both expose metadata endpoints that tell you exactly how to talk to the model. An AI model cannot accept just any input — it expects data in a very specific format. These endpoints are the instruction manual.

### Triton — Model Config

```
GET /v2/models/<name>/config
```

Example response:

```json
{
  "input": {
    "name": "image",
    "shape": [1,224,224,3],
    "datatype": "FP32"
  }
}
```

Breaking down each field:

| Field | Example | Meaning |
|---|---|---|
| **Input name** | `"image"` | Which field to send (like a form field name) |
| **Shape** | `[1,224,224,3]` | 1 image, 224×224 pixels, 3 colour channels (RGB) |
| **Datatype** | `FP32` | 32-bit floating-point numbers (e.g., `0.12, 0.56, 0.98`) |
| **Max batch size** | `8` | You can send up to 8 images at once |
| **Backend** | `pytorch_libtorch` | What framework the model was built with |

Other common datatypes:

| Datatype | Meaning | Example Values |
|---|---|---|
| `FP32` | 32-bit floating-point | `0.12, 0.56, 0.98` |
| `INT8` | 8-bit integers | `1, 5, 120` |
| `UINT64` | Unsigned 64-bit integers | `500000` |

### TensorFlow Serving — Model Metadata

```
GET /v1/models/<name>/metadata
```

Returns similar information: input names, output names, shapes, and data types.

> [!NOTE] Why This Matters to an Attacker
> The metadata tells them: how to construct valid requests, what kind of data the model processes, which AI framework is in use, and limits like maximum batch size. It's like finding the instruction manual for a machine — it doesn't give you the machine itself, but it tells you exactly how to operate it.

## 3. Vector Database Enumeration

Vector databases store embeddings (numerical representations of documents) and power semantic search for RAG pipelines. Enumeration here means asking: "What information are you storing?" — not the documents themselves, but information *about* the database.

> [!NOTE] Analogy
> Imagine walking into a library. Without opening any books, you read the shelf labels: "HR Policies," "Employee Salaries," "Legal Contracts." You already know what topics the library contains and how it's organized. Vector database enumeration is the digital equivalent.

### Weaviate

**`GET /v1/meta`** — Returns server version and installed modules:

```json
{
  "version":"1.27",
  "modules":["text2vec-openai", "generative-openai"]
}
```

**`GET /v1/schema`** — Returns the data structure. A schema is simply the "column names" of the database:

```json
{
 "class":"EmployeePolicies",
 "properties":["title", "department", "policy_text"]
}
```

Now you know the system stores titles, departments, and policy text — even without reading the documents.

Inside the schema you might see the **vectorizer** field (e.g., `text2vec-openai` or `text2vec-transformers`), which reveals which embedding model converts text into vectors — discovering which AI engine powers the search.

**`/v1/graphql`** — Even more powerful. Instead of just asking "What tables exist?" you can ask "Show me records." If authentication is missing, you might actually retrieve stored data.

### Qdrant

**`GET /collections`** — Lists all collection names (like folders):

```json
["employees", "hr-policies", "customer-support"]
```

**`GET /collections/hr-policies`** — Returns collection details:

```json
{
 "vectors":768,
 "distance":"cosine",
 "points":50000
}
```

| Field | Value | Meaning |
|---|---|---|
| `vectors` | `768` | Each document is represented by 768 numbers (an "embedding") |
| `distance` | `cosine` | Similarity is measured using cosine similarity (others: Euclidean, Dot Product) |
| `points` | `50000` | ~50,000 stored vectors (roughly one document per vector) |

A collection named `internal-hr-policies` with 768-dimensional vectors and 50,000 points tells you a lot about what that RAG system indexes — without opening a single document.

### Chroma

Older versions expose `GET /api/v1/collections` without authentication by default, listing all collections.

## 4. Prometheus Metrics as Intelligence

Model servers often expose `/metrics` on a dedicated port (Triton on 8002, TorchServe on 8082). These Prometheus-format endpoints return:

```
model_requests_total 153248
gpu_memory_usage_bytes 6442450944
model_name fraud_detector
model_version 5
```

This is **passive intelligence** — you learn the deployment topology without sending a single request to the inference API itself:

| Metric | Example | What You Learn |
|---|---|---|
| Model names | `fraud_detector_v5, customer_chatbot` | What AI models the company runs |
| Version numbers | `v5` | Which iteration is deployed |
| Request counts | `523,000 today` | This model is heavily used |
| Latency | `120 ms average` | How fast the AI responds |
| Batch size | `32` | Server processes 32 requests together |
| GPU usage | `18 GB used` | They're using GPUs; approximate workload |

## 5. Debug Interfaces and Information Leakage

### FastAPI Auto-Generated Docs

Many AI services are built with FastAPI, which automatically creates documentation:

- **`/docs`** — Swagger UI listing every available API endpoint (e.g., `POST /predict`, `POST /upload`, `GET /status`). You can even test them from the browser.
- **`/openapi.json`** — JSON describing the API: endpoint names, required parameters, data types, authentication methods, example requests/responses. Essentially the API manual.

### MLflow GraphQL

Some MLflow versions also exposed a `/graphql` interface that historically bypassed the REST API's authentication controls. An unauthenticated attacker could query internal resolvers like `mlflowSearchRuns` and `mlflowGetRun`, extracting host machine usernames, source code paths via `mlflow.source.name` tags, and the full project inventory.

> [!WARNING] Key Point
> Misconfigured or vulnerable interfaces can expose metadata even if the main API is protected.

### Debug Parameters

Appending `?debug=true` or `?verbose=1` to AI gateway endpoints can trigger raw stack traces:

```
File:         /home/ml/models/train.py
Python:       3.11
TensorFlow:   2.16
Error:        Missing AWS_SECRET_KEY
```

This reveals filesystem paths, installed library versions, environment variable names, and occasionally hardcoded credentials.

## 6. Jupyter Notebook Enumeration

`GET /api/kernels` on an unauthenticated Jupyter instance returns the names, kernel IDs, and last activity timestamps of running kernels:

```json
[
  {"id":"abc123", "name":"Python 3", "last_activity":"2026-07-15"}
]
```

But the real value is in the notebook cells. Data scientists routinely store cleartext credentials directly in their code:

```python
MLFLOW_TRACKING_USERNAME = "alice"
MLFLOW_TRACKING_PASSWORD = "mypassword"
```

```python
AWS_ACCESS_KEY = "AKIA..."
```

```python
HUGGINGFACE_TOKEN = "hf_xxxxxxxxx"
```

This is often the bridge between compromising one service and gaining access to everything else in the stack.

### Overall Architecture

```
                 AI Company
                     │
     ┌───────────────┼───────────────┐
     │               │               │
 Prometheus       FastAPI         Jupyter
   /metrics         /docs          Notebooks
     │               │               │
     ▼               ▼               ▼
Usage stats     API manual      Developer code
                     │               │
                     └──────┬────────┘
                            ▼
                     Helpful intelligence
```

Each component exists for legitimate operational reasons, but if exposed without proper access controls, it can reveal valuable information about the system.

## Case Study: IBM X-Force ML Training Infrastructure Attack Chain

In 2025, [IBM X-Force Red documented](https://securityintelligence.com/x-force/attacking-ml-training-infrastructure/) a complete attack chain demonstrating how enumeration leads to full compromise.

### The Attack Chain

```
Phishing
     │
     ▼
Azure ML (Data Scientist workspace)
     │
     ▼
Jupyter Notebook (contained cleartext MLflow credentials)
     │
     ▼
MLflow Server (model registry, artifact URIs)
     │
     ▼
S3 Bucket (actual model files)
```

**Step 1 — Phishing:** Attackers tricked a data scientist into giving access to their Azure ML environment.

**Step 2 — Jupyter Notebook:** Inside a notebook, they found credentials stored in plaintext:

```python
MLFLOW_TRACKING_USERNAME = "alice"
MLFLOW_TRACKING_PASSWORD = "password123"
```

**Step 3 — MLflow:** Using those credentials, they ran **MLOKit** (IBM's open-source CLI tool for MLflow reconnaissance). `mlokit list-models` inventoried every registered model. `mlokit download-model` pulled version metadata and artifact URIs.

**Step 4 — S3 Storage:** The artifact URIs pointed to Amazon S3 buckets containing the actual model files (`model.pkl`, `weights.bin`, `config.yaml`).

Three components, each trusting the one before it. The security failure was not a software vulnerability — it was that each service was accessible, and the credentials to connect them were sitting in a notebook cell.

### MLOKit Capabilities

IBM later extended [MLOKit](https://github.com/xforcered/MLOKit) to support SageMaker and other platforms:

- **`list-notebooks`** → Discover available notebooks
- **`add-notebook-trigger`** → Configure notebook lifecycle behavior to execute code automatically
- **`poison-model`** → Replace or modify model artifacts when the user has sufficient permissions

> [!IMPORTANT] Main Lesson
> This case study isn't about a clever exploit — it's about how small security mistakes combine into a much larger compromise: a notebook contained credentials → credentials granted access to MLflow → MLflow revealed model locations → storage trusted the same credentials. That's why protecting credentials, enforcing least privilege, and requiring authentication at every layer are critical.
