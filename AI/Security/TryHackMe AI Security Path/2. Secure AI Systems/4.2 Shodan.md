## Initial Assessment — Service Priority

| Port     | Service              | Priority   | Reason                                                                         |
| -------- | -------------------- | ---------- | ------------------------------------------------------------------------------ |
| **2375** | Docker Remote API    | ⭐⭐⭐⭐⭐ | Often leads to full host compromise if unauthenticated.                        |
| **10250**| Kubernetes Kubelet   | ⭐⭐⭐⭐⭐ | Historically one of the highest-value services if anonymous access is allowed. |
| **8888** | Jupyter Notebook     | ⭐⭐⭐⭐   | Can expose notebooks or allow code execution if unauthenticated.               |
| **6379** | Redis                | ⭐⭐⭐⭐   | Misconfigurations can lead to command execution or SSH key injection.           |
| **5900** | VNC                  | ⭐⭐⭐     | Worth checking authentication.                                                 |

## High-Risk Observations

- 🔴 **Docker Remote API exposed (2375)**
    - This is one of the most concerning findings.
    - Docker API should not be exposed without authentication/TLS.
    - Immediate remediation:
        - Disable public access.
        - Bind to localhost or a management network.
        - Enable TLS authentication.
- 🔴 **Redis (6379) exposed**
    - Verify authentication is enabled.
    - Restrict access with firewall rules.
    - Redis exposed to the Internet is a common misconfiguration.
- 🔴 **Kubernetes kubelet (10250) appears reachable**
    - Ensure authentication and authorization are enabled.
    - Restrict network exposure.
- 🟠 **Jupyter Notebook (8888)**
    - Verify it requires authentication.
    - Ensure token/password protection.
- 🟠 **VNC (5900)**
    - Should not be publicly accessible unless absolutely necessary.
    - Restrict by firewall/VPN.
- 🟠 **WinRM (5985)**
    - Verify it is intentionally exposed.
    - Limit access to trusted management hosts.
- 🟠 **Apache 2.4.66**
    - Running an older version.
    - Upgrade to the latest stable release.
    - Note that Shodan lists many CVEs based solely on version matching; this **does not mean the host is actually exploitable**. Many require specific modules or configurations.

### Other Observations

- Self-signed certificate (`CN=localhost`)
- Apache default page still present
- Multiple management services exposed simultaneously
- SSH available on both **22** and **2222**

## 1. Docker API (2375) — Highest Priority

First verify it's really the Docker API:

```bash
curl http://TARGET:2375/version
curl http://TARGET:2375/info
curl http://TARGET:2375/images/json
curl http://TARGET:2375/containers/json?all=1
```

If these respond, you've confirmed an exposed Docker daemon.

### Actual Results

```
┌──(kali㉿kali)-[~/Desktop]
└─$ curl http://143.110.179.178:2375/version
{"Version":"24.0.7","ApiVersion":"1.43","GoVersion":"go1.20.10","Os":"linux","Arch":"amd64","KernelVersion":"5.15.0"}                                                                                         
┌──(kali㉿kali)-[~/Desktop]
└─$ curl http://143.110.179.178:2375/info
{}                                                                                         
┌──(kali㉿kali)-[~/Desktop]
└─$ curl http://143.110.179.178:2375/images/json
{}                                                                                         
┌──(kali㉿kali)-[~/Desktop]
└─$ curl http://143.110.179.178:2375/containers/json?all=1
{}
```

### Analysis

`/version` returns valid Docker information:

```json
{
  "Version":"24.0.7",
  "ApiVersion":"1.43",
  ...
}
```

So something is definitely speaking the Docker API.

However, `/info`, `/images/json`, and `/containers/json` all return `{}` instead of the large JSON objects you'd normally expect.

> [!NOTE] Why `{}` Is Unusual
> Normally you'd expect `[]` (empty array) for `/containers/json` if there are no containers. Returning `{}` (empty object) is unusual and suggests one of the following:
>
> 1. **Reverse proxy or API filter** ⭐⭐⭐⭐ — The lab may expose only a subset of the Docker API. Some endpoints may be blocked while others are allowed.
> 2. **Custom challenge** — CTFs often implement fake or partially functional Docker APIs.
> 3. **Empty/sandboxed environment** — The backend may be intentionally stripped down.

## 2. Kubernetes Kubelet (10250)

Check what endpoints are accessible:

```bash
curl -k https://TARGET:10250/pods
curl -k https://TARGET:10250/runningpods
curl -k https://TARGET:10250/configz
curl -k https://TARGET:10250/metrics
curl -k https://TARGET:10250/spec
```

If authentication is disabled, kubelet can expose a lot of information.

---

## 3. Redis (6379)

See whether authentication is required:

```bash
redis-cli -h TARGET
```

Then try:

```
INFO
CONFIG GET *
KEYS *
```

If `CONFIG GET *` works, that's a significant finding.

## 5. Apache (80/443)

The default page usually means "look elsewhere." Enumerate anyway:

```bash

```

```bash
ffuf -u http://TARGET/FUZZ \
-w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt
```

Check virtual hosts too.

## 6. SSH (22 & 2222)

Interesting that SSH runs on **22** and **2222**. Compare them:

```bash
nmap -sV -sC -p22,2222 TARGET
```

See whether one is inside a container.

## Note on Shodan CVEs

> [!WARNING]
> The Apache CVEs listed by Shodan are mostly **version-based**. They are **not automatically exploitable** because many depend on:
>
> - `mod_proxy`
> - `mod_http2`
> - `mod_dav`
> - `mod_ldap`
> - specific backend configurations
>
> Treat them as patching information, not immediate attack paths.
