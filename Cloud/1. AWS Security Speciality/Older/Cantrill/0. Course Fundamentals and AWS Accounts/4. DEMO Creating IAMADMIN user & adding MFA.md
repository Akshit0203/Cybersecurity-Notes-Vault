# DEMO — Creating the IAMADMIN User & Adding MFA

---

## Overview

In this demo you will:
- Set an **IAM Account Alias** (custom sign-in URL)
- Create an **IAM user** called `iamadmin`
- Grant it **AdministratorAccess**
- Enable **MFA** on the IAM user
- **Sign out** and **sign back in** as `iamadmin` to verify everything works

---

## Part 1 — Set an IAM Account Alias

1. Open the **IAM** service in the AWS Console. If it's not already open, use the search box at the top — type `IAM`, then select it from the list of services (you can right-click → *Open in new tab*).

![](attachments/image-26.png)

2. On the right-hand side you will see a **Sign-in URL for IAM users**. By default this URL contains your numeric Account ID. We want to customise it so it's easier to remember.

![](attachments/image-28.png)

3. Click **Create** below *Account Alias*.

![](attachments/image-30.png)

4. Enter a **Preferred alias** — this must be **globally unique**. Use a name similar to your AWS account name (e.g. `cantrillawstraining2026-1`).

![](attachments/image-31.png)

5. Notice the sign-in URL now updates to something much easier to remember. Click **Create alias**.

![](attachments/image-32.png)

6. Once the alias is created, **copy the new sign-in URL** somewhere safe (e.g. make a bookmark) — you will need it later.

![](attachments/image-33.png)

---

## Part 2 — Create the `iamadmin` IAM User

7. In the IAM console, click **Users** in the left-hand navigation, then click **Create user**.

![](attachments/image-34.png)

8. Under **User name**, type `iamadmin`. This name only needs to be unique within your AWS account.

![](attachments/image-35.png)

9. Check the box **Provide user access to the AWS Management Console**.

![](attachments/image-36.png)

10. You will be asked to set a **Console password**:
    - **Autogenerate a password** — easier, but you will need to note the password down.
    - **Custom password** — choose this if your password manager generates one for you.

![](attachments/image-37.png)

11. Decide whether the user **must create a new password at next sign-in**:
    - If you are creating this user for someone else → leave the box **checked**.
    - If you are creating this user for yourself → **uncheck** the box and use the password you just set.

![](attachments/image-38.png)

12. Scroll down and click **Next**.

![](attachments/image-39.png)

---

## Part 3 — Set Permissions (AdministratorAccess)

13. On the **Set permissions** page, choose **Attach policies directly**.

![](attachments/image-41.png)

14. Scroll down and locate the **AdministratorAccess** policy. Check the box next to it.

![](attachments/image-42.png)

![](attachments/image-43.png)

15. Scroll to the bottom and click **Next**.

![](attachments/image-44.png)

16. **Review** the settings — make sure everything looks correct — then click **Create user**.

![](attachments/image-45.png)

![](attachments/image-46.png)

17. If you had AWS autogenerate the password, **note that password down now**. You cannot access it again after leaving this page without resetting it.

![](attachments/image-47.png)

18. Click **Return to users list**.

![](attachments/image-48.png)

> [!WARNING]
> If you haven't noted the password down or downloaded the details, you **cannot** access the password again — you would need to reset it.

---

## Part 4 — Add MFA to the `iamadmin` User

19. From the users list, click on the **iamadmin** user.

![](attachments/image-49.png)

20. Click the **Security credentials** tab.

![](attachments/image-50.png)

21. Scroll down to the **Multi-factor authentication (MFA)** section. Click **Assign MFA device**.

![](attachments/image-51.png)

![](attachments/image-52.png)

22. Give the MFA device a descriptive **Device name** so you know where this MFA is stored.

![](attachments/image-54.png)

23. Select **Authenticator app**, then click **Next**.

![](attachments/image-55.png)

> [!NOTE]
> If you receive an error saying *"Entity already exists — MFA device already exists"*, click **Previous**, choose a different (unique) device name, select **Authenticator app** again, and click **Next**.

![](attachments/image-56.png)

24. Follow the setup steps shown on screen:
    1. Make sure you have a compatible authenticator application installed (e.g. Google Authenticator, Duo Mobile, Authy).
    2. Click **Show QR code** and scan it with your authenticator app.
    3. Enter **two consecutive MFA codes** from the app into the fields provided.

![](attachments/image-57.png)

![](attachments/image-58.png)

![](attachments/image-59.png)

25. Once you've entered both codes, click **Add MFA**.

---

## Part 5 — Test the IAM Login

26. Now test the setup. Click the **account dropdown** in the top-right corner, then click **Sign out**.

![](attachments/image-60.png)

![](attachments/image-61.png)

27. Open the **IAM sign-in URL** you bookmarked earlier.

28. Enter the **IAM username** (`iamadmin`) and the **password** you set, then click **Sign in**.

![](attachments/image-63.png)

29. Because MFA is enabled, you will be prompted for an **MFA code**. Enter the one-time code from your authenticator app and click **Sign in**.

![](attachments/image-64.png)

30. You are now logged in to your AWS account as the **iamadmin** IAM user (not the account root user).

![](attachments/image-65.png)

![](attachments/image-66.png)

---

## Summary

> [!TIP]
> Going forward, you will use the **iamadmin** IAM user to log in to the general AWS account for most labs in this course — not the account root user.

In this demo you completed the following:

- ✅ Created the AWS account
- ✅ Configured MFA on the **account root user** (previous demo)
- ✅ Set an **IAM Account Alias** (custom sign-in URL)
- ✅ Created an **iamadmin** IAM user with a console password
- ✅ Attached the **AdministratorAccess** policy
- ✅ Assigned an **MFA device** to the IAM user
- ✅ Signed out and logged back in as **iamadmin** to verify

> [!NOTE]
> In larger AWS environments you would create separate IAM identities for different purposes, granting only the **minimum permissions** required (principle of least privilege). Identity federation is another sign-in method covered in a later video.
