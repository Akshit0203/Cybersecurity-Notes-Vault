### Purpose

The TRAI SMS Header portal lets you verify the sender information behind many bulk/enterprise SMS messages in India.

It is designed to help users check whether a message claiming to be from a bank, government department, or business is associated with a registered sender header and DLT (Distributed Ledger Technology) registration.

What it helps verify:

- Registered sender header (e.g., HDFCBK, SBICRD, EXEMPT).
    
- Communication category (Service / Promotional / Transactional / Government).
    
- Associated entity details shown by the portal.
    
- Whether a 1600-series sender number is part of the authorized enterprise messaging ecosystem.
    

### How SMS headers work

A typical SMS header has three parts:

|1.|Prefix: XY<br><br>X represents the telecom service provider (TSP) and Y represents the service area.|
|---|---|
|2.|Header Name: ABCDEF<br><br>Identifies the registered sender or organization.|
|3.|Suffix: G<br><br>Indicates the type of communication.|

### Two ways to query

|Input Type|Example|Use Case|
|---|---|---|
|1600-series number|`1600XXXX11`|Verify BFSI/government-style sender numbers|
|SMS Header|`CP-HDFCBK-T`|Verify the registered sender header and category|

### Header format

1. Prefix: `CP` (TSP/service-area routing information)
    
2. Header Name: `HDFCBK` (registered sender identifier)
    
3. Suffix / Category: `T`
    

Common suffix meanings:

|Suffix|Meaning|Typical Use|
|---|---|---|
|`S`|Service|Informational messages to existing customers|
|`P`|Promotional|Marketing offers and campaigns|
|`T`|Transactional|OTPs, payment alerts, account activity|
|`G`|Government|Government communications|

Examples shown on the portal:

|Header|Interpretation|
|---|---|
|`CP-CLINICX-S`|Service message from a clinic/provider|
|`CP-HDFCBK-T`|Transactional banking messages (OTP/alerts)|
|`CP-BIGSALE-P`|Promotional marketing campaign|
|`AD-EXEMPU-G`|Government-category communication|

### Investigation workflow

1. Copy the SMS sender string exactly as shown on the phone (e.g., `CP-HDFCBK-T`).
    
2. Open smsheader.trai.gov.in .
    
3. Enter either the 1600-series number or the header.
    
4. Record the returned entity name, address, and communication type.
    
5. Compare it with the claim made in the message (bank, government agency, company, etc.).
    
6. If the header does not match the claimed organization, treat the message as suspicious and verify through official channels.
    

### Important limitations

A valid header does not prove the specific message is legitimate. It only shows that the sender identifier exists in the registered messaging ecosystem.

Attackers may still:

- Include phishing links.
    
- Impersonate brands in message text.
    
- Use lookalike domains.
    
- Exploit compromised business accounts.
    

Therefore verification should include:

- Domain/URL inspection.
    
- Official app/website confirmation.
    
- Bank/government customer-care verification.
    
- Cross-checking transaction or account details.
    

### Practical note for fraud analysis

When investigating SMS phishing or fake banking alerts, collect:

1. Sender header (e.g., `CP-HDFCBK-T`).
    
2. 1600-series number (if present).
    
3. Full message text.
    
4. Embedded URLs.
    
5. Timestamp and recipient number.
    
6. TRAI portal verification result.
    

This helps separate unregistered spoof-like messages from messages sent through the registered enterprise SMS ecosystem, though additional evidence is still required to determine whether the communication itself was fraudulent.

Key takeaway

TRAI header verification is a useful authenticity signal, not a guarantee of safety. Treat it as one piece of evidence alongside URL analysis, account verification, and official-channel confirmation.
