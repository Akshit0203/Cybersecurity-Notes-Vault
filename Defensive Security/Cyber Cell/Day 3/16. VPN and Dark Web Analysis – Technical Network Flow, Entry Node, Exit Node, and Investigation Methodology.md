
# VPN and Dark Web Analysis – Technical Network Flow, Entry Node, Exit Node, and Investigation Methodology

## Overview

Investigators frequently encounter:

- Commercial VPN services
    
- TOR (The Onion Router) network traffic
    
- Dark web marketplaces
    
- Anonymous communication platforms
    
- Privacy-focused hosting providers
    

The primary investigative objective is:

> To attribute network activity to a specific user, device, account, or organization.

VPNs and TOR are privacy-enhancing technologies that obscure network paths and source locations. However, attribution may still be possible through technical evidence, logs, endpoint artifacts, financial records, and operational security failures.

---

# What Is a VPN?

VPN stands for:

**Virtual Private Network**

A VPN establishes an encrypted tunnel between a client device and a VPN server. All traffic is encapsulated and transmitted through this tunnel before reaching its final destination.

---

## Step-by-Step VPN Connection Process

### Step 1 – User Initiates a Connection

The user launches a VPN client and selects a VPN server.

Example:

```text
User Device
IP: 49.x.x.x
```

---

### Step 2 – VPN Tunnel Establishment

The VPN client performs authentication and key exchange using protocols such as:

- OpenVPN
    
- WireGuard
    
- IKEv2/IPsec
    
- L2TP/IPsec
    

During this phase:

- Encryption keys are negotiated
    
- Authentication occurs
    
- Secure tunnel is established
    

---

### Step 3 – Traffic Encapsulation

The user's packets are encrypted and encapsulated inside VPN packets.

Original packet:

```text
Source IP: 49.x.x.x
Destination IP: example.com
```

Encapsulated packet:

```text
Source IP: 49.x.x.x
Destination IP: VPN Server
Payload: Encrypted
```

---

### Step 4 – VPN Server Decrypts Traffic

The VPN server receives the encrypted packet and decrypts it.

The server now sees:

```text
Source: VPN User
Destination: example.com
```

---

### Step 5 – VPN Server Forwards Traffic

The VPN server sends traffic to the destination website using its own public IP address.

```text
Website sees:

Source IP = VPN Server IP
```

instead of:

```text
Source IP = User IP
```

---

## VPN Network Flow

Normal Connection:

```text
User Device
   │
   ▼

   │
   ▼
Website
```

VPN Connection:

```text
User Device
   │
Encrypted Tunnel
   │
   ▼
VPN Server
   │
   ▼

```

## What the ISP Sees

The Internet Service Provider typically sees:

- User IP address
    
- VPN server IP address
    
- Connection start time
    
- Connection end time
    
- Data volume transferred
    
- VPN protocol in use
    

The ISP generally cannot inspect the encrypted contents of the VPN tunnel.

---

## What the VPN Provider May See

Depending on architecture and logging policies, a VPN provider may have access to:

- Source IP address
    
- Session timestamps
    
- Authentication records
    
- Account identifiers
    
- Payment information
    
- Destination traffic metadata
    

Potential logs may include:

```text
Timestamp
Source IP
VPN Server Used
Session Duration
Account ID
```

Actual retention varies by provider and jurisdiction.

# What Is TOR?

TOR stands for:

**The Onion Router**

TOR is a distributed anonymity network that routes traffic through multiple relays.

Instead of trusting a single VPN provider, TOR distributes trust across several independently operated nodes.

---

# Step-by-Step TOR Circuit Creation

## Step 1 – TOR Client Starts

The TOR Browser or TOR client contacts TOR directory authorities.

Directory authorities provide:

- Available relay information
    
- Relay public keys
    
- Network status information
    

---

## Step 2 – Relay Selection

The TOR client selects:

```text
1 Entry (Guard) Node
1 Middle Relay
1 Exit Node
```

Example:

```text
Guard Node
↓

Middle Relay
↓

Exit Node
```

---

## Step 3 – Layered Encryption Creation

The client encrypts traffic multiple times.

Example:

```text
Layer 1 → Exit Node Key
Layer 2 → Middle Relay Key
Layer 3 → Entry Node Key
```

This layered encryption resembles layers of an onion.

---

## Step 4 – Traffic Sent to Entry Node

The client sends encrypted traffic to the Entry Node.

The Entry Node removes only its encryption layer.

It learns:

- User IP address
    
- Next relay address
    

It cannot see:

- Final destination
    

---

## Step 5 – Traffic Sent to Middle Relay

The Middle Relay removes its encryption layer.

It learns:

- Previous relay
    
- Next relay
    

It cannot determine:

- Original user
    
- Final destination
    

---

## Step 6 – Traffic Sent to Exit Node

The Exit Node removes the final encryption layer.

The Exit Node learns:

- Destination website
    
- Outgoing traffic
    

The Exit Node does not know:

- Original user IP
    

---

## Step 7 – Traffic Reaches Destination

The destination website receives traffic from the Exit Node.

Website logs show:

```text
Exit Node IP
```

rather than:

```text
User IP
```

---

# TOR Circuit Architecture

```text
User
  │
  ▼
Entry Node (Guard)
  │
  ▼
Middle Relay
  │
  ▼
Exit Node
  │
  ▼
Website
```

---

# Entry Node (Guard Node)

The Entry Node is the first relay in the TOR circuit.

### Information Available

- User IP address
    
- Connection timestamp
    
- Selected next relay
    

### Information Not Available

- Final destination website
    
- Complete circuit path
    

---

# Middle Relay

The Middle Relay acts as a routing intermediary.

### Information Available

- Previous relay
    
- Next relay
    

### Information Not Available

- User identity
    
- Destination website
    

---

# Exit Node

The Exit Node is the final relay before traffic reaches the destination.

### Information Available

- Destination address
    
- Outgoing traffic metadata
    

### Information Not Available

- Original user IP address
    

---

# Example TOR Flow

```text
User IP:
49.x.x.x

↓

Guard Node

↓

Middle Relay

↓

Exit Node

↓

example.com
```

Website logs:

```text
185.x.x.x
```

This IP belongs to the TOR Exit Node.

# How .onion Services Work

Unlike normal websites, .onion services do not require an Exit Node.

Communication remains entirely inside the TOR network.

---

## Step-by-Step Onion Service Access

### Step 1

User enters:

```text
exampleabc123.onion
```

---

### Step 2

TOR client retrieves onion service descriptors.

---

### Step 3

Client establishes a TOR circuit.

---

### Step 4

The onion service establishes its own TOR circuit.

---

### Step 5

Both circuits meet at a rendezvous point.

```text
User Circuit
      │
      ▼
Rendezvous Point
      ▲
      │
Service Circuit
```

---

### Step 6

Encrypted communication occurs entirely within TOR.

No Exit Node is required.

# Common Misconceptions

### Myth

"VPN makes me completely anonymous."

### Reality

A VPN primarily changes who can observe traffic.

Trust shifts from:

```text
ISP
```

to:

```text
VPN Provider
```

---

### Myth

"TOR users cannot be identified."

### Reality

TOR significantly improves anonymity but does not eliminate investigative opportunities.

Attribution may occur through:

- Device evidence
    
- Account correlation
    
- Financial tracing
    
- OPSEC failures
    
- Infrastructure seizures
    
- Human intelligence

# Key Takeaway

VPNs and TOR use different approaches to privacy and anonymity. A VPN routes traffic through a single trusted provider, while TOR distributes trust across multiple relays using layered encryption. In a TOR circuit, the Entry Node knows the user's IP address, the Middle Relay only knows adjacent relays, and the Exit Node knows the destination but not the original source. Technical investigations involving VPNs, TOR, and dark web activity typically rely on endpoint evidence, log correlation, device forensics, cryptocurrency analysis, infrastructure intelligence, and operational security mistakes rather than simply identifying a single IP address.
