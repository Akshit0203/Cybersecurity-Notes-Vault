# Enumeration

---

## What is Enumeration?

**Enumeration is the process of collecting as much information as possible about a target.**

> The goal is **not** to gain access immediately. The goal is to identify **every possible way** you _could_ attack the target.

It is not just based on the tools we use. They will only do much good if we know what to do with the information we get from them. The tools are just tools, and tools alone should never replace our knowledge and our attention to detail. It is much more about actively interacting with the individual services to see what information they provide us and what possibilities they offer us.

It is essential to understand how these services work and what syntax they use for effective communication and interaction with the different services.

> **Analogy:** Your partner lost the car keys. "In the living room" is vague. "On the white shelf, next to the TV, in the third drawer" is precise. More information → faster results. Enumeration works the same way.

---

## The Two Things You're Looking For

Almost every attack starts from one of these:

### 1. Functions or Resources

Services that let you interact with the target:

- SSH
- HTTP
- FTP
- SMB

### 2. Information

Sometimes the service itself leaks useful data:

- Software version
- Usernames
- Hostname
- Shares
- Configuration details

That information can later be used to gain access.

> Most of the information we get comes from **misconfigurations** or neglect of security for the respective services. Misconfigurations are either the result of ignorance or a wrong security mindset. For example, if the administrator only relies on the firewall, Group Policy Objects (GPOs), and continuous updates, it is often not enough to secure the network.

---

## Why is Enumeration So Important?

> **Enumeration is the key.**

### Person A — Immediately starts running exploits

```
Target → Exploit → Fails
```

They don't know what services exist or what versions are running.

### Person B — First enumerates

```
Target
   │
   ▼
Find open ports
   │
   ▼
Identify services
   │
   ▼
Determine versions
   │
   ▼
Check configurations
   │
   ▼
Choose the correct attack
```

This person has a much higher chance of success.

---

## Tools Are Not Enough

Many beginners think:

> "If I use enough tools, I'll find the vulnerability."

That's the wrong mindset. The problem usually isn't that you picked the wrong tool. The problem is that you don't understand **how the service works** or **how to communicate with it**.

For example, if Nmap tells you port 21 is running `FTP` but you don't know the FTP protocol, you still won't know what to do next. **Learning the protocol is often more valuable than running another scanner.**

---

## Why Manual Enumeration Matters

Automated scanners are helpful, but they aren't perfect. Many scanners (including Nmap) use **timeouts**:

```
Target
   ↓
Nmap sends request
   ↓
No response before timeout
   ↓
Marks port closed
```

But imagine the server was just slow — the port might actually be open. If you trust the scan blindly, you may completely miss an attack path.

`Manual enumeration` is a `critical` component. Many scanning tools simplify and accelerate the process, but they cannot always bypass the security measures of the services.

# Introduction to Nmap

---

**Nmap (Network Mapper)** is an open-source network analysis and security auditing tool written in C, C++, Python, and Lua. It is designed to scan networks and identify which hosts are available on the network using raw packets, and services and applications, including the name and version, where possible. It can also identify the operating systems and versions of these hosts. Besides other features, Nmap also offers scanning capabilities that can determine if packet filters, firewalls, or intrusion detection systems (IDS) are configured as needed.

## Use Cases

- Auditing network security
- Simulating penetration tests
- Checking firewall and IDS configurations
- Network mapping
- Response analysis
- Finding open ports
- Vulnerability assessment

Think of Nmap as your **first reconnaissance tool**:

```
Target
   │
   ▼
Nmap Scan
   │
   ▼
Open Ports
Running Services
Versions
Operating System
```

---

## Nmap Architecture

Nmap can be divided into five major scanning capabilities:

| #   | Capability                          | Question it answers                     | Example                                 |
| --- | ----------------------------------- | --------------------------------------- | --------------------------------------- |
| 1   | **Host Discovery**                  | "Is the machine alive?"                 | `nmap 10.10.10.5`                       |
| 2   | **Port Scanning**                   | "Which ports are open?"                 | `22`, `80`, `443`, `3306`               |
| 3   | **Service Enumeration & Detection** | "What service is running on that port?" | `22 → SSH`, `80 → HTTP`, `3306 → MySQL` |
| 4   | **OS Detection**                    | "What operating system is running?"     | Windows, Ubuntu, Debian, FreeBSD        |
| 5   | **Nmap Scripting Engine (NSE)**     | Scriptable interaction with services    | SMB enumeration, vuln checks            |

---

## Basic Nmap Syntax

Every Nmap command follows the same pattern:

```
nmap <scan types> <options> <target>
```

Example:

```
nmap -sS 10.10.10.5
```

```
nmap
 │
 ├── Scan Type (-sS)
 ├── Options
 └── Target
```

---

## Scan Techniques

Nmap offers many different scanning techniques. Common ones:

| Option | Purpose           |
|--------|-------------------|
| `-sS`  | TCP SYN Scan      |
| `-sT`  | TCP Connect Scan  |
| `-sU`  | UDP Scan          |
| `-sN`  | NULL Scan         |
| `-sF`  | FIN Scan          |
| `-sX`  | Xmas Scan         |
| `-sA`  | ACK Scan          |
| `-sO`  | IP Protocol Scan  |

Full list from `nmap --help`:

```
SCAN TECHNIQUES:
  -sS/sT/sA/sW/sM: TCP SYN/Connect()/ACK/Window/Maimon scans
  -sU: UDP Scan
  -sN/sF/sX: TCP Null, FIN, and Xmas scans
  --scanflags <flags>: Customize TCP scan flags
  -sI <zombie host[:probeport]>: Idle scan
  -sY/sZ: SCTP INIT/COOKIE-ECHO scans
  -sO: IP protocol scan
  -b <FTP relay host>: FTP bounce scan
```

Focus on **`-sS`** first — it's the default and most commonly used.

---

## TCP SYN Scan (`-sS`)

Often called a **half-open scan**. It sends only the **SYN** packet and does **not** complete the TCP three-way handshake. That makes it fast and hard to detect.

### Normal TCP Connection (Three-Way Handshake)

```
Client                 Server

SYN ------------------>

<------------------ SYN-ACK

ACK ------------------>
```

Connection established.

### SYN Scan (Half-Open)

```
Client                 Server

SYN ------------------>

<------------------ SYN-ACK

RST ------------------>
```

Instead of completing the handshake, Nmap sends an **RST** (reset), so a full connection is never established.

---

## How Nmap Interprets Responses

| Response         | Nmap Conclusion |
|------------------|-----------------|
| **SYN-ACK**      | `open`          |
| **RST**          | `closed`        |
| **No response**  | `filtered`      |

> Firewalls may drop or ignore packets, leading to a `filtered` result.

---

## Example Scan

```bash
sudo nmap -sS localhost
```

```
PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
5432/tcp open  postgresql
5901/tcp open  vnc-1
```

**Output columns:**

| Column    | Meaning                                            |
|-----------|----------------------------------------------------|
| **PORT**  | Port number and protocol (e.g. `22/tcp`)           |
| **STATE** | Whether the port is `open`, `closed`, or `filtered`|
| **SERVICE** | Nmap's best guess of the service on that port    |

## Key Takeaways

- **Enumeration** = Gather as much information as possible before attacking
- The goal is to identify **every possible attack surface**, not immediately gain access
- You're mainly looking for:
    - Services/resources you can interact with
    - Information those services reveal
- **Understanding protocols and services** is more valuable than simply running more tools
- **Manual enumeration** complements automated tools because scanners can miss information due to timeouts or other limitations

### What to Remember for HTB, CPTS, and OSCP

Before you exploit anything, always ask:

1. **What ports are open?**
2. **What services are running?**
3. **What versions are they?**
4. **What information do they reveal?**
5. **How can I interact with each service manually?**

- **Nmap** is your primary network enumeration tool
- Use the basic syntax: `nmap <scan types> <options> <target>`
- The **TCP SYN scan (`-sS`)** is the fastest and most common — it doesn't complete the full TCP handshake
- Interpret SYN scan results as:
    - **SYN-ACK → Open**
    - **RST → Closed**
    - **No response → Filtered**
- Always read the three main output columns: **PORT**, **STATE**, **SERVICE**
