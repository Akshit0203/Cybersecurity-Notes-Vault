# Network Layer

---

The `network layer` (`Layer 3`) of `OSI` controls the exchange of data packets, as these cannot be directly routed to the receiver and therefore have to be provided with routing nodes. The data packets are transferred from node to node until they reach their target. The `network layer` identifies the individual network nodes, sets up and clears connection channels, and takes care of routing and data flow control.

In short, it is responsible for:

- `Logical Addressing`
- `Routing`

The most used protocols on this layer are:

- `IPv4` / `IPv6`
- `IPsec`
- `ICMP`
- `IGMP`
- `RIP`
- `OSPF`

It ensures the routing of packets from source to destination within or outside a subnet. Since direct communication between the sender and the receiver is not always possible due to different subnets, packets must be forwarded from nodes (routers) that are on the way.

---

# IP Addresses

---

Each host in the network can be identified by the so-called `Media Access Control` address (`MAC`). This would allow data exchange within this one network. If the remote host is located in another network, knowledge of the `MAC` address is not enough — addressing on the Internet is done via the `IPv4` and/or `IPv6` address, which is made up of the `network address` and the `host address`.

> [!TIP] Think of It This Way
> - `IPv4` / `IPv6` — describes the unique postal address and district of the receiver's building
> - `MAC` — describes the exact floor and apartment of the receiver

It is possible for a single IP address to address multiple receivers (broadcasting) or for a device to respond to multiple IP addresses. However, each IP address must be assigned only once within the network.

---

## IPv4 Structure

The most common method of assigning IP addresses is `IPv4`, which consists of a `32`-bit binary number combined into `4 bytes` consisting of `8`-bit groups (`octets`) ranging from `0-255`.

| **Notation** | **Presentation** |
| --- | --- |
| Binary | 0111 1111.0000 0000.0000 0000.0000 0001 |
| Decimal | 127.0.0.1 |

Each network interface (network cards, network printers, or routers) is assigned a unique IP address.

The `IPv4` format allows 4,294,967,296 unique addresses. The IP address is divided into a `host part` and a `network part`. The `router` assigns the `host part` at home or an administrator assigns it. The respective `network administrator` assigns the `network part`. On the Internet, this is `IANA`.

### IP Address Classes

| **`Class`** | **Network Address** | **First Address** | **Last Address** | **Subnetmask** | **CIDR** | **Subnets** | **IPs** |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `A` | 1.0.0.0 | 1.0.0.1 | 127.255.255.255 | 255.0.0.0 | /8 | 127 | 16,777,214 + 2 |
| `B` | 128.0.0.0 | 128.0.0.1 | 191.255.255.255 | 255.255.0.0 | /16 | 16,384 | 65,534 + 2 |
| `C` | 192.0.0.0 | 192.0.0.1 | 223.255.255.255 | 255.255.255.0 | /24 | 2,097,152 | 254 + 2 |
| `D` | 224.0.0.0 | 224.0.0.1 | 239.255.255.255 | Multicast | Multicast | Multicast | Multicast |
| `E` | 240.0.0.0 | 240.0.0.1 | 255.255.255.255 | reserved | reserved | reserved | reserved |

> The `two` additional `IPs` added in the IPs column are reserved for the `network address` and the `broadcast address`. The `default gateway` is the IPv4 address of the `router` that couples networks. It is common for the default gateway to be assigned the first or last assignable IPv4 address in a subnet.

---

## Subnet Mask

A further separation of these classes into small networks is done with the help of `subnetting`. This separation is done using `netmasks`, which is as long as an IPv4 address. It describes which bit positions within the IP address act as `network part` or `host part`.

---

## Broadcast Address

The `broadcast` IP address connects all devices in a network. A host sends a data packet to all other participants simultaneously, communicating its `IP address`. This is the `last IPv4` address used for the `broadcast`.

---

## Binary System

The binary system uses only two states (`0` and `1`). An IPv4 address is divided into 4 octets, each consisting of `8 bits`. Each position has a specific decimal value.

Example: IPv4 Address `192.168.10.39`

#### 1st Octet — Value: 192

```
Values:         128  64  32  16  8  4  2  1
Binary:           1   1   0   0  0  0  0  0
```

| **Octet** | **Values** | **Sum** |
| --- | --- | --- |
| 1st | 128 + 64 + 0 + 0 + 0 + 0 + 0 + 0 | = `192` |
| 2nd | 128 + 0 + 32 + 0 + 8 + 0 + 0 + 0 | = `168` |
| 3rd | 0 + 0 + 0 + 0 + 8 + 0 + 2 + 0 | = `10` |
| 4th | 0 + 0 + 32 + 0 + 0 + 4 + 2 + 1 | = `39` |

#### IPv4 — Binary Notation

```
Octet:             1st         2nd         3rd         4th
Binary:         1100 0000 . 1010 1000 . 0000 1010 . 0010 0111
Decimal:           192    .    168    .     10    .     39
```

#### Subnet Mask Example

```
Octet:             1st         2nd         3rd         4th
Binary:         1111 1111 . 1111 1111 . 1111 1111 . 0000 0000
Decimal:           255    .    255    .    255    .     0
```

- IPv4 Address: `192.168.10.39`
- Subnet mask: `255.255.255.0`

---

## CIDR

`Classless Inter-Domain Routing` (`CIDR`) replaces the fixed assignment between IPv4 address and network classes. The `CIDR suffix` indicates how many bits from the beginning of the IPv4 address belong to the network. It represents the `subnet mask` by specifying the number of `1`-bits.

- IPv4 Address: `192.168.10.39`
- Subnet mask: `255.255.255.0`
- CIDR: `192.168.10.39/24`

```
Octet:             1st         2nd         3rd         4th
Binary:         1111 1111 . 1111 1111 . 1111 1111 . 0000 0000 (/24)
Decimal:           255    .    255    .    255    .     0
```

# Subnetting

---

The division of an address range of IPv4 addresses into several smaller address ranges is called `subnetting`. A subnet is a logical segment of a network that uses IP addresses with the same network address.

With subnetting, we can determine:

- `Network address`
- `Broadcast address`
- `First host`
- `Last host`
- `Number of hosts`

### Worked Example

- IPv4 Address: `192.168.12.160`
- Subnet Mask: `255.255.255.192`
- CIDR: `192.168.12.160/26`

#### Network Part

| **Details of** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **Decimal** |
| --- | --- | --- | --- | --- | --- |
| IPv4 | `1100 0000` | `1010 1000` | `0000 1100` | `10`10 0000 | 192.168.12.160`/26` |
| Subnet mask | `1111 1111` | `1111 1111` | `1111 1111` | `11`00 0000 | `255.255.255.192` |

From the `1`-bits in the subnet mask, we know which bits in the IPv4 address `cannot` be changed — they determine the "main network."

#### Host Part

The bits in the `host part` can be changed to the `first` and `last` address. The first = `network address`, the last = `broadcast address`.

#### Network Address (all host bits = 0)

| **Details of** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **Decimal** |
| --- | --- | --- | --- | --- | --- |
| IPv4 | 1100 0000 | 1010 1000 | 0000 1100 | 10`\|00 0000` | `192.168.12.128`/26 |
| Subnet mask | `1111 1111` | `1111 1111` | `1111 1111` | `11\|`00 0000 | 255.255.255.192 |

#### Broadcast Address (all host bits = 1)

| **Details of** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **Decimal** |
| --- | --- | --- | --- | --- | --- |
| IPv4 | 1100 0000 | 1010 1000 | 0000 1100 | 10`\|11 1111` | `192.168.12.191`/26 |
| Subnet mask | `1111 1111` | `1111 1111` | `1111 1111` | `11\|`00 0000 | 255.255.255.192 |

This subnet offers `64 - 2` = `62` usable IPv4 addresses:

| **Hosts** | **IPv4** |
| --- | --- |
| Network Address | `192.168.12.128` |
| First Host | `192.168.12.129` |
| Other Hosts | `...` |
| Last Host | `192.168.12.190` |
| Broadcast Address | `192.168.12.191` |

---

## Subnetting Into Smaller Networks

Divide the subnet into 4 additional subnets. We can only divide based on the binary system:

| **Exponent** | **Value** |
| --- | --- |
| 2`^0` | = 1 |
| 2`^1` | = 2 |
| 2`^2` | = 4 |
| 2`^3` | = 8 |
| 2`^4` | = 16 |
| 2`^5` | = 32 |
| 2`^6` | = 64 |
| 2`^7` | = 128 |
| 2`^8` | = 256 |

`4` = 2`^2`, so we extend the subnet mask by `2 bits` from `/26` to `/28`:

| **Details of** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **Decimal** |
| --- | --- | --- | --- | --- | --- |
| IPv4 | 1100 0000 | 1010 1000 | 0000 1100 | 1000`\|` 0000 | 192.168.12.128`/28` |
| Subnet mask | `1111 1111` | `1111 1111` | `1111 1111` | `1111\|` 0000 | `255.255.255.240` |

64 IPs / 4 = `16` hosts per subnet:

| **Subnet No.** | **Network Address** | **First Host** | **Last Host** | **Broadcast Address** | **CIDR** |
| --- | --- | --- | --- | --- | --- |
| 1 | `192.168.12.128` | 192.168.12.129 | 192.168.12.142 | `192.168.12.143` | 192.168.12.128/28 |
| 2 | `192.168.12.144` | 192.168.12.145 | 192.168.12.158 | `192.168.12.159` | 192.168.12.144/28 |
| 3 | `192.168.12.160` | 192.168.12.161 | 192.168.12.174 | `192.168.12.175` | 192.168.12.160/28 |
| 4 | `192.168.12.176` | 192.168.12.177 | 192.168.12.190 | `192.168.12.191` | 192.168.12.176/28 |

---

## Mental Subnetting

Each octet repeats itself, and everything is a power of two. First, identify what octet changes:

| **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** |
| --- | --- | --- | --- |
| /8 | /16 | /24 | /32 |

Given `192.168.1.1/25`, only the fourth octet may change.

Next, use the `Modulo Operation (%)`: `(25 % 8)` = 1. That's 1 bit reserved for the network mask. Remaining host bits = 2^(8-1) = 2^7 = **128**.

| **Remainder** | **Number** | **Exponential Form** | **Division Form** |
| --- | --- | --- | --- |
| 0 | 256 | 2^8 | 256 |
| 1 | 128 | 2^7 | 256/2 |
| 2 | 64 | 2^6 | 256/2/2 |
| 3 | 32 | 2^5 | 256/2/2/2 |
| 4 | 16 | 2^4 | 256/2/2/2/2 |
| 5 | 8 | 2^3 | 256/2/2/2/2/2 |
| 6 | 4 | 2^2 | 256/2/2/2/2/2/2 |
| 7 | 2 | 2^1 | 256/2/2/2/2/2/2/2 |

For `/25` with 128 IPs: first range is `192.168.1.0-127`. Usable: `192.168.1.1-126`. If your IP is above 128, usable space is `192.168.1.129-254` (128 = network, 255 = broadcast).

### Practice Questions

> [!NOTE]- Q1: Subnet mask of `10.200.20.0/27`?
> **Answer:** `255.255.255.224`

> [!NOTE]- Q2: Broadcast address of `10.200.20.0/27`?
> **Answer:** `10.200.20.31`

> [!NOTE]- Q3: Split `10.200.20.0/27` into 4 subnets — network address of the 3rd subnet?
> **Answer:** `10.200.20.16` — Each subnet has 8 IPs → new CIDR /29. Subnet 1: .0, Subnet 2: .8, Subnet 3: .16, Subnet 4: .24

> [!NOTE]- Q4: Split `10.200.20.0/27` into 4 subnets — broadcast address of the 2nd subnet?
> **Answer:** `10.200.20.15` — The 2nd subnet ranges from `10.200.20.8` to `10.200.20.15`, where .15 is the broadcast

# MAC Addresses

---

Each host in a network has its own `48`-bit (`6 octets`) `Media Access Control` (`MAC`) address, represented in hexadecimal format. `MAC` is the `physical address` for our network interfaces. Standards include:

- Ethernet (IEEE 802.3)
- Bluetooth (IEEE 802.15)
- WLAN (IEEE 802.11)

Each network card has its individual MAC address, configured at the manufacturer's hardware side but can always be changed (at least temporarily).

### MAC Address Formats

- `DE:AD:BE:EF:13:37`
- `DE-AD-BE-EF-13-37`
- `DEAD.BEEF.1337`

| **Representation** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **5th Octet** | **6th Octet** |
| --- | --- | --- | --- | --- | --- | --- |
| Binary | 1101 1110 | 1010 1101 | 1011 1110 | 1110 1111 | 0001 0011 | 0011 0111 |
| Hex | DE | AD | BE | EF | 13 | 37 |

---

### MAC Address Structure

The MAC address consists of `6 bytes`:

- **First 3 bytes (24 bits)** = `Organization Unique Identifier` (`OUI`) — defined by IEEE for each manufacturer
- **Last 3 bytes** = `Individual Address Part` / `Network Interface Controller` (`NIC`) — assigned once by the manufacturer to ensure uniqueness

### Delivery Logic

If source and destination are in the **same subnet**, the Ethernet frame goes directly to the target's physical address. If in a **different subnet**, the frame is addressed to the `MAC address` of the `default gateway` (router). `Address Resolution Protocol` (`ARP`) is used in IPv4 to determine the MAC addresses associated with IP addresses.

### Reserved MAC Ranges

| **Local Range** |
| --- |
| 0`2`:00:00:00:00:00 |
| 0`6`:00:00:00:00:00 |
| 0`A`:00:00:00:00:00 |
| 0`E`:00:00:00:00:00 |

### Unicast vs Multicast vs Broadcast

The last bit in the first octet identifies `Unicast` (`0`) or `Multicast` (`1`). The second-to-last bit identifies `Global OUI` (`0`) or `Locally Administrated` (`1`).

#### MAC Unicast

| **Representation** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **5th Octet** | **6th Octet** |
| --- | --- | --- | --- | --- | --- | --- |
| Binary | 1101 111`0` | 1010 1101 | 1011 1110 | 1110 1111 | 0001 0011 | 0011 0111 |
| Hex | D`E` | AD | BE | EF | 13 | 37 |

#### MAC Multicast

| **Representation** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **5th Octet** | **6th Octet** |
| --- | --- | --- | --- | --- | --- | --- |
| Binary | `0000 0001` | `0000 0000` | `0101 1110` | 1110 1111 | 0001 0011 | 0011 0111 |
| Hex | `01` | `00` | `5E` | EF | 13 | 37 |

#### MAC Broadcast

| **Representation** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** | **5th Octet** | **6th Octet** |
| --- | --- | --- | --- | --- | --- | --- |
| Binary | `1111 1111` | `1111 1111` | `1111 1111` | `1111 1111` | `1111 1111` | `1111 1111` |
| Hex | `FF` | `FF` | `FF` | `FF` | `FF` | `FF` |

---

## MAC Address Attack Vectors

MAC addresses can be changed/manipulated or spoofed. They should not be relied upon as the sole means of security.

- **MAC spoofing** — Altering the MAC address to match another device's, typically to gain unauthorized access.
- **MAC flooding** — Sending many packets with different MAC addresses to a switch, causing it to reach its MAC address table capacity.
- **MAC address filtering bypass** — Some networks only allow specific MAC addresses, which we can bypass with spoofing.

---

## Address Resolution Protocol (ARP)

[ARP](https://en.wikipedia.org/wiki/Address_Resolution_Protocol) is used to resolve a Layer 3 IP address to a Layer 2 MAC address. When a device on a LAN wants to communicate with another device, it sends a broadcast message containing the destination IP address. The device with the matching IP address responds with its MAC address.

#### ARP Request

When a device wants to communicate, it sends an ARP request (broadcast) to resolve the destination's IP to its MAC. The device with the matching IP responds with its MAC address.

#### ARP Reply

The responding device sends an ARP reply containing the IP and MAC addresses of both devices.

#### Tshark Capture of ARP Requests

```
1   0.000000 10.129.12.100 -> 10.129.12.255 ARP 60  Who has 10.129.12.101?  Tell 10.129.12.100
2   0.000015 10.129.12.101 -> 10.129.12.100 ARP 60  10.129.12.101 is at AA:AA:AA:AA:AA:AA
3   0.000030 10.129.12.102 -> 10.129.12.255 ARP 60  Who has 10.129.12.103?  Tell 10.129.12.102
4   0.000045 10.129.12.103 -> 10.129.12.102 ARP 60  10.129.12.103 is at BB:BB:BB:BB:BB:BB
```

The "`who has`" message indicates a device is requesting the MAC for a given IP. The reply lines show the responding MAC.

### ARP Spoofing

`ARP spoofing` (also `ARP cache poisoning`) is an attack using tools like [Ettercap](https://github.com/Ettercap/ettercap) or [Cain & Abel](https://github.com/xchwarze/Cain) where we send falsified ARP messages over a LAN. The goal is to associate our MAC address with the IP of a legitimate device, intercepting traffic intended for it.

```
1   0.000000 10.129.12.100 -> 10.129.12.101 ARP 60 10.129.12.255 is at CC:CC:CC:CC:CC:CC  (attacker claiming gateway IP)
2   0.000015 10.129.12.101 -> Broadcast     ARP 60 Who has 10.129.12.100? Tell 10.129.12.101
3   0.000030 10.129.12.100 -> 10.129.12.101 ARP 60 10.129.12.100 is at CC:CC:CC:CC:CC:CC
4   0.000045 10.129.12.101 -> 10.129.12.100 ARP 60 Who has 10.129.12.255? Tell 10.129.12.101
```

The attacker at `10.129.12.100` sends a falsified ARP reply to the target (`10.129.12.101`), associating `CC:CC:CC:CC:CC:CC` with the gateway IP. Traffic intended for the gateway will now be sent to the attacker.

> [!WARNING] Defenses
> Protect against ARP spoofing with secure network protocols (IPSec, SSL), firewalls, and intrusion detection systems.

# Why Both IP and MAC Are Needed

> [!IMPORTANT] Key Concept
> - **IP address = "Where is the device?"** — used for routing across different networks
> - **MAC address = "Which device on this local network?"** — used for delivering data within a local network
>
> Both are essential because the internet is a network of **many local networks connected together**. IP gets the packet to the correct network, and MAC gets it to the correct device on that network.

### Analogy — Taxi Ride

You tell the driver: *"Take me to New York."* → That's like an **IP address** (general destination).

Once in New York: *"Take me to 123 Main Street."* → That's like a **MAC address** (exact local destination).

### Why Switches Need MAC

A switch has a table like:

```
MAC AA → Port 1
MAC BB → Port 2
MAC CC → Port 3
```

It has **no idea** what IP addresses those devices have. If a frame only contained an IP address, the switch would have no way to know which port to send it out.

### What Changes at Each Hop?

At your laptop:
```
Source IP:      192.168.1.10        → Stays the same end-to-end
Destination IP: 142.250.190.14     → Stays the same end-to-end

Source MAC:      AA:AA:AA (Laptop)  → Changes at every hop
Destination MAC: BB:BB:BB (Router) → Changes at every hop
```

**MAC addresses never leave the local network.** Every time your packet reaches a router, the router removes the old MAC addresses and creates new ones for the next link.

### ARP — The Bridge Between IP and MAC

When your laptop knows `Printer IP = 192.168.1.20` but doesn't know which Ethernet device owns that IP, it sends an ARP request: *"Who has IP 192.168.1.20?"* The printer replies: *"Me! My MAC is BB:BB:BB..."* Now the laptop can build an Ethernet frame with the correct destination MAC.

### One-Line Summary

- **IP decides _where the packet should go_.**
- **MAC decides _which wire (switch port) it should leave through right now_.**

# IPv6 Addresses

---

`IPv6` is the successor of IPv4. The `IPv6` address is `128` bit long. The `prefix` identifies the host and network parts. The Internet Assigned Numbers Authority (`IANA`) is responsible for assigning IPv4 and IPv6 addresses. IPv6 is expected to completely replace IPv4 long-term. IPv4 and IPv6 can be made available simultaneously (`Dual Stack`).

IPv6 advantages:

- Larger address space
- Address self-configuration (SLAAC)
- Multiple IPv6 addresses per interface
- Faster routing
- End-to-end encryption (IPsec)
- Data packages up to 4 GByte

| **Features** | **IPv4** | **IPv6** |
| --- | --- | --- |
| Bit length | 32-bit | 128 bit |
| OSI layer | Network Layer | Network Layer |
| Addressing range | ~ 4.3 billion | ~ 340 undecillion |
| Representation | Decimal | Hexadecimal |
| Prefix notation | 10.10.10.0/24 | fe80::dd80:b1a9:6687:2d3b/64 |
| Dynamic addressing | DHCP | SLAAC / DHCPv6 |
| IPsec | Optional | Mandatory |

### IPv6 Address Types

| **Type** | **Description** |
| --- | --- |
| `Unicast` | Addresses for a single interface. |
| `Anycast` | Addresses for multiple interfaces, where only one receives the packet. |
| `Multicast` | Addresses for multiple interfaces, where all receive the same packet. |

> [!NOTE] IPv6 eliminates the broadcast address. It uses multicast instead.

---

## Hexadecimal System

The `hexadecimal system` (`hex`) shows `16` states (`0-F`) with a single character. Example of IPv4 `192.168.12.160` in hex:

| **Representation** | **1st Octet** | **2nd Octet** | **3rd Octet** | **4th Octet** |
| --- | --- | --- | --- | --- |
| Binary | 1100 0000 | 1010 1000 | 0000 1100 | 1010 0000 |
| `Hex` | `C0` | `A8` | `0C` | `A0` |
| Decimal | 192 | 168 | 12 | 160 |

## IPv6 Notation

The `128 bits` are divided into `8 blocks` of 16 bits (4 hex numbers each), separated by colons (`:`).

- Full IPv6: `fe80:0000:0000:0000:dd80:b1a9:6687:2d3b/64`
- Short IPv6: `fe80::dd80:b1a9:6687:2d3b/64`

An IPv6 address consists of:
- `Network Prefix` (network part)
- `Interface Identifier` / `Suffix` (host part) — formed from the 48-bit MAC address, converted to 64-bit

### RFC 5952 Rules

- Alphabetical characters are always lowercase
- Leading zeros of a block are always omitted
- One or more consecutive blocks of `0000` are shortened by `::` (may only be performed **once**, starting from the left)
