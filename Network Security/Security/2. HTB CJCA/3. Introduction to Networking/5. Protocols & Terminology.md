# Common Protocols

---

Internet protocols are standardized rules defined in RFCs that specify how devices on a network should communicate. The two main connection types are [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol) and [UDP](https://en.wikipedia.org/wiki/User_Datagram_Protocol).

---

## Transmission Control Protocol

`TCP` is a `connection-oriented` protocol that establishes a virtual connection between two devices before transmitting data using a [Three-Way-Handshake](https://en.wikipedia.org/wiki/Transmission_Control_Protocol#Connection_establishment). This connection is maintained until the data transfer is complete. `TCP` is reliable but slower than UDP because it requires additional overhead.

## User Datagram Protocol

`UDP` is a `connectionless` protocol — it does not establish a virtual connection before transmitting data. It sends data packets to the destination without checking if they were received. This makes `UDP` faster but less reliable.

Example: Video streaming on YouTube uses UDP because the video can tolerate some data loss, and speed is more important than reliability.

## ICMP

[Internet Control Message Protocol](https://en.wikipedia.org/wiki/Internet_Control_Message_Protocol) (`ICMP`) is used by devices to communicate for various purposes, including error reporting and status information.

### ICMP Requests

| **Request Type** | **Description** |
| --- | --- |
| `Echo Request` | Tests whether a device is reachable. Tools like `tracert` (Windows) or `traceroute` (Linux) always send ICMP echo requests. |
| `Timestamp Request` | Determines the time on a remote device. |
| `Address Mask Request` | Requests the subnet mask of a device. |

### ICMP Messages

| **Message Type** | **Description** |
| --- | --- |
| `Echo reply` | Sent in response to an echo request. |
| `Destination unreachable` | Sent when a device cannot deliver a packet to its destination. |
| `Redirect` | A router informs a device to send packets to a different router. |
| `Time exceeded` | Sent when a packet has taken too long to reach its destination. |
| `Parameter problem` | Sent when there is a problem with a packet's header. |
| `Source quench` | Sent when a device receives packets too quickly and cannot keep up. |

### Time-To-Live (TTL)

The [TTL](https://en.wikipedia.org/wiki/Time_to_live) field in the ICMP packet header limits the packet's lifetime. Each time a packet passes through a router, the router decrements the `TTL by 1`. When TTL reaches `0`, the router discards the packet and sends an ICMP `Time Exceeded` message.

> [!TIP] OS Fingerprinting via TTL
> Each OS has a default TTL value:
> - **Windows** (2000/XP/2003/Vista/10): TTL `128`
> - **macOS / Linux**: TTL `64`
> - **Solaris**: TTL `255`
>
> If you see a ping with TTL `122`, it could be a Windows system (`128 - 6 hops = 122`).

## VoIP

[Voice over Internet Protocol](https://www.fcc.gov/general/voice-over-internet-protocol-voip) (`VoIP`) transmits voice and multimedia communications over the internet (e.g., Skype, WhatsApp, Google Hangouts, Zoom).

Most common VoIP ports: `TCP/5060` and `TCP/5061` for [SIP](https://en.wikipedia.org/wiki/Session_Initiation_Protocol). Port `TCP/1720` may be used for [H.323](https://en.wikipedia.org/wiki/H.323).

### SIP Methods

| **Method** | **Description** |
| --- | --- |
| `INVITE` | Initiates a session or invites another endpoint to participate. |
| `ACK` | Confirms the receipt of an INVITE request. |
| `BYE` | Terminate a session. |
| `CANCEL` | Cancels a pending INVITE request. |
| `REGISTER` | Registers a SIP user agent with a SIP server. |
| `OPTIONS` | Requests information about the capabilities of a SIP server or user agent. |

### Information Disclosure

SIP allows us to enumerate existing users for potential attacks. The SIP `OPTIONS` request can probe a SIP server for information or test its connectivity.

During analysis, we may discover a `SEPxxxx.cnf` file — a configuration file used by Cisco Unified Communications Manager to define settings for a Cisco Unified IP Phone.

# Wireless Networks

---

Wireless networks use radio frequency (`RF`) technology to transmit data between devices. Each device has a wireless adapter that converts data into RF signals and sends them over the air.

- **WiFi** — local area, range of a few hundred feet, uses `2.4 GHz` or `5 GHz` bands
- **WWAN** — wide area, uses cellular data (`3G`, `4G LTE`, `5G`)

Communication occurs via a [Wireless Access Point](https://en.wikipedia.org/wiki/Wireless_access_point) (`WAP`) — a central device (like a router) that connects the wireless network to a wired network and controls access.

---

## WiFi Connection

To connect to a router, a device uses [IEEE 802.11](https://en.wikipedia.org/wiki/IEEE_802.11). When a device wants to join, it sends an `association request` containing:

| | |
| --- | --- |
| `MAC address` | A unique identifier for the device's wireless adapter. |
| `SSID` | The network name ([Service Set Identifier](https://www.geeksforgeeks.org/service-set-identifier-ssid-in-computer-network/)). |
| `Supported data rates` | A list of data rates the device can communicate. |
| `Supported channels` | A list of channels (frequencies) the device can use. |
| `Supported security protocols` | Security protocols the device supports, such as `WPA2`/`WPA3`. |

The `SSID` can be hidden by disabling broadcasting, but can still be found in the authentication packet.

### WEP Challenge-Response Handshake

| **Step** | **Who** | **Description** |
| --- | --- | --- |
| 1 | `Client` | Sends an association request packet to the WAP, requesting access. |
| 2 | `WAP` | Responds with an association response including a challenge string. |
| 3 | `Client` | Calculates a response using the challenge string and shared secret key. |
| 4 | `WAP` | Calculates expected response with the same shared key and sends authentication response. |

[CRC](https://en.wikipedia.org/wiki/Cyclic_redundancy_check) (Cyclic Redundancy Check) is used for error-detection in WEP. However, `CRC` is calculated using `plaintext` data, which allows decryption of a single packet `without` knowing the encryption key.

---

## Security Features

- **Encryption** — WEP, WPA2, WPA3
- **Access Control** — Requiring passwords or MAC addresses for authorized devices
- **Firewall** — WiFi routers often have built-in firewalls

---

## Encryption Protocols

### WEP

`WEP` uses a `40-bit` or `104-bit` key with the `RC4 cipher`. It is vulnerable to various attacks and is no longer considered secure.

| **Protocol** | **IV** | **Secret Key** |
| --- | --- | --- |
| `WEP-40`/`WEP-64` | 24-bit | 40-bit |
| `WEP-104` | 24-bit | 80-bit |

Since the IV is relatively small, we can brute force it and use it to decrypt data.

### WPA

`WPA` provides the highest level of security. It uses more secure authentication methods such as a [Pre-Shared Key](https://en.wikipedia.org/wiki/Pre-shared_key) (`PSK`) or an 802.1X authentication server. All wireless networks should implement at least `WPA2` or `WPA3`.

---

## Authentication Protocols

[LEAP](https://en.wikipedia.org/wiki/Lightweight_Extensible_Authentication_Protocol) and [PEAP](https://en.wikipedia.org/wiki/Protected_Extensible_Authentication_Protocol) are both based on [EAP](https://en.wikipedia.org/wiki/Extensible_Authentication_Protocol):

- **LEAP** — uses a `shared key` for authentication (same key for encryption and authentication). Relatively easy to compromise.
- **PEAP** — uses tunneled [TLS](https://en.wikipedia.org/wiki/Transport_Layer_Security). Establishes a secure connection using a `digital certificate`. More resistant to attacks.

---

## TACACS+

[TACACS+](https://web.archive.org/web/20250423051356/https://www.ciscopress.com/articles/article.asp?p=422947&seqNum=4) authenticates and authorizes users accessing network devices (routers, switches). When a WAP sends an authentication request to a TACACS+ server, the `entire request packet` is typically encrypted using `SSL`/`TLS` or `IPSec`.

---

## Disassociation Attack

A [Disassociation Attack](https://www.makeuseof.com/what-are-disassociation-attacks/) aims to disrupt communication between a WAP and its clients by sending disassociation frames. This can be launched from `within` or `outside` the network and is often used as a precursor to MITM attacks.

---

## Wireless Hardening

- **Disabling broadcasting** — WAP will not transmit beacon frames; network won't be visible to unconnected devices
- **WiFi Protected Access** — WPA-Personal (home/small business) and WPA-Enterprise (larger organizations, uses RADIUS or TACACS+)
- **MAC filtering** — Accept connections only from approved MAC addresses
- **Deploying EAP-TLS** — Uses digital certificates and PKI for strong authentication

# Virtual Private Networks

---

A `Virtual Private Network` (`VPN`) allows a secure and encrypted connection between a private network and a remote device. VPN typically uses `TCP/1723` for [PPTP](https://www.paloaltonetworks.com/cyberpedia/what-is-pptp) and `UDP/500` for [IKEv1](https://www.cisco.com/c/en/us/support/docs/security-vpn/ipsec-negotiation-ike-protocols/217432-understand-ipsec-ikev1-protocol.html)/[IKEv2](https://nordvpn.com/blog/ikev2ipsec/).

| **Requirement** | **Description** |
| --- | --- |
| `VPN Client` | Installed on the remote device to establish and maintain a VPN connection (e.g., OpenVPN client). |
| `VPN Server` | Responsible for accepting VPN connections and routing traffic between clients and the private network. |
| `Encryption` | Uses algorithms like AES and IPsec to secure the connection. |
| `Authentication` | VPN server and client authenticate via shared secret, certificate, or other method. |

At the TCP/IP layer, a VPN connection typically uses the [Encapsulating Security Payload](https://www.ibm.com/docs/en/i/7.4?topic=protocols-encapsulating-security-payload) (`ESP`) protocol to encrypt and authenticate VPN traffic.

---

## IPsec

[Internet Protocol Security](https://www.cloudflare.com/learning/network-layer/what-is-ipsec/) (`IPsec`) provides encryption and authentication for internet communications using two protocols:

1. **[Authentication Header](https://www.ibm.com/docs/en/i/7.1?topic=protocols-authentication-header) (AH)** — Provides integrity and authenticity but NOT encryption. Adds a cryptographic checksum to verify packets haven't been tampered with.
2. **[Encapsulating Security Payload](https://www.ibm.com/docs/en/i/7.4?topic=protocols-encapsulating-security-payload) (ESP)** — Provides encryption AND optional authentication.

### IPsec Modes

| **Mode** | **Description** |
| --- | --- |
| `Transport Mode` | Encrypts/authenticates the data payload but NOT the IP header. Used for end-to-end communication between two hosts. |
| `Tunnel Mode` | Encrypts/authenticates the entire IP packet including the IP header. Used to create VPN tunnels between networks. |

### Firewall Rules for IPsec

| **Protocol** | **Port** | **Description** |
| --- | --- | --- |
| `IP` | Protocol `50–51` (`ESP`, `AH`) | Foundation for VPN-related headers |
| `IKE` | `UDP/500` | Negotiate and establish shared secret keys using Diffie-Hellman |
| `ESP` | Protocol `50` _(NAT-T: `UDP/4500`)_ | Encrypt VPN traffic using keys negotiated with IKE |

### IPsec Encryption Algorithms

| Purpose | Common Algorithm |
| --- | --- |
| **Encryption (Confidentiality)** | **AES** (most common today) |
| Older encryption | 3DES (legacy), DES (obsolete/insecure) |
| Authentication/Integrity | HMAC-SHA-256, HMAC-SHA-1 (older) |
| Key Exchange | IKE/IKEv2 using Diffie-Hellman or ECDH |

Most modern IPsec VPNs use: **AES-128** or **AES-256** for encryption, **SHA-256** for integrity, **IKEv2** for key exchange.

---

## PPTP

[Point-to-Point Tunneling Protocol](https://www.vpnranks.com/blog/pptp-vs-l2tp/) (`PPTP`) enables VPN creation by establishing a secure tunnel. Originally an extension of PPP, it is supported by many operating systems.

> [!WARNING] PPTP is no longer secure
> Its authentication method, MSCHAPv2, uses the outdated DES encryption which can be easily cracked. It has been largely replaced by L2TP/IPsec, IPsec/IKEv2, and OpenVPN.

# VLANs

---

`Virtual Local Area Networks` (`VLANs`) conceptually break down one switch into smaller mini-switches, logically segmenting the network to prevent attacks abusing broadcast traffic (such as `broadcast storms`).

A `VLAN` is a logical grouping of network endpoints connected to administratively defined ports on a switch. VLANs act as separate broadcast domains — the broadcast traffic generated in one VLAN does not reach other VLANs. It is possible to restrict inter-VLAN communication through a router or Layer 3 switch, acting as a router between VLANs.

---

## VLAN Memberships

- **Static VLAN** — Each port assigned to a VLAN manually. More secure.
- **Dynamic VLAN** — Automatically determines membership based on `MAC` addresses or protocols using a `VLAN Membership Policy Server` (`VMPS`). An attacker could use tools like [macchanger](https://github.com/alobbs/macchanger) to spoof MAC addresses.

---

## Access and Trunk Ports

- **Access ports** — Belong to and carry traffic of only one VLAN. Any traffic arriving is assumed to belong to the assigned VLAN.
- **Trunk ports** — Carry multiple VLANs simultaneously. Trunk links connect two trunk ports on switches (or switch and router).

---

## VLAN Identification

Standard `802.3` Ethernet frames do not contain VLAN information. Two trunking methods exist:

### Inter-Switch Link (ISL)

Cisco-proprietary, deprecated. Encapsulated the entire Ethernet frame with a 26-byte header and 4-byte trailer.

### IEEE 802.1Q

The widely adopted standard. Added `TPID` and `TCI` fields (which contains `PCP`, `DEI`, and `VID`) to the Ethernet frame.

![Diagram showing conversion of a 802.3 Ethernet frame to a 802.1Q Ethernet frame by inserting a 802.1Q header between the source address and length fields.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/34/8023_Legacy_8021Q_Ethernet_Frames.png)

- `TPID` — 16-bit field always set to `0x8100`
- `VID` — 12-bit field allowing 4094 usable VLAN IDs (0 and 4095 reserved)
- **Double Tagging** — inserting multiple 802.1Q tags within a single packet, introduced by [802.1ad](https://standards.ieee.org/ieee/802.1Q/10323/)

## VLAN-Capable NICs

### Assigning NICs a VLAN in Linux

First, ensure the Kernel has the 802.1Q module loaded:

```shellsession
Akshit023@htb[/htb]$ sudo modprobe 8021q
Akshit023@htb[/htb]$ lsmod | grep 8021
8021q                  40960  0
garp                   16384  1 8021q
mrp                    20480  1 8021q
```

Create a VLAN interface on top of `eth0`:

```shellsession
# Using vconfig (deprecated)
Akshit023@htb[/htb]$ sudo vconfig add eth0 20

# Using ip (recommended)
sudo ip link add link eth0 name eth0.20 type vlan id 20
```

Assign IP and bring up:

```shellsession
Akshit023@htb[/htb]$ sudo ip addr add 192.168.1.1/24 dev eth0.20
Akshit023@htb[/htb]$ sudo ip link set up eth0.20
Akshit023@htb[/htb]$ ip a | grep eth0.20
4: eth0.20@eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default qlen 1000
    inet 192.168.1.1/24 scope global eth0.20
```

### Assigning NICs a VLAN in Windows

Via **Device Manager** → Adapter Properties → Advanced → VLAN ID.

![Device Manager window showing properties for ASIX AX88772B USB2.0 to Fast Ethernet Adapter. VLAN ID is selected with a value of 10.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/34/Windows_Device_Manager_Adapter_Properties_VLAN_ID.png)

Or via **PowerShell**:

```powershell
PS C:\> Get-NetAdapterAdvancedProperty -DisplayName "vlan id"
PS C:\> Set-NetAdapter -Name "Ethernet 2" -VlanID 10
```

Use Wireshark with the `vlan` filter. To search for specific VLAN IDs: `vlan.id == 10`

## Security Implications and VLAN Attacks

### VLAN Hopping

Exploits Cisco's `Dynamic Trunking Protocol` (`DTP`). An adversary configures a host to mimic a switch to take advantage of automatic trunking. If successful, the switch establishes a `trunk link` with the adversary's host, exposing packets from multiple VLANs.

Tools: [Yersinia](https://linux.die.net/man/8/yersinia)

![Yersinia interface showing 'enabling trunking' selected for DTP.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/34/Yersinia_DTP_Attack.png)

### Double-Tagging VLAN Hopping

An adversary embeds a hidden `802.1Q` tag inside an already-tagged frame. **Only works if the adversary is connected to a port in the same VLAN as the native VLAN of the trunk port.**

1. Adversary sends a double-tagged frame: outer tag = native VLAN (e.g., VLAN 10), inner tag = target VLAN (e.g., VLAN 30)
2. First switch strips the outer VLAN 10 tag (it's the native VLAN) and forwards. The inner VLAN 30 tag remains intact.
3. Second switch sees only VLAN 30 tag and forwards to the victim's port.

Tools: [Scapy](https://scapy.readthedocs.io/en/latest/usage.html#vlan-hopping), Yersinia

![Yersinia interface showing 'sending 802.1Q double enc. packet' selected.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/34/Yersinia_Double_Tagging_VLAN_Hopping_Attack.png)

## VXLAN

[RFC7348](https://datatracker.ietf.org/doc/html/rfc7348) introduces `Virtual eXtensible Local Area Network` (`VXLAN`) — a 'Layer 2 overlay scheme on a Layer 3 network.' It extends Layer 2 networks across data centers. Each `VXLAN segment` is identified by a 24-bit `VXLAN Network Identifier` (`VNI`), allowing 16 million segments — far beyond the 4094 VLAN limit.

## Cisco Discovery Protocol (CDP)

A layer-2 Cisco protocol used to gather information about directly connected Cisco devices. Usually enabled by default; can be disabled for security.
