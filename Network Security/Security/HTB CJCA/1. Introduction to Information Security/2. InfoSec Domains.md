# InfoSec Domains

> [!info] Module Context
> The major domains (specializations) within Information Security. Each domain protects a different layer of the technology stack — from the network wire to the physical door lock.

---

## Network Security

Network security safeguards a computer network and the data transmitted through it from threats — external hackers or internal actors. It employs tools and techniques to detect, prevent, and defend against security threats.

![](attachments/Pasted%20image%2020260719235717.png)

### Key Elements

| **Element** | **Description** |
| --- | --- |
| `Firewalls` | Act as barriers between trusted internal networks and untrusted external networks, filtering traffic based on predetermined security rules. |
| `Intrusion Detection and Prevention Systems` (`IDS`/`IPS`) | Monitor network traffic for suspicious activities and take automated actions to detect or block potential threats. |
| `Virtual Private Networks` (`VPNs`) | Provide secure, encrypted connections over public networks, ensuring data privacy and integrity during transmission. For example, used by employees to connect to internal network resources. |
| `Access control mechanisms` | Include authentication and authorization protocols to ensure only legitimate users can access network resources. |
| `Encryption technologies` | Protect sensitive data both in transit and at rest, rendering it unreadable to unauthorized parties. |

### Analogy — The Mail Carrier

Imagine network security as a diligent mail carrier responsible for delivering sensitive letters and packages across a bustling city. Just as the mail carrier protects the integrity, confidentiality, and timely delivery of mail, network security safeguards the integrity, confidentiality, and availability of data across computer networks⁠.

- The mail carrier's **uniform and ID badge** represent authentication mechanisms, ensuring only authorized personnel handle the mail⁠.
- The **locked mailbag** acts as a firewall, separating trusted mail from potential threats and allowing only verified items to pass through⁠.
- The carrier's **vigilant eye**, always on the lookout for suspicious packages, mirrors Intrusion Detection and Prevention Systems (IDS/IPS)⁠.
- **Secure courier services** for highly confidential documents are akin to Virtual Private Networks (VPNs), providing extra protection for sensitive data⁠.
- **Tamper-evident seals** on packages represent encryption technologies, ensuring the contents remain unreadable to unauthorized parties⁠.

Just as the mail carrier navigates various challenges to ensure safe and timely delivery, network security employs multiple strategies to protect data as it travels across the digital landscape⁠.

> [!warning] Firewalls Are Not Enough
> Just like skilled burglars might find a way to pick a lock or sneak through an open window, cybercriminals can sometimes use advanced techniques to bypass firewalls. A firewall is an important first line of defense, but it doesn't provide complete protection for the network.

### Threat Landscape

Cybersecurity threats can range from financially motivated attacks (ransomware, data theft) to state-sponsored espionage and hacktivism. Consequences of a successful network breach include:

- Financial losses
- Reputational damage
- Legal liabilities
- Operational disruptions

With the increasing adoption of **cloud computing**, **IoT devices**, and **remote work**, the attack surface has expanded significantly, making comprehensive network security essential.

### Responsibility

| **Role** | **Responsibility** |
| --- | --- |
| `Network Security Manager` | Leads the network security team; reports to the CISO |
| `Network Security Team` | Designs, implements, and maintains the network security infrastructure — configuring devices, enforcing policies, monitoring traffic, responding to incidents |
| `Penetration Testers / Ethical Hackers` | Simulate real-world attacks to identify vulnerabilities and weaknesses |
| `CISO` | Sets overall security strategy; aligns network security with business objectives and risk tolerance |
| `IT Management (CIO, IT Director)` | Allocates resources; integrates security into broader IT infrastructure |
| `Network Administrators & Security Analysts` | Day-to-day operations and monitoring |
| `Compliance Officers` | Ensure network security meets regulatory requirements |
| `Risk Management Teams` | Assess and prioritize security investments based on business impact |

## Application Security

Application security focuses on protecting software applications from external threats throughout their **entire lifecycle** — from development through deployment and ongoing maintenance. It is often a significant factor in breaches if not properly implemented.

The primary goal is to ensure that applications preserve the **confidentiality, integrity, and availability** ([CIA Triad](https://www.fortinet.com/resources/cyberglossary/cia-triad)) of the data they process.

Application Security involves a combination of **secure coding practices**, **rigorous testing**, and **security controls**. Developers write code resistant to common vulnerabilities such as SQL injection, cross-site scripting (XSS), and buffer overflows.

### Pseudo-Code Example — Building a House

> [!note] What is Pseudocode?
> Pseudocode is a simplified, informal way of describing a program's logic and structure. It uses plain language mixed with basic programming concepts. It isn't meant to be executed by a computer but serves as a guide to visualize how a process works.

```python
# 1. Start Building the House (Develop the App)
def build_house():
    # Put locks on doors and windows (Secure Authentication)
    install_locks_on_doors_and_windows()

    # Use strong walls and materials (Write Secure Code)
    use_strong_materials_for_walls()

    # Ensure the roof doesn't leak (Encrypt Data)
    install_waterproof_roof()


# 2. Inspect the House for Weak Spots (Test for Vulnerabilities)
def inspect_house():
    # Check if doors are locked properly (Penetration Testing)
    test_if_locks_are_working()

    # Make sure there are no cracks in the walls (Check for Bugs)
    look_for_cracks_in_walls()

    # Test if the roof holds up against rain (Test Data Security)
    test_roof_with_water()


# 3. Keep the House Safe Over Time (Ongoing Security Monitoring)
def maintain_house_security():
    # Watch out for unusual activity (Monitor for Threats)
    install_security_cameras()

    # Fix any new cracks or broken locks (Patch Vulnerabilities)
    repair_cracks_and_replace_broken_locks()


# The overall process of Application Security
def protect_application():
    build_house()              # Develop the app securely
    inspect_house()            # Test for vulnerabilities
    maintain_house_security()  # Monitor and maintain security over time


# Call the function to secure the application (House)
protect_application()
```

#### 1. Build the House (Develop the App)

- **Locks on doors and windows** → Authentication — only the right people can get in.
- **Strong walls and materials** → Secure code, free from weaknesses hackers could exploit.
- **Waterproof roof** → Encryption — ensures no one can read or steal data while it's being transferred.

#### 2. Inspect for Weak Spots (Test for Vulnerabilities)

- **Test if locks are working** → Penetration testing — trying different methods to break in.
- **Look for cracks in walls** → Checking the app's code for bugs or weak spots.
- **Test roof with water** → Making sure sensitive data stays protected under stress.

#### 3. Keep the House Safe Over Time (Ongoing Monitoring)

- **Install security cameras** → Monitor regularly for new threats.
- **Fix cracks and replace broken locks** → Regular updates to fix vulnerabilities.

> [!important] What Happens When Testing Fails
> When the `test_if_locks_are_working()` process goes wrong — such as the checker skipping a door due to error or lack of time — it leaves a vulnerable entry point. If an intruder notices that specific lock isn't working, they can exploit that weakness to break into the application.

### Security by Design

Security isn't an afterthought — you build it in from the start.

- `Threat modeling` — Imagining all the ways someone might break in; figuring out potential risks early.
- `Secure code reviews` — Carefully checking code for weak spots before finishing construction.
- `Servers and databases` — Like the land your house sits on and the water supply it uses; if they aren't secure, the whole system is at risk.
- `Authentication and authorization` — High-quality locks. Authentication ensures the right people can get in; authorization ensures they can only access the rooms (data) they're allowed to.

### Responsibility

| **Role** | **Responsibility** |
| --- | --- |
| `Application Developers` | Write secure code and implement security features |
| `Security Architects` | Design the overall security structure of applications and infrastructure |
| `IT Operations` | Maintain the security of the production environment |
| `Application Security Manager / CISO` | Set policies, ensure compliance, oversee security across all applications |
| `Security Testers / Penetration Testers` | Use static/dynamic analysis, fuzzing, manual code reviews, and simulated attacks to identify vulnerabilities |

> [!tip] Security vs. Speed
> Companies often face the challenge of balancing security with time pressure to launch quickly. Rushing leads to shortcuts in security — like not checking every window or rushing the installation of locks. The app may look ready, but the lack of proper security checks leaves it exposed.

Application security assessment is not a one-time effort but an **ongoing process** — new vulnerabilities and attack techniques constantly emerge, requiring continuous monitoring, testing, and updating.

## Operational Security (OPSEC)

Operational Security (`OpSec`) encompasses the processes, practices, and decisions related to handling and protecting data assets throughout their lifecycle. The primary goal is to maintain a secure environment for day-to-day operations.

> [!abstract] One-Line Definition
> **OPSEC is the practice of identifying and preventing information leaks that could help an attacker understand, predict, or interfere with your operations.**

It's not just about protecting data — it's about protecting **information about what you're doing**. Your tools, actions, infrastructure, and behavior shouldn't reveal more information than necessary, whether you're defending systems or performing authorized security testing.

### Real-Life Analogy — Surprise Birthday Party

Imagine you're planning a surprise birthday party. Even if you never tell the birthday person directly, you could accidentally reveal it by:

- Leaving decorations visible.
- Searching "birthday cakes" on the family computer.
- Talking loudly on the phone.
- Sending invitations where they can see them.

You didn't reveal the secret directly, but your **behavior leaked information**. That's OPSEC.

### Cybersecurity Examples

#### Bad OPSEC — Noisy Scan

You run:

```
nmap -A 10.10.10.5
```

during business hours. The blue team immediately notices:

- Huge port scan
- OS detection
- Service detection
- NSE scripts

They know someone is attacking. **Mission compromised.**

#### Good OPSEC — Stealthy Approach

Instead, you:

- Scan slowly
- Randomize timing
- Limit packets
- Blend into normal traffic
- Use legitimate-looking User-Agents
- Clean up artifacts afterward

Now defenders may not notice. That's good OPSEC.

#### Hiding on a Compromised Machine

You compromise a Windows machine. Instead of creating:

```
hacker.exe
```

you name it:

```
svchost.exe
```

and place it somewhere that looks normal. You also:

- Delete logs
- Remove command history
- Delete temporary files

You're trying to hide evidence. That's OPSEC.

#### Defender OPSEC — Accidental Leak

Your company has:

```
backup-server.company.local
```

An employee posts a screenshot online:

```
Administrator
Backup Server
10.0.0.4
```

Now an attacker learns: internal IP range, hostnames, usernames, infrastructure. Even though no passwords were leaked, useful intelligence was. **Poor OPSEC.**

### OPSEC in OSCP / Pentesting

Good OPSEC means:

- Don't leave reverse shells running unnecessarily.
- Remove uploaded tools after use.
- Delete web shells when finished.
- Don't create obvious filenames like `shell.php`.
- Minimize noisy scans.
- Don't expose your VPN IP unnecessarily.
- Avoid modifying more than necessary.

### Common Examples of Bad OPSEC

- Posting screenshots with IP addresses.
- Uploading terminal screenshots showing usernames or hostnames.
- Leaving GitHub repositories public with API keys.
- Reusing passwords.
- Using your real identity while performing security research.
- Leaving SSH keys on compromised machines.
- Uploading malware samples with identifiable metadata.
- Broadcasting your infrastructure in public documentation.

### The OPSEC Process (5 Steps)

The formal OPSEC process, applied by both attackers and defenders:

1. **Identify critical information** — What must stay hidden? (Passwords, internal IPs, domain names, attack plans)
2. **Identify threats** — Who wants this information? (Hackers, competitors, insider threats)
3. **Find vulnerabilities** — Could information leak through logs, social media, emails, misconfigured servers?
4. **Assess risk** — How likely is the leak? What would the impact be?
5. **Apply countermeasures** — Restrict access, encrypt data, use least privilege, monitor systems, train employees

### Analogy — The Birthday Party (Formal Process)

Imagine you're planning a big birthday party at your house. You have precious items — your favorite video game console, a family heirloom, special jewelry — that you don't want lost or damaged.

#### 1. Assets Identification

Figure out which items are most important to protect — your "critical information assets." Just as you decide that your heirloom necklace needs special care, organizations identify sensitive data that requires extra protection.

#### 2. Threat Identification

Think about what could go wrong. Could someone knock over your gaming console? Might a guest wander into your room and misplace your jewelry? This is analyzing threats and assessing vulnerabilities — figuring out where things could go awry.

#### 3. Vulnerability Identification

Take action. Lock valuable items in a safe place, restrict certain areas, keep an eye on guests. Similarly, OpSec involves passwords, security badges, or surveillance cameras.

#### 4. Access Control

Decide who gets to enter your room or handle special items. Maybe only your best friend gets the key. Companies use OpSec to determine who can access sensitive data, ensuring only the right people have permissions.

#### 5. Monitoring

During the party, stay alert. If guests enter areas they shouldn't, adjust your plan. OpSec is a continuous process that adapts to new threats.

### Core Components

| **Component** | **Description** |
| --- | --- |
| `Access Control` | Determines who has access to what information and under what circumstances. Includes multi-factor authentication, authorization systems, and regular audits of access rights (especially when employees change roles or leave). |
| `Asset Management` | Maintaining an up-to-date inventory of all information assets — hardware, software, and data. Knowing what exists and where helps identify and prioritize vulnerabilities. |
| `Change Management` | Ensuring changes to systems and processes are made in a controlled manner with proper testing and approval, preventing unintended security vulnerabilities during updates. |
| `Security Awareness Training` | Educating all employees about phishing attacks, strong passwords, and proper handling of sensitive information. |

### Responsibility

The responsibility for OpSec falls on the Information Security team, led by the `CISO`, who works closely with IT, HR, and Legal. However, OpSec requires cooperation and commitment from **all levels** of the organization — front-line employees to top-level executives.

Testing is carried out by internal security teams or external consultants specializing in penetration testing. Testers may attempt to bypass access controls, exploit misconfigurations, or use social engineering tactics to test the effectiveness of OpSec measures.

## Disaster Recovery & Business Continuity

`Disaster Recovery` (`DR`) and `Business Continuity` (`BC`) are critical components of an organization's resilience strategy, designed to ensure continued operations in the face of significant disruptions.

> [!abstract] Key Distinction
> **DR = Fix the computers** — Restore IT systems, applications, and data after a disaster.
> **BC = Keep the business running** — Plan for maintaining operations during and after a disruption, even if systems are unavailable.

### Disaster Recovery (DR)

DR deals with the restoration of critical systems and data following a catastrophic event — natural disasters (earthquakes, floods), man-made disasters (fires, terrorist attacks), or technological failures (system crashes, cyberattacks). The goal is to minimize downtime and data loss.

#### DR Example — Ransomware Attack

A ransomware attack encrypts all company servers. DR includes:

- Restoring files from backups
- Rebuilding servers
- Reinstalling operating systems
- Recovering databases
- Restoring network devices
- Bringing applications back online

### Business Continuity (BC)

BC is the broader plan. It ensures that, no matter what happens, the business can keep going, even if adjustments are needed.

#### BC Example — Office Floods

Business Continuity might involve:

- Employees working from home
- Using paper forms temporarily
- Switching to a backup office
- Using alternate internet connections
- Redirecting customer calls to another location

### Combined Example — Amazon Data Center Fire

| **Disaster Recovery** | **Business Continuity** |
| --- | --- |
| IT team restores servers | Traffic redirected to another data center |
| Recovers databases | Customers can still place orders |
| Repairs networking | Employees continue working |
| Brings the website back online | Customer support remains available |

### Analogy — Concert in the Park

You've planned a big concert in a park — stage, sound system, performers, seating. But what if it starts pouring rain or there's a power outage?

- **DR** is bringing an umbrella and a generator. If it rains, set up the umbrella over the stage. If power goes out, switch on the generator. Focus on restoring the critical parts that failed.
- **BC** is having a contingency for moving the concert indoors or arranging an acoustic performance if all else fails. Ensure the show goes on no matter what.

### Comparison

| **Disaster Recovery** | **Business Continuity** |
| --- | --- |
| Focuses on IT systems | Focuses on the entire business |
| Restore servers | Keep business operating |
| Recover data | Continue serving customers |
| Technical process | Organizational process |
| Part of Business Continuity | Broader strategy |

### Responsibility

| **Role** | **Responsibility** |
| --- | --- |
| `Business Continuity Manager` | Leads the dedicated DR/BC team |
| `IT, Operations, Executive Leadership` | Collaborate on developing and maintaining plans |
| `DR/BC Team` | Conduct risk assessments, identify critical business functions, set RTOs and RPOs, design recovery strategies |
| `Penetration Testers` | Identify vulnerabilities that could compromise DR/BC efforts; test effectiveness of recovery procedures |

> [!note] Key Metrics
> - **RTO** (Recovery Time Objective) — Maximum acceptable downtime
> - **RPO** (Recovery Point Objective) — Maximum acceptable data loss (measured in time)

**Testing** includes tabletop exercises (walking through simulated scenarios) to full-scale simulations (actually failing over to backup systems). Annual testing is common.

## Cloud Security

Cloud security encompasses all the measures taken to keep data and applications safe when they're stored in the cloud.

### Analogy — Shared Storage Facility

Imagine storing precious belongings in a high-tech, shared storage facility instead of at home. The facility is "the cloud." Since other people also use it, you must ensure your valuables are safe and only accessible to you.

### Shared Responsibility Model

Both you and the facility owners have roles. The facility provides overall security (guards, surveillance cameras), but you are responsible for locking your individual storage unit.

> [!important] Shared Responsibility Model
> The **cloud provider** secures the building (the infrastructure). **You** secure your own unit (your data and applications).

### Common Threats

| **Threat** | **Analogy** |
| --- | --- |
| `Data Breach` | Someone picks the lock to your unit and steals items — unauthorized access to sensitive information |
| `Insecure APIs` | The facility's access system has flaws that allow unauthorized entry |
| `Misconfigured Cloud Storage` | You forget to lock your storage unit, leaving it open to anyone |
| `Account Hijacking` | Someone steals your access card and pretends to be you |

### Key Areas of Cloud Security

| **Area** | **Description** |
| --- | --- |
| `Data Protection` | Encrypting data at rest and in transit — like using a strong lock and a safe inside your unit |
| `Identity and Access Management (IAM)` | Ensuring only authorized individuals can enter — personalized key or access code |
| `Network Security` | Secure hallways and monitored entrances — firewalls and VPNs protecting data in motion |
| `Compliance & Governance` | Following laws and regulations about how data is handled — like rules about not storing illegal items |

### Responsibility

1. `Cloud Service Providers` — Facility management. Ensure the building is secure, surveillance is operational, security personnel are on duty. Handle overall cloud security infrastructure.
2. `You / Administrator` — Secure your individual unit. Implement strong passwords, manage user access, safeguard your data.
3. `Security Teams` — Plan and oversee measures. Develop strategies, conduct risk assessments, address both technical and human elements.

> [!tip] Ongoing Vigilance
> Cloud security requires constant attention and updates — patching vulnerabilities, updating security protocols, monitoring for suspicious activities, and educating users. Both the cloud provider and the customer must be proactive.

## Physical Security

Physical security protects the actual hardware and facilities that store and process data — computers, servers, server racks, network equipment, and even printed documents. The goal is to prevent unauthorized people from physically accessing these resources.

### Analogy — The Candy Store

Imagine you own a candy store. You lock the cash register and secure the candy displays, but if someone breaks into the store after hours, they could take everything. Physical security is installing sturdy locks, setting up an alarm system, and maybe hiring a security guard.

### Defense in Depth

Physical security integrates **people, processes, and technology** to create layers of protective measures that **deter, detect, delay, and respond** to physical threats.

> [!example] Layered Defense Example
> A secure facility might have:
> - **Perimeter fencing** → deter intruders
> - **Access control systems** → detect unauthorized entry attempts
> - **Reinforced doors** → delay forced entry
> - **On-site security personnel** → respond to breaches

### Why Physical Security Matters

1. Protects valuable assets including expensive equipment and critical data stored on physical devices from theft or damage.
2. Safeguards personnel — ensuring safety of employees and visitors.
3. Maintains operational continuity by preventing disruptions from physical breaches.
4. Often forms a critical part of **regulatory compliance** — many industries require specific physical security measures.

### Common Physical Vulnerabilities

| **Vulnerability** | **Description** |
| --- | --- |
| `Unsecured access points` | Doors, windows, or other entry points left unlocked or easily bypassed |
| `Weak locks` | Outdated or low-quality locks that can be easily picked or broken |
| `Inadequate perimeter security` | Lack of fencing, barriers, or surveillance around the facility's perimeter |
| `Poor key management` | Improper handling or storage of keys, access cards, or other physical credentials |
| `Insufficient lighting` | Dark areas that could conceal intruders or criminal activity |
| `Exposed IT infrastructure` | Servers, network devices, or wiring closets physically accessible to unauthorized individuals |
| `Lack of visitor management` | Weak protocols for identifying, escorting, and monitoring visitors |
| `Unattended workstations` | Computers or devices left unlocked and accessible in public or shared spaces |

### Responsibility

| **Role** | **Responsibility** |
| --- | --- |
| `Physical Security Team` | Reports to the CSO or CISO; implements and maintains physical security measures |
| `Facilities Management Team` | Maintains the building; ensures physical security measures are in place and functioning |
| `IT Security Team` | Secures hardware and network equipment; works closely with physical security teams |
| `All Employees` | Follow security protocols — don't prop open secure doors or share access cards |
| `Red Teamers / Physical Pen Testers` | Simulate real-world attacks to identify physical vulnerabilities — bypassing access controls, social engineering, testing cameras, evaluating barriers |

> [!warning] Physical + Cyber
> Even the most sophisticated cybersecurity measures can be rendered ineffective if an attacker gains physical access to systems or storage devices. A comprehensive information security strategy **must** include robust physical security.

## Mobile Security

Mobile security focuses on protecting mobile devices, the data they store, and the networks they connect to from a wide range of threats — hackers stealing personal information, malicious apps corrupting devices, or unsecured networks exposing data.

### Analogy — The Portable Treasure Chest

Your mobile device is a treasure chest you carry everywhere, filled with personal letters, ID, contacts, keys, money, family photos, financial documents, contracts, and confidential work files.

### Device Protection — Four Layers

| **Layer** | **Description** |
| --- | --- |
| `Device Security` | Strong locks preventing unauthorized access — passcodes, biometric authentication (fingerprints, facial recognition), remote wipe capabilities |
| `Data Security` | A safe within the chest — encryption (scrambles data so it can only be read with the decryption key), secure backups, data loss prevention strategies |
| `Network Security` | Secure roads for your treasures — VPNs act as private tunnels shielding data on public Wi-Fi; secure communication protocols prevent eavesdropping |
| `Application Security` | Safe tools and gadgets — app vetting, permission management, secure development practices |

> [!note] Quiz
> **How many layers are typically included in device protection?** → **4**

### Responsibility

1. `IT Departments` — Implement and manage security solutions like secure networks and device encryption
2. `CISOs` — Develop overarching security strategies, assess risks, ensure compliance
3. `Security Teams` — Conduct penetration testing to identify and address vulnerabilities
4. `IT Security Managers` — Oversee day-to-day operations, ensure policies are followed, adapt to new threats

## Internet of Things (IoT) Security

The `Internet of Things` (`IoT`) refers to the network of everyday objects connected to the internet, allowing them to send and receive data — smart home devices, wearable fitness trackers, industrial sensors, connected cars.

### Analogy — Smart Home

Your home is filled with smart devices: a thermostat, lights that turn on when you enter, a refrigerator that tells you when you're out of milk, a door lock controlled from your smartphone. These devices make life convenient, but they introduce new ways for unwelcome guests to enter — not through doors or windows, but through **invisible digital pathways**.

IoT security is adding locks, alarms, and safeguards to these digital doorways.

### Why IoT Is Hard to Secure

Unlike traditional computers, many IoT devices have **limited processing power and memory**, making it difficult to implement advanced security features. They're also often deployed in **large numbers** across various environments, increasing the chances one could be compromised.

> [!example] Real-World IoT Breach
> A major retail chain installed smart HVAC systems across its stores for energy efficiency. These were connected to the internet for remote monitoring but lacked proper security. Hackers exploited this vulnerability to gain access to the company's network, ultimately stealing **millions of customers' credit card details**.

### Responsibility

| **Player** | **Responsibility** |
| --- | --- |
| `Device Manufacturers` | Design devices with security in mind from the beginning — secure design principles, minimizing unnecessary features, providing timely security updates |
| `Network Administrators` | Secure the networks IoT devices connect to — network segmentation, intrusion detection systems |
| `Application Developers` | Ensure software interacting with IoT devices is secure — proper authentication, data encryption |
| `CISO / IoT Security Manager` | Overall management of IoT security strategy |

As the IoT landscape continues to expand, so do the challenges. New device types are constantly introduced, each with unique vulnerabilities. Cybercriminals are becoming more sophisticated, finding innovative ways to exploit weaknesses.
