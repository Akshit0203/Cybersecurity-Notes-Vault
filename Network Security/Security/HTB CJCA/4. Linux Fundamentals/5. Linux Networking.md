# Network Configuration

As a penetration tester, one of the essential skills is configuring and managing network settings on Linux systems. This allows us to efficiently set up testing environments, manipulate network traffic, and identify or exploit vulnerabilities.

Key network protocols to understand:
- **TCP/IP** — Core protocol suite for Internet communications
- **DNS** — Domain name resolution
- **DHCP** — Dynamic IP address allocation
- **FTP** — File transfer

---

## Network Access Control (NAC)

NAC ensures that only authorized and compliant devices are granted access to the network.

| **Type** | **Description** |
| --- | --- |
| Discretionary Access Control (`DAC`) | The owner of the resource sets permissions for who can access it. |
| Mandatory Access Control (`MAC`) | Permissions are enforced by the operating system, not the owner — more secure but less flexible. |
| Role-Based Access Control (`RBAC`) | Permissions are assigned based on roles within an organization, making it easier to manage user privileges. |

Configuring Linux for NAC involves setting up security policies like `SELinux`, `AppArmor` profiles, and `TCP wrappers` to control access to services based on IP addresses.

Monitoring tools: `syslog`, `rsyslog`, `ss`, `lsof`, and the `ELK stack` (Elasticsearch, Logstash, Kibana).

### Activate / Deactivate a Network Interface

```shellsession
Akshit023@htb[/htb]$ sudo ifconfig eth0 up
# OR
Akshit023@htb[/htb]$ sudo ip link set eth0 up
```

### Assign an IP Address

```shellsession
Akshit023@htb[/htb]$ sudo ifconfig eth0 192.168.1.2
```

### Assign a Netmask

```shellsession
Akshit023@htb[/htb]$ sudo ifconfig eth0 netmask 255.255.255.0
```

### Set the Default Gateway

```shellsession
Akshit023@htb[/htb]$ sudo route add default gw 192.168.1.1 eth0
```

### Configure DNS

Edit `/etc/resolv.conf`:

```shellsession
Akshit023@htb[/htb]$ sudo vim /etc/resolv.conf
```

```txt
nameserver 8.8.8.8
nameserver 8.8.4.4
```

> [!warning]
> Changes to `/etc/resolv.conf` are **not persistent** across reboots — they may be overwritten by `NetworkManager` or `systemd-resolved`. To make DNS changes permanent, configure them through the appropriate network management tool.

### Persistent Network Configuration (`/etc/network/interfaces`)

```shellsession
Akshit023@htb[/htb]$ sudo vim /etc/network/interfaces
```

```txt
auto eth0
iface eth0 inet static
  address 192.168.1.2
  netmask 255.255.255.0
  gateway 192.168.1.1
  dns-nameservers 8.8.8.8 8.8.4.4
```

After making changes, restart the networking service:

```shellsession
Akshit023@htb[/htb]$ sudo systemctl restart networking
```

## Network Access Control — Details

### Discretionary Access Control (DAC)

DAC enables resource owners to control access permissions to their resources. Users and groups who own a resource can decide who has access and what actions (read, write, execute, delete) they are authorized to perform.

### Mandatory Access Control (MAC)

MAC provides more fine-grained control than DAC. It defines rules based on the resource's security level and the user's security clearance. Access is only granted if the user's security level is equal to or greater than the resource's security level. Used in military, government, financial, and healthcare systems.

### Role-Based Access Control (RBAC)

RBAC assigns permissions based on roles within an organization. Each role has a set of permissions that define what actions users in that role can perform. More flexible and scalable than DAC for large organizations.

## Monitoring

Network monitoring involves capturing, analyzing, and interpreting network traffic to identify security threats, performance issues, and suspicious behavior.

As penetration testers, we can capture credentials when someone uses an unencrypted connection (e.g., FTP login). Tools covered in the [Intro to Network Traffic Analysis](https://academy.hackthebox.com/module/details/81) module include **Wireshark**, **tshark**, and **Tcpdump**.

### Traceroute

Traces the route packets take to reach a remote host by sending packets with increasing TTL values:

```shellsession
Akshit023@htb[/htb]$ traceroute www.inlanefreight.com

traceroute to www.inlanefreight.com (134.209.24.248), 30 hops max, 60 byte packets

 2  10.80.71.5 (10.80.71.5)  2.716 ms  2.700 ms  2.730 ms
```

### Common Network Issues

| Issue | Common Causes |
| --- | --- |
| Connectivity problems | Incorrectly configured firewalls/routers, damaged cables |
| DNS resolution issues | Incorrect DNS server settings, DNS server failures, incorrectly configured DNS entries |
| Packet loss | Network congestion, hardware failures |
| Performance issues | Outdated network hardware, incorrect network settings, unpatched software |

## Hardening

Three key mechanisms for securing Linux systems:

### SELinux (Security-Enhanced Linux)

A mandatory access control (`MAC`) system integrated into the Linux kernel. Provides fine-grained control over access to system resources by enforcing security policies. Operates at a low level — powerful but complex to configure.

### AppArmor

Also a `MAC` system, but simpler and more user-friendly. Implemented as a Linux Security Module (`LSM`) and uses application profiles to define resource access. Easier to configure than SELinux but may not offer the same granularity.

### TCP Wrappers

A host-based network access control tool that restricts access to network services based on IP addresses. When a network request is made, TCP wrappers check it against a list of allowed or denied IP addresses. Simple but limited to network-level access control.

### Comparison

| | SELinux | AppArmor | TCP Wrappers |
| --- | --- | --- | --- |
| **Type** | MAC (kernel-integrated) | MAC (kernel module) | Host-based network ACL |
| **Scope** | System-wide resources | Application-level profiles | Network services only |
| **Complexity** | High | Medium | Low |
| **Granularity** | Very fine-grained | Profile-based | IP-based only |
