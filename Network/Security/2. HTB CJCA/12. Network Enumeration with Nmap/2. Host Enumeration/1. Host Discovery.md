# Host Discovery

---

Host discovery is the **first step** before port scanning — it answers one question:

> **"Is the target alive?"**

If a host isn't alive, there's no point scanning its ports. This is why host discovery always comes before enumeration.

When conducting an internal penetration test for the entire network of a company, we should first get an overview of which systems are online. Nmap provides various host discovery options. The most effective host discovery method is to use **ICMP echo requests**.

> [!TIP]
> Always store every single scan. This can later be used for comparison, documentation, and reporting. Different tools may produce different results.

---

## Scan an Entire Network Range

```bash
sudo nmap 10.129.2.0/24 -sn -oA tnet | grep for | cut -d" " -f5
```

Output:

```
10.129.2.4
10.129.2.10
10.129.2.11
10.129.2.18
10.129.2.19
10.129.2.20
10.129.2.28
```

| Option            | Description                                                          |
|-------------------|----------------------------------------------------------------------|
| `10.129.2.0/24`   | Target network range (entire subnet)                                 |
| `-sn`             | Disables port scanning — host discovery only                         |
| `-oA tnet`        | Stores results in all formats with prefix `tnet`                     |

The pipe `grep for | cut -d" " -f5` extracts only the discovered IP addresses.

> This scanning method works only if the firewalls of the hosts allow it. Otherwise, other scanning techniques must be used (see "Firewall and IDS Evasion").

---

## Scan from an IP List (`-iL`)

During an internal penetration test, it is common to be provided with a list of hosts to test.

```bash
cat hosts.lst
```

```
10.129.2.4
10.129.2.10
10.129.2.11
10.129.2.18
10.129.2.19
10.129.2.20
10.129.2.28
```

Scan the list:

```bash
sudo nmap -sn -oA tnet -iL hosts.lst | grep for | cut -d" " -f5
```

```
10.129.2.18
10.129.2.19
10.129.2.20
```

| Option      | Description                                              |
|-------------|----------------------------------------------------------|
| `-sn`       | Disables port scanning                                   |
| `-oA tnet`  | Stores results in all formats with prefix `tnet`         |
| `-iL`       | Reads targets from the provided `hosts.lst` file         |

> Only 3 of 7 hosts responded. The others may be ignoring ICMP echo requests due to firewall configurations. Nmap marks unresponsive hosts as inactive.

## Scan Multiple Individual IPs

Specify IPs directly:

```bash
sudo nmap -sn -oA tnet 10.129.2.18 10.129.2.19 10.129.2.20 | grep for | cut -d" " -f5
```

Or use a range for consecutive IPs:

```bash
sudo nmap -sn -oA tnet 10.129.2.18-20 | grep for | cut -d" " -f5
```

Both produce:

```
10.129.2.18
10.129.2.19
10.129.2.20
```

## What Does `-sn` Mean?

> **Don't perform a port scan. Only discover hosts.**

Instead of checking ports (22, 80, 443...), Nmap simply asks:

> "Are you alive?"

---

## ARP vs ICMP Discovery

### ARP Discovery (Default on Local Networks)

Even if you specify `-PE` (ICMP Echo Request), Nmap on a local network **uses ARP first** because ARP is more reliable than ICMP on the same subnet.

```bash
sudo nmap 10.129.2.18 -sn -oA host -PE --packet-trace
```

```
SENT (0.0074s) ARP who-has 10.129.2.18 tell 10.10.14.2
RCVD (0.0309s) ARP reply 10.129.2.18 is-at DE:AD:00:00:BE:EF
Nmap scan report for 10.129.2.18
Host is up (0.023s latency).
MAC Address: DE:AD:00:00:BE:EF
Nmap done: 1 IP address (1 host up) scanned in 0.05 seconds
```

| Option             | Description                                           |
|--------------------|-------------------------------------------------------|
| `-PE`              | Performs ping scan using ICMP Echo Requests            |
| `--packet-trace`   | Shows all packets sent and received                   |

The packet trace shows **ARP** was actually used, not ICMP.

### The `--reason` Option

See **why** Nmap marked a host as alive:

```bash
sudo nmap 10.129.2.18 -sn -oA host -PE --reason
```

```
Host is up, received arp-response (0.028s latency).
```

| Option      | Description                                 |
|-------------|---------------------------------------------|
| `--reason`  | Displays the reason for the specific result |

---

### ICMP Discovery (Force with `--disable-arp-ping`)

To force ICMP instead of ARP:

```bash
sudo nmap 10.129.2.18 -sn -PE --packet-trace --disable-arp-ping
```

```
SENT (0.0107s) ICMP [10.10.14.2 > 10.129.2.18 Echo request (type=8/code=0) id=13607 seq=0] IP [ttl=255 id=23541 iplen=28 ]
RCVD (0.0152s) ICMP [10.129.2.18 > 10.10.14.2 Echo reply (type=0/code=0) id=13607 seq=0] IP [ttl=128 id=40622 iplen=28 ]
Nmap scan report for 10.129.2.18
Host is up (0.086s latency).
MAC Address: DE:AD:00:00:BE:EF
Nmap done: 1 IP address (1 host up) scanned in 0.11 seconds
```

| Option                | Description                                    |
|-----------------------|------------------------------------------------|
| `--disable-arp-ping`  | Disables ARP discovery, forces ICMP            |

Now the packet trace shows `ICMP Echo Request → ICMP Echo Reply` instead of ARP.

## Inferring OS from TTL

Pay attention to details in the ICMP reply. For example:

```
ttl=128
```

Common default TTL values:

| TTL  | Likely OS                          |
|------|------------------------------------|
| 64   | Linux / Unix                       |
| 128  | Windows                            |
| 255  | Network devices (often Cisco)      |

This is a useful inference during enumeration.

## Commands to Remember

| Command                                     | Purpose                                   |
|---------------------------------------------|-------------------------------------------|
| `nmap -sn <target>`                         | Host discovery only                       |
| `nmap -sn 10.129.2.0/24`                    | Scan a subnet                             |
| `nmap -sn -iL hosts.lst`                    | Scan targets from a file                  |
| `nmap -sn 10.129.2.18-20`                   | Scan an IP range                          |
| `-PE`                                       | Send ICMP Echo Requests                   |
| `--packet-trace`                            | Show packets sent and received            |
| `--reason`                                  | Show why Nmap marked a host as up/down    |
| `--disable-arp-ping`                        | Disable ARP discovery, use ICMP instead   |
