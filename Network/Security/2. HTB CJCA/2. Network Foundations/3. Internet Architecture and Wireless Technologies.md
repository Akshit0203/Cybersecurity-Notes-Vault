# Internet Architecture and Wireless Technologies

---

## Internet Architecture

`Internet Architecture` describes how data is organized, transmitted, and managed across networks. Different models serve different needs — from straightforward client-server setups (websites) to distributed approaches (file-sharing). Each comes with trade-offs in scalability, performance, security, and manageability.

---

### Peer-to-Peer (P2P) Architecture

In a `P2P` network, each node acts as **both client and server**, sharing resources (files, processing power, bandwidth) directly without a central server. Can be fully decentralized or partially centralized.

> [!EXAMPLE] Photo Sharing
> A group of friends installs a P2P file-sharing app and each selects a folder to share. Everyone can browse and download photos directly from each other's shared folders — no central server needed.

A popular P2P example is **BitTorrent** — anyone with the file (`seeder`) can upload it, and others download from multiple sources simultaneously.

![P2P network diagram with interconnected devices](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Arch_Models/P2P-1.png)

| **Advantages**         | **Description**                                                                |
| ---------------------- | ------------------------------------------------------------------------------ |
| `Scalability`          | More nodes = more total resources (storage, CPU)                               |
| `Resilience`           | If one node goes offline, others continue functioning                          |
| `Cost distribution`    | Resource burden is distributed among peers                                     |

| **Disadvantages**              | **Description**                                                      |
| ------------------------------ | -------------------------------------------------------------------- |
| `Management complexity`        | Harder to control updates/security policies across all nodes         |
| `Potential reliability issues` | Too many peers leaving can make resources unavailable                 |
| `Security challenges`          | Each node is exposed to potential vulnerabilities                    |

---

### Client-Server Architecture

In the `Client-Server` model, clients send requests (e.g., browser requesting a webpage) and servers respond. Data and applications reside on centralized servers.

> [!EXAMPLE] Weather Website
> You type `weatherexample.com` → browser sends a request to the server → server processes it, locates the page, and sends back the weather data → browser displays the webpage.

![Client-Server diagram with Internet, clients, and servers](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Arch_Models/Client_Server_Arch-1.png)

#### Tier Models

| Tier              | Description                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| `Single-Tier`     | Client, server, and database all on the same machine. Simple but limited scalability/security                  |
| `Two-Tier`        | Client handles presentation; server manages data. Seen in desktop apps with direct database communication      |
| `Three-Tier`      | Client (presentation) + Application server (business logic) + Database server. Independently maintainable     |
| `N-Tier`          | Multiple application server levels. Highly scalable, ideal for robust web applications                         |

> [!NOTE]
> In a typical web application, the browser does **not** directly interact with the database server. The browser requests pages from a **web server**, which may interact with an application server or database to formulate its response.

| **Advantages**       | **Description**                                     |
| -------------------- | --------------------------------------------------- |
| `Centralized control`| Easier to manage and update                         |
| `Security`           | Central security policies can be applied            |
| `Performance`        | Dedicated servers optimized for their tasks         |

| **Disadvantages**          | **Description**                                                                |
| -------------------------- | ------------------------------------------------------------------------------ |
| `Single point of failure`  | Server goes down → clients lose access                                         |
| `High cost and maintenance`| Expensive to set up and sustain                                                |
| `Network congestion`       | Too many simultaneous clients can slow or disrupt connections                  |

---

### Hybrid Architecture

A `Hybrid` model blends **Client-Server** and **P2P**. Central servers handle coordination/authentication; actual data transfer occurs directly between peers.

> [!EXAMPLE] Video Conferencing
> Login credentials are verified by central servers. Once the meeting begins, video/audio data transfers directly between participants (P2P), reducing lag and server load.

![Hybrid architecture diagram](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Arch_Models/Hybrid_Architecture-1.png)

| **Advantages** | **Description**                                                          |
| -------------- | ------------------------------------------------------------------------ |
| `Efficiency`   | Relieves server workload by letting peers share data                     |
| `Control`      | Central server manages authentication, directory services, or indexing   |

| **Disadvantages**                  | **Description**                                                         |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `Complex implementation`           | More sophisticated design needed                                        |
| `Potential single point of failure`| If the central coordinating server fails, peer discovery may stop       |

### Cloud Architecture

`Cloud Architecture` — computing infrastructure hosted by third-party providers (AWS, Azure, Google Cloud). Provides on-demand access to servers, storage, and applications over the Internet.

Services like **Google Drive** and **Dropbox** operate under the `SaaS` (Software as a Service) model.

![Cloud architecture diagram](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Arch_Models/Cloud_Arch-1.png)

**Five Essential Characteristics:**

| **Characteristic**           | **Description**                                                |
| ---------------------------- | -------------------------------------------------------------- |
| `On-demand self-service`     | Set up and manage services without human help                  |
| `Broad network access`       | Access from any internet-connected device                      |
| `Resource pooling`           | Dynamically share/allocate resources among users               |
| `Rapid elasticity`           | Quickly scale up or down based on demand                       |
| `Measured service`           | Pay only for what you use, tracked with precision              |

| **Advantages**               | **Description**                                |
| ---------------------------- | ---------------------------------------------- |
| `Scalability`                | Easily add/remove computing resources          |
| `Reduced cost & maintenance` | Hardware managed by the provider               |
| `Flexibility`                | Access from anywhere with Internet             |

| **Disadvantages**        | **Description**                                                        |
| ------------------------ | ---------------------------------------------------------------------- |
| `Vendor lock-in`         | Migrating between providers is complex                                 |
| `Security/Compliance`    | Third-party hosting raises data privacy concerns                       |
| `Connectivity`           | Requires stable Internet access                                        |

### Software-Defined Networking (SDN)

`SDN` separates the **control plane** (traffic decisions) from the **data plane** (traffic forwarding). The control plane is centralized in a software-based controller; network devices simply execute instructions.

![SDN architecture diagram](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/289/Internet_Arch_Models/Software-Defined_Arch-1.png)

| **Advantages**                    | **Description**                                                                  |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `Centralized control`             | Simplifies network management                                                   |
| `Programmability & Automation`    | Configurations changed via software instead of manually per device               |
| `Scalability & Efficiency`        | Dynamically optimize traffic flows for better resource utilization               |

| **Disadvantages**              | **Description**                                                      |
| ------------------------------ | -------------------------------------------------------------------- |
| `Controller vulnerability`     | Central controller failure adversely affects the network             |
| `Complex implementation`       | Requires new skill sets and specialized software/hardware            |

#### Traditional Networking vs. SDN — Analogy

> **Traditional Networking** = 50 classrooms, each with its own fan. You walk to each one to change the speed.
>
> **SDN** = All 50 fans connected to **one remote control**. Press a button → every fan changes instantly.

```
Traditional:                    SDN:
Admin                              SDN Controller
  │                                      │
  ├── Switch A  ← manual         ┌───────┼───────┐
  ├── Switch B  ← manual         │       │       │
  ├── Router C  ← manual      Switch A Switch B Router C
  └── Firewall D ← manual              │
                                    Firewall D
```

> [!EXAMPLE] Real-World SDN
> A company has 2,000 switches. Without SDN: login and configure each one individually.
> With SDN: open the controller → click **Deploy** → all 2,000 switches update automatically.

> [!EXAMPLE] Policy-Based Access Control with SDN
> Create one policy:
> ```
> HR → HR Servers
> Finance → Finance Servers
> Guests → Internet Only
> ```
> The controller automatically pushes these rules to every device.

### Software-Defined Architecture (SDA)

SDA is **broader than SDN**. SDN controls the roads; SDA controls the entire city.

```
Software-Defined Architecture
│
├── Software-Defined Networking
├── Security Policies
├── Automation
├── Network Segmentation
└── Device Management
```

#### SDN vs. SDA Comparison

| SDN                                  | SDA                                               |
| ------------------------------------ | ------------------------------------------------- |
| Controls the network                 | Controls the entire network ecosystem              |
| Focuses on routers and switches      | Includes networking, security, automation, policies |
| Centralized network management       | Complete software-driven infrastructure            |
| Part of SDA                          | Broader concept                                    |

> **SDN:** _Centrally manage and automate network devices using software instead of configuring each manually._
> **SDA:** _A broader approach using software to centrally manage the entire network — networking, security, policies, and automation._

---

### Key Architecture Comparisons

| Architecture    | Centralized                  | Scalability            | Ease of Management                 | Typical Use Cases                    |
| --------------- | ---------------------------- | ---------------------- | ---------------------------------- | ------------------------------------ |
| `P2P`           | Decentralized (or partial)   | High (as peers grow)   | Complex (no central control)       | File-sharing, blockchain             |
| `Client-Server` | Centralized                  | Moderate               | Easier (server-based)              | Websites, email services             |
| `Hybrid`        | Partially central            | Higher than C-S        | More complex                       | Messaging apps, video conferencing   |
| `Cloud`         | Centralized in provider      | High                   | Easier (outsourced)                | Cloud storage, SaaS, PaaS           |
| `SDN`           | Centralized control plane    | High (policy-driven)   | Moderate (specialized tools)       | Datacenters, large enterprises       |

## Wireless Networks

A `wireless network` uses radio waves or other wireless signals to connect devices (computers, smartphones, IoT) — enabling communication and data exchange without physical cables.

| **Advantages**          | **Description**                                              |
| ----------------------- | ------------------------------------------------------------ |
| `Mobility`              | Users move freely within the coverage area                   |
| `Ease of installation`  | No extensive cabling needed                                  |
| `Scalability`           | Adding new devices is simpler than wired                     |

| **Disadvantages**       | **Description**                                                               |
| ----------------------- | ----------------------------------------------------------------------------- |
| `Interference`          | Signals disrupted by walls, electronics, or atmospheric conditions            |
| `Security risks`        | Without proper security, transmissions can be easier to intercept             |
| `Speed limitations`     | Generally slower than wired connections of the same generation                |

---

### Wireless Router

A `wireless router` combines:

| **Function**              | **Description**                                         |
| ------------------------- | ------------------------------------------------------- |
| `Routing`                 | Directing data to the correct destination               |
| `Wireless Access Point`   | Providing Wi-Fi coverage                                |

**Main Components:**

| **Component**          | **Description**                                                   |
| ---------------------- | ----------------------------------------------------------------- |
| `WAN Port`             | Connects to internet source (e.g., cable modem)                   |
| `LAN Ports`            | Wired connections to local devices (desktop, printer)             |
| `Antennae`             | Transmit/receive wireless signals (some internal)                 |
| `Processor & Memory`   | Handle routing and network management tasks                       |

---

### Mobile Hotspot

A `mobile hotspot` shares a smartphone's **cellular data connection** via Wi-Fi. Other devices connect as they would to a regular Wi-Fi network.

Key characteristics:
- Uses cellular data (4G/5G)
- Limited range (few meters)
- Significant battery drain on the host device
- Password-protected access

---

### Cell Tower

A `cell tower` (cell site) hosts antennas and communications equipment to create a cellular network `cell` — the specific coverage area of one tower, connecting seamlessly with adjacent cells.

**Components:**
- Radio transmitters/receivers with antennas
- **Base Station Controllers (BSC)** — manage multiple towers, handle call/data handoffs
- **Backhaul links** — fiber optic or microwave connections to the core network

**Types:**
- `Macro cells` — large towers, extensive coverage (kilometers), ideal for rural areas
- `Micro/small cells` — smaller installations in urban centers, filling coverage gaps

---

### Frequencies in Wireless Communications

Radio waves are emitted at specific frequencies (measured in hertz):

| **Frequency Band**  | **Description**                                                                                     |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| `2.4 GHz`            | Older Wi-Fi (802.11b/g/n). Better wall penetration, but prone to interference (microwaves, Bluetooth) |
| `5 GHz`              | Newer Wi-Fi (802.11a/n/ac/ax). Faster speeds, but shorter range                                    |
| `Cellular Bands`     | 4G (LTE) and 5G. From 700 MHz (lower, wider range) to 28 GHz+ (higher, more data, shorter range)   |

> [!TIP] Key Trade-Off
> **Lower frequencies** → travel farther, carry less data
> **Higher frequencies** → shorter range, carry more data
>
> Government agencies (e.g., FCC) regulate frequency allocations to prevent interference.

### Summary

On a typical day, you might use:
- **Wi-Fi** (wireless router) — local wireless access at 2.4 GHz and 5 GHz
- **Cellular networks** — wide-area coverage via cell towers (4G/5G)
- **Mobile hotspot** — personal data sharing from your phone
