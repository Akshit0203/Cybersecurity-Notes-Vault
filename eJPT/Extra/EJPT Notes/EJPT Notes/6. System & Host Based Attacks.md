## Windows Credential Dumping:

#### Windows Password Hashes:
- Windows OS stores the password hashes locally in SAM.
- Authentication and verification of passwords is done by Local Security Authority (LSA).
- Upto windows server 2003, we have 2 types of hashes.
	- LM
	- NTLM
- After Windows Vista all of them uses NTLM hashes.

**SAM Database**:
- It stores the user accounts and passwords on windows. All of these details are hashed.
- SAM database cannot be copied while OS is running.
- Windows NT kernel always keep the SAM DB locked. 
- So attackers uses in memory techniques to dump the hashes from LSASS.
- LSASS process keep a cache memory, that will have the data of SAM DB.
- In modern versions of windows , SAM is encrypted with syskey.

**Note: Elevated privileges are required to interact with LSASS Process.


**LM (LanMan)**:
- Default hashing algorithm in windows before NT4.0
- LM hashing is weak protocol and can easily be cracked, bcuz password hash does not include salts.
- The algorithm , by default converts all letters to uppercase and then hash it. So its case insensitive.

**NTLM (NT Hash)**:
- NTLM is a collection of protocols that is used to authenticate the windows systems.
- Requires a valid username and password to authenticate successfully.
- When account is created , it uses MD4 for hashing and dispose the password.
- It is case sensitive.![[2025-06-17_22-33.png]]

**Exploiting Bash Vulnerability - CVE-2014-6271 (ShellShock)**:
ShellShock refers to a family of Linux Vulnerabilities that allow attackers to execute arbitrary commands on a system via Bash shell.
Discovered in 2014.
It occurs when bash mistakenly executes the commands that comes after `() {:;};`

Eg: bash allows functions to be shared between processes using environment variables.
`export MYFUNC='() { echo Hello; }' bash -c "echo test`
we can do `bash -c "MYFUNC"` to execute the function.

Apache web server running CGI scripts or .sh scripts are also vulnerable.
CGI - Common Gateway Interface . These scripts are used by apache to execute arbitrary commands.
Eg: The url request will be to /cgi-bin/test.sh - something like this.
So any Http Header which is passed to the script is vulnerable.

### Exploiting Misconfigured CronJobs:

**Cron Jobs**:
- Task scheduling will be done using cron jobs.
- It runs a specific script in the scheduled time, it can also repeat everyday.
- Used to automate daily tasks, repetitive tasks.
- Used in taking backups, updating packages etc.
- Some cronjobs run as root user. So we can try to exploit it.

**Exploitation Vector**:
- Scripts executed by cron may have write access, so we can rewrite the script.
- Even script not writable, dir maybe. Then we can delete the script and replace with our own.
- Sometimes the cron itself is writable.

**Exploitation Steps**
- Do `ls -al` to check whether there is any file with root access.
- We got a file with root access, get the path of current dir using `pwd`.
- And do a grep search to find any files that has this path in it.
`grep -rnw /usr -e "/home/student/<filename>"`
This will search all files in usr dir recursively for the path. /usr will usually have the scripts stored.

`grep -rnw`
Here -r --> recursively search all directories
-n --> shows the line number where it got matched.
-w --> matches the whole word only.
Eg: `grep -rnw /usr -e "cat"` --> this picks onyl word `cat`. If word like `concatenate` or `forcat` comes, it won't pick it

- Now find the file and read contents. And understand what is happening,
- Sometimes the code might be configured to execute a shell script file.
- We can check permission for the file , and if there is write permission for user access, we can modify it. There is a possibility that this file will be executed by a cron job, every one minute.

`printf '#!/bin/bash\necho "student ALL=NOPASSWD:ALL" >> /etc/sudoers' > /usr/local/share/copy.sh`

Syntax:
`printf '#!/bin/bash\necho "<user> ALL=NOPASSWD:ALL" >> /etc/sudoers' > <script-path>`

`\necho` --> here \n is for nextline
`student ALL=NOPASSWD:ALL` --> allows the user (student) to run any commands with root access without sudo and no password prompt. We are writing this rule in the sudoers file.

In `/etc/sudoers` file will have the permissions for root user and normal users.
So this entire command will be overwritten into the copy.sh file.
Now run sudo to test whether it works.

`sudo su` --> after the above steps, run this cmd to switch to root user.
